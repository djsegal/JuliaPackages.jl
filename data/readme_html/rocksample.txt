<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Problem description</h2><a id="user-content-problem-description" class="anchor" aria-label="Permalink: Problem description" href="#problem-description"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto"><strong>States</strong>: position of the robot and status of the rocks.</p>
</li>
<li>
<p dir="auto"><strong>Actions</strong>: There are 5 basic actions, moving up, down, left, and right, and sampling a rock and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="abb56d6240534d09294a0c7581a48af4">$K$</math-renderer> sensing actions to check the state of a rock. When sampling or sensing, the robot does not move.</p>
</li>
<li>
<p dir="auto"><strong>Transition model</strong>: When taking a moving action, the robot moves deterministically to the desired cell. The robot can only exit the map by the exit area (on the right side of the grid). Actions that causes the robot to go over the edge of the grid have no effects.</p>
</li>
<li>
<p dir="auto"><strong>Observation model</strong>: The robot can observe the status of the rock with some noise when executing a sensing action. The noise varies exponentially with the distance to the rock. The decaying rate is controlled by the parameter <code>sensor_efficiency</code>. If the robot is moving or sampling it does not receive an observation (receives <code>:none</code>).</p>
</li>
<li>
<p dir="auto"><strong>Reward model</strong>: At each action, the robot receives a reward of <code>step_penalty</code> (negative number). The robot receives a positive reward of <code>exit_reward</code> for reaching the exit area. When sampling, the robot receives a reward of <code>good_rock_reward</code> if the sampled rock is good or <code>bad_rock_penalty</code> (negative number) if the rock is bad. When using the sensor, the robot receives a reward of <code>sensor_use_penalty</code> (negative number). The <code>step_penalty</code> is additive to the other rewards (e.g. when sampling a good rock, the robot would receive a reward of <code>step_penalty</code> + <code>good_rock_reward</code>).</p>
</li>
</ul>

<p dir="auto"><strong><code>RockSamplePOMDP</code> Parameters:</strong></p>
<ul dir="auto">
<li>constructor: <code>RockSamplePOMDP{K}(kwargs...)</code> where <code>K</code> is an integer representing the number of rocks</li>
<li>keyword arguments:
<ul dir="auto">
<li><code>map_size::Tuple{Int,Int}</code> the size of the grid, default (5,5)</li>
<li><code>rocks_positions::Vector{K,RSPos}</code>, the list of positions of the rocks, default <code>@SVector[(1,1), (3,3), (4,4)]</code></li>
<li><code>init_pos::RSPos</code> the initial position of the robot, default (1, 1)</li>
<li><code>sensor_efficiency::Float64</code>, the decaying rate of the sensor performance, default 20.</li>
<li><code>bad_rock_penalty::Float64</code> default -10.</li>
<li><code>good_rock_reward::Float64</code> default 10.</li>
<li><code>step_penalty::Float64</code> default 0.</li>
<li><code>sensor_use_penalty::Float64</code> default 0.</li>
<li><code>exit_reward::Float64</code> default 10.</li>
<li><code>discount_factor::Float64</code> default 0.95</li>
</ul>
</li>
</ul>
<p dir="auto"><strong>Internal types:</strong></p>
<p dir="auto"><code>RSPos</code> : represent a position in the grid as a static array of 2 integers.
<code>RSState</code>: represent the state of the POMDP. The field <code>pos::RSPos</code> is the position of the robots
and the field <code>rocks::SVector{K, Bool}</code> represents the status of the rocks (good or bad).</p>
