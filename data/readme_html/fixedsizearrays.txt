<p dir="auto"><code>FixedSizeArrays.jl</code> is a proof-of-concept package for the <a href="https://julialang.org/" rel="nofollow">Julia programming language</a> which implements mutable fixed-size arrays, which means the length of the array is constant and is amenable to be <a href="https://en.wikipedia.org/wiki/Constant_folding" rel="nofollow">constant-propagated</a> at compile-time when possible.
This is an alternative implementation to <a href="https://juliaarrays.github.io/StaticArrays.jl/stable/pages/api/#StaticArraysCore.MArray" rel="nofollow"><code>MArray</code></a> from <a href="https://github.com/JuliaArrays/StaticArrays.jl"><code>StaticArrays.jl</code></a>.</p>
<p dir="auto">Main differences between <code>FixedSizeArray</code> and <code>MArray</code> are:</p>
<ul dir="auto">
<li><code>FixedSizeArray</code> is based on the <code>Memory</code> type introduced in Julia v1.11, <code>MArray</code> is backed by tuples;</li>
<li>the size of the array is part of the type parameters of <code>MArray</code>, this isn't the case for <code>FixedSizeArray</code>, where the size is only a constant field of the data structure.</li>
</ul>
<p dir="auto">FixedSizeArrays supports the usual array interfaces, so things like broadcasting, matrix
multiplication, other linear algebra operations, <code>similar</code>, <code>copyto!</code> or <code>map</code> should just work.</p>
<p dir="auto">Use the constructors to convert from other array types. Use <code>collect_as</code> to convert from
arbitrary iterators.</p>

<p dir="auto">Note: <code>FixedSizeArray</code>s are not guaranteed to be stack-allocated, in fact they will more likely <em>not</em> be stack-allocated.
However, in some <em>extremely</em> simple cases the compiler may be able to completely elide their allocations:</p>
