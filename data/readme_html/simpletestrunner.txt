<p dir="auto">Provides a <code>runtests()</code> function that does most of the work of a Julia project's <code>test/runtests.jl</code>:</p>
<p dir="auto">It assumes that it will be called from a directory that contains files with names ending in <code>_tests.jl</code>
and may contain directory trees that themselves may contain files so named. It includes each file in
a <code>@testset</code> named after the file.</p>
<p dir="auto">So, given this directory structure:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="MyPackage

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The function grew out of the <a href="https://docs.julialang.org/en/v1/stdlib/Test/#Workflow-for-Testing-Packages" rel="nofollow">Julia Workflow for Testing Packages</a> documentation and Erik Engheim's article on <a href="https://erikexplores.substack.com/p/julia-testing-best-pratice" rel="nofollow">Julia Test Running: Best Practices</a>. So it supports a variety of workflows:</p>
<ul dir="auto">
<li>Getting Started</li>
<li>Infrequent and Correct Testing</li>
<li>Regular Slow Testing</li>
<li>Rapid Iteration Testing</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Getting started</h3><a id="user-content-getting-started" class="anchor" aria-label="Permalink: Getting started" href="#getting-started"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The workflow for getting started is similar to Mr Engheim's approach, but adding <code>SimpleTestRunner</code> instead of <code>Test</code>:</p>
<ul dir="auto">
<li>Generate the main package</li>
<li>Create a test package nested inside it</li>
<li>Activate the test package</li>
<li>Add <code>SimpleTestRunner</code> to the test package</li>
<li>Use <code>SimpleTestRunner.Interactive</code> to create <code>test/setup.jl</code> and <code>test/runtests.jl</code></li>
<li>Start testing</li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Rapid Iteration Testing</h3><a id="user-content-rapid-iteration-testing" class="anchor" aria-label="Permalink: Rapid Iteration Testing" href="#rapid-iteration-testing"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This is all about staying and working from a single Julia REPL process to avoid Julia startup time.</p>
<p dir="auto">First, install the <code>Revise</code> globally:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="$ julia -e 'using Pkg; Pkg.add(&quot;Revise&quot;)'"><pre class="notranslate"><code>$ julia -e 'using Pkg; Pkg.add("Revise")'
</code></pre></div>
<p dir="auto">Now arrange for the <code>Revise</code> package to be loaded into your Julia REPL early:</p>
<p dir="auto"><code>~/.julia/config/startup.jl</code>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="if isinteractive()
    try
        using Revise
    catch e
        @warn &quot;Could not initialize Revise&quot; exception=(e, catch_backtrace())
    end
end"><pre class="notranslate"><code>if isinteractive()
    try
        using Revise
    catch e
        @warn "Could not initialize Revise" exception=(e, catch_backtrace())
    end
end
</code></pre></div>
<p dir="auto">Now start an interactive Julia REPL in the project environment:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="$ julia --project=."><pre class="notranslate"><code>$ julia --project=.
</code></pre></div>
<p dir="auto">You can now repeatedly edit/test/repeat without Julia startup overhead.</p>
<p dir="auto">Run all tests with:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; include(&quot;test/runtests.jl&quot;);"><pre class="notranslate"><code>julia&gt; include("test/runtests.jl");
</code></pre></div>
<p dir="auto">The semicolon suppresses display of the test set data structure.</p>
<p dir="auto">Individual test files can be run separately, but only after <code>test/setup.jl</code> has been run at least once
in this interactive session:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; include(&quot;test/setup.jl&quot;);
julia&gt; include(&quot;test/child/alice_tests.jl&quot;);"><pre class="notranslate"><code>julia&gt; include("test/setup.jl");
julia&gt; include("test/child/alice_tests.jl");
</code></pre></div>
<p dir="auto">Because of the way setup is handled, you can't run individual test files directly from the command-line.
But remember that the runner supports command-line arguments that select the test files you want, e.g.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="$ julia --project=. test/runtests.jl foo child/alice"><pre class="notranslate"><code>$ julia --project=. test/runtests.jl foo child/alice
</code></pre></div>
<p dir="auto">Individual tests are most easily run with copy and paste into the Julia REPL, again relying
on <code>test/setup.jl</code> having been run at least once in this interactive session:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; include(&quot;test/setup.jl&quot;);
julia&gt; @test &quot;Hello world!&quot; == greet()
Test Passed"><pre class="notranslate"><code>julia&gt; include("test/setup.jl");
julia&gt; @test "Hello world!" == greet()
Test Passed
</code></pre></div>
<p dir="auto">VS Code users may find it productive to assign a keybind to <em>Terminal: Run Selected Text In Active Terminal</em>
in the Command Palette. This allows test cases to be built up on the fly very quickly.</p>
