<p dir="auto">This Julia package supplies functions <code>CIFTI.load</code> and <code>CIFTI.save</code> for reading and writing files of the CIFTI-2 format (<a href="https://www.nitrc.org/projects/cifti" rel="nofollow">https://www.nitrc.org/projects/cifti</a>) for fMRI data, along with some convenience functions for indexing into the data matrix.</p>
<p dir="auto">The intended use is for simple, fast reading of CIFTI data. No attempt has been made to comprehensively support the CIFTI specification. For more complex use cases in Julia, I recommend instead using Julia's cross-language interoperability to take advantage of one of several more comprehensive implementations in other languages (see the <code>cifti</code> and <code>ciftiTools</code> R packages, <code>nibabel</code> in Python, etc).</p>
<p dir="auto">The <code>CIFTI.load</code> function supplied here should work for any of the common CIFTI filetypes (dtseries, dscalar, ptseries, dconn, etc). If you have a CIFTI filetype that's not supported, please send me a sample (anonymized and containing only synthetic data) and I'll add support for it.</p>
<p dir="auto">Version 1.2 introduces <code>CIFTI.save</code>, to save data out (either from a <code>CiftiStruct</code> or simply from a <code>Matrix</code>) to a copy of an existing CIFTI file on disk.</p>

<p dir="auto">The basic usage of <code>CIFTI.load</code> is demonstrated below. A <code>CiftiStruct</code> struct is returned, containing:</p>
<ul dir="auto">
<li><code>data</code>: a numeric matrix of whatever data type is specified in the cifti file header</li>
<li><code>brainstructure</code>: an OrderedDict of indices into anatomical structures as parsed from the CIFTI file's internal XML data</li>
</ul>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="x = CIFTI.load(filename)
x.data                   # access the data Matrix
x.brainstructure         # access the OrderedDict of anatomical indices"><pre class="notranslate"><code>x = CIFTI.load(filename)
x.data                   # access the data Matrix
x.brainstructure         # access the OrderedDict of anatomical indices
</code></pre></div>
<p dir="auto">When reading in a CIFTI file, transposition will occur or not occur according to the following logic:</p>
<ul dir="auto">
<li>If the file is stored on disk with spatial dimensions (either parcels or "grayordinates") along the columns but scalars or series elements along the rows (such as timepoints), the data matrix will be transposed for the sake of consistent representation.</li>
<li>If the rows and columns <em>both</em> represent spatial elements, such as in connectivity matrices (pconns and dconns), then no transposition will be done, in part to avoid the cost of transposing large data in those cases. It is expected in these cases that you'll have a symmetric connectivity matrix, so transposition will not matter; but if this does not hold true for you for some reason, then pay attention to the orientation and make sure to do any transposing yourself if necessary.</li>
</ul>
<p dir="auto">In other words: data will be transposed if it's necessary in order to ensure that there's a spatial mapping along the <em>rows</em>, so that indexing can occur in a consistent manner.</p>
<p dir="auto">Some convenience functions for indexing into <code>data</code> are also supplied, taking advantage of the <code>BrainStructure</code> enum types that constitute the keys of the <code>CiftiStruct.brainstructure</code> dictionary. Constants <code>L</code>, <code>R</code>, and <code>LR</code> are supplied as a short-hand for <code>CORTEX_LEFT</code>, <code>CORTEX_RIGHT</code>, and <code>[CORTEX_LEFT, CORTEX_RIGHT]</code>, respectively.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="x[L]   # return a Matrix where the rows correspond to CORTEX_LEFT anatomical indices

x[R]   # return a Matrix where the rows correspond to CORTEX_RIGHT anatomical indices
x[LR]  # return a Matrix where the rows correspond to left or right coritical indices
</code></pre></div>
<p dir="auto">Or you can index into the data using a vector of arbitrary <code>BrainStructure</code> keys:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="x[[AMYGDALA_LEFT, AMYGDALA_RIGHT]]
x[[AMYGDALA_RIGHT, AMYGDALA_LEFT]]"><pre class="notranslate"><code>x[[AMYGDALA_LEFT, AMYGDALA_RIGHT]]
x[[AMYGDALA_RIGHT, AMYGDALA_LEFT]]
</code></pre></div>
<p dir="auto">Important note: order matters in the vector that you specify, so the two lines above will return matrix subsets of the same size but differently sorted.</p>
<p dir="auto">As of version 1.2, data from a <code>CiftiStruct</code> or <code>Matrix</code> can be written to disk by specifying a <code>template</code>, i.e. an existing CIFTI file that has the desired properties. A copy of <code>template</code> will be created on disk, with its data component replaced with the new data that you supply.</p>
