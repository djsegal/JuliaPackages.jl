<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Introduction</h2><a id="user-content-introduction" class="anchor" aria-label="Permalink: Introduction" href="#introduction"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package provides the functions <code>freeze()</code> to freeze your Julia environment by adding the current versions of your package environment to the <code>[compat]</code> section of your project, and the function <code>lower_bound()</code> to set a lower bound of the versions of your packages.
If a <code>[compat]</code> section already exists it is overwritten without warning, so make a backup of your <code>Project.toml</code> file first.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Background</h3><a id="user-content-background" class="anchor" aria-label="Permalink: Background" href="#background"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For reproducible research it is important to document the version of all packages you used to
achieve a result that you published in a paper. This package makes it easy to do this. Compared to committing the <code>Manifest.toml</code> this approach has the following advantages:</p>
<ul dir="auto">
<li>the project stays compatible with different Julia versions;</li>
<li>changes in the git log are readable (I find the Manifest.toml file unreadable, YMMV).</li>
</ul>
<p dir="auto">Freezing your package versions has one more advantage: It can avoid unwanted package updates when adding new packages to your project.</p>

</code></pre></div>

<p dir="auto">You can also use ranges, e.g.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="freeze(Pkg; julia=&quot;1.6 - 1.11&quot;)"><pre><span class="pl-c1">freeze</span>(Pkg; julia<span class="pl-k">=</span><span class="pl-s"><span class="pl-pds">"</span>1.6 - 1.11<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">If you use a range there must be a space around the hyphen.</p>
<p dir="auto">You can also call:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="freeze(Pkg; relaxed=true)"><pre><span class="pl-c1">freeze</span>(Pkg; relaxed<span class="pl-k">=</span><span class="pl-c1">true</span>)</pre></div>
<p dir="auto">This omits the patch version from the generated <code>compat</code> entry. The effect is that non-braking updates of the packages are allowed. While updates of the patch version SHOULD be non-braking, this is not always the case. Use this option with care.</p>
<p dir="auto">More info about the version specifiers can be found <a href="https://pkgdocs.julialang.org/v1/compatibility/" rel="nofollow">here</a>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Keeping your existing compats</h3><a id="user-content-keeping-your-existing-compats" class="anchor" aria-label="Permalink: Keeping your existing compats" href="#keeping-your-existing-compats"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">From version 0.3.0 onwards, there exists the <code>keep</code> keyword argument to both the <code>freeze</code> and <code>lower_bound</code> functions.
This argument when <code>true</code> (the default) will keep any existing compat entries from the Project.toml.
These compat <em>values</em> are kept <em>exactly as is</em> with all specifiers intact.
Their order may however be affected by the call to <code>freeze</code> or <code>lower_bound</code>.
Setting <code>keep</code> to <code>false</code> will result in the previous behaviour of the compat section being overwritten entirely.</p>
