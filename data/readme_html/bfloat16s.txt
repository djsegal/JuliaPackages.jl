<p dir="auto">This package defines the <a href="https://en.wikipedia.org/wiki/Bfloat16_floating-point_format" rel="nofollow">BFloat16 data type</a>,
a floating-point format with 1 sign bit, 8 exponent bits and 7 mantissa bits.</p>
<p dir="auto">Hardware implementation of this datatype is available in Google's
<a href="https://en.wikipedia.org/wiki/Tensor_processing_unit" rel="nofollow">Cloud TPUs</a> as well as
in a growing number of CPUs, GPUs, and more specialized processors. See the
<a href="https://en.wikipedia.org/wiki/Bfloat16_floating-point_format" rel="nofollow">wikipedia entry</a>
for more information.</p>
<p dir="auto">This package is suitable to evaluate whether using BFloat16 would cause
precision problems for any particular algorithm, even without access to supporting
hardware. Note that this package is designed for functionality, not performance,
so this package should be used for precision experiments only, not performance
experiments.</p>

<p dir="auto">This package exports the <code>BFloat16</code> data type. This datatype behaves
just like any built-in floating-point type</p>

a method for <code>BFloat16</code> although it should. In this case, please raise an issue so that we can
close the gap in support compared to other low-precision types like <code>Float16</code>. The usage
of <code>BFloat16</code> should be as smooth as the following example, solving a linear equation system</p>

<p dir="auto">In addition, this package provides the <code>LowPrecArray</code> type.
This array is supposed to emulate the kind
of matrix multiplications that TPUs do well (BFloat16 multiply with Float32
accumulate). Broadcasts and scalar operations are peformed in Float32 (as
they would be on a TPU) while matrix multiplies are performed in BFloat16 with
Float32 accumulates, e.g.</p>
