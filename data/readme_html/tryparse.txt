<p dir="auto">When working interactively or interacting with other sources of data, one can find oneself in a situation, where one needs to construct Julia objects from a given string. While this is in general a hard problem, in practice it is more managable, as the types are restricted to a small set, including numbers, arrays or tuples. For number types <code>Base.tryparse</code> provides this functionality, as long as the string is a literal interger.
Here we provide a function <code>Tryparse.tryparse</code>, which does the same as <code>Base.tryparse</code>, but allows (for number types) a wider range of basic types as well expressions. Here is a short example, which illustrates the functionality:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; Base.tryparse(Int, &quot;2 + 3^2 - 2 * 3&quot;) === nothing # this means, parsing could not be done

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Notable difference to the REPL experience</h2><a id="user-content-notable-difference-to-the-repl-experience" class="anchor" aria-label="Permalink: Notable difference to the REPL experience" href="#notable-difference-to-the-repl-experience"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In almost all cases, executing <code>Tryparse.tryparse(T, x)</code> will yield the same result as entering <code>x</code> in the REPL and hitting enter. One situation, where this is not the case, is related to arithmetic expressions and overflow. The function <code>Tryparse.tryparse</code> will always first parse all literal numbers and then evaluate the expression. For example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; BigInt(2^64)
0

julia&gt; Tryparse.tryparse(BigInt, &quot;2^64&quot;)
18446744073709551616"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-c1">BigInt</span>(<span class="pl-c1">2</span><span class="pl-k">^</span><span class="pl-c1">64</span>)
<span class="pl-c1">0</span>

julia<span class="pl-k">&gt;</span> Tryparse<span class="pl-k">.</span><span class="pl-c1">tryparse</span>(BigInt, <span class="pl-s"><span class="pl-pds">"</span>2^64<span class="pl-pds">"</span></span>)
<span class="pl-c1">18446744073709551616</span></pre></div>
<p dir="auto">This choice of behavior is on purpose, to make working with command line arguments less painful.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Command line argument parsing</h2><a id="user-content-command-line-argument-parsing" class="anchor" aria-label="Permalink: Command line argument parsing" href="#command-line-argument-parsing"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The reason this package exists is parsing of command line arguments for julia scripts. Command line scripts are invokved in the form</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="bla@home&gt; julia script.jl arg1 arg2"><pre>bla@home<span class="pl-k">&gt;</span> julia script.jl arg1 arg2</pre></div>
<p dir="auto">In this situation, inside <code>script.jl</code>, the arguments are available only as strings and thus need to be processed. Here is where <code>Tryparse.tryparse</code> comes into play.</p>
<p dir="auto">Similarly, if one uses ArgParse.jl, ArgMacros.jl or Comonicon.jl (those packages are highly recommended!), this looks like</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="bla@home&gt; julia script.jl --opt1=arg1 --opt2=arg2"><pre>bla@home<span class="pl-k">&gt;</span> julia script.jl --opt1=arg1 --opt2=arg2</pre></div>
<p dir="auto">and one can specifiy what the types of <code>arg1</code> and <code>arg2</code>. But this will work only for types and strings, for which <code>Base.tryparse</code> respectively <code>Base.parse</code> works. For example, out of the box</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="bla@home&gt; julia script.jl --opt1=&quot;10^10&quot; --opt2=&quot;[2, 3]&quot;"><pre>bla@home<span class="pl-k">&gt;</span> julia script.jl --opt1=<span class="pl-s"><span class="pl-pds">"</span>10^10<span class="pl-pds">"</span></span> --opt2=<span class="pl-s"><span class="pl-pds">"</span>[2, 3]<span class="pl-pds">"</span></span></pre></div>
<p dir="auto">would not work, whereas this is possible with <code>Tryparse</code>. We illustrate how to use <code>Tryparse</code> together with <a href="https://github.com/carlobaldassi/ArgParse.jl">ArgParse.jl</a>, <a href="https://github.com/zachmatson/ArgMacros.jl">ArgMacros.jl</a> and <a href="https://github.com/comonicon/Comonicon.jl">Comonicon.jl</a>.</p>

<p dir="auto">Enabling parsing of command line arguments is straight forward for ArgParse.jl. Just add (one of) the following lines to your script:</p>
