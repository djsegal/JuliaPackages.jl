<p dir="auto">DirectSearch.jl provides a framework for the implementation of direct search algorithms, currently focusing on the Mesh Adaptive Direct Search (MADS) family. These are derivative free, black box algorithms, meaning that no analytical knowledge of the objective function or any constraints are needed. This package provides the core MADS algorithms (LTMADS, OrthoMADS, granular variables and dynamic scaling, as well as progressive and extreme barrier constraints), and is designed to allow custom algorithms to be easily added.</p>

<p dir="auto">A more detailed guide is available in the <a href="https://imperialcollegelondon.github.io/DirectSearch.jl/dev/man/usage/" rel="nofollow">documentation</a>.</p>
<p dir="auto">A problem is defined with <code>DSProblem(N)</code>, where N is the dimension of the problem. The objective function and initial point need to be set before optimization can run.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="obj(x) = x'*[2 1;1 4]*x + x'*[1;4] + 7;

p <span class="pl-k">=</span> <span class="pl-c1">DSProblem</span>(<span class="pl-c1">2</span>; objective<span class="pl-k">=</span>obj, initial_point<span class="pl-k">=</span>[<span class="pl-c1">1.0</span>,<span class="pl-c1">2.0</span>]);</pre></div>
<p dir="auto">Note that the objective function is assumed to take a vector of points of points as the input, and return a scalar cost. The initial point should be an array of the same dimensions of the problem, and feasible with respect to any extreme barrier constraints. See <code>DSProblem</code>'s documentation for a full list of parameters.</p>
<p dir="auto">Parameters can also be set after generation of the problem:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="p = DSProblem(2)

<span class="pl-c1">SetObjective</span>(p,obj)</pre></div>
<p dir="auto">Run the algorithm with <code>Optimize!</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="Optimize!(p)"><pre><span class="pl-c1">Optimize!</span>(p)</pre></div>
<p dir="auto">This will run MADS until one of the defined stopping conditions is met. By default, the stopping conditions are set to the iteration limit (default 1000), function evaluation limit (default 5000), mesh precision limit (<code>Float64</code> precision) and poll precision limit (<code>Float64</code> precision). For more details on stopping conditions, and how to add a custom one see <a href="https://imperialcollegelondon.github.io/DirectSearch.jl/dev/man/addstoppingconditions/" rel="nofollow">Adding Stopping Conditions</a> in the documentation.</p>

<p dir="auto">If variables other than continuous, such as integers, are desired to be used, this can be specified through the granularity of the problem variables. The granularity is taken to be 0 for continuous variables and 1 for integers. The granularity can be any non-negative value.</p>
<p dir="auto">If the granularity for a single variable is required to be defined, it can be set with <code>SetGranularity</code>. <code>i</code> is the index of the variable, and the following number is the granularity.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="SetGranularity(p, i, 0.1)"><pre><span class="pl-c1">SetGranularity</span>(p, i, <span class="pl-c1">0.1</span>)</pre></div>
<p dir="auto">The same operation can be applied to multiple variables by passing a collection of <code>key =&gt; value</code> pairs to the <code>SetGranularity</code> function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="SetGranularity(p, Dict( 1 =&gt; 0.1, 2 =&gt; 0.2 ))"><pre><span class="pl-c1">SetGranularity</span>(p, <span class="pl-c1">Dict</span>( <span class="pl-c1">1</span> <span class="pl-k">=&gt;</span> <span class="pl-c1">0.1</span>, <span class="pl-c1">2</span> <span class="pl-k">=&gt;</span> <span class="pl-c1">0.2</span> ))</pre></div>

<p dir="auto">Two kinds of constraints are included, progressive barrier, and extreme barrier constraints. As with the objective function, these should be specified as a Julia function that takes a vector, and returns a value.</p>

<p dir="auto">Progressive barrier constraints may be violated, transforming the optimization into a dual-objective form that attempts to decrease the amount that the constraint is violated by. Functions that implement a progressive barrier constraint should take a point input and return a numerical value that indicates the constraint violation amount (≤0 for feasible, &gt;0 for infeasible). Added via <code>AddProgressiveConstraint</code>:</p>
