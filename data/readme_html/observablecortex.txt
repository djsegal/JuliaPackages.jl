<p dir="auto">This package aims to replicate much of the functionality of <a href="https://humanconnectome.org/software/connectome-workbench" rel="nofollow">Connectome Workbench</a>'s GUI software <code>wb_view</code> for viewing 3d cortical surface meshes, but with the advantages of a programmatic interface and access to all of the <a href="https://docs.makie.org/stable/" rel="nofollow">Makie.jl</a> and <a href="https://juliagizmos.github.io/Observables.jl/stable/" rel="nofollow">Observables.jl</a> functions for interactive 3d plotting and animations in Julia.</p>
<p dir="auto">To do this, this package just transparently manages a few things that make it easier for you (in the context of surface space fMRI) to take full advantage of Makie and Observables:</p>
<ul dir="auto">
<li>Convert your surface into a format required by Makie's <code>mesh</code> plotting function</li>
<li>Split your <code>color</code> vector (the colors to be plotted on the brain) into left and right hemispheres, if necessary</li>
<li>Pad the <code>color</code> vector to account for medial wall, if necessary, in order to match the underlying surface geometry</li>
<li>Arrange the visualization into a customary 4-panel layout showing lateral and medial views of the left and right hemispheres (or allow you the flexibility to specify a custom arrangement)</li>
<li>Provide some commonly used color schemes from the literature</li>
<li>Enable easy access to more complex visualizations requiring graph traversal-based operations, such as plotting region borders (<em>not yet implemented</em>)</li>
</ul>
<p dir="auto">This is a work in progress. Basic functionality is available and usable right now. Much more is coming soon.</p>

<p dir="auto">First, to bring in some related packages we'll need:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="using JLD

using CorticalSurfaces
using Colors
using ObservableCortex
</code></pre></div>
<p dir="auto">Then a <code>CorticalSurface</code> struct must be created to supply the surface geometry, medial wall definition, etc. I omit this part for brevity here, but see <code>examples/surface_setup.jl</code> for details. We'll call the resulting struct <code>c</code> in the code examples below.</p>
<p dir="auto">You can then define a <code>Montage</code> which is just a struct that contains several of the things Makie will need to know in order to construct the plot:</p>
<ul dir="auto">
<li><strong>views</strong>: an <code>OrthographicLayout</code> defining the set of brain views you want to visualize (here we'll just use <code>default_views</code> to get a four-panel arrangement of medial and lateral views)</li>
<li><strong>grid</strong>: a <code>Makie.GridLayout</code> that will be used to organize and render the surface views</li>
<li><strong>surface</strong>: a <code>CorticalSurface</code> that supplies the geometry for the surface mesh (see <a href="https://github.com/myersm0/CorticalSurfaces.jl">CorticalSurfaces.jl</a>)</li>
</ul>
<p dir="auto">Then, in the call to <code>plot!</code> below, the argument <code>colors</code> can be any <code>Vector{T} where T &lt;: Union{AbstractFloat, Colorant}</code>. Its length should be equal to the total number of vertices in the surface <code>c</code>, with or without medial wall. A common use case will be working with data from a <a href="https://github.com/myersm0/CIFTI.jl">CIFTI</a> file, which typically will include both hemispheres in a single matrix and will omit the medial wall. The <code>Montage</code> struct from this package will know how to handle these cases, because it knows from its component <code>c::CorticalSurface</code> about properties of the surface like medial wall location and the number of vertices in each hemisphere. This implies the additional expectation that your <code>color</code> vector must be from data in the same space as that of the surface that you provided, which will be the case if you consistently work with a certain surface space representation such as the so-called fsLR_32k space.</p>
<p dir="auto">You can also supply arbitrary additional keyword arguments that will simply be delegated to <code>Makie.mesh!</code>. (To generate the below image, I also added a <code>Colorbar</code> but I omit that step here for brevity; see <code>examples/demo.jl</code>.)</p>

To do so, first of all you need to be able to access the <code>Axis3</code> object that corresponds to the specific panel(s) that you want to work with. Several ways to do this are provided. Note the pluralization of the function name in the third line:</p>

<p dir="auto">As of version 0.3, plotting discrete-valued data such as parcels (see <a href="https://github.com/myersm0/CorticalParcels.jl">CorticalParcels.jl</a>) is now supported. You can supply a <code>colormap</code> dictionary that maps all parcel keys (as well as zero) to a <code>Colorant</code>, or you can omit this and use the default set of <code>distinguishable_colors</code> from the <code>Colors</code> package. If <code>parcel_file</code> is the path to a CIFTI file containing a set of parcels you want to visualize:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="using CorticalParcels
