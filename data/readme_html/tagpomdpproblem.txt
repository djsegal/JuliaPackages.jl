<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Problem description</h2><a id="user-content-problem-description" class="anchor" aria-label="Permalink: Problem description" href="#problem-description"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The goal of the agent is to tag the opponent by performing the tag action while in the same square as the opponent.</p>
<ul dir="auto">
<li>
<p dir="auto"><strong>States</strong>: position of the robot and target and whether the target has been tagged or not</p>
</li>
<li>
<p dir="auto"><strong>Actions</strong>:  The agent can move in the four cardinal directions or perform the tag action. When performing the <code>tag</code> action, the robot does not move. The target moves during <code>tag</code> if the robot and target are not at the same location.</p>
</li>
<li>
<p dir="auto"><strong>Transition model</strong>: The movement of the agent is deterministic based on its selected action. The opponent moves stochastically according to a fixed policy away from the agent. The opponent moves away from the agent <code>move_away_probability</code> of the time and stays in the same cell otherwise. The implementation of the opponent’s movement policy varies slightly from the original paper allowing more movement away from the agent, thus making the scenario slightly more challenging. This implementation redistributes the probabilities of actions that result in hitting a wall to other actions that result in moving away. See the <code>transitions.jl</code> for details. The transition function from the original implementation can be used by passing <code>transition_option=:orig</code>.</p>
</li>
<li>
<p dir="auto"><strong>Observation model</strong>: The agent’s position is fully observable but the opponent’s position is unobserved unless both actors are in the same cell. The number of observations is one more than the number of grid squares (e.g. 30 observations for the default problem).</p>
</li>
<li>
<p dir="auto"><strong>Reward model</strong>: A reward of <code>step_penalty</code> is imposed for each motion action and the tag action results in a <code>tag_reward</code> for a successful tag and <code>tag_penalty</code> otherwise.</p>
</li>
</ul>
