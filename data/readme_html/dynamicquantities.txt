<p dir="auto">DynamicQuantities defines a simple statically-typed <code>Quantity</code> type for Julia.
Physical dimensions are stored as a <em>value</em>, as opposed to a parametric type, as in <a href="https://github.com/PainterQubits/Unitful.jl">Unitful.jl</a>.
This can greatly improve both runtime performance, by avoiding type instabilities, and startup time, as it avoids overspecializing methods.</p>

<p dir="auto">DynamicQuantities can greatly outperform Unitful
when the compiler cannot infer dimensions in a function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using BenchmarkTools, DynamicQuantities; import Unitful

julia&gt; dyn_uni = 0.2u&quot;m/s&quot;
0.2 m s⁻¹

julia&gt; unitful = convert(Unitful.Quantity, dyn_uni)
0.2 m s⁻¹

julia&gt; f(x, i) = x ^ i * 0.3;

julia&gt; @btime f($dyn_uni, 1);
  2.708 ns (0 allocations: 0 bytes)

julia&gt; @btime f($unitful, 1);
  2.597 μs (30 allocations: 1.33 KiB)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">using</span> BenchmarkTools, DynamicQuantities; <span class="pl-k">import</span> Unitful

julia<span class="pl-k">&gt;</span> dyn_uni <span class="pl-k">=</span> <span class="pl-c1">0.2</span><span class="pl-s"><span class="pl-pds"><span class="pl-c1">u</span>"</span>m/s<span class="pl-pds">"</span></span>
<span class="pl-c1">0.2</span> m s⁻¹

julia<span class="pl-k">&gt;</span> unitful <span class="pl-k">=</span> <span class="pl-c1">convert</span>(Unitful<span class="pl-k">.</span>Quantity, dyn_uni)
<span class="pl-c1">0.2</span> m s⁻¹

julia<span class="pl-k">&gt;</span> <span class="pl-en">f</span>(x, i) <span class="pl-k">=</span> x <span class="pl-k">^</span> i <span class="pl-k">*</span> <span class="pl-c1">0.3</span>;

julia<span class="pl-k">&gt;</span> <span class="pl-c1">@btime</span> <span class="pl-c1">f</span>(<span class="pl-k">$</span>dyn_uni, <span class="pl-c1">1</span>);
  <span class="pl-c1">2.708</span> ns (<span class="pl-c1">0</span> allocations<span class="pl-k">:</span> <span class="pl-c1">0</span> bytes)

julia<span class="pl-k">&gt;</span> <span class="pl-c1">@btime</span> <span class="pl-c1">f</span>(<span class="pl-k">$</span>unitful, <span class="pl-c1">1</span>);
  <span class="pl-c1">2.597</span> μs (<span class="pl-c1">30</span> allocations<span class="pl-k">:</span> <span class="pl-c1">1.33</span> KiB)</pre></div>
<p dir="auto"><strong>Note the μ and n: this is a 1000x speedup!</strong>
Here, the DynamicQuantities quantity object allows the compiler to build a function that is type stable,
while the Unitful quantity object, which stores its dimensions in the type, requires type inference at runtime.</p>
<p dir="auto">However, if the dimensions in your function <em>can</em> be inferred by the compiler,
then you can get better speeds with Unitful:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; g(x) = x ^ 2 * 0.3;

julia&gt; @btime g($dyn_uni);
  1.791 ns (0 allocations: 0 bytes)

julia&gt; @btime g($unitful);
  1.500 ns (0 allocations: 0 bytes)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-en">g</span>(x) <span class="pl-k">=</span> x <span class="pl-k">^</span> <span class="pl-c1">2</span> <span class="pl-k">*</span> <span class="pl-c1">0.3</span>;

julia<span class="pl-k">&gt;</span> <span class="pl-c1">@btime</span> <span class="pl-c1">g</span>(<span class="pl-k">$</span>dyn_uni);
  <span class="pl-c1">1.791</span> ns (<span class="pl-c1">0</span> allocations<span class="pl-k">:</span> <span class="pl-c1">0</span> bytes)

julia<span class="pl-k">&gt;</span> <span class="pl-c1">@btime</span> <span class="pl-c1">g</span>(<span class="pl-k">$</span>unitful);
  <span class="pl-c1">1.500</span> ns (<span class="pl-c1">0</span> allocations<span class="pl-k">:</span> <span class="pl-c1">0</span> bytes)</pre></div>
<p dir="auto">While both of these are type stable,
because Unitful parametrizes the type on the dimensions, functions can specialize
to units and the compiler can optimize away units from the code.</p>

by using the convenience macro <code>u"..."</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; x = 0.3u&quot;km/s&quot;

julia<span class="pl-k">&gt;</span> y <span class="pl-k">=</span> <span class="pl-c1">42</span> <span class="pl-k">*</span> <span class="pl-s"><span class="pl-pds"><span class="pl-c1">u</span>"</span>kg<span class="pl-pds">"</span></span>
<span class="pl-c1">42.0</span> kg</pre></div>
<p dir="auto">or by importing explicitly:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using DynamicQuantities: kPa

<p dir="auto">Note that <code>Units</code> is an exported submodule, so you can
also access this as <code>Units.kPa</code>. You may like to define</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; const U = Units"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">const</span> U <span class="pl-k">=</span> Units</pre></div>
<p dir="auto">so that you can simply write, say, <code>U.kPa</code> or <code>C.m_e</code>.</p>
<p dir="auto">This supports a wide range of SI base and derived units, with common
prefixes.</p>
<p dir="auto">You can also construct values explicitly with the <code>Quantity</code> type,
with a value and keyword arguments for the powers of the physical dimensions
(<code>mass</code>, <code>length</code>, <code>time</code>, <code>current</code>, <code>temperature</code>, <code>luminosity</code>, <code>amount</code>):</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; x = Quantity(300.0, length=1, time=-1)
