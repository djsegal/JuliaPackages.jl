<p dir="auto">A Julia port of "Routines for Arbitrary Precision Floating-point Arithmetic and Fast Robust Geometric Predicates"
by Jonathan Richard Shewchuk. <a href="https://www.cs.cmu.edu/~quake/robust.html" rel="nofollow">https://www.cs.cmu.edu/~quake/robust.html</a></p>
<p dir="auto">The package provides four predicates. In the functions below, all the inputs should be <code>NTuple</code>s with either <code>Float64</code> or <code>Float32</code> coordinates; complex inputs can be used for <code>orient2</code> and <code>incircle</code>.</p>
<ul dir="auto">
<li><code>orient2(pa, pb, pc)</code>: Given three points <code>pa</code>, <code>pb</code>, and <code>pc</code> in two dimensions, returns a positive value if the points are in counter-clockwise order; a negative value if they occur in clockwise order; and zero if they are collinear. Equivalently, returns a positive value if <code>pc</code> is left of the oriented line from <code>pa</code> to <code>pb</code>; a negative value if <code>pc</code> is right of this line; and zero if they are collinear.</li>
<li><code>orient3(pa, pb, pc, pd)</code>: Given four points <code>pa</code>, <code>pb</code>, <code>pc</code>, and <code>pd</code> in three dimensions, define the oriented plane on which the triangle <code>(pa, pb, pc)</code> is positively oriented. Returns a positive value if <code>pd</code> is below this plane; a negative value if <code>pd</code> is above this plane; and zero if the points are coplanar.</li>
<li><code>incircle(pa, pb, pc, pd)</code>: Given four points <code>pa</code>, <code>pb</code>, <code>pc</code>, and <code>pd</code> in two dimensions, returns a positive value if <code>pd</code> is inside the circle through <code>pa</code>, <code>pb</code>, and <code>pc</code>; a negative value if <code>pd</code> is outside this circle; and zero if <code>pd</code> is on the circle.</li>
<li><code>insphere(pa, pb, pc, pd, pe)</code>: Given five points <code>pa</code>, <code>pb</code>, <code>pc</code>, <code>pd</code>, and <code>pe</code> in three dimensions, returns a positive value if <code>pe</code> inside of the sphere through <code>pa</code>, <code>pb</code>, <code>pc</code>, and <code>pd</code>; a negative value if <code>pe</code> is outside this sphere; and zero if <code>pe</code> is on the sphere.</li>
</ul>
<p dir="auto">We also define the functions <code>orient2p</code>, <code>orient3p</code>, <code>incirclep</code>, and <code>inspherep</code> which simply return the sign of the corresponding predicate. For example,</p>

<p dir="auto">All the functions from the <code>predicates.c</code> file from Shewchuk's original code have been included in this package. This includes,</p>
<ul dir="auto">
<li>All macros have been implemented as functions, e.g. <code>Fast_Two_Sum</code> and <code>Four_Four_Sum</code>.</li>
<li>All arithmetic functions have been implemented, e.g. <code>grow_expansion</code> and <code>scale_expansion_zeroelim</code>.</li>
<li>All the predicates have been implemented. In particular, not only have <code>orient2</code>, <code>orient3</code>, <code>incircle</code>, and <code>insphere</code> been implemented, but also the forms with the suffixes <code>fast</code>, <code>exact</code>, and <code>slow</code> (and <code>adapt</code>, but this is what <code>orient2</code>, <code>orient3</code>, <code>incircle</code>, and <code>insphere</code> use anyway).</li>
</ul>
<p dir="auto">Only the functions <code>orient2</code>, <code>orient3</code>, <code>incircle</code>, and <code>insphere</code> have been marked as <code>public</code>, as well as their <code>p</code> and <code>fast</code> counterparts.</p>

<p dir="auto">Shewchuk's original paper gives no analysis in the presence of underflow or overflow. The only mention of it is:</p>
<blockquote>
<p dir="auto">This article does not address issues of overflow and underflow, so I allow the exponent to be an integer in the range  <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="959b6e336ab210a2b245d1b3bd40a570">$[-\infty, \infty]$</math-renderer>. (Fortunately, many applications have inputs whose exponents fall within a circumscribed range. The four predicates implemented for this article will not overflow nor underflow if their inputs have exponents in the range <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="959b6e336ab210a2b245d1b3bd40a570">$[-142, 201]$</math-renderer> and IEEE 754 double precision arithmetic is used.)</p>
</blockquote>
<ul dir="auto">
<li>Richard Shewchuk, J. Adaptive Precision Floating-Point Arithmetic and Fast Robust Geometric Predicates. Discrete Comput Geom 18(3), 305–363 (1997)</li>
</ul>
<p dir="auto">Note that this range comes from the <code>insphere</code> predicate. The number range is much wider for <code>orient2</code>, for example, since it requires far fewer additions, subtractions, and multiplications.</p>
<p dir="auto">Thus, for some numbers, the values returned from these predicates may be invalid due to underflow or overflow. In ranges where this is a concern, you should use <a href="https://github.com/lairez/ExactPredicates.jl">ExactPredicates.jl</a> instead. If you need the values of the predicates and not just their signs, but are outside of the range valid for AdaptivePredicates.jl, you are unfortunately out of luck.</p>
<p dir="auto">If you need more information about how these predicates work, you should refer to Shewchuk's paper.</p>
