<p dir="auto"><code>ChemistryQuantitativeAnalysis.jl</code> is a package for quantitative analysis of chemicals based on tabular data.</p>
<p dir="auto">For command line interfaces, see <a href="https://github.com/yufongpeng/juliaquant"><code>juliaquant</code></a>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Tabular data wrapper</h2><a id="user-content-tabular-data-wrapper" class="anchor" aria-label="Permalink: Tabular data wrapper" href="#tabular-data-wrapper"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package provides two wrappers for data, <code>SampleDataTable{A, S, N, T}</code> and <code>AnalyteDataTable{A, S, N, T}</code> which are subtypes of <code>AbstractDataTable{A, S, N, T}</code>. <code>SampleDataTable</code> indicates that part of columns represent analytes, and all rows reprsent samples. <code>AnalyteDataTable</code> indicates that part of columns represent samples, and all rows represent analytes. Both types behave like the underlying <code>table</code> object.</p>

<p dir="auto"><code>SampleDataTable{A, S, N, T}</code> can be constructed in the following ways:</p>
<ol dir="auto">
<li><code>SampleDataTable(analytetype::TypeOrFn, samplecol::Symbol, table; analytename = setdiff(propertynames(table), [samplecol]))</code></li>
<li><code>SampleDataTable(table, analytetype::TypeOrFn, samplecol::Symbol; analytename = setdiff(propertynames(table), [samplecol]))</code></li>
<li><code>SampleDataTable(samplecol::Symbol, table; analytename = setdiff(propertynames(table), [samplecol]))</code></li>
<li><code>SampleDataTable(table, samplecol::Symbol; analytename = setdiff(propertynames(table), [samplecol]))</code></li>
</ol>
<p dir="auto"><code>AnalyteDataTable{A, S, N, T}</code> can be constructed in the following ways:</p>
<ol dir="auto">
<li><code>AnalyteDataTable(analytecol::Symbol, sampletype::TypeOrFn, table; samplename = setdiff(propertynames(table), [analytecol]))</code></li>
<li><code>AnalyteDataTable(table, analytecol::Symbol, sampletype::TypeOrFn; samplename = setdiff(propertynames(table), [analytecol]))</code></li>
<li><code>AnalyteDataTable(analytecol::Symbol, table; samplename = setdiff(propertynames(table), [analytecol]))</code></li>
<li><code>AnalyteDataTable(table, analytecol::Symbol; samplename = setdiff(propertynames(table), [analytecol]))</code></li>
</ol>
<p dir="auto"><code>analaytename</code> and <code>samplename</code> will be converted to a vector of string, and then converted to the desired type using <code>cqaconvert(analytetype, analaytename)</code> and <code>cqaconvert(sampletype, samplename)</code>.</p>

<p dir="auto"><code>AnalysisMethod{A, M, C, D}</code> is used for storing method, containing all analytes, their internal standards and calibration curve setting, and data for fitting calibration curve.</p>

<p dir="auto">The key for signal data is determined by <code>method.signal</code>. Default names for relative signal, true concentration, estimated concentration and accuracy are <code>relative_signal</code>, <code>true_concentration</code>, <code>estimated_concentration</code> and <code>accuracy</code>.</p>
<p dir="auto"><code>AnalysisTable{A, S, T}</code> can be constructed in the following ways:</p>
<ol dir="auto">
<li><code>AnalysisTable(keys::AbstractVector{Symbol}, tables::AbstractVector{&lt;: AbstractDataTable{A, S}})</code></li>
<li><code>analysistable(iter)</code></li>
</ol>
<p dir="auto"><code>iter</code> is an iterable iter of key-value <code>Pair</code>s (or other iterables of two elements, such as a two-tuples). Keys should be <code>Symbol</code>s, and values should be <code>AbstractDataTable</code>s.</p>

<p dir="auto">To read a batch into julia, call <code>ChemistryQuantitativeAnalysis.read</code>.</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; batch = ChemistryQuantitativeAnalysis.read(&quot;batch_name.batch&quot;, T; table_type, analytetype, delim)"><pre>julia&gt; batch <span class="pl-k">=</span> ChemistryQuantitativeAnalysis<span class="pl-k">.</span><span class="pl-c1">read</span>(<span class="pl-s"><span class="pl-pds">"</span>batch_name.batch<span class="pl-pds">"</span></span>, T; table_type, analytetype, delim)</pre></div>
<p dir="auto"><code>T</code> is the sink function for tabular data; it should create an object following <code>Tables.jl</code> interface. <code>table_type</code> is <code>T</code> parameter in the type signature of <code>Batch</code> which determines the underlying table type, <code>analytetype</code> is a concrete type for <code>analyte</code>, <code>sampletype</code> is a concrete type for <code>sample</code>, and <code>delim</code> specifies delimiter for tabular data if <code>config[:delim]</code> does not exist.</p>
<p dir="auto">For <code>analytetype</code> and <code>sampletype</code>, <code>string(cqaconvert(analytetype, x))</code> and <code>string(cqaconvert(sampletype, x))</code> should equal <code>x</code> if <code>x</code> is a valid string. <ul dir="auto">
<li><code>tryparse(::Type{analytetype}, x::AbstractString)</code> is neccessary for <code>AnalyteDataTable</code>.</li>
<li><code>tryparse(::Type{sampletype}, x::AbstractString)</code> is neccessary for <code>SampleDataTable</code>.</li>
</ul>

const CQA = ChemistryQuantitativeAnalysis
import Base: show, convert, tryparse

# Custom Analyte type
struct AnalyteG1
    name::String
end
struct AnalyteG2
    name::String
end
struct AnalyteOther
    name::String
end
const AnalyteTest = Union{AnalyteG1, AnalyteG2, AnalyteOther} # Use Union rather than abstarct type because csv parser only support concrete type
show(io::IO, analyte::AnalyteTest) = print(io, analyte.name)

# Analyte parser
function (::Type{AnalyteTest})(name::String)
    g = match(r&quot;^G(\d)\(.*\)$&quot;, name)
    isnothing(g) &amp;&amp; return AnalyteOther(name)
    g = parse(Int, first(g))
    g == 1 ? AnalyteG1(name) : g == 2 ? AnalyteG2(name) : AnalyteOther(name)
end
tryparse(::Type{AnalyteTest}, s::String) = AnalyteTest(s) # For reading data from disk

# Generate data
analytes = typedmap(AnalyteTest, [&quot;G1(drug_a)&quot;, &quot;G2(drug_a)&quot;, &quot;G1(drug_b)&quot;, &quot;G2(drug_b)&quot;])
conc = Float64[1, 2, 5, 10, 20, 50, 100]
signal1 = vcat(Float64[1, 2, 5, 10, 20, 50, 100], [1, 2, 5, 10, 20, 50, 100] .+ 0.1, [1, 2, 5, 10, 20, 50, 100] .- 0.1)
