<p dir="auto">Use SQLite tables as Array- or Dict-like collections.</p>
<p dir="auto"><code>SQLStore.jl</code> is not an ORM and doesn't try to be. It effectively maps SQL tables to the simplest Julia collections, following Array and Dict interfaces as possible.</p>
<p dir="auto"><code>SQLStore.jl</code> supports both native SQLite datatypes and serialization to JSON or Julia Serialization formats. It automatically creates table schemas based on Julia types, adding constraints when necessary. As an example, for a field of Julia type <code>Int</code>, the SQLite column definition is <code>colname int not null check (typeof(colname) = 'integer')</code>. This ensures that only values of proper types can end up in the table, despite the lack of strict typing in SQLite itself.</p>
<p dir="auto">For array-like collections, <code>SQLStore.jl</code> uses <code>push!</code> to insert elements into the collection. Selection and filtering uses functions like <code>collect</code>, <code>filter</code>, <code>only</code> and others. Main data modification functions: <code>update!</code>, <code>updateonly!</code>, <code>updatesome!</code>, and similarly with <code>delete!</code>. Values of supported Julia types are automatically converted to/from corresponding SQLite types.</p>
<p dir="auto">See the <a href="https://aplavin.github.io/SQLStore.jl/test/examples.html" rel="nofollow">Pluto notebook</a> for more examples, and docstrings for more details on specific functions.</p>
