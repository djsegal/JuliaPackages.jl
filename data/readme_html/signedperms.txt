<p dir="auto"><a id="user-content-signedperms" href="#SignedPerms">#</a>
<strong><code>SignedPerms</code></strong> — <em>Module</em>.</p>
<p dir="auto">A  signed permutation of <code>1:n</code> is  a permutation of the set <code>-n,…,-1,1,…,n</code> which  preserves the  pairs <code>(-i,i)</code>.  It is  represented internally as the images of <code>1:n</code>. It is printed as a product of signed cycles.</p>
<p dir="auto"><strong>Examples</strong></p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; SPerm([-2,-1,-3])

<p dir="auto">The group of signed permutations of <code>1:n</code> is called the hyperoctaedral group.</p>

<p dir="auto">A  motivation for my use of signed  permutations is to find if two matrices differ  only by a simultaneous signed permutation of lines and columns. See the example below with <code>SPerm(m,n;dims=(1,2))</code>.</p>
<p dir="auto">The  type  of  signed  permutations  is  <code>SPerm{T}</code>  where  <code>T&lt;:Integer</code>, a <code>struct</code>  with one  field, a  <code>Vector{T}</code> which  holds the  image of <code>1:n</code>. Using a <code>T</code> different than <code>Int</code> may possibly save space or time. If <code>T</code> is not  specified we  take it  to be  <code>Int16</code> since  this is a good compromise between speed and compactness.</p>
<p dir="auto"><code>SPerm</code>s  have methods <code>copy, hash, ==, isless</code>  (total order) so they can be keys in hashes or elements of sets; two <code>SPerm</code>s are equal if they move the same points to the same images. For instance,</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; SPerm([-2,-1,-3])==SPerm([-2,-1,-3,4])

<p dir="auto"><a id="user-content-signedperms.sperm" href="#SignedPerms.SPerm">#</a>
<strong><code>SignedPerms.SPerm</code></strong> — <em>Type</em>.</p>
<p dir="auto"><code>struct SPerm</code></p>
<p dir="auto">An  <code>SPerm</code> represents a signed permutation of <code>1:n</code>, that is a permutation of  the  set  <code>-n,…,-1,1,…,n</code>  which  preserves  the  pairs <code>(-i,i)</code>. It is implemented  by a <code>struct SPerm</code> which has  one field <code>d</code>, a vector holding the images of <code>1:n</code>. It is printed as its cycle decomposition.</p>

<p dir="auto"><code>invpermute</code> can also act on matrices with a keyword <code>dims</code>. If <code>dims=1</code> it invpermutes  the lines, if <code>dims=2</code> the  columns and for <code>dims=(1,2)</code> both. If <code>P=Matrix(p)</code> and <code>iP=Matrix(inv(p))</code> then <code>invpermute(m,p;dims=1)==iP*m</code>,      <code>invpermute(m,p;dims=2)==m*P</code>      and <code>invpermute(m,p;dims=(1,2))==iP*m*P</code>. Finally, the form <code>invpermute(m,p1,p2)</code>  invpermutes the lines of <code>m</code> by <code>p1</code> and the columns by <code>p2</code>.</p>

<p dir="auto"><a id="user-content-signedperms.sstab_onmats" href="#SignedPerms.sstab_onmats">#</a>
<strong><code>SignedPerms.sstab_onmats</code></strong> — <em>Function</em>.</p>
<p dir="auto"><code>sstab_onmats([G,]M[,l])</code></p>
<p dir="auto">if  the argument <code>G</code>  is given (which  should be an  <code>SPermGroup</code>) this is just  a fast implementation of <code>centralizer(G,M,onmats)</code>. If <code>G</code> is omitted it  is  taken  to  be  <code>hyperoctaedral_group(size(M,1))</code>.  The program uses sophisticated  algorithms, and can  handle matrices up  to 80×80. If <code>l</code> is given the return group should also centralize <code>l</code> (for the action ^)</p>

<strong><code>SignedPerms.SPerm</code></strong> — <em>Method</em>.</p>
<p dir="auto"><code>SPerm(M::AbstractMatrix,N::AbstractMatrix;dims)</code></p>
<p dir="auto">returns  a signed  permutation <code>p</code>  such that  <code>invpermute(N,p;dims)==M</code> if such  a <code>p</code> exists,  and <code>nothing</code> otherwise.  If <code>dims=(1,2)</code> then <code>M</code> and <code>N</code> should be symmetric matrices.</p>
<p dir="auto">The  case <code>dims=(1,2)</code> routine is useful  to identify two objects which are isomorphic  but with different labelings. It  is used in Chevie to identify Lusztig  Fourier transform  matrices with  standard (classified)  data. The program  uses sophisticated algorithms, and can often handle matrices up to 80×80.</p>

<strong><code>SignedPerms.SPerm_onmats</code></strong> — <em>Function</em>.</p>
<p dir="auto"><code>SPerm_onmats(M,N;extra=nothing)</code></p>
<p dir="auto"><code>M</code>  and <code>N</code> should be symmetric  matrices. <code>SPerm_onmats</code> returns a signed permutation <code>p</code> such that <code>onmats(N,p)=M</code> if such a permutation exists, and <code>nothing</code>  otherwise. If  in addition  vectors <code>extra=[m,n]</code> are given, the signed permutation <code>p</code> should also satisfy <code>invpermute(n,p)==m</code>.</p>
<p dir="auto">Efficient version of <code>transporting_elt(hyperoctaedral_group(size(M,1)),M,N,onmats)</code></p>
