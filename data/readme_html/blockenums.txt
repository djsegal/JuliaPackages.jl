<p dir="auto">BlockEnums is like the built-in Enums. The main differences are</p>
<ul dir="auto">
<li>Enumerated types are mutable in the sense that instances may be added after the type is created.</li>
<li>The type may be optionally enclosed in a module (a namespace).</li>
<li>The enumeration may be partitioned into blocks of values. For example <code>@addinblock A 2 x</code> would add
the instance <code>x</code> to type <code>A</code> in the second block of indices.</li>
</ul>
<p dir="auto">These are supported by keyword arguments <code>blocklength</code>, <code>mod</code>, <code>numblocks</code>.
There is also a keyword <code>compactshow</code> that causes the integer associated with the enum value to be
omitted when displaying.</p>

<p dir="auto">It came to my attention at JuliaCon2023 that <a href="https://github.com/JuliaLang/JuliaSyntax.jl/tree/main">JuliaSyntax.jl</a> includes a type <code>Kind</code> that has similarities
with <code>BlockEnums.jl</code>.</p>
<ul dir="auto">
<li>They are both like <code>Base.Enums</code> in that they are primitive types: <a href="https://github.com/JuliaLang/JuliaSyntax.jl/blob/main/src/kinds.jl#L940"><code>primitive type Kind 16 end</code></a></li>
<li>Intervals of the integer values have semantic significance. A difference is that the "blocks" in <code>Kind</code> are smaller and fixed.</li>
</ul>
<p dir="auto">The motivation for <code>Kind</code> is essentially the same as for <code>BlockEnums</code>:</p>
<p dir="auto"><a href="https://github.com/JuliaLang/JuliaSyntax.jl/blob/ad9b16681389dbe3f21a89897f7a86dec793f72a/src/kinds.jl#L927-L931">Here</a></p>
<blockquote>
<p dir="auto"><code>Kind</code> is a type tag for specifying the type of tokens and interior nodes of
a syntax tree. Abstractly, this tag is used to define our own <em>sum types</em> for
syntax tree nodes. We do this explicitly outside the Julia type system because
(a) Julia doesn't have sum types and (b) we want concrete data structures which
are unityped from the Julia compiler's point of view, for efficiency.</p>
</blockquote>
<p dir="auto">And <a href="https://github.com/JuliaLang/JuliaSyntax.jl/blob/main/src/kinds.jl#L942-L944">here</a></p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# The implementation of Kind here is basically similar to @enum. However we use
# the K_str macro to self-name these kinds with their literal representation,
# rather than needing to invent a new name for each."><pre><span class="pl-c"><span class="pl-c">#</span> The implementation of Kind here is basically similar to @enum. However we use</span>
<span class="pl-c"><span class="pl-c">#</span> the K_str macro to self-name these kinds with their literal representation,</span>
<span class="pl-c"><span class="pl-c">#</span> rather than needing to invent a new name for each.</span></pre></div>

<p dir="auto">Methods for the following functions in <code>Base</code> are defined and follow the established semantics.</p>
<ul dir="auto">
<li><code>cconvert</code></li>
<li><code>write</code>, converts to the underlying bitstype before writing.</li>
<li><code>read</code> , reads a value from the bitstype and converts to the <code>BlockEnum</code></li>
<li><code>isless</code></li>
<li><code>Symbol</code></li>
<li><code>length</code></li>
<li><code>typemin</code>, <code>typemax</code> These are the min and max of values with names bound to them.</li>
<li><code>instances</code></li>
<li><code>print</code></li>
</ul>
