<p dir="auto">This lightweight package provides convenience macros for traits (similar to and inspired by <a href="https://github.com/mauro3/SimpleTraits.jl">SimpleTraits.jl</a>). However, function behavior depending on traits can now be specified via intuitive <code>if</code>/<code>else</code> syntax using <code>@iftraits</code>.</p>

<p dir="auto">This package is in an early stage of development; whether it's concept really is useful is not yet clear to me. Feel free to suggest features, improvements and (of course) bugfixes!</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Implementation</h2><a id="user-content-implementation" class="anchor" aria-label="Permalink: Implementation" href="#implementation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Internally, we just replace  <code>IsNice(x)</code> by a function call <code>trait{IsNice}(x)</code> and return <code>true</code> in the case of a fulfilled trait and <code>false</code> in the case of a missing trait.
Because the compiler is smart, the return value of these functions gets detected at compile time and the trait dispatch does not have to be done at runtime.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Main functionality</h2><a id="user-content-main-functionality" class="anchor" aria-label="Permalink: Main functionality" href="#main-functionality"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">From this example the advantage over other packages is not apparent. The real power instead lies in the simplicity of defining functions which <em>depend on multiple types</em>.
As far as I know, usually the approach to this problem is either to use <a href="https://github.com/mauro3/SimpleTraits.jl/issues/71" data-hovercard-type="issue" data-hovercard-url="/mauro3/SimpleTraits.jl/issues/71/hovercard">combined traits</a> (which in my opinion is not very intuitive) or to define a bunch of <a href="https://github.com/mauro3/SimpleTraits.jl/pull/2" data-hovercard-type="pull_request" data-hovercard-url="/mauro3/SimpleTraits.jl/pull/2/hovercard">different functions</a> depending on several input traits (which imo is kinda messy).</p>
<p dir="auto">In our case, this can be solved with generic syntax:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# dummy example

@traitimpl CanSing(OperaSinger, ChartsSinger)
@traitimpl CanCompose(Composer, ChartsSinger)"><pre><span class="pl-c"><span class="pl-c">#</span> dummy example</span>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Multitype traits</h3><a id="user-content-multitype-traits" class="anchor" aria-label="Permalink: Multitype traits" href="#multitype-traits"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">My current understanding is that special traits of the form <code>BelongTogether(X, Y)</code> are just a (more or less) natural extension. Let's say we have a function <code>ship</code> which we would like to formulate using traits.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct Romeo end; struct Juliet end

belong_together(a::Romeo, b::Juliet) = true
belong_together(a::Juliet, b::Romeo) = true

<span class="pl-en">belong_together</span>(a, b) <span class="pl-k">=</span> <span class="pl-c1">false</span>
<span class="pl-en">belong_together</span>(a<span class="pl-k">::</span><span class="pl-c1">Romeo</span>, b<span class="pl-k">::</span><span class="pl-c1">Juliet</span>) <span class="pl-k">=</span> <span class="pl-c1">true</span>
<span class="pl-en">belong_together</span>(a<span class="pl-k">::</span><span class="pl-c1">Juliet</span>, b<span class="pl-k">::</span><span class="pl-c1">Romeo</span>) <span class="pl-k">=</span> <span class="pl-c1">true</span>
<span class="pl-en">ship</span>(a, b) <span class="pl-k">=</span> <span class="pl-c1">belong_together</span>(a, b) <span class="pl-k">?</span> <span class="pl-s"><span class="pl-pds">"</span>go marry<span class="pl-pds">"</span></span> <span class="pl-k">:</span> <span class="pl-s"><span class="pl-pds">"</span>nothing holds forever<span class="pl-pds">"</span></span></pre></div>
<p dir="auto">Now we can use the following trick:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# Multi is just a dummy trait, we could instead use an arbitrary type

<p dir="auto">Thus, we can now write</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="ship(a, b) = @iftraits BelongTogether(⊕(a, b)) ? &quot;go marry&quot; : &quot;nothing holds forever&quot;"><pre><span class="pl-en">ship</span>(a, b) <span class="pl-k">=</span> <span class="pl-c1">@iftraits</span> <span class="pl-c1">BelongTogether</span>(<span class="pl-k">⊕</span>(a, b)) <span class="pl-k">?</span> <span class="pl-s"><span class="pl-pds">"</span>go marry<span class="pl-pds">"</span></span> <span class="pl-k">:</span> <span class="pl-s"><span class="pl-pds">"</span>nothing holds forever<span class="pl-pds">"</span></span></pre></div>
<p dir="auto">Note however that we need a different function <code>⊕</code> for every multi-type trait. This pattern could of course be simplified by some new feature (something along defining <code>struct ⊕{T} end</code> and extending <code>@traitdef</code>/<code>@traitimpl</code> macros).</p>
