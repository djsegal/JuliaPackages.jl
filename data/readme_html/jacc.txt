<p dir="auto">CPU/GPU performance portable layer for Julia</p>
<p dir="auto">JACC.jl follows a function as a argument approach in combination with the power of Julia's ecosystem for multiple dispatch, GPU access via <a href="https://juliagpu.org/" rel="nofollow">JuliaGPU back ends</a>, and <a href="https://julialang.org/blog/2023/04/julia-1.9-highlights/#package_extensions" rel="nofollow">package extensions</a> since Julia v1.9 . Similar to portable layers like Kokkos, users would pass a size and a function including its arguments to a <code>parallel_for</code> or <code>parallel_reduce</code> function.
The overall goal is to write a single source code that can be executed on multiple vendor CPU and GPU parallel programming environments. JACC meant to simplify CPU/GPU kernel programming using a simple application programming interface (API).</p>
<p dir="auto">JuliaCon 2023 presentation <a href="https://live.juliacon.org/talk/AY8EUX" rel="nofollow">video</a>.</p>

<p dir="auto">We currently have a limited number of configurations.
We hope to study and incoorporate more relevant cases and dimensions shapes as needed.
For an app integration example see the <a href="https://github.com/JuliaORNL/GrayScott.jl/tree/GrayScott-JACC">GrayScott.jl JACC branch</a> and the <a href="https://github.com/JuliaORNL/GrayScott.jl/blob/GrayScott-JACC/src/simulation/Simulation.jl">Simulation.jl</a> for writing kernels with JACC.jl and selecting specific vendor back ends in Julia.</p>
