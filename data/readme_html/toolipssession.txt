<p dir="auto"><code>ToolipsSession</code> provides <code>Toolips</code> with the <code>Session</code> extension, which registers fullstack callbacks on a client-to-client basis. Alongside this, the module provides InputMaps (swipe and keyboard input), <code>rpc!</code> callbacks, Authentication via the <code>Auth</code> extension, and <code>next!</code> animation callbacks.</p>

<div class="markdown-heading" dir="auto"><h5 class="heading-element" dir="auto">session</h5><a id="user-content-session" class="anchor" aria-label="Permalink: session" href="#session"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>Session</code> a <code>Toolips</code> server extension (<code>&lt;:Toolips.AbstractExtension</code>) which manages clients and their fullstack callbacks. In order to load a server extension into our server, we need to construct and export it.</p>

<p dir="auto">The <code>Session</code> constructor takes two optional arguments, <code>active_routes</code> and <code>timeout</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="Session(active_routes::Vector{String} = [&quot;/&quot;]; timeout = 5)"><pre><span class="pl-c1">Session</span>(active_routes<span class="pl-k">::</span><span class="pl-c1">Vector{String}</span> <span class="pl-k">=</span> [<span class="pl-s"><span class="pl-pds">"</span>/<span class="pl-pds">"</span></span>]; timeout <span class="pl-k">=</span> <span class="pl-c1">5</span>)</pre></div>
<p dir="auto"><code>Session</code> will only provide interactivity to the route paths provided in <code>active_routes</code>. <code>timeout</code> represents the number of minutes after not recieving a callback that we will terminate a user's session. Once <code>Session</code> is loaded, we can immediately register callbacks on its active routes.</p>
<div class="markdown-heading" dir="auto"><h5 class="heading-element" dir="auto">creating callbacks</h5><a id="user-content-creating-callbacks" class="anchor" aria-label="Permalink: creating callbacks" href="#creating-callbacks"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Callbacks in base <code>Toolips</code> are created using the <code>on</code> function, which is provided a <code>Function</code> with an event name, and -- if binding to a <code>Component</code> -- a <code>Component</code>. These types of callbacks are provided a <code>ClientModifier</code>, which allows us to make client-side changes when these events are triggered.</p>

<p dir="auto">Here, we use <a href="#modifier-functions">modifier functions</a> to modify the changes we want to make on our client's page. Fullstack callbacks work very similarly, but require the <code>Connection</code> to be provided as an argument, and will pass a <code>ComponentModifier</code> to the <code>Function</code>. Here we will reuse <code>alert!</code> in the same exact context for a fullstack callback. Another important thing is to compose to a <code>body</code> <code>Component</code>, so that <code>ToolipsSession</code> is able to read all components.</p>

<p dir="auto">This type of callback actually calls the server, rather than making the changes on the client directly. This means that we are able to utilize Julia and utilize the data contained within our server, whereas with a <code>ClientModifier</code> our provided <code>Function</code> is ran when our page is initially served and all of our callbacks remain client-side as callable functions. This means that we are able to serve data straight from our <code>Function</code>, or the <code>Connection</code> to our user in a far more dynamic way.</p>

<p dir="auto">There is a major thing to be aware of when using <code>Toolips</code> multi-threading alongside <code>ToolipsSession</code>... First, a prerequisite; t is recommended to read <a href="https://github.com/ChifiSource/Toolips.jl#multi-threading">toolips' overview on multi-threading</a> before trying to use multi-threading alongside this package. The main thing to be aware of is that closures will <strong>not</strong> <em>serialize over threads</em>. This means that each <code>Function</code> provided for a callback must be a defined <code>Function</code> inside of a <code>Module</code>, not a <code>Function</code> provided as an argument -- like in the case of using <code>do</code>.</p>
