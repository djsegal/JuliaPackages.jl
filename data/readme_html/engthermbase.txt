<p dir="auto">In the above example, by respectivly using the  <code>T_</code>,  <code>P_</code>,  and  <code>q_</code>  constructors  (from
<code>EngThermBase.jl</code>),  the  respective  argument  quantities  of  <code>500u"°C"</code>,  <code>1u"MPa"</code>,  and
<code>800u"kJ/kg"</code> were <strong>tagged</strong> (or  labeled)  as  a  temperature,  a  pressure,  and  a  heat
interaction.</p>
<p dir="auto">Once tagged, the quantity is stored and shown in <strong>default units</strong> for each  quantity  type,
meaning in the <code>T_(500u"°C")</code> constructor call, there was a unit conversion from 500 °C into
773.15 K, in the <code>P_(1u"MPa")</code> constructor call, there was a unit conversion from 1 MPa into
1000 kPa, and no unit conversion in the <code>q_(800u"kJ/kg")</code> constructor call.</p>
<p dir="auto">Moreover, the quantities also pretty-print with a pre-settable amount of significant digits,
and optional floating point precision, as in the <code>T₆₄: 773.15 K</code> output, the  <code>T</code>  indicates
the quantity type---a temperature; the <code>₆₄</code> the underlying floating point precision  (of  64
bits), while <code>773.15 K</code> is the amount, powered by <code>Unitful.jl</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; typeof(pars[1])

<p dir="auto">It is worth noting that amounts are parameterized. Amounts such as temperature and  pressure
are (1) floating-point precision-,  and  (2)  exactness-  parameterized,  for  instance,  in
<code>T_amt{Float64, EX}</code>, the precision  is  <code>Float64</code>,  and  the  exactness  is  <code>EX</code>,  meaning
"exact".</p>
<p dir="auto">Due to <code>EngThermBase.jl</code> tagging and type tree, we can then make some theory  queries,  such
as "asking" whether or not quantities are (i) properties or (ii) interactions,  as  well  as
their base:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; property_pars = [ p for p in pars if p isa Property ]

<span class="pl-c1">1</span><span class="pl-k">-</span>element Vector{q_amt{Float64, EX, MA}}<span class="pl-k">:</span>

<p dir="auto">Therefore, <code>pars[1]</code> and <code>pars[2]</code>, respectively tagged as a temperature and a pressure, are
listed as properties, while <code>pars[3]</code>, tagged as a specific heat transfer, is listed  as  an
interaction. Moreover, its precision, exactness, and base are recovered in the last example,
with the <code>precof</code>, <code>exacof</code>, and <code>baseof</code> functions.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Quantity untagging (and optional unit conversion):</h2><a id="user-content-quantity-untagging-and-optional-unit-conversion" class="anchor" aria-label="Permalink: Quantity untagging (and optional unit conversion):" href="#quantity-untagging-and-optional-unit-conversion"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In <code>EngThermBase.jl</code>, amounts are <code>functors</code>, meaning they can be called as a function.  The
default behavior is to untag itself, returning unaltered it's <code>val</code> member. If,  however,  a
unit is passed as an argument to the functor, a unit conversion will be attempted. All  unit
operations on <code>EngThermBase.jl</code> are powered by <code>Unitful.jl</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; x, y = T_(512), P_(1024)

julia&gt; x(u&quot;°C&quot;)

(T₆₄<span class="pl-k">:</span> <span class="pl-c1">512.00</span> K, P₆₄<span class="pl-k">:</span> <span class="pl-c1">1024.0</span> kPa)

<span class="pl-c1">238.85000000000002</span> °C</pre></div>
<p dir="auto">The example illustrates that constructors apply default units to unitless arguments, so that
the default temperature unit, <code>K</code>, was applied by <code>T_</code> in the <code>T_(512)</code> call.  An  analogous
behavior is illusrtated with the <code>P_(1024)</code> call.</p>
<p dir="auto">Untagging happens when the <code>x</code> and <code>y</code> objects are called (as  functors),  with  <code>x()</code>,  and
<code>y()</code>, in which case we see the plain underlying  values  of  <code>512.0  K</code>  and  <code>1024.0  kPa</code>
returned as a 2-tuple. Nota that there's no mor pretty-printing because the values  are  not
<code>EngThermBase.jl</code> amounts.</p>
<p dir="auto">In the last example, a unit conversion is performed when a unit is  passed  to  the  functor
call <code>x(u"°C")</code>, that returns 238.85 °C. Note again, the lack of pretty-printing.</p>
<p dir="auto">Other untagging functions are: <code>amt</code>, <code>bare</code>, and <code>pod</code>; which, respectively return the  (i)
underlying amount (with units, just like the  functor),  (ii)  the  "bare"  numerical  value
without units, and (iii) a "plain-old data", which also strips from  bare  numerical  values
any possible uncertainty.</p>

<p dir="auto">In this example, the operation <code>u + P * v</code>  resulted  in  an  enthalpy,  <code>h</code>.  Moreover,  by
definition, <code>u - T * s --&gt; a</code>, and <code>(P * v) / (R * T) --&gt; Z</code>. Moreover, a Mach  number  <code>Ma</code>
of 1.25 is obtained by dividing the velocity of 1500 km/h by the sound speed of  1200  km/h,
and the classic ratio <code>cp / cv --&gt; γ</code>.</p>
