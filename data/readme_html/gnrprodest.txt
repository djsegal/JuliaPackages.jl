<p dir="auto">You can use estimation routine in two ways. Either run both stages using <code>gnrprodest</code> or run each estimation stage separately with <code>gnrfirststage</code> and <code>gnrsecondstage</code>. Versions of these functions that end with an <code>!</code> modify their inputs (most importantly the dataframe).</p>

<p dir="auto">Both versions have exactly the same arguments. The difference is, that gnrprodest modifies its arguments (especially <code>data</code>). <code>fes_returns</code> is a NamedTuple of first stage return objects, <code>ses_returns</code> is the equivalent for the second stage, <code>results_table</code> is a DataFrame printed at the end containing key statistics, and <code>estimation_sample</code> is the DataFrame used in the estimation routine.</p>

<p dir="auto">All arguments in any of the functions are keyword arguments. The necessary arguments are:</p>
<ul dir="auto">
<li><code>data</code> is a DataFrame that includes all columns defined by other arguments.</li>
<li><code>output</code> is the Symbol and represents the firms natural logarithm of gross output.</li>
<li><code>flexible_input</code> is a Symbol representing the natural logarithm of the flexible input of the production function.</li>
<li><code>fixed_inputs</code> is a Symbol or a vector of Symbols representing any natural logarithm of fixed production inputs.</li>
<li><code>id</code> is a Symbol of each firm's unique identifier.</li>
<li><code>time</code> is a Symbol identifying the observation`s time period.</li>
</ul>
<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Optional Arguments</h4><a id="user-content-optional-arguments" class="anchor" aria-label="Permalink: Optional Arguments" href="#optional-arguments"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<code>ln_share_flex_y</code> is a Symbol for the natural logarithm of the flexible input share of revenue. If it is not defined by the user, the package calculates it internally.</li>
<li>
<code>share_degree</code> is the degree of the polynomial series in the share regression. Its default value is <code>3</code> if it is not defined by the user.</li>
<li>
<code>lm_tfp_degree</code> is the degree of the law of motion for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="39af52b0c2366d299d0efc0c367d634a">$\omega$</math-renderer> (tfp) over time. The default value if not defined by user is <code>3</code>.</li>
<li>
<code>int_const_series_degree</code> is the degree of the polynomial series of the constant of integration in the second stage. Its default value is <code>3</code> if not defined by the user.</li>
<li>
<code>fes_starting_values</code> is a vector of starting values for the first stage non-linear least squares regression. If the user does not define them, the package chooses them using a linear regression.</li>
<li>
<code>ses_starting_values</code> is a vector of starting values for the second stage GMM estimation routine. If the user does not define them, the package chooses them using a linear regression.</li>
<li>
<code>boot_reps</code> is an integer indicating the number of repetitions the Bootstrap algorithm uses in the standard error estimation. The default is 200.</li>
<li>
<code>opts</code> is a dictionary of futher options.
<ul dir="auto">
<li>
<code>fes_print_starting_values</code> prints first stage starting values if set to <code>true</code>.</li>
<li>
<code>fes_print_results</code> prints first stage results if set to <code>true</code>.</li>
<li>
<code>fes_optimizer</code> can be used to change the numerical optimization algorithm in the first stage. The default is NelderMead. You can find a list of available optimizers with an in-dept description here: <a href="https://julianlsolvers.github.io/Optim.jl/stable/" rel="nofollow">Optim.jl</a>
</li>
<li>
<code>fes_optimizer_options</code> allows the user to configure the options of the first stage numerical optimization routine. Use an <code>Optim.Options()</code> object to define them. The configurable options depend on the optimizer chosen. You can find a list of options here: <a href="https://julianlsolvers.github.io/Optim.jl/stable/user/config/" rel="nofollow">Optim.Options</a>
</li>
<li>
<code>ses_print_starting_values</code> prints first stage starting values if set to <code>true</code>.</li>
<li>
<code>ses_print_results</code> prints first stage results if set to <code>true</code>.</li>
<li>
<code>ses_optimizer</code> can be used to change the numerical optimization algorithm in the second stage. The default is NelderMead. You can find a list of available optimizers with an in-dept description here: <a href="https://julianlsolvers.github.io/Optim.jl/stable/" rel="nofollow">Optim.jl</a>
</li>
<li>
<code>ses_optimizer_options</code> allows the user to change the options of the second stage numerical optimization routine. Use an <code>Optim.Options()</code> object to define them. The configurable options depend on the optimizer chosen. You can find a list of options here: <a href="https://julianlsolvers.github.io/Optim.jl/stable/user/config/" rel="nofollow">Optim.Options</a>
</li>
<li>
<code>print_results</code> prints a summary table of key statistics including (among others) standard errors and confidence intervals. Deflaut is <code>true</code>.</li>
</ul>
</li>
</ul>

<p dir="auto">Instead of using one command for both stages, you can estimate both stages independently. The command for the estimation of the first stage is <code>gnrfirststage</code> or <code>gnrfirststage!</code>. The difference is that the latter changes its inputs (especially the data). See the list of argument descriptions above.<code>fes_returns</code> is a NamedTuple of first stage return objects and <code>estimation_sample</code> is the DataFrame used in the estimation routine.</p>
