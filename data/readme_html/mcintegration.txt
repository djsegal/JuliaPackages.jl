<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Why Choose MCIntegration.jl?</h2><a id="user-content-why-choose-mcintegrationjl" class="anchor" aria-label="Permalink: Why Choose MCIntegration.jl?" href="#why-choose-mcintegrationjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">MCIntegration.jl is a comprehensive Julia package designed to handle both regular and singular high-dimensional integrals with ease. Its implementation of robust Monte Carlo integration methods makes it a versatile tool in various scientific domains, including high-energy physics, material science, computational chemistry, financial mathematics, and machine learning.</p>
<p dir="auto">The high-level simplicity and flexibility of Julia combined with the performance capabilities of C/C++-like compiled languages make it a fantastic choice for implementing Monte Carlo methods. Monte Carlo methods, which require extensive computations, can greatly benefit from Julia's just-in-time (JIT) compilation that allows <code>MCIntegration.jl</code> to perform calculations at a near-C/C++ efficiency. Moreover, the intuitive high-level syntax of Julia allows users to define their integrands effortlessly, adding to the customizability and user-friendliness of <code>MCIntegration.jl</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Understanding Variables</h2><a id="user-content-understanding-variables" class="anchor" aria-label="Permalink: Understanding Variables" href="#understanding-variables"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To handle more complex integrals, it's necessary to understand how <code>MCIntegration.jl</code> designs and uses variables. <code>MCIntegration.jl</code> can handle multiple integrals with multi-dimensional variables in the general form
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\int d\vec{x} \int d\vec{y}... \vec{f}(\vec{x}, \vec{y}...)$</math-renderer>
The package handles both continuous and discrete variables; for discrete variables, the integrals are interpreted as summations.</p>
<p dir="auto">In <code>MCIntegration.jl</code>, the <strong>"degrees of freedom" (<code>dof</code>)</strong> define the dimensionality of each variable group in the integrand. They are represented as a list of dimensions: dof(<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{f}$</math-renderer>) = [[dim(<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{x}$</math-renderer>), dim(<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{y}$</math-renderer>), ...], ...], with dim(<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{f}$</math-renderer>) elements.</p>
<p dir="auto">The building blocks of variable organization in <code>MCIntegration.jl</code> are the <strong>variable vectors</strong> (like <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{x}$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="88ac6d480a2700aa3bd46ee9a2260b44">$\vec{y}$</math-renderer>, ...), which are implemented as <strong>unlimited</strong> pools of variables. These variable vectors can be combined or used individually, depending on the integrand's structure.</p>
<ul dir="auto">
<li>
<p dir="auto"><strong>Variable Vectors (Symmetric Variables):</strong> If the variables in the integrands are interchangeable, they can be organized into a variable vector acting as a pool. All variables within the same pool are sampled from the same optimized distributions.</p>
</li>
<li>
<p dir="auto"><strong>Composite Variable Vectors:</strong> When two or more variable vectors consistently appear together across all integrands, they can be bundled to form composite variable vectors. Composite variables share the same <code>dof</code> and can be updated together during the integration process, offering computational efficiency especially when working with MCMC-based solvers (see the next section for more details).</p>
</li>
</ul>
<p dir="auto">Both variable vectors and composite variable vectors can be organized into <code>Tuple</code>, offering more complex interactions between different variables or composite variables in the integrands.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Selecting Algorithms</h2><a id="user-content-selecting-algorithms" class="anchor" aria-label="Permalink: Selecting Algorithms" href="#selecting-algorithms"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>MCIntegration.jl</code> offers three Monte Carlo integration algorithms, all of which leverage the Vegas map technique for importance sampling. This approach constructs a piecewise constant Vegas map, a probability distribution function approximating the shape of the integrand to enhance the efficiency of the integral estimation.</p>
<p dir="auto">Here's a brief overview of the three solvers:</p>
<ol dir="auto">
<li>
<p dir="auto"><strong>Vegas (<code>:vegas</code>):</strong> The classic Vegas algorithm uses the Monte Carlo method and samples all integrands across all variables simultaneously at each step. It is efficient for low-dimensional integrals but might struggle with high-dimensional ones where the Vegas map fails to accurately mimic the integrand's shape.</p>
</li>
<li>
<p dir="auto"><strong>Vegas with MCMC (<code>:vegasmc</code>):</strong> This innovative solver, first introduced in <code>MCIntegration.jl</code>, combines Vegas with Markov-chain Monte Carlo. This hybrid approach provides a robust solution, especially for intricate, high-dimensional integrals. In the Vegas MC approach, a variable is selected randomly, and a Metropolis-Hastings algorithm is utilized to propose a new variable based on the Vegas map. This update is applied simultaneously across all integrands, improving robustness when the Vegas map struggles with approximating the shape of the integrand accurately.</p>
</li>
<li>
<p dir="auto"><strong>MCMC (<code>:mcmc</code>):</strong> The MCMC solver is ideal for dealing with a bundle of integrands that are too large to be computed all at once. It uses the Metropolis-Hastings algorithm to traverse between different integrals, evaluating only one integrand at each step. Though it can be less efficient due to the integral-jumping auto-correlations, it stands out in its ability to handle extremely high-dimensional integrals where the other two solvers fail.</p>
</li>
</ol>
<p dir="auto">Given its robustness and efficiency, the default solver in this package is <code>:vegasmc</code>. To choose a specific solver, use the <code>solver</code> parameter in the <code>integrate</code> function, like <code>solver=:vegas</code>.</p>
<p dir="auto">Please note that the calling convention for the user-defined integrand for <code>:mcmc</code> is slightly different from that of <code>:vegas</code> and <code>:vegasmc</code>. Please refer to the separate <a href="https://numericaleft.github.io/MCIntegration.jl/dev/#Algorithm" rel="nofollow">detailed note</a> on this.</p>
<p dir="auto">Packed variables can enhance the efficiency of the <code>:vegasmc</code> and <code>:mcmc</code> solvers by reducing the auto-correlation time of the Markov chain, leading to a more effective sampling process.</p>
<p dir="auto">Learn more from documentation: <a href="https://numericaleft.github.io/MCIntegration.jl/dev/lib/vegas/" rel="nofollow">Vegas</a>, <a href="https://numericaleft.github.io/MCIntegration.jl/dev/lib/vegasmc/" rel="nofollow">VegasMC</a> and <a href="https://numericaleft.github.io/MCIntegration.jl/dev/lib/mcmc/" rel="nofollow">MCMC</a> algorithms.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Parallelization</h2><a id="user-content-parallelization" class="anchor" aria-label="Permalink: Parallelization" href="#parallelization"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Parallelization is a vital aspect of <code>MCIntegration.jl</code>, enhancing the performance of your Monte Carlo simulations. The package supports both MPI and multi-thread parallelization, with an option to combine them as required.</p>
<ul dir="auto">
<li>
<p dir="auto"><strong>MPI:</strong>
With MPI, you can run your code in a distributed manner, using the command:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mpiexec -n N julia your_script.jl"><pre>mpiexec -n N julia your_script.jl</pre></div>
<p dir="auto">Here, <code>N</code> denotes the number of workers. The MC sampler internally dispatches blocks (controlled by the <code>Nblock</code> argument) to different workers and collects the estimates on the root node. While using MPI, the <code>integrate</code> function returns meaningful estimates only for the root node. For other workers, it returns <code>nothing</code>.</p>
<p dir="auto"><strong>Note:</strong> For MPI functionality, install the <a href="https://github.com/JuliaParallel/MPI.jl">MPI.jl</a> package and follow the <a href="https://juliaparallel.github.io/MPI.jl/stable/configuration/" rel="nofollow">configuration</a> instructions.</p>
</li>
<li>
<p dir="auto"><strong>Multi-threading:</strong>
To enable multi-threading, start Julia as follows:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia -t N your_script.jl"><pre>julia -t N your_script.jl</pre></div>
<p dir="auto">Remember, all threads share the same memory, so ensure your integrand and measure functions are thread-safe. Check Julia's official <a href="https://docs.julialang.org/en/v1/manual/multi-threading/" rel="nofollow">documentation</a> for further guidance. For multi-threading, you have two options:</p>
<ul dir="auto">
<li><strong>Concurrent Integration:</strong> Each thread independently calls <code>integrate</code> to perform separate integrations.</li>
<li><strong>Block-wise Parallelization:</strong> Only the main thread invokes <code>integrate</code>, while the computation blocks within are parallelized across multiple threads. To apply this, use <code>integrate</code> with the argument <code>parallel = :thread</code>.</li>
</ul>
<p dir="auto">The following examples demonstrate the difference between the two approaches,</p>
