<p dir="auto">This package does quantum operator algebra (i.e., algebra with non-commuting
operators) in Julia, supporting bosonic, fermionic, and two-level system
operators, with arbitrary names and indices, as well as sums over any of the
indices. It defines an opinionated canonical form (normal ordering plus some
additional rules) to automatically simplify expressions. It is recommended to
use an interface that can display LaTeX formulas (e.g., Jupyter notebooks) for
convenient output formatting.</p>
<p dir="auto">Starting from v1.4, QuantumAlgebra also interoperates with computer algebra
systems (CAS) such as
<a href="https://github.com/JuliaSymbolics/Symbolics.jl">Symbolics.jl</a> or
<a href="https://github.com/JuliaPy/SymPy.jl">SymPy.jl</a> /
<a href="https://github.com/jverzani/SymPyPythonCall.jl">SymPyPythonCall.jl</a>, as the
"scalar" prefactors of each quantum term can be arbitrary expressions provided
by these systems. While such expressions do not support symbolic indices in the
same way as QuantumAlgebra, they provide much more flexibility in terms of the
mathematical operations and powerful manipulation functions possible on the
parameters.</p>
<p dir="auto">Example jupyter notebooks are available in the <code>examples</code> folder and can be
viewed online with
<a href="https://nbviewer.jupyter.org/github/jfeist/QuantumAlgebra.jl/blob/main/examples/" rel="nofollow">nbviewer</a>
and tried out interactively with
<a href="https://mybinder.org/v2/gh/jfeist/QuantumAlgebra.jl/main?filepath=examples" rel="nofollow">Binder</a>.</p>

<p dir="auto">The basic functions to create QuantumAlgebra expressions (which are of type
<code>QuExpr</code>) are</p>
<ul dir="auto">
<li>
<p dir="auto"><code>a(inds...)</code> and <code>a'(inds...)</code> for <em>a</em> and <em>a<sup>†</sup></em>, the annihilation
and creation operators for a bosonic mode.</p>
</li>
<li>
<p dir="auto"><code>f(inds...)</code> and <code>f'(inds...)</code> for <em>f</em> and <em>f<sup>†</sup></em>, the annihilation
and creation operators for a fermionic mode.</p>
</li>
<li>
<p dir="auto"><code>σx(inds...)</code>, <code>σy(inds...)</code>, <code>σz(inds...)</code> for the Pauli matrices
<em>σ<sup>x,y,z</sup></em> for a two-level system (TLS).</p>
</li>
<li>
<p dir="auto"><code>σp(inds...)</code>, <code>σm(inds...)</code> for excitation and deexcitation operators
<em>σ<sup>±</sup></em> for a two-level system (TLS).</p>
</li>
<li>
<p dir="auto"><strong>Indices</strong>: All of these functions take an arbitrary number of indices as
arguments, which can be either integers (1,2,...) or symbolic, where symbolic
indices must be a single unicode character, with possibly an integer subindex:</p>

</li>
<li>
<p dir="auto">You can define your own bosonic/fermionic/two-level system operators with a
set of macros:</p>
<ul dir="auto">
<li><code>@boson_ops name</code> defines new function <code>$name()</code> (and deprecated <code>$(name)dag()</code>) for
bosonic species <code>name</code>.</li>
<li><code>@fermion_ops name</code> defines new function <code>$name()</code> (and deprecated <code>$(name)dag()</code>) for
fermionic species <code>name</code>.</li>
<li><code>@tlsxyz_ops name</code> defines new functions <code>$(name)x()</code>, <code>$(name)y()</code> and
<code>$(name)z()</code> for the Pauli matrices for two-level system species <code>name</code>.</li>
<li><code>@tlspm_ops name</code> defines new functions <code>$(name)p()</code> and <code>$(name)m()</code> for
the two-level system excitation and deexcitation operators for species
<code>name</code>.</li>
</ul>
<p dir="auto">Note that for <code>@boson_ops</code> and <code>@fermion_ops</code>, the deprecated <code>$(name)dag()</code>
functions are defined for backward compatibility. These will be removed in a
future version, as <code>$(name)'()</code> is now the preferred syntax for creating an
adjoint.</p>

<p dir="auto">Operators with different names are assumed to belong to different "species"
and always commute. For fermions, this is not always desired, since you might
want to use different named operators to refer to different kinds of states
for the same species (e.g., localized and itinerant electrons). This can be
achieved with the macro <code>@anticommuting_fermion_group</code>, which creates several
fermionic operators that mutually anticommute:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; @anticommuting_fermion_group c d

<span class="pl-c1">0</span></pre></div>
</li>
<li>

one of <code>'r'</code>, <code>'n'</code>, or <code>'c'</code> for purely real, non-conjugated complex, and
conjugated complex parameters. More conveniently, parameters can be entered
with string macros <code>Pr"name_inds..."</code> and <code>Pc"name_inds..."</code> for real and
complex parameters:</p>

<li>
<p dir="auto">Arithmetic operations (<code>*</code>, <code>+</code>, <code>-</code>, <code>^</code>, <code>adjoint</code>=<code>'</code>) are supported
(exponents must be nonnegative integers), with any <code>Number</code> types integrating
automatically. Division by numbers is also supported.</p>

<p dir="auto">If you explicitly need a bare number as a QuantumAlgebra expression, you can
use, e.g. <code>QuExpr(1)</code> (which is equal to <code>one(QuExpr)</code>). However, most
functions that take a <code>QuExpr</code> will also accept a bare number.</p>
</li>
<li>
<p dir="auto"><code>∑(ind,A::QuExpr)</code> to represent an analytic sum over index <code>ind</code>. Since summed
indices have no semantic meaning, the index within the expression gets
replaced by a special numbered sum index <code>#ᵢ</code>, with <code>i=1,2,...</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; ∑(:i,a(:i))
∑₁ a(#₁)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-c1">∑</span>(<span class="pl-c1">:i</span>,<span class="pl-c1">a</span>(<span class="pl-c1">:i</span>))
∑₁ <span class="pl-c1">a</span>(<span class="pl-c"><span class="pl-c">#</span>₁)</span></pre></div>
</li>
<li>
<p dir="auto"><code>normal_form(A::QuExpr)</code> converts an expression to a well-defined "canonical"
order. To achieve this canonical form, relevant commutators etc are used, so
an expression written as a single product can turn into a sum of expressions.
The order is essentially normal ordering (creation before annihilation
operators, with σˣʸᶻ in the middle), with some additional conventions to make
the normal form (hopefully) unique. In some contexts (e.g., interactive work),
it can be convenient to automatically transform all expressions to normal
form. This can be enabled by calling <code>QuantumAlgebra.auto_normal_form(true)</code>.
To make the setting permanent, call <code>QuantumAlgebra.auto_normal_form(true; set_preference=true)</code>
or alternatively use <a href="https://github.com/JuliaPackaging/Preferences.jl">Preferences.jl</a> directly,
i.e., call <code>Preferences.set_preferences!(QuantumAlgebra,"auto_normal_form"=&gt;true/false)</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; normal_form(a(:i)*a'(:j))
δ(ij)  + a†(j) a(i)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-c1">normal_form</span>(<span class="pl-c1">a</span>(<span class="pl-c1">:i</span>)<span class="pl-k">*</span>a<span class="pl-k">'</span>(<span class="pl-c1">:j</span>))

</li>
<li>
<p dir="auto"><code>expval(A::QuExpr)</code> to represent an expectation value.</p>

<p dir="auto"><code>heisenberg_eom(A,H,Ls=())</code> calculates the <a href="https://en.wikipedia.org/wiki/Lindbladian#Heisenberg_picture" rel="nofollow">Heisenberg equation of
motion</a> for
operator <code>A</code> under the action of Hamiltonian <code>H</code> and potential Lindblad decay
terms <code>Ls</code>, given by <em>dA/dt = i[H,A] + ∑<sub>i</sub> γ<sub>i</sub>

L<sub>i</sub>,A}).</em> The Lindblad decay operators are passed as a tuple (not an
array) of tuples, where each inner tuple describes one decay operator. The
possible forms are <code>(L,)</code> for decay operator <code>L</code>, <code>(γ,L)</code> for decay operator
<code>L</code> with rate <code>γ</code>, and <code>(inds,γ,L)</code> for decay operators summed over the given
indices (note that this is different from the operator itself being a sum,
seen in the example below). Finally, <code>L</code> can (in all three cases above) be
just a single operator or a tuple of two operators <code>L=(X,Y)</code> to represent
off-diagonal Lindblad terms <em>L<sub>X,Y</sub>[ρ] = X ρ Y<sup>†</sup> - 1/2
{Y<sup>†</sup> X,ρ}</em>.</p>

<li>
<p dir="auto"><code>heisenberg_eom_system(H,rhsfilt,Ls=(),ops=nothing)</code> calculates the system of
equations of motion for the expectation values of operators appearing in <code>H</code>
and <code>Ls</code> (same conventions as for <code>heisenberg_eom</code> above). Typically, these
equation systems are not closed without approximations as equations for
products of <em>n</em> operators involve products of <em>m&gt;n</em> operators, so the
system has to be truncated. This is achieved with a filter function that
removes higher-order terms or rewrites them (approximately) in terms of
lower-order expressions. The function <code>rhsfilt</code> is applied to the right-hand
side of the equations to filter them as desired. If
<code>rhsfilt(A::QuExpr)::QuExpr</code> is a function, it will be applied to the
calculated right-hand side of the equations. <code>QuantumAlgebra</code> comes with two
predefined constructors for filter functions, <code>droplen(maxorder::Int)</code>, which
leads to all terms of order higher than <code>maxorder</code> being neglected, and
<code>dropcorr(maxorder::Int)</code>, where all terms of order higher than <code>maxorder</code> are
rewritten in terms of lower-order expressions up to order <code>maxorder</code> and
higher-order correlators, with those correlations being neglected (i.e.,
<code>dropcorr(1)</code> will replace <em>⟨a<sup>†</sup> a⟩ = ⟨a<sup>†</sup> a⟩<sub>c</sub> + ⟨a<sup>†</sup>⟩ ⟨a⟩ ≈ ⟨a<sup>†</sup>⟩ ⟨a⟩</em>).
If <code>rhsfilt</code> is a number, it will be interpreted as <code>droplen(rhsfilt)</code>.
Finally, the <code>ops</code> argument can be used to specify the operators that should
be used to "seed" the system of equations, otherwise all operators appearing
in <code>H</code> are used.</p>

<p dir="auto">Several preferences changing the behavior of QuantumAlgebra can be set
permanently (this uses <a href="https://github.com/JuliaPackaging/Preferences.jl">Preferences.jl</a>):</p>
<ul dir="auto">
<li><code>"define_default_ops"</code>: if this is set to <code>false</code> (default is <code>true</code>), the
"default" operators <code>a, adag, f, fdag, σx, σy, σz, σp, σm</code> are not defined
upon import. Note that changing this value requires restarting the Julia
session to take effect. The setting can be changed with
<code>QuantumAlgebra.set_define_default_ops(true/false)</code> (which will inform you
whether a restart is required) or with
<code>Preferences.set_preferences!(QuantumAlgebra,"define_default_ops"=&gt;true/false).</code></li>
<li><code>"auto_normal_form"</code>: Choose whether all expressions are automatically
converted to normal form upon creation. The default is <code>false</code>. It can be
changed for a single session with
<code>QuantumAlgebra.auto_normal_form(true/false)</code>, and can be made permanent
with <code>QuantumAlgebra.auto_normal_form(true/false; set_preference=true)</code> or
with
<code>Preferences.set_preferences!(QuantumAlgebra,"auto_normal_form"=&gt;true/false)</code>.
Note that this could previously be set by defining an environment variable
<code>"QUANTUMALGEBRA_AUTO_NORMAL_FORM"</code>, but this usage has been deprecated and
will be removed in a future version.</li>
<li><code>"use_σpm"</code>: Choose whether for two-level systems, the "basic" operators are
excitation/deexcitation operators <code>σ⁺</code>,<code>σ⁻</code> or the Pauli matrices
<code>σˣ</code>,<code>σʸ</code>,<code>σᶻ</code>. This can be changed in a single session by calling
<code>QuantumAlgebra.use_σpm(true/false)</code>, and can be made permanent with
<code>QuantumAlgebra.use_σpm(true/false; set_preference=true)</code> or with
<code>Preferences.set_preferences!(QuantumAlgebra,"use_σpm"=&gt;true/false)</code>.</li>
</ul>
