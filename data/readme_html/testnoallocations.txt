<p dir="auto">This Package adds simple Macro <code>@testnoallocations</code> which makes sure, that a tested implementation of a function is allocation free.
All credit goes to Daniel Pinyol for the post at <a href="https://forem.julialang.org/dpinol/detecting-test-allocated-gotchas-34op" rel="nofollow">https://forem.julialang.org/dpinol/detecting-test-allocated-gotchas-34op</a>. Read the post for background information.
To know where the allocations occur use <code>@warn_alloc</code>.</p>

<p dir="auto">The package provides two macros:</p>
<ul dir="auto">
<li><code>@testnoallocations</code></li>
<li><code>@warn_alloc</code></li>
</ul>
<p dir="auto">Use <code>@testnoallocations</code> in unittest, to fail incase of allocations.<br>
Use <code>@warn_alloc</code> to find the location of these allocations occurring.</p>

<p dir="auto">To use the macro <code>@testnoallocations</code>, include it and add it in front of a function call inside a <code>@testset</code>.
The package <code>using Test</code> has to be included as well.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using TestNoAllocations
using Test


function test_no_allocs()
    @testset &quot;testallocs&quot; begin
        @testnoallocations 1 + 1 # passes
        @testnoallocations BigInt(1) + 1 # fails
        # Expression: allocs === 0
        # Evaluated: 96 === 0
    end
end


test_no_allocs()

<ul dir="auto">
<li>Always call the tests in a function. Calling from the Main-Namespace often causes additional allocations.</li>
<li>Don't use global variables, as these cause additional Allocations.
<ul dir="auto">
<li>If it can't be avoided, specify the type exactly</li>
<li>alternatively use <code>const</code></li>
</ul>
</li>
</ul>
