<p dir="auto">Support for the VOTable format (Virtual Observatory Table, <a href="https://www.ivoa.net/documents/VOTable/" rel="nofollow">defined</a> by <a href="https://www.ivoa.net/" rel="nofollow">IVOA</a>) in Julia.</p>
<p dir="auto">Supports:</p>
<ul dir="auto">
<li>✅ Read VOTable files, both XML (<code>TABLEDATA</code>) and binary (<code>BINARY2</code>) formats</li>
<li>✅ Parse numbers, strings, datetimes (optional), units (optional, uses <a href="https://github.com/PainterQubits/Unitful.jl">Unitful.jl</a>)</li>
<li>✅ Extract column descriptions from VOTable files into Julia table metadata</li>
<li>✅ Write VOTable files</li>
</ul>
<p dir="auto">Does not support (yet):</p>
<ul dir="auto">
<li>Some binary serialization formats: <code>FITS</code>, <code>BINARY</code></li>
<li>Multiple tables in a single file</li>
</ul>
<p dir="auto">See also: <a href="https://github.com/JuliaAstro/VOTables.jl">https://github.com/JuliaAstro/VOTables.jl</a>, an older package with similar goals. That one was never registered in General, and the current <code>VOTables.jl</code> package is more performant and featureful.<br>
See also: <a href="https://gitlab.com/aplavin/VirtualObservatory.jl" rel="nofollow">VirtualObservatory.jl</a> for integrations with online services following <a href="https://www.ivoa.net/" rel="nofollow">Virtual Observatory</a> protocols.</p>

<p dir="auto">The result is a <code>StructArray</code> be default, a Julia table with column-based storage. Whole columns can be accessed as <code>tbl.colname</code>, rows as <code>tbl[123]</code>, and individual values as <code>tbl.colname[123]</code> or <code>tbl[123].colname</code>.
To avoid compilation overhead, especially for very wide tables, can use <code>DictArray</code> instead (from <a href="https://gitlab.com/aplavin/DictArrays.jl" rel="nofollow">DictArrays.jl</a>): <code>VOTables.read(DictArray, "tbl.vot")</code>.</p>
