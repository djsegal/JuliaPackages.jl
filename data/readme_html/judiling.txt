<p dir="auto">Before we start, we first need to load the JudiLing package:</p>

<p dir="auto"><strong>Note:</strong>
As of JudiLing 0.8.0, <a href="https://github.com/JuliaPy/PyCall.jl">PyCall</a> and <a href="https://fluxml.ai/Flux.jl/stable/" rel="nofollow">Flux</a> have become optional dependencies. This means that all code in JudiLing which requires calls to python is only available if PyCall is loaded first, like this:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using PyCall
using JudiLing"><pre><span class="pl-k">using</span> PyCall
<span class="pl-k">using</span> JudiLing</pre></div>
<p dir="auto">Likewise, the code involving deep learning is only available if Julia's deep learning library Flux is loaded first, like this:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Flux
using JudiLing"><pre><span class="pl-k">using</span> Flux
<span class="pl-k">using</span> JudiLing</pre></div>
<p dir="auto">Note that Flux and PyCall have to be installed separately, and the newest version of Flux requires at least Julia 1.9. If you want to run deep learning in a GPU, make sure to also install and import <a href="https://cuda.juliagpu.org/stable/" rel="nofollow">CUDA</a>.</p>

<p dir="auto">For the production model, we want to predict correct forms given their lexemes and inflectional features. For example, giving the lexeme <code>vocare</code> and its inflectional features <code>p1</code>, <code>sg</code>, <code>present</code>, <code>active</code> and <code>ind</code>, the model should produce the form <code>vocoo</code>. On the other hand, the comprehension model takes forms as input and tries to predict their lexemes and inflectional features.</p>
<p dir="auto">We use letter trigrams to encode our forms. For word <code>vocoo</code>, for example, we use trigrams <code>#vo</code>, <code>voc</code>, <code>oco</code>, <code>coo</code> and <code>oo#</code>. Here, <code>#</code> is used as start/end token to encode the initial trigram and finial trigram of a word. The row vectors of the C matrix specify for each word which of the trigrams are realized in that word.</p>
<p dir="auto">To make the C matrix, we use the <code>make_cue_matrix</code> function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cue_obj = JudiLing.make_cue_matrix(
    latin,
    grams=3,
    target_col=:Word,
    tokenized=false,
    keep_sep=false
    )"><pre>cue_obj <span class="pl-k">=</span> JudiLing<span class="pl-k">.</span><span class="pl-c1">make_cue_matrix</span>(
    latin,
    grams<span class="pl-k">=</span><span class="pl-c1">3</span>,
    target_col<span class="pl-k">=</span><span class="pl-c1">:Word</span>,
    tokenized<span class="pl-k">=</span><span class="pl-c1">false</span>,
    keep_sep<span class="pl-k">=</span><span class="pl-c1">false</span>
    )</pre></div>
<p dir="auto">Next, we simulate the semantic matrix S using the <code>make_S_matrix</code> function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="n_features = size(cue_obj.C, 2)
S = JudiLing.make_S_matrix(
    latin,
    [&quot;Lexeme&quot;],
    [&quot;Person&quot;,&quot;Number&quot;,&quot;Tense&quot;,&quot;Voice&quot;,&quot;Mood&quot;],
    ncol=n_features)"><pre>n_features <span class="pl-k">=</span> <span class="pl-c1">size</span>(cue_obj<span class="pl-k">.</span>C, <span class="pl-c1">2</span>)
S <span class="pl-k">=</span> JudiLing<span class="pl-k">.</span><span class="pl-c1">make_S_matrix</span>(
    latin,
    [<span class="pl-s"><span class="pl-pds">"</span>Lexeme<span class="pl-pds">"</span></span>],
    [<span class="pl-s"><span class="pl-pds">"</span>Person<span class="pl-pds">"</span></span>,<span class="pl-s"><span class="pl-pds">"</span>Number<span class="pl-pds">"</span></span>,<span class="pl-s"><span class="pl-pds">"</span>Tense<span class="pl-pds">"</span></span>,<span class="pl-s"><span class="pl-pds">"</span>Voice<span class="pl-pds">"</span></span>,<span class="pl-s"><span class="pl-pds">"</span>Mood<span class="pl-pds">"</span></span>],
    ncol<span class="pl-k">=</span>n_features)</pre></div>
<p dir="auto">For this simulation, first random vectors are assigned to every lexeme and inflectional feature, and next the vectors of those features are summed up to obtain the semantic vector of the inflected form. Similar dimensions for C and S work best. Therefore, we retrieve the number of columns from the C matrix and pass it to <code>make_S_matrix</code> when constructing S.</p>
<p dir="auto">Then, the next step is to calculate a mapping from S to C by solving equation C = SG. We use Cholesky decomposition to solve this equation:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="G = JudiLing.make_transform_matrix(S, cue_obj.C)"><pre>G <span class="pl-k">=</span> JudiLing<span class="pl-k">.</span><span class="pl-c1">make_transform_matrix</span>(S, cue_obj<span class="pl-k">.</span>C)</pre></div>
<p dir="auto">Then, we can make our predicted C matrix Chat:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="Chat = S * G"><pre>Chat <span class="pl-k">=</span> S <span class="pl-k">*</span> G</pre></div>
<p dir="auto">and evaluate the model's prediction accuracy:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@show JudiLing.eval_SC(Chat, cue_obj.C)"><pre><span class="pl-c1">@show</span> JudiLing<span class="pl-k">.</span><span class="pl-c1">eval_SC</span>(Chat, cue_obj<span class="pl-k">.</span>C)</pre></div>
<p dir="auto">Output:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="JudiLing.eval_SC(Chat, cue_obj.C) = 0.9926"><pre lang="output" class="notranslate"><code>JudiLing.eval_SC(Chat, cue_obj.C) = 0.9926
</code></pre></div>

<p dir="auto"><strong><em>NOTE:</em></strong> Accuracy may be different depending on the simulated semantic matrix.</p>

<p dir="auto">To model speech production, the proper triphones have to be selected and put into the right order. We have two algorithms that accomplish this. Both algorithms construct paths in a triphone space that start with word-initial triphones and end with word-final triphones.</p>
<p dir="auto">The first step is to construct an adjacency matrix that specify which triphone can follow each other. In this example, we use the adjacency matrix constructed by <code>make_cue_matrix</code>, but we can also make use of a independently constructed adjacency matrix if required.</p>

<p dir="auto">There are two types of supports in outputs. An utterance level and a set of supports for each cue. The former support is also called "synthesis-by-analysis" support. This support is calculated by predicted S vector and original S vector and it is used to select the best paths. Cue level supports are slices of Yt matrices from each timestep. Those supports are used to determine whether a cue is eligible for constructing paths.</p>
