<p dir="auto">This package provides an implementation of the <a href="https://arxiv.org/abs/2010.02857" rel="nofollow">Interpolated Factored Green
Function Method (IFGF)</a> for accelerating the
evaluation of certain dense linear operators arising in boundary integral equation
methods. In particular, it provides an efficient approximation of the
matrix-vector product for both non-oscillatory kernels (e.g. Laplace, Stokes) and
oscillatory kernels (e.g. Helmholtz, Maxwell).</p>
<p dir="auto">To illustrate how the <code>IFGFOp</code> can be used to approximate dense linear maps,
consider the problem of computing <code>Ax</code> where <code>A</code> is an <code>M×N</code> matrix with
entries given by <code>A[i,j] = K(X[i],Y[j])</code>, with <code>K(x,y)=exp(ik|x-y|)/|x-y|</code> being
the kernel function, and <code>X,Y</code> being a vector of <code>M</code> and <code>N</code> points in three
dimensions. The following code show how one may set up the aforementioned
matrix:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using IFGF, LinearAlgebra, StaticArrays
import IFGF: wavenumber

# random points on a cube
const Point3D = SVector{3,Float64}
m,n = 100_000, 100_000
X,Y = rand(Point3D,m), rand(Point3D,n)

# define a the kernel matrix
struct HelmholtzMatrix &lt;: AbstractMatrix{ComplexF64}
    X::Vector{Point3D}
    Y::Vector{Point3D}
    k::Float64
end

# indicate that this is an ocillatory kernel with wavenumber `k`
wavenumber(A::HelmholtzMatrix) = A.k

# functor interface
function (K::HelmholtzMatrix)(x,y)
    k = wavenumber(K)
    d = norm(x-y)
    exp(im*k*d)*inv(4*pi*d)
end

# abstract matrix interface
Base.size(::HelmholtzMatrix) = length(X), length(Y)
Base.getindex(A::HelmholtzMatrix,i::Int,j::Int) = A(A.X[i],A.Y[j])

# create the abstract matrix
k = 2π   
A = HelmholtzMatrix(X,Y,k)"><pre><span class="pl-k">using</span> IFGF, LinearAlgebra, StaticArrays

<p dir="auto">Although the memory footprint of the object <code>A</code> is very small (it <em>lazily</em>
computes its entries), multiplying it by a vector has complexity proportional to
<code>m*n</code>, which can be prohibitively costly for large problem sizes. The <code>IFGFOp</code>
computes an approximation as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="L = assemble_ifgf(A,X,Y; tol = 1e-4)"><pre>L <span class="pl-k">=</span> <span class="pl-c1">assemble_ifgf</span>(A,X,Y; tol <span class="pl-k">=</span> <span class="pl-c1">1e-4</span>)</pre></div>
<p dir="auto">We can now use <code>L</code> in lieu of <code>A</code> to approximate the matrix vector product, as
illustrated below:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="x     = randn(ComplexF64,n)
y     = L*x"><pre>x     <span class="pl-k">=</span> <span class="pl-c1">randn</span>(ComplexF64,n)
y     <span class="pl-k">=</span> L<span class="pl-k">*</span>x</pre></div>
<p dir="auto">In order to assess the quality of the approximation, we may take a few random
rows and compare the approximate result against the exact one:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="I  = rand(1:m,100)
exact = [sum(A[i,j]*x[j] for j in 1:n) for i in I]
er    = norm(y[I]-exact) / norm(exact) "><pre>I  <span class="pl-k">=</span> <span class="pl-c1">rand</span>(<span class="pl-c1">1</span><span class="pl-k">:</span>m,<span class="pl-c1">100</span>)
exact <span class="pl-k">=</span> [<span class="pl-c1">sum</span>(A[i,j]<span class="pl-k">*</span>x[j] <span class="pl-k">for</span> j <span class="pl-k">in</span> <span class="pl-c1">1</span><span class="pl-k">:</span>n) <span class="pl-k">for</span> i <span class="pl-k">in</span> I]

<p dir="auto">The error should be smaller than the prescribed tolerance.</p>
