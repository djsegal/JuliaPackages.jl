<p dir="auto">XAIBase is a light-weight dependency that defines the interface of XAI methods in the <a href="https://github.com/Julia-XAI">Julia-XAI ecosystem</a>,
which focusses on post-hoc, local input space explanations of black-box models.
In simpler terms, methods that try to answer the question
<em>"Which part of the input is responsible for the model's output?"</em></p>
<p dir="auto">Building on top of XAIBase (or providing an interface via <a href="https://pkgdocs.julialang.org/v1/creating-packages/#Conditional-loading-of-code-in-packages-(Extensions)" rel="nofollow">package extensions</a>)
makes your package compatible with the Julia-XAI ecosystem,
allowing you to automatically compute heatmaps for vision and language models
using <a href="https://julia-xai.github.io/XAIDocs/VisionHeatmaps/stable/" rel="nofollow">VisionHeatmaps.jl</a>
and <a href="https://julia-xai.github.io/XAIDocs/TextHeatmaps/stable/" rel="nofollow">TextHeatmaps.jl</a>.
It also allows you to use input-augmentations from <a href="https://github.com/Julia-XAI/ExplainableAI.jl">ExplainableAI.jl</a>.</p>

<p dir="auto">XAIBase only requires you to fulfill the following two requirements:</p>
<ol dir="auto">
<li>An XAI algorithm has to be a subtype of <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.AbstractXAIMethod" rel="nofollow"><code>AbstractXAIMethod</code></a></li>
<li>An XAI algorithm has to implement a <code>call_analyzer</code> method:</li>
</ol>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import XAIBase: call_analyzer

call_analyzer(input, method::MyMethod, output_selector::AbstractOutputSelector; kwargs...)"><pre><span class="pl-k">import</span> XAIBase<span class="pl-k">:</span> call_analyzer

<span class="pl-c1">call_analyzer</span>(input, method<span class="pl-k">::</span><span class="pl-c1">MyMethod</span>, output_selector<span class="pl-k">::</span><span class="pl-c1">AbstractOutputSelector</span>; kwargs<span class="pl-k">...</span>)</pre></div>
<ul dir="auto">
<li><code>call_analyzer</code> has to return an <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.Explanation" rel="nofollow"><code>Explanation</code></a></li>
<li>the input is expected to have a batch dimensions as its last dimension</li>
<li>when applied to a batch, the method returns a single <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.Explanation" rel="nofollow"><code>Explanation</code></a>,
which contains the batched output in the <code>val</code> field.</li>
<li><a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.AbstractOutputSelector" rel="nofollow"><code>AbstractOutputSelector</code></a>
are predefined callable structs that select scalar values from a model's output,
e.g. the maximally activated output of a classifier using <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.MaxActivationSelector" rel="nofollow"><code>MaxActivationSelector</code></a>.</li>
</ul>
<p dir="auto">Refer to the <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/api/#XAIBase.Explanation" rel="nofollow"><code>Explanation</code></a> documentation for a description of the expected fields.
For more information, take a look at the <a href="https://julia-xai.github.io/XAIDocs/XAIBase/stable/" rel="nofollow">documentation</a>.</p>
