<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Limitations of computing symbolic limits</h1><a id="user-content-limitations-of-computing-symbolic-limits" class="anchor" aria-label="Permalink: Limitations of computing symbolic limits" href="#limitations-of-computing-symbolic-limits"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Zero equivalence of log-exp functions is undecidable and reducible to computing symbolic limits. Specifically, to
determine if the expression <code>x</code> is zero, compute the limit <code>limit(ϵ/(x + ϵ), ϵ, 0)</code>, which is 1 if <code>x == 0</code> and 0
if <code>x != 0</code>. This package implements a reduction in the reverse direction, and always produces an answer and
terminates. To avoid the undecidability issue, SymbolicLimits utilizes a heuristic iszero detector and, tracks all
its results as assumptions. The returned result is correct if the assumptions all hold. In practice, the heuristic
is pretty good and the assumptions typically all hold.</p>

<p dir="auto">The <code>limit</code> function is the whole of the public API of this package.</p>
<p dir="auto"><code>limit(expr, var, h[, side::Symbol])</code></p>
<p dir="auto">Compute the limit of <code>expr</code> as <code>var</code> approaches <code>h</code> and return <code>(limit, assumptions)</code>. If
all the <code>assumptions</code> are true, then the returned <code>limit</code> is correct.</p>
<p dir="auto"><code>side</code> indicates the direction from which <code>var</code> approaches <code>h</code>. It may be one of <code>:left</code>,
<code>:right</code>, or <code>:both</code>. If <code>side</code> is <code>:both</code> and the two sides do not align, an error is
thrown. Side defaults to <code>:both</code> for finite <code>h</code>, <code>:left</code> for <code>h = Inf</code>, and <code>:right</code> for
<code>h = -Inf</code>.</p>
