<p dir="auto"><code>ForwardMethods</code> provides macros that automate some of the boilerplate involved when using composition for object polymorphism. This package is essentially fancy copy + paste for forwarding function definitions, as well as providing automatically generated generic interfaces for struct types.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto"><code>@forward_methods</code></h1><a id="user-content-forward_methods" class="anchor" aria-label="Permalink: @forward_methods" href="#forward_methods"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Given a hypothetical definition for type <code>T</code> with a subfield <code>s</code> of type <code>S</code>, i.e.,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct T 
    ...
    s::S
    ...
end"><pre><span class="pl-k">struct</span> T 
    <span class="pl-k">...</span>
    s<span class="pl-k">::</span><span class="pl-c1">S</span>
    <span class="pl-k">...</span>
<span class="pl-k">end</span></pre></div>
<p dir="auto">suppose that type <code>S</code> has a number of existing functions defined as <code>f₁(..., obj::S, ...; kwargs...)</code>, ..., <code>fₙ(..., obj::S, ...; kwargs...)</code>. In the argument list here, <code>...</code> indicates a fixed number of preceding or following arguments (and not a Julia splatting pattern).</p>
<p dir="auto">If you wanted to define instances of these methods for <code>x::T</code> by forwarding them to <code>getfield(x, :s)</code>, the normal boilerplate code you would have to write in standard Julia would be</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    for f in (:f₁, ..., :fₙ)
        @eval $f(..., x::T, ...) = $f(..., getfield(x, :s), ...)
    end"><pre>    <span class="pl-k">for</span> f <span class="pl-k">in</span> (<span class="pl-c1">:f₁</span>, <span class="pl-k">...</span>, <span class="pl-c1">:fₙ</span>)
        <span class="pl-c1">@eval</span> <span class="pl-k">$</span><span class="pl-en">f</span>(<span class="pl-k">...</span>, x<span class="pl-k">::</span><span class="pl-c1">T</span>, <span class="pl-k">...</span>) <span class="pl-k">=</span> <span class="pl-k">$</span><span class="pl-c1">f</span>(<span class="pl-k">...</span>, <span class="pl-c1">getfield</span>(x, <span class="pl-c1">:s</span>), <span class="pl-k">...</span>)
    <span class="pl-k">end</span></pre></div>
<p dir="auto">which works fine when all of the functions <code>fᵢ</code> have same number of arguments and the position of the argument of type <code>S</code> is the same in each argument list. If this is not the case, it can be fairly tedious to generate all of the specific signature expressions to evaluate.</p>
<p dir="auto">The <code>@forward_methods</code> macro automates much of this boilerplate away by only requiring you to specify the type, the fieldname, and the signature of the methods you'd like to forward.</p>
<p dir="auto">To take a concrete example, suppose we define</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    struct T
        s::Vector{Int}
    end"><pre>    <span class="pl-k">struct</span> T
        s<span class="pl-k">::</span><span class="pl-c1">Vector{Int}</span>
    <span class="pl-k">end</span></pre></div>
<p dir="auto">We'd like to forward a number of method signatures corresponding to the <code>AbstractArray</code> interface. We can write this compactly using <code>@forward_methods</code> as:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    @forward_methods T field=s Base.length(x::T) Base.getindex(x::T, i::Int) Base.setindex!(x::T, v, i::Int)"><pre>    <span class="pl-c1">@forward_methods</span> T field<span class="pl-k">=</span>s Base<span class="pl-k">.</span><span class="pl-c1">length</span>(x<span class="pl-k">::</span><span class="pl-c1">T</span>) Base<span class="pl-k">.</span><span class="pl-c1">getindex</span>(x<span class="pl-k">::</span><span class="pl-c1">T</span>, i<span class="pl-k">::</span><span class="pl-c1">Int</span>) Base<span class="pl-k">.</span><span class="pl-c1">setindex!</span>(x<span class="pl-k">::</span><span class="pl-c1">T</span>, v, i<span class="pl-k">::</span><span class="pl-c1">Int</span>)</pre></div>
<p dir="auto">Here the position of the argument of interest will be inferred from the type annotation <code>::T</code>. We can write this even more compactly as</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    @forward_methods T field=s Base.length Base.getindex(_, i::Int) Base.setindex!(x::T, v, i::Int)"><pre>    <span class="pl-c1">@forward_methods</span> T field<span class="pl-k">=</span>s Base<span class="pl-k">.</span>length Base<span class="pl-k">.</span><span class="pl-c1">getindex</span>(_, i<span class="pl-k">::</span><span class="pl-c1">Int</span>) Base<span class="pl-k">.</span><span class="pl-c1">setindex!</span>(x<span class="pl-k">::</span><span class="pl-c1">T</span>, v, i<span class="pl-k">::</span><span class="pl-c1">Int</span>)</pre></div>
<p dir="auto">Here a <code>0-</code>argument expression <code>Base.length</code> is expanded to <code>Base.length(x::T)</code> and the placeholder underscore <code>_</code> is expanded to <code>x::T</code>.</p>
<p dir="auto">Rather than defining a forwarded method with an object argument to its child value, e.g., <code>x::T</code> -&gt; <code>getfield(x, :s)</code> as above, you can also forward the method with a type argument <code>::Type{T}</code> to <code>fieldtype(T, :s)</code> as follows</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    @forward_methods T field=s Base.eltype(::Type{T}) Base.IndexStyle(::Type{T})"><pre>    <span class="pl-c1">@forward_methods</span> T field<span class="pl-k">=</span>s Base<span class="pl-k">.</span><span class="pl-c1">eltype</span>(<span class="pl-k">::</span><span class="pl-c1">Type{T}</span>) Base<span class="pl-k">.</span><span class="pl-c1">IndexStyle</span>(<span class="pl-k">::</span><span class="pl-c1">Type{T}</span>)</pre></div>
<p dir="auto">Parametric types and type signatures are also supported, so if you have, say,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct A{B}
    d::Dict{String, B}
end"><pre><span class="pl-k">struct</span> A{B}
    d<span class="pl-k">::</span><span class="pl-c1">Dict{String, B}</span>
<span class="pl-k">end</span></pre></div>
<p dir="auto">you can easily forward parametric / non-parametric method definitions to field <code>d</code> simultaneously via</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    @forward_methods A{B} field=d (Base.getindex(a::A{B}, k::String) where {B}) Base.keys(x::A) Base.values(_)"><pre>    <span class="pl-c1">@forward_methods</span> A{B} field<span class="pl-k">=</span>d (Base<span class="pl-k">.</span><span class="pl-c1">getindex</span>(a<span class="pl-k">::</span><span class="pl-c1">A{B}</span>, k<span class="pl-k">::</span><span class="pl-c1">String</span>) <span class="pl-k">where</span> {B}) Base<span class="pl-k">.</span><span class="pl-c1">keys</span>(x<span class="pl-k">::</span><span class="pl-c1">A</span>) Base<span class="pl-k">.</span><span class="pl-c1">values</span>(_)</pre></div>
<p dir="auto">Letting <code>x::T</code> denote the object of interest, the value of the keyword argument <code>field = _field</code> has the following effects on the generated expressions:</p>
<ul dir="auto">
<li>
<p dir="auto">If <code>_field = k</code> with <code>k::Symbol</code> or a <code>k::QuoteNode</code>, or an expression of the form <code>getfield(_, k)</code>, in which case methods will be forwarded to <code>getfield(x, k)</code></p>
</li>
<li>
<p dir="auto">If <code>_field = a.b.c. ... .z</code> is a dotted expression, methods will be forwarded to <code>getfield(getfield(... getfield(getfield(x, :a), :b), ...), :z)</code></p>
</li>
<li>
<p dir="auto">If <code>_field</code> is an expression of the form <code>getproperty(_, k)</code>, the method instances will be forwarded to <code>getproperty(x, k)</code></p>
</li>
<li>
<p dir="auto">If <code>_field</code> is an expression of the form <code>t[args...]</code>, the method instances will be forwarded to <code>x[args...]</code></p>
</li>
<li>
<p dir="auto">If <code>_field</code> is an expression of the form <code>f(_)</code> for a single-argument function <code>f</code>, the method instances will be forwarded to <code>f(x)</code></p>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto"><code>@forward_interface</code></h1><a id="user-content-forward_interface" class="anchor" aria-label="Permalink: @forward_interface" href="#forward_interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If the type of <code>S</code> has a known interface (e.g., a fixed set of methods defined with a particular type signature), it may be more convenient to forward the entire suite of methods for that interface to objects <code>x::T</code>, rather than to specify each method signature individually.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    @forward_interface T field=_field interface=_interface [kwargs...]"><pre>    <span class="pl-c1">@forward_interface</span> T field<span class="pl-k">=</span>_field interface<span class="pl-k">=</span>_interface [kwargs<span class="pl-k">...</span>]</pre></div>
<p dir="auto">Here <code>T</code> and <code>_field</code> are as above and <code>_interface</code> is one of a preset number of values, namely <code>iteration</code>, <code>indexing</code>, <code>array</code>, <code>dict</code>, <code>getfields</code>, and <code>setfields</code>. The value of <code>_interface</code> determines the specific forwarded method signatures that are generated, e.g.,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct B
    b::Dict{String, Int}
end

@forward_interface B field=b interface=dict 

b = B(Dict{String,Int}())"><pre><span class="pl-k">struct</span> B
    b<span class="pl-k">::</span><span class="pl-c1">Dict{String, Int}</span>
<span class="pl-k">end</span>

<span class="pl-c1">@forward_interface</span> B field<span class="pl-k">=</span>b interface<span class="pl-k">=</span>dict 

b <span class="pl-k">=</span> <span class="pl-c1">B</span>(<span class="pl-c1">Dict</span><span class="pl-c1">{String,Int}</span>())</pre></div>
<p dir="auto"><code>b</code> can now be used as a drop-in replacement in any method where a <code>Dict{String,Int}</code> is supported.</p>
<p dir="auto">Note: certain methods for certain interfaces (e.g., <code>Base.similar</code> for the Array interface) are not included in this macro as direct method forwarding would not make sense to apply in these cases.</p>
<p dir="auto">The <code>getfields</code> and <code>setfields</code> interfaces are dynamically generated based on the fields of type <code>T</code>.</p>
<p dir="auto">When <code>interface=getfields</code>, this macro forwards methods of the form <code>$field(x::T) = getfield(x, $field)</code> for each <code>field ∈ fieldnames(T)</code></p>
<p dir="auto">When <code>interface=setfields</code>, this macro forwards methods of the form <code>$field!(x::T, value) = setfield!(x, $field, value)</code> for each <code>field ∈ fieldnames(T)</code></p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto"><code>@define_interface</code></h1><a id="user-content-define_interface" class="anchor" aria-label="Permalink: @define_interface" href="#define_interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Certain interfaces are defined for objects <code>x::T</code> that don't involve explicit forwarding to a fixed-field, per-se, but can be generally useful.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto"><code>properties</code> interface</h2><a id="user-content-properties-interface" class="anchor" aria-label="Permalink: properties interface" href="#properties-interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <code>properties</code> interface allows a unified <code>Base.propertynames</code>, <code>Base.getproperty</code>, and <code>Base.setproperty!</code> interface for <code>x::T</code> which is composed of subfields <code>k1, k2, ..., kn</code> whose fields should also be included in the properties of <code>x</code>. This pattern arises when creating composite types. For example,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; struct A
           key1::Int
           key2::Bool
       end

julia&gt; struct B
           key3::String
           key4::Float64
       end

julia&gt; struct C
           a::A
           b::B
       end

julia&gt; @define_interface C interface=properties delegated_fields=(a,b)

julia&gt; c = C(A(1, true), B(&quot;a&quot;, 0.0))
C(A(1, true), B(&quot;a&quot;, 0.0))

julia&gt; (key1=c.key1, key2=c.key2, key3=c.key3, key4=c.key4, a=c.a, b=c.b)
(key1 = 1, key2 = true, key3 = &quot;a&quot;, key4 = 0.0, a = A(1, true), b = B(&quot;a&quot;, 0.0))"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">struct</span> A
