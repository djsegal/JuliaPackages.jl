<p dir="auto">Transform an image into to a low-resolution artistic version using Delaunay Triangulation.</p>
<p dir="auto">This package is a learning exercise for me. YMMV. Some behind-the-scenes details are in <a href="https://jcarroll.com.au/2024/02/04/my-first-julia-package-triangulart-jl/" rel="nofollow">this blog post</a>.</p>
<p dir="auto">This began life as a Julia port of
<a href="https://www.degeneratestate.org/posts/2017/May/24/images-to-triangles/" rel="nofollow">this Python-based script</a>
by Iain Barr, but will likely diverge as time goes on.</p>

<p dir="auto">A small number of named options are available, including:</p>
<ul dir="auto">
<li><code>npts=100</code>: change the number of points to be sampled from the entropy</li>
<li><code>fast=false</code>: use a "fast" algorithm selecting points randomly, or a "slow"
entropy-based algorithm</li>
<li><code>refine=false</code>: use the <code>DelaunayTriangulation</code> <code>refine</code> method to add more
triangles where possible</li>
<li><code>debug=false</code>: draw the sampled points and edges explicitly</li>
<li><code>showimage=true</code>: show a grayscale version of the original image beneath the
debug points</li>
<li><code>showimagecol=true</code>: show a colour version of the original image beneath the
debug points</li>
</ul>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Method</h2><a id="user-content-method" class="anchor" aria-label="Permalink: Method" href="#method"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Following the <a href="https://www.degeneratestate.org/posts/2017/May/24/images-to-triangles/" rel="nofollow">the original script described here</a>,
this package first generates points spaced evenly around the border.</p>
<p dir="auto">Rather than randomly selecting points around the image, especially where there are
large blocks of a single colour, points should be selected where large changes occur,
e.g. from one colour to the another (an edge). I did attempt to solve this with an
edge-detection algorithm, but even better is to use the local entropy of the image,
determined as the number of bits required to encode the histogram of the grayscale
pixes in that region.</p>
<p dir="auto">The entropy of each point is calculated using a disk of 20px - this currently uses
<code>skimage</code> directly from python as the closest Julia implementation I could find uses a
square <code>ImageFiltering::mapwindow()</code>. Otherwise, a close equivalent would be</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="function shannon(w::AbstractMatrix)
    cm = collect(values(countmap(w))) / sum(size(w)) / 256
    sum([-x * log2(x) for x in cm])
end

# window dimensions must be odd
mapwindow(shannon, im1, (19, 19))"><pre class="notranslate"><code>function shannon(w::AbstractMatrix)
    cm = collect(values(countmap(w))) / sum(size(w)) / 256
    sum([-x * log2(x) for x in cm])
end

# window dimensions must be odd
mapwindow(shannon, im1, (19, 19))
</code></pre></div>
<p dir="auto">The point with the highest entropy is selected, then a Gaussian centered on
this point is subtracted from the entropy, reducing the neighbouring points
(so that the sampled points are not too close together).</p>
<p dir="auto">These two steps - calculating the entropy and finding the point with the
maximum entropy (currently via <code>findmax()</code>) are the two largest bottlenecks
to performance.</p>
<p dir="auto">Once <code>npts</code> are selected, a <code>DelaunayTriangulation::triangulate()</code> is performed
on the combined edge points and maximum-entropy points. If requested, this is
<code>DelaunayTriangulation::refine()</code>d.</p>
<p dir="auto">The triangle to which each pixel belongs is calculated, then the average colour
of each triangle is determined. The triangles are then drawn and filled with the
respective average colour.</p>
<p dir="auto">The source for the python version is <a href="https://github.com/jonocarroll/images-to-triangles">forked here</a> where I have made minor tweaks to bring it back up to date with current package versions.</p>

<li>
<p dir="auto">The white border around the produced image remains - I have tried setting

</li>
<li>
<p dir="auto">Performance is not as good as it can be, I suspect; the entropy calculation
(calling python) is definitely a bottleneck. Profiling also suggests the <code>findmax()</code>
is expensive.</p>
</li>
<li>
<p dir="auto">To speed up the processing, only every 10th pixel is used to determine the
average colour of the triangle - this may fail to identify an entire triangle.</p>
