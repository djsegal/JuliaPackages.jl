<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What does <code>BestieTemplate</code> do?</h2><a id="user-content-what-does-bestietemplate-do" class="anchor" aria-label="Permalink: What does BestieTemplate do?" href="#what-does-bestietemplate-do"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Creating <code>Julia</code> packages involve the creation and edition of many tiny files.
Wouldn't it be great to automate this?</p>
<p dir="auto">This is exactly what <code>BestieTemplate</code> does.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">FAQ</h3><a id="user-content-faq" class="anchor" aria-label="Permalink: FAQ" href="#faq"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>How is <code>BestieTemplate</code> different from <code>PkgTemplates</code>?
<ul dir="auto">
<li>it can be applied to existing packages</li>
<li>it invites to follow some (opinionated) best practices</li>
<li>it can be reapplied to acquire updates made to the template</li>
<li>it is automatically reapplied through Pull Requests made by the <code>Copier.yml</code> workflow (Work in progress)</li>
</ul>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Architecture</h3><a id="user-content-architecture" class="anchor" aria-label="Permalink: Architecture" href="#architecture"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Under the hood, <code>BestieTemplate</code> is no more and no less than:</p>
<ul dir="auto">
<li>a <a href="https://copier.readthedocs.io" rel="nofollow">copier</a> template/skeleton for Julia packages (see folder <a href="template">template</a>); and</li>
<li>a package that wraps <code>copier</code> in Julia using <code>PythonCall</code> with some convenience functions.</li>
</ul>

<p dir="auto">Here is a list of links/repos that include content that we have used for inspiration, or used directly.
This is most likely not a complete list, since many of the things included here were based on existing packages and knowledge that we brought from other projects.
This also doesn't explain where each file came from or why they are here. You can find some of that information in the <a href="https://abelsiqueira.com/BestieTemplate.jl/stable/20-explanation/" rel="nofollow">Explanation</a> section of the docs.</p>
<ul dir="auto">
<li><a href="https://github.com/JuliaCI/PkgTemplates.jl">PkgTemplates.jl</a>, naturally. We used it for many years, and in particular for the initial TulipaEnergyModel.jl commit (see below).</li>
<li><a href="https://github.com/NLeSC/python-template">Netherlands eScience Center's python template</a> includes many of the best practices that we apply here. We used many of the ideas there in a Julia context, and took many non-Julia specific ideas from there.</li>
<li><a href="https://github.com/TulipaEnergy/TulipaEnergyModel.jl">TulipaEnergyModel.jl</a> was the project that motivated this version of a template. From the start we decide to implement many best practices and so we started from a PkgTemplates.jl template and started adding parts of the python template that made sense.</li>
<li>The <a href="https://jso.dev" rel="nofollow">Julia Smooth Optimizers</a> package ecosystem was one of the main motivations to look for a solution that could be applied and reapplied to existing packages, in particular to help maintainers.</li>
</ul>
