<p dir="auto"><strong>QuantumCollocation.jl</strong> uses <a href="https://github.com/kestrelquantum/NamedTrajectories.jl">NamedTrajectories.jl</a> to set up and solve direct collocation problems specific to quantum optimal control, i.e. generating a <em>pulse</em> sequence <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="725133c97cecb3fe0db287e4e7e5fbb6">$a_{1:T-1}$</math-renderer> to drive a quantum system and realize a target gate <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="725133c97cecb3fe0db287e4e7e5fbb6">$U_{\text{goal}}$</math-renderer>. We formulate this problem as a nonlinear program (NLP) of the form</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="725133c97cecb3fe0db287e4e7e5fbb6">$$\begin{aligned}
\underset{U, a, \Delta t}{\text{minimize}} &amp; \quad \ell(U_T, U_{\text{goal}})\\\
\text{ subject to } &amp; \quad U_{t+1} = \exp(-i \Delta t H(a_t)) U_t 
\end{aligned}$$</math-renderer>
<p dir="auto">Where the dynamics between <em>knot points</em> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="725133c97cecb3fe0db287e4e7e5fbb6">$(U_t, a_t)$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="725133c97cecb3fe0db287e4e7e5fbb6">$(U_{t+1}, a_{t+1})$</math-renderer> are enforced as constraints on the states which are free variables in the solver; this optimization framework is called <em>direct collocation</em>.  For details of our implementation please see our award-winning IEEE QCE 2023 paper, <a href="https://arxiv.org/abs/2305.03261" rel="nofollow">Direct Collocation for Quantum Optimal Control</a>. If you use QuantumCollocation.jl in your work, please cite 🙌!</p>
<p dir="auto">QuantumCollocation.jl gives the user the ability to add other constraints and objective functions to this problem and solve it efficiently using <a href="https://github.com/jump-dev/Ipopt.jl">Ipopt.jl</a> and <a href="https://github.com/jump-dev/MathOptInterface.jl">MathOptInterface.jl</a> under the hood.</p>

<p dir="auto"><strong>Install Julia</strong> <a href="https://github.com/JuliaLang/juliaup">Juliaup</a> is an installer and version manager. This is one useful way to manage Julia versions and keep up with the latest changes. After installing, run <code>julia</code> to obtain the Julia <em>REPL</em>.</p>
<p dir="auto"><strong>Julia environments</strong>
<a href="https://pkgdocs.julialang.org/v1/environments/#Using-someone-else's-project" rel="nofollow">(Documentation)</a> Your project's environment is stored in <em>Project.toml</em>. You can interactively add packages to an environment by using the Julia command line <em>REPL</em> and <em>package manager</em>.  Start Julia in the project folder. Type <code>]</code> to enter the package manager. Type <code>activate .</code> to activate or create an environment specified by <em>Project.toml</em> located in the current folder. Separately, you generate a manifest (solving the versions to create a valid environment) by running <code>instantiate</code>; instantiate will check that the environment is correct after you add all the packages you want.</p>
<p dir="auto"><strong>Adding packages</strong>
<a href="https://pkgdocs.julialang.org/v1/managing-packages/#Adding-packages" rel="nofollow">(Documentation)</a> The initial cell for a Piccolo notebook might look something like the following:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# Standard packages
using LinearAlgebra
using CairoMakie

# Piccolo packages
using QuantumCollocation

using TrajectoryIndexingUtils"><pre><span class="pl-c"><span class="pl-c">#</span> Standard packages</span>

<p dir="auto">First, let's install some standard packages (these are like Numpy and Matplotlib). Open the package manager in the current environment (type <code>julia</code>, <code>]</code>, and <code>activate .</code>), type <code>add LinearAlgebra</code> to install and precompile <em>LinearAlgebra</em>. Same with <code>CairoMakie</code>.</p>
<p dir="auto">Second, let's install <em>Piccolo</em>. There are three packages (<em>QuantumCollocation</em>, <em>NamedTrajetories</em>, <em>TrajectoryIndexingUtils</em>) inside <a href="https://docs.juliahub.com/General/Piccolo/stable/" rel="nofollow">Piccolo</a>. We could do <code>add Piccolo</code> to get the three as a bundle from the Julia repository. Instead of individually calling <code>using ...</code> for each, this approach only requires <code>using Piccolo</code> at the start of a file or notebook.</p>
<p dir="auto">As a developer, we want to use the git repositories directly from <a href="https://github.com/kestrelquantum">the Kestrel Quantum Github page</a>. Clone, then add the local packages to the Project file with e.g. <code>dev ../relative/path/to/repo/QuantumCollocation</code>. This command installs the development version of <em>QuantumCollocation</em> pointing to the local Github code instead of the package repository. You can repeat this for the others, also.</p>

<p dir="auto"><strong>Julia extension</strong> You can run Julia notebooks and much more with <a href="https://code.visualstudio.com/docs/languages/julia" rel="nofollow">the Julia extension</a>. Upon opening your project folder in VS code and attempting to run an <code>.ipynb</code>, you will see that VS Code finds the interpreters managed by juliaup and defaults to using the environment based on the <em>Project.toml</em> in the project directory.</p>
<p dir="auto"><strong>Fonts</strong> VS Code will not display all characters allowed by Julia. You can change the editor font family in the settings to <code>'JuliaMono'</code> to get full support. If you don't want to mix and mash, you can create a new VS Code settings profile for working in Julia at <em>File&gt;Preferences&gt;Profile</em>.</p>
<p dir="auto"><strong>Tests</strong> Tests should automatically populate in VS Code when working with a Piccolo package. For example, just by adding the <code>QuantumCollocation.jl</code> folder to your workspace, you should see tests appear if you click on the <em>Testing</em> sidebar icon. If you run one of these tests, a new Julia kernel is spawned for the test. You can find the kernel if you click on the <em>Julia</em> sidebar icon (after installing the Julia extensions). Sometimes, for the tests to recognize new changes, you may need to manually kill this kernel to see your changes reflected.</p>
