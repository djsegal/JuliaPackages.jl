<p dir="auto">Split many kinds of expressions into detailed parts, play with them, and put them back together again.
Think of it as a really souped-up version of <code>splitdef()</code> and <code>splitarg()</code> from <strong>MacroTools.jl</strong>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="using CodeSculptor

<ul dir="auto">
<li><code>SplitFunction</code> for function calls and definitions</li>
<li><code>SplitMacro</code> for macro invocations</li>
<li><code>SplitMeta</code> for metadata around a definition, such as a docstring or <code>@inline</code></li>
<li><code>SplitType</code> for type declarations (like <code>C{R, T&lt;:Integer} &lt;: B</code>)</li>
<li><code>SplitArg</code> for function arguments (like <code>a::Int...</code>)</li>
</ul>
<p dir="auto">Each field on the <code>SplitX</code> types is documented with comments.</p>
<p dir="auto">Each split type can return <code>nothing</code> when constructed, if the expression fails to parse.
The constructors can also run in a less strict mode by passing <code>false</code> into the constructor,
for example to stop <code>SplitFunction</code> from verifying that a function name has valid syntax.</p>
<p dir="auto">Each of them can be deep-copied by constructing with a source instance to copy from.
Some of them offer extra flags to skip copying particular parts of the AST.</p>

<ul dir="auto">
<li><code>is_scopable_name(expr)</code> checks that the expression is either a Symbol or a series of Symbols separated by a <code>.</code> expression. Optionally allows type parameters at the end, like <code>A.B{C}</code>.</li>
<li><code>expr_deepcopy(e)</code> works like deepcopy, but without copying special literals/interpolated references (like a <code>Module</code>).</li>
<li><code>visit_exprs(e)</code> is like <code>MacroTools.postwalk()</code>, but without modifying anything and with extra provided data that tells you exactly where you are in the original AST.</li>
<li><code>unescape(e)</code> and <code>unescape_deep(e)</code> help remove <code>esc()</code> from expressions.</li>
</ul>

<p dir="auto">There are some tools to map between operators and assignments (e.x. <code>+</code> and <code>+=</code>).</p>
<ul dir="auto">
<li><code>ASSIGNMENT_INNER_OP</code> maps assignment to operator</li>
<li><code>ASSIGNMENT_WITH_OP</code> maps operator to assignment</li>
<li><code>compute_op(s::Union{Symbol, Val}, a, b)</code> computes an assignment as an operator
<ul dir="auto">
<li>For example, <code>compute_op(:+=, 3, 4)</code> returns <code>compute_op(Val(:+=), 3, 4)</code> returns <code>7</code>.</li>
</ul>
</li>
</ul>
