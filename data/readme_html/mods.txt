<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Quick Overview</h2><a id="user-content-quick-overview" class="anchor" aria-label="Permalink: Quick Overview" href="#quick-overview"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This module supports modular values and arithmetic. The moduli are integers (at least 2)
and the values are either integers or Gaussian integers.</p>
<p dir="auto">An element of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f5d1d8b8248cabde8d9f4693aa9e4579">$\mathbb{Z}_N$</math-renderer> is entered as <code>Mod{N}(a)</code> and is of type <code>Mod{N}</code>.
An element of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f5d1d8b8248cabde8d9f4693aa9e4579">$\mathbb{Z}_N[i]$</math-renderer> is entered a <code>Mod{N}(a+b*im)</code> and is of type
<code>GaussMod{N}</code>. Both types are fully interoperable with each other and with
(ordinary) integers and Gaussian integers.</p>

<p dir="auto">Integers modulo <code>N</code> (where <code>N&gt;1</code>) are values in the set
<code>{0,1,2,...,N-1}</code>. All arithmetic takes place modulo <code>N</code>. To create a mod-<code>N</code> number
we use <code>Mod{N}(a)</code>. For example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; Mod{10}(3)

<p dir="auto">The usual arithmetic operations may be used. Furthermore, oridinary integers can be
combined with <code>Mod</code> values. However, values of different moduli cannot be used
together in an arithmetic expression.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Limitations</h2><a id="user-content-limitations" class="anchor" aria-label="Permalink: Limitations" href="#limitations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The modulus and value of a <code>Mod</code> number are of type <code>Int</code> (or <code>Complex{Int}</code> for <code>GaussMod</code> numbers). This implies that the largest possible modulus is <code>typemax(Int)</code> which equals <code>2^63-1</code>
(assuming a 64-bit system).</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Overflow safety</h3><a id="user-content-overflow-safety" class="anchor" aria-label="Permalink: Overflow safety" href="#overflow-safety"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Integer operations on 64-bit numbers can give results requiring more than
64 bits. Fortunately, when working with modular numbers the results of
the operations are bounded by the modulus.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; N = 10^18                # this is a 60-bit number
1000000000000000000

julia&gt; a = 10^15
1000000000000000

julia&gt; a*a                      # We see that a*a overflows
5076944270305263616

julia&gt; Mod{N}(a*a)              # this gives an incorrect answer

<p dir="auto">The result of <code>Mod{N}(a//b)</code> is exactly
<code>Mod{N}(numerator(a)) / Mod{N}(denominator(b))</code>. This may equal
<code>Mod{N}(a)/Mod{N}(b)</code> if <code>a</code> and <code>b</code> are relatively prime to each other
and to <code>N</code>.</p>
<p dir="auto">When a <code>Mod</code> and a <code>Rational</code> are operated with each other, the
<code>Rational</code> is first converted to a <code>Mod</code>, and then the operation
proceeds.</p>
<p dir="auto">Bad things happen if the denominator and the modulus are not
relatively prime.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Version 2 vs Version 1 of <code>Mods</code></h2><a id="user-content-version-2-vs-version-1-of-mods" class="anchor" aria-label="Permalink: Version 2 vs Version 1 of Mods" href="#version-2-vs-version-1-of-mods"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In version 2 the modulus of a <code>Mod</code> number must be of type <code>Int</code>.
If a <code>Mod</code> number is constructed with any other typeof <code>Integer</code>, the
constructor will (try to) convert it to type <code>Int</code>.</p>
<p dir="auto">The old style <code>Mod{N,T}(v)</code> no longer works.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Why this change?</h3><a id="user-content-why-this-change" class="anchor" aria-label="Permalink: Why this change?" href="#why-this-change"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There were various issues in the earlier version of <code>Mods</code> that are
resolved by requiring <code>N</code> to be of type <code>Int</code>.</p>
<ul dir="auto">
<li>
<p dir="auto">Previously <code>Mod</code> numbers created with different sorts of integer parameters would
be different. So if <code>N = 17</code> and <code>M = 0x11</code>, then <code>Mod{N}(1)</code> would not be interoperable with <code>Mod{M}(1).</code></p>
</li>
<li>
<p dir="auto">The internal storage of the value of the <code>Mod</code> numbers could be  different.
For example, <code>Mod{17}(-1)</code> would store the
value internally as <code>-1</code> whereas <code>Mod{17}(16)</code> would store the value as <code>16</code>.</p>
</li>
<li>
<p dir="auto">Finally, if the modulus were a large <code>Int128</code> number, then arithmetic
operations could silently fail.</p>
</li>
</ul>
<p dir="auto">We believe that the dominant use case for this module will be with moduli between
<code>2</code> and <code>2^63-1</code> and so we do not expect this change to affect
users. Further, since <code>Mod</code> numbers that required <code>Int128</code> moduli were
likely to give incorrect results, version 1 of this module was buggy.</p>
<p dir="auto">In addition, some functionality has been moved to the <code>extras</code> folder.
See the <code>README</code> there. In particular, the <code>CRT</code> function is no longer part of the <code>Mods</code>
module but resides in <code>extras/CRT.jl</code>.</p>

<p dir="auto">Since moduli are of type <code>Int</code>, a <code>Mod</code> numbers uses 8 bytes (and a <code>GaussMod</code> uses 16 bytes). A
large matrix of <code>Mod</code> numbers could unnecessarily use a lot of memory, especially if the moduli
are small.</p>
<p dir="auto">Some solutions to this problem:</p>
<ul dir="auto">
<li>Use the latest Version 1 of <code>Mods</code>.</li>
<li>Create a cloned copy of the <code>Mods</code> package and edit this line in the file <code>Mods.jl</code>:</li>
</ul>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const value_type = Int                # storage type for the value in a Mod"><pre><span class="pl-k">const</span> value_type <span class="pl-k">=</span> Int                <span class="pl-c"><span class="pl-c">#</span> storage type for the value in a Mod</span></pre></div>
<p dir="auto">to set <code>value_type</code> to a smaller type of integer (say, <code>Int16</code>).</p>
<ul dir="auto">
<li>For very small moduli (between 2 and 255) see the <a href="https://github.com/scheinerman/MiniMods.jl">MiniMods</a> module.</li>
</ul>
