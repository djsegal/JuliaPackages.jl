<p dir="auto">General and composable utilities for manipulating tabular, quasi-tabular, and non-tabular datasets.</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer nofollow" href="https://camo.githubusercontent.com/0623b88abd55bb660fdd610ab9a75c6cbb34a7abfd7a40da32e92f0654636f2a/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f6d6f7469766174696f6e2d7768792533462d627269676874677265656e"><img src="https://camo.githubusercontent.com/0623b88abd55bb660fdd610ab9a75c6cbb34a7abfd7a40da32e92f0654636f2a/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f6d6f7469766174696f6e2d7768792533462d627269676874677265656e" alt="" data-canonical-src="https://img.shields.io/badge/motivation-why%3F-brightgreen" style="max-width: 100%;"></a> Base Julia provides the most foundational building blocks for data processing, such as <code>map</code> and <code>filter</code> functions. The goal of <code>DataManipulation</code> is to extend common data processing functionality on top of that. This package provides more general mapping over datasets, grouping, selecting, reshaping and so on.</p>
<p dir="auto"><code>DataManipulation</code> handles basic data structures already familiar to Julia users and doesn't require switching to custom specialized dataset types. All functions aim to stay composable and support datasets represented as Julia collections: arrays, dictionaries, tuples, many <code>Tables</code> types, ... .</p>
<p dir="auto"><em>Note</em> This package is intended primarily for interactive usage: load <code>DataManipulation</code> and get access to a wide range of data processing tools. Other packages should prefer depending on individual packages listed below, when possible. Nevertheless, <code>DataManipulation</code> follows semver and is well-tested.</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer nofollow" href="https://camo.githubusercontent.com/06e1a37bf7a3410857b1c634bc17ca45940f6f2203e62facf2935f181b6a8069/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f636f6d706f6e656e74732d776861742773253230696e736964652533462d627269676874677265656e"><img src="https://camo.githubusercontent.com/06e1a37bf7a3410857b1c634bc17ca45940f6f2203e62facf2935f181b6a8069/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f636f6d706f6e656e74732d776861742773253230696e736964652533462d627269676874677265656e" alt="" data-canonical-src="https://img.shields.io/badge/components-what's%20inside%3F-brightgreen" style="max-width: 100%;"></a> <code>DataManipulation</code> functionality consists of two major parts.</p>
<ul dir="auto">
<li>
<p dir="auto">Reexports from companion packages, each focused on a single area. These packages are designed so that they work together nicely and provide consistent and uniform interfaces:</p>
<ul dir="auto">
<li><a href="https://gitlab.com/aplavin/DataPipes.jl" rel="nofollow">DataPipes.jl</a>: boilerplate-free piping for data manipulation</li>
<li><a href="https://gitlab.com/aplavin/FlexiMaps.jl" rel="nofollow">FlexiMaps.jl</a>: functions such as <code>flatmap</code>, <code>filtermap</code>, and <code>mapview</code>, extending the all-familiar <code>map</code></li>
<li><a href="https://gitlab.com/aplavin/FlexiGroups.jl" rel="nofollow">FlexiGroups.jl</a>: group data by arbitrary keys &amp; more</li>
<li><a href="https://gitlab.com/aplavin/Skipper.jl" rel="nofollow">Skipper.jl</a>: <code>skip(predicate, collection)</code>, a generalization of <code>skipmissing</code></li>
<li><a href="https://github.com/JuliaObjects/Accessors.jl">Accessors.jl</a>: modify nested data structures conveniently with optics</li>
</ul>
<p dir="auto">See the docs of these packages for more details.</p>
<p dir="auto">Additionally, <a href="https://gitlab.com/aplavin/FlexiJoins.jl" rel="nofollow">FlexiJoins.jl</a> is considered a companion package with relevant goals and compatible API. For now it's somewhat heavy in terms of dependencies and isn't included in <code>DataManipulation</code>, but can be added in the future.</p>
</li>
<li>
<p dir="auto">Functions defined in <code>DataManipulation</code> itself: they do not clearly belong to a narrower-scope package, or just have not been split out yet. See the docstrings for details.</p>
<ul dir="auto">
<li><code>findonly</code>, <code>filteronly</code>, <code>filterfirst</code>, <code>uniqueonly</code>: functions with the semantics of corresponding Base function combinations, but more efficient and naturally support <code>Accessors.set</code>.</li>
<li><code>sortview</code>, <code>uniqueview</code>, <code>collectview</code>: non-copying versions of corresponding Base functions.</li>
<li>zero-cost property selection, indexing, and nesting by regex: <code>sr"regex"</code> literal, <code>nest</code> function</li>
<li>And more: <code>discreterange</code>, <code>shift_range</code>, <code>rev</code></li>
</ul>
</li>
</ul>
