<p dir="auto">SecureArithmetic.jl is a Julia package for performing cryptographically secure arithmetic
operations using fully homomorphic encryption. It currently provides a backend for
OpenFHE-secured computations using <a href="https://github.com/hpsc-lab/OpenFHE.jl">OpenFHE.jl</a>, and
an unencrypted backend for fast verification of a computation pipeline.</p>

<p dir="auto">If you have not yet installed Julia, please <a href="https://julialang.org/downloads/platform/" rel="nofollow">follow the instructions for your
operating system</a>.
<a href="https://github.com/hpsc-lab/SecureArithmetic.jl">SecureArithmetic.jl</a> works with Julia v1.8
and later on Linux and macOS platforms, and with Julia v1.9 or later on Windows platforms.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Memory issues</h3><a id="user-content-memory-issues" class="anchor" aria-label="Permalink: Memory issues" href="#memory-issues"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">OpenFHE is a memory-optimized C++ library, but these optimizations can cause
memory issues when transitioning to Julia.</p>
<p dir="auto">In OpenFHE, large objects like <code>Ciphertext</code>, <code>Plaintext</code>, and <code>CryptoContext</code> are managed
using <code>std::shared_ptr</code>. These objects are not freed until all associated <code>std::shared_ptr</code>s
are destroyed. Since the Julia objects that hold a reference to these shared pointers are relatively
small, Julia's garbage collector does not always free them automatically, as they are not considered
a high priority for garbage collection. This is because Julia's garbage collector primarily
focuses on "young" objects during its incremental collections, leaving some <code>std::shared_ptr</code>s
in memory even when they are no longer in use. This may result in a significant increase in memory
consumption over time, as a single <code>Ciphertext</code> object can occupy over 60 MB. Consequently, complex
operations may lead to gigabytes of memory being occupied without being freed until the Julia
session is terminated. One possible solution is to manually trigger Julia's garbage collector
to perform a full collection, which will also clean up these "small" objects:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="GC.gc()"><pre>GC<span class="pl-k">.</span><span class="pl-c1">gc</span>()</pre></div>
<p dir="auto">Additionally, OpenFHE optimizes memory usage in C++ by storing evaluation keys and <code>CryptoContext</code>s
in static objects. These objects, being quite large, remain in memory until the Julia REPL is
closed. To release them while the REPL is still running, you can execute the following function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="release_context_memory()"><pre><span class="pl-c1">release_context_memory</span>()</pre></div>
<p dir="auto">Note that this will invalidate all currently existing contexts, even those which are
still in use. Thus you should only call these functions once you are done with a given
FHE setup and want to start a new one.
For more details, please refer to the documentation for <a href="@ref"><code>release_context_memory</code></a>.</p>
<p dir="auto">Therefore, for a full cleanup of all OpenFHE-occupied memory, first ensure that all variables holding
references to OpenFHE objects are out of scope and then execute</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="release_context_memory()
GC.gc()"><pre><span class="pl-c1">release_context_memory</span>()
GC<span class="pl-k">.</span><span class="pl-c1">gc</span>()</pre></div>
<p dir="auto">By running these commands at appropriate points in your code, you can prevent excessive memory
usage and ensure efficient memory management when using SecureArithmetic.jl.</p>
