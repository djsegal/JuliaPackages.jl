<p dir="auto">A new program for the simulating and fitting of molecular rotational spectra for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$C_s$</math-renderer> molecules with one internal rotor and one spin source.</p>
<p dir="auto">The paper is available <a href="https://doi.org/10.1016/j.jms.2024.111928" rel="nofollow">here</a> and the pre-print is available <a href="https://dx.doi.org/10.2139/ssrn.4807560" rel="nofollow">here</a>.</p>
<p dir="auto">Please feel free to direct any questions about the program to <a href="mailto:westerfit@proton.me">westerfit@proton.me</a></p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Quickstart</h1><a id="user-content-quickstart" class="anchor" aria-label="Permalink: Quickstart" href="#quickstart"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The following is intended to be a quick reference on the input file structure &amp; program usage. A more complete manual will be constructed once the paper is published.
The westerfit input file is divided into three sections each with a designated header. The very first line is a title card and the sections are the Control Settings (%CNTRLS), Second Order Parameters (%2NDORDER), and the additional Operators &amp; Parameters (%PARAMS).</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Control Settings</h3><a id="user-content-control-settings" class="anchor" aria-label="Permalink: Control Settings" href="#control-settings"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Below are control settings, their meanings, and default values::Type</p>
<p dir="auto"><strong>apology</strong> (true::Bool): Prints a sincere if awkward apology for the name of the program</p>
<p dir="auto"><strong>RUNmode</strong> (ESF::String): Dictates how the program is run by finding characters in string. E calculates &amp; prints energy levels, S calculates &amp; prints transitions, and F performs the optimization. ES will run through the same calculations as S but without printing energy levels. The Fit will run first and then put the new parameters into the ES calculation.</p>
<p dir="auto"><strong>overwrite</strong> (true::Bool): Whether or not to overwrite the input file with the new values from the fit. Regardless, the input file will be copied to a back up.</p>
<p dir="auto"><strong>S</strong> (0::Float64): Spin value of the internal spin source. This can be either electron or nuclear spin</p>
<p dir="auto"><strong>NFOLD</strong> (0::Int): Symmetry-fold of the internal rotor. 0 disables most of the torsional code (I think)</p>
<p dir="auto"><strong>mcalc</strong> (8::Int): Determines the size of the torsional basis as 2mcalc+1 for A &amp; E symmetry states and 2mcalc+2 for B symmetry. BELGI uses 10 for the first stage and the equivalent of 4 for the second stage. I've found 5 to work reasonably well without being repulsively slow.</p>
<p dir="auto"><strong>vtmax</strong> (0::Int): Largest torsional state output by the code. I <em>think</em> this also impacts what torsional states are used in the fitter. Best to keep with just ground state for now.</p>
<p dir="auto"><strong>Jmax</strong> (0.0::Float64): Largest J value in the simulation. The code will automatically adjust if S is a half integer and print a warning.</p>
<p dir="auto"><strong>νmin</strong> (0.0::Float64): Lowest frequency in the simulation in GHz. The first character is a <em>nu</em> not a v so be careful</p>
<p dir="auto"><strong>νmax</strong> (40.::Float64): Highest frequency in the simulation in GHz. Make sure this is larger than νmin or the code will crash</p>
<p dir="auto"><strong>INTthres</strong> (0.0::Float64): Minimum intensity value included in the file</p>
<p dir="auto"><strong>TK</strong> (8.0::Float64): Temperature of the simulation in Kelvin</p>
<p dir="auto"><strong>λlm0</strong> (0.0001::Float64): Scale-factor used to determine the inital Levenberg-Marquardt Parameter. This gets multiplied by a function of the rms to determine the LBMQ Parameter used in a given step.</p>
<p dir="auto"><strong>turducken</strong> (1::Int): Number of Levenberg-Marquardt steps calculated on single step before recalculated the Jacobian. Doesn't seem worth it given the current performance of the Jacobian but can give an occasional performance boost</p>
<p dir="auto"><strong>goal</strong> (1.0::Float64): The value of the weighted RMS that terminates the fit. Intended to prevent fitting past the experimental resolution.</p>
<p dir="auto"><strong>assign</strong> (expect::String): Determines how the quantum numbers are assigned after diagonalization. The default, <strong>expect</strong>, uses the expectation values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$m$</math-renderer> &amp; then <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$N$</math-renderer> followed by an energetic sorting to assign <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$K$</math-renderer>. <strong>RAM36</strong> uses the contributions of different blocks of the eigenvectors to provide a spin-expanded version of the assigner in RAM36. <strong>expectk</strong> is similar to expect but uses the expectation values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$K$</math-renderer> as well and doesn't seem to work. Lastly, <strong>eeo</strong> does the expection values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$m$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$N$</math-renderer> followed by eigenvector analysis to assign <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$K$</math-renderer>. This does the best job of reproducing SPFIT's DIAG=3. Generally <strong>expect</strong> is recommended but <strong>RAM36</strong> works very nicely for single perturbations (spin or torsion). I'm personally fond of the theory in <strong>eeo</strong> but find its performance lacking.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Second Order Parameters</h3><a id="user-content-second-order-parameters" class="anchor" aria-label="Permalink: Second Order Parameters" href="#second-order-parameters"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The second order Hamiltonian of westerfit is hardcoded. You can comment out any lines with # but the number of lines must remain fixed in this section. All the parameters default to zero and there are some internal transformations that occur upon initializing the code.</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$A$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$B$</math-renderer>, and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$C$</math-renderer> are the rotational constants corresponding to the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$z$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$x$</math-renderer>, and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$y$</math-renderer> molecule fixed axes respectively.
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$D_{ab}$</math-renderer> is the off-diagonal rotational constant on the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$z$</math-renderer> axes for the Rho Axis Method.
When it is included, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$A$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$B$</math-renderer> refer to their RAM meanings not their PAM meanings. These are all in MHz</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$F$</math-renderer> is the internal rotor constant. It is the reduced value as is used in RAM36.
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\rho_z$</math-renderer> is the coupling term between the methyl rotation and the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$z$</math-renderer>-axis angular momentum.
It engages in the Hamiltonian as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$-2\rho FP_{\alpha}N_{z}$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$(A-F\rho^{2})N_{z}^{2}$</math-renderer>.
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\rho_x$</math-renderer> is analogous to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\rho_z$</math-renderer> though for the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$x$</math-renderer>-axis.
For RAM fits, leave this as zero but it can be included for PAM fits.
The <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$Vn$</math-renderer> is the first term in the potential expansion as determined by NFOLD.</p>
<p dir="auto">The <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\epsilon$</math-renderer> terms are the spin-rotation coupling terms referring to axes in their subscripts.
If only one of either <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\epsilon_{zx}$</math-renderer> or <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\epsilon_{xz}$</math-renderer> is provided, the code will internally treat the value as average term, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$T^2_{\pm}(\epsilon)$</math-renderer>.
These are transformed into spherical tensor notation upon start of the code.
These can also serve as nuclear spin-rotation coupling as they are mathematically equivalent.</p>
<p dir="auto">The <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\chi$</math-renderer> terms are the quadrupole terms, again referring to the axes in their subscript.
This can be used as either the electronic spin-spin in molecules of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$S\ge1$</math-renderer> or as the nuclear electric quadrupole moment for molecules with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$I\ge1$</math-renderer>.
They are also transformed into spherical tensor form upon initializaiton.</p>
<p dir="auto">Lastly are the spin-torsion coupling terms <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\eta_z$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$\eta_x$</math-renderer> which refer to the operators <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$S_zP_{\alpha}$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$S_xP_{\alpha}$</math-renderer>.
Definitions of the operators are provided in the paper.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Higher order operators</h3><a id="user-content-higher-order-operators" class="anchor" aria-label="Permalink: Higher order operators" href="#higher-order-operators"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">These are manual coded in operators that are implemented as the anti-commutator of what the user codes in.
These lines can also be commented out but do not remove the lines opening with %.
The first column is a name string for the operators.
Here are some unicode characters for easier name: Δ, δ, Φ, ϕ, ϵ, χ, ρ, η, μ.
The second &amp; third columns are Float64 and are the parameter value and step scale factor, respectively. A scale factor of zero will keep that operator fixed during the optimization.
The next 8 columns are Int referring to the powers of the various operators as described in the line beginign that block of the input file.
There are no checks of symmetry like in RAM36 so go wild.
One could also code in inverse powers but I'm not sure why one would.
Let me know if you do and how it helped!
The last column is a stage. It is either 0 for intensites of 1 for Hamiltonian operators. Might expand that if I come up with better code structures.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Line File Format</h3><a id="user-content-line-file-format" class="anchor" aria-label="Permalink: Line File Format" href="#line-file-format"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The experimental transitions should be included in the molnam.lne file.
This uses a comma delimited format in the following structure:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Ju, Nu, Kau, Kcu, mu, Jl, Nl, Kal, Kcl, ml, freq, unc"><pre class="notranslate"><code>Ju, Nu, Kau, Kcu, mu, Jl, Nl, Kal, Kcl, ml, freq, unc
</code></pre></div>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$J$</math-renderer> is the total angular momentum (called <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$F$</math-renderer> for cases with nuclear spin) and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$N$</math-renderer> is the angular momentum of the molecular frame.
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$K_a$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$K_c$</math-renderer> are the traditional assymetric top state labels and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0f851fc5d06c60c8c9f16bc069d29cf0">$m$</math-renderer> is the free rotor quantum number.
The u and l labels denote the upper and lower states respectively.
Lastly, freq is the experimental frequency and unc is the uncertainty in the line position which is used for weighting in the Levenberg-Marquadt routine.
Make sure that Ju, Jl, freq, and unc are all floating point numbers (include a decimal point) and all the rest are integers.</p>
