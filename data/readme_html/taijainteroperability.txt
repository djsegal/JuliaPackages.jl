<p dir="auto">A package for enabling interoperability between Python and R machine learning models with Taija.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Importing PyTorch models</h2><a id="user-content-importing-pytorch-models" class="anchor" aria-label="Permalink: Importing PyTorch models" href="#importing-pytorch-models"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The package combined with CounterfactualExplanations supports generating counterfactuals for any neural network that has been previously defined and trained using PyTorch, regardless of the specific architectural details of the model. To generate counterfactuals for a PyTorch model, save the model inside a <code>.pt</code> file and call the following function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="model_loaded = TaijaInteroperability.pytorch_model_loader(
    &quot;$(pwd())/docs/src/tutorials/miscellaneous&quot;,

    &quot;NeuralNetwork&quot;,
    &quot;$(pwd())/docs/src/tutorials/miscellaneous/pretrained_model.pt&quot;
)"><pre>model_loaded <span class="pl-k">=</span> TaijaInteroperability<span class="pl-k">.</span><span class="pl-c1">pytorch_model_loader</span>(
    <span class="pl-s"><span class="pl-pds">"</span><span class="pl-v">$(<span class="pl-c1">pwd</span>())</span>/docs/src/tutorials/miscellaneous<span class="pl-pds">"</span></span>,
    <span class="pl-s"><span class="pl-pds">"</span>neural_network_class<span class="pl-pds">"</span></span>,
    <span class="pl-s"><span class="pl-pds">"</span>NeuralNetwork<span class="pl-pds">"</span></span>,
    <span class="pl-s"><span class="pl-pds">"</span><span class="pl-v">$(<span class="pl-c1">pwd</span>())</span>/docs/src/tutorials/miscellaneous/pretrained_model.pt<span class="pl-pds">"</span></span>
)</pre></div>
<p dir="auto">The method <code>pytorch_model_loader</code> requires four arguments:</p>
<ol dir="auto">
<li>The path to the folder with a <code>.py</code> file where the PyTorch model is defined</li>
<li>The name of the file where the PyTorch model is defined</li>
<li>The name of the class of the PyTorch model</li>
<li>The path to the Pickle file that holds the model weights</li>
</ol>
<p dir="auto">In the above case:</p>
<ol dir="auto">
<li>The file defining the model is inside <code>$(pwd())/docs/src/tutorials/miscellaneous</code></li>
<li>The name of the <code>.py</code> file holding the model definition is <code>neural_network_class</code></li>
<li>The name of the model class is NeuralNetwork</li>
<li>The Pickle file is located at <code>$(pwd())/docs/src/tutorials/miscellaneous/pretrained_model.pt</code></li>
</ol>
<p dir="auto">Though the model file and Pickle file are inside the same directory in this tutorial, this does not necessarily have to be the case.</p>
<p dir="auto">The reason why the model file and Pickle file have to be provided separately is that the package expects an already trained PyTorch model as input. It is also possible to define new PyTorch models within the package, but since this is not the expected use of the package, special support is not offered for that. A guide for defining Python and PyTorch classes in Julia through <code>PythonCall.jl</code> can be found <a href="https://cjdoris.github.io/PythonCall.jl/stable/pythoncall-reference/#Create-classes" rel="nofollow">here</a>.</p>
<p dir="auto">Once the PyTorch model has been loaded into the package, wrap it inside the PyTorchModel class:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="model_pytorch = TaijaInteroperability.PyTorchModel(model_loaded, counterfactual_data.likelihood)"><pre>model_pytorch <span class="pl-k">=</span> TaijaInteroperability<span class="pl-k">.</span><span class="pl-c1">PyTorchModel</span>(model_loaded, counterfactual_data<span class="pl-k">.</span>likelihood)</pre></div>
<p dir="auto">This model can now be passed into the generators like any other as described in the CounterfactualExplanations  documentation.</p>
<p dir="auto">Please note that the functionality for generating counterfactuals for Python models is only available if your Julia version is 1.8 or above. For Julia 1.7 users, we recommend upgrading the version to 1.8 or 1.9 before loading a PyTorch model into the package.</p>

<blockquote>
<p dir="auto">Please note that due to the incompatibility between RCall and PythonCall, it is not feasible to test both PyTorch and RTorch implementations within the same pipeline. While the RTorch implementation has been manually tested, we cannot ensure its consistent functionality as it is inherently susceptible to bugs.</p>
</blockquote>
<p dir="auto">The TaijaInteroperability package combined with CounterfactualExplanations package supports generating counterfactuals for neural networks that have been defined and trained using R torch. Regardless of the specific architectural details of the model, you can easily generate counterfactual explanations by following these steps.</p>

<div class="highlight highlight-source-r notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="torch_save(model, file = &quot;$(pwd())/docs/src/tutorials/miscellaneous/r_model.pt&quot;)"><pre>torch_save(<span class="pl-smi">model</span>, <span class="pl-v">file</span> <span class="pl-k">=</span> <span class="pl-s"><span class="pl-pds">"</span>$(pwd())/docs/src/tutorials/miscellaneous/r_model.pt<span class="pl-pds">"</span></span>)</pre></div>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="model_loaded = TaijaInteroperability.rtorch_model_loader(&quot;$(pwd())/docs/src/tutorials/miscellaneous/r_model.pt&quot;)"><pre>model_loaded <span class="pl-k">=</span> TaijaInteroperability<span class="pl-k">.</span><span class="pl-c1">rtorch_model_loader</span>(<span class="pl-s"><span class="pl-pds">"</span><span class="pl-v">$(<span class="pl-c1">pwd</span>())</span>/docs/src/tutorials/miscellaneous/r_model.pt<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">The <code>rtorch_model_loader()</code> function requires only one argument:</p>
<ol dir="auto">
<li><code>model_path</code>: The path to the <code>.pt</code> file that contains the trained R torch model.</li>
</ol>

<p dir="auto">Now that the R torch model has been wrapped inside the <code>RTorchModel</code> class, you can pass it into the counterfactual generators as you would with any other model.</p>
<p dir="auto">Please note that RCall is not fully compatible with PythonCall. Therefore, it is advisable not to import both R torch and PyTorch models within the same Julia session. Additionally, it’s worth mentioning that the R torch integration is still untested in the CounterfactualExplanations package.</p>
