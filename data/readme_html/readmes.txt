<p dir="auto">The core thesis of this package is that full on deployed documentation websites (e.g. done with <a href="https://github.com/JuliaDocs/Documenter.jl">Documenter.jl</a>) is overkill for many packages; and that a good read me is all you need.
People often only look at the readme on github, they don't want to click through to the docs.
However, one feature that is missing from that is automatically including docstrings into the read-me.
This package aims to solve that.</p>
<p dir="auto">Rather than working with the <code>README.md</code> directly, you work on a <code>README.template.md</code>,
from which the <code>README.md</code> is generated.
You then check that file into the the git-repo and it will be displayed by github etc.
When you update it</p>
<p dir="auto">This package has one function:</p>
<hr>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="generate_readme([outfile], [template_file], [module_name])"><pre class="notranslate"><code>generate_readme([outfile], [template_file], [module_name])
</code></pre></div>
<p dir="auto">Generates the readme from <code>template_file</code> storing the result in template*file. it automatically load the module of <code>module*name</code>If none of the options are provided, they are defaulted for the current directory. i.e. if in the top level project directory can just run<code>generate_readme()</code>.</p>

<p dir="auto">You can use a github action (like this repo does) that automatically adds a commit to regenerate the <code>README.md</code>.
You can just copy the file from <a href=".github/workflows/regenerate.yml"><code>.github/workflows/regenerate.yml</code></a> into your repo.</p>
<p dir="auto">You could alternatively do it will a similar git precommit hook script locally.</p>
