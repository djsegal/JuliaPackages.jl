<p dir="auto">This script implements a simplified version of the <a href="https://en.wikipedia.org/wiki/String_art" rel="nofollow">String Art</a> greedy algorithm. Given an image, it attempts to create a similar representation using a single thread wound around a circle of nails, effectively constructing an image using only lines. This technique is probably most well-know for the artistic works of <a href="https://www.saatchiart.com/vrellis" rel="nofollow">Petros Vrllis</a>.</p>
<p dir="auto">Most implementations often require high-contrast images, and still the results can vary significantly from one image to another. In this version, I've tweaked the algorithm parameters to <strong>enhance the contrast and detail in the final output</strong>. While this adjustment impacts performance, it remains usable.</p>
<p dir="auto">Additionally, the script features a command-line interface (CLI) with various tweakable parameters, option flags, <strong>RGB color mode</strong> and you can also save the <strong>GIF animation</strong> with easy. Feel free to explore these options to customize the output according to your preferences, if you want to reuse the code or call it somewhere else, you should look at <code>StringArt.run</code>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Algorithm</h3><a id="user-content-algorithm" class="anchor" aria-label="Permalink: Algorithm" href="#algorithm"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ol dir="auto">
<li><strong>Setup:</strong></li>
</ol>
<ul dir="auto">
<li>Load the source image and create an empty output image.</li>
<li>Calculate pin positions and all possible lines between 2 pins.</li>
</ul>
<ol start="2" dir="auto">
<li><strong>Iteration Step:</strong></li>
</ol>
<ul dir="auto">
<li>Choose a pin (P).</li>
<li>Create all possible lines connecting P to the other pins in the circle.</li>
<li>Calculate the error between each lines and the source image.</li>
<li>Find the line (L) that gives the minimum error.</li>
<li>Update the output image adding L, and the source image subtracting L.</li>
<li>Set the pin to be opposite point in the line L.</li>
</ul>
<p dir="auto"><strong>Line Generating Function:</strong>
One-pixel-width lines (or any square/stair-like lines) do not yield good results. Experimentation with different line functions is essential here. I ended up choosing to apply the Gaussian Blur Kernel to the line. It's simple, and it works (also, it eliminates the need to fine-tune other parameters).</p>
<p dir="auto"><strong>Line Pixel Strength:</strong>
Opt for low line pixel values to create nuanced shades of gray in the output image.</p>
<p dir="auto"><strong>Choose Pin:</strong>
Randomizing the pin position periodically (every N steps) tends to give better results.</p>
<p dir="auto"><strong>Error Function:</strong>
Arguably the most critical part of the algorithm. You should minimize the error here and not any other metric (I lost a lot of time doing that...). The best function that I found was the squared difference between the source image and the line (but the performance takes a considerable hit here).</p>
<p dir="auto"><strong>Excluding Already Visited Lines:</strong>
While excluding used lines each iteration improves performance, it results in a more diffuse and noisy image. In this implementation, visited lines are retained. If you prefer the noisy style, just uncomment the lines with <code>filter!</code>.</p>
