<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Introduction: Partially Ordered Sets</h2><a id="user-content-introduction-partially-ordered-sets" class="anchor" aria-label="Permalink: Introduction: Partially Ordered Sets" href="#introduction-partially-ordered-sets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A <em>partially ordered set</em>, or <em>poset</em> for short, is a pair <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$(V,\prec)$</math-renderer> where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$V$</math-renderer> is a set and
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$\prec$</math-renderer> is a binary relation on <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$V$</math-renderer> that is</p>
<ul dir="auto">
<li>
<em>irreflexive</em> (for all <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$v \in V$</math-renderer>, it is never the case that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$v \prec v$</math-renderer>),</li>
<li>
<em>antisymmetric</em> (for all <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$v,w \in V$</math-renderer>, we never have both <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$v \prec w$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$w \prec v$</math-renderer>), and</li>
<li>
<em>transitive</em> (for all <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$u,v,w \in V$</math-renderer>, if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$u \prec v$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$v \prec w$</math-renderer> then <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$u \prec w$</math-renderer>).</li>
</ul>
<p dir="auto">Posets are naturally represented as transitively closed, directed, acyclic graphs. This is how this module implements posets using the <code>DiGraph</code> type in <code>Graphs</code>.</p>
<p dir="auto">The design philosophy for this module is modeled exactly on <code>Graphs</code>. In particular, the vertex set of a poset is necessarily of the form <code>{1,2,...,n}</code>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Constructing new posets</h3><a id="user-content-constructing-new-posets" class="anchor" aria-label="Permalink: Constructing new posets" href="#constructing-new-posets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Create a new poset with no elements using <code>Poset()</code> or a poset with a specified number
of elements with <code>Poset(n)</code>.</p>
<p dir="auto">Given a poset <code>p</code>, use <code>Poset(p)</code> to create an independent copy of <code>p</code>.</p>
<p dir="auto">Given a directed graph <code>d</code>, use <code>Poset(d)</code> to create a new poset from the transitive
closure of <code>d</code>. An error is thrown if <code>d</code> has cycles. (Self loops in <code>d</code> are ignored.)</p>
<p dir="auto">Given a square matrix <code>A</code>, create a poset in which <code>i &lt; j</code> exactly when the <code>i,j</code>-entry
of <code>A</code> is nonzero. Diagonal entries are ignored. If this matrix would create a cycle, an
error is thrown.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Adding a relation</h3><a id="user-content-adding-a-relation" class="anchor" aria-label="Permalink: Adding a relation" href="#adding-a-relation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To add a relation to a poset, use <code>add_relation!</code>. This returns <code>true</code> when successful.</p>

<p dir="auto">Let's look at this carefully to understand why the third call to <code>add_relation!</code> does not succeed:</p>
<ul dir="auto">
<li>The first call to <code>add_relation!</code> causes the relation <code>1 &lt; 2</code> to hold in <code>p</code>.</li>
<li>The second call to <code>add_relation!</code> causes the relation <code>2 &lt; 3</code> to be added to <code>p</code>. Given that <code>1 &lt; 2</code> and <code>2 &lt; 3</code>, by transitivity we automatically have <code>1 &lt; 3</code> in <code>p</code>.</li>
<li>Therefore, we cannot add <code>3 &lt; 1</code> as a relation to this poset as that would violate antisymmetry.</li>
</ul>
<p dir="auto">The <code>add_relation!</code> function may also be called as <code>add_relation!(p, (a,b))</code> or
<code>add_relation!(p, a =&gt; b)</code>. Both are equivalent to <code>add_relations(p, a, b)</code>.</p>

<p dir="auto">The addition of a relation to a poset can be somewhat slow.
Each addition involves error checking and calculations to ensure the integrity
of the underlying data structure. See the Implementation section at the
end of this document.  Adding a list of relations one at a time can be inefficient,
but it is safe. We also provide the function <code>add_relations!</code> (plural) that is more
efficient, but can cause serious problems.</p>
<p dir="auto">To underscore the risk, this function
is not exported, but needs to be invoked as <code>Posets.add_relations!(p, rlist)</code>
where <code>rlist</code> is a list of either tuples <code>(a,b)</code> or pairs <code>a =&gt; b</code>.</p>
<p dir="auto">Here is a good application of this function (although using <code>chain(10)</code> is safer):</p>

<p dir="auto">When element <code>2</code> is removed from <code>p</code>, element <code>5</code> takes its place. Because of this renumbering,
we have some unexpected behavior:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; p = subset_lattice(4)

<p dir="auto">One might expect that deleting a vertex from a poset results in a poset that is a subset of the original. However,
when vertex <code>9</code> was removed from (a copy of) <code>p</code>, the vertex <code>16</code> is relabeled <code>9</code>. Hence vertex <code>9</code> in <code>p</code> is
not maximal, but it is maximal in <code>q</code>.</p>
<blockquote>
<p dir="auto">For a more extensive explanation, see <a href="https://github.com/scheinerman/Posets.jl/blob/main/delete-doc/poset-deletion.pdf">poset-deletion.pdf</a> in the <code>delete-doc</code> folder.</p>
</blockquote>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>poset_builder</code> function</h3><a id="user-content-poset_builder-function" class="anchor" aria-label="Permalink: poset_builder function" href="#poset_builder-function"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Posets are a collection of objects and a <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$\prec$</math-renderer> relation. The <code>poset_builder</code> function
takes a list of objects and a function the determines if they obey a <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$\prec$</math-renderer> relation, and
returns the resulting poset.</p>
<p dir="auto">The function is invoked as <code>poset_builder(list, comp_func)</code> where</p>
<ul dir="auto">
<li>
<code>list</code> is a list (vector) of objects and</li>
<li>
<code>comp_func</code> is a function that takes a pair of objects and returns <code>true</code> if they satisfy a <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$\prec$</math-renderer> relation.</li>
</ul>

Here is how to do that:</p>

<p dir="auto">Use <code>nv(p)</code> to return the number of vertices in the poset <code>p</code>. As in <code>Graphs</code>, the
elements of the poset are integers from <code>1</code> to <code>n</code>.</p>
<p dir="auto">Use <code>in(a, p)</code> [or <code>a ∈ p</code>] to determine if <code>a</code> is an element of <code>p</code>.
This is equivalent to <code>1 &lt;= a &lt;= nv(p)</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Relations</h3><a id="user-content-relations" class="anchor" aria-label="Permalink: Relations" href="#relations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There are three ways to check if elements are related in a poset.</p>
<p dir="auto">First, to see if  <code>1 &lt; 3</code> in <code>p</code> we use the <code>has_relation</code> function:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; has_relation(p,1,3)

</code></pre></div>
<p dir="auto">Second, the syntax <code>p(a,b)</code> is equivalent to <code>has_relation(p,a,b)</code>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; p(1,3)

<p dir="auto">There is a third way to determine the relation between elements <code>a</code> and <code>b</code> in a poset <code>p</code>. Instead of <code>has_relation(p,a,b)</code> or <code>p(a,b)</code> we may use this instead: <code>p[a] &lt; p[b]</code>.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; has_relation(p,1,3)

<p dir="auto">The other comparison operators (<code>&lt;=</code>, <code>&gt;</code>, <code>&gt;=</code>, <code>==</code>, <code>!=</code>) works as expected.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; p[3] &gt; p[1]

<p dir="auto">Neither <code>has_relation(p,a,b)</code> nor <code>p(a,b)</code> generate errors; they return <code>false</code>
even if <code>a</code> or <code>b</code> are not elements of <code>p</code>.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; p(-2,9)

<p dir="auto">However, the expression <code>p[a] &lt; p[b]</code>  throws an error in either of these situations:</p>
<ul dir="auto">
<li>Using the syntax <code>p[a]</code> if <code>a</code> is not an element of <code>p</code>.</li>
<li>Trying to compare elements of different posets (even if the two posets are equal).</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Comparability check</h3><a id="user-content-comparability-check" class="anchor" aria-label="Permalink: Comparability check" href="#comparability-check"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The functions <code>are_comparable(p,a,b)</code> and <code>are_incomparable(p,a,b)</code> behave as follows:</p>
<ul dir="auto">
<li><code>are_comparable(p,a,b)</code> returns <code>true</code> exactly when <code>a</code> and <code>b</code> are both in the poset, and one of the following is true: <code>a&lt;b</code>, <code>a==b</code>, or <code>a&gt;b</code>.</li>
<li><code>are_incompable(p,a,b)</code> returns <code>true</code> exactly when <code>a</code> and <code>b</code> are both in the poset, but none of the follower are true: <code>a&lt;b</code>, <code>a==b</code>, or <code>a&gt;b</code>.</li>
</ul>
<p dir="auto">Alternatively, use <code>p[a] ⟂ p[b]</code> to test if <code>a</code> and <code>b</code> are comparable, and use <code>p[a] ∥ p[b]</code> to test if <code>a</code> and <code>b</code> are incomparable.</p>

<p dir="auto">Given a list of elements <code>vlist</code> of a poset <code>p</code>:</p>
<ul dir="auto">
<li><code>is_chain(p, vlist)</code> returns <code>true</code> if the elements of <code>vlist</code> form a chain in <code>p</code>.</li>
<li><code>is_antichain(p, vlist)</code> returns <code>true</code> if the elements of <code>vlist</code> form an antichain in <code>p</code>.</li>
</ul>
<p dir="auto">Both return <code>false</code> if an element of <code>vlist</code> is not in <code>p</code>.</p>

<code>p[a] &lt;&lt; p[b]</code> or <code>p[b] &gt;&gt; p[a]</code>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Maximals, minimals, height, and width</h3><a id="user-content-maximals-minimals-height-and-width" class="anchor" aria-label="Permalink: Maximals, minimals, height, and width" href="#maximals-minimals-height-and-width"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li><code>maximals(p)</code> returns an iterator for the maximal elements of <code>p</code>.</li>
<li><code>minimals(p)</code> returns an iterator for the minimal elements of <code>p</code>.</li>
<li><code>maximum(p)</code> returns the maximum element of <code>p</code> or <code>0</code> if no such element exists.</li>
<li><code>minimum(p)</code> returns the minimum element of <code>p</code> or <code>0</code> if no such element exists.</li>
<li><code>max_chain(p)</code> returns a vector containing the elements of a largest chain in <code>p</code>.</li>
<li><code>max_antichain(p)</code> returns a vector containing the elements of a largest antichain in <code>p</code>.</li>
<li><code>height(p)</code> returns the size of a largest chain in <code>p</code>.</li>
<li><code>width(p)</code> returns the size of a largest antichain in <code>p</code>.</li>
<li><code>chain_cover(p)</code> returns a minimum-size collection of chains of <code>p</code> such that every element of
<code>p</code> is in one of the chains. The number of chains is the width of <code>p</code>.</li>
<li><code>antichain_cover(p)</code> returns a minimum-size collection of antichains of <code>p</code> such that
every element of <code>p</code> is in one of the antichains. The number of antichains is the height of <code>p</code>.</li>
</ul>
<blockquote>
<p dir="auto"><strong>Note</strong>: The function <code>max_chain</code> returns a largest chain in the poset. It is possible that there are two or more possible answers because there are two or more such chains of maximum size. There is no guarantee as to which largest chain will be returned. Likewise for <code>max_antichain</code>. Similarly, <code>chain_cover</code> returns a minimum-size partition of the elements into chains. If there are multiple minimum-size chain covers, there is no guarantee which will be returned by <code>chain_cover</code>. Likewise for <code>antichain_cover</code>.</p>
</blockquote>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Isomorphism</h3><a id="user-content-isomorphism" class="anchor" aria-label="Permalink: Isomorphism" href="#isomorphism"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For posets <code>p</code> and <code>q</code>, use <code>iso(p,q)</code> to compute an isomorphism from <code>p</code> to <code>q</code>,
or throw an error if the posets are not isomorphic.</p>
<p dir="auto">Let <code>f = iso(p,q)</code>. Then <code>f</code> is a <code>Dict</code> mapping vertices of <code>p</code> to vertices of <code>q</code>.
For example, if <code>p</code> has a unique minimal element <code>x</code>, then <code>f[x]</code> is the unique minimal
element of <code>q</code>.</p>
<p dir="auto">To check if posets are isomorphic, use <code>iso_check</code> (which calls <code>iso</code> inside a <code>try/catch</code> block).</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Ranking</h3><a id="user-content-ranking" class="anchor" aria-label="Permalink: Ranking" href="#ranking"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The function <code>ranking(p)</code> returns a ranking (as a dictionary) of the poset
starting from the minimal elements.
That is, the minimal elements are assigned rank 0. Elements that are above only elements of
rank 0 are assigned rank 1. Elements that are only above elements of rank 0 and 1 are assigned
rank 2. And so forth.</p>
<p dir="auto">Note that not all posets are ranked, but this function always returns a result.</p>
<p dir="auto">We also provide <code>dual_ranking</code> which combines the rankings of <code>p</code> and its dual, <code>p'</code>.
This removes the bias that minimal elements are treated differently than maximal elements.</p>
<p dir="auto">For example, suppose the poset is a the disjoint union of a 3-element and a 2-element chain.
The function <code>ranking</code> places both minimal elements at rank <code>0</code>, then their covers at
rank <code>1</code>, and finally the maximal element in the 3-chain at rank <code>2</code>.</p>
<p dir="auto">By contrast, <code>dual_ranking</code> places the elements in the 3-chain at ranks <code>0</code>, <code>2</code>, and <code>4</code>,
and the elements of the 2-chain at ranks <code>1</code> and <code>3</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Standard Posets</h2><a id="user-content-standard-posets" class="anchor" aria-label="Permalink: Standard Posets" href="#standard-posets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The following functions create standard partially ordered sets.
See the <a href="https://github.com/scheinerman/Posets.jl/blob/main/gallery/README.md">Gallery</a>
for pictures of some of these posets.</p>
<ul dir="auto">
<li>
<p dir="auto"><code>antichain(n)</code> creates the poset with <code>n</code> elements and no relations. Same as <code>Poset(n)</code>.</p>
</li>
<li>
<p dir="auto"><code>chain(n)</code> creates the poset with <code>n</code> elements in which <code>1 &lt; 2 &lt; 3 &lt; ... &lt; n</code>.</p>
</li>
<li>
<p dir="auto"><code>chain(vlist)</code> creates a chain from the integer vector <code>vlist</code> (which must be a permutation of <code>1:n</code>). For example, <code>chain([2,1,3])</code> creates a chain in which <code>2 &lt; 1 &lt; 3</code>.</p>
</li>
<li>
<p dir="auto"><code>chevron()</code> creates a poset with <code>6</code> elements that has dimension equal to <code>3</code>. It is
different from <code>standard_example(3)</code>.</p>
</li>
<li>
<p dir="auto"><code>crown(n,k)</code> creates the crown poset with <code>2n</code> elements with two levels: <code>n</code> elements as minimals
and <code>n</code> as maximals. Each minimal is comparable to <code>n-k</code> maximals. See the help message for more information.</p>
</li>
<li>
<p dir="auto"><code>random_linear_order(n)</code>: Create a linear order in which the numbers <code>1</code> through <code>n</code>
appear in random order.</p>
</li>
<li>
<p dir="auto"><code>random_poset(n,d=2)</code>: Create a random <code>d</code>-dimensional poset by intersecting <code>d</code> random linear orders,
each with <code>n</code> elements.</p>
</li>
<li>
<p dir="auto"><code>standard_example(n)</code> creates a poset with <code>2n</code> elements. Elements <code>1</code> through <code>n</code> form an antichain
as do elements <code>n+1</code> through <code>2n</code>. The only relations are of the form <code>j &lt; k</code> where <code>1 ≤ j ≤ n</code>
and <code>k = n+i</code> where <code>1 ≤ i ≤ n</code> and <code>i ≠ j</code>. This is a smallest-size poset of dimension <code>n</code>.
Equivalent to <code>crown(n,1)</code>.</p>
</li>
<li>
<p dir="auto"><code>subset_lattice(d)</code>: Create the poset corresponding to the <code>2^d</code> subsets of <code>{1,2,...,d}</code>
ordered by inclusion. For <code>a</code> between <code>1</code> and <code>2^d</code>, element <code>a</code> corresponds to a
subset of <code>{1,2,...,d}</code> as follows: Write <code>a-1</code> in binary and view the bits as the characteristic
vector indicating the members of the set. For example, if <code>a</code> equals <code>12</code>, then <code>a-1</code> is <code>1011</code> in
binary. Reading off the digits from the right, this gives the set <code>{1,2,4}</code>.</p>
<ul dir="auto">
<li>Use <code>subset_decode(a)</code> to convert an element <code>a</code> of this poset into a set of positive integers, <code>A</code>.</li>
<li>Use <code>subset_encode(A)</code> to convert a set of positive integers to its name in this poset.</li>
</ul>
</li>
<li>
<p dir="auto"><code>weak_order(vals)</code>: Create a weak order <code>p</code> from a list of real numbers. In <code>p</code> element <code>i</code> is less than element <code>j</code> provided <code>vals[i] &lt; vals[j]</code> .</p>
</li>
</ul>

<ul dir="auto">
<li><code>zeta_matrix(p)</code> returns the zeta matrix of the poset. This is a <code>0,1</code>-matrix whose
<code>i,j</code>-entry is <code>1</code> exactly when <code>p[i] ≤ p[j]</code>.</li>

<p dir="auto">Use <code>linear_extension(p)</code> to create  a linear extension of <code>p</code>.
This is a total order <code>q</code> with the same elements as <code>p</code> and with <code>p ⊆ q</code>.</p>
<p dir="auto">The function <code>random_linear_extension(p)</code> creates a pseudo-random linear extension of <code>p</code><br>
as follows: Pick a minimal element of <code>p</code> at random. Make that the first element
of the result. Now ignore that element and pick a minimal element at random from
among those that remain. Continue in this way until all elements have been
incorporated.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Join and meet</h3><a id="user-content-join-and-meet" class="anchor" aria-label="Permalink: Join and meet" href="#join-and-meet"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Let <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y$</math-renderer> be elements of a poset <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$P$</math-renderer>.
Let <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$U$</math-renderer> be the set of all elements <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$z$</math-renderer> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$P$</math-renderer> such that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x \preceq z$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y \preceq z$</math-renderer>.
This is the set of all elements above or equal to both <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y$</math-renderer>.
If <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$U$</math-renderer> contains a minimum element (one that is below all the other elements of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$U$</math-renderer>),
then that minimum element <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$u$</math-renderer> is the <em>join</em> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y$</math-renderer>. Notation <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$u = x \vee y$</math-renderer>.</p>
<p dir="auto">Similarly, let <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$D$</math-renderer> be the set of all elements <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$z$</math-renderer> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$P$</math-renderer> such that
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$z \preceq x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$z \preceq y$</math-renderer>. This is the set of all
elements in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$P$</math-renderer> that are below or equal to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y$</math-renderer>. If <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$D$</math-renderer> contains a unique maximum element
(one that is above all the other elements in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$D$</math-renderer>), then that maximum element <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$d$</math-renderer> is the
<em>meet</em> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$x$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$y$</math-renderer>. Notation: <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$d = x \wedge y$</math-renderer>.</p>
<p dir="auto">There are two ways to compute the join [or meet] of elements in a poset.</p>
<ul dir="auto">
<li>The join and meet of elements <code>x</code> and <code>y</code> in poset <code>p</code> can be computed as <code>p[x] ∨ p[y]</code> and <code>p[x] ∧ p[y]</code>.</li>
<li>Or use the functions <code>lattice_join(p,x,y)</code> or <code>lattice_meet(p,x,y)</code></li>
</ul>
<p dir="auto"><strong>Important notes</strong>:</p>
<ul dir="auto">
<li>The meet [or join] of two elements need not exist.
<ul dir="auto">
<li>In the operation form, <code>p[x] ∧ p[y]</code> [or <code>p[x] ∨ p[y]</code>], if there is no meet [or join], an error is thrown.</li>
<li>In the function form, <code>lattice_meet(p,x,y)</code> [or <code>lattice_join(x,y)</code>], if there is no meet [or join] then <code>0</code> is returned.</li>
</ul>
</li>
<li>Cannot compute the meet [or join] of elements in different posets.</li>
<li>The expression <code>p[x]</code> throws an error if <code>x</code> is not an element of <code>p</code>.</li>
<li>The symbol <code>∨</code> is typed <code>\vee&lt;TAB&gt;</code> and <code>∧</code> is typed <code>\wedge&lt;TAB&gt;</code>.</li>
<li>The result of <code>p[x] ∨ p[y]</code> is an object of type <code>PosetElement</code> (likewise for <code>∧</code>).</li>
<li>The result of <code>lattice_join</code> [or <code>lattice_meet</code>] is always an integer. The return value of <code>0</code> is used to show that the join [or meet] does not exist.</li>
</ul>
<p dir="auto">The join and meet operations for posets are analogous to union and intersection for sets as illustrated here:</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Implementation</h2><a id="user-content-implementation" class="anchor" aria-label="Permalink: Implementation" href="#implementation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A <code>Poset</code> is a structure that contains a single data element: a <code>DiGraph</code>.
Users should not be accessing this directly, but it may be useful to understand
how posets are implemented. The directed graph is acyclic (including loopless)
and transitively closed. This means if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$a \to b$</math-renderer> is an edge and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$b\to c$</math-renderer> is
an edge, then <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$a \to c$</math-renderer> is also an edge. The advantage to this structure is that
checking if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$a \prec b$</math-renderer> in a poset is quick. There are two disadvantages.</p>
<p dir="auto">First, the graph may be larger than needed. If we only kept cover edges
(the transitive reduction of the digraph) we might have many fewer edges.
For example, a linear order with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$n$</math-renderer> elements has <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$\binom{n}{2} \sim n^2/2$</math-renderer>
edges in the digraph that represents it, whereas there are only <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$n-1$</math-renderer> edges in
the cover digraph. However, this savings is an extreme example. A poset with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$n$</math-renderer>
elements split into two antichains, with every element of the first antichain below
every element of the second, has <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$n^2/4$</math-renderer> edges in either representation.
So in either case, the representing digraph may have up to order <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$n^2$</math-renderer> edges.</p>
<p dir="auto">Second, the computational cost of adding (or deleting) a relation is nontrivial.
The <code>add_relation!</code> function first checks if the added relation would violate
transitivity; this is speedy because we can add the relation <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$a \prec b$</math-renderer> so
long as we don't have <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$b\prec a$</math-renderer> already in the poset. However, after the edge <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="0bf606891e8ddd5354a36d1b46a2d225">$(a,b)$</math-renderer>
is inserted into the digraph, we execute <code>transitiveclosure!</code> and that takes some
work. Adding several relations to the poset, one at a time, can be slow.</p>
<p dir="auto">This can be greatly accelerated by using <code>Posets.add_relations!</code> but (as discussed above)
this function can cause severe problems if not used carefully.</p>
