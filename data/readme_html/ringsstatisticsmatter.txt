<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Julia Rings</h2><a id="user-content-julia-rings" class="anchor" aria-label="Permalink: Julia Rings" href="#julia-rings"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package provides a tool for finding primitive rings efficiently for large models of amorphous materials.</p>
<p dir="auto">Designed for large structural models, this can handle 100,000-atoms in under 10 minutes multithreaded on a 16GB M2 Mac laptop.</p>
<p dir="auto">This package implements an algorithm based on the work described in:</p>
<div dir="auto">
<div dir="auto">Yuan, X. &amp; Cormack, A. N.</div>
<div dir="auto"><a href="https://doi.org/10.1016/S0927-0256(01)00256-7" rel="nofollow">"Efficient Algorithm for Primitive Ring Statistics in Topological Networks."</a>.</div>
<div dir="auto">Computational Materials Science, vol. <strong>24</strong>, pp. 343-360, 2002.</div>
<div dir="auto"><br></div>
</div>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Features</h3><a id="user-content-features" class="anchor" aria-label="Permalink: Features" href="#features"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>Python wrappers for easy plotting and incorporation into more complex analysis frameworks.</li>
<li>Returns node indices for each ring in your structure</li>
<li>Flexible multi-element support via ASE NeighborList (ignore or allow homopolar bonds, handle multiple custom cutoff-radii etc.)</li>
<li>Shared-memory parallelism via Julia's native multithreading. Scales well up to 128 cores (and presumably beyond).</li>
</ul>

<p dir="auto">If you see non-integer entries in the ring statistics, or the nodes don't seem right, this is most likely from using small unit cells.</p>
<p dir="auto">We try to automatically create supercells to fix this, but there may be edge cases where this isn't enough. For large enough cells, this shouldn't be an issue.</p>

<p dir="auto">The following extra arguments can be used with the command line tool:</p>
<ul dir="auto">
<li><code>--maxlvl</code>: Specifies the maximum level of rings that can be found.</li>
<li><code>--mxpths</code>: If your structure has numerous neighbors and you're using a large <code>maxlvl</code>, consider increasing this parameter. This adjustment can help mitigate errors like <code>BoundsError: attempt to access 1000×6 Matrix{Int64} at index [1001, 1]</code>.</li>
</ul>
