<p dir="auto"><a href="https://github.com/Jutho/TensorKit.jl">TensorKit.jl</a> extension for low rank unitary fusion categories, using <a href="https://github.com/JCBridgeman/smallRankUnitaryFusionData">smallRankUnitaryFusionData</a> and the <a href="https://anyonwiki.github.io/" rel="nofollow">AnyonWiki</a></p>

<p dir="auto">This package currently provides TensorKit's sectortypes for all objects of multiplicity-free (braided)
fusion categories up to rank 6. The full list, along with the naming convention can be found
<a href="https://anyonwiki.github.io/pages/Lists/losmffc.html" rel="nofollow">here</a>.</p>
<p dir="auto">Additionally, some specific categories with multiplicities have also been added.</p>
<p dir="auto">The fusion categories adhere to a hierarchical structure of exported abstract types:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="BraidedCategory &lt;: FusionCategory &lt;: FusionRing"><pre>BraidedCategory <span class="pl-k">&lt;:</span> <span class="pl-c1">FusionCategory</span> <span class="pl-k">&lt;:</span> <span class="pl-c1">FusionRing</span></pre></div>
<p dir="auto">which indicate implementations of fusion rules (<code>Nsymbol</code>), associators (<code>Fsymbol</code>) and
braidings (<code>Rsymbol</code>).</p>
<p dir="auto">Objects in these categories are identified with integers ranging from <code>1</code> to <code>R</code>, where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="6c74d0f8a20f952af291a21e27a26be9">$R$</math-renderer>
is the rank of the category and the identity object is always <code>1</code>. These can then be used as
any other <code>Sector</code> for constructing <code>TensorMap</code>s.</p>

<p dir="auto">The data for the fusion categories is stored in the <code>data</code> github branch, and retrieved using the <code>Artifacts</code> package. In particular, in order to add to, or change the data, the following steps should be taken:</p>
<ol dir="auto">
<li>Update the <code>data</code> github branch with the new data.</li>
<li>Release/tag a new version of the data <code>data-vX.Y.Z</code>, which can then be registered as an artifact.</li>
<li>Check the url of the release, which should be of the following form <code>"https://github.com/lkdvos/CategoryData.jl/archive/refs/tags/data-vX.Y.Z.tar.gz"</code></li>
<li>Switch to the <code>main</code> branch, and update the <code>Artifact.toml</code> file. This can be done either manually, or by using <code>ArtifactUtils.jl</code>:</li>
</ol>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using ArtifactUtils
julia&gt; add_artifact(&quot;Artifacts.toml&quot;, &quot;fusiondata&quot;, &quot;https://github.com/lkdvos/CategoryData.jl/archive/refs/tags/data-vX.Y.Z.tar.gz&quot;; force=true);"><pre>julia&gt; <span class="pl-k">using</span> ArtifactUtils
julia&gt; <span class="pl-c1">add_artifact</span>(<span class="pl-s"><span class="pl-pds">"</span>Artifacts.toml<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>fusiondata<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>https://github.com/lkdvos/CategoryData.jl/archive/refs/tags/data-vX.Y.Z.tar.gz<span class="pl-pds">"</span></span>; force<span class="pl-k">=</span><span class="pl-c1">true</span>);</pre></div>
<ol start="5" dir="auto">
<li>Update the <code>artifact_path</code> constant in the source code <code>src/artifacts.jl</code>.</li>
<li>Push the changes to the <code>main</code> branch.</li>
</ol>
