<p dir="auto"><strong>MeshIntegrals.jl</strong> uses differential forms to enable fast and easy numerical integration of arbitrary integrand functions over domains defined via <a href="https://github.com/JuliaGeometry/Meshes.jl"><strong>Meshes.jl</strong></a> geometries. This is achieved using:</p>
<ul dir="auto">
<li>Gauss-Legendre quadrature rules from <a href="https://github.com/JuliaApproximation/FastGaussQuadrature.jl"><strong>FastGaussQuadrature.jl</strong></a>: <code>GaussLegendre(n)</code></li>
<li>H-adaptive Gauss-Kronrod quadrature rules from <a href="https://github.com/JuliaMath/QuadGK.jl"><strong>QuadGK.jl</strong></a>: <code>GaussKronrod(kwargs...)</code></li>
<li>H-adaptive cubature rules from <a href="https://github.com/JuliaMath/HCubature.jl"><strong>HCubature.jl</strong></a>: <code>HAdaptiveCubature(kwargs...)</code></li>
</ul>
<p dir="auto">These solvers have support for integrand functions that produce scalars, vectors, and <a href="https://github.com/PainterQubits/Unitful.jl"><strong>Unitful.jl</strong></a> <code>Quantity</code> types. While HCubature.jl does not natively support <code>Quantity</code> type integrands, this package provides a compatibility layer to enable this feature.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="integral(f, geometry)"><pre><span class="pl-c1">integral</span>(f, geometry)</pre></div>
<p dir="auto">Performs a numerical integration of some integrand function <code>f(p::Meshes.Point)</code> over the domain specified by <code>geometry</code>. A default integration method will be automatically selected according to the geometry: <code>GaussKronrod()</code> for 1D, and <code>HAdaptiveCubature()</code> for all others.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="integral(f, geometry, algorithm, FP=Float64)"><pre><span class="pl-c1">integral</span>(f, geometry, algorithm, FP<span class="pl-k">=</span>Float64)</pre></div>
<p dir="auto">Performs a numerical integration of some integrand function <code>f(p::Meshes.Point)</code> over the domain specified by <code>geometry</code> using the specified integration algorithm, e.g. <code>GaussKronrod()</code>.</p>
<p dir="auto">Optionally, a fourth argument can be provided to specify the floating point precision level desired. This setting can be manipulated if your integrand function produces outputs with alternate floating point precision (e.g. <code>Float16</code>, <code>BigFloat</code>, etc) AND you'd prefer to avoid implicit type promotions.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="lineintegral(f, geometry)
surfaceintegral(f, geometry)
volumeintegral(f, geometry)"><pre><span class="pl-c1">lineintegral</span>(f, geometry)
<span class="pl-c1">surfaceintegral</span>(f, geometry)
<span class="pl-c1">volumeintegral</span>(f, geometry)</pre></div>
<p dir="auto">Alias functions are provided for convenience. These are simply wrappers for <code>integral</code> that first validate that the provided <code>geometry</code> has the expected number of parametric/manifold dimensions. Like with <code>integral</code> in the examples above, the <code>algorithm</code> can also be specified as a third-argument.</p>
<ul dir="auto">
<li><code>lineintegral</code> for curve-like geometries or polytopes (e.g. <code>Segment</code>, <code>Ray</code>, <code>BezierCurve</code>, <code>Rope</code>, etc)</li>
<li><code>surfaceintegral</code> for surfaces (e.g. <code>Disk</code>, <code>Sphere</code>, <code>CylinderSurface</code>, etc)</li>
<li><code>volumeintegral</code> for (3D) volumes (e.g. <code>Ball</code>, <code>Cone</code>, <code>Torus</code>, etc)</li>
</ul>
