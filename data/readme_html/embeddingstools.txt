<p dir="auto"><strong>EmbeddingsTools.jl</strong> is a Julia package that provides additional tools for working with word embeddings, complementing existing packages such as <strong><a href="https://github.com/JuliaText/Embeddings.jl">Embeddings.jl</a></strong>. Please note that the compatibility with other packages is currently limited, namely, type conversions are currently missing. Still, this package can be used as a standalone tool for working with embedding vectors.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The package is intended to read local embedding files, and it currently supports only text files (e.g., <code>.vec</code>) and binary Julia files. The package can perform basic operations on these embedding files.</p>
<p dir="auto">The embeddings are represented as either <code>WordEmbedding</code> or <code>IndexedWordEmbedding</code> types. Both types contain an embedding table and a token vocabulary that is similar to embedding objects in <strong>Embeddings.jl</strong>. They also have <code>ntokens</code> and <code>ndims</code> fields to store the dimensionality of an embedding table. In addition, <code>IndexedWordEmbedding</code> objects have an extra lookup dictionary that maps its tokens to corresponding embedding vectors' views.</p>
<p dir="auto">Indexing is useful when the embedding table must be aligned with a pre-existing vocabulary, such as the one obtained from a corpus of texts.</p>

<p dir="auto">The original goal of the package was to allow users to read local embedding vectors in Julia. We discovered that this feature was quite limited in <strong>Embeddings.jl</strong>. For example, a user can manually download an embedding table, e.g. from <a href="https://fasttext.cc/docs/en/crawl-vectors.html" rel="nofollow">the FastText repository</a> or <a href="https://rusvectores.org/en/" rel="nofollow">RusVectōrēs project</a> (a collection of Ukrainian and Russian embeddings) and then read it into Julia using:</p>

<p dir="auto">The <code>read_vec()</code> function is a basic function that reads embeddings. It takes two arguments: <code>path</code> and <code>delim</code> (the delimiter), and creates a <code>WordEmbedding</code> object using CSV.jl. This function reads the entire embedding table, which results in better performance due to its straightforward logic. However, it may fail to read embeddings with more than 500k words.</p>
<p dir="auto"><code>read_embedding()</code> is an alternative function that provides more control options through keyword arguments. If <code>max_vocab_size</code> is specified, the function limits the size of the vector to that number. If a vector <code>keep_words</code> is provided, it only keeps those words. If a word in <code>keep_words</code> is not found, the function returns a zero vector for that word.</p>
<p dir="auto">If the file is a <code>WordEmbedding</code> object within a Julia binary file (with extension <code>.jld</code> or in specific formats <code>.emb</code> or <code>.wem</code>), the entire embedding is loaded, and keyword arguments are not applicable. You can also use the <code>read_emb()</code> function directly on binary files. See <code>?write_embedding</code> for saving embedding objects to Julia binary files to read them faster in the future.</p>

<p dir="auto">There are some differences in the behavior of certain functions in <strong>EmbeddingsTools.jl</strong>, depending on whether the embedding table object contains a lookup dictionary or not. If the object contains a lookup dictionary, then it is referred to as an object of type <code>IndexedWordEmbedding</code>, which is considerably faster to operate on. On the other hand, if it does not contain the lookup dictionary, then it is referred to as an object of type <code>WordEmbedding</code>, which takes a bit of time to index and should only be done when necessary. To index an embedding object, you can either call <code>IndexedWordEmbedding()</code> (which is a constructor function) or <code>index()</code> on the object.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# These are equivalent

embtable_ind = index(embtable)"><pre><span class="pl-c"><span class="pl-c">#</span> These are equivalent</span>

embtable_ind <span class="pl-k">=</span> <span class="pl-c1">index</span>(embtable)</pre></div>

<p dir="auto">At times, we may need to adjust an embedding table to match a set of words or tokens. This could be the result of pre-processing a corpus of text documents using the <strong><a href="https://github.com/JuliaText/TextAnalysis.jl">TextAnalysis.jl</a></strong> package. The <code>subspace()</code> function can be used to create a new <code>WordEmbedding</code> object from an existing embedding and a vector of strings containing the words or tokens of interest. The order of the new embedding vectors corresponds to the order of the input tokens. If a token is not present in the source embedding vocabulary, a zero vector is returned for that token.</p>
<p dir="auto">It's important to note that the <code>subspace()</code> method performs much faster when used with an indexed embedding object.</p>

<p dir="auto">The <code>reduce_emb()</code> function allows you to decrease the size of embedding objects, whether they are indexed or not. You can choose between two reduction techniques (specified using the <code>method</code> keyword): <code>pca</code> (the default) for Principal Component Analysis, or <code>svd</code> for Singular Value Decomposition.</p>
