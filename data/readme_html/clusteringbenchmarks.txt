<p dir="auto">This is a repository of data sets and metrics which may be used to evaluate clustering algorithms. The data sets include:</p>
<ul dir="auto">
<li><a href="https://clustering-benchmarks.gagolewski.com" rel="nofollow">Marek Gagolewski's collection</a> (direct access to <a href="https://github.com/gagolews/clustering-data-v1">data</a>). See <code>?load_gagolewski</code> for details about how to load the data sets. Quite a few of these are not very "naturalistic"; among the low-dimensional data sets, the "sipu" and "fcps" batteries arguably have a larger proportion of problems that one might imagine coming from real data.</li>
</ul>
<p dir="auto">The metrics to compare the agreement between two clusterings of the same data set include:</p>
<ul dir="auto">
<li><a href="https://dl.acm.org/doi/abs/10.1145/1553374.1553511?casa_token=T02zuKJpK3AAAAAA:7caf54YsKdR0Xf4nTPnCrY0Na906rGbuNh-IPvem7cgCxSHqLobsbhYGJc4A90TqrDYqNvQShj7vvA" rel="nofollow">Adjusted Mutual Information (<code>ami</code>)</a></li>
<li><a href="https://arxiv.org/pdf/2209.02935.pdf" rel="nofollow">Normalised Clustering Accuracy (<code>nca</code>)</a></li>
</ul>
<p dir="auto">Both support only hard clustering; at present there is no metric for soft clusterings. <code>ami</code> is recommended because
it does not require that both clusterings have the same number of clusters, and it scales reasonably well when there are many clusters.</p>
<p dir="auto"><a href="https://github.com/JuliaStats/Clustering.jl">Clustering.jl</a> contains additional evaluation metrics. Its <code>mutualinfo(x, y; normed=true)</code> is closest to this package's <code>ami</code>; see the AMI paper for details on the differences.</p>

<p dir="auto"><code>ami</code> scores were computed for several algorithms in Clustering.jl on a subset of the Gagolewski collection (see <code>demos/bench_clustering.jl</code> for details). The results are shown as a violin plot below:</p>

<p dir="auto">Some algorithms depend on computing the pairwise distance matrix, and thus scale poorly for large data sets.
For these algorithms, any data set with more than 3000 points was excluded. Here were the number of benchmarks that were runnable for each algorithm:</p>

<p dir="auto">Algorithms (or variants) marked with a <code>*</code> are fully automated, and do not require anything beyond the input data. The remainding algorithms received one or more "hints" from the reference clustering (e.g., the number of clusters).
Some choices were made for the fully-automated variants:</p>
<ul dir="auto">
<li><code>dbscan</code>'s hyperparameters were set to have <code>2d</code> neighbors in <code>d</code> dimensions, and the radius was set as the mean distance to the <code>2d</code>th neighbor.</li>
<li><code>hclust*</code> split at the longest gap between splits in the <a href="https://en.wikipedia.org/wiki/Dendrogram" rel="nofollow">dendrogram</a>.</li>
</ul>
<p dir="auto">There may be more optimal automation strategies than these. In particular, all algorithms can be automated by optimizing <a href="https://juliastats.org/Clustering.jl/stable/validate.html" rel="nofollow">evaluation metrics</a>, although one still needs to choose, e.g., the range of numbers of clusters considered.</p>
