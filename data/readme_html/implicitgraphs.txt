<p dir="auto">An <code>ImplicitGraph</code> is a graph in which the vertices and edges are implicitly defined by two functions: one that tests for vertex membership and one that returns a list of the (out) neighbors of a vertex.</p>
<p dir="auto">The vertex set of an <code>ImplicitGraph</code> may be finite or (implicitly) infinite. The (out) degrees, however, must be finite.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Creating Graphs</h2><a id="user-content-creating-graphs" class="anchor" aria-label="Permalink: Creating Graphs" href="#creating-graphs"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">An <code>ImplicitGraph</code> is defined as follows:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="ImplicitGraph{T}(has_vertex, out_neighbors)"><pre class="notranslate"><code>ImplicitGraph{T}(has_vertex, out_neighbors)
</code></pre></div>
<p dir="auto">where</p>
<ul dir="auto">
<li><code>T</code> is the data type of the vertices.</li>
<li><code>has_vertex(v::T)::Bool</code> is a function that takes objects of type <code>T</code> as input and returns <code>true</code> if <code>v</code> is a vertex of the graph.</li>
<li><code>out_neighbors(v::T)::Vector{T}</code> is a function that takes objects of type <code>T</code> as input and returns a list of the (out) neighbors of <code>v</code>.</li>
</ul>
<p dir="auto">For example, the following creates an (essentially) infinite path whose vertices are integers (see the <code>iPath</code> function):</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="yes(v::Int)::Bool = true 
N(v::Int)::Vector{Int} = [v-1, v+1]
G = ImplicitGraph{Int}(yes, N)"><pre><span class="pl-en">yes</span>(v<span class="pl-k">::</span><span class="pl-c1">Int</span>)<span class="pl-k">::</span><span class="pl-c1">Bool</span> <span class="pl-k">=</span> <span class="pl-c1">true</span> 
<span class="pl-en">N</span>(v<span class="pl-k">::</span><span class="pl-c1">Int</span>)<span class="pl-k">::</span><span class="pl-c1">Vector{Int}</span> <span class="pl-k">=</span> [v<span class="pl-k">-</span><span class="pl-c1">1</span>, v<span class="pl-k">+</span><span class="pl-c1">1</span>]
G <span class="pl-k">=</span> <span class="pl-c1">ImplicitGraph</span><span class="pl-c1">{Int}</span>(yes, N)</pre></div>
<p dir="auto">The <code>yes</code> function always returns <code>true</code> for any <code>Int</code>. The <code>N</code> function returns the two neighbors of a vertex <code>v</code>. (For a truly infinite path, use <code>BigInt</code> in place of <code>Int</code>.)</p>
<p dir="auto">Note that if <code>v</code> is an element of its own neighbor set, that represents a loop at vertex <code>v</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Undirected and directed graphs</h3><a id="user-content-undirected-and-directed-graphs" class="anchor" aria-label="Permalink: Undirected and directed graphs" href="#undirected-and-directed-graphs"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The user-supplied <code>out_neighbors</code> function can be used to create both undirected and directed graphs. If an undirected graph is intended, be sure that if <code>{v,w}</code> is an edge of the graph, then <code>w</code> will be in the list returned by <code>out_neighbors(v)</code> and <code>v</code> will be in the list returned by <code>out_neighbors(w)</code>.</p>
<p dir="auto">To create an infinite <em>directed</em> path, the earlier example can be modified like this:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="yes(v::Int)::Bool = true

<p dir="auto">We provide a few basic graphs that can be created using the following methods:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>iCycle(n::Int)</code> creates an undirected cycle with vertex set <code>{1,2,...,n}</code>;
<code>iCycle(n,false)</code> creates a directed <code>n</code>-cycle.</p>
</li>
<li>
<p dir="auto"><code>iPath()</code> creates an (essentially) infinite undirected path whose vertex set contains all integers  (objects of type <code>Int</code>); <code>iPath(false)</code> creates a one-way infinite path <code>⋯ → -2 → -1 → 0 → 1 → 2 → ⋯</code>.</p>
</li>
<li>
<p dir="auto"><code>iGrid()</code> creates an (essentially) infinite grid whose vertices are ordered pairs of integers (objects of type <code>Int</code>).</p>
</li>
<li>
<p dir="auto"><code>iCube(d::Int)</code> creates a <code>d</code>-dimensional cube graph. The vertices are all <code>d</code>-long strings of <code>0</code>s and <code>1</code>s. Two vertices are adjacent iff they differ in exactly one bit.</p>
</li>
<li>
<p dir="auto"><code>iKnight()</code> creates the Knight's move graph on an (essentially) infinite chessboard. The vertices are pairs of integers (objects of type <code>Int</code>).</p>
</li>
<li>
<p dir="auto"><code>iShift(alphabet, n::Int)</code> creates the shift digraph whose vertices are <code>n</code>-tuples of elements of <code>alphabet</code>.</p>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Inspection</h2><a id="user-content-inspection" class="anchor" aria-label="Permalink: Inspection" href="#inspection"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">To test if <code>v</code> is a vertex of an <code>ImplicitGraph</code> <code>G</code>, use <code>has(G)</code>. Note that the data type of <code>v</code> must match the element type of <code>G</code>. (The function <code>eltype</code> returns the data type of the vertices of the <code>ImplicitGraph</code>.)</p>
</li>
<li>
<p dir="auto">To test if <code>{v,w}</code> is an edge of <code>G</code> use <code>G[v,w]</code> or <code>has(G,v,w)</code>. Note that <code>v</code> and <code>w</code> must both be vertices of <code>G</code> or an error is thrown.</p>
</li>
<li>
<p dir="auto">To get a list of the (out) neighbors of a vertex <code>v</code>, use <code>G[v]</code>.</p>
</li>
<li>
<p dir="auto">To get the degree of a vertex in a graph, use <code>deg(G,v)</code>.</p>
</li>
</ul>

<p dir="auto">For large undirected graphs, you may find that <code>find_path_undirected</code> runs faster.
It uses bidirectional search to reduce memory usage and runtime. It does not support
directed graphs, however.</p>

<p dir="auto">Optionally, instead of a single target vertex whose type is the same as other vertices of the <code>ImplicitGraph</code>, we can call <code>find_path</code> with this signature:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="find_path(G::ImplicitGraph{T}, s::T, is_target::Function) where {T}"><pre class="notranslate"><code>find_path(G::ImplicitGraph{T}, s::T, is_target::Function) where {T}

<p dir="auto">The function <code>is_target</code> is expected to take a vertex of <code>G</code> as its only argument and return a <code>Bool</code> which is <code>true</code> if the vertex is a target. In this way, we can search for a path from the source vertex to one of many target vertices, or a vertex with a specified property.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Guided path finding</h3><a id="user-content-guided-path-finding" class="anchor" aria-label="Permalink: Guided path finding" href="#guided-path-finding"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The function <code>guided_path_finder</code> employs a score function to try to find a
path between vertices. It may be faster than <code>find_path</code>, but might not give a shortest path.</p>
<p dir="auto">This function is called as follows: <code>guided_path_finder(G,s,t,score=sc, depth=d, verbose=0)</code> where</p>
<ul dir="auto">
<li><code>G</code> is an <code>ImplicitGraph</code>,</li>
<li><code>s</code> is the starting vertex of the desired path,</li>
<li><code>t</code> is the ending vertex of the desired path,</li>
<li><code>sc</code> is a score function that mapping vertices to integers and should get smaller as vertices get closer to <code>t</code> (and should minimize at <code>t</code>),</li>
<li><code>d</code> controls amount of look ahead (default is <code>1</code>), and</li>
<li><code>verbose</code> sets how often to print progess information (or <code>0</code> for no diagnostics).</li>
</ul>
