<p dir="auto">Oceananigans is a fast, friendly, flexible software package for finite volume simulations of the nonhydrostatic
and hydrostatic Boussinesq equations on CPUs and GPUs.
It runs on GPUs (wow, <a href="http://arxiv.org/abs/2309.06662" rel="nofollow">fast!</a>), though we believe Oceananigans makes the biggest waves
with its ultra-flexible user interface that makes simple simulations easy, and complex, creative simulations possible.</p>
<p dir="auto">Oceananigans.jl is developed by the <a href="https://clima.caltech.edu" rel="nofollow">Climate Modeling Alliance</a> and heroic external collaborators.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Performance benchmarks</h2><a id="user-content-performance-benchmarks" class="anchor" aria-label="Permalink: Performance benchmarks" href="#performance-benchmarks"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">We've performed some preliminary performance benchmarks (see the <a href="https://clima.github.io/OceananigansDocumentation/stable/appendix/benchmarks/" rel="nofollow">performance benchmarks</a> section of the documentation) by initializing models of various sizes and measuring the wall clock time taken per model iteration (or time step).</p>
<p dir="auto">This is not really a fair comparison as we haven't parallelized across all the CPU's cores so we will revisit these benchmarks once Oceananigans.jl can run on multiple CPUs and GPUs.</p>
<p dir="auto">To make full use of or fully saturate the computing power of a GPU such as an Nvidia Tesla V100 or
a Titan V, the model should have around ~10 million grid points or more.</p>
<p dir="auto">Sometimes counter-intuitively running with <code>Float32</code> is slower than <code>Float64</code>. This is likely due
to type mismatches causing slowdowns as floats have to be converted between 32-bit and 64-bit, an
issue that needs to be addressed meticulously. Due to other bottlenecks such as memory accesses and
GPU register pressure, <code>Float32</code> models may not provide much of a speedup so the main benefit becomes
lower memory costs (by around a factor of 2).</p>
