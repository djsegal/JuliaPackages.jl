<p dir="auto">Welcome to olive! Olive is a <strong>pure julia</strong> notebook editor built on the back of multiple dispatch. Through multiple dispatch, olive is able to change functionality entirely by simply having new methods. Using extensions, olive can edit <strong>any</strong> file. Among other things, olive features ...</p>
<ul dir="auto">
<li>regular <strong>julia modules</strong></li>
<li>unparalleled <strong>extensibility</strong></li>
<li><strong>modular</strong> design</li>
<li><strong>tabbing</strong> notebooks</li>
<li>its own <strong>julia</strong> ecosystem</li>
<li><strong>customizable</strong> settings</li>
<li>reading of pluto, julia, olive, <strong>and</strong> ipython notebooks</li>
<li>exporting to <strong>multiple</strong> formats</li>
<li>a full <strong>file-browser</strong></li>
<li>julia <strong>repl cells</strong></li>
<li>module and include cells for <strong>software development</strong></li>
<li><strong>deployability</strong></li>
<li><strong>shared variables</strong> between multiple cell-types</li>
<li>a <strong>two-pane</strong> design</li>
<li><strong>loadable</strong> directories as <strong>profiles</strong></li>
<li><strong>flexible</strong> and modern design</li>
<li>the ability to edit <strong>any</strong> file</li>
</ul>

<p dir="auto">To change the IP or PORT, use the positional arguments <code>IP</code> (<strong>1</strong>, <code>String</code>) and <code>PORT</code> (<strong>2</strong>, <code>Int64</code>). There are also the key-word arguments</p>
<ul dir="auto">
<li><code>path</code><strong>::String</strong> = <code>homedirec()</code> -- Provides a path from which to setup or start <code>Olive</code>.</li>
<li><code>warm</code><strong>::Bool</strong> = <code>true</code> -- determines whether or not <code>Olive</code> should precompile <code>olive</code> and "warm" the <code>Toolips</code> server. This helps reduce initial latency when starting <code>Olive</code>.</li>
</ul>
<p dir="auto">If there is no <code>olive</code> setup inside of <code>path</code>, <code>start</code> will ask us for a root name to create a new <code>olive</code> home at that path. Providing <code>path</code> allows us to setup multiple <code>Olive</code> environments across our filesystem.</p>

<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">explanation</h4><a id="user-content-explanation" class="anchor" aria-label="Permalink: explanation" href="#explanation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Olive uses <strong>parameters</strong> and <strong>multiple dispatch</strong> to load new features with the creation of method definitions. This technique is used comprehensively for <code>Olive</code>'s <code>Directory</code> and <code>Project</code> types, as well as <a href="https://github.com/ChifiSource/IPyCells.jl">IPyCell's</a> <code>Cell</code>. This allows for a <code>Symbol</code> to be provided as a parameter. With this, <code>Olive</code> either reads the methods for its own functions or provides them as arguments to alter the nature of UI components. <code>Project</code>, <code>Directory</code>, and <code>Cell</code> are all <strong>julia types</strong>. These are translated into the <code>Olive</code> web-based UI using <code>build</code> methods. For example, the <code>creator</code> cell will list out all of the methods that <code>Olive</code> has defined for <code>build(::Toolips.AbstractConnection, ::Toolips.Modifier, ::Cell{&lt;:Any}, ::Vector{Cell}, proj::Project{&lt;:Any})</code>. In order to name such a cell, simply label the parameter in the <code>Cell</code> using a <code>Symbol</code>.</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="https://github.com/ChifiSource/image_dump/blob/main/olive/alpha9sc/creatorcell.png"><img src="https://github.com/ChifiSource/image_dump/raw/main/olive/alpha9sc/creatorcell.png" style="max-width: 100%;"></a></p>
<p dir="auto">This is the defining characteristic of <code>Olive</code>, and also how the base <code>Olive</code> features are built. This is why <code>Olive</code> is a <strong>multiple dispatch notebook</strong>, not just that but a <strong>parametric</strong> multiple dispatch notebook. As a result, a lot of what <code>Projects</code>, <code>Cells</code>, and <code>Directories</code> do is pretty open-ended -- anything is possible. This is also how extensions for <code>Olive</code> work. While this might not be that important to know if you are not extending <code>Olive</code> on your own, it is helpful to know this going into <code>Olive</code> and the rest of this <code>README</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">user interface</h3><a id="user-content-user-interface" class="anchor" aria-label="Permalink: user interface" href="#user-interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Olive's user-interface is relatively straightforward. When starting olive, you will be greeted with a <code>get started</code> <code>Project</code>. A <code>Project</code> in <code>Olive</code> is represented by a tab and the project's cells. This consumes the majority of the UI. These projects are contained within two separate panes, the <strong>left pane</strong> and the <strong>right pane</strong> respectively. The left pane <strong>can</strong> be open without the right pane, but the right pane <strong>cannot</strong> be open without the left pane. The project can be switched using the pane switcher button on the top of the project. At the top of the window will be the <strong>topbar</strong>. The <strong>topbar</strong> has two buttons on it, on the left this is a folder with an arrow. Clicking this button will open the <strong>project explorer</strong>. This is the menu to the left of your <code>Olive</code> session. The <strong>project explorer</strong> contains a (<em>green</em>) working directory, as well as any other saved user directories. Additionally, the project explorer holds a <code>home</code> directory if the current user is root.</p>

<p dir="auto">The main window is called <strong>session</strong>. This contains two panes which will be filled with your projects. Projects are denoted by a tab and a window which contains cells. This tab can be double clicked for a range of different project options.</p>

<p dir="auto"><strong>Session</strong> is the colloquial name for the main editor which comprises <code>Olive</code> -- this being the <code>Project</code> and <code>Cell</code> combination. Inside of <strong>session</strong> there are two panes, <code>pane_one</code> and <code>pane_two</code> respectively. These panes houses projects, their tabs being contained within a tab container above them. Clicking these tabs will yield project focus. Double clicking will add the tab's controls to the tab. These are, from left to right, <code>decollapse controls</code>, <code>new cell</code>, <code>switch pane</code>, <code>re-source</code>,<code>step evaluate</code>, and <code>close project</code>. Other than this, the hotkeys in <a href="https://github.com/ChifiSource/Olive.jl#keybindings">keybindings</a> are the primary method <code>Olive</code> uses for input. Files are open from the <strong>project explorer</strong> and then edited inside of this session, before being saved.</p>

<p dir="auto">The <strong>project explorer</strong> is a crucial component to your <code>Olive</code> session because it manages the entire underlying filesystem running in your <code>Environment</code>. Directories, like cells and projects, are parametric types -- so <code>Olive</code> has different directory types. Base <code>Olive</code> comes with the following directory types:</p>
<ul dir="auto">
<li><code>home</code> (<strong>pink</strong>) is the home directory used to change <code>Olive</code>, which is added only for root.</li>
<li><code>pwd</code> (<strong>green</strong>) is the current <code>Environment</code> working directory.</li>
<li><code>{&lt;:Any}</code> (<strong>black</strong>) is the catchall directory, in practice this usually represents an unsaved directory in <code>Olive</code>.</li>
<li><code>saved</code> (<strong>purple</strong>) is a saved directory.</li>
</ul>
<p dir="auto">New directories and files are created through the <code>pwd</code> directory, where all file operations take place. This directory is essentially our file browser. The bookmark indicator on directories in this menu will add a directory to your saved directories, which may then be permanently saved using the save button.</p>

<p dir="auto"><code>Olive</code> is not <code>Olive</code> without extensions. While the base <code>Olive</code> features are pretty cool, <code>Olive</code>'s base is intentionally built with a minimalist mindset. The idea is that <strong>nothing is everyone's cup of tea</strong>, so why use someone else's computer to load things for people who do not even want those things to begin with? With the <code>Olive</code> (and frankly, <strong>Julia</strong>) approach new features are added by adding new methods to existing <code>Olive</code> functions. With this, <code>Olive</code> becomes a notebook centralized on multiple dispatch! Olive extensions work off of <code>Olive</code>'s <a href="#parametric-methodology">parametric multiple dispatch methodology</a> for loading extensions. A parameter is used to denote the existence of a new function, and each method of a given function becomes representative of that cell's action.</p>

  A web<span class="pl-k">-</span>server is given <span class="pl-k">as</span> a <span class="pl-k">return</span> from a ServerTemplate whenever ServerTemplate<span class="pl-k">.</span><span class="pl-c1">start</span>() is ran. It can be rerouted with route! and indexed similarly to
  the Connection, with Symbols representing extensions and Strings representing routes.

  example
  <span class="pl-k">⋅⋅⋅⋅⋅⋅⋅⋅⋅</span>

  st <span class="pl-k">=</span> <span class="pl-c1">ServerTemplate</span>()
  ws <span class="pl-k">=</span> st<span class="pl-k">.</span><span class="pl-c1">start</span>()
  <span class="pl-c1">routes</span>(ws)
  <span class="pl-k">...</span>
  <span class="pl-c1">extensions</span>(ws)
  <span class="pl-k">...</span>
  <span class="pl-c1">route!</span>(ws, <span class="pl-s"><span class="pl-pds">"</span>/<span class="pl-pds">"</span></span>) <span class="pl-k">do</span> c<span class="pl-k">::</span><span class="pl-c1">Connection</span>
      <span class="pl-c1">write!</span>(c, <span class="pl-s"><span class="pl-pds">"</span>hello<span class="pl-pds">"</span></span>)
  <span class="pl-k">end</span>
</pre></div>
<p dir="auto">This is an introspectable server type that holds <strong>all</strong> of the data for your <code>Olive</code> session. From your Julia REPL, this can easily be introspected by accessing the extensions and routes.</p>

<p dir="auto">This also means that the routes of an <code>Olive</code> server could be changed, or rerouted in anyway -- really. All of the projects are stored within the <code>OliveCore.open</code> field, a <code>Vector{Olive.Environment}</code>. Our client data is stored inside of <code>OliveCore.client_data</code> and open projects are in <code>OliveCore.open</code>.</p>

<p dir="auto">When submitting issues or pull-requests for Olive, it is important to make sure of a few things. We are not super strict, but making sure of these few things will be helpful for maintainers!</p>
<ol dir="auto">
<li>You have replicated the issue on <code>Olive#Unstable</code></li>
<li>The issue does not currently exist... or does not have a planned implementation different to your own. In these cases, please collaborate on the issue, express your idea and we will select the best choice.</li>
<li><strong>Pull Request TO UNSTABLE</strong></li>
<li>This is an issue with Olive, not a dependency; if there is a problem with highlighting, please report that issue to <a href="https://github.com/ChifiSource/ToolipsMarkdown.jl">ToolipsMarkdown</a>. If there is an issue with Cell reading/writing, report that issue to <a href="https://github.com/ChifiSource/IPyCells.jl">IPyCells</a></li>
<li>Be <strong>specific</strong> about your issue -- if you are experiencing multiple issues, open multiple issues. It is better to have a high quantity of issues that specifically describe things than a low quantity of issues that describe multiple things.</li>
<li>If you have a new issue, <strong>open a new issue</strong>. It is not best to comment your issue under an unrelated issue; even a case where you are experiencing that issue, if you want to mention <strong>another issue</strong>, open a <strong>new issue</strong>.</li>
<li>Questions are fine, but <strong>not</strong> questions answered inside of this <code>README</code>.</li>
</ol>
