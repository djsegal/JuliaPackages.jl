<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is Mice.jl?</h2><a id="user-content-what-is-micejl" class="anchor" aria-label="Permalink: What is Mice.jl?" href="#what-is-micejl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>Mice.jl</code> is a Julia package for multiple imputation using chained equations. It is heavily based on the R package <a href="https://cran.r-project.org/web/packages/mice/index.html" rel="nofollow">mice</a> by Stef van Buuren and Karin Groothuis-Oudshoorn <a href="#1">[1]</a>.</p>
<p dir="auto"><code>Mice.jl</code>'s syntax is very similar to that of <code>mice</code> and it is intended to be used in conjunction with <a href="https://github.com/JuliaData/Tables.jl">Tables.jl</a>-compatible tables, including <a href="https://github.com/JuliaData/DataFrames.jl">DataFrames</a>.</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mice(data, ...)"><pre><span class="pl-c1">mice</span>(data, <span class="pl-k">...</span>)</pre></div>
<p dir="auto">where:</p>
<p dir="auto"><code>data</code> is the data table.</p>
<p dir="auto"><code>m</code> is the number of imputations.</p>
<p dir="auto"><code>imputeWhere</code> is an <code>AxisVector</code> of vectors specifying which values of each variable are to be imputed. If not specified, all missing values are imputed. You can create a default <code>imputeWhere</code> vector (which you can then edit) using the function <code>findMissings(data)</code>.</p>
<p dir="auto"><code>visitSequence</code> is a vector of column names specifying the order in which the columns should be imputed. If not specified, the order is determined automatically. You can skip the imputation of a column by removing it from the <code>visitSequence</code>.</p>
<p dir="auto"><code>methods</code> is an <code>AxisVector</code> of imputation methods. If not specified, the default methods are used. Currently, <code>Mice.jl</code> supports only a few methods (<code>"pmm"</code>, <code>"rf"</code>, <code>"norm"</code>, <code>"mean"</code> and <code>"sample"</code>). You can make a default methods vector (which you can then edit) using the function <code>makeMethods(data)</code>.</p>
<p dir="auto"><code>predictorMatrix</code> is an <code>AxisMatrix</code> of predictors for each column (with the predictors in the columns of the matrix). If not specified, all other columns are used for each column. To prevent one column from predicting another, ensure that value of the corresponding cell is set to <code>0</code>. You can make a default predictor matrix (which you can then edit) using the function <code>makePredictorMatrix(data)</code>.</p>
<p dir="auto"><code>iter</code> is the number of iterations to perform.</p>
<p dir="auto"><code>progressReports</code> is a boolean indicating whether to print progress reports.</p>
<p dir="auto"><code>gcSchedule</code> determines how often the garbage collector is invoked (additionally to when it would be anyway). This can improve performance for large datasets. The value is the fraction of your machine's RAM that remains free at which the garbage collector will be invoked. The default is <code>0.3</code>, but you may wish to increase this for very large jobs.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Why is <code>Mice.jl</code> so slow for small jobs?</h3><a id="user-content-why-is-micejl-so-slow-for-small-jobs" class="anchor" aria-label="Permalink: Why is Mice.jl so slow for small jobs?" href="#why-is-micejl-so-slow-for-small-jobs"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Julia is a just-in-time compiled language. This means that the first time a function is run, it is compiled into machine code, which takes time. Therefore, the first iteration of <code>mice()</code> will be (much) slower in Julia than in R, for example. However, subsequent iterations will be much faster, as all of the required functions are already compiled.</p>
