<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Overview</h2><a id="user-content-overview" class="anchor" aria-label="Permalink: Overview" href="#overview"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">ExaModels.jl employs what we call <strong><a href="https://en.wikipedia.org/wiki/Single_instruction,_multiple_data" rel="nofollow">SIMD</a> abstraction for <a href="https://en.wikipedia.org/wiki/Nonlinear_programming" rel="nofollow">nonlinear programs</a></strong> (NLPs), which allows for the <strong>preservation of the parallelizable structure</strong> within the model equations, facilitating <strong>efficient, parallel <a href="https://en.wikipedia.org/wiki/Automatic_differentiation" rel="nofollow">reverse-mode automatic differentiation</a></strong> on the <strong><a href="https://en.wikipedia.org/wiki/Graphics_processing_unit" rel="nofollow">GPU</a> accelerators</strong>.</p>
<p dir="auto">ExaModels.jl is different from other algebraic modeling tools, such as <a href="https://github.com/jump-dev/JuMP.jl">JuMP</a> or <a href="https://ampl.com/" rel="nofollow">AMPL</a>, in the following ways:</p>
<ul dir="auto">
<li><strong>Modeling Interface</strong>: ExaModels.jl requires users to specify the model equations always in the form of <code>Generator</code>s. This restrictive structure allows ExaModels.jl to preserve the SIMD-compatible structure in the model equations. This unique feature distinguishes ExaModels.jl from other algebraic modeling tools.</li>
<li><strong>Performance</strong>: ExaModels.jl compiles (via Julia's compiler) derivative evaluation codes tailored to each computation pattern. Through reverse-mode automatic differentiation using these tailored codes, ExaModels.jl achieves significantly faster derivative evaluation speeds, even when using CPU.</li>
<li><strong>Portability</strong>: ExaModels.jl goes beyond traditional boundaries of
algebraic modeling systems by <strong>enabling derivative evaluation on GPU
accelerators</strong>. Implementation of GPU kernels is accomplished using
the portable programming paradigm offered by
<a href="https://github.com/JuliaGPU/KernelAbstractions.jl">KernelAbstractions.jl</a>.
With ExaModels.jl, you can run your code on various devices, including
multi-threaded CPUs, NVIDIA GPUs, AMD GPUs, and Intel GPUs. Note that
Apple's Metal is currently not supported due to its lack of support
for double-precision arithmetic.</li>
</ul>
