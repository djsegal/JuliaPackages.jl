<p dir="auto">IncrementalSVD provides incremental (updating) singular value decomposition.
This allows you to update an existing SVD with new columns, and even implement
online SVD with streaming data.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">All-at-once usage</h2><a id="user-content-all-at-once-usage" class="anchor" aria-label="Permalink: All-at-once usage" href="#all-at-once-usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For reasons that will be described below, if you want a truncated SVD and your matrix is small enough to fit in memory,
you're better off using <a href="https://github.com/JuliaLinearAlgebra/TSVD.jl">TSVD</a>. However, IncrementalSVD can do it too:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using IncrementalSVD, LinearAlgebra

julia&gt; X = randn(5, 12);

julia&gt; U, s = isvd(X, 4);    # get a rank-4 truncated SVD

julia&gt; Vt = Diagonal(s) \ (U' * X);"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">using</span> IncrementalSVD, LinearAlgebra

julia<span class="pl-k">&gt;</span> X <span class="pl-k">=</span> <span class="pl-c1">randn</span>(<span class="pl-c1">5</span>, <span class="pl-c1">12</span>);

julia<span class="pl-k">&gt;</span> U, s <span class="pl-k">=</span> <span class="pl-c1">isvd</span>(X, <span class="pl-c1">4</span>);    <span class="pl-c"><span class="pl-c">#</span> get a rank-4 truncated SVD</span>

julia<span class="pl-k">&gt;</span> Vt <span class="pl-k">=</span> <span class="pl-c1">Diagonal</span>(s) <span class="pl-k">\</span> (U<span class="pl-k">'</span> <span class="pl-k">*</span> X);</pre></div>
<p dir="auto">Note that <code>Vt</code> is <em>not</em> returned by <code>isvd</code>; for reasons described <a href="#on-the-fly-v">below</a> we compute it afterwards.</p>
<p dir="auto"><code>isvd</code> uses incremental updating, which is lossy to an extent that depends on the distribution of singular values.
For comparison:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using TSVD

<p dir="auto">In this particular case, the rank-4 absolute error with TSVD is a few percent better than with IncrementalSVD.
The error of incremental SVD comes from the fact that it works on chunks, and there is a truncation step after each chunk that discards information; see <a href="#references">Brand 2006</a> Eq 5 for more insight.</p>
<p dir="auto">However, the <em>real</em> use-case for IncrementalSVD is in computing incremental updates or handling cases where <code>X</code> is too large to fit in memory all at once, and for such applications it handily beats alternatives like random projection + power iteration (e.g., <code>rsvd</code> from <a href="https://github.com/JuliaLinearAlgebra/RandomizedLinAlg.jl">RandomizedLinAlg.jl</a>).</p>

<p dir="auto">The most straightforward way to reduce error is to retain more components than you actually need.
To estimate this error and how it depends on the number of extra components and the characteristics of the input matrix, in this demo we'll use covariance matrices where eigenvalue <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\lambda_{k+1} = \beta \lambda_k$</math-renderer> for a constant <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$0 \le \beta \le 1$</math-renderer>.
Using this covariance matrix, we generate 1000 samples in a 100-dimensional space, and compare the accuracy of <code>isvd</code> vs <code>svd</code> for 5 retained components.
Without any extra components, the error for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta=1$</math-renderer> is approximately 1.8% and drops below 0.1% for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta \approx 0.78$</math-renderer>.
If we instead compute <code>isvd</code> with twice as many components (10) as we expect to keep (5), the error for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta=1$</math-renderer> is 1.2% and drops below 0.1% for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta \approx 0.93$</math-renderer>.
(For comparison, <code>rsvd</code> from <a href="https://github.com/JuliaLinearAlgebra/RandomizedLinAlg.jl">RandomizedLinAlg.jl</a> with no extra components has an error of 11% at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta=1$</math-renderer> and stayed above 5% for all tested <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta$</math-renderer>; with twice as many components the error was 4.4% at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta=1$</math-renderer> and did not drop below 0.1% until <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta = 0.35$</math-renderer>.)
The relative error as a function of both <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e65b6d5999b1b2444930db7ab7c6dba9">$\beta$</math-renderer> and the number of "extra" components retained can be shown as a heatmap:</p>

<p dir="auto">You can reduce the amount of memory allocated with each update by supplying a cache for intermediate results.
See <code>?IncrementalSVD.Cache</code>.</p>
<p dir="auto">IncrementalSVD performs NaN-imputation. While in normal usage it doesn't modify values of <code>X</code> in-place, see <code>?IncrementalSVD.impute_nans</code>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">On-the-fly V</h2><a id="user-content-on-the-fly-v" class="anchor" aria-label="Permalink: On-the-fly V" href="#on-the-fly-v"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Why doesn't <code>isvd</code> return <code>V</code>? This is because <code>X</code> is processed in chunks, and both <code>U</code> and <code>s</code> get updated
with each chunk; if we computed <code>V</code> "on-the-fly", the early rows of <code>V</code> would be computed from an early
approximation of <code>U</code> and <code>s</code>, and thus inconsistent with later rows. <em>The error that comes from not using a fully "trained" <code>U</code> and <code>s</code> can be very large</em>.</p>
<p dir="auto">In online applications, a good strategy might be to "train" <code>U</code> and <code>s</code> with enough samples, and then start
computing <code>V</code> once trained (no longer updating <code>U</code> and <code>s</code>).</p>
<p dir="auto">But for online applications where you can't afford to throw away anything---even at the cost of <em>large</em> errors in the early columns of <code>Vt</code>---here's how you can do it:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function isvd_with_Vt(X::AbstractMatrix{&lt;:Real}, nc)
    Base.require_one_based_indexing(X)
    T = float(eltype(X))
    U = s = nothing
    Vt = zeros(T, nc, size(X, 2))
    cache = IncrementalSVD.Cache{T}(size(X,1), nc, nc)
    for j = 1:nc:size(X,2)
        Xchunk = @view(X[:,j:min(j+nc-1,end)])
        U, s = IncrementalSVD.update!(U, s, Xchunk, size(Xchunk, 2) == nc ? cache : nothing)
        Vt[:,j:min(j+nc-1,end)] = Diagonal(s) \ (U' * Xchunk)
    end
    return U, s, Vt
end"><pre><span class="pl-k">function</span> <span class="pl-en">isvd_with_Vt</span>(X<span class="pl-k">::</span><span class="pl-c1">AbstractMatrix{&lt;:Real}</span>, nc)

        Vt[:,j<span class="pl-k">:</span><span class="pl-c1">min</span>(j<span class="pl-k">+</span>nc<span class="pl-k">-</span><span class="pl-c1">1</span>,<span class="pl-k">end</span>)] <span class="pl-k">=</span> <span class="pl-c1">Diagonal</span>(s) <span class="pl-k">\</span> (U<span class="pl-k">'</span> <span class="pl-k">*</span> Xchunk)
    <span class="pl-k">end</span>
    <span class="pl-k">return</span> U, s, Vt
<span class="pl-k">end</span></pre></div>
