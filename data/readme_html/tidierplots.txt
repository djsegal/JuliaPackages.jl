<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is TidierPlots.jl?</h2><a id="user-content-what-is-tidierplotsjl" class="anchor" aria-label="Permalink: What is TidierPlots.jl?" href="#what-is-tidierplotsjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">TidierPlots.jl is a 100% Julia implementation of the R package <a href="https://ggplot2.tidyverse.org/" rel="nofollow">ggplot2</a> powered by <a href="https://github.com/MakieOrg/Makie.jl">Makie.jl</a>.</p>
<p dir="auto"><code>TidierPlots.jl</code> has three goals, which differentiate it from other plotting packages in Julia:</p>
<ol dir="auto">
<li>
<p dir="auto"><strong>Stick as closely to tidyverse syntax and behaviour as possible:</strong> Whereas other
meta-packages introduce Julia-centric idioms for working with
plots, this package’s goal is to reimplement ggplot
in Julia. This currently just means that <code>TidierPlots.jl</code> gives the option for specifying <code>aes</code> with the macro <code>@es</code> to allow unquoted column references, but the use of macros may need to expand as more features are added.</p>
</li>
<li>
<p dir="auto"><strong>Stay as compatible as possible with Makie.jl</strong> This package is meant
to be a thin wrapper around Makie's SpecApi syntax to help introduce R users to plotting in
Julia.</p>
</li>
<li>
<p dir="auto"><strong>To Extend ggplot using julia-specific features where appropriate</strong> as long as this does
not confict with the first two goals. The package aims to behave exactly like ggplot
unless told otherwise. Additional options and parameters that are not present in ggplot
may be added, but options that are present in R's ggplot should behave the way they do in R.</p>
</li>
</ol>

<p dir="auto">TidierPlots.jl currently supports the top-level function <code>ggplot()</code>, plus:</p>
<p dir="auto">Geoms:</p>
<ul dir="auto">
<li><code>geom_point</code></li>
<li><code>geom_errorbar</code></li>
<li><code>geom_path</code>, <code>geom_line</code>, and <code>geom_step</code></li>
<li><code>geom_bar</code>, <code>geom_col</code>, and <code>geom_histogram</code></li>
<li><code>geom_boxplot</code> and <code>geom_violin</code></li>
<li><code>geom_contour</code> and <code>geom_tile</code></li>
<li><code>geom_density</code></li>
<li><code>geom_text</code> and <code>geom_label</code></li>
</ul>
<p dir="auto">Makie Themes:</p>
<ul dir="auto">
<li><code>theme_ggplot2()</code> (the default)</li>
<li><code>theme_dark()</code></li>
<li><code>theme_black()</code></li>
<li><code>theme_light()</code></li>
<li><code>theme_minimal()</code></li>
</ul>
<p dir="auto">Colour Scales:</p>
<ul dir="auto">
<li><code>scale_color_manual()</code> - set <code>values = c(c1, c2, c3, ...)</code>, accepts anything that can be parsed as a color by Colors.jl (named colors, hex values, etc.)</li>
<li><code>scale_color_[discrete|continuous|binned]()</code> - set <code>palette =</code> a <a href="https://juliagraphics.github.io/ColorSchemes.jl/stable/catalogue/" rel="nofollow">ColorSchemes.jl palette</a> as a string or symbol. Also accepts ColorSchemes.jl color scheme objects.</li>
</ul>
<p dir="auto">Additional Elements:</p>
<ul dir="auto">
<li><code>scale_[x|y]_[continuous|log[ |2|10]|logit|pseudolog10|sqrt|reverse]</code></li>
<li><code>labs</code></li>
<li><code>lims</code></li>
</ul>

<p dir="auto">Use the function <code>TidierPlots_set(option::String, value::Bool)</code> to control display options. The following options are supported:</p>
<ul dir="auto">
<li>"plot_show" (default true). Enables <code>ggplot</code>-like behaviour where plots are displayed when created.</li>
<li>"plot_log" (default true). Prints a text summary of the properties of the ggplot</li>
</ul>
<p dir="auto">You will likely want to disable both of these if you are working in a notebook environment. In <a href="https://github.com/fonsp/Pluto.jl">Pluto.jl</a>, you can get interactive plots (scroll, zoom, labels, etc.) using <code>WGLMakie</code> by including <code>WGLMakie.activate!()</code> as the first cell after your imports.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Differences from ggplot2</h2><a id="user-content-differences-from-ggplot2" class="anchor" aria-label="Permalink: Differences from ggplot2" href="#differences-from-ggplot2"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The goal of this package is to allow you to write code that is as similar to ggplot2 code as possible. The only difference in basic usage is in the <code>aes()</code> function. TidierPlots.jl accepts two forms for aes specification, neither of which is <em>exactly</em> the same as ggplot2.</p>
<ul dir="auto">
<li>Option 1: <code>aes</code> function, julia-style columns, e.g. <code>aes(x = :x, y = :y)</code> or <code>aes(:x, :y)</code></li>
<li>Option 2: <code>@aes</code> (or <code>@es</code>) macro, aes as in ggplot, e.g. <code>@aes(x = x, y = y)</code> or <code>@aes(x, y)</code></li>
<li>Option 3 (Deprecated): <code>aes</code> function, column names as strings, e.g. <code>aes(x = "x", y = "y")</code> or <code>aes("x", "y")</code></li>
</ul>
<p dir="auto">If you use Option 1, you get experimental support for calculations inside aes, including <code>+</code>, <code>-</code>, <code>*</code>, <code>/</code> and function application. Functions can be applied to columns with the <code>&gt;&gt;</code> operator, or wrapped for aes use with the <code>aesthetics_function()</code> command. The following geom_point specifications are equivalent:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="my_fn(x) = x ./ 10

geom_point(aes(x = my_aes_fn(:x)))"><pre><span class="pl-en">my_fn</span>(x) <span class="pl-k">=</span> x <span class="pl-k">./</span> <span class="pl-c1">10</span>
