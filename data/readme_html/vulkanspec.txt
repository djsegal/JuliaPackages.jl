<p dir="auto"><a href="https://en.wikipedia.org/wiki/Vulkan" rel="nofollow">Vulkan</a> is a cross-platform graphics API for GPUs, created by the Khronos Group consortium. It is gigantic in size, and reflects the complexity found in modern day GPUs with varying designs and functionality. Fortunately, Khronos gives us tools to make sense of it, and to reduce the effort required in using it. The <a href="https://registry.khronos.org/vulkan/specs/1.3-extensions/html/vkspec.html" rel="nofollow">specification document</a> is enormous however, and if you don't want to read it all, it's OK: you are just being a sane person. To the rescue, the <a href="https://github.com/KhronosGroup/Vulkan-Docs">specification repository</a> hosts a <a href="https://github.com/KhronosGroup/Vulkan-Docs/blob/main/xml/vk.xml">machine-readable version of the specification</a> under the form of an XML file.</p>
<p dir="auto">If you were, say, trying to interface with the C Vulkan drivers (which are mere software libraries that conform to the API dictated by the Vulkan specification), you may find it (very) tedious to do everything by hand. Instead, you will want a wrapper for Vulkan written in your language of choice, e.g. Julia, such that you don't need to care about C interfacing details. For Julia, there is <a href="https://github.com/JuliaGPU/Vulkan.jl">Vulkan.jl</a>, and for other languages, you have <a href="https://vulkan.org/tools#language-bindings" rel="nofollow">quite a few existing wrappers</a>.</p>
<p dir="auto">The functionality provided by this package was originally meant to help automate the generation of bindings for Julia, and was living under <a href="https://github.com/JuliaGPU/Vulkan.jl">Vulkan.jl</a>. However, it seemed like a good idea to split it out and enable new uses: with access to the structure of the Vulkan API, you can do more than generating wrappers. Here are a few ideas:</p>
<ul dir="auto">
<li>Learning by inspecting the various parts of the API from the REPL.</li>
<li>Making a Vulkan-aware IDE extension to bring practical information to the coding activity directly.</li>
<li>Designing a web page targeted at exploration, learning and/or reference material.</li>
<li>Creating easy-to-read diffs between Vulkan versions to facilitate keeping up with new functionality.</li>
</ul>
<p dir="auto">... and probably more!</p>
<p dir="auto">Check out the <strong><a href="https://serenity4.github.io/VulkanSpec.jl/dev/" rel="nofollow">DOCUMENTATION</a></strong> to get started.</p>
