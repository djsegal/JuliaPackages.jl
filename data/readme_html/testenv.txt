<p dir="auto">This is a 1-function package: <code>TestEnv.activate</code>.
It lets you activate the test environment from a given package.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Why is this useful?</h3><a id="user-content-why-is-this-useful" class="anchor" aria-label="Permalink: Why is this useful?" href="#why-is-this-useful"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This lets you run code in the test enviroment, interactively; giving you access to all your test-only dependencies.
When you run <code>]test</code> in the REPL, a new Julia process is started which activates a temporary environment containing the tested package together with all its test-only dependencies.
These can be either defined in the <code>[extras]</code> section in the package's <code>Project.toml</code> or in a separate <code>test/Project.toml</code>.
The special temporary environment is different than the plain package environment (which doesn't contain the extra test dependencies) or the <code>test/Project.toml</code> environment (which doesn't contain the package itself, and may not exist).
Once the tests finish, the extra Julia process is closed and the temporary environment is deleted.
You are not able to manually run any other code in it, which would be useful for test writing and debugging.
Julia does not offer an official mechanism to activate such an environment outside of <code>]test</code>.
That's what <code>TestEnv.activate()</code> is for.</p>

<p dir="auto">Like other developer focused tools, TestEnv.jl should not be added as a dependency of the package you are developing, but rather added to your global enviroment, so it is always available.
The easiest way to install it to the global enviroment is to start julia (without passing the <code>--project</code> argument), and then run <code>] add TestEnv</code>.</p>

<p dir="auto">Consider <strong>ChainRules.jl</strong> which has a test-only dependency of <strong>ChainRulesTestUtils.jl</strong>,
not a main dependency.</p>
<p dir="auto">(Note that you can install <code>TestEnv</code> in your global environment as it has no dependencies other than <code>Pkg</code>.
This way you can load it from anywhere, instead of having to add it to package environments.)</p>

<p dir="auto">Use <code>Pkg.activate</code> to re-activate the previous environment, e.g. <code>Pkg.activate("~/.julia/dev/ChainRules")</code>.</p>
<p dir="auto">You can also pass in the name of a package, to activate that package and it's test dependencies:
<code>TestEnv.activate("Javis")</code> for example would activate Javis.jl's test environment.</p>
<p dir="auto">Finally you can pass in a function to run in this environment.</p>
