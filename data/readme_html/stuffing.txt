This algorithm provides a solution for <strong>2D irregular nesting problems</strong> (also known as cutting problems or packing problems). It is capable of processing arbitrary shapes represented by <strong>binary or ternary raster masks</strong> as inputs and excels in efficiently handling the nesting problems associated with numerous small objects. The implementation of this algorithm is based on quadtree and gradient optimization techniques. Additionally, it can be parallelized by launching <code>julia</code> with <code>julia --threads k</code>. This package is utilized by <a href="https://github.com/guo-yong-zhi/WordCloud.jl">WordCloud.jl</a>.<br>
Examples: <a href="./examples/collision.jl">collision detection</a>, <a href="./examples/dynamiccollisions.jl">dynamic collision detection</a>, <a href="./examples/packing.jl">packing</a><br>
Benchmark: <a href="./examples/collision_benchmark.jl">collision benchmark</a>, <a href="https://github.com/guo-yong-zhi/WordCloud.jl/blob/master/examples/benchmark.jl">fit benchmark</a></p>

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Algorithm Description</h1><a id="user-content-algorithm-description" class="anchor" aria-label="Permalink: Algorithm Description" href="#algorithm-description"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The algorithm consists of three main steps:</p>
<ol dir="auto">
<li><strong>Ternary Raster Pyramid Construction</strong>: Initially, a ternary raster pyramid (<a href="./src/qtrees.jl"><code>AbstractStackedQTree</code></a>) is created for each original binary raster mask. This pyramid comprises downsampled layers of the original mask. Each subsequent layer is downsampled at a 2:1 scale. Consequently, the pyramid can be viewed as a collection of hierarchical bounding boxes. Each pixel in every layer (tree node) can take one of three values: <code>FULL</code>, <code>EMPTY</code>, or <code>MIX</code>.</li>
</ol>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="./res/pyramid1.png"><img src="./res/pyramid1.png" alt="pyramid1" style="max-width: 100%;"></a>
<a target="_blank" rel="noopener noreferrer" href="./res/pyramid2.png"><img src="./res/pyramid2.png" alt="pyramid2" style="max-width: 100%;"></a></p>
<ol start="2" dir="auto">
<li><strong>Top-Down Collision Detection</strong>: The algorithm employs a top-down approach (<a href="./src/qtree_functions.jl"><code>collision</code></a>) to identify collisions between two pyramids or trees. At level 𝑙 and coordinates (𝑎,𝑏), if a node in one tree is <code>FULL</code> and the corresponding node in the other tree is not <code>EMPTY</code>, a collision occurs at (𝑙,𝑎,𝑏). However, pairwise collision detection between multiple objects would be time-consuming. To address this, the algorithm first locates the objects within hierarchical sub-regions (<a href="./src/qtree.jl"><code>HashSpacialQTree</code> or <code>LinkedSpacialQTree</code></a>). It then detects collisions between objects within each sub-region and between objects in sub-regions and their ancestral regions (<a href="./src/qtree_functions.jl"><code>totalcollisions_spacial</code>, <code>partialcollisions</code> and <code>locate!</code></a>).</li>
</ol>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="./res/collision.png"><img src="./res/collision.png" alt="collision" style="max-width: 100%;"></a></p>
<ol start="3" dir="auto">
<li><strong>Object Movement and Reconstruction</strong>: In the final step, each object in a collision pair is moved based on the local gradient (<a href="./src/fit.jl"><code>grad2d</code></a>) near the collision point (𝑙,𝑎,𝑏). The movement aims to separate the objects and create more space between them. Specifically, the objects are shifted away from the <code>EMPTY</code> regions. After moving the objects, the algorithm rebuilds the <code>AbstractStackedQTree</code>s to prepare for the next round of collision detection.</li>
</ol>
