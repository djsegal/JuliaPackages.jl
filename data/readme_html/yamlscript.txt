<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">About YAMLScript</h2><a id="user-content-about-yamlscript" class="anchor" aria-label="Permalink: About YAMLScript" href="#about-yamlscript"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">YAMLScript is a functional programming language with a stylized YAML syntax.</p>
<p dir="auto">YAMLScript can be used for:</p>
<ul dir="auto">
<li>Writing new programs and applications
<ul dir="auto">
<li>Run with <code>ys file.ys</code></li>
<li>Or compile to binary with <code>ys -C file.ys</code></li>
</ul>
</li>
<li>Writing reusable shared libraries
<ul dir="auto">
<li>Bindable to almost any programming language</li>
</ul>
</li>
<li>Using as a YAML loader module in many programming languages
<ul dir="auto">
<li>Plain / existing YAML files</li>
<li>YAML files with new functional magics</li>
</ul>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Run or Load?</h3><a id="user-content-run-or-load" class="anchor" aria-label="Permalink: Run or Load?" href="#run-or-load"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">YAMLScript programs can either be "run" or "loaded".
When a YAMLScript program is run, it is executed as a normal program.
When a YAMLScript program is loaded, it evaluates to a JSON-model data
structure.</p>
<p dir="auto">Most existing YAML files in the wild are already valid YAMLScript programs.
If you have a valid YAML (<a href="https://yaml.org/spec/1.2.2/#103-core-schema" rel="nofollow">1.2 Core Schema</a>) file that doesn't use custom
tags, and loads to a value expressible in JSON, then it is a valid YAMLScript
program.
YAMLScript's <code>load</code> operation will evaluate that file exactly the same in any
programming language / environment.</p>
<p dir="auto">These existing YAML files obviously can't use YAMLScript's functional
programming features since that would be ambiguous.
For example, what is the JSON value when "loading" this YAMLScript program?</p>
<div class="highlight highlight-source-yaml notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="foo: inc(41)"><pre><span class="pl-ent">foo</span>: <span class="pl-s">inc(41)</span></pre></div>
<p dir="auto">Is it <code>{"foo": "inc(41)"}</code> or <code>{"foo": 42}</code>?</p>
<p dir="auto">YAMLScript programs must start with a special YAML tag <code>!yamlscript/v0</code> to
indicate that they have functional capabilities.</p>
<div class="highlight highlight-source-yaml notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="!yamlscript/v0/data
foo:: inc(41)"><pre><span class="pl-s">!yamlscript/v0/data</span>
<span class="pl-ent">foo:</span>: <span class="pl-s">inc(41)</span></pre></div>
<blockquote>
<p dir="auto">Note: The <code>/v0</code> in the tag indicates the YAMLScript API version.
This is so that future versions of YAMLScript can run programs written to an
older API version, and also so that older versions of YAMLScript don't try to
run programs written to a newer API version.</p>
</blockquote>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Using YAMLScript</h3><a id="user-content-using-yamlscript" class="anchor" aria-label="Permalink: Using YAMLScript" href="#using-yamlscript"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There are two primary ways to use YAMLScript:</p>
<ul dir="auto">
<li>Using the <code>ys</code> command line runner / loader / compiler / installer</li>
<li>Using a YAMLScript library in your own programming language</li>
</ul>
<p dir="auto">The <code>ys</code> command line tool is the easiest way to get started with YAMLScript.
It has these main modes of operation:</p>
<ul dir="auto">
<li><code>ys &lt;file&gt;</code> - Run a YAMLScript program</li>
<li><code>ys --run &lt;file&gt;</code> - Same as above but explicit</li>
<li><code>ys --load &lt;file&gt;</code> - Load a YAMLScript program</li>
<li><code>ys --compile &lt;file&gt;</code> - Compile a YAMLScript program to Clojure</li>
<li><code>ys --binary &lt;file&gt;</code> - Compile YAMLScript to a native binary executable</li>
<li><code>ys --eval '&lt;expr&gt;'</code> - Evaluate a YAMLScript expression string</li>
<li><code>ys --repl</code> - Start an interactive YAMLScript REPL session</li>
<li><code>ys --install</code> - Install the latest libyamlscript shared library</li>
<li><code>ys --upgrade</code> - Upgrade ys and libyamlscript</li>
<li><code>ys --help</code> - Show the <code>ys</code> command help</li>
</ul>
<p dir="auto">You can also use YAMLScript as a library in your own programming language.
For example, in Python you can use the <code>yamlscript</code> module like this:</p>
<div class="highlight highlight-source-python notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import yamlscript

<span class="pl-s1">data</span> <span class="pl-c1">=</span> <span class="pl-s1">ys</span>.<span class="pl-en">load</span>(<span class="pl-s1">text</span>)</pre></div>

<p dir="auto">YAMLScript is supported on these operating systems:</p>
<ul dir="auto">
<li>Linux</li>
<li>macOS</li>
<li>Windows  (work in progress)</li>
</ul>
<p dir="auto">YAMLScript is supported on these architectures:</p>
<ul dir="auto">
<li>Intel/AMD (<code>x86_64</code>)</li>
<li>ARM (<code>aarch64</code>)</li>
</ul>
<p dir="auto">For now other systems cannot be supported because <code>ys</code> and <code>libyamlscript</code> are
compiled by GraalVM's <code>native-image</code> tool, which only supports the above
systems.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Is YAMLScript a Lisp?</h3><a id="user-content-is-yamlscript-a-lisp" class="anchor" aria-label="Permalink: Is YAMLScript a Lisp?" href="#is-yamlscript-a-lisp"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Even though YAMLScript often has the look of an imperative programming language,
it actually is just a (YAML based) syntax that <em>compiles</em> to
<a href="https://clojure.org/" rel="nofollow">Clojure</a> code.
The resulting Clojure code is then run by a native-machine-code Clojure runtime
called <a href="https://github.com/babashka/sci">Small Clojure Interpreter (SCI)</a>.</p>
<p dir="auto">Clojure is a functional programming language with its own Lisp syntax.
Therefore it is fair to say that YAMLScript is a (functional) Lisp, even though
it commonly doesn't look like one syntactically.</p>
<p dir="auto">Typically Clojure produces Java bytecode that is run on the JVM, but for
YAMLScript there is no Java or JVM involved.
In testing so far, YAMLScript programs tend to run as fast or faster than
equivalent Perl or Python programs.</p>
<p dir="auto">For getting started with YAMLScript, you don't need to know anything about Lisp
or Clojure.
You can use it with as much or as little Lisp-ness as you want; the
syntax is quite flexible (<em>and even programmable!</em>).
As your YAMLScript programming requirements grow, you can rest assured that you
have the full power of Clojure at your disposal.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Installing YAMLScript</h2><a id="user-content-installing-yamlscript" class="anchor" aria-label="Permalink: Installing YAMLScript" href="#installing-yamlscript"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">At the moment, the best way to install YAMLScript is to build it from source,
but see the section "Installing YAMLScript Binary Releases" below.</p>
<p dir="auto">This is very easy to do because the YAMLScript build process has very few
dependencies:</p>
<ul dir="auto">
<li><code>bash</code> (your interactive shell can be any shell)</li>
<li><code>curl</code></li>
<li><code>git</code></li>
<li><code>make</code></li>
<li><code>zlib-dev</code> (need this installed on Linux)</li>
</ul>
<p dir="auto">To install the <code>ys</code> command line tool, and <code>libyamlscript</code> shared library,
run these commands:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="git clone https://github.com/yaml/yamlscript
cd yamlscript
make build
make install"><pre>git clone https://github.com/yaml/yamlscript
<span class="pl-c1">cd</span> yamlscript
make build
make install</pre></div>
<p dir="auto">The <code>make install</code> command will install <code>ys</code> and <code>libyamlscript</code> to
<code>~/.local/bin</code> and <code>~/.local/lib</code> respectively, by default.
If run as root they will default to <code>/usr/local/bin</code> and <code>/usr/local/lib</code>.</p>
<p dir="auto">To install to a different location, run <code>make install PREFIX=/some/path</code>.</p>
<blockquote>
<p dir="auto">Notes:</p>
<ul dir="auto">
<li><code>make install</code> triggers a <code>make build</code> if needed, but...</li>
<li>You need to run <code>make build</code> not as root</li>
<li>The build can take several minutes (<code>native-image</code> is slow)</li>
<li>If you install to a custom location, you will need to add that location to
your <code>PATH</code> and <code>LD_LIBRARY_PATH</code> environment variables</li>
</ul>
</blockquote>

<p dir="auto">YAMLScript now ships binary releases for some platforms <a href="https://github.com/yaml/yamlscript/releases">here</a>.</p>
<p dir="auto">To install a latest release for your machine platform, try:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="$ curl https://yamlscript.org/install | bash"><pre>$ curl https://yamlscript.org/install <span class="pl-k">|</span> bash</pre></div>
<p dir="auto">Make sure <code>~/.local/bin</code> is in your <code>PATH</code> environment variable.</p>
<p dir="auto">You can use the following environment variables to control the installation:</p>
<ul dir="auto">
<li><code>PREFIX=...</code> - The directory to install to. Default: <code>~/.local</code></li>
<li><code>VERSION=...</code> - The YAMLScript version to install. Default: <code>0.1.75</code></li>
<li><code>BIN=1</code> - Only install the <code>PREFIX/bin/ys</code> command line tool.</li>
<li><code>LIB=1</code> - Only install the <code>PREFIX/lib/libyamlscript</code> shared library.</li>
<li><code>DEBUG=1</code> - Print the Bash commands that are being run.</li>
</ul>
<p dir="auto">Once you have installed the <code>ys</code> command you can upgrade to a bin binary
version with <code>ys --upgrade</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Installing a YAMLScript Binding for a Programming Language</h3><a id="user-content-installing-a-yamlscript-binding-for-a-programming-language" class="anchor" aria-label="Permalink: Installing a YAMLScript Binding for a Programming Language" href="#installing-a-yamlscript-binding-for-a-programming-language"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">YAMLScript ships its language binding libraries and the <code>libyamlscript.so</code>
shared library separately.</p>
<p dir="auto">Currently, each binding release version requires an exact version of the shared
library, or it will not work.
That's because the YAMLScript language is still evolving quickly.</p>
<p dir="auto">The best way to install a binding library is to use your programming language's
package manager to install the latest binding version, and the YAMLScript
installer to install the latest shared library version.</p>
<p dir="auto">So for Python you would:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="$ pip install yamlscript
$ ys --install"><pre>$ pip install yamlscript
$ ys --install</pre></div>
<p dir="auto">The Perl installation process can automatically install the shared library, so
you can just do:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cpanm YAMLScript"><pre>cpanm YAMLScript</pre></div>
<p dir="auto">Eventually, the YAMLScript binding installation process will become simpler and
more consistent across all languages.</p>

<p dir="auto">The <a href="https://github.com/yaml/yamlscript">YAMLScript source code repository</a>
is a mono-repo containing:</p>
<ul dir="auto">
<li>The YAMLScript compiler code</li>
<li>The YAMLScript shared library code</li>
<li>A YAMLScript binding module for each programming language</li>
<li>The YAMLScript test suite</li>
<li>The YAMLScript documentation</li>
<li>The yamlscript.org website (with docs, blog, wiki, etc)</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>make</code> It So</h3><a id="user-content-make-it-so" class="anchor" aria-label="Permalink: make It So" href="#make-it-so"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The YAMLScript repository uses a <code>Makefile</code> system to build, test and install
its various offerings.
There is a top level <code>Makefile</code> and each repo subdirectory has its own
<code>Makefile</code>.
When run at the top level, many <code>make</code> targets like <code>test</code>, <code>build</code>, <code>install</code>,
<code>clean</code>, <code>distclean</code>, etc will invoke that target in each relevant subdirectory.</p>
<p dir="auto">Given that this repository has so few dependencies, you should be able to clone
it and run <code>make</code> targets (try <code>make test</code>) without any problems.</p>

<p dir="auto">To ensure that YAMLScript libraries work the same across all languages, this
project aims to have a binding implementation for each programming language.</p>
<p dir="auto">If you would like to contribute a new YAMLScript binding for a programming
language, you are encouraged to
<a href="https://github.com/yaml/yamlscript/pulls">submit a pull request</a> to this
repository.</p>
<p dir="auto">See the YAMLScript <a href="https://github.com/yaml/yamlscript/tree/main/Contributing.md">Contributing Guide</a> for more details.</p>
