<hr>
<p dir="auto">CoralBlox is a coral growth and mortality model. It simulates distinct coral
<code>FunctionalGroups</code> indirectly competing for a limited space over time. The model does not
directly consider disturbances such as mortality caused by cyclone, CoTS or heat stress. It
also does not have representation of anthropogenic restoration and conservation activities
such as coral seeding or cloud brightening. Such considerations can be included by
perturbing model state and CoralBlox parameters between time steps.</p>
<p dir="auto">In CoralBlox, the corals are grouped according to their approximate diameter, forming
<code>SizeClasses</code>. A <code>SizeClass</code> is defined by a diameter interval, so all corals whose diameter
lie within the same interval belong to the same <code>SizeClass</code>. Hence, at each timestep, coral
growth is represented by a displacement in the diameter space. For each functional group,
corals from distinct <code>SizeClasses</code> have distinct growth rates. Since all corals within the
same <code>SizeClass</code> and <code>FunctionalGroup</code> have the same growth rate, we can visualize the
growth as groups of corals moving on the diameter space in blocks. Further details about
how this growth and mortality are implemented can be found below.</p>

<p dir="auto">The <code>linear_extension_scale_factors</code> calculated at each timestep prevents the corals from outgrowing
the habitable area, taking into account the simultaneous growth across all functional groups
and size classes. Details about how this scale factor is calculated and used can be
found below.</p>
<p dir="auto">Consideration of external factors that may influence coral growth and mortality
could be included outside of each <code>timestep!</code> call, potentially informed by a broader
ecosystem model.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Model details</h2><a id="user-content-model-details" class="anchor" aria-label="Permalink: Model details" href="#model-details"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Consider the area of each colony approximated by the area of a circumference with diameter
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$x$</math-renderer>:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
a(x) = \frac{\pi x^2}{4}
\end{equation}
$$</math-renderer></p>
<p dir="auto">Hence, given a diameter density function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\lambda(x)$</math-renderer> that represents the number of corals
with diameter <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$x$</math-renderer>, the area <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C(x_i,x_f)$</math-renderer> covered by corals with diameter between <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$x_i$</math-renderer> and
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$x_f$</math-renderer> is given by the integral:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
C(x_i,x_f) = \int_{x_i}^{x_f} \lambda(x) \frac{\pi x^2}{4} dx
\end{equation}
$$</math-renderer></p>
<p dir="auto">In practice, we work with groups of coral with a constant diameter density over a certain
diameter interval, that we call <code>CoralBlock</code>. Each <code>CoralBlock</code> is characterized by a
constant diameter density <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\lambda_{\tau\sigma b}$</math-renderer> (the block's height) and a diameter
interval <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$[\delta_{\tau\sigma b}^-, \delta_{\tau\sigma b}^+]$</math-renderer>, with size
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\Delta \delta_{\tau\sigma b} = \delta_{\tau\sigma b}^+ - \delta_{\tau\sigma b}^-$</math-renderer> (the
block's width). The indices <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\tau\sigma b$</math-renderer> refer to the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$b$</math-renderer>-th block from functional group
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\tau$</math-renderer> and size class <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma$</math-renderer>. Therefore, the area covered by the corals within a coral
block <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\tau\sigma b$</math-renderer> is given by:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
C_{\tau\sigma b} = \lambda_{\tau\sigma b} \frac{\pi}{12} ((\delta_{\tau\sigma b}^+)^3 - (\delta_{\tau\sigma b}^-)^3)
\end{equation}
$$</math-renderer></p>
<p dir="auto">The following sections explain in more detail how growth and mortality are represented.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">How does mortality work?</h3><a id="user-content-how-does-mortality-work" class="anchor" aria-label="Permalink: How does mortality work?" href="#how-does-mortality-work"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">At each timestep <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$t$</math-renderer>, before the growth event, we apply a survival rate to each
<code>CoralBlock</code>. That is done by multiplying each <code>FunctionalGroup</code> and <code>SizeClass</code> survival
rate <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$(1 - m_{\tau\sigma})$</math-renderer> by each <code>CoralBlock</code> diameter density
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\lambda_{\tau\sigma b; t}$</math-renderer>, so that:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
\lambda_{\tau\sigma b; t} = \lambda_{\tau\sigma b; t-1} (1 - m_{\tau\sigma})
\end{equation}
$$</math-renderer></p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">How does growth work?</h3><a id="user-content-how-does-growth-work" class="anchor" aria-label="Permalink: How does growth work?" href="#how-does-growth-work"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For each <code>FunctionalGroup</code>, we can think of a horizontal axis representing the diameter
space with its <code>CoralBlock</code>s lined up. Then, a growth event is conceived as the displacement
of each block in this axis by a factor <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\omega_{\tau\sigma;t}$</math-renderer>, called growth rate, constant
for each <code>FunctionalGroup</code> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\tau$</math-renderer> and <code>SizeClass</code> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma$</math-renderer>. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\omega_{\tau\sigma;t}$</math-renderer> is
always smaller than the correspondent <code>SizeClass</code> width
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\Delta d_{\tau\sigma}=d_{\tau\sigma}^+-d_{\tau\sigma}^-$</math-renderer>.</p>
<p dir="auto">After a growth event we can have one of the three following situations: (1) the entire block
remains in size class <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma$</math-renderer>; (2) the entire block has moved to size class <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma+1$</math-renderer>; (3)
part of the block remains in size class <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma$</math-renderer> and part has moved to size class
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\sigma+1$</math-renderer>. In the last case, we break the block in two new blocks, each belonging to only
a single size class.</p>
<p dir="auto">In (1), the <code>CoralBlock</code> doesn't cross the frontier between <code>SizeClass</code>es. In this case,
its movement is constant. In (2) and (3), as soon as part of the block enters the next
<code>SizeClass</code>, the two parts move with different speeds (one can think of an analogy with a
mass of water flowing between two pipes with distinct diameters).</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">How does the linear extension scale factor work?</h3><a id="user-content-how-does-the-linear-extension-scale-factor-work" class="anchor" aria-label="Permalink: How does the linear extension scale factor work?" href="#how-does-the-linear-extension-scale-factor-work"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Each coral colony has a base growth <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$l_{\tau\sigma}$</math-renderer>, which is an increase in diameter.
This is referred to as the <em>linear extension</em> and depends on the colony's <code>FunctionalGroup</code>
and <code>SizeClass</code>. As the available space gets more populated, we assume that growth is
negatively affected, since there is a competition for resources. Even more, when there's no
available space left, we want the growth to be zero. To account for that, at each time step
we multiply all linear extensions by the same scale factor <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\gamma_t$</math-renderer>. This factor takes
into account not only the leftover space, but also the competition between different
<code>FunctionalGroup</code>s.</p>
<p dir="auto">First we calculate a <em>projected cover</em> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^P_t$</math-renderer>, assuming no space limitation nor
competition, using the linear extensions directly as growth rates. We also calculate an
upper bound for the projected cover, called <em>maximum projected cover</em> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^*$</math-renderer> assuming all
corals are in the last <code>SizeClass</code> of the <code>FunctionalGroup</code> with the highest linear
extension, and they growth freely. Two important notes here. First, there are infinite
possible upper bounds and, although the choice will affect the final scale factor, this
shouldn't change the final result drastically. Second, to prevent having to run a whole
timestep twice, for this <em>projected cover</em> (and other calculations related to the scale
factor) we instead use a simplified version of the model where each block moves by with a
constant velocity, even when changing <code>SizeClass</code>es.</p>
<p dir="auto">Next, we calculate an <em>adjusted projected cover</em> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^A_t$</math-renderer>:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
C^A_t = C_{t-1} + \frac{C^P_{t} - C_{t-1}}{C^*-C_{t-1}}\left(H - C_{t-1}\right)
\end{equation}
$$</math-renderer></p>
<p dir="auto">Where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$H$</math-renderer> is the habitable area, and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C_{t-1}$</math-renderer> is the cover on the previous timestep.
One can easily see that if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^P_{t} = C^*$</math-renderer>, we have <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^A_t = H$</math-renderer>. In other words, in the
worst case, the <em>adjusted projected cover</em> is equals the habitable area. For all other
values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^P_t$</math-renderer>, we have <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$C^A_t &amp;lt; H$</math-renderer>, which means that the <em>adjusted projected cover</em> will
never outgrow the habitable area.</p>
<p dir="auto">Lastly, we find the scale factor <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$\gamma_t$</math-renderer> that makes the <em>projected cover</em> equal to the
<em>adjusted projected cover</em>, assuming each <code>CoverBlock</code> growth rate is given by
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$l_{\tau\sigma} \gamma_t$</math-renderer> and the sum of all <code>CoverBlocks</code>. The actual growth rate
used to run a timestep <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$t$</math-renderer> is given by:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="436aa154fedfd34a150f15d5196764cf">$$
\begin{equation}
\omega_{\tau\sigma;t} = l_{\tau\sigma} \gamma_t
\end{equation}
$$</math-renderer></p>
