<p dir="auto"><a target="_blank" rel="noopener noreferrer nofollow" href="https://camo.githubusercontent.com/0623b88abd55bb660fdd610ab9a75c6cbb34a7abfd7a40da32e92f0654636f2a/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f6d6f7469766174696f6e2d7768792533462d627269676874677265656e"><img src="https://camo.githubusercontent.com/0623b88abd55bb660fdd610ab9a75c6cbb34a7abfd7a40da32e92f0654636f2a/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f6d6f7469766174696f6e2d7768792533462d627269676874677265656e" alt="" data-canonical-src="https://img.shields.io/badge/motivation-why%3F-brightgreen" style="max-width: 100%;"></a> There are multiple implementation of the piping concept in Julia: <a href="https://github.com/c42f/Underscores.jl">1</a>, <a href="https://github.com/jkrumbiegel/Chain.jl">2</a>, <a href="https://github.com/FNj/Hose.jl">3</a>, <a href="https://github.com/oxinabox/Pipe.jl">4</a>, maybe even more. <code>DataPipes</code> design is focused on usual data processing and analysis tasks. What makes <code>DataPipes</code> distinct from other packages is that it ticks all these points:</p>
<p dir="auto">✅ Gets rid of basically all boilerplate for common data processing functions:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@p tbl |&gt; filter(_.a &gt; 5) |&gt; map(_.b + _.c)"><pre><span class="pl-c1">@p</span> tbl <span class="pl-k">|&gt;</span> <span class="pl-c1">filter</span>(_<span class="pl-k">.</span>a <span class="pl-k">&gt;</span> <span class="pl-c1">5</span>) <span class="pl-k">|&gt;</span> <span class="pl-c1">map</span>(_<span class="pl-k">.</span>b <span class="pl-k">+</span> _<span class="pl-k">.</span>c)</pre></div>
<p dir="auto">✅ Can be inserted in as a step of a vanilla Julia pipeline without modifying the latter:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="tbl |&gt; sum  # before
tbl |&gt; @f(map(_ ^ 2) |&gt; filter(_ &gt; 5)) |&gt; sum  # after"><pre>tbl <span class="pl-k">|&gt;</span> sum  <span class="pl-c"><span class="pl-c">#</span> before</span>
tbl <span class="pl-k">|&gt;</span> <span class="pl-c1">@f</span>(<span class="pl-c1">map</span>(_ <span class="pl-k">^</span> <span class="pl-c1">2</span>) <span class="pl-k">|&gt;</span> <span class="pl-c1">filter</span>(_ <span class="pl-k">&gt;</span> <span class="pl-c1">5</span>)) <span class="pl-k">|&gt;</span> sum  <span class="pl-c"><span class="pl-c">#</span> after</span></pre></div>
<p dir="auto">✅ Can define a function transforming the data instead of immediately applying it</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="func = @f map(_ ^ 2) |&gt; filter(_ &gt; 5) |&gt; sum  # define func
func(tbl)  # apply it"><pre>func <span class="pl-k">=</span> <span class="pl-c1">@f</span> <span class="pl-c1">map</span>(_ <span class="pl-k">^</span> <span class="pl-c1">2</span>) <span class="pl-k">|&gt;</span> <span class="pl-c1">filter</span>(_ <span class="pl-k">&gt;</span> <span class="pl-c1">5</span>) <span class="pl-k">|&gt;</span> sum  <span class="pl-c"><span class="pl-c">#</span> define func</span>
<span class="pl-c1">func</span>(tbl)  <span class="pl-c"><span class="pl-c">#</span> apply it</span></pre></div>
<p dir="auto">✅ Supports easily exporting the result of an intermediate pipeline step</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@p let
    tbl
    @export tbl_filt = filter(_.a &gt; 5)  # export a single intermediate result
    map(_.b + _.c)
end

@p begin  # use begin instead of let to make all intermediate results available afterwards
    tbl
    tbl_filt = filter(_.a &gt; 5)
    map(_.b + _.c)
end

# tbl_filt is available here"><pre><span class="pl-c1">@p</span> <span class="pl-k">let</span>
    tbl
    <span class="pl-c1">@export</span> tbl_filt <span class="pl-k">=</span> <span class="pl-c1">filter</span>(_<span class="pl-k">.</span>a <span class="pl-k">&gt;</span> <span class="pl-c1">5</span>)  <span class="pl-c"><span class="pl-c">#</span> export a single intermediate result</span>
    <span class="pl-c1">map</span>(_<span class="pl-k">.</span>b <span class="pl-k">+</span> _<span class="pl-k">.</span>c)
<span class="pl-k">end</span>

<span class="pl-c1">@p</span> <span class="pl-k">begin</span>  <span class="pl-c"><span class="pl-c">#</span> use begin instead of let to make all intermediate results available afterwards</span>
    tbl
    tbl_filt <span class="pl-k">=</span> <span class="pl-c1">filter</span>(_<span class="pl-k">.</span>a <span class="pl-k">&gt;</span> <span class="pl-c1">5</span>)
    <span class="pl-c1">map</span>(_<span class="pl-k">.</span>b <span class="pl-k">+</span> _<span class="pl-k">.</span>c)
<span class="pl-k">end</span>

<span class="pl-c"><span class="pl-c">#</span> tbl_filt is available here</span></pre></div>
<p dir="auto">✅ Provides no-boilerplate nesting</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@p let
	&quot;a=1 b=2 c=3&quot;
	split
	map() do __  # `__` turns the inner function into a pipeline
		split(__, '=')
		Symbol(__[1]) =&gt; parse(Int, __[2])
	end
	NamedTuple
end  # == (a = 1, b = 2, c = 3)"><pre><span class="pl-c1">@p</span> <span class="pl-k">let</span>
	<span class="pl-s"><span class="pl-pds">"</span>a=1 b=2 c=3<span class="pl-pds">"</span></span>
	split
	<span class="pl-c1">map</span>() <span class="pl-k">do</span> __  <span class="pl-c"><span class="pl-c">#</span> `__` turns the inner function into a pipeline</span>
		<span class="pl-c1">split</span>(__, <span class="pl-s"><span class="pl-pds">'</span>=<span class="pl-pds">'</span></span>)
		<span class="pl-c1">Symbol</span>(__[<span class="pl-c1">1</span>]) <span class="pl-k">=&gt;</span> <span class="pl-c1">parse</span>(Int, __[<span class="pl-c1">2</span>])
	<span class="pl-k">end</span>
	NamedTuple
<span class="pl-k">end</span>  <span class="pl-c"><span class="pl-c">#</span> == (a = 1, b = 2, c = 3)</span></pre></div>
<p dir="auto">As demonstrated, <code>DataPipes</code> tries to minimally modify regular Julia syntax and stays fully composable both with other instruments <em>(vanilla pipelines)</em> and with itself <em>(nested pipes)</em>.</p>

<p dir="auto">Those design decisions make <code>DataPipes</code> convenient for both working with flat tabular data, and for processing nested structures. An example of the former:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@p begin
    tbl
    filter(!any(ismissing, _))
    filter(_.id &gt; 6)
    groupview(_.group)
    map(sum(_.age))
end"><pre><span class="pl-c1">@p</span> <span class="pl-k">begin</span>
    tbl
    <span class="pl-c1">filter</span>(<span class="pl-k">!</span><span class="pl-c1">any</span>(ismissing, _))
    <span class="pl-c1">filter</span>(_<span class="pl-k">.</span>id <span class="pl-k">&gt;</span> <span class="pl-c1">6</span>)
    <span class="pl-c1">groupview</span>(_<span class="pl-k">.</span>group)
    <span class="pl-c1">map</span>(<span class="pl-c1">sum</span>(_<span class="pl-k">.</span>age))
<span class="pl-k">end</span></pre></div>
