<p dir="auto">In <a href="https://doi.org/10.1016/j.compchemeng.2021.107413" rel="nofollow">our recent paper</a>, we presented a new approach for generating a guaranteed affine underestimator for a black-box convex function on a box domain, by tractable derivative-free sampling. Felix Bonhoff's master's thesis (RWTH Aachen, 2023) presented a variant of this approach that requires fewer samples.</p>
<p dir="auto">This repository provides a Julia implementation of our new sampling approach, tested in Julia v1.9. If you make use of this implementation in your own work, please cite the accompanying article:</p>
<blockquote>
<p dir="auto">Yingkai Song, Huiyi Cao, C. Mehta, and Kamil A. Khan, Bounding convex relaxations of process models from below by tractable
black-box sampling, <em>Computers &amp; Chemical Engineering</em>, <strong>153</strong>:107413 (2021). doi:10.1016/j.compchemeng.2021.107413</p>
</blockquote>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import Pkg; Pkg.add(url=&quot;https://github.com/kamilkhanlab/ConvexSampling.jl&quot;)"><pre><span class="pl-k">import</span> Pkg; Pkg<span class="pl-k">.</span><span class="pl-c1">add</span>(url<span class="pl-k">=</span><span class="pl-s"><span class="pl-pds">"</span>https://github.com/kamilkhanlab/ConvexSampling.jl<span class="pl-pds">"</span></span>)</pre></div>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Example</h2><a id="user-content-example" class="anchor" aria-label="Permalink: Example" href="#example"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Consider the following convex quadratic function <code>f</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using LinearAlgebra

A = [65.0 56.0; 56.0 65.0]
b = [6.0, 2.0]
c = 23.0

f(x) = dot(x, A, x) + dot(b, x) + c

xL = [-5.0, -3.0]
xU = [5.0, 3.0]"><pre><span class="pl-k">using</span> LinearAlgebra

A <span class="pl-k">=</span> [<span class="pl-c1">65.0</span> <span class="pl-c1">56.0</span>; <span class="pl-c1">56.0</span> <span class="pl-c1">65.0</span>]
b <span class="pl-k">=</span> [<span class="pl-c1">6.0</span>, <span class="pl-c1">2.0</span>]
c <span class="pl-k">=</span> <span class="pl-c1">23.0</span>

<span class="pl-en">f</span>(x) <span class="pl-k">=</span> <span class="pl-c1">dot</span>(x, A, x) <span class="pl-k">+</span> <span class="pl-c1">dot</span>(b, x) <span class="pl-k">+</span> c

xL <span class="pl-k">=</span> [<span class="pl-k">-</span><span class="pl-c1">5.0</span>, <span class="pl-k">-</span><span class="pl-c1">3.0</span>]
xU <span class="pl-k">=</span> [<span class="pl-c1">5.0</span>, <span class="pl-c1">3.0</span>]</pre></div>
<p dir="auto">on the box domain: <code>all(xL .&lt;= x .&lt;= xU)</code>. Suppose we wish to construct affine underestimators and/or lower bounds of <code>f</code> on its box domain.</p>
<ol dir="auto">
<li>
<p dir="auto">Once the package is installed, we can load its module:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using ConvexSampling"><pre><span class="pl-k">using</span> ConvexSampling</pre></div>
</li>
<li>
<p dir="auto">Now, <code>f</code> can be sampled at either 5 domain points using the approach of Song et al.:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="data = sample_convex_function(f, xL, xU; stencil=:compass)"><pre>data <span class="pl-k">=</span> <span class="pl-c1">sample_convex_function</span>(f, xL, xU; stencil<span class="pl-k">=</span><span class="pl-c1">:compass</span>)</pre></div>
<p dir="auto">or at 4 domain points using the approach of Bonhoff:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="data = sample_convex_function(f, xL, xU; stencil=:simplex)"><pre>data <span class="pl-k">=</span> <span class="pl-c1">sample_convex_function</span>(f, xL, xU; stencil<span class="pl-k">=</span><span class="pl-c1">:simplex</span>)</pre></div>
<p dir="auto">In general, for a function of <code>n</code> variables, <code>stencil=:compass</code> will sample this function <code>2n+1</code> times, while <code>stencil=:simplex</code> will sample it <code>n+2</code>    times, but may ultimately yield a looser relaxation.</p>
<p dir="auto">Our approach handles univariate and multivariate functions differently, so our implementation has Julia dispatch over <code>typeof(xL)</code>:</p>
<ul dir="auto">
<li>If <code>xL</code> is a <code>Float64</code>, then <code>f</code> must have the signature <code>f(x::Float64) -&gt; Float64</code>, and our univariate formulas will be applied. Any univariate function must be entered this way.</li>
<li>If <code>xL</code> is a <code>Vector{Float64}</code> with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$\geq 2$</math-renderer> components, then <code>f</code> must have the signature <code>f(x::Vector{Float64}) -&gt; Float64</code>, and our multivariate formulas will be applied.</li>
</ul>
<p dir="auto">Either way, <code>xU</code> must have the same type and number of components as <code>xL</code>.</p>
</li>
<li>
<p dir="auto">Using the sampled information, we can construct a guaranteed affine underestimator of <code>f</code> on its box domain:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="fAffine = construct_underestimator(data)"><pre>fAffine <span class="pl-k">=</span> <span class="pl-c1">construct_underestimator</span>(data)</pre></div>
<p dir="auto">The constructed function <code>fAffine</code> underestimates <code>f</code> on its box domain, so <code>fAffine(x) &lt;= f(x)</code> whenever <code>all(xL .&lt;= x .&lt;= xU)</code>. We can instead obtain       this underestimator as its constant coefficients:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="w0, b, c = evaluate_underestimator_coeffs(data)"><pre>w0, b, c <span class="pl-k">=</span> <span class="pl-c1">evaluate_underestimator_coeffs</span>(data)</pre></div>
<p dir="auto">in which case <code>fAffine(x) == c + dot(b, x - w0)</code> for all <code>x</code>.</p>
<p dir="auto">We can also evaluate a guaranteed lower bound of <code>f</code> on its box domain:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="fL = evaluate_lower_bound(data)"><pre>fL <span class="pl-k">=</span> <span class="pl-c1">evaluate_lower_bound</span>(data)</pre></div>
<p dir="auto">Then, we will have <code>f(x) &gt;= fL</code> for each <code>x</code> in the domain.</p>
</li>
<li>
<p dir="auto">The function <code>f</code> may be plotted with its sampling-based underestimator <code>fAffine</code> and lower bound <code>fL</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="graph = plot_underestimator(data, f)
@show graph"><pre>graph <span class="pl-k">=</span> <span class="pl-c1">plot_underestimator</span>(data, f)
<span class="pl-c1">@show</span> graph</pre></div>
<p dir="auto"><a target="_blank" rel="noopener noreferrer nofollow" href="https://user-images.githubusercontent.com/104848815/173203263-26bdc553-c1b5-496a-913f-eeb0553461d7.png"><img src="https://user-images.githubusercontent.com/104848815/173203263-26bdc553-c1b5-496a-913f-eeb0553461d7.png" alt="ConvexSampleplot" style="max-width: 100%;"></a></p>
<p dir="auto">Note that if the <code>plot_sampling_underestimator</code> function is entered directly in the REPL, the <code>@show</code> command is not required.</p>
</li>
</ol>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Method outline</h2><a id="user-content-method-outline" class="anchor" aria-label="Permalink: Method outline" href="#method-outline"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Suppose we have a convex function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$f$</math-renderer> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$n$</math-renderer> variables, defined on a box domain <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$X = [\mathbf{x}^L, \mathbf{x}^U]$</math-renderer>. Our <a href="https://doi.org/10.1016/j.compchemeng.2021.107413" rel="nofollow">new underestimating approach</a> samples <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$f$</math-renderer> at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$(2n+1)$</math-renderer> domain points: the midpoint of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$X,$</math-renderer> and perturbations of this midpoint in each positive/negative coordinate direction. These sampled values are then tractably assembled using new finite difference formulas to yield guaranteed affine underestimators and guaranteed lower bounds for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$f$</math-renderer> on <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$X.$</math-renderer> These underestimators are guaranteed by convex analysis theory; roughly, the sampled information is sufficient to infer a compact polyhedral set that encloses all subgradients of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$f$</math-renderer> at the midpoint of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$X.$</math-renderer> Using this information, we can deduce the "worst-case" convex functions that are consistent with the sampled data.</p>
<p dir="auto">As in our paper, this implementation also allows for absolute error in evaluating <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$f$</math-renderer>, and for off-center sampling stencils. When <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$n=1$</math-renderer>, we additionally exploit the fact that each domain point is collinear with all three sampled points.</p>
<p dir="auto">A newer procedure is implemented in Bonhoff's master's thesis (RWTH Aachen, 2023), requiring <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$(n+2)$</math-renderer> samples instead of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="c9bae9ba21e751d7c1a6a2a08c372d07">$(2n+1)$</math-renderer> samples.</p>
