<p dir="auto"><a href="https://en.wikipedia.org/wiki/REDCap" rel="nofollow">REDCap</a> is a data capture system for scientific research, especially clinical trials.
REDCap.jl is an API wrapper for REDCap v14, written in Julia.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Syntax</h2><a id="user-content-syntax" class="anchor" aria-label="Permalink: Syntax" href="#syntax"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Each REDCap method accepts a number of parameters that follow a shared naming convention.
REDCap.jl is designed to closely follow the design and syntax patterns of REDCap.
Every REDCap API method is available as a function that supplies certain required parameters and checks user inputs for validity.</p>
<p dir="auto">Return values and REDCap messages are returned as Strings directly, but the documentation shows how these can be parsed in useful ways.</p>
<p dir="auto">Function arguments are named after REDCap method parameters.
These are passed as named arguments and take values with intuitive types.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>token</code> and <code>url</code></h3><a id="user-content-token-and-url" class="anchor" aria-label="Permalink: token and url" href="#token-and-url"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Nearly all REDCap methods accept a token that is unique to the project and user.</p>
<p dir="auto">The URL must exactly match this example:
<code>https://example.example/redcap/api/</code></p>
<p dir="auto">Your REDCap token and your institution's REDCap API URL can be read by default from Julia's environment variables.
You can make them avaiable to REDCap.jl by putting the following lines in <a href="https://docs.julialang.org/en/v1/manual/command-line-interface/#Startup-file" rel="nofollow">your local Julia startup file</a> (probably <code>~/.julia/config/startup.jl</code>):</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="ENV[&quot;REDCAP_API_TOKEN&quot;] = &quot;C0FFEEC0AC0AC0DEC0FFEEC0AC0AC0DE&quot;

<p dir="auto">They can also be passed as ordinary named arguments.</p>
<p dir="auto">A few methods accept a super token, including <code>create_project</code>, which can be used to generate a project and project-level token.
If you have a super token, you might wish to keep that in your startup file, generating and saving project-level tokens as needed.</p>

<p dir="auto">The <code>data</code> parameter contains a list of attributes.
In REDCap.jl, this can be a NamedTuple (or any derived type), a file handle, or a String.
If you use a NamedTuple, it will be translated internally into whatever <code>format</code> you use (xml by default).</p>

<p dir="auto">As for collections, only collections of scalar entries are currently supported.
So, a list of attributes and values is accepted, but a Dict containing multiple rows per column can only be read in from a file.</p>
<p dir="auto">In the REDCap API, the presence of a <code>data</code> parameter often changes the behavior of a method.
For instance, most import methods are implemented as an export method with an added data parameter.
In REDCap.jl, it would be considered a bug for <code>import_project_data</code> to ever act as <code>export_project_data</code>, so the data paramater is almost always required where it is present.</p>

<p dir="auto">Supported options are <code>:csv</code>, <code>:json</code>, <code>:xml</code> (the default value), and sometimes <code>:odm</code>.
These values can be passed as Strings or Symbols.</p>
<p dir="auto">Generally, the <code>format</code> parameter designates user input and the <code>returnFormat</code> parameter applies to REDCap messages and return values.
However, this is not consistent within REDCap.
REDCap.jl functions are designed to not accept any parameters that have no effect on the result.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>content</code> and <code>action</code></h3><a id="user-content-content-and-action" class="anchor" aria-label="Permalink: content and action" href="#content-and-action"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <code>content</code> and <code>action</code> parameters are what define each REDCap method, for the most part.
In REDCap.jl, these are passed internally and don't need to be supplied by the user.
Instead, they're fixed for each function.</p>

<p dir="auto">If a function call doesn't produce the expected results, try making debug messages visible for this package by running <code>ENV["JULIA_DEBUG"] = REDCap</code>.
The data parameter is converted to a formatted string, so you might try different format parameters (<code>:csv</code>, <code>:json</code>, or <code>:xml</code>).
Feel free to create an issue for any unexpected errors, or for feature requests.</p>
