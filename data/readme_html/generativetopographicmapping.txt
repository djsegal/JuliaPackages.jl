<p dir="auto">A Julia package for Generative Topographic Mapping originally introduced by <a href="https://www.microsoft.com/en-us/research/wp-content/uploads/1998/01/bishop-gtm-ncomp-98.pdf" rel="nofollow">Bishop and Svensen</a> with inspiration from the <a href="https://ugtm.readthedocs.io/en/latest/overview.html" rel="nofollow">UGTM</a> python package. This implementation provides wrappers for use withing the MLJ framework.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Using the package</h1><a id="user-content-using-the-package" class="anchor" aria-label="Permalink: Using the package" href="#using-the-package"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To train a GTM model first load MLJ and this package.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using MLJ, GenerativeTopographicMapping"><pre><span class="pl-k">using</span> MLJ, GenerativeTopographicMapping</pre></div>
<p dir="auto">The GTM can then be instantiated in the usual way for an unsupervised method:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="gtm = GTM()
mach = machine(gtm, df)
fit!(mach)"><pre>gtm <span class="pl-k">=</span> <span class="pl-c1">GTM</span>()
mach <span class="pl-k">=</span> <span class="pl-c1">machine</span>(gtm, df)
<span class="pl-c1">fit!</span>(mach)</pre></div>
<p dir="auto">Calling <code>fitted_params</code> on the trained machine will return a tuple holding the underlying <code>gtm</code> struct if further inspection is desired.</p>
<p dir="auto">The GTM model learns a transformation from a latent space of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="7019ed7f7acc8aebe17442b9538786b8">$k\times k$</math-renderer> nodes. The result is a set of responsibilities for each latent node. By computing the mean of this distribution for each record, we can use the GTM as a nonlinear dimensionality reduction scheme</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="means = MLJ.transform(mach, X)"><pre>means <span class="pl-k">=</span> MLJ<span class="pl-k">.</span><span class="pl-c1">transform</span>(mach, X)</pre></div>
<p dir="auto">Alternatively, the GTM can be viewed as performing an unsupervised classification into <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="7019ed7f7acc8aebe17442b9538786b8">$k\times k$</math-renderer> classes. The class label for each record can be obtained as the index of the node corresponding to the node of the responsibility distribution via</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="class_label = MLJ.predict(mach, X)"><pre>class_label <span class="pl-k">=</span> MLJ<span class="pl-k">.</span><span class="pl-c1">predict</span>(mach, X)</pre></div>
<p dir="auto">If the full responsibility distribution is desired, you can <code>predict_responsability</code> on the trained machine</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="R = predict_responsibility(mach, X)"><pre>R <span class="pl-k">=</span> <span class="pl-c1">predict_responsibility</span>(mach, X)</pre></div>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">GSM</h1><a id="user-content-gsm" class="anchor" aria-label="Permalink: GSM" href="#gsm"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The GSM (Generative Simplex Mapping) is a riff on the GTM structure designed for unmixing problems. The latent space is chosen to be the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="7019ed7f7acc8aebe17442b9538786b8">$n$</math-renderer>-simplex corresponding to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="7019ed7f7acc8aebe17442b9538786b8">$n$</math-renderer> unique sources. Additionally, model weights can optionally be constrained to positive values for source apportionment or spectral unmixing applications. The following MLJ-style syntax can be used to initialize and fit a GSM.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="gsm = GSM()
mach = machine(gsm, df)
fit!(mach)"><pre>gsm <span class="pl-k">=</span> <span class="pl-c1">GSM</span>()
mach <span class="pl-k">=</span> <span class="pl-c1">machine</span>(gsm, df)
<span class="pl-c1">fit!</span>(mach)</pre></div>
