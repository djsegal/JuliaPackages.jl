<p dir="auto">This package introduces a high performance Julia implementation of the parcellation method presented originally in Tim Laumann and Evan Gordon's 2016 paper <a href="https://pubmed.ncbi.nlm.nih.gov/25316338/" rel="nofollow">"Generation and Evaluation of a Cortical Area Parcellation from Resting-State Correlations."</a>, and based on their original MATLAB code. It builds upon recently registered packages <a href="https://github.com/myersm0/CIFTI.jl">CIFTI.jl</a>, <a href="https://github.com/myersm0/CorticalSurfaces.jl">CorticalSurfaces.jl</a>, and <a href="https://github.com/myersm0/CorticalParcels.jl">CorticalParcels.jl</a>.</p>
<p dir="auto">Our own new results from this method, a neonatal parcellation generated from a dataset of 261 subjects, can be found <a href="https://github.com/myersm0/Myers-Labonte_parcellation">here</a>. The paper pre-print is available <a href="https://www.biorxiv.org/content/10.1101/2023.11.10.566629v1" rel="nofollow">here</a>.</p>
<p dir="auto">The goals of this package are:</p>
<ul dir="auto">
<li>Improve accessibility of this parcellation method to other researchers by:
<ul dir="auto">
<li>Implementing it with open source tools</li>
<li>Substantially improving the execution speed</li>
<li>Bringing RAM usage under control (&lt;= 32 GB)</li>
<li>Breaking the method into modular, customizable pieces that encourage further experimentation and improvement</li>
</ul>
</li>
<li>Extend the Julia language's ecosystem of fMRI-related packages</li>
<li>Demonstrate utility of a framework of operations (laid out in <a href="https://github.com/myersm0/CorticalSurfaces.jl">CorticalSurfaces.jl</a> and <a href="https://github.com/myersm0/CorticalParcels.jl">CorticalParcels.jl</a>) for more easily and efficiently working with spatial and functional neuroimaging data in conjunction</li>
</ul>

<p dir="auto">The method requires handling several large matrices. To generate and evaluate a bilateral parcellational of the cortical surface in a space of 64,000 vertices:</p>
<ul dir="auto">
<li>32 GB RAM</li>
<li>4 to 8 CPU cores (recommended)</li>
<li>Julia &gt;= v1.9</li>
</ul>
<p dir="auto">For working with a single-hemisphere only, you should be able to reduce the RAM usage to 12 GB.</p>

<p dir="auto">Now that we've made a parcellation, we want to test the method's effectiveness by evaluating the homogeneity of its parcels, relative to a null distribution of 1000 randomly rotated versions of the same parcellation.</p>
<p dir="auto">First, to get the randomly rotated parcellations to be used for null model testing:</p>

<p dir="auto">Now use it to test the parcel homogeneity of the real parcellation and of the 1000 rotations:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="real_homogeneity = homogeneity_test(px, cov_corr; criteria = p -&gt; default_criteria(p))

<p dir="auto">Notice the keyword arg for which we're passing <code>p -&gt; default_criteria(p)</code>. This is one of the strenghts of the current implementation: instead of the supplied <code>default_criteria</code> function, you could pass in a function specifying your own parcel inclusion criteria, possibly involving other objects in your workspace such as a map of low-signal regions that you want to exclude. Then, in any individual parcel undergoing a homogeneity test, upon receiving a <code>false</code> return value from this criteria function the result will be <code>NaN</code> and a homogeneity score will not be calculated. This is in order to exclude calculation of homogeneity for parcels that overlap with the medial wall, at a minimum, since functional measures (and therefore homogeneity) will not be defined within the medial wall, or to impose a minimum parcel size criterion, etc. See the full demo for more details.</p>
<p dir="auto">Finally, compare the real and the rotated results (null model) by taking the mean homogoneity of the real parcellation minus the mean of the same from all rotated parcellations, divided by the standard deviation of homogeneity from the rotated parcellations, to get a z-score:</p>
