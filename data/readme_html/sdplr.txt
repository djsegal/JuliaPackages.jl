<p dir="auto"><a href="https://github.com/blegat/SDPLR.jl">SDPLR.jl</a> is a wrapper for the
<a href="https://github.com/sburer/sdplr">SDPLR</a> semidefinite programming solver.</p>

<p dir="auto">The following attributes can be also be used both with <code>JuMP.set_attributes</code> and <code>JuMP.get_attributes</code>, but they are also
modified by <code>optimize!</code>:</p>
<ul dir="auto">
<li><code>majiter</code></li>
<li><code>iter</code></li>
<li><code>lambdaupdate</code></li>
<li><code>totaltime</code></li>
<li><code>sigma</code></li>
</ul>
<p dir="auto">When they are <code>set</code>, it provides the initial value of the algorithm.
With <code>get</code>, they provide the value at the end of the algorithm.
<code>totaltime</code> is the total time in second. For the other attributes,
their meaning is best described by the following pseudo-code.</p>
<p dir="auto">Given values of <code>R</code>, <code>lambda</code> and <code>sigma</code>, let
<code>vio = [dot(A[i], R * R') - b[i]) for i in 1:m]</code> (<code>vio[0]</code> is <code>dot(C, R * R')</code> in the C implementation, but we ignore this entry here),
<code>val = dot(C, R * R') - dot(vio, lambda) + sigma/2 * norm(vio)^2</code>,
<code>y = -lambda - sigma * vio</code>,
<code>S = C + sum(A[i] * y[i] for i in 1:m)</code> and
the gradient is <code>G = 2S * R</code>.
Note that <code>norm(G)</code> used in SDPLR when comparing with <code>rho_c</code> which has a 2-scaling difference
from <code>norm(S * R)</code> used in the paper.</p>
