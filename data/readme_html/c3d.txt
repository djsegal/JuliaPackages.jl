<p dir="auto">C3D is a common file format for motion capture and other biomechanics related measurement
systems (force plate data, EMG, etc). This package completely implements the <a href="https://www.c3d.org" rel="nofollow">C3D file
spec</a>, and can read files from all major manufacturers where they might
differ from or extend the C3D file spec.</p>
<p dir="auto">C3D.jl is exhaustively tested against sample data found on the <a href="https://www.c3d.org/sampledata.html" rel="nofollow">C3D
website</a> and can read many technically out-of-spec
files.
Please open an issue if you have a file that is not being read correctly. Pull requests welcome!</p>

<p dir="auto">Write a C3D file using the <code>writec3d</code> function. The groups and parameters of a .c3d file
describe the data contained by the file. As of v0.8, there are no C3D.jl functions that
coordinate modifying a <code>C3DFile</code> object, therefore, it is your responsibility to ensure that
any modifications (adding/removing a marker or analog channel, etc) produce a
internally-consistent (i.e. groups/parameters have been correctly updated to match the
modified data, etc) file before writing.</p>

<p dir="auto">Writing c3d files is exhaustively tested against the corpus of sample data from the C3D.org
website, and <code>writec3d</code> is tested to ensure that all files that are written are
functionally<sup><a href="#user-content-fn-1-aa24e4ab6b7f8931a5ecab779ca72f81" id="user-content-fnref-1-aa24e4ab6b7f8931a5ecab779ca72f81" data-footnote-ref="" aria-describedby="footnote-label">1</a></sup> and/or bitwise identical to the original at the binary file level in the
vast majority<sup><a href="#user-content-fn-2-aa24e4ab6b7f8931a5ecab779ca72f81" id="user-content-fnref-2-aa24e4ab6b7f8931a5ecab779ca72f81" data-footnote-ref="" aria-describedby="footnote-label">2</a></sup> of cases, and in all cases, the groups, parameters, and data for a
<code>C3DFile</code> that was "copied" with <code>writec3d</code> will be exactly identical to the groups,
parameters, and data from the original <code>C3DFile</code>.</p>

<p dir="auto">According to the C3D format documentation, invalid data points are signified by setting the
residual word to <code>-1.0</code>. This convention is respected in C3D.jl by changing the residual and
coordinates of invalid points/frames to <code>missing</code>. If your C3D files do not respect this
convention, or if you wish to ignore this for some other reason, this behavior can be
disabled by setting keyword arg <code>missingpoints=false</code> in the <code>readc3d</code> function. Convention
is to signify calculated points (e.g. filtered, interpolated, etc) by setting the residual
value to <code>0.0</code>.</p>
