<p dir="auto"><code>NearestNeighbors.jl</code> is a Julia package for performing nearest neighbor searches.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Creating a Tree</h2><a id="user-content-creating-a-tree" class="anchor" aria-label="Permalink: Creating a Tree" href="#creating-a-tree"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There are currently three types of trees available:</p>
<ul dir="auto">
<li><code>KDTree</code>: Recursively splits points into groups using hyper-planes.</li>
<li><code>BallTree</code>: Recursively splits points into groups bounded by hyper-spheres.</li>
<li><code>BruteTree</code>: Not actually a tree. It linearly searches all points in a brute force manner.</li>
</ul>
<p dir="auto">These trees can be created using the following syntax:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="KDTree(data, metric; leafsize, reorder)
BallTree(data, metric; leafsize, reorder)
BruteTree(data, metric; leafsize, reorder) # leafsize and reorder are unused for BruteTree
"><pre><span class="pl-c1">KDTree</span>(data, metric; leafsize, reorder)
<span class="pl-c1">BallTree</span>(data, metric; leafsize, reorder)
<span class="pl-c1">BruteTree</span>(data, metric; leafsize, reorder) <span class="pl-c"><span class="pl-c">#</span> leafsize and reorder are unused for BruteTree</span>
</pre></div>
<ul dir="auto">
<li><code>data</code>: The points to build the tree from, either as
<ul dir="auto">
<li>A matrix of size <code>nd × np</code> where <code>nd</code> is the dimensionality and <code>np</code> is the number of points, or</li>
<li>A vector of vectors with fixed dimensionality <code>nd</code>, i.e., <code>data</code> should be a <code>Vector{V}</code> where <code>V</code> is a subtype of <code>AbstractVector</code> with defined <code>length(V)</code>. For example a <code>Vector{V}</code> where <code>V = SVector{3, Float64}</code> is ok because <code>length(V) = 3</code> is defined.</li>
</ul>
</li>
<li><code>metric</code>: The <code>Metric</code> (from <code>Distances.jl</code>) to use, defaults to <code>Euclidean</code>. <code>KDTree</code> works with axis-aligned metrics: <code>Euclidean</code>, <code>Chebyshev</code>, <code>Minkowski</code>, and <code>Cityblock</code> while for <code>BallTree</code> and <code>BruteTree</code> other pre-defined <code>Metric</code>s can be used as well as custom metrics (that are subtypes of <code>Metric</code>).</li>
<li><code>leafsize</code>: Determines the number of points (default 10) at which to stop splitting the tree. There is a trade-off between tree traversal and evaluating the metric for an increasing number of points.</li>
<li><code>reorder</code>: If <code>true</code> (default), during tree construction this rearranges points to improve cache locality during querying. This will create a copy of the original data.</li>
</ul>
<p dir="auto">All trees in <code>NearestNeighbors.jl</code> are static, meaning points cannot be added or removed after creation.
Note that this package is not suitable for very high dimensional points due to high compilation time and inefficient queries on the trees.</p>
<p dir="auto">Example of creating trees:</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">k-Nearest Neighbor (kNN) Searches</h2><a id="user-content-k-nearest-neighbor-knn-searches" class="anchor" aria-label="Permalink: k-Nearest Neighbor (kNN) Searches" href="#k-nearest-neighbor-knn-searches"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A kNN search finds the <code>k</code> nearest neighbors to a given point or points. This is done with the methods:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="knn(tree, point[s], k, skip = always_false) -&gt; idxs, dists
knn!(idxs, dists, tree, point, k, skip = always_false)"><pre><span class="pl-c1">knn</span>(tree, point[s], k, skip <span class="pl-k">=</span> always_false) <span class="pl-k">-&gt;</span> idxs, dists
<span class="pl-c1">knn!</span>(idxs, dists, tree, point, k, skip <span class="pl-k">=</span> always_false)</pre></div>
<ul dir="auto">
<li><code>tree</code>: The tree instance.</li>
<li><code>points</code>: A vector or matrix of points to find the <code>k</code> nearest neighbors for. A vector of numbers represents a single point; a matrix means the <code>k</code> nearest neighbors for each point (column) will be computed. <code>points</code> can also be a vector of vectors.</li>
<li><code>skip</code> (optional): A predicate to skip certain points, e.g., points already visited.</li>
</ul>
<p dir="auto">For the single closest neighbor, you can use <code>nn</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="nn(tree, points, skip = always_false) -&gt; idxs, dists"><pre><span class="pl-c1">nn</span>(tree, points, skip <span class="pl-k">=</span> always_false) <span class="pl-k">-&gt;</span> idxs, dists</pre></div>

<p dir="auto">By default, trees store a copy of the <code>data</code> provided during construction. For data sets larger than available memory, <code>DataFreeTree</code> can be used to strip a tree of its data field and re-link it later.</p>
