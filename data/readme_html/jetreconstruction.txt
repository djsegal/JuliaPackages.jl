<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Algorithms</h3><a id="user-content-algorithms" class="anchor" aria-label="Permalink: Algorithms" href="#algorithms"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Algorithms used are based on the C++ FastJet package (<a href="https://fastjet.fr" rel="nofollow">https://fastjet.fr</a>,
<a href="https://arxiv.org/abs/hep-ph/0512210" rel="nofollow">hep-ph/0512210</a>,
<a href="https://arxiv.org/abs/1111.6097" rel="nofollow">arXiv:1111.6097</a>), reimplemented natively in Julia.</p>
<p dir="auto">The algorithms include anti-<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">${k}_\text{T}$</math-renderer>, Cambridge/Aachen, inclusive
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer>, generalised <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer> for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$pp$</math-renderer> events; and the Durham
algorithm and generalised <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer> for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$e^+e^-$</math-renderer>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Interface</h3><a id="user-content-interface" class="anchor" aria-label="Permalink: Interface" href="#interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The simplest interface is to call:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cs = jet_reconstruct(particles::Vector{T}; algorithm = JetAlgorithm.AntiKt, R = 1.0, [p = -1,] [recombine = +,] [strategy = RecoStrategy.Best])"><pre>cs <span class="pl-k">=</span> <span class="pl-c1">jet_reconstruct</span>(particles<span class="pl-k">::</span><span class="pl-c1">Vector{T}</span>; algorithm <span class="pl-k">=</span> JetAlgorithm<span class="pl-k">.</span>AntiKt, R <span class="pl-k">=</span> <span class="pl-c1">1.0</span>, [p <span class="pl-k">=</span> <span class="pl-k">-</span><span class="pl-c1">1</span>,] [recombine <span class="pl-k">=</span> <span class="pl-k">+</span>,] [strategy <span class="pl-k">=</span> RecoStrategy<span class="pl-k">.</span>Best])</pre></div>
<ul dir="auto">
<li>
<code>particles</code> - a vector of input particles for the clustering
<ul dir="auto">
<li>Any type that supplies the methods <code>pt2()</code>, <code>phi()</code>, <code>rapidity()</code>, <code>px()</code>, <code>py()</code>, <code>pz()</code>, <code>energy()</code> can be used</li>
<li>These methods have to be defined in the namespace of this package, i.e., <code>JetReconstruction.pt2(::T)</code>
</li>
<li>The <code>PseudoJet</code> type from this package, or a 4-vector from <code>LorentzVectorHEP</code> are suitable (and have the appropriate definitions)</li>
</ul>
</li>
<li>
<code>algorithm</code> is the name of the jet algorithm to be used (from the <code>JetAlgorithm</code> enum)
<ul dir="auto">
<li>
<code>JetAlgorithm.AntiKt</code> anti-<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">${k}_\text{T}$</math-renderer> clustering (default)</li>
<li>
<code>JetAlgorithm.CA</code> Cambridge/Aachen clustering</li>
<li>
<code>JetAlgorithm.Kt</code> inclusive <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer>
</li>
<li>
<code>JetAlgorithm.GenKt</code> generalised <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer> (which also requires specification of <code>p</code>)</li>
<li>
<code>JetAlgorithm.Durham</code> the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$e^+e-$</math-renderer> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer> algorithm, also known as the Durham algorithm</li>
<li>
<code>JetAlgorithm.EEKt</code> the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$e^+e-$</math-renderer> generalised <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer> algorithm</li>
</ul>
</li>
<li>
<code>R</code> - the cone size parameter; no particles more geometrically distance than <code>R</code> will be merged (default 1.0; note this parameter is ignored for the Durham algorithm)</li>
<li>
<code>recombine</code> - the function used to merge two pseudojets (default is a simple 4-vector addition of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$(E, \mathbf{p})$</math-renderer>)</li>
<li>
<code>strategy</code> - the algorithm strategy to adopt, as described below (default <code>RecoStrategy.Best</code>)</li>
</ul>
<p dir="auto">The object returned is a <code>ClusterSequence</code>, which internally tracks all merge steps.</p>
<p dir="auto">Alternatively, <em>for pp reconstruction</em>, one can swap the <code>algorithm=...</code>
parameter for the value of <code>p</code>, the transverse momentum power used in the
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$d_{ij}$</math-renderer> metric for deciding on closest jets, as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k^{2p}_\text{T}$</math-renderer>. Different
values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$p$</math-renderer> then correspond to different reconstruction algorithms:</p>
<ul dir="auto">
<li>
<code>-1</code> gives anti-<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">${k}_\text{T}$</math-renderer> clustering (default)</li>
<li>
<code>0</code> gives Cambridge/Aachen</li>
<li>
<code>1</code> gives inclusive <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$k_\text{T}$</math-renderer>
</li>
</ul>
<p dir="auto">Note, for the <code>GenKt</code> and <code>EEKt</code> algorithms the <code>p</code> value <em>must</em> also be given to specify the algorithm fully.</p>
<p dir="auto">To obtain the final inclusive jets, use the <code>inclusive_jets</code> method:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="final_jets = inclusive_jets(cs::ClusterSequence; ptmin=0.0)"><pre>final_jets <span class="pl-k">=</span> <span class="pl-c1">inclusive_jets</span>(cs<span class="pl-k">::</span><span class="pl-c1">ClusterSequence</span>; ptmin<span class="pl-k">=</span><span class="pl-c1">0.0</span>)</pre></div>
<p dir="auto">Only jets passing the cut <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$p_T &amp;gt; p_{Tmin}$</math-renderer> will be returned. The result is returned as a <code>Vector{LorentzVectorHEP}</code>.</p>

<p dir="auto">As sorting vectors is trivial in Julia, no special sorting methods are provided. As an example, to sort exclusive jets of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e444050a33160914d8fcbf0eb76bd0a4">$&amp;gt;5.0$</math-renderer> (usually GeV, depending on your EDM) from highest energy to lowest:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="sorted_jets = sort!(inclusive_jets(cs::ClusterSequence; ptmin=5.0), by=JetReconstruction.energy, rev=true)"><pre>sorted_jets <span class="pl-k">=</span> <span class="pl-c1">sort!</span>(<span class="pl-c1">inclusive_jets</span>(cs<span class="pl-k">::</span><span class="pl-c1">ClusterSequence</span>; ptmin<span class="pl-k">=</span><span class="pl-c1">5.0</span>), by<span class="pl-k">=</span>JetReconstruction<span class="pl-k">.</span>energy, rev<span class="pl-k">=</span><span class="pl-c1">true</span>)</pre></div>

<p dir="auto">Generally one can use the <code>jet_reconstruct</code> interface, shown above, as the <em>Best</em> strategy safely as the overhead is extremely low. That interface supports a <code>strategy</code> option to switch to a different option.</p>
<p dir="auto">Another option, if one wishes to use a specific strategy, is to call that strategy's interface directly, e.g.,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# For N2Plain strategy called directly

<p dir="auto">Note that there is no <code>strategy</code> option in these interfaces.</p>

<p dir="auto">In the examples directory there are a number of example scripts.</p>
<p dir="auto">See the <code>jetreco.jl</code> script for an example of how to call jet reconstruction.</p>

<p dir="auto">There are options to explicitly set the algorithm (use <code>--help</code> to see these).</p>
<p dir="auto">The example also shows how to use <code>JetReconstruction.HepMC3</code> to read HepMC3
ASCII files (via the <code>read_final_state_particles()</code> wrapper).</p>
<p dir="auto">Further examples, which show visualisation, timing measurements, profiling, etc.
are given - see the <code>README.md</code> file in the examples directory.</p>
<p dir="auto">Note that due to additional dependencies the <code>Project.toml</code> file for the
examples is different from the package itself.</p>
