<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Callbacks on messages or connection/disconnection</h3><a id="user-content-callbacks-on-messages-or-connectiondisconnection" class="anchor" aria-label="Permalink: Callbacks on messages or connection/disconnection" href="#callbacks-on-messages-or-connectiondisconnection"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">While the mosquitto C library requires callback functions, this package uses Channels to indicate the receiving of a message or the connection/disconnection to/from a broker. You should <code>take!(channel)</code> on these, possibly after checking for the number of available messages if not run in a separate thread. Each client contains 3 channels (one is reserved for internal use) of which the 2 important ones can be accessed via:</p>
<ul dir="auto">
<li><code>get_messages_channel(client)</code></li>
<li><code>get_connect_channel(client)</code></li>
</ul>
<p dir="auto">To awaid blocking when channels are full due to too many messages, the channels can be treated similar as circular buffers, i.e., first item is removed if the channel is full and a new item is pushed. The options to activate this behavior are keyword options of the Client constructor</p>
<ul dir="auto">
<li><code>autocleanse_message_channel</code></li>
<li><code>autocleanse_connect_channel</code></li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Running the loop continuously</h3><a id="user-content-running-the-loop-continuously" class="anchor" aria-label="Permalink: Running the loop continuously" href="#running-the-loop-continuously"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The network loop needs to be called continuously in order to send receive messages. The simplest way to do this
is to call the <em>loop(client)</em> function regularly.</p>
<p dir="auto">As a first alternative, the functions <em>loop_start(client)</em> and <em>loop_stop(client)</em> can be called to handle this in another C-thread.</p>
<p dir="auto">As a second alternative, the mosquitto library provides a <em>Mosquitto.loop_forever(client)</em> function that is wrapped as well. This background task will run until <em>disconnect(client)</em> is called and then return. As such, the message and connect events should be handled in an @async task. For an example usage, see <a href="examples/07_loop_forever.jl">examples/07_loop_forever.jl</a>. Due to reports of instability, it is recommended to use <em>loop(client)</em> instead of <em>Mosquitto.loop_forever(client)</em>.</p>

<p dir="auto">Instead of creating a <code>Client</code> object, create a <code>Client_v5</code> object. Most functions like <code>publish</code>, <code>subscribe</code>, <code>loop</code> etc are overloaded to work the same way as for the v3.1.1 client, except some of them accept an optional keyword argument <code>properties</code>.
This keyword argument can be set to a <code>PropertyList</code>. See the example <a href="examples/09_MQTT5_properties.jl">examples/09_MQTT5_properties.jl</a> for an example on how to use properties, or consult <code>?PropertyList</code>.</p>

# Different from the previous example, the client will resubscribe to its topic every time it connects to the broker
using Mosquitto

# Connect to a broker using tls and username/password authetication.
# The CA certificate can be downloaded from the mosquitto page https://test.mosquitto.org/ssl/mosquitto.org.crt
# The connect function must be used only after tls_set.
client = Client(; id = &quot;JuliaClient1&quot;)
const cafilepath = &quot;...&quot; # add path to ca certificate here
tls_set(client, cafilepath)
connect(client, &quot;test.mosquitto.org&quot;, 8885; username = &quot;rw&quot;, password = &quot;readwrite&quot;)


# Subscribe to topic &quot;test&quot; every time the client connects
# To know if there was a connection/disconnection, the channel
# get_connect_channel(client) is used.
function onconnect(c)
    nmessages = 0

    # Treat all events
    while !isempty(get_connect_channel(c))
        conncb = take!(get_connect_channel(c))
        nmessages += 1
        if conncb.val == 1
            println(&quot;Connection of client $(client.id) successfull, subscribing to test/#&quot;)
            subscribe(c, &quot;test/#&quot;)
        elseif conncb.val == 0
            println(&quot;Client $(client.id) disconnected&quot;)
        end
    end
    return nmessages
end


# Print a message if it is received.
# To know if a message was received, we check
# the channel msg_channel = get_messages_channel(client).
function onmessage(mrcount, client)
    nmessages = 0
    msg_channel = get_messages_channel(client)

    # At this point, a message was received, lets process it
    while !isempty(msg_channel)
        temp = take!(msg_channel)
        nmessages += 1
        println(&quot;Message $(mrcount+nmessages):&quot;)
        message = String(temp.payload)
        length(message) &gt; 20 &amp;&amp; (message = message[1:18]*&quot;...&quot;)
        println(&quot;\ttopic: $(temp.topic)\tmessage:$(message)&quot;)
    end
    return nmessages
end


function main()
    # We trigger the loop manually until we have received at least
    # 20 messages
    mrcount = 0
    while mrcount &lt; 20
        loop(client) # network loop
        onconnect(client) # check for connection/disconnection
        mrcount += onmessage(mrcount, client) # check for messages
    end

    # Disconnect the client
    disconnect(client)
    loop(client)
end
