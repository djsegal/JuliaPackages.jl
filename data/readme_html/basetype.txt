<p dir="auto">This package currently exports a tiny function <code>base_numeric_type</code> that
extracts the base numeric type from a numeric type <code>T</code>:</p>
<ul dir="auto">
<li><code>base_numeric_type(::Type{T}) where {T}</code></li>
<li><code>base_numeric_type(x::T)</code></li>
</ul>

<p dir="auto">Package maintainers should write a specialized method for their type.
For example, to define the base numeric type for a dual number, one could write:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import BaseType: base_numeric_type

base_numeric_type(::Type{Dual{T}}) where {T} = base_numeric_type(T)"><pre><span class="pl-k">import</span> BaseType<span class="pl-k">:</span> base_numeric_type

<span class="pl-en">base_numeric_type</span>(<span class="pl-k">::</span><span class="pl-c1">Type{Dual{T}}</span>) <span class="pl-k">where</span> {T} <span class="pl-k">=</span> <span class="pl-c1">base_numeric_type</span>(T)</pre></div>
<p dir="auto">It is important to call <code>base_numeric_type</code> recursively like this to deal with
nested numeric types such as <code>Quantity{Measurement{T}}</code>.</p>
<p dir="auto">The fallback behavior of <code>base_numeric_type</code> is to return the <em>first</em> type parameter,
or, if that type has parameters of its own (such as <code>Dual{Complex{Float32}}</code>),
to recursively take the first type parameter until a non-parameterized type is found.
This works for the vast majority of types, but it is still preferred
if package maintainers write a specialized method.</p>
