<p dir="auto">ProgressTMap provides a map function that will spread the workload evenly across all available threads. Via <a href="https://github.com/JuliaLogging/ProgressLogging.jl">ProgressLogging.jl</a>, progress events are emitted as each thread completes its task. These events can be displayed in the VSCode status bar via the <a href="https://github.com/julia-vscode/julia-vscode/">Julia VSCode extension</a> or as a progress bar in the Julia REPL via the <a href="https://github.com/JuliaLogging/TerminalLoggers.jl">TerminalLoggers.jl</a> package.</p>

<p dir="auto">Say we have a costly function <code>f</code> that we want to compute using all available threads on our machine. Luckily evaluations of <code>f</code> are independent of each other, so we can don't have any requirement on the of calls of <code>f</code>. Using this package, we can multithread this computation as follows.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using ProgressTMap

f(t) = sleep(t)  # example slow function

ts = 1:100

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">How it works</h2><a id="user-content-how-it-works" class="anchor" aria-label="Permalink: How it works" href="#how-it-works"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The function divides the input into <code>n</code> even chunks, where <code>n</code> is the number of threads the julia worker is started with (<code>Threads.nthreads()</code>). This is done with the <a href="https://github.com/JuliaFolds2/ChunkSplitters.jl">ChunkSplitters.jl</a> package. <sup><a href="#user-content-fn-1-bb875d03c617561b682953c7ae8e79d6" id="user-content-fnref-1-bb875d03c617561b682953c7ae8e79d6" data-footnote-ref="" aria-describedby="footnote-label">1</a></sup> For each chunk, a new <code>Task</code> is spawned, on which the function is broadcasted over the chunk. The results of each task are then combined at the end and returned.</p>
