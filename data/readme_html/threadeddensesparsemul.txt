<p dir="auto">The interface is adapted from the 5-parameter definition used by <code>mul!</code> and also BLAS.
Previously we tried to overload the <code>mul!</code> operator, which comes with some nice syntactic convenience, but it lead to some downstream problems with package precompilation, and checking whether our implementation is actually used.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Rationale</h2><a id="user-content-rationale" class="anchor" aria-label="Permalink: Rationale" href="#rationale"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">I want to do <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$C \leftarrow C - D \times S$</math-renderer> fast, where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$D$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$S$</math-renderer> are dense and sparse matrices, respectively.
Notice how this is different from <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$C \leftarrow C - S \times D$</math-renderer>, i.e. dense <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\times$</math-renderer> sparse vs sparse <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\times$</math-renderer> dense.
In particular:</p>
<ul dir="auto">
<li>The SparseArrays.jl package doesn't support threaded multiplication.</li>
<li>The IntelMKL.jl package doesn't seem to support dense <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\times$</math-renderer> sparsecsc multiplication, although one can get similar performance using that package and transposing appropriately. It also comes with possible licensing issues and is vendor-specific.</li>
<li>The ThreadedSparseCSR.jl package also just supports sparsecsr <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\times$</math-renderer> dense.</li>
<li>The ThreadedSparseArrays.jl package also just supports ThreadedSparseMatrixCSC <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\times$</math-renderer> dense, and also doesn't install for me currently.</li>
</ul>
<p dir="auto">I haven't found an implementation for that, so made one myself. In fact, the package <code>Polyester.jl</code> makes this super easy, the entire code is basically</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import SparseArrays: SparseMatrixCSC, mul!; import SparseArrays
import Polyester: @batch

function fastdensesparsemul_threaded!(C::AbstractMatrix, A::AbstractMatrix, B::SparseMatrixCSC, α::Number, β::Number)
    @batch for j in axes(B, 2)
        C[:, j] .*= β
        C[:, j] .+= A * (α.*B[:, j])
    end
    return C
end"><pre><span class="pl-k">import</span> SparseArrays<span class="pl-k">:</span> SparseMatrixCSC, mul!; <span class="pl-k">import</span> SparseArrays
<span class="pl-k">import</span> Polyester<span class="pl-k">:</span> <span class="pl-c1">@batch</span>

<span class="pl-k">function</span> <span class="pl-en">fastdensesparsemul_threaded!</span>(C<span class="pl-k">::</span><span class="pl-c1">AbstractMatrix</span>, A<span class="pl-k">::</span><span class="pl-c1">AbstractMatrix</span>, B<span class="pl-k">::</span><span class="pl-c1">SparseMatrixCSC</span>, α<span class="pl-k">::</span><span class="pl-c1">Number</span>, β<span class="pl-k">::</span><span class="pl-c1">Number</span>)
    <span class="pl-c1">@batch</span> <span class="pl-k">for</span> j <span class="pl-k">in</span> <span class="pl-c1">axes</span>(B, <span class="pl-c1">2</span>)
        C[:, j] <span class="pl-k">.*=</span> β
        C[:, j] <span class="pl-k">.+</span><span class="pl-k">=</span> A <span class="pl-k">*</span> (α<span class="pl-k">.*</span>B[:, j])
    <span class="pl-k">end</span>
    <span class="pl-k">return</span> C
<span class="pl-k">end</span></pre></div>
<p dir="auto">Notice that this approach doesn't make sense for matrix-vector multiplication (the loop would just have one element), so that case is not considered in this package, however it does make sense for outer producs.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Note on column-major and CSC vs CSR</h3><a id="user-content-note-on-column-major-and-csc-vs-csr" class="anchor" aria-label="Permalink: Note on column-major and CSC vs CSR" href="#note-on-column-major-and-csc-vs-csr"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">I haven't found much literature on the choice of CSC vs CSR storage specifically of the context of dense <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$\cdot$</math-renderer> sparse multiplication with column-major dense storage.
However, as we can see in the code snippet above, the CSC format seems to be reasonably sensible for column-major dense storage.
To compute any given column in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$C_{(:,j)}$</math-renderer> of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$C$</math-renderer> we are essentially computing a weighted sum of columns in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$A$</math-renderer>, i.e. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$C_{(:,j)} = \sum_k \lambda_k \cdot A_{(:,k)}$</math-renderer> which should be very cache efficient and SSE-able.</p>

<p dir="auto">For matrices <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$(N\times K)$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$(K\times M)$</math-renderer> we fix <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$N=1'000$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$K=2'000$</math-renderer> and vary M.
Here's are the benchmark results, comparing against SparseArrays.jl, which ships with Julia but is single-threaded:</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="/benchmark/scaling.png"><img src="/benchmark/scaling.png" alt="scaling benchmark" style="max-width: 100%;"></a></p>
<p dir="auto">For all M we see a speed up over <code>_spmul!</code> from the SparseArrays package of up to ~2x for M in [300, 30_000].
We also compare against <code>MKLSparse.jl</code>. However, since MKLSparse only supports <code>dense x sparse</code> we first need to allocate spare buffers and transpose the dense matrix (these allocations are not measured in the <code>no_transpose</code> variant), and then computing essentially <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5d788685f7d595dbb7e67a3af2941d9e">$(B^T A^T)^T$</math-renderer>.
The result is much slower, likely due to the fact that the dense matrix is column-major.
We also compare against SparseArrays.jl doing the same, where we also see poor performance.</p>
