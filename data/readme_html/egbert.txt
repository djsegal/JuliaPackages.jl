Egbert.jl (E-Graph-Based Expression Rewrite Tool) is an optimization framework developed for my masters thesis at Ghent University. It uses e-graphs and equality saturation to optimize a function with a set of rewrite rules.
</p><p dir="auto">The optimization process used in this project uses the e-graph implementation found in <a href="https://github.com/JuliaSymbolics/Metatheory.jl/">Metatheory.jl</a> and lends many ideas and techniques from the <a href="https://github.com/bytecodealliance/wasmtime/blob/main/cranelift/README.md">Cranelift</a> project.</p>
<p dir="auto"></p>

<p dir="auto">Running this optimizer requires a custom build of the Julia compiler. This custom version includes a pass manager which allows for the optimization pipeline to be changed at run time.</p>
<p dir="auto">This fork of the Julia compiler can be found at <a href="https://github.com/HectorPeeters/julia">HectorPeeters/julia</a>. The required changes are on the <a href="https://github.com/HectorPeeters/julia/tree/pass-manager">pass-manager</a> branch, while the original commit <a href="https://github.com/HectorPeeters/julia/commit/29a58d5c4a5943774984ba83b2a84f98ff377a73">29a58d5</a> from which all changes for the pass manager have been made is marked using the <a href="https://github.com/HectorPeeters/julia/releases/tag/baseline">baseline</a> tag.</p>
<p dir="auto">The normal Julia <a href="https://github.com/HectorPeeters/julia/tree/master#building-julia">build instructions</a> (i.e. running <code>make</code>) should be sufficient for compiling this fork.</p>
<p dir="auto">This custom version can be added to juliaup using the following command:</p>

<p dir="auto">All tests of the project are contained within the <code>test/</code> folder. Running all of the tests at once can be done using the following command:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia +&lt;name-of-version&gt; --project=. test/all.jl"><pre>julia +<span class="pl-k">&lt;</span>name-of-version<span class="pl-k">&gt;</span> --project=. test/all.jl</pre></div>
<p dir="auto">Tests can also be run individually using the corresponding filename instead of <code>test/all.jl</code>.</p>
<p dir="auto">Observing the generated IR for each test can be done by adding the <code>log_ir=true</code> parameter to the <code>Options</code> property passed to the <code>@optimize</code> macro.</p>

<p dir="auto">The benchmarks are stored in the <code>benches/</code> folder. Executing a benchmark can be done in the same manner as running the tests. Running the benchmarks from the REPL is not recommended to reduced any caching related performance fluctuations.</p>
<p dir="auto">All benchmarks run the evaluations for multiple different input sizes and either output a CSV file of the results or print them to the console. One exception is <code>benches/astsize.jl</code>, which requires manually changing the size of the input in the code as this generates an expression tree at compile time using a macro.</p>

<p dir="auto">With the guidance of Alessandro Cheli, one of the developers of Metatheory, I started the conversion to Metatheory 3.0. This version is currently still in beta but ships with many bug fixes and performance improvements. While this resulted in cleaner and more efficient code, the optimizer using Metatheory 3.0 did not reach feature parity in time due to some unresolved issues in the Metatheory library. While the implementation is very unstable, the changes can be found on the <code>mt3</code> branch.</p>

<p dir="auto">The main way to interact with the optimizer is through the use of the <code>@optimize</code> macro. This macro is used to optimize a specific function call with a set of rewrite rules. It can be used as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@optimize Options() rules to_optimize()"><pre><span class="pl-c1">@optimize</span> <span class="pl-c1">Options</span>() rules <span class="pl-c1">to_optimize</span>()</pre></div>
<p dir="auto">The rules parameter takes a <em>Metatheory.jl</em> theory which is a set of rewrite rules. It follows the same convention as <em>Metatheory.jl</em> with regards to the definition of the rules. The full documentation about the definition of these rewrite rules can be found on the <a href="https://juliasymbolics.github.io/Metatheory.jl/dev/rewrite/" rel="nofollow"><em>Metatheory.jl</em> docs</a>. A simple example is shown below:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="t = @theory x y z begin

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Limitations</h2><a id="user-content-limitations" class="anchor" aria-label="Permalink: Limitations" href="#limitations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Below is a short list of the limitations of the current implementation:</p>
<ul dir="auto">
<li>No control flow support, only single basic block functions are supported</li>
<li>Matching on qualified function names is fully not supported (e.g. <code>Main.test()</code> or <code>Base.(:+)(12, 13)</code>) in the current Metatheory version. This prevents the usage of the built-in operators (e.g. +, -, *, /). Wrapper functions will have to be used instead. Patterns containing qualified function names (e.g. <code>Main.add(a, b) --&gt; Main.add(b, a)</code>) will not be matched correctly.</li>
</ul>
