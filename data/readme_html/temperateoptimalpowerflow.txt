<p dir="auto"><a href="https://github.com/gillioz/TemperateOptimalPowerFlow.jl/actions/workflows/CI.yml?query=branch%3Amain"><img src="https://github.com/gillioz/TemperateOptimalPowerFlow.jl/actions/workflows/CI.yml/badge.svg?branch=main" alt="Build Status" style="max-width: 100%;"></a></p>
<p dir="auto">This package implements a "temperate" Optimal Power Flow (OPF) algorithm
that dispatches production sources in a power system while disfavoring heavily-loaded lines.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Line cost function</h2><a id="user-content-line-cost-function" class="anchor" aria-label="Permalink: Line cost function" href="#line-cost-function"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The core of the algorithm is to assign a cost to each line of the power grid
that is proportional to the square of the line's loading rate.
In this way, the optimal power flow becomes a convex optimization problem
that can be solved with standard methods.</p>
<p dir="auto">Given the power <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$P_i$</math-renderer> flowing through a line with index <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$i$</math-renderer>,
and the thermal limit of the line <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$P_i^{th}$</math-renderer>,
the loading rate <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$R_i$</math-renderer> of the line is given by the formula</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$R_i = | P_i | / P_i^{th}$</math-renderer></p>
<p dir="auto">We define the cost associated with line <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$i$</math-renderer> to be the square of the loading rate,
weighted by the line's thermal limit:</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$P_i^{th} R_i^2$</math-renderer></p>
<p dir="auto">Using the definition of the loading rate, this is equivalent to:</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$P_i^2 / P_i^{th}$</math-renderer></p>
<p dir="auto">This cost is independent of the sign of the power <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e2de40df278736823f2f1d5e375bf6e4">$P_i$</math-renderer>, which depends on the line's direction.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Other features</h2><a id="user-content-other-features" class="anchor" aria-label="Permalink: Other features" href="#other-features"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In addition to the quadratic line cost, a conventional, linear production cost can be associated
with each generator in order to model the contingencies of power production
and introduce some realistic noise in the optimisation process.</p>
<p dir="auto">The TOPF algorithm also supports constraints that ensures a given total production
over a certain period of time for every individual generator.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To begin, import a model in <a href="https://www.pserc.cornell.edu/matpower/" rel="nofollow">MatPower</a>
or <a href="https://lanl-ansi.github.io/PowerModels.jl/stable/network-data/" rel="nofollow">PowerModels</a> format.
For instance, working the package's directory, one can use:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using TemperateOptimalPowerFlow
network = import_model(&quot;test/switzerland.json&quot;)"><pre><span class="pl-k">using</span> TemperateOptimalPowerFlow
network <span class="pl-k">=</span> <span class="pl-c1">import_model</span>(<span class="pl-s"><span class="pl-pds">"</span>test/switzerland.json<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">or</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using TemperateOptimalPowerFlow, PowerModels
network = parse_file(&quot;test/case3.m&quot;)
prepare_model!(network)"><pre><span class="pl-k">using</span> TemperateOptimalPowerFlow, PowerModels
network <span class="pl-k">=</span> <span class="pl-c1">parse_file</span>(<span class="pl-s"><span class="pl-pds">"</span>test/case3.m<span class="pl-pds">"</span></span>)
<span class="pl-c1">prepare_model!</span>(network)</pre></div>
<p dir="auto">If the model is imported with the <em>PowerModels</em> <code>parse_file</code> method,
it is necessary to run the command <code>prepare_model!</code> that adds some features to the model.
In particular, it ensures that the model contains an <em>expected generation value</em> <code>pexp</code>
for each generator,  which must be a fraction of the generator's capacity <code>pmax</code>
(if missing, this is set to 50% of the capacity by default).</p>
<p dir="auto">The optimal power flow computation is then setup with the command</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="setup(directory, network, loads, gen_costs)"><pre><span class="pl-c1">setup</span>(directory, network, loads, gen_costs)</pre></div>
<p dir="auto">where</p>
<ul dir="auto">
<li><code>directory</code> is a path to a directory to be created, in which computation files will be placed;</li>
<li><code>network</code> is the network object imported before;</li>
<li><code>loads</code> is a matrix that contain time series for each load of the model, arranged as rows;</li>
<li><code>gen_costs</code> is a similar matrix with one row for each generator of the model,
containing the variable generation cost of that generator.</li>
</ul>
<p dir="auto">Several files are generated in the relevant directory.
To perform the actual optimal power flow computation,
one needs to import an optimizer such as <a href="https://www.gurobi.com/" rel="nofollow">Gurobi</a> (commercial)
or <a href="https://github.com/coin-or/Ipopt">Ipopt</a> (open source),
or otherwise provide a <code>get_optimizer()</code> method that returns an optimizer
in the <a href="https://jump.dev/MathOptInterface.jl/stable/" rel="nofollow">MathOptInterface</a> format.
Then the computation can be launched with</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Ipopt
compute(directory)"><pre><span class="pl-k">using</span> Ipopt
<span class="pl-c1">compute</span>(directory)</pre></div>
<p dir="auto"><strong>WARNING</strong>: For large models and/or long time series the computation can be slow (several hours!) and memory-intensive.
It is recommended to partition the optimal power flow computation into smaller parts.
For instance, a time series of 8736 time steps (364 days x 24 hours) can be partitioned into
52 weeks of 168 time steps using</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="compute(directory, &quot;P_result_52x168&quot;, [52, 168])"><pre><span class="pl-c1">compute</span>(directory, <span class="pl-s"><span class="pl-pds">"</span>P_result_52x168<span class="pl-pds">"</span></span>, [<span class="pl-c1">52</span>, <span class="pl-c1">168</span>])</pre></div>
<p dir="auto">or partitioned further into 13 "months" of 28 days of 24 hours as</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="compute(directory, &quot;P_result_13x28x24&quot;, [13, 28, 24])"><pre><span class="pl-c1">compute</span>(directory, <span class="pl-s"><span class="pl-pds">"</span>P_result_13x28x24<span class="pl-pds">"</span></span>, [<span class="pl-c1">13</span>, <span class="pl-c1">28</span>, <span class="pl-c1">24</span>])</pre></div>
<p dir="auto">The second argument in both cases indicates the name of the result file.</p>
<p dir="auto">Once the computation is done, the results can be accessed with</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="retrieve_gen_results(directory, &quot;P_result_13x28x24&quot;)"><pre><span class="pl-c1">retrieve_gen_results</span>(directory, <span class="pl-s"><span class="pl-pds">"</span>P_result_13x28x24<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">returning a matrix of time series in which each row corresponds to a generator of the model.
The ordered list of generators can be obtained with</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="get_ordered_gen_ids(network)"><pre><span class="pl-c1">get_ordered_gen_ids</span>(network)</pre></div>
<p dir="auto">Similarly, the power flowing through the lines of the network can be accessed with</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="retrieve_line_flows(directory, &quot;P_result_13x28x24&quot;)"><pre><span class="pl-c1">retrieve_line_flows</span>(directory, <span class="pl-s"><span class="pl-pds">"</span>P_result_13x28x24<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">where the rows correspond to the line IDs of</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="get_ordered_line_ids(network)"><pre><span class="pl-c1">get_ordered_line_ids</span>(network)</pre></div>
<p dir="auto">A more complete description of the package's possibilities can be found in the
<a href="https://github.com/GeeeHesso/PowerData/tree/main/run">PowerData repository</a>.</p>
