<p dir="auto">Implementation of flexible (and thread-safe) temporary arrays and array pools for situations where a little bit of semi-manual memory management improves performance. Used quite heavily throughout the ACE codebase, can lead to significant performance gains in some cases. Unfortunately, at this point, those gains are not always as systematic as one would hope.</p>
<p dir="auto">The following Table shows a basic benchmark for evaluating a Chebyshev basis, for multiple inputs at the same time. This is a typical use-case for which this package is intended: the cost of arithmetic is on the same order of magnitude as the cost of allocation.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>FlexArray</code></h3><a id="user-content-flexarray" class="anchor" aria-label="Permalink: FlexArray" href="#flexarray"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>ObjectPools.jl</code> exports <code>FlexArray</code> which can be used to keep memory for an array and adapt its type and size as needed. In particular the eltype and size can change at runtime without performance loss. They are constructed as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="tmp = FlexArray()"><pre>tmp <span class="pl-k">=</span> <span class="pl-c1">FlexArray</span>()</pre></div>
<p dir="auto">This stores a resizable array that can be obtained via</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="A = acquire!(tmp, (N,), Float64)  # N = length of array
A = acquire!(tmp, (10, 10, 10), Bool)"><pre>A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(tmp, (N,), Float64)  <span class="pl-c"><span class="pl-c">#</span> N = length of array</span>
A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(tmp, (<span class="pl-c1">10</span>, <span class="pl-c1">10</span>, <span class="pl-c1">10</span>), Bool)</pre></div>
<p dir="auto">The object <code>tmp</code> actually stores a <code>Vector{UInt8}</code> which is converted into a <code>PtrArray</code> and then re-interpreted and reshaped at essentially zero-cost.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>FlexArrayCache</code></h3><a id="user-content-flexarraycache" class="anchor" aria-label="Permalink: FlexArrayCache" href="#flexarraycache"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>ObjectPools.jl</code> exports <code>FlexArrayCache</code>, which provides stacks of arrays to reuse without garbage collection. This can be thought of as a very limited and manual re-implementation of garbage collection. They are used as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cache = FlexArrayCache()
A = acquire!(cache, (N, ), Float64)
# do something with A 
release!(A)"><pre>cache <span class="pl-k">=</span> <span class="pl-c1">FlexArrayCache</span>()
A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(cache, (N, ), Float64)
<span class="pl-c"><span class="pl-c">#</span> do something with A </span>
<span class="pl-c1">release!</span>(A)</pre></div>
<p dir="auto">The <code>acquire!</code> function obtains an array of size <code>(N,)</code> from the stack (in the current thread). After the array is no longer needed, it can be returned to the stack via <code>release!</code>. It is ok if it is never released. Once there is no longer a reference to <code>A</code>, it will just be garbage collected.</p>
<p dir="auto">One can also use the <code>unwrap</code> function to get the <code>PtrArray</code> of a <code>FlexCachedArray</code> or adjoint/transpose of a <code>FlexCachedArray</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cache = FlexArrayCache()
A = acquire!(cache, (M, N), Float64)
Aptr = unwrap(A) # PtrArray of size (M, N)

At = A' # Adjoint of A in FlexCachedArray
Atptr = unwrap(At) # PtrArray of At with size (N, M)"><pre>cache <span class="pl-k">=</span> <span class="pl-c1">FlexArrayCache</span>()
A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(cache, (M, N), Float64)
Aptr <span class="pl-k">=</span> <span class="pl-c1">unwrap</span>(A) <span class="pl-c"><span class="pl-c">#</span> PtrArray of size (M, N)</span>

At <span class="pl-k">=</span> A<span class="pl-k">'</span> <span class="pl-c"><span class="pl-c">#</span> Adjoint of A in FlexCachedArray</span>
Atptr <span class="pl-k">=</span> <span class="pl-c1">unwrap</span>(At) <span class="pl-c"><span class="pl-c">#</span> PtrArray of At with size (N, M)</span></pre></div>
<p dir="auto">Warning: Use of <code>parent</code> to obtain the <code>PtrArray</code> of a <code>FlexCachedArray</code> is deprecated. Always use <code>unwrap</code> instead.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Array Pools</h3><a id="user-content-array-pools" class="anchor" aria-label="Permalink: Array Pools" href="#array-pools"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A pool is a dictionary of temporary arrays or array caches indexed by symbols. It enables the management of many temporary arrays (or caches) within a single field. For example,</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pool = ArrayPool(FlexArray)
A = acquire!(pool, :A, (10, 10), Float64)

A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(pool, <span class="pl-c1">:A</span>, (<span class="pl-c1">10</span>, <span class="pl-c1">10</span>), Float64) 
B <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(pool, <span class="pl-c1">:B</span>, (<span class="pl-c1">10</span>, <span class="pl-c1">100</span>), ComplexF64)</pre></div>
<p dir="auto">One can similarly create a <code>ArrayPool(FlexArrayCache)</code></p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Thread Safety</h3><a id="user-content-thread-safety" class="anchor" aria-label="Permalink: Thread Safety" href="#thread-safety"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In multi-threaded code it can become important that each thread uses its own temporary work array. This can be achieved by wrapping a <code>FlexArray</code> or <code>FlexArrayCache</code> or an <code>ArrayPool</code> into a <code>TSafe</code>, e.g.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="tmp = TSafe(ArrayPool(FlexArrayCache))"><pre>tmp <span class="pl-k">=</span> <span class="pl-c1">TSafe</span>(<span class="pl-c1">ArrayPool</span>(FlexArrayCache))</pre></div>
<p dir="auto">We can now access this as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@threads for n = 1:N 
   A = acquire!(tmp, :A, (10,10), SVector{3, Float64}) 
   # do something with A 
   release!(A)
end "><pre><span class="pl-c1">@threads</span> <span class="pl-k">for</span> n <span class="pl-k">=</span> <span class="pl-c1">1</span><span class="pl-k">:</span>N 
   A <span class="pl-k">=</span> <span class="pl-c1">acquire!</span>(tmp, <span class="pl-c1">:A</span>, (<span class="pl-c1">10</span>,<span class="pl-c1">10</span>), SVector{<span class="pl-c1">3</span>, Float64}) 
   <span class="pl-c"><span class="pl-c">#</span> do something with A </span>
   <span class="pl-c1">release!</span>(A)
<span class="pl-k">end</span> </pre></div>
<p dir="auto">Here, <code>tmp</code> actually stores a separate <code>ArrayPool</code> for each thread. Note that due to the dynamic scheduler it is possible that an array <code>A</code> is aquired in thread <code>i</code> and released in thread <code>j</code> in which case it is released back to a different stack.</p>
<p dir="auto">Note that due to the dynamics scheduler, <code>TSafe(FlexArray)</code> is <em>NOT</em> entirely thread-safe. These arrays are only thread safe when using the static scheduler, e.g.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="tmp = TSafe(FlexCache)
@threads :static for i = 1:10
   A = acquire!(tmp, (20, 30, 5), ComplexF32) 
   # do something with A 
end"><pre>tmp <span class="pl-k">=</span> <span class="pl-c1">TSafe</span>(FlexCache)
<span class="pl-c1">@threads</span> <span class="pl-c1">:static</span> <span class="pl-k">for</span> i <span class="pl-k">=</span> <span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">10</span>

<span class="pl-k">end</span></pre></div>

<p dir="auto">The following example contains code that is not intended to run, but only indicative:</p>
<p dir="auto">The simplest use-case of <code>ObjectPools.jl</code> is to have flexible temporary variables and output arrays that can be reused. For example, suppose we want to evaluate the spherical harmonics. This could be implemented as follows</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct Ylms

<p dir="auto">The first advantage of the above implementation is that the input type parameter <code>T</code> need not be known at any point other than runtime. E.g., we can now use <code>ForwardDiff</code> to differentiate the basis and the <code>FlexArray</code>s will just become arrays of <code>Dual</code> numbers.</p>
<p dir="auto">The second advantage is that the output array gets released back to the array cache and is not newly allocated at each step. Of course one could instead pre-allocate and write an in-place version of the evaluation code. But this requires type management <em>outside</em> of the Ylms implementation, which can get tedious. The <code>FlexArrayCache</code> is a simple mechanism to keep all type management <em>localized</em> to the actual implementation.</p>
<p dir="auto">If we wanted to make the <code>for i = 1:niter</code> loop multi-threaded then we could rewrite this code as follows:</p>
