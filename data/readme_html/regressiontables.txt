<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">RegressionTables.jl</h1><a id="user-content-regressiontablesjl" class="anchor" aria-label="Permalink: RegressionTables.jl" href="#regressiontablesjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package provides publication-quality regression tables for use with <a href="https://github.com/matthieugomez/FixedEffectModels.jl">FixedEffectModels.jl</a>, <a href="https://github.com/JuliaStats/GLM.jl">GLM.jl</a>, <a href="https://github.com/jmboehm/GLFixedEffectModels.jl">GLFixedEffectModels.jl</a> and <a href="https://github.com/JuliaStats/MixedModels.jl">MixedModels.jl</a>, as well as any package that implements the <a href="https://juliastats.org/StatsBase.jl/latest/statmodels/" rel="nofollow">RegressionModel abstraction</a>.</p>
<p dir="auto">In its objective it is similar to  (and heavily inspired by) the Stata command <a href="http://repec.sowi.unibe.ch/stata/estout/esttab.html" rel="nofollow"><code>esttab</code></a> and the R package <a href="https://cran.r-project.org/web/packages/stargazer/" rel="nofollow"><code>stargazer</code></a>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Arguments</h3><a id="user-content-arguments" class="anchor" aria-label="Permalink: Arguments" href="#arguments"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li><code>rr::FixedEffectModel...</code> are the <code>FixedEffectModel</code>s from <code>FixedEffectModels.jl</code> that should be printed. Only required argument.</li>
<li><code>keep</code> is a <code>Vector</code> of regressor names (<code>String</code>s), integers, ranges or regex that should be shown, in that order. Defaults to an empty vector, in which case all regressors will be shown.</li>
<li><code>drop</code> is a <code>Vector</code> of regressor names (<code>String</code>s), integers, ranges or regex that should not be shown. Defaults to an empty vector, in which case no regressors will be dropped.</li>
<li><code>order</code> is a <code>Vector</code> of regressor names (<code>String</code>s), integers, ranges or regex that should be shown in that order. Defaults to an empty vector, in which case the order of regressors will be unchanged. Other regressors are still shown (assuming <code>drop</code> is empty)</li>
<li><code>fixedeffects</code> is a <code>Vector</code> of FE names (<code>String</code>s), integers, ranges or regex that should be shown, in that order. Defaults to an empty vector, in which case all FE's will be shown.</li>
<li><code>align</code> is a <code>Symbol</code> from the set <code>[:l,:c,:r]</code> indicating the alignment of results columns (default <code>:r</code> right-aligned). Currently works only with ASCII and LaTeX output.</li>
<li><code>header_align</code> is a <code>Symbol</code> from the set <code>[:l,:c,:r]</code> indicating the alignment of the header row (default <code>:c</code> centered). Currently works only with ASCII and LaTeX output.</li>
<li><code>labels</code> is a <code>Dict</code> that contains displayed labels for variables (<code>String</code>s) and other text in the table. If no label for a variable is found, it default to variable names. See documentation for special values.</li>
<li><code>estimformat</code> is a <code>String</code> that describes the format of the estimate.</li>
<li><code>digits</code> is an <code>Int</code> that describes the precision to be shown in the estimate. Defaults to <code>nothing</code>, which means the default (3) is used (default can be changed by setting <code>RegressionTables.default_digits(render::AbstractRenderType, x) = 3</code>).</li>
<li><code>statisticformat</code> is a <code>String</code> that describes the format of the number below the estimate (se/t).</li>
<li><code>digits_stats</code> is an <code>Int</code> that describes the precision to be shown in the statistics. Defaults to <code>nothing</code>, which means the default (3) is used (default can be changed by setting <code>RegressionTables.default_digits(render::AbstractRenderType, x) = 3</code>).</li>
<li><code>below_statistic</code> is a type that describes a statistic that should be shown below each point estimate. Recognized values are <code>nothing</code>, <code>StdError</code>, <code>TStat</code>, and <code>ConfInt</code>. <code>nothing</code> suppresses the line. Defaults to <code>StdError</code>.</li>
<li><code>regression_statistics</code> is a <code>Vector</code> of types that describe statistics to be shown at the bottom of the table. Built in recognized types are <code>Nobs</code>, <code>R2</code>, <code>PseudoR2</code>, <code>R2CoxSnell</code>, <code>R2Nagelkerke</code>, <code>R2Deviance</code>, <code>AdjR2</code>, <code>AdjPseudoR2</code>, <code>AdjR2Deviance</code>, <code>DOF</code>, <code>LogLikelihood</code>, <code>AIC</code>, <code>AICC</code>, <code>BIC</code>, <code>FStat</code>, <code>FStatPValue</code>, <code>FStatIV</code>, <code>FStatIVPValue</code>, R2Within. Defaults vary based on regression inputs (simple linear model is [Nobs, R2]).</li>
<li><code>extralines</code> is a <code>Vector</code> or a <code>Vector{&lt;:AbsractVector}</code> that will be added to the end of the table. A single vector will be its own row, a vector of vectors will each be a row. Defaults to <code>nothing</code>.</li>
<li><code>number_regressions</code> is a <code>Bool</code> that governs whether regressions should be numbered. Defaults to <code>true</code>.</li>
<li><code>groups</code> is a <code>Vector</code>, <code>Vector{&lt;:AbstractVector}</code> or <code>Matrix</code> of labels used to group regressions. This can be useful if results are shown for different data sets or sample restrictions.</li>
<li><code>print_fe_section</code> is a <code>Bool</code> that governs whether a section on fixed effects should be shown. Defaults to <code>true</code>.</li>
<li><code>print_estimator_section</code>  is a <code>Bool</code> that governs whether to print a section on which estimator (OLS/IV/Binomial/Poisson...) is used. Defaults to <code>true</code> if more than one value is displayed.</li>
<li><code>standardize_coef</code> is a <code>Bool</code> that governs whether the table should show standardized coefficients. Note that this only works with <code>TableRegressionModel</code>s, and that only coefficient estimates and the <code>below_statistic</code> are being standardized (i.e. the R^2 etc still pertain to the non-standardized regression).</li>
<li><code>render::AbstractRenderType</code> is a <code>AbstractRenderType</code> type that governs how the table should be rendered. Standard supported types are ASCII (via <code>AsciiTable()</code>) and LaTeX (via <code>LatexTable()</code>). Defaults to <code>AsciiTable()</code>.</li>
<li><code>file</code> is a <code>String</code> that governs whether the table should be saved to a file. Defaults to <code>nothing</code>.</li>
<li><code>transform_labels</code> is a <code>Dict</code> or one of the <code>Symbol</code>s <code>:ampersand</code>, <code>:underscore</code>, <code>:underscore2space</code>, <code>:latex</code></li>
</ul>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Main Changes for v0.6</h2><a id="user-content-main-changes-for-v06" class="anchor" aria-label="Permalink: Main Changes for v0.6" href="#main-changes-for-v06"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Version 0.6 was a major rewrite of the backend with the goal of increasing the flexibility and decreasing the dependencies on other packages (regression packages are now extensions). While most code written with v0.5 should continue to run, there might be a few differences and some deprecation warnings. Below is a brief overview of the changes:</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">New Features</h3><a id="user-content-new-features" class="anchor" aria-label="Permalink: New Features" href="#new-features"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>There is an <code>extralines</code> argument that can accept vectors with pairs, where the pair defines a multicolumn value (<code>["Label", "two columns" =&gt; 2:3, 1.5 =&gt; 4:5]</code>), it can also accept a <code>DataRow</code> object that allows for more control.</li>
<li>New <code>keep</code> <code>drop</code> and <code>order</code> arguments allow exact names, regex to search within names, integers to select specific values, and ranges (<code>1:4</code>) to select groups, and they can be mixed (<code>[1:2, :end, r"Width"]</code>)</li>
<li><code>labels</code> now applies to individual parts of an interaction or categorical coefficient name (hopefully reducing the number of labels required)</li>
<li>The interaction symbol now depends on the table type, so in Latex, the interactions will have <code>\$\\times\$</code>
<ul dir="auto">
<li>Using a Latex table will also automatically escape parts of coefficient names (if no other labels are provided)</li>
</ul>
</li>
<li>A confidence interval is now an option for a below statistic (<code>below_statistic=ConfInt</code>)</li>
<li>Several defaults are different to try and provide more relevant information (see changes do defaults section)</li>
<li>Fixed effect values now have a suffix (defaults to <code>" Fixed Effects"</code>) so that labeling can be simpler. Disable by setting <code>print_fe_suffix=false</code></li>
<li>It is now possible to print the coefficient value and "under statistic" on the same line (<code>stat_below=false</code>)</li>
<li>It is possible to define custom regression statistics that are calculated based on the regressions provided</li>
<li>It is possible to change the order of the major blocks in a regression table</li>
<li>Using RegressionTables for descriptive statistics is now easier. Describe a DataFrame (<code>df_described=describe(df)</code>) and provide that to a RegressionTable (<code>tab = RegressionTable(names(df_described), Matrix(df_described))</code>), there are also options to render the table as a <code>LatexTable</code> or <code>HtmlTable</code>. Write this to a file using <code>write(file_name, tab)</code></li>
<li>It is possible to overwrite almost any setting. For example, to make T-Statistics the default in all tables, run <code>RegressionTables.default_below_statistic(render::AbstractRenderType)=TStat</code></li>
<li>Option to show clustering (<code>print_clusters=true</code>).
<ul dir="auto">
<li>Can also be the size of the clusters by running <code>Base.repr(render::AbstractRenderType, x::RegressionTables.ClusterValue; args...) = repr(render, value(x); args...)</code></li>
</ul>
</li>
<li>Several new regression statistics are now available, the full list is: <code>[Nobs, R2, PseudoR2, R2CoxSnell, R2Nagelkerke, R2Deviance, AdjR2, AdjPseudoR2, AdjR2Deviance, DOF, LogLikelihood, AIC, AICC, BIC, FStat, FStatPValue, FStatIV, FStatIVPValue, R2Within]</code></li>
<li>Use <code>LatexTableStar</code> to create a table that expands the entire text width</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Changes to Defaults</h3><a id="user-content-changes-to-defaults" class="anchor" aria-label="Permalink: Changes to Defaults" href="#changes-to-defaults"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There are some changes to the defaults from version 0.5 and two additional settings</p>
<ul dir="auto">
<li>Interactions in coefficients now vary based on the type of table. In Latex, this now defaults to <code>$\\times$</code> and in HTML <code>&amp;times;</code>. These can be changed by running:
<ul dir="auto">
<li><code>RegressionTables.interaction_combine(render::AbstractRenderType) = " &amp; "</code></li>
<li><code>RegressionTables.interaction_combine(render::AbstractLatex) = " &amp; "</code></li>
<li><code>RegressionTables.interaction_combine(render::AbstractHtml) = " &amp; "</code></li>
</ul>
</li>
<li><code>print_estimator</code> default was <code>true</code>, now it is <code>true</code> if more than one type of regression is provided (i.e., "IV" and "OLS" will display the estimator, all "OLS" will not). Set to the old default by running:
<ul dir="auto">
<li><code>RegressionTables.default_print_estimator(x::AbstractRenderType, rrs) = true</code></li>
</ul>
</li>
<li><code>number_regressions</code> default was <code>true</code>, now it is <code>true</code> if more than one regression is provided. Set to the old default by running:
<ul dir="auto">
<li><code>RegressionTables.default_number_regressions(x::AbstractRenderType, rrs) = true</code></li>
</ul>
</li>
<li><code>regression_statistics</code> default was <code>[Nobs, R2]</code>, these will vary based on provided regressions. For example, a fixed effect regression will default to <code>[Nobs, R2, R2Within]</code> and a Probit regression will default to <code>[Nobs, PseudoR2]</code> (and if multiple types, these will be combined). Set to the old default by running:
<ul dir="auto">
<li><code>RegressionTables.default_regression_statistics(x::AbstractRenderType, rrs::Tuple) = [Nobs, R2]</code></li>
</ul>
</li>
<li>Labels for the type of the regression are more varied for non-linear cases, instead of "NL", it will display "Poisson", "Probit", etc. These can be changed by running:
<ul dir="auto">
<li><code>RegressionTables.label_distribution(x::AbstractRenderType, d::Probit) = "NL"</code></li>
</ul>
</li>
<li><code>print_fe_suffix</code> is a new setting where <code>" Fixed Effect"</code> is added after the fixed effect. Turn this off for all tables by running:
<ul dir="auto">
<li><code>RegressionTables.default_print_fe_suffix(x::AbstractRenderType) = false</code></li>
</ul>
</li>
<li><code>print_control_indicator</code> is a new setting where a line is added if any coefficients are omitted. Turn this off for all tables by running:
<ul dir="auto">
<li><code>RegressionTables.default_print_control_indicator(x::AbstractRenderType) = false</code></li>
</ul>
</li>
</ul>

<p dir="auto">Labels for coefficient names are the same, but interaction and categorical terms might see some differences. Now, each part of an interaction or categorical term can be labeled independently (so <code>labels=Dict("coef1" =&gt; "Coef 1", "coef2" =&gt; "Coef 2")</code> would relabel <code>coef1 &amp; coef2</code> to <code>Coef 1 &amp; Coef 2</code>). This might cause changes to tables if the labels dictionary contains an interaction label but not both pieces independently, the display would depend on which order the dictionary is applied (so <code>labels=Dict("coef1" =&gt; "Coef 1", "coef1 &amp; coef2" =&gt; "Coef 1 &amp; Coef 2")</code> might turn the interaction into either <code>Coef 1 &amp; Coef 2</code> or <code>Coef 1 &amp; coef2</code>).</p>

<p dir="auto">The <code>custom_statistics</code> argument took a <code>NamedTuple</code> with vectors, this is now simplified in the <code>extralines</code> argument to a <code>Vector</code>, where the first argument is what is displayed in the left most column. <code>extralines</code> now accepts a <code>Pair</code> of <code>val =&gt; cols</code> (e.g., <code>0.153 =&gt; 2:3</code>), where the second value creates a multicolumn display. See the examples in the documentation under "Extralines".</p>
<p dir="auto">For statistics that can use the values in the regression model (e.g., the mean of Y), it is possible to create those under an <code>AbstractRegressionStatistic</code>. See the documentation for an example.</p>
