<li>Differentially private synthetic data preserving lower order marginals of an input data set</li>
<li>Optimized in-memory implementation for small number of data attributes</li>

<p dir="auto">By default, MWEM works with the histogram representation of a data sets. This
means that the data is represented by a vector whose length is equal to the size
of domain. For example, data consisting of <code>d</code> binary attributes would be
converted to an array of length <code>2^d</code>. MWEM needs to store and array of this
length in main memory, which is often the computational bottleneck.</p>

<p dir="auto">When the histogram representation is too large, try using factored histograms.
Factored histograms maintain a product distribution over clusters of attributes
of the data. Each component is represented using a single histogram. Components
are merged as it becomes necessary. This often allows to scale up MWEM by orders
of magnitude.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Histogram queries</h3><a id="user-content-histogram-queries" class="anchor" aria-label="Permalink: Histogram queries" href="#histogram-queries"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Histogram queries are linear functions in the histogram representation of the
data.  You can define custom query workloads by using
<code>HistogramQueries(query_matrix)</code> instead of <code>Parities(d, 3)</code>. Here <code>query matrix</code> is an <code>N x k</code> matrix specifying the query set in its Histogram
representation, <code>N</code> is the histogram length and <code>k</code> is the <code>k</code> is the number of
queries.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Custom query types</h3><a id="user-content-custom-query-types" class="anchor" aria-label="Permalink: Custom query types" href="#custom-query-types"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To build query sets with your own implicit representations, sub-type
<code>Query</code> and <code>Queries</code>. Implement the functions specified in <code>src/interface.jl</code>.</p>
<p dir="auto">See <code>src/parities.jl</code> for an example.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Available query sets</h3><a id="user-content-available-query-sets" class="anchor" aria-label="Permalink: Available query sets" href="#available-query-sets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto"><strong>Parities</strong>(d, k)</p>
<p dir="auto">Parities of <code>k</code> out of <code>d</code> attributes. This corresponds to approximating
<code>k</code>-way marginals of the original data.</p>
</li>
<li>
<p dir="auto"><strong>FactorParities</strong>(d, k)</p>
<p dir="auto">Parities of <code>k</code> out of <code>d</code> attributes for factored histogram representation.</p>
</li>
<li>
<p dir="auto"><strong>SeriesRangeQueries</strong>(N)</p>
<p dir="auto">Range queries corresponding to all interval queries over a histogram of length <code>N</code>.</p>
<ul dir="auto">
<li><em>SeriesRangeQueries</em>*(Intervals)</li>
</ul>
<p dir="auto">Range queries over histogram with length N, corresponding to intervals = {Interval1, Interval2, ...}
where Interval = (i, j) so that 1 &lt;= i &lt;= j &lt;= N.</p>
</li>
</ul>
