<p dir="auto">DiffEq(For)Lux.jl (aka DiffEqFlux.jl) fuses the world of differential equations with machine learning
by helping users put diffeq solvers into neural networks. This package utilizes
<a href="https://docs.sciml.ai/DiffEqDocs/stable/" rel="nofollow">DifferentialEquations.jl</a>, and <a href="https://lux.csail.mit.edu/" rel="nofollow">Lux.jl</a>  as its building blocks to support research in
<a href="https://www.stochasticlifestyle.com/the-essential-tools-of-scientific-machine-learning-scientific-ml/" rel="nofollow">Scientific Machine Learning</a>, specifically neural differential equations to add physical information into traditional machine learning.</p>

<p dir="auto">DiffEqFlux.jl is for implicit layer machine learning.
DiffEqFlux.jl provides architectures which match the interfaces of machine learning libraries such as Flux.jl and Lux.jl to make it easy to build continuous-time machine learning layers into larger machine learning applications.</p>
<p dir="auto">The following layer functions exist:</p>
<ul dir="auto">
<li>Neural Ordinary Differential Equations (Neural ODEs)</li>
<li>Collocation-Based Neural ODEs (Neural ODEs without a solver, by far the fastest way!)</li>
<li>Multiple Shooting Neural Ordinary Differential Equations</li>
<li>Neural Stochastic Differential Equations (Neural SDEs)</li>
<li>Neural Differential-Algebraic Equations (Neural DAEs)</li>
<li>Neural Delay Differential Equations (Neural DDEs)</li>
<li>Augmented Neural ODEs</li>
<li>Hamiltonian Neural Networks (with specialized second order and symplectic integrators)</li>
<li>Continuous Normalizing Flows (CNF) and FFJORD</li>
</ul>
<p dir="auto">with high order, adaptive, implicit, GPU-accelerated, Newton-Krylov, etc.
methods. For examples, please refer to
<a href="https://julialang.org/blog/2019/01/fluxdiffeq" rel="nofollow">the release blog post</a>.
Additional demonstrations, like neural
PDEs and neural jump SDEs, can be found
<a href="https://www.stochasticlifestyle.com/neural-jump-sdes-jump-diffusions-and-neural-pdes/" rel="nofollow">in this blog post</a>
(among many others!).</p>
<p dir="auto">Do not limit yourself to the current neuralization. With this package, you can
explore various ways to integrate the two methodologies:</p>
<ul dir="auto">
<li>Neural networks can be defined where the “activations” are nonlinear functions
described by differential equations</li>
<li>Neural networks can be defined where some layers are ODE solves</li>
<li>ODEs can be defined where some terms are neural networks</li>
<li>Cost functions on ODEs can define neural networks</li>
</ul>

<ul dir="auto">
<li><code>TensorLayer</code> has been removed, use <code>Boltz.Layers.TensorProductLayer</code> instead.</li>
<li>Basis functions in DiffEqFlux have been removed in favor of <code>Boltz.Basis</code> module.</li>
<li><code>SplineLayer</code> has been removed, use <code>Boltz.Layers.SplineLayer</code> instead.</li>
<li><code>NeuralHamiltonianDE</code> has been removed, use <code>NeuralODE</code> with <code>Layers.HamiltonianNN</code> instead.</li>
<li><code>HamiltonianNN</code> has been removed in favor of <code>Layers.HamiltonianNN</code>.</li>
</ul>

<ul dir="auto">
<li>Flux dependency is dropped. If a non Lux <code>AbstractExplicitLayer</code> is passed we try to automatically convert it to a Lux model with <code>FromFluxAdaptor()(model)</code>.</li>
<li><code>Flux</code> is no longer re-exported from <code>DiffEqFlux</code>. Instead we reexport <code>Lux</code>.</li>
<li><code>NeuralDAE</code> now allows an optional <code>du0</code> as input.</li>
<li><code>TensorLayer</code> is now a Lux Neural Network.</li>
<li>APIs for quite a few layer constructions have changed. Please refer to the updated documentation for more details.</li>
</ul>
