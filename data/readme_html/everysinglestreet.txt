<p dir="auto">This project is intended to be used to keep track of all the streets you've visited in your city. Do you maybe want to run every single street of your hometown?</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">About</h2><a id="user-content-about" class="anchor" aria-label="Permalink: About" href="#about"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This project provides tools for processing and analyzing street network data. It offers functionalities for tasks such as:</p>
<ul dir="auto">
<li>Map matching: Mapping gps tracks to the most likely walked actual path based on the underlying street network</li>
<li>Calculating statistics:
<ul dir="auto">
<li>How much of the city are already walked (taking into account only walkable roads)</li>
<li>How much of districts in the city are already walked (if district info is provided)</li>
</ul>
</li>
</ul>

<p dir="auto">This maps the points to the walkable street network and returns a list of candidate points representing the most likely route. If there is a gap in between for which no possible path was found the list is split up into several parts.
Therefore it returns a vector of vectors of <code>Candidate</code>.</p>
<p dir="auto">Let's have a look at the first candidate point:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="first_candidate = candidates[1][1]"><pre>first_candidate <span class="pl-k">=</span> candidates[<span class="pl-c1">1</span>][<span class="pl-c1">1</span>]</pre></div>
<p dir="auto">Each candidate point is in this format:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="struct Candidate

<p dir="auto">Let's quickly have a look at each of those fields:</p>
<ul dir="auto">
<li>measured_point: The actual recorded <code>GPSPoint</code></li>
<li>lla: The latitude, longitude and altitude of the point on the street network. (Altitude doesn't contain reasonable values atm)</li>
<li>way: A <code>Way</code> object that contains information about the street</li>
<li>way_is_reverse: Whether the λ shows the distance rom the start or from the end of the way</li>
<li>dist: Holds the information of the distance between the measured point and the point it was mapped to. <code>euclidean_distance(candidate.measured_point.pos, candidate.lla)</code></li>
<li>λ: Holds info of how far away this point is from the start (if <code>way_is_reverse</code> is <code>false</code>) or from the end (if <code>way_is_reverse</code> is <code>true</code>) along the way. This makes it simple to calculate which parts of each way are already visited</li>
</ul>
<p dir="auto">You can also get the information in a different format which might be more helpful in certain cases when tracking the achievement of how much one has walked already.</p>

<p dir="auto">So it simply consists of two <code>Candidate</code>s but for those it is asserted that they are both from the same street and in the same direction.
For example if previously candidate 1 was in one street and candidate 2 in another this will create several segments such that this isn't the case anymore. For example by adding the end point of the street on which candidate 1 is on and the start point of the street where candidate 2 is on.</p>
<p dir="auto">There is one more representation which is helpful when looking at several walks combined.</p>
<p dir="auto">Let's have a look at a different way to load a city map which is useful for machines which can't hold a whole city network with precomputed fields in RAM.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="_, altona_map = EverySingleStreet.parse_no_graph_map(&quot;Altona.json&quot;);"><pre>_, altona_map <span class="pl-k">=</span> EverySingleStreet<span class="pl-k">.</span><span class="pl-c1">parse_no_graph_map</span>(<span class="pl-s"><span class="pl-pds">"</span>Altona.json<span class="pl-pds">"</span></span>);</pre></div>

<p dir="auto">The <code>parse_no_graph_map</code> functionality parses the json file but doesn't create a network graph out of it and doesn't precompute shortest paths on the graph.</p>
<p dir="auto">In general the idea of this approach is that whenever one wants to map a new walk onto that network extracts a local map of that walked area and computes the shortest paths on that instead of from the whole city.</p>
<p dir="auto">We initialize a struct of walked parts of the city like this:</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mm_data = EverySingleStreet.map_matching(altona_walk_path, altona_map, walked_parts);"><pre>mm_data <span class="pl-k">=</span> EverySingleStreet<span class="pl-k">.</span><span class="pl-c1">map_matching</span>(altona_walk_path, altona_map, walked_parts);</pre></div>

<p dir="auto">The first struct matches street names to a list of integer ids and then the other matches those integer ids to walked ways.</p>
<p dir="auto">A walked way is described as following:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mutable struct WalkedWay
    way::Way
    parts::Vector{Tuple{Float64, Float64}}
end"><pre><span class="pl-k">mutable struct</span> WalkedWay
    way<span class="pl-k">::</span><span class="pl-c1">Way</span>
    parts<span class="pl-k">::</span><span class="pl-c1">Vector{Tuple{Float64, Float64}}</span>
<span class="pl-k">end</span></pre></div>
<p dir="auto">A <code>Way</code> holds general information like the open street map id, all the nodes that describe the way. The name of the way, the total length and some more.</p>
<p dir="auto">The <code>parts</code> section holds tuples of which parts of the way were walked by distance from the start point. For example</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="(30.771703385452646, 67.50341022110413)"><pre>(<span class="pl-c1">30.771703385452646</span>, <span class="pl-c1">67.50341022110413</span>)</pre></div>
<p dir="auto">Means that one walked the part 30.7m to 67.5m from the start of the way.</p>
