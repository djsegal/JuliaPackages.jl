<p dir="auto">A scan or prefix operation is a generalization of a cumulative sum.
Given a sequence <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="433ba71518d22d2b27b9ecb14d1030c1">$x_1, x_2, ... , x_n$</math-renderer>, and an associative operator, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="433ba71518d22d2b27b9ecb14d1030c1">$\oplus$</math-renderer>, the the scan is:</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="433ba71518d22d2b27b9ecb14d1030c1">$$x_1, x_2 \oplus x_1, x_3 \oplus x_2 \oplus x_1, ... , x_n \oplus x_{n-1} \oplus \cdots \oplus x_1$$</math-renderer>
<p dir="auto">The scan can be parallelized when <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="433ba71518d22d2b27b9ecb14d1030c1">$\oplus$</math-renderer> is associative. This package provides an in-place scan implementation using SIMD, <code>scan_simd!(⊕, x)</code>.
For testing and performance comparison, there is also a serial implementation, <code>scan_serial!(⊕, x)</code>.</p>

<p dir="auto"><a href="https://schrimpf.github.io/SIMDscan.jl/dev/benchmarks/" rel="nofollow">See the benchmarks section of the docs</a>. With 512 bit SIMD vectors, <code>scan_simd!</code> appears to be about 4 time faster. With 256 bit SIMD vectors, the gain is smaller, but still notable. The benchmarks run on github actions, so the resuls and CPU will vary from commit to commit. Of course, the performance will also depend on problem size and the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="433ba71518d22d2b27b9ecb14d1030c1">$\oplus$</math-renderer> operator.</p>
