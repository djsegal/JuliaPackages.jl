<p dir="auto">A game and 3D graphics framework for Julia, using OpenGL 4.6 + bindless textures.
Offers game math, wrappers for OpenGL/GLFW/Dear ImGUI, scene graph algorithms, and numerous other modules.</p>
<p dir="auto">Add it to your project with <code>] add Bplus</code> or <code>using Pkg; Pkg.add("Bplus")</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Structure</h2><a id="user-content-structure" class="anchor" aria-label="Permalink: Structure" href="#structure"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To import everything B+ has to offer, just do <code>using Bplus; @using_bplus</code>.
All documented modules are available directly inside (e.x. <code>Bplus.Math</code>),
but under the hood this library is segmented into several smaller packages:</p>
<ul dir="auto">
<li><a href="https://github.com/heyx3/BplusCore">BplusCore</a> contains utilities and game math.</li>
<li><a href="https://github.com/heyx3/BplusApp">BplusApp</a> provides convenient access to OpenGL, GLFW, and Dear ImGUI.</li>
<li><a href="https://github.com/heyx3/BplusTools">BplusTools</a> provides a variety of other game-development tools, like a scene-graph algorithm, ECS algorithm, and more.</li>
</ul>
<p dir="auto">You can, for example, integrate <code>BplusCore</code> into your own project to get all the game math,
without having to use OpenGL, Dear ImGUI, or any of the other parts of the library.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Tests</h2><a id="user-content-tests" class="anchor" aria-label="Permalink: Tests" href="#tests"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Unit tests follow Julia convention: kept in the <em>test</em> folder, and centralized in <em>test/runtests.jl</em>.
Each sub-package (<code>BplusCore</code>, <code>BplusApp</code>, and <code>BplusTools</code>) runs its own tests,
and this package runs each of those in sequence.
The test behavior is standardized by <code>BplusCore</code>, which provides the path
to a test-running Julia file through <code>BplusCore.TEST_RUNNER_PATH</code>.</p>
<p dir="auto">I never liked how the official Julia Test package does not let you assign messages to tests,
so my tests are implemented with my own macros:</p>
<ul dir="auto">
<li><code>@bp_check(condition, msg...)</code> for normal checks</li>
<li><code>@bp_check_throws(statement, msg...)</code> to ensure something causes an error</li>
<li><code>@bp_test_no_allocations(expr, expected_value, msg...)</code> to test expressions that need to be completely static and type-stable (game math, scene graph operations, raycast math, etc).
<ul dir="auto">
<li>A slightly longer version is offered in case you need to set up the test with some operations that may allocate: <code>@bp_test_no_allocations_setup(setup_expr, test_expr, expected_value, msg...)</code>.</li>
</ul>
</li>
</ul>

<p dir="auto">Below is a quick overview of the modules. <a href="docs/!home.md">A thorough description is available here</a>. You can also refer to the inline doc-strings, comments, and <a href="https://github.com/heyx3/BpExamples">sample projects</a>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>Bplus.Utilities</code></h3><a id="user-content-bplusutilities" class="anchor" aria-label="Permalink: Bplus.Utilities" href="#bplusutilities"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A dumping ground for all sorts of convenience functions and macros.</p>
<p dir="auto">Detailed info can be found <a href="docs/Utilities.md">in this document</a>, but here are the highlights:</p>
<ul dir="auto">
<li><code>PRNG</code>: An alternative to Julia's various <code>AbstractRNG</code>'s which is more suitable for aesthetic, short-term use-cases such as procedural generation.</li>
<li><code>@bp_check(condition, error_msg...)</code>, a run-time test that raises <code>error()</code> if the expression is false.</li>
<li><code>@make_toggleable_asserts()</code> sets up a "debug" vs "release" compile-time flag for your module.</li>
<li><code>@bp_enum</code> and <code>@bp_bitflag</code>: Much better alternatives to Julia's <code>@enum</code> and BitFlags' <code>@bitflag</code>.</li>
<li><code>SerializedUnion{Union{...}}</code>: Can serialize <em>and deserialize</em> a union of values, using the <em>StructTypes</em> package (which means it can be used in major IO packages like <em>JSON3</em>).</li>
<li><code>RandIterator{TIdx, TRng}</code>: Randomly and efficiently iterates through every value in some range <code>1:n</code>.</li>
<li><code>UpTo{N, T}</code>: A type-stable, immutable, stack-allocated container for up to N values of type T. Implements <code>AbstractVector{T}</code>.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>Bplus.Math</code></h3><a id="user-content-bplusmath" class="anchor" aria-label="Permalink: Bplus.Math" href="#bplusmath"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Typical game math stuff, but using Julia's full expressive power.</p>
<p dir="auto">Detailed info can be found <a href="docs/Math.md">in this document</a>, but here is a high-level overview:</p>
<ul dir="auto">
<li>Vectors are represented with <code>Vec{N, T}</code>.</li>
<li>Quaternions are <code>Quaternion{F}</code>.</li>
<li>Matrices are <code>@Mat{C, R, F}</code>.</li>
<li>Various functions such as <code>lerp()</code> and <code>inv_lerp()</code>.</li>
<li><code>Box{N, T}</code> and <code>Interval{T}</code>, to represent contiguous spaces.</li>
<li><code>Ray{N, F}</code>, and a hierarchy of <code>AbstractShape</code></li>
<li>Noise functions:
<ul dir="auto">
<li><code>perlin(pos)</code></li>
</ul>
</li>
<li><code>Contiguous{T}</code> is an alias for a wide variety of storage for some sequence of <code>T</code>. For example, <code>NTuple{10, Vec{3, Float32}}</code> is both a <code>Contiguous{Float32}</code> and a <code>Contiguous{Vec{3, Float32}}</code>.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>Bplus.GL</code></h3><a id="user-content-bplusgl" class="anchor" aria-label="Permalink: Bplus.GL" href="#bplusgl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Wraps OpenGL constructs, and provides a centralized place for a graphics context and its accompanying window. This is the big central module of B+ along with <code>Math</code>.</p>
<p dir="auto">Detailed information can be found <a href="docs/GL.md">in this document</a>, but here is a high-level overview:</p>
<ul dir="auto">
<li><code>Context</code> represents the global OpenGL context, uniquely associated with a specific thread and GLFW window.</li>
<li>Services are singletons attached to the <code>Context</code>. Some are built into B+, but you can also define your own using the <code>@bp_service</code> macro.</li>
<li><code>AbstractResource</code> is the type hierarchy for OpenGL objects, like <code>Texture</code>, <code>Buffer</code>, or <code>Mesh</code>.</li>
<li>Clear the screen with <code>clear_screen()</code>. Draw something with <code>render_mesh()</code>.</li>
</ul>

<p dir="auto">Detailed explanation available <a href="docs/Input.md">here</a>.</p>
<p dir="auto">Provides a greatly-simplified window into GLFW input, as a <a href="docs/GL.md#Services">GL Context Service</a>. Input bindings are defined in a data-driven way that is easily serialized through the <code>StructTypes</code> package.</p>
<p dir="auto">Make sure to update this service every frame with <code>service_Input_update()</code>; this is already done for you if you build your game logic within <a href="docs/Helpers.md#Game-Loop"><code>@game_loop</code></a>.</p>

<p dir="auto">Helps you integrate B+ projects with the Dear ImGUI library, exposed in Julia through the <em>CImGui.jl</em> package.</p>
<p dir="auto">Detailed information can be found in <a href="docs/GUI.md">this document</a>, but here is how you use it at a basic level:</p>
<ol dir="auto">
<li>Initialize the service with <code>service_GUI_init()</code>.</li>
<li>Start the frame with <code>service_GUI_start_frame()</code>.</li>
<li>After starting the frame, use <em>CImGui</em> as normal.</li>
<li>End the frame with <code>service_GUI_end_frame()</code></li>
</ol>
<p dir="auto">If you use <a href="docs/Helpers.md#Game-Loop"><code>@game_loop</code></a>, then this is all handled for you and you can use <em>CImGui</em> freely.</p>
<p dir="auto">To send a texture (or texture View) to the GUI system, you must wrap it with <code>gui_tex_handle(tex_or_view)</code></p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>Bplus.ECS</code></h3><a id="user-content-bplusecs" class="anchor" aria-label="Permalink: Bplus.ECS" href="#bplusecs"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A very simple entity-component system that's easy to iterate on, loosely based on Unity3D's model. If you want a high-performance, use an external Julia ECS package instead such as <em>Overseer.jl</em>.</p>
<p dir="auto">Detailed information can be found in <a href="docs/ECS.md">this document</a>, but here is a high-level overview:</p>
<ul dir="auto">
<li>A <code>World</code> is a list of <code>Entity</code> (plus accelerated lookup structures)</li>
<li>An <code>Entity</code> is a list of <code>AbstractComponent</code></li>
<li>You can add, remove, and query entities for components.
<ul dir="auto">
<li>You can also query the components across an entire <code>World</code>.</li>
</ul>
</li>
<li>You can define component types with the <code>@component</code> macro. Components have a OOP structure to them; abstract parent components can add fields, "promises" (a.k.a. abstract functions) and "configurables" (a.k.a. virtual functions).
<ul dir="auto">
<li>Refer to the <code>@component</code> doc-string for a very detailed explanation of the features and syntax.</li>
</ul>
</li>
<li>You can update an entire world with <code>tick_world(world, delta_seconds::Float32)</code>.</li>
</ul>
