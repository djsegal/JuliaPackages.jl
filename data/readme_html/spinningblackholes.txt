<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Installation</h1><a id="user-content-installation" class="anchor" aria-label="Permalink: Installation" href="#installation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The first step is to install Julia on your machine, if not already installed. This can be done by following the instructions on <a href="https://julialang.org/downloads/platform/" rel="nofollow">the official website</a>.</p>
<p dir="auto">This package is not in the official registry. You can install it (and its dependencies) by first opening a Julia REPL</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia"><pre>julia</pre></div>
<p dir="auto">and pressing the ] key to enter the Pkg REPL. Afterwards, you must specify the URL to the repository:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; add https://github.com/pgsfernandes/SpinningBlackHoles.jl"><pre>pkg<span class="pl-k">&gt;</span> add https<span class="pl-k">:</span><span class="pl-k">//</span>github<span class="pl-k">.</span>com<span class="pl-k">/</span>pgsfernandes<span class="pl-k">/</span>SpinningBlackHoles<span class="pl-k">.</span>jl</pre></div>
<p dir="auto">and that is it, the package is installed. To exit the Pkg REPL simply press backspace, and to exit Julia you can type <em>exit()</em>.</p>
<p dir="auto">To check the source code and download the examples one can git clone the repository to a suitable folder</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="git clone https://github.com/pgsfernandes/SpinningBlackHoles.jl"><pre>git clone https://github.com/pgsfernandes/SpinningBlackHoles.jl</pre></div>
<p dir="auto">To obtain the field equations for our metric ansatz, you can use whatever computer algebra system you prefer. In our examples we have used Mathematica together with the <a href="https://github.com/bshoshany/OGRe">OGRe package</a>. Instuctions for installing this package can be found at the link. The process of obtaining the field equations is time-consuming (for complicated field equations such as scalar-Gauss-Bonnet it could take about an hour or two), but needs only to be done once for every model one wants to study. To speed up the process, we recommend a quick adaptation of the OGRe package to use the Simplify function of Mathematica by default (rather than the FullSimplify function). This can be achieved by opening the OGRe.m file and replacing the three occurances of "FullSimplify" with "Simplify".</p>
<p dir="auto">To export the field equations to a format compatible with our numerical infrastructure, we use again Mathematica. Using our exporting file (GenerateSystem.nb) is highly recommended, but not necessary. One can opt e.g. to adapt one of our examples manually or write their own exporter in their favourite language.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">How to implement and run a model</h1><a id="user-content-how-to-implement-and-run-a-model" class="anchor" aria-label="Permalink: How to implement and run a model" href="#how-to-implement-and-run-a-model"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">We have two working examples of successfully implemented models in the Examples folder: general relativity and scalar-Gauss-Bonnet gravity. The first step in implementing a model is to obtain the field equations for our metric ansatz, which contains four free functions of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$r$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\theta$</math-renderer>: <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$f$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$g$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$h$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$W$</math-renderer>. These field equations can be obtained from their covariant version, e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$G_{\mu \nu} = 0$</math-renderer>, by computing the relevant geometrical quantities. The process is divided into two steps, both contained in the Deriving FEqs subfolder of each examples' directory. The first step is performed in the Mathematica file Derive_FEqs_Part_1.nb, where we provide our metric ansatz and compute the relevant geometrical quantities and effective stress-energy tensor. The equations of motion are then defined. By comparing the files for the two cases we have provided, it should be clear how different field equations could be implemented instead. For example there is an additional equation in the Gauss Bonnet case associated with the scalar field present. These quantities are then exported by the mathematica file to another file FEqs.m, such that later we can use them by simply importing the file rather than computing them again. Then, in the file Derive_FEqs_Part_2.nb, we import the file FEqs.m and manipulate the field equations by performing relevant linear combinations. Again comparing the files for the GR and Gauss-Bonnet cases is illustrative of how to adapt the code further. Finally, we perform a change of radial variable <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$x = 1-\frac{2r_H}{r}$</math-renderer> in order to use our spectral method, mapping <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$r \in [r_H, \infty[$</math-renderer> to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$x\in [-1,1]$</math-renderer>. Also, we re-label our angular coordinate <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\theta \to y$</math-renderer>. The final product is stored in the file EqsDiag.mx in the same folder. Note again that these notebooks will have to be adapted depending on the model you are considering.</p>
<p dir="auto">Now that we have our field equations, we are ready to export them to Julia code by using the Mathematica file GenerateSystem.nb. This file contains a function which receives the field equations we have just calculated as the input, and together with the appropriate boundary conditions which are defined in this file (and could be changed if needed for a new setting), outputs the necessary Julia code (including the Jacobian of the system). The function is:</p>
<div class="highlight highlight-source-mathematica notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="PrintToJulia[name, dfeqs, bcH, bcI, bcHspin, bcIspin, vars, params, Funcs, rules]"><pre><span class="pl-en">PrintToJulia</span>[<span class="pl-v">name</span>, <span class="pl-v">dfeqs</span>, <span class="pl-v">bcH</span>, <span class="pl-v">bcI</span>, <span class="pl-v">bcHspin</span>, <span class="pl-v">bcIspin</span>, <span class="pl-v">vars</span>, <span class="pl-v">params</span>, <span class="pl-v">Funcs</span>, <span class="pl-v">rules</span>]</pre></div>
<p dir="auto">where</p>
<ul dir="auto">
<li>
<em>name</em> is the name of the file to which we want to export the field equations. We typically use System.jl</li>
<li>
<em>dfeqs</em> are the field equations calculated in previous steps, contained in the file EqsDiag.mx</li>
<li>
<em>bcH</em> and <em>bcI</em> are respectively the boundary conditions for our fields/functions at the horizon and infinity, assuming that we want to provide the black hole horizon angular velocity as an input parameter. <em>bcHspin</em> and <em>bcIspin</em> are analogous, but for providing the dimensionless spin as the input</li>
<li>
<em>vars</em> are the fields present in our problem, such as our metric functions</li>
<li>
<em>params</em> are the all input parameters that our code uses, such as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$r_H$</math-renderer>...</li>
<li>
<em>Funcs</em> is related to coupling functions that might exist in our model. For example, in scalar-Gauss-Bonnet gravity we have a coupling function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$F(\phi)$</math-renderer>, which would be provided in this argument as {{F,p}}.</li>
<li>
<em>rules</em> are the string parsing rules to pass to the function in case the field equations contain some term which was not changed to Julia syntax. Example: if for some reason your field equations contain a term <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\sqrt{h}$</math-renderer>, it is likely that your generated System.jl file will contain a term Sqrt[h], which is incompatible with Julia syntax. To get rid of this term our <em>rules</em> parameter would have to be {"Sqrt[h]"-&gt;"h^(1/2)"}.</li>
</ul>
<p dir="auto">If everything was done correctly, you should now have a System.jl file in your folder. You should also have a Solver.jl file in the same folder, which is not generated by Mathematica, and must be adapted depending on the setting. Once again inspection of the Solver.jl files for the two implemented cases should make it clear how they can be adapted further.</p>

<p dir="auto">where <em>WBC</em> is the dimensionless spin of the solution, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\chi$</math-renderer>, if <em>spin</em> is true or the horizon angular velocity if <em>spin</em> is false, <em>rh</em> is the event horizon radius that we typically set to 1.0, <em>A</em> is <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\alpha/r_H^2$</math-renderer> (with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="d9f1f09df2f829d0372874ebd98605ce">$\alpha$</math-renderer> the Gauss-Bonnet coupling constant).
