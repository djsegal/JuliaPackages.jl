<p dir="auto">This is a light-weight pure-julia library for computing the nearest correlation matrix. A few algorithms are provided, including a quadratically convergent Newton algorithm.</p>

<p dir="auto">The <code>nearest_cor</code> and <code>nearest_cor!</code> methods are the "batteries included" methods for finding the nearest correlation matrix, and are designed to just work. They also have a final check to ensure that the solution is strictly positive-definite, as often that is required for other algorithms (e.g. Cholesky decomposition).</p>

<ul dir="auto">
<li><code>alias_A</code>: Whether to alias the matrix <code>A</code> or use a copy by default. When <code>true</code>,
algorithms that operate in place can save memory by reusing <code>A</code>. Defaults to <code>true</code> if
the algorithm is known not to modify <code>A</code>, and <code>false</code> otherwise.</li>
<li><code>fix_sym</code>: If <code>true</code>, then makes the input matrix symmetric if it is not already. Defaults
to <code>false</code>, and init will fail if the input matrix is not symmetric.</li>
<li><code>uplo</code>: If <code>fix_sym</code> is <code>true</code>, then the upper (<code>:U</code>) or lower (<code>:L</code>) triangle of the
input is used to make a symmetric matrix. Defaults to <code>:U</code>.</li>
<li><code>convert_f16</code>: If the algorithm does not support <code>Float16</code> values, then the input matrix
will be converted to an <code>AbstractMatrix{Float32}</code>. Defaults to <code>false</code>, and init will
fail if the algorithm does not support <code>Float16</code>.</li>
<li><code>force_f16</code>: If <code>true</code>, then the algorithm will be forced to use the input matrix, even
if the algorithm doesn't fully support <code>Float16</code> values in a stable way.</li>
<li><code>ensure_pd</code>: Checks (and corrects) that the resulting matrix is positive definite.
Defaults to <code>false</code>.</li>
<li><code>verbose</code>: Whether to print extra information. Defaults to <code>false</code>.</li>
</ul>

<p dir="auto">The following algorithms are implemented:</p>
<ul dir="auto">
<li><code>Newton</code>: An accurate and quadratically convergent algorithm</li>
<li><code>AlternatingProjections</code>: A simple linearly convergent algorithm</li>
<li><code>DirectProjection</code>: A fast, one-step projection onto the set of correlation matrices</li>
</ul>
<p dir="auto">The default algorithm is the Newton method, which offers a great balance between accuracy and speed.</p>

<p dir="auto">Because a correlation matrix is defined as only positive semi-definite, it is possible for an algorithm to converge successfully but still not be useable for other methods such as a cholesky decomposition (common in probability models). Furthermore, the smallest eigenvalues may be negative on the order of machine precision (e.g. -2.2e-16) due to the inherent nature of floating point numbers. If a positive definite matrix is absolutely required, then pass the argument <code>ensure_pd=true</code> to the solver. This will replace the smallest eigenvalues with a small positive value and reconstruct the NCM:</p>
