<p dir="auto">Low level support for ONNX files. This package is useful if you want
to investigate ONNX files in detail or create new tools to read or
write ONNX files. It is not useful if you just want to load an ONNX
file into your favorite machine learning library or run inference. For
the former, search for ONNX loading support in the library. For the
latter you can use
<a href="https://github.com/jw3126/ONNXRunTime.jl">ONNXRunTime.jl</a>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Comparison to ONNX.jl</h2><a id="user-content-comparison-to-onnxjl" class="anchor" aria-label="Permalink: Comparison to ONNX.jl" href="#comparison-to-onnxjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <a href="https://github.com/FluxML/ONNX.jl">ONNX.jl</a> package has roughly
the same purpose as this package. The fundamental difference is that
ONNXLowLevel has no dependencies apart from ProtoBuf whereas ONNX
supports saving and loading graphs with a tape representation and can
run inference on some of the ONNX operations.</p>
<p dir="auto">Both packages export the ProtoBuf generated structs but differ
slightly in their additional convenience constructors and functions.</p>

<p dir="auto">The ONNX format is defined by the <a href="proto/onnx.proto3">onnx.proto3</a>
file, which defines ProtoBuf messages and their meanings. These are
automatically converted into structs, and an ONNX file corresponds to
nested structs with a <code>ModelProto</code> at the top.</p>

<p dir="auto">All ONNX structs, such as <code>ModelProto</code>, have keyword argument
constructors, where omitted fields are set to empty or neutral values.
The struct docstring lists all fields, which can also be found in
<code>onnx.proto3</code>.</p>
<p dir="auto">Some structs and fields have names which do not match Julia's naming
rules. Those can be accessed with the <code>var"X"</code> syntax, such as
<code>var"TensorShapeProto.Dimension"</code> or <code>value_info.var"#type"</code>.</p>

<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">TensorProto</h4><a id="user-content-tensorproto" class="anchor" aria-label="Permalink: TensorProto" href="#tensorproto"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">ONNX tensors are stored in row-major format, which is contrary to
Julia's native column-major. This means that conversion between a
Julia <code>Array</code> and an ONNX <code>TensorProto</code> either needs to reverse the
dimensions or transpose the data. ONNXLowLevel chooses the former
option since transposing the data is relatively expensive and it is
easy to convert to the latter option with <code>permutedims(x, ndims(x):-1:1)</code>.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="TensorProto(name::AbstractString, x::AbstractArray)"><pre class="notranslate"><code>TensorProto(name::AbstractString, x::AbstractArray)
</code></pre></div>
<p dir="auto">Create a <code>TensorProto</code> with the given <code>name</code>. The data <code>x</code> can have
any shape and an element type of either <code>Int64</code>, <code>UInt64</code>, <code>Int32</code>,
<code>UInt32</code>, <code>Int16</code>, <code>UInt16</code>, <code>Int8</code>, <code>UInt8</code>, <code>Float64</code>, <code>Float32</code>,
<code>Float16</code>, <code>ComplexF64</code>, <code>ComplexF32</code>, <code>Bool</code>, or <code>String</code>.</p>
<p dir="auto">See a later section for support of four bit integer, 8 bit float, and
bfloat16 element types.</p>

<p dir="auto">The ONNX format includes a number of data types which are not natively
supported by Julia: <code>BFLOAT16</code>, <code>FLOAT8E4M3FN</code>, <code>FLOAT8E4M3FNUZ</code>,
<code>FLOAT8E5M2</code>, <code>FLOAT8E5M2FNUZ</code>, <code>INT4</code>, and <code>UINT4</code>.</p>
<p dir="auto">Neither of these are currently supported by ONNXLowLevel. The plan is
to support <code>BFLOAT16</code> as an extension for the <code>BFloat16s</code> package. The
other data types may get minimal support within this package.</p>
