<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">About <code>TulipaIO.jl</code> (<code>TIO</code>)</h2><a id="user-content-about-tulipaiojl-tio" class="anchor" aria-label="Permalink: About TulipaIO.jl (TIO)" href="#about-tulipaiojl-tio"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package relies on <a href="https://duckdb.org/docs/" rel="nofollow"><code>DuckDB</code></a> to tie a
variety of data sources with Julia, and <code>TulipaEnergyModel</code> (<code>TEM</code>).
It also enables a bidirectional capability to manipulate datasets from
Julia and back to DuckDB.</p>
<p dir="auto">A standard workflow requires a DuckDB connection, either to an
in-memory database, or to a database file.  Every data source is can
be made available in the database as a table, optionally importing it.
We can use SQL queries to transform and manipulate these tables into
something <code>TEM</code> can consume.  Thankfully we don't need to resort to
SQL every time.  <code>TIO</code> offers Julia functions that wrap common
transformations into a consistent API.  These functions can be chained
together to form a data processing pipeline.</p>
<p dir="auto">The package also offers parsers for data formats like ESDL.</p>
