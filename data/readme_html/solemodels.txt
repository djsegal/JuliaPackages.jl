<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">In a nutshell</h2><a id="user-content-in-a-nutshell" class="anchor" aria-label="Permalink: In a nutshell" href="#in-a-nutshell"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><em>SoleModels.jl</em> defines the building blocks of <em>symbolic</em> modeling and learning.
It features:</p>
<ul dir="auto">
<li>Definitions for symbolic models (decision trees/forests, rules, branches, etc.);</li>
<li>Tools for evaluate them, and extracting rules from them;</li>
<li>Support for mixed, neuro-symbolic computation.</li>
</ul>
<p dir="auto">These definitions provide a unified base for implementing symbolic algorithms, such as:</p>
<ul dir="auto">
<li>Decision tree/random forest learning;</li>
<li>Classification/regression rule extraction;</li>
<li>Association rule mining.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Models</h2><a id="user-content-models" class="anchor" aria-label="Permalink: Models" href="#models"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Basic models are:</p>
<ul dir="auto">
<li>Leaf models: wrapping native Julia computation (e.g., constants, functions);</li>
<li>Rules: structures with <code>IF antecedent THEN consequent END</code> semantics;</li>
<li>Branches: structures with <code>IF antecedent THEN pos_consequent ELSE neg_consequent END</code> semantics.</li>
</ul>
<p dir="auto">Remember that:</p>
<ul dir="auto">
<li>An antecedent is a logical formula that can be checked on a logical interpretation (that is, an <em>instance</em> of a symbolic learning dataset), yielding a truth value (e.g., <code>true/false</code>);</li>
<li>A consequent is another model, for example, a (final) constant model or branch to be applied.</li>
</ul>
<p dir="auto">Within this framework, a decision tree is no other than a branch with branch and final consequents.
Note that antecedents can consist of <em>logical formulas</em> and, in such case, the symbolic models
are can be applied to <em>logical interpretations</em>.
For more information, refer to <a href="https://github.com/aclai-lab/SoleLogics.jl"><em>SoleLogics.jl</em></a>, the underlying logical layer.</p>
<p dir="auto">Other noteworthy models include:</p>
<ul dir="auto">
<li>Decision List (or decision table): see <a href="https://en.wikipedia.org/wiki/Decision_list" rel="nofollow">Wikipedia</a>;</li>
<li>Decision Tree: see <a href="https://en.wikipedia.org/wiki/Decision_tree" rel="nofollow">Wikipedia</a>;</li>
<li>Decision Forest (or tree ensamble): see <a href="https://en.wikipedia.org/wiki/Random_forest" rel="nofollow">Wikipedia</a>;</li>
<li>Mixed Symbolic Model: a nested structure, mixture of many symbolic models.</li>
</ul>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Dataset structures (for logical symbolic learning)</h2><a id="user-content-dataset-structures-for-logical-symbolic-learning" class="anchor" aria-label="Permalink: Dataset structures (for logical symbolic learning)" href="#dataset-structures-for-logical-symbolic-learning"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Learning logical models (that is, models with logical formulas as antecedents)
<a href="https://scholar.google.com/scholar?q=Multi-Models+and+Multi-Formulas+Finite+Model+Checking+for+Modal+Logic+Formulas+Induction." rel="nofollow">often</a>
requires performing <a href="https://en.wikipedia.org/wiki/Model_checking" rel="nofollow">model checking</a> many times.
<em>SoleModels.jl</em> provides a set of structures for representing <a href="https://github.com/aclai-lab/SoleLogics.jl#interpretation-sets">logical datasets</a>,
specifically optimized for multiple model checking operations.</p>
