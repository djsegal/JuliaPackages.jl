<p dir="auto"><strong>Jai</strong> is an accelerator programming interfaces for <a href="http://julialang.org/" rel="nofollow">Julia</a> programmers.</p>
<p dir="auto"><strong>Jai</strong> focuses on reusing Fortran and C/C++ codes, especially for large-scale simulation applications, within Julia. Jai does not limit its support to specific languages or programming frameworks, as long as the code can be compiled as a shared library. Currently, Jai supports the basic capabilities of Fortran, C/C++, Fortran OpenMP, Fortran OpenACC, C++ OpenMP, CUDA, as well as HIP.</p>
<p dir="auto">This package is still in the early stages of development. Please use this package at your own risk.</p>

<ul dir="auto">
<li>Provides Julia users with an OpenMP-like macro interface to run CPU and GPU code.</li>
<li>Automatically generates a shared library of pre-existing Fortran/C/C++ code so that it can be called from Julia.</li>
<li>Provides a simple interface to exchange data between Julia Arrays and GPU memory.</li>
<li>Allows different CPU and GPU programming frameworks to coexist within an application.</li>
<li>Boosts the performance of original code through just-in-time compilation.</li>
</ul>

<p dir="auto">The @jkernel directive creates a Jai kernel context. The user must specify the string of the kernel, as in this example. Alternatively, the user can provide Jai with a path string to a text file that contains the kernel. To identify the kernel context, we use the literal name mykernel1.</p>
<p dir="auto">The framework clause specifies the kind of acceleration, which in this example is Fortran. The user can provide Jai with the actual compiler command line to generate a shared library. The command line should include the compiler and all compiler flags, except the -o flag, which specifies the name of the output file and the path to the input source file.</p>

<p dir="auto">The first argument to the @jlaunch directive is the name of the kernel context used in the @jkernel directive. The user then adds the names of variables to the input and output clauses accordingly. However, it is important to note that you should only use simple variable names for inputs and outputs to/from the kernel in the @jlaunch directive. For example, you cannot write something like this:</p>
