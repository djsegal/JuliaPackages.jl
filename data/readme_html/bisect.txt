<p dir="auto">If you have a snippet of Julia code that you suspect behaves differently on different
versions of a repo, you can post that code in a comment on github and ask
@LilithHafnerBot to figure out exactly which commit changed its behavior. The robot will run
a bisection and respond with its results.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Invocation syntax</h2><a id="user-content-invocation-syntax" class="anchor" aria-label="Permalink: Invocation syntax" href="#invocation-syntax"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">An invocation is a github comment with a trigger and a code block. For example,</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Let's try to bisect this.

```julia

```"><pre class="notranslate"><code>Let's try to bisect this.

@LilithHafnerBot bisect(new=main, old=v1.0.0)

```julia
using Statistics
mean([1, 2, 3]) == 2
```
</code></pre></div>
<p dir="auto">The trigger must take the form <code>@LilithHafnerBot bisect(&lt;args&gt;)</code> where <code>&lt;args&gt;</code> is
a (possibly empty) comma separated list of arguments. Each argument must be of the form
<code>&lt;key&gt;=&lt;value&gt;</code>. Supported keys are</p>
<ul dir="auto">
<li><code>new</code>: the new end of the bisection</li>
<li><code>old</code>: the old end of the bisection</li>
</ul>
<p dir="auto">Any value that can be interpreted as a revision by <code>git checkout &lt;value&gt;</code> can be used
as the value for <code>new</code> and <code>old</code>. For example, commit hashes, branch names, and tags
are all valid values.</p>
<p dir="auto">Line breaks and <code>)</code> characters are not permitted in the argument list.</p>
<p dir="auto">The code block must be a Julia code block, beginning with
<code>```julia</code> and ending with <code>```</code>. The trigger and code block must be in
the same comment.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Default values for <code>old</code> and <code>new</code></h3><a id="user-content-default-values-for-old-and-new" class="anchor" aria-label="Permalink: Default values for old and new" href="#default-values-for-old-and-new"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The default value for <code>new</code> is "HEAD", which for issues, points to the head of hhe default
branch and for pull requests, points to the head of the pull request branch (even if that
pull request is from a fork!)</p>
<p dir="auto">The default value for <code>old</code> is more complicated. We attempt to find the oldest release on
the current breaking version (e.g. "v1.0.0"). The exact details are subject to change, but the current
implementation is</p>
<ul dir="auto">
<li>Filter down to tags that can be parsed by <code>VersionString</code></li>
<li>If possible, filter out any tags that have a prerelease component</li>
<li>If there's any tag with a nonzero major version, keep only tags with the highest major version
and otherwise keep only tags with the highest minor version (prefer v1.0.0 over both 0.7.4 and
1.1.2)</li>
<li>Of the remaining tags, take the earliest according to symbolic version comparison breaking
ties lexicographically (e.g. if your repo has both a 1.0.0 tag and a v1.0.0 tag, this will
prefer 1.0.0)</li>
</ul>
<p dir="auto">If no tags are found, the default value for <code>old</code> is the oldest commit with no parents.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Security Model</h2><a id="user-content-security-model" class="anchor" aria-label="Permalink: Security Model" href="#security-model"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The @LilithHafnerBot GitHub account sends it's notifications to <code>&lt;secret-key-1&gt;@proxiedmail.com</code>.
proxiedmail.com forwards those emails to <a href="mailto:LilithHafner@gmail.com">LilithHafner@gmail.com</a> and sends an HTTP post request to
<a href="https://lilithhafner.com/lilithhafnerbot/trigger_1.php" rel="nofollow">https://lilithhafner.com/lilithhafnerbot/trigger_1.php</a> containing their content.</p>
<p dir="auto">The servers at lilithhafner.com check that the post request contains <code>&lt;secret-key-1&gt;</code> with the regex
match <code>&lt;first 10 digits of secret-key-1&gt;(\w{60})@proxiedmail.com</code> and then verifies that the hash
of the remianing 60 digits is equal to a known hash. After verifying authentication, those servers
check to see if the body of the message includes the string <code>@LilithHfanerBot bisect</code>. If so, it
uses the <code>gh</code> command line tool and an authentication token for the <code>@LilithHafnerBot</code> github account
to trigger a workflow run at <a href="https://github.com/LilithHafnerBot/bisect">https://github.com/LilithHafnerBot/bisect</a>. It sends that workflow a
freshly genereated, single use <code>&lt;key-2&gt;</code> and the URL of the comment that triggered the notification,
and saves that url and key and a timestamp localy. Then the servers add an 👀 reaction to the
triggering comment.</p>
<p dir="auto">GitHub actions automatically publically logs all arguments to the workflow trigger including <code>&lt;key-2&gt;</code>
with no way to disable that logging. The workflow itself downloads the triggering comment's content,
parses it, runs a bisection if able, and produces a comment in response. It then posts back to
<a href="https://lilithahfner.com/lilithhafnerbot/trigger_2.php" rel="nofollow">https://lilithahfner.com/lilithhafnerbot/trigger_2.php</a> a request containing the key, comment URL,
and response message.</p>
<p dir="auto">The servers at lilithhafner.com verify that the url and key exist in it's local logs with a
timestamp from the last 4 hours, verifies the message format looks plausible (notably including
a check that the length is not too long), checks that that comment url has not been responded to
before, checks that the comment contains the string <code>@LilithHafnerBot bisect</code>, logs that comment
url as having been responded to, and posts the message to github.</p>
