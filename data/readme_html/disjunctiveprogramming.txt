<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Model</h2><a id="user-content-model" class="anchor" aria-label="Permalink: Model" href="#model"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A generalized disjunctive programming (GDP) model is created using <code>GDPModel()</code>, where the optimizer can be passed at model creation, along with other keyword arguments supported by JuMP Models.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using DisjunctiveProgramming
using HiGHS

model = GDPModel(HiGHS.Optimizer)"><pre><span class="pl-k">using</span> DisjunctiveProgramming
<span class="pl-k">using</span> HiGHS

model <span class="pl-k">=</span> <span class="pl-c1">GDPModel</span>(HiGHS<span class="pl-k">.</span>Optimizer)</pre></div>
<p dir="auto">A <code>GDPModel</code> is a <code>JuMP Model</code> with a <code>GDPData</code> field in the model's <code>.ext</code> dictionary, which stores the following:</p>
<ul dir="auto">
<li><code>Logical Variables</code>: Indicator variables used for the various disjuncts involved in the model's disjunctions.</li>
<li><code>Logical Constraints</code>: Selector (cardinality) or proposition (Boolean) constraints describing the relationships between the logical variables.</li>
<li><code>Disjunct Constraints</code>: Constraints associated with each disjunct in the model.</li>
<li><code>Disjunctions</code>: Disjunction constraints.</li>
<li><code>Solution Method</code>: The reformulation technique or solution method. Currently supported methods include Big-M, Hull, and Indicator Constraints.</li>
<li><code>Reformulation Variables</code>: List of JuMP variables created when reformulating a GDP model into a MIP model.</li>
<li><code>Reformulation Constraints</code>: List of constraints created when reformulating a GDP model into a MIP model.</li>
<li><code>Ready to Optimize</code>: Flag indicating if the model can be optimized.</li>
</ul>
<p dir="auto">Additionally, the following mapping dictionaries are stored in <code>GDPData</code>:</p>
<ul dir="auto">
<li><code>Indicator to Binary</code>: Maps the Logical variables to their respective reformulated Binary variables.</li>
<li><code>Indicator to Constraints</code>: Maps the Logical variables to the disjunct constraints associated with them.</li>
</ul>
<p dir="auto">A GDP Model's <code>GDPData</code> can be accessed via:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="data = gdp_data(model)"><pre>data <span class="pl-k">=</span> <span class="pl-c1">gdp_data</span>(model)</pre></div>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Logical Variables</h2><a id="user-content-logical-variables" class="anchor" aria-label="Permalink: Logical Variables" href="#logical-variables"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Logical variables are JuMP <code>AbstractVariable</code>s with two fields: <code>fix_value</code> and <code>start_value</code>. These can be optionally specified at variable creation. Logical variables are created with the <code>@variable</code> JuMP macro by adding the tag <code>Logical</code> as the last keyword argument. As with the regular <code>@variable</code> macro, variables can be named and indexed:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@variable(model, Y[1:3], Logical)"><pre><span class="pl-c1">@variable</span>(model, Y[<span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">3</span>], Logical)</pre></div>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Logical Constraints</h2><a id="user-content-logical-constraints" class="anchor" aria-label="Permalink: Logical Constraints" href="#logical-constraints"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Two types of logical constraints are supported:</p>
<ol dir="auto">
<li>
<p dir="auto"><code>Selector</code> or cardinality constraints: A subset of Logical variables is passed and <code>Exactly</code>, <code>AtMost</code>, or <code>AtLeast</code> <code>n</code> of these is allowed to be <code>true</code>. These constraints are specified with the <code>func</code> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="bb8fab15ac47564f2ee0e0efe8ff8ebd">$\in$</math-renderer> <code>set</code> notation in <code>MathOptInterface</code> in a <code>@constraint</code> JuMP macro. It is not assumed that disjunctions have an <code>Exactly(1)</code> constraint enforced on their disjuncts upon creation. This constraint must be explicitly specified.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@constraint(model, [Y[1], Y[2]] in Exactly(1))"><pre><span class="pl-c1">@constraint</span>(model, [Y[<span class="pl-c1">1</span>], Y[<span class="pl-c1">2</span>]] <span class="pl-k">in</span> <span class="pl-c1">Exactly</span>(<span class="pl-c1">1</span>))</pre></div>
</li>
<li>
<p dir="auto"><code>Proposition</code> or Boolean constraints: These describe the relationships between Logical variables via Boolean algebra. Supported logical operators include:</p>
<ul dir="auto">
<li>
<code>∨</code> or <code>logical_or</code> or <code>||</code> (OR, typed with <code>\vee + tab</code>).</li>
<li>
<code>∧</code> or <code>logical_and</code> or <code>&amp;&amp;</code> (AND, typed with <code>\wedge + tab</code>).</li>
<li>
<code>¬</code> or <code>logical_not</code> (NOT, typed with <code>\neg + tab</code>).</li>
<li>
<code>⟹</code> or <code>implies</code> (Implication, typed with <code>\Longrightarrow + tab</code>).</li>
<li>
<code>⇔</code> or <code>iff</code> or <code>==</code> (double implication or equivalence, typed with <code>\Leftrightarrow + tab</code>).</li>
</ul>
<p dir="auto">The <code>@constraint</code> JuMP macro is used to create these constraints using <code>:=</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@constraint(model, Y[1] ⟹ Y[2] := true)"><pre><span class="pl-c1">@constraint</span>(model, Y[<span class="pl-c1">1</span>] <span class="pl-k">⟹</span> Y[<span class="pl-c1">2</span>] <span class="pl-k">:=</span> <span class="pl-c1">true</span>)</pre></div>
<p dir="auto"><em>DisjunctiveProgramming.jl</em> will automatically reformulate Logical propositions to integer programming constraints by converting these expressions to <a href="https://en.wikipedia.org/wiki/Conjunctive_normal_form" rel="nofollow">Conjunctive Normal Form</a>, and then to algebraic constraints.</p>
<p dir="auto">Variable splatting is supported in the logical operator functions <code>logical_or</code>, <code>logical_and</code>, <code>logical_not</code>, <code>implies</code>, and <code>iff</code> such that</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@constraint(model, logical_and(Y...) := true)"><pre><span class="pl-c1">@constraint</span>(model, <span class="pl-c1">logical_and</span>(Y<span class="pl-k">...</span>) <span class="pl-k">:=</span> <span class="pl-c1">true</span>)</pre></div>
<p dir="auto">is equivalent to</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@constraint(model, Y[1] ∧ Y[2] := true)"><pre><span class="pl-c1">@constraint</span>(model, Y[<span class="pl-c1">1</span>] <span class="pl-k">∧</span> Y[<span class="pl-c1">2</span>] <span class="pl-k">:=</span> <span class="pl-c1">true</span>)</pre></div>
</li>
</ol>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Disjunctions</h2><a id="user-content-disjunctions" class="anchor" aria-label="Permalink: Disjunctions" href="#disjunctions"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Disjunctions are built by first defining the constraints associated with each disjunct. This is done via the <code>@constraint</code> JuMP macro with the extra <code>Disjunct</code> tag specifying the Logical variable associated with the constraint:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@variable(model, x)
@constraint(model, x ≤ 100, Disjunct(Y[1]))
@constraint(model, x ≥ 200, Disjunct(Y[2]))"><pre><span class="pl-c1">@variable</span>(model, x)
<span class="pl-c1">@constraint</span>(model, x <span class="pl-k">≤</span> <span class="pl-c1">100</span>, <span class="pl-c1">Disjunct</span>(Y[<span class="pl-c1">1</span>]))
<span class="pl-c1">@constraint</span>(model, x <span class="pl-k">≥</span> <span class="pl-c1">200</span>, <span class="pl-c1">Disjunct</span>(Y[<span class="pl-c1">2</span>]))</pre></div>
<p dir="auto">After all disjunct constraints associated with a disjunction have been defined, the disjunction is created with the <code>@disjunction</code> macro, where the disjunction is defined as a <code>Vector</code> of Logical variables associated with each disjunct:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@disjunction(model, [Y[1], Y[2]])"><pre><span class="pl-c1">@disjunction</span>(model, [Y[<span class="pl-c1">1</span>], Y[<span class="pl-c1">2</span>]])</pre></div>
<p dir="auto">Disjunctions can be nested by passing an additional <code>Disjunct</code> tag. The Logical variable in the <code>Disjunct</code> tag specifies which disjunct, the nested disjunction belongs to:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@disjunction(model, Y[1:2], Disjunct(Y[3]))"><pre><span class="pl-c1">@disjunction</span>(model, Y[<span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">2</span>], <span class="pl-c1">Disjunct</span>(Y[<span class="pl-c1">3</span>]))</pre></div>
<p dir="auto">Empty disjuncts are supported in GDP models. When used, the only constraints enforced on the model when the empty disjunct is selected are the global constraints and any other disjunction constraints defined.</p>
<p dir="auto">For convenience, the <code>Exactly(1)</code> selector constraint is added by default when adding a disjunction to the model. In other words, <code>@disjunction(model, Y)</code> will add the disjunction and automatically add the logical constraint <code>Y in Exactly(1)</code>. For nested disjunctions, the appropriate <code>Exactly</code> constraint is added (e.g., <code>@constraint(model, Y[1:2] in Exactly(Y[3]))</code>) to indicate that <code>Exactly 1</code> logical variable in <code>Y[1:2]</code> is set to <code>true</code> when <code>Y[3]</code> is <code>true</code>, and both variables in <code>Y[1:2]</code> are set to <code>false</code> when <code>Y[3]</code> is <code>false</code>, meaning the parent disjunct is not selected. Adding the <code>Exactly</code> selector constraint by default can be disabled by setting the keyword argument <code>exactly1</code> to <code>false</code> in the <code>@disjunction</code> macro.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">MIP Reformulations</h2><a id="user-content-mip-reformulations" class="anchor" aria-label="Permalink: MIP Reformulations" href="#mip-reformulations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The following reformulation methods are currently supported:</p>
<ol dir="auto">
<li>
<p dir="auto"><a href="https://optimization.cbe.cornell.edu/index.php?title=Disjunctive_inequalities#Big-M_Reformulation%5B1%5D%5B2%5D" rel="nofollow">Big-M</a>: The <code>BigM</code> struct is created with the following optional arguments:</p>
<ul dir="auto">
<li><code>value</code>: Big-M value to use. Default: <code>1e9</code>. Big-M values are currently global to the model. Constraint specific Big-M values can be supported in future releases.</li>
<li><code>tighten</code>: Boolean indicating if tightening the Big-M value should be attempted (currently supported only for linear disjunct constraints when variable bounds have been set or specified in the <code>variable_bounds</code> field). Default: <code>true</code>.</li>
</ul>
</li>
<li>
<p dir="auto"><a href="https://optimization.cbe.cornell.edu/index.php?title=Disjunctive_inequalities#Convex-Hull_Reformulation%5B1%5D%5B2%5D" rel="nofollow">Hull</a>: The <code>Hull</code> struct is created with the following optional arguments:</p>
<ul dir="auto">
<li><code>value</code>: <code>ϵ</code> value to use when reformulating quadratic or nonlinear constraints via the perspective function proposed by <a href="https://link.springer.com/article/10.1007/s10589-020-00176-0" rel="nofollow">Furman, et al. [2020]</a>. Default: <code>1e-6</code>. <code>ϵ</code> values are currently global to the model. Constraint specific tolerances can be supported in future releases.</li>
</ul>
</li>
<li>
<p dir="auto"><a href="https://jump.dev/JuMP.jl/stable/manual/constraints/#Indicator-constraints" rel="nofollow">Indicator</a>: This method reformulates each disjunct constraint into an indicator constraint with the Boolean reformulation counterpart of the Logical variable used to define the disjunct constraint.</p>
</li>
</ol>
