<p dir="auto"><code>OptimalMatrixCompletion</code> is a Julia package which solves low-rank matrix completion problems to certifiable optimality via a custom branch-and-bound scheme. It is the implementation of the following paper: <a href="https://optimization-online.org/2023/05/optimal-low-rank-matrix-completion-semidefinite-relaxations-and-eigenvector-disjunctions/" rel="nofollow">Optimal Low-Rank Matrix Completion: Semidefinite Relaxations and Eigenvector Disjunctions</a>.</p>

<p dir="auto">To install the package:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; Pkg.install(&quot;OptimalMatrixCompletion&quot;)"><pre class="notranslate"><code>julia&gt; Pkg.install("OptimalMatrixCompletion")

<p dir="auto">To perform matrix completion on the matrix <code>A</code> with observed indices <code>indices</code>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; using OptimalMatrixCompletion

julia&gt; noise = true;

<p dir="auto">Here, <code>solution</code> is a dictionary with the following fields:</p>
<ul dir="auto">
<li>
<code>"X_initial"</code>: the solution obtained after an alternating minimization procedure at the root node.</li>
<li>
<code>"Y_initial"</code>, <code>"U_initial"</code>: obtained from <code>X_initial</code> such that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$(Y, U, X)$</math-renderer> are feasible for the master problem.</li>
<li>
<code>"objective_initial"</code>: the objective value obtained for <code>X_initial</code>.</li>
<li>
<code>"MSE_in_initial"</code>: the in-sample MSE of <code>X_initial</code> compared to the input matrix <code>A</code>
</li>
<li>
<code>"MSE_out_initial"</code>: the out-of-sample MSE of <code>X_initial</code> compared to the input matrix <code>A</code>  (this is only relevant if one has access to the unobserved values in <code>A</code>)</li>
<li>
<code>"MSE_all_initial"</code>: the overall MSE of <code>X_initial</code> compared to the input matrix <code>A</code>  (this is only relevant if one has access to the unobserved values in <code>A</code>)</li>
<li>
<code>"X"</code>: the solution obtained after the branch-and-bound algorithm.</li>
<li>
<code>"Y"</code>, <code>"U"</code>: obtained from <code>X</code> such that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$(Y, U, X)$</math-renderer> are feasible for the master problem.</li>
<li>
<code>"objective"</code>: the objective value obtained for <code>X</code>.</li>
<li>
<code>"MSE_in"</code>: the in-sample MSE of <code>X</code> compared to the input matrix <code>A</code>
</li>
<li>
<code>"MSE_out"</code>: the out-of-sample MSE of <code>X</code> compared to the input matrix <code>A</code>  (this is only relevant if one has access to the unobserved values in <code>A</code>)</li>
<li>
<code>"MSE_all"</code>: the overall MSE of <code>X</code> compared to the input matrix <code>A</code>  (this is only relevant if one has access to the unobserved values in <code>A</code>)</li>
</ul>
<p dir="auto"><code>printlist</code> is a <code>Vector{String}</code> that contains the logged output of the algorithm. <code>instance</code> is a dictionary with the following fields:</p>
<ul dir="auto">
<li><code>"run_log"</code>: a log of the branch-and-bound algorithm, documenting the number of explored and total nodes, the incumbent lower and upper bounds, the current optimality gap, and the time taken so far.</li>
<li><code>"run_details"</code>: a dictionary consisting of the parameters to <code>branchandbound_frob_matrixcomp()</code>, together with measurements on the time taken for various parts of the algorithm, and number of nodes in branch-and-bound of various categories.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Parameters</h2><a id="user-content-parameters" class="anchor" aria-label="Permalink: Parameters" href="#parameters"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>branchandbound_frob_matrixcomp()</code> has the following required parameters:</p>
<ul dir="auto">
<li>
<code>k::Int</code>, the rank constraint on the imputed matrix <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$X$</math-renderer>.</li>
<li>
<code>A::Array{Float64, 2}</code>, the observed data matrix <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$A \in \mathbb{R}^{m \times n}$</math-renderer>.</li>
<li>
<code>indices::BitMatrix</code>, the observed indices in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$A$</math-renderer> as a 0-1 matrix with 1 denoting the positions of observed entries.</li>
<li>
<code>γ::Float64</code>, the regularization parameter <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$\gamma &amp;gt; 0$</math-renderer> on the imputed matrix <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$X$</math-renderer>. A larger value indicates less regularization, while a value closer to 0 indicates more regularization.</li>
<li>
<code>λ::Float64</code>, the penalty parameter <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$\lambda$</math-renderer> on the rank of the matrix. This is typically set to 0.</li>
<li>
<code>noise::Bool</code>, whether the entries in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$A$</math-renderer> are observed with noise or noiselessly.</li>
</ul>
<p dir="auto">See below for a full list of optional paramters.</p>
<ul dir="auto">
<li><code>branching_type::Union{String, Nothing} = nothing</code>: in the situation with <code>use_disjunctive_cuts = false</code>, determining which coordinate to branch on: either "lexicographic" or "bounds" or "gradient".</li>
<li><code>branch_point::Union{String, Nothing} = nothing</code>: in the situation with <code>use_disjunctive_cuts = false</code>, determine which value to branch on: either "midpoint" or "current_point".</li>
<li><code>node_selection::String = "breadthfirst"</code>: the node selection strategy to use: either "breadthfirst" or "bestfirst" or "depthfirst" or "bestfirst_depthfirst".</li>
<li><code>bestfirst_depthfirst_cutoff::Int = 10000</code>: in the situation with <code>node_selection = "bestfirst_depthfirst"</code>, the number of nodes in the queue before the algorithm switches from <code>"bestfirst"</code> to <code>"depthfirst"</code>.</li>
<li><code>gap::Float64 = 1e-4</code>: relative optimality gap for branch-and-bound algorithm.</li>
<li><code>use_disjunctive_cuts::Bool = true</code>: whether to use eigenvector disjunctions, highly recommended to be <code>true</code>.</li>
<li><code>disjunctive_cuts_type::Union{String, Nothing} = nothing</code>: number of pieces in piecewise linear upper-approximation; either "linear" (2 pieces) or "linear2" (3 pieces) or "linear3" (4 pieces).</li>
<li><code>disjunctive_cuts_breakpoints::Union{String, Nothing} = nothing</code>: number of eigenvectors to use in constructing separation oracle, either "smallest_1_eigvec" (most negative eigenvector) or "smallest_2_eigvec" (combination of first and second most negative eigenvectors).</li>
<li><code>presolve::Bool = false</code>: in the noiseless setting (<code>noise = false</code>), whether to perform presolve, highly recommended to be <code>true</code>.</li>
<li><code>add_basis_pursuit_valid_inequalities::Bool = false</code>: in the noiseless setting (<code>noise = false</code>), whether to impose valid inequalities from determinant minors.</li>
<li><code>add_Shor_valid_inequalities::Bool = false</code>: whether to add Shor SDP inequalities to strengthen SDP relaxation at each node.</li>
<li><code>Shor_valid_inequalities_noisy_rank1_num_entries_present::Vector{Int} = [1, 2, 3, 4]</code>: if <code>add_Shor_valid_inequalities</code> is true, the set of 2-by-2 determinant minors to model with Shor SDP inequalities, based on the number of filled entries (should be some subset of <code>[1, 2, 3, 4]</code>).</li>
<li><code>add_Shor_valid_inequalities_fraction::Float64 = 1.0</code>: if <code>add_Shor_valid_inequalities</code> is true, the proportion of 2-by-2 determinant minors to model with Shor SDP inequalities.</li>
<li><code>add_Shor_valid_inequalities_iterative::Bool = false</code>: if <code>add_Shor_valid_inequalities</code> is true, whether to add them iteratively from parent node to child node.</li>
<li><code>max_update_Shor_indices_probability::Float64 = 1.0</code>: if <code>add_Shor_valid_inequalities_iterative</code> is true, the maximum probability of adding inequalities at a node.</li>
<li><code>min_update_Shor_indices_probability::Float64 = 0.1</code>, if <code>add_Shor_valid_inequalities_iterative</code> is true, the minimum probability of adding inequalities at a node.</li>
<li><code>update_Shor_indices_probability_decay_rate::Float64 = 1.1</code>: if <code>add_Shor_valid_inequalities_iterative</code> is true, the base of the exponential decay of the probability of adding inequalities at a node, as a function of depth in the tree.</li>
<li><code>update_Shor_indices_n_minors::Int = 100</code>: if <code>add_Shor_valid_inequalities_iterative</code> is true, the number of Shor SDP inequalities to add at a node whenever adding is performed.</li>
<li><code>root_only::Bool = false</code>: if true, only solves relaxation at root node</li>
<li><code>altmin_flag::Bool = true</code>: whether to perform alternating minimization at nodes in the branch-and-bound tree, highly recommended to be <code>true</code>.</li>
<li><code>max_altmin_probability::Float64 = 1.0</code>: if <code>altmin_flag</code> is true, the maximum probability of performing alternating minimization at a node.</li>
<li><code>min_altmin_probability::Float64 = 0.005</code>: if <code>altmin_flag</code> is true, the minimum probability of performing alternating minimization at a node.</li>
<li><code>altmin_probability_decay_rate::Float64 = 1.1</code>: if <code>altmin_flag</code> is true, the base of the exponential decay of the probability of performing alternating minimization at a node, as a function of depth in the tree.</li>
<li><code>use_max_steps::Bool = false</code>: whether to terminate the algorithm based on the number of branch-and-bound nodes explored.</li>
<li><code>max_steps::Int = 1000000</code>: if <code>use_max_steps</code> is true, the upper limit on number of branch-and-bound nodes explored.</li>
<li><code>time_limit::Int = 3600</code>: time limit in seconds.</li>
<li><code>update_step::Int = 1000</code>: number of branch-and-bound nodes explored per printed update.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage tips</h2><a id="user-content-usage-tips" class="anchor" aria-label="Permalink: Usage tips" href="#usage-tips"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>It is highly recommended to set the parameter <code>use_disjunctive_cuts</code> and <code>altmin_flag</code> to true (the method in the paper), which implements eigenvector disjunctions and alternating minimization at branch-and-bound nodes respectively.</li>
<li>For basis pursuit problems (the noiseless setting), it's highly recommended to set <code>presolve</code> to true, which fills in some entries based on a determinant condition on the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="41cc1437a4e4204a7ccabeb9a3ce968d">$(k+1)$</math-renderer>-by-$(k+1)$ minors.</li>
<li>The regularization parameter <code>γ</code> should be tuned according to some paramter tuning and cross-validation procedure. Bear in mind that large values of <code>γ</code>, corresponding to less regularized problems, usually corresponds to longer solution times and more nodes explored.</li>
<li>Take care in deciding the <code>add_Shor_valid_inequalities</code> parameter. If set to true, convex relaxations at each node in general take much longer to solve (especially with a large set in <code>Shor_valid_inequalities_noisy_rank1_num_entries_present</code>). This can greatly increase solution time. However, depending on the sparsity and rank regime, judicious choices of <code>Shor_valid_inequalities_noisy_rank1_num_entries_present</code> can result in a much stronger relaxation that is tight, resulting in few if any branch-and-bound nodes required.</li>
<li>Don't forget to set the <code>time_limit</code> to a reasonable value!</li>
</ul>
