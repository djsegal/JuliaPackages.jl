<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Finding homoclinic orbits</h2><a id="user-content-finding-homoclinic-orbits" class="anchor" aria-label="Permalink: Finding homoclinic orbits" href="#finding-homoclinic-orbits"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The algorithm from the paper is given below:</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="docs/resources/Listing1_pseudocode.png"><img src="docs/resources/Listing1_pseudocode.png" alt="Listing 1 from Avrutin V et al." style="max-width: 100%;"></a></p>
<p dir="auto">Note that line 11 in the pseudocode above is incorrect; it should be <strong>if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$p \in f(V_j)$</math-renderer> then</strong>.</p>
<p dir="auto">You must supply <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x^*$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}_0$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$r_{\max}$</math-renderer>, and the additional parameter <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$n_{\text{iter}}$</math-renderer> to the function <code>AvrutinSearch.homoclinic_to_equilibrium</code>.</p>
<ul dir="auto">
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f$</math-renderer> should be two vectors of <code>Float64</code> values each having the same length which, when <code>zip</code>ped together, have elements corresponding to pairs <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$(x, f(x))$</math-renderer>.
A linear interpolation of the supplied sample points is taken.
In the future we may allow you to supply more general functions, but doing so requires far more computationally inefficient methods for computing iterates of the initial target interval <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$T_0$</math-renderer>.</p>
</li>
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x^*$</math-renderer> should be a <code>Float64</code> value. Make sure that this is a repelling fixed point of the map!
The easiest way to check this is by representing <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x^*$</math-renderer> as a variable <code>x</code> and running <code>f(x) == x</code>; this should evaluate to <code>true</code>.</p>
</li>
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}_0$</math-renderer> is the initial target subset of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathbb{W}^u(x^*)$</math-renderer> being searched for.
Practically, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}_0$</math-renderer> is supplied as an <code>Interval</code> value and should contain <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x^*$</math-renderer>.
Some guidelines for selecting <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}_0$</math-renderer> are given in the paper by Avrutin et al.:</p>
<blockquote>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="docs/resources/target_set_determination.png"><img src="docs/resources/target_set_determination.png" alt="Determination of target sets from Avrutin V et al." style="max-width: 100%;"></a></p>
</blockquote>
</li>
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer> is some closed bounded interval <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$[a, b]$</math-renderer> satisfying <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x^* \in \mathcal{I}$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f(\mathcal{I}) \subseteq \mathcal{I}$</math-renderer> (the paper assumes that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f(\mathcal{I}) = \mathcal{I}$</math-renderer>, but this is unnecessary).
In practice, this should be an <code>Interval</code> value.
Currently, you do need to determine this interval by manual inspection of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f$</math-renderer>; in the future we may implement an algorithm for determination of this interval.</p>
<p dir="auto">Note that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer> can and should be chosen to be as small as possible; as long as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer> satisfies the two aforementioned requirements, any points lying outside of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer> cannot be involved in homoclinic orbits.
Moreover, there should be some positive integer <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$k$</math-renderer> such that for each <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$x \in \mathcal{I}$</math-renderer> the pre-image set <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f|_\mathcal{I}^{-1}(x)$</math-renderer> has at most <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$k$</math-renderer> many elements; otherwise the pre-image search tree may become intractibly broad.
In particular, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f$</math-renderer> should have <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$k$</math-renderer> many interval ``branches'' <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{V}_1, \dots, \mathcal{V}_k$</math-renderer> in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{I}$</math-renderer> on which its restriction is invertible.
Because the function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$f$</math-renderer> is reconstructed by linearly interpolating finitely many sample points of its graph, this branch limit is currently guaranteed.</p>
</li>
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{r_{\max}}$</math-renderer> should be a <code>UInt64</code> value.
This is a maximal depth in the pre-image search tree.
If <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{r_{\max}}$</math-renderer> is zero, there will be no maximal rank of pre-image imposed (which is probably not the best idea).</p>
</li>
<li>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$n_{\text{iter}}$</math-renderer> should be a <code>UInt64</code> value.
This controls how many forward iterates of the initially supplied target interval <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}_0$</math-renderer> are taken as a final target set <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}$</math-renderer>.
If zero, then no forward iterates are used; in this case <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T} = \mathcal{T}_0$</math-renderer>.
More iterates mean  less pre-image computation steps during search; this can drastically improve search time.</p>
</li>
</ul>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\{f_j^{-1}, \mathcal{V}_j\}_{j=1}^k$</math-renderer> is computed automatically.
We prune any <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{V}_j$</math-renderer> which lies fully within <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="93e923451ec4d9488acc902587a234c5">$\mathcal{T}$</math-renderer>.</p>
