<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">PlutoDependencyExplorer.jl</h3><a id="user-content-plutodependencyexplorerjl" class="anchor" aria-label="Permalink: PlutoDependencyExplorer.jl" href="#plutodependencyexplorerjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package (ExpressionExplorer.jl) is used by the package <a href="https://github.com/JuliaPluto/PlutoDependencyExplorer.jl">PlutoDependencyExplorer.jl</a>, which is used by Pluto.jl.</p>
<p dir="auto"><strong>ExpressionExplorer.jl</strong> looks at a single expression, and gives the definitions and references.</p>
<p dir="auto"><strong><a href="https://github.com/JuliaPluto/PlutoDependencyExplorer.jl">PlutoDependencyExplorer.jl</a></strong> looks at a series of expressions (i.e. all cells in a notebook) and gives the "topological order": the order in which to run cells, taking definitions and references into account.</p>

<p dir="auto">The main function to use is <code>compute_reactive_node(expression)</code>, which returns a <code>ReactiveNode</code>. There is also a more low-level API available: <code>compute_symbols_state</code> returning a <code>SymbolsSate</code>.</p>

<p dir="auto"><code>FunctionNameSignaturePair</code> looks like <code>FunctionNameSignaturePair([:Base, :sqrt], UInt(0xb187232b478))</code>. It contains a "hash of the function signature, minus variable names", i.e. <code>Base.sqrt(x::Int)::String</code> and <code>Base.sqrt(x::Number)</code> will have different hashes, but <code>Base.sqrt(x)</code> and <code>Base.sqrt(woww)</code> won't.</p>

<p dir="auto">ExpressionExplorer ignores the arguments of macro calls. Macros can transform an expression into anything, so the output of ExpressionExplorer for expressions with a macro call is ambiguous. For example, the expression <code>@time x</code> contains a <em>reference</em> to <code>x</code>, while <code>@gensym x</code> contains a <em>definition</em> of <code>x</code>.</p>
<p dir="auto">In this example, notice that the assignment to <code>x</code> and reference to <code>y</code> are detected, but <code>AAA</code> and <code>BBB</code> are ignored, because they happen inside a macro call argument.</p>
