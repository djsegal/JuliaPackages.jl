<p dir="auto">A Julia package for performing calculations with the <a href="https://en.wikipedia.org/wiki/Ray_transfer_matrix_analysis" rel="nofollow">ray transfer matrix (or ABCD) formalism</a>, for both 1D ray tracing and <a href="https://en.wikipedia.org/wiki/Gaussian_beam" rel="nofollow">Gaussian beam</a> propagation in the <a href="https://en.wikipedia.org/wiki/Paraxial_approximation" rel="nofollow">paraxial approximation</a>.</p>
<p dir="auto">The following introduction to the package assumes familiarity with the ABCD formalism and its utility in optical analysis and design.  In addition to the above links, the following are classic and useful introductory references:</p>
<ol dir="auto">
<li>H. Kogelnik and T. Li, "Laser Beams and Resonators", <em>Applied Optics</em> <strong>5</strong>, 1550-1567 (1966)</li>
<li>A. E. Siegman, <em>Lasers</em> (University Science Books, Sausalito, 1986)</li>
</ol>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Optical elements</h2><a id="user-content-optical-elements" class="anchor" aria-label="Permalink: Optical elements" href="#optical-elements"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This section discusses how we represent the ABCD model of optical elements and how to access their standard representation as numerical ray transfer matrices.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Fundamental elements</h3><a id="user-content-fundamental-elements" class="anchor" aria-label="Permalink: Fundamental elements" href="#fundamental-elements"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The basic type representing an optical element is <code>Element</code>.  As an abstract type, its implemented concrete types are (all physical distances taken to be in some consistent, arbitrary unit):</p>
<ul dir="auto">
<li><code>FreeSpace(L::Real)</code>: Represents a section of free space of distance represented by <code>L</code>.</li>
<li><code>ThinLens(f::Real)</code>: Represents a focusing element that behaves like a thin lens of focal length represented by <code>f</code>.  Optionally, a tilt angle represented by <code>θ</code> in radians can be specified using <code>ThinLens(f::Real,θ::Real)</code>; otherwise it defaults to <code>θ=0</code>.</li>
<li><code>Interface(η::Real)</code>: Represents an dielectric interface where <code>η</code> is the ratio of the initial to final refractive indices.  Optionally, a tilt angle represented by <code>θ</code> in radians and a radius of curvature (positive when concave side faces incoming beam) represented by <code>R</code> can be specified using <code>Interface(η::Real,θ::Real,R::Real)</code>.  Note that if either of these two are specified, they must both be specified, and otherwise they default to <code>θ=0</code> and <code>R=Inf</code>.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Additional elements</h3><a id="user-content-additional-elements" class="anchor" aria-label="Permalink: Additional elements" href="#additional-elements"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There are some additional optical elements which are physically distinct but which, in the paraxial approximation, can be represented in terms of the above elements.  Currently, the following convenience methods allow such "elements" to be constructed:</p>
<ul dir="auto">
<li><code>Mirror(R::Real,θ::Real) = ThinLens(R/2,θ)</code> represents a curved mirror with radius of curvature (positive when concave side faces incoming beam) represented by <code>R</code> and a tilt angle represented by <code>θ</code> in radians.</li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Ray transfer (ABCD) matrices</h3><a id="user-content-ray-transfer-abcd-matrices" class="anchor" aria-label="Permalink: Ray transfer (ABCD) matrices" href="#ray-transfer-abcd-matrices"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The usual ABCD formalism for calculations involve the multiplication of 2x2 matrices, as discussed in the references above. To facilitate this formalism, each element has a well-defined matrix, which is accessed by calling <code>RTM(e::Element)</code>.  For example, <code>RTM(ThinLens(100)) == [1 0 ; -1/100 1]</code> evaluates as true.  Dot syntax for broadcasting can be used to create a corresponding vector of matrices, and the corresponding elements can be multiplied up, as in</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# Total ABCD matrix for above 4-lens system

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Sagittal and tangential elements</h3><a id="user-content-sagittal-and-tangential-elements" class="anchor" aria-label="Permalink: Sagittal and tangential elements" href="#sagittal-and-tangential-elements"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In the ABCD formalism, optical components that can have a non-zero tilt relative to the optical axis (i.e., with a nonzero field <code>θ</code>) bifurcate into two distinct elements, acting differently on the sagittal and tangential components of the ray or Gaussian beam.  To represent this dual behavior, composite <code>Element</code> types called <code>Tan</code> and <code>Sag</code> wrap the fundamental <code>Element</code> types and dispatch differently on <code>RTM</code> in order to produce the respective ray transfer matrices for the tangential and sagittal components.</p>
<p dir="auto">For example, suppose the above beam expander were misaligned with a tilt angle represented by <code>θ::Real</code>.  We would represent the optical system as</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="system = [ThinLens(f,θ), FreeSpace(3f), ThinLens(2f,θ)] # Component-agnostic description of system

system_tan_RTM = reduce(*, RTM.(system_tan)) # Total matrix in the tangential component

(This latter behavior could be changed, should there be a reason for it to be otherwise...)</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Beam propagation</h2><a id="user-content-beam-propagation" class="anchor" aria-label="Permalink: Beam propagation" href="#beam-propagation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The numerical ray transfer matrices in the ABCD formalism facilitate a transfer-function-based approach to optical analysis.  However, it is also possible to take a <em>state-based</em> viewpoint, by representing the state of the ray or beam as it passes through the elements.  Here, the parameters that describe the state of the beam are modified by each element, causing the beam to evolve as it propagates through the elements.  This approach is most useful for visualizing the optical propagation of the beam, or for optimizing beam properties in the design.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Beam parameters</h3><a id="user-content-beam-parameters" class="anchor" aria-label="Permalink: Beam parameters" href="#beam-parameters"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Consistent with the ABCD formalism, we provide a description the state of a Gaussian beam (and the ray parameters) at a particular point along the optical axis.  It is represented with a concrete type <code>Beam</code> containing the following fields:</p>
<ul dir="auto">
<li><code>q</code>: The complex Gaussian beam parameter</li>
<li><code>x</code>: The transverse component of the ray perpendicular to the optical axis</li>
<li><code>k</code>: The slope of the ray relative to the optical axis</li>
<li><code>z</code>: The location at which the state is being described, along the optical axis</li>
<li><code>n</code>: The refractive index at this location</li>
<li><code>λ</code>: The physical wavelength of the (monochromatic) beam</li>
</ul>
<p dir="auto">All optical elements modify <code>x</code>, <code>k</code>, and <code>q</code>, as prescribed by the ABCD formalism.  The parameter <code>z</code> is only modified by <code>FreeSpace</code> (via addition by the field <code>L</code>), while the parameter <code>n</code> is only modified by <code>Interface</code> (via division by the field <code>η</code>).  The wavelength <code>λ</code> does not play a direct role in the (scale-free) beam propagation; it is only used for spot size calculations.</p>
<p dir="auto">A useful constructor method is <code>Beam(λ::Real,w0::Real,n0::Real=1)</code>, which represents a beam state with position represented by <code>z=0</code> in refractive index represented by <code>n0</code> and at a focus with 1/e² waist represented by <code>w0</code> (so that the Gaussian beam parameter is imaginary), provided its wavelength <code>λ</code>; furthermore, the ray position and slope are represented by <code>x=0</code> and <code>k=0</code>, respectively.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Beam transformation by an element</h3><a id="user-content-beam-transformation-by-an-element" class="anchor" aria-label="Permalink: Beam transformation by an element" href="#beam-transformation-by-an-element"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">We think of the optical elements as effecting a transformation on the beam state.  If we have an optical element represented by <code>e::Element</code> and a beam state <code>Γ::Beam</code>, there is a non-exported function <code>transform(e::Element,Γ::Beam)</code>, which returns a new instance of <code>Beam</code> with fields representing the beam state after propagation through that element.  This function is unexported because it should rarely see utility given the beamtracing functionality described in the next subsection.</p>
<p dir="auto"><strong>Note</strong>: It is very natural to use Julia's functor mechanism to represent the transformation, via some definition like <code>(e::Element)(Γ::Beam)</code> which behaves identically to the currently-implemented <code>transform(e,Γ)</code>.  Unfortunately, this is not possible at the moment due to <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="130901064" data-permission-text="Title is private" data-url="https://github.com/JuliaLang/julia/issues/14919" data-hovercard-type="issue" data-hovercard-url="/JuliaLang/julia/issues/14919/hovercard" href="https://github.com/JuliaLang/julia/issues/14919">JuliaLang/julia#14919</a>.  While an obvious workaround is to define the transformation for each concrete subtype, this is inelegant enough to be not worth it.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Beam and ray tracing</h3><a id="user-content-beam-and-ray-tracing" class="anchor" aria-label="Permalink: Beam and ray tracing" href="#beam-and-ray-tracing"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Perhaps the most useful part of this whole package is the ability to trace the beam state by providing an initial beam state and propagating it forwards using the optical elements of a given system, recording the state after each element.  For an optical system represented by <code>elems::Vector{&lt;:Element}</code> and an initial beam state represented by <code>Γ0::Beam</code>, <code>beamtrace(elems::Vector{&lt;:Element},Γ0::Beam)</code> returns an instance of <code>Vector{Beam}</code> (of length given by <code>length(elems)+1</code>) where the first item is <code>Γ0</code>, and each subsequent item is the result of applying <code>transform</code> to the previous item using the corresponding item of <code>elems</code>.</p>
