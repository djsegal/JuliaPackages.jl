<p dir="auto">The Options package provides macros that allow the simulation of optional
keyword arguments for Julia functions. Some of this functionality was
superseded by language support for keyword arguments (<a href="https://github.com/JuliaLang/julia/issues/485" data-hovercard-type="issue" data-hovercard-url="/JuliaLang/julia/issues/485/hovercard">see
#485</a>). However, the Options
package will likely remain relevant for cases where you need to pass optional
arguments to nested functions without the parent functions needing to be aware
of those arguments.</p>

<p dir="auto">Install via the Julia package manager, <code>Pkg.add("Options")</code>.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Basic usage</h1><a id="user-content-basic-usage" class="anchor" aria-label="Permalink: Basic usage" href="#basic-usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">You gain access to <code>Options</code> via</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="require(&quot;Options&quot;)
using OptionsMod"><pre class="notranslate"><code>require("Options")
using OptionsMod
</code></pre></div>
<p dir="auto">The <code>@defaults</code> macro is for writing functions that take optional parameters.
The typical syntax of such functions is:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="  function myfunc(requiredarg1, requiredarg2, ..., opts::Options)
      @defaults opts a=11 b=2a+1 c=a*b d=100
      # The function body. Use a, b, c, and d just as you would
      # any other variable. For example,
      k = a + b
      # You can pass opts down to subfunctions, which might supply
      # additional defaults for other variables aa, bb, etc.
      y = subfun(k, opts)
      # Terminate your function with check_used, then return values
      @check_used opts
      return y
  end"><pre class="notranslate"><code>  function myfunc(requiredarg1, requiredarg2, ..., opts::Options)
      @defaults opts a=11 b=2a+1 c=a*b d=100
      # The function body. Use a, b, c, and d just as you would
      # any other variable. For example,
      k = a + b
      # You can pass opts down to subfunctions, which might supply
      # additional defaults for other variables aa, bb, etc.
      y = subfun(k, opts)
      # Terminate your function with check_used, then return values
      @check_used opts
      return y
  end
</code></pre></div>
<p dir="auto">Note the function calls <code>@check_used</code> at the end; this will be discussed below.</p>
<p dir="auto">It is possible to have more than one <code>Options</code> parameter to a function, for
example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="  function twinopts(x, plotopts::Options, calcopts::Options)
      @defaults plotopts linewidth=1
      @defaults calcopts n_iter=100
      # Do stuff
      @check_used plotopts
      @check_used calcopts
  end"><pre class="notranslate"><code>  function twinopts(x, plotopts::Options, calcopts::Options)
      @defaults plotopts linewidth=1
      @defaults calcopts n_iter=100
      # Do stuff
      @check_used plotopts
      @check_used calcopts
  end
</code></pre></div>
<p dir="auto">Within a given scope, you should have only one call to <code>@defaults</code> per options
variable.</p>
<p dir="auto">The <code>@options</code> macro is typically the easiest way to <em>set</em> the value of optional
parameters for a function that has been written to use them:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content=" opts = @options a=5 b=7"><pre class="notranslate"><code> opts = @options a=5 b=7
</code></pre></div>
<p dir="auto">For a function that uses optional parameters <code>a</code> and <code>b</code>, this will override the
default settings for these parameters. You would likely call that function in
the following way:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content=" myfunc(requiredarg1, requiredarg2, ..., opts)"><pre class="notranslate"><code> myfunc(requiredarg1, requiredarg2, ..., opts)
</code></pre></div>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Argument checking</h1><a id="user-content-argument-checking" class="anchor" aria-label="Permalink: Argument checking" href="#argument-checking"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For functions that take many optional arguments, one fairly common problem is
that the relevant options may change over time, but users may not notice the
change and continue providing parameters that are no longer used by the
function. A similar scenario arises when users simply misspell an optional
parameter. In such cases the user may be quite confused about why changing the
value of those parameters has no impact on the output of the function.</p>
<p dir="auto">For this reason, the default expected behavior is for functions to check that
all optional parameters have been used by the function. This is achieved with
the <code>@check_used</code> macro. The test is performed at the end of the function body,
so that subfunctions which handle parameters not used by the parent function may
be "credited" for their usage. Each sub-function should also call <code>@check_used</code>,
for example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="  function complexfun(x, opts::Options)
      @defaults opts parent=3 both=7
      println(parent)
      println(both)
      subfun1(x, opts)
      subfun2(x, opts)
      @check_used opts
  end
  
  function subfun1(x, opts::Options)
      @defaults opts sub1=&quot;sub1 default&quot; both=0
      println(sub1)
      println(both)
      @check_used opts
  end
  
  function subfun2(x, opts::Options)
      @defaults opts sub2=&quot;sub2 default&quot; both=22
      println(sub2)
      println(both)
      @check_used opts
  end"><pre class="notranslate"><code>  function complexfun(x, opts::Options)
      @defaults opts parent=3 both=7
      println(parent)
      println(both)
      subfun1(x, opts)
      subfun2(x, opts)
      @check_used opts
  end
  
  function subfun1(x, opts::Options)
      @defaults opts sub1="sub1 default" both=0
      println(sub1)
      println(both)
      @check_used opts
  end
  
  function subfun2(x, opts::Options)
      @defaults opts sub2="sub2 default" both=22
      println(sub2)
      println(both)
      @check_used opts
  end
</code></pre></div>
<p dir="auto">Typically, unused parameters will result in an error. The user can control the
behavior this way:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content=" # throw an error if a or b is not used (the default)
 opts = @options CheckError a=5 b=2
 # issue a warning if a or b is not used

 # don't check whether a and b are used

 opts = @options CheckError a=5 b=2
 # issue a warning if a or b is not used
 opts = @options CheckWarn a=5 b=2

</code></pre></div>

<p dir="auto">As an alternative to the macro syntax, you can also say:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content=" opts = Options(CheckWarn, :a, 5, :b, 2)"><pre class="notranslate"><code> opts = Options(CheckWarn, :a, 5, :b, 2)
</code></pre></div>
<p dir="auto">The check flag is optional.</p>
<p dir="auto">The <code>@set_options</code> macro lets you add new parameters to an existing options
structure.  For example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="  @set_options opts d=99"><pre class="notranslate"><code>  @set_options opts d=99
</code></pre></div>
<p dir="auto">would add <code>d</code> to the set of parameters in <code>opts</code>, or re-set its value if it was
already supplied.</p>

<p dir="auto">The fields of the <code>Options</code> type are</p>
<ul dir="auto">
<li><code>key2index</code>: a <code>Dict</code> that looks up an integer index, given the symbol for a
variable (e.g., <code>key2index[:a]</code> for the variable <code>a</code>)</li>
<li><code>vals</code>: <code>vals[key2index[:a]]</code> is the value to be assigned to the variable <code>a</code></li>
<li><code>used</code>: A vector of booleans, one per variable, with <code>used[key2index[:a]]</code>
representing whether the value for variable <code>a</code> has been accessed by the
<code>@defaults</code> macro</li>
<li><code>check_lock</code>: A vector of booleans, one per variable. This is a "lock" that
prevents sub-functions from complaining that they did not access variables that
were intended for the parent function. <code>@defaults</code> sets the lock to true for any
options variables that have already been defined; new variables added through
<code>@set_options</code> will start with their <code>check_lock</code> set to <code>false</code>, to be handled
by a subfunction.</li>
</ul>
