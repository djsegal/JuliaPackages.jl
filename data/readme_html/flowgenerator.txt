<p dir="auto">FlowGenerator is a network flow optimization library written in Julia. Its purpose is to solve complex, large-scale problems while offering a range of advanced features, including:</p>
<ul dir="auto">
<li><strong>Multicommodity Flow</strong>: Each commodity has a source, sink, flow demand and capacity.</li>
<li><strong>Generalized Flows</strong>: Allows flow loss or gain on arcs.</li>
<li><strong>Hyper-Graph Support</strong>: Handles hyper-arcs with one head and many tails.</li>
<li><strong>Hybrid Arc Flow Domain</strong>: Flexibility in defining the flow domain of each arc as either integer or continuous</li>
<li><strong>Generic Linear Side-Constraints</strong>: Allows to model demands, resource capacities, and other practical features as side-constraints.</li>
</ul>
<p dir="auto">The library can solve a network flow problem with all these features either by using a general-purpose MIP solver or by using our prototype solver that employs column generation and other state-of-the-art techniques for large-scale optimization.</p>

<p dir="auto">By default, each arc has zero cost, infinite capacity and continuous domain. The domain can be restricted to integer using the <code>var_type = INTEGER</code> parameter. For instance, to restrict <code>arc1</code> to have integer flow, we create it as:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="arc1 = new_arc!(builder, v1, v2; cost = 1.0, var_type = INTEGER)"><pre>arc1 <span class="pl-k">=</span> <span class="pl-c1">new_arc!</span>(builder, v1, v2; cost <span class="pl-k">=</span> <span class="pl-c1">1.0</span>, var_type <span class="pl-k">=</span> INTEGER)</pre></div>
<p dir="auto">After creating the network, we need to set at least one commodity to establish a flow source and sink. Below, we create a commodity with source <code>v1</code> and sink <code>v4</code> with flow demand <code>2.0</code> and flow capacity <code>4.0</code>:</p>

<p dir="auto">The flow conservation constraints are specific to each commodity, but all commodities share the same arc capacities.</p>
<p dir="auto">To solve this problem, FlowGenerator relies on an external LP or MIP solver. We recommend using <a href="https://github.com/jump-dev/HiGHS.jl">HiGHS</a> as a high-performance open-source solver. After including the solver package (e.g., <code>using HiGHS</code>), the problem can be solved as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="problem = get_problem(builder)

<p dir="auto"><strong>Generalized Flows</strong>: To account for flow loss or gain, we can assign a multiplier to each arc. This multiplier represents the amount of incoming flow consumed to generate one unit of outgoing flow. This is done by wrapping the tail and the multiplier in a pair. For example, to define a multiplier 4.0 for the tail of <code>arc5</code>, we define it as:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="arc5 = new_arc!(builder, (v3, 4.0), v4; cost = 2.0)"><pre>arc5 <span class="pl-k">=</span> <span class="pl-c1">new_arc!</span>(builder, (v3, <span class="pl-c1">4.0</span>), v4; cost <span class="pl-k">=</span> <span class="pl-c1">2.0</span>)</pre></div>
<p dir="auto"><strong>Hyper-Graph Support</strong>: FlowGenerator also supports hyper-arcs with multiple tails. This is done by providing a dictionary in the arc construction of each tail to its corresponding multiplier. For example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="tail_to_multiplier_map = Dict(v2 =&gt; 1.0, v3 =&gt; 2.0)
arc5 = new_arc!(builder, tail_to_multiplier_map, v4; cost = 2.0)"><pre>tail_to_multiplier_map <span class="pl-k">=</span> <span class="pl-c1">Dict</span>(v2 <span class="pl-k">=&gt;</span> <span class="pl-c1">1.0</span>, v3 <span class="pl-k">=&gt;</span> <span class="pl-c1">2.0</span>)
arc5 <span class="pl-k">=</span> <span class="pl-c1">new_arc!</span>(builder, tail_to_multiplier_map, v4; cost <span class="pl-k">=</span> <span class="pl-c1">2.0</span>)</pre></div>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Theoretical and technical background</h2><a id="user-content-theoretical-and-technical-background" class="anchor" aria-label="Permalink: Theoretical and technical background" href="#theoretical-and-technical-background"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">FlowGenerator originated as a prototyping tool to solve real-world problems in the industry. It represents a generalization of the Network Flow Framework (NF-F), which was proposed in:</p>
<p dir="auto">de Lima, V.L., Iori, M. &amp; Miyazawa, F.K. Exact solution of network flow models with strong relaxations. <em>Math. Program.</em> <strong>197</strong>, 813–846 (2023). <a href="https://doi.org/10.1007/s10107-022-01785-9" rel="nofollow">https://doi.org/10.1007/s10107-022-01785-9</a>.</p>
<p dir="auto">NF-F solves network flow models with general linear side constraints, like the following:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$$\begin{align}
\min &amp; \sum_{a \in A} c_{a} \varphi_{a} &amp; \\
\text{s.t.:} &amp; \sum_{a \in \delta^+(v)} \varphi_{a} = \sum_{a \in \delta^-(v)} \varphi_{a}, &amp; \forall v \in V \setminus {v^-, v^+}, \\
&amp; Q_i^- \leq \sum_{a \in A} q_{ia} \varphi_{a} \leq Q_i^+, &amp; \forall i \in I, \\
&amp; \varphi_{a} \in \mathbb{Z}_+, &amp; \forall a \in A,
\end{align}$$</math-renderer></p>
<p dir="auto">The framework is designed to address scalability issues in network flow models with strong relaxations. Although the model solved by NF-F is fairly generic, it does not cover some key practical features common in real-life problems. These features are integrated into the generalized model underlying FlowGenerator.</p>
<p dir="auto">The model addressed by FlowGenerator is as follows:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$$\begin{align}
\min &amp; \sum_{a \in A} \sum_{k \in K} c_{a} \varphi_{ak} &amp; \\
\text{s.t.:} &amp; \sum_{a \in \delta^+(v)} \mu_{a}(v)\varphi_{ak} = \sum_{a \in \delta^-(v)} \varphi_{ak}, &amp; \forall k \in K, ~ \forall v \in V \setminus {v_k^-, v_k^+}, &amp; ~~ (1) \\
&amp; D_k^- \leq \sum_{a \in \delta^-(v)} \varphi_{ak} \leq D_k^+, &amp; \forall k \in K, v = v_k^-, &amp;~~(2) \\
&amp; Q_i^- \leq \sum_{a \in A} \sum_{k \in K} q_{ia} \varphi_{ak} \leq Q_i^+, &amp; \forall i \in I,&amp; ~~ (3) \\
&amp; 0 \leq \sum_{k \in K} \varphi_{ak} \leq b_a, &amp; \forall a \in A, &amp; ~~ (4) \\
&amp; \varphi_{a} \in \mathbb{Z}_+, &amp; \forall a \in A_Z, &amp; ~~ (5)
\end{align}$$</math-renderer></p>
<p dir="auto">In this model:</p>
<ul dir="auto">
<li>Constraints (1) represent flow conservation, where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$\mu_a(v)$</math-renderer> denotes the flow multiplier for vertex <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$v$</math-renderer> if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$v$</math-renderer> a tail of arc <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$a$</math-renderer>.</li>
<li>Constraints (2) impose a demand and capacity of flow entering the sink of each commodity <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="28ed079b3d90b4a4d2df969f6dae8066">$k \in K$</math-renderer>.</li>
<li>Constraints (3) are equivalent to the generic linear side-constraints from NF-F.</li>
<li>Constraints (4) model arc capacities.</li>
<li>Constraints (5) enforce integrality constraints on a subset of arcs.</li>
</ul>
<p dir="auto">The user of FlowGenerator can choose to solve the model either directly through a general-purpose MIP solver or by utilizing our specialized algorithms, which include:</p>
<ul dir="auto">
<li><strong>Column Generation</strong>: Solves the linear relaxation of models with huge networks.</li>
<li><strong>Reduced-Cost Variable-Fixing</strong>: Filters the network by removing arcs that are proven to not improve the best known solution.</li>
<li><strong>Bidirectional Shortest-Path Computation</strong>: Enhances column generation and variable fixing computations.</li>
<li><strong>Specialized Branching Scheme from NF-F</strong>: Specifically designed for quickly finding high-quality heuristic solutions by relying on general-purpose MIP solvers. Particularly effective in models with strong relaxations.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Limitations and future work</h2><a id="user-content-limitations-and-future-work" class="anchor" aria-label="Permalink: Limitations and future work" href="#limitations-and-future-work"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">FlowGenerator has demonstrated high performance in problem classes that are well-addressed by NF-F. However, it is important to note that it is currently in a prototype stage and is continuously evolving. Some key areas for future development and current limitations include:</p>
<ul dir="auto">
<li>
<p dir="auto"><strong>Acyclic Networks</strong>: Like in NF-F, FlowGenerator's shortest-path computations assume acyclic networks. We are planning to integrate alternative shortest-path algorithms to overcome this limitation.</p>
</li>
<li>
<p dir="auto"><strong>Strong Relaxations</strong>: Currently, the branching and variable-fixing techniques are optimized for problems with strong relaxations. As cutting planes and other strengthening techniques are not yet implemented, strong relaxation remains crucial for best performance. Future research will focus on the development and integration of generic cutting planes to strengthen relaxations.</p>
</li>
<li>
<p dir="auto"><strong>Hyper-Graph Limitations</strong>: FlowGenerator extends NF-F key components to most new features, but it faces limitations with hyper-graphs. Specifically, the bidirectional shortest-path algorithm, which is a key component, could not be efficiently extended for hyper-graphs. We plan to research and implement techniques based on forward labelling that can serve as an efficient alternative to the bidirectional approach.</p>
</li>
<li>
<p dir="auto"><strong>Resource-Constrained Network Flow</strong>: FlowGenerator currently handles resource constraints through linear global constraints. However, certain resource constraints, like time or path-dependent resources, cannot always be modeled this way. Although users can enumerate resources directly in the network definition, this approach can lead to impractically large networks. The state of the art deals with this issues by enumerating resources dynamically. This is a future research direction.</p>
</li>
</ul>
<p dir="auto">There are many open directions for improvement in the library. As part of our commitment to solving challenging problems in practice, our medium-term plan is to enhance FlowGenerator's ability to find high-quality solutions quickly, rather than focusing on proving optimality. For that, our short-term goals include:</p>
<ul dir="auto">
<li><strong>Efficient Column Generation</strong>: Generally, the ability solving the root node efficiently is a core aspect in successful integer optimization solvers. To achieve this, we plan to significantly improve the efficiency of column generation. This enhancement may involve integrating methods from pure network flow literature, such as the network simplex algorithm, exploiting hybrid arc/path generation approaches, and dual stabilization techniques.</li>
<li><strong>Primal Heuristics Based on Rounding and Diving</strong>: We plan to extend the branching scheme inspired by NF-F with further rounding and diving techniques.</li>
</ul>
