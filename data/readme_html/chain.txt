<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Summary</h2><a id="user-content-summary" class="anchor" aria-label="Permalink: Summary" href="#summary"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Chain.jl exports the <code>@chain</code> macro.</p>
<p dir="auto">This macro rewrites a series of expressions into a chain, where the result of one expression
is inserted into the next expression following certain rules.</p>
<p dir="auto"><strong>Rule 1</strong></p>
<p dir="auto">Any <code>expr</code> that is a <code>begin ... end</code> block is flattened.
For example, these two pseudocodes are equivalent:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain a b c d e f

@chain a begin
    b
    c
    d
end e f"><pre><span class="pl-c1">@chain</span> a b c d e f

<span class="pl-c1">@chain</span> a <span class="pl-k">begin</span>
    b
    c
    d
<span class="pl-k">end</span> e f</pre></div>
<p dir="auto"><strong>Rule 2</strong></p>
<p dir="auto">Any expression but the first (in the flattened representation) will have the preceding result
inserted as its first argument, unless at least one underscore <code>_</code> is present.
In that case, all underscores will be replaced with the preceding result.</p>
<p dir="auto">If the expression is a symbol, the symbol is treated equivalently to a function call.</p>
<p dir="auto">For example, the following code block</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain begin
    x
    f()
    @g()
    h
    @i
    j(123, _)
    k(_, 123, _)
end"><pre><span class="pl-c1">@chain</span> <span class="pl-k">begin</span>
    x
    <span class="pl-c1">f</span>()
    <span class="pl-c1">@g</span>()
    h
    <span class="pl-c1">@i</span>
    <span class="pl-c1">j</span>(<span class="pl-c1">123</span>, _)
    <span class="pl-c1">k</span>(_, <span class="pl-c1">123</span>, _)
<span class="pl-k">end</span></pre></div>
<p dir="auto">is equivalent to</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="begin
    local temp1 = f(x)
    local temp2 = @g(temp1)
    local temp3 = h(temp2)
    local temp4 = @i(temp3)
    local temp5 = j(123, temp4)
    local temp6 = k(temp5, 123, temp5)
end"><pre><span class="pl-k">begin</span>
    <span class="pl-k">local</span> temp1 <span class="pl-k">=</span> <span class="pl-c1">f</span>(x)
    <span class="pl-k">local</span> temp2 <span class="pl-k">=</span> <span class="pl-c1">@g</span>(temp1)
    <span class="pl-k">local</span> temp3 <span class="pl-k">=</span> <span class="pl-c1">h</span>(temp2)
    <span class="pl-k">local</span> temp4 <span class="pl-k">=</span> <span class="pl-c1">@i</span>(temp3)
    <span class="pl-k">local</span> temp5 <span class="pl-k">=</span> <span class="pl-c1">j</span>(<span class="pl-c1">123</span>, temp4)
    <span class="pl-k">local</span> temp6 <span class="pl-k">=</span> <span class="pl-c1">k</span>(temp5, <span class="pl-c1">123</span>, temp5)
<span class="pl-k">end</span></pre></div>
<p dir="auto"><strong>Rule 3</strong></p>
<p dir="auto">An expression that begins with <code>@aside</code> does not pass its result on to the following expression.
Instead, the result of the previous expression will be passed on.
This is meant for inspecting the state of the chain.
The expression within <code>@aside</code> will not get the previous result auto-inserted, you can use
underscores to reference it.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain begin
    [1, 2, 3]
    filter(isodd, _)
    @aside @info &quot;There are \$(length(_)) elements after filtering&quot;
    sum
end"><pre><span class="pl-c1">@chain</span> <span class="pl-k">begin</span>
    [<span class="pl-c1">1</span>, <span class="pl-c1">2</span>, <span class="pl-c1">3</span>]
    <span class="pl-c1">filter</span>(isodd, _)
    <span class="pl-c1">@aside</span> <span class="pl-c1">@info</span> <span class="pl-s"><span class="pl-pds">"</span>There are <span class="pl-cce">\$</span>(length(_)) elements after filtering<span class="pl-pds">"</span></span>
    sum
<span class="pl-k">end</span></pre></div>
<p dir="auto"><strong>Rule 4</strong></p>
<p dir="auto">It is allowed to start an expression with a variable assignment.
In this case, the usual insertion rules apply to the right-hand side of that assignment.
This can be used to store intermediate results.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain begin
    [1, 2, 3]
    filtered = filter(isodd, _)
    sum
end

filtered == [1, 3]"><pre><span class="pl-c1">@chain</span> <span class="pl-k">begin</span>
    [<span class="pl-c1">1</span>, <span class="pl-c1">2</span>, <span class="pl-c1">3</span>]
    filtered <span class="pl-k">=</span> <span class="pl-c1">filter</span>(isodd, _)
    sum
<span class="pl-k">end</span>

filtered <span class="pl-k">==</span> [<span class="pl-c1">1</span>, <span class="pl-c1">3</span>]</pre></div>
<p dir="auto"><strong>Rule 5</strong></p>
<p dir="auto">The <code>@.</code> macro may be used with a symbol to broadcast that function over the preceding result.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain begin
    [1, 2, 3]
    @. sqrt
end"><pre><span class="pl-c1">@chain</span> <span class="pl-k">begin</span>
    [<span class="pl-c1">1</span>, <span class="pl-c1">2</span>, <span class="pl-c1">3</span>]
    <span class="pl-c1">@.</span> sqrt
<span class="pl-k">end</span></pre></div>
<p dir="auto">is equivalent to</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain begin
    [1, 2, 3]
    sqrt.(_)
end"><pre><span class="pl-c1">@chain</span> <span class="pl-k">begin</span>
    [<span class="pl-c1">1</span>, <span class="pl-c1">2</span>, <span class="pl-c1">3</span>]
    <span class="pl-c1">sqrt</span>.(_)
<span class="pl-k">end</span></pre></div>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Motivation</h2><a id="user-content-motivation" class="anchor" aria-label="Permalink: Motivation" href="#motivation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>The implicit first argument insertion is useful for many data pipeline scenarios, like <code>groupby</code>, <code>transform</code> and <code>combine</code> in DataFrames.jl</li>
<li>The <code>_</code> syntax is there to either increase legibility or to use functions like <code>filter</code> or <code>map</code> which need the previous result as the second argument</li>
<li>There is no need to type <code>|&gt;</code> over and over</li>
<li>Any line can be commented out or in without breaking syntax, there is no problem with dangling <code>|&gt;</code> symbols</li>
<li>The state of the pipeline can easily be checked with the <code>@aside</code> macro</li>
<li>Flattening of <code>begin ... end</code> blocks allows you to split your chain over multiple lines</li>
<li>Because everything is just lines with separate expressions and not one huge function call, IDEs can show exactly in which line errors happened</li>
<li>Pipe is a name defined by Base Julia which can lead to conflicts</li>
</ul>

<p dir="auto">The <code>@chain</code> macro replaces all underscores in the following block, unless it encounters another <code>@chain</code> macrocall.
In that case, the only underscore that is still replaced by the outer macro is the first argument of the inner <code>@chain</code>.
You can use this, for example, in combination with the <code>@aside</code> macro if you need to process a side result further.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@chain df begin
    dropmissing
    filter(r -&gt; r.weight &lt; 6, _)
    @aside @chain _ begin
            select(:group)
            CSV.write(&quot;filtered_groups.csv&quot;, _)
        end
    groupby(:group)
    combine(:weight =&gt; sum =&gt; :total_weight)
end"><pre><span class="pl-c1">@chain</span> df <span class="pl-k">begin</span>
