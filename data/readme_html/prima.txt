<p dir="auto">This package is a Julia interface to the <a href="https://github.com/libprima/prima">PRIMA
library</a>, a <em>Reference Implementation for
Powell's Methods with Modernization and Amelioration</em>, by <a href="https://www.zhangzk.net/" rel="nofollow">Zaikun
Zhang</a> who re-implemented and improved algorithms
originally by <a href="https://en.wikipedia.org/wiki/Michael_J._D._Powell" rel="nofollow">M.J.D.
Powell</a> for minimizing a
multi-variate objective function possibly under constraints and without
derivatives.</p>
<p dir="auto">Depending on the problem to solve, other Julia package(s) with similar
objectives may be of interest:</p>
<ul dir="auto">
<li>
<p dir="auto"><a href="https://github.com/robertfeldt/BlackBoxOptim.jl">BlackBoxOptim</a> is a global
optimization package for single- and multi-variate problems that does not
require the objective function to be differentiable.</p>
</li>
<li>
<p dir="auto"><a href="https://github.com/bbopt/NOMAD.jl">NOMAD</a> is an interface to the <em>Mesh
Adaptive Direct Search algorithm</em> (MADS) designed for difficult black-box
optimization problems.</p>
</li>
</ul>
<p dir="auto">Formally, the algorithms provided by <code>PRIMA</code> are designed to solve problems of
the form:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="min f(x)    subject to   x ∈ Ω ⊆ ℝⁿ"><pre>min <span class="pl-c1">f</span>(x)    subject to   x <span class="pl-k">∈</span> Ω <span class="pl-k">⊆</span> ℝⁿ</pre></div>
<p dir="auto">where <code>f: Ω → ℝ</code> is the function to minimize, <code>Ω ⊆ ℝⁿ</code> is the set of feasible
variables, and <code>n ≥ 1</code> is the number of variables. The most general feasible
set is:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="Ω = { x ∈ ℝⁿ | xl ≤ x ≤ xu, Aₑ⋅x = bₑ, Aᵢ⋅x ≤ bᵢ, cₑ(x) = 0, and cᵢ(x) ≤ 0 }"><pre>Ω <span class="pl-k">=</span> { x <span class="pl-k">∈</span> ℝⁿ <span class="pl-k">|</span> xl <span class="pl-k">≤</span> x <span class="pl-k">≤</span> xu, Aₑ<span class="pl-k">⋅</span>x <span class="pl-k">=</span> bₑ, Aᵢ<span class="pl-k">⋅</span>x <span class="pl-k">≤</span> bᵢ, <span class="pl-en">cₑ</span>(x) <span class="pl-k">=</span> <span class="pl-c1">0</span>, and <span class="pl-c1">cᵢ</span>(x) <span class="pl-k">≤</span> <span class="pl-c1">0</span> }</pre></div>
<p dir="auto">where <code>xl ∈ ℝⁿ</code> and <code>xu ∈ ℝⁿ</code> are lower and upper bounds, <code>Aₑ</code> and <code>bₑ</code>
implement linear equality constraints, <code>Aᵢ</code> and <code>bᵢ</code> implement linear
inequality constraints, <code>cₑ: ℝⁿ → ℝᵐ</code> implements <code>m</code> non-linear equality
constraints, and <code>cᵢ: ℝⁿ → ℝʳ</code> implements <code>r</code> non-linear inequality
constraints.</p>
<p dir="auto">The five Powell's algorithms of the <a href="https://github.com/libprima/prima">PRIMA
library</a> are provided by the <code>PRIMA</code>
package:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>uobyqa</code> (<em>Unconstrained Optimization BY Quadratic Approximations</em>) is for
unconstrained optimization, that is <code>Ω = ℝⁿ</code>.</p>
</li>
<li>
<p dir="auto"><code>newuoa</code> is also for unconstrained optimization. According to M.J.D. Powell,
<code>newuoa</code> is superior to <code>uobyqa</code>.</p>
</li>
<li>
<p dir="auto"><code>bobyqa</code> (<em>Bounded Optimization BY Quadratic Approximations</em>) is for simple
bound constrained problems, that is <code>Ω = { x ∈ ℝⁿ | xl ≤ x ≤ xu }</code>.</p>
</li>
<li>
<p dir="auto"><code>lincoa</code> (<em>LINearly Constrained Optimization</em>) is for constrained
optimization problems with bound constraints, linear equality constraints,
and linear inequality constraints.</p>
</li>
<li>
<p dir="auto"><code>cobyla</code> (<em>Constrained Optimization BY Linear Approximations</em>) is for general
constrained problems with bound constraints, non-linear constraints, linear
equality constraints, and linear inequality constraints.</p>
</li>
</ul>
<p dir="auto">All these algorithms are trust region methods where the variables are updated
according to an affine or a quadratic local approximation interpolating the
objective function at a given number of points (set by keyword <code>npt</code> by some of
the algorithms). No derivatives of the objective function are needed. These
algorithms are well suited to problems with a non-analytic objective function
that takes time to be evaluated.</p>

methods (<em>"linear"</em> constraints includes equality and inequality linear
constraints).</p>

<p dir="auto">To use the most suitable Powell's algorithm depending on the constraints,
simply do:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="x, info = prima(f, x0; kwds...)"><pre>x, info <span class="pl-k">=</span> <span class="pl-c1">prima</span>(f, x0; kwds<span class="pl-k">...</span>)</pre></div>
<p dir="auto">To explicitly use one the specific Powell's algorithms, call one of:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="x, info = uobyqa(f, x0; kwds...)
x, info = newuoa(f, x0; kwds...)

x, info = lincoa(f, x0; kwds...)"><pre>x, info <span class="pl-k">=</span> <span class="pl-c1">uobyqa</span>(f, x0; kwds<span class="pl-k">...</span>)
x, info <span class="pl-k">=</span> <span class="pl-c1">newuoa</span>(f, x0; kwds<span class="pl-k">...</span>)
x, info <span class="pl-k">=</span> <span class="pl-c1">bobyqa</span>(f, x0; kwds<span class="pl-k">...</span>)
x, info <span class="pl-k">=</span> <span class="pl-c1">cobyla</span>(f, x0; kwds<span class="pl-k">...</span>)
x, info <span class="pl-k">=</span> <span class="pl-c1">lincoa</span>(f, x0; kwds<span class="pl-k">...</span>)</pre></div>
<p dir="auto">In any case, <code>f</code> is the objective function and <code>x0</code> specifies the initial
values of the variables (and is left unchanged). Constraints and options may be
specified by keywords <code>kwds...</code> (see below).</p>
<p dir="auto">The objective function is called as <code>f(x)</code> with <code>x</code> the variables, it must
implement the following signature:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="f(x::Vector{Cdouble})::Real"><pre><span class="pl-c1">f</span>(x<span class="pl-k">::</span><span class="pl-c1">Vector{Cdouble}</span>)<span class="pl-k">::</span><span class="pl-c1">Real</span></pre></div>
<p dir="auto">All the algorithms return a 2-tuple <code>(x, info)</code> with <code>x</code> the variables and
<code>info</code> a structured object collecting all other information. If
<code>issuccess(info)</code> is true, then the algorithm was successful and <code>x</code> is an
approximate solution of the problem.</p>
<p dir="auto">The output <code>info</code> has the following properties:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="info.fx       # value of the objective function f(x) on return
info.nf       # number of calls to the objective function

info.nl_ineq  # non-linear inequality constraints, empty vector if none"><pre>info<span class="pl-k">.</span>fx       <span class="pl-c"><span class="pl-c">#</span> value of the objective function f(x) on return</span>
info<span class="pl-k">.</span>nf       <span class="pl-c"><span class="pl-c">#</span> number of calls to the objective function</span>
info<span class="pl-k">.</span>status   <span class="pl-c"><span class="pl-c">#</span> final status code</span>
info<span class="pl-k">.</span>cstrv    <span class="pl-c"><span class="pl-c">#</span> amount of constraints violation, 0.0 if unconstrained</span>
info<span class="pl-k">.</span>nl_eq    <span class="pl-c"><span class="pl-c">#</span> non-linear equality constraints, empty vector if none</span>
info<span class="pl-k">.</span>nl_ineq  <span class="pl-c"><span class="pl-c">#</span> non-linear inequality constraints, empty vector if none</span></pre></div>
<p dir="auto">Calling one of:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="issuccess(info)
issuccess(info.status)"><pre><span class="pl-c1">issuccess</span>(info)
<span class="pl-c1">issuccess</span>(info<span class="pl-k">.</span>status)</pre></div>
<p dir="auto">yield whether the algorithm has converged. If this is the case, <code>info.status</code>
can be one of:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>PRIMA.SMALL_TR_RADIUS</code> if the radius of the trust region becomes smaller or
equal the value of keyword <code>rhobeg</code>, in other words, the algorithm has
converged in terms of variable precision;</p>
</li>
<li>
<p dir="auto"><code>PRIMA.FTARGET_ACHIEVED</code> if the objective function is smaller of equal the
value of keyword <code>ftarget</code>, in other words, the algorithm has converged in
terms of function value.</p>
</li>
</ul>
<p dir="auto">There are other possibilities which all indicate a failure. Calling one of:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="PRIMA.reason(info)
PRIMA.reason(info.status)"><pre>PRIMA<span class="pl-k">.</span><span class="pl-c1">reason</span>(info)
PRIMA<span class="pl-k">.</span><span class="pl-c1">reason</span>(info<span class="pl-k">.</span>status)</pre></div>
<p dir="auto">yield a textual explanation about the reason that leads the algorithm to stop.</p>

<p dir="auto">Assuming <code>n = length(x)</code> is the number of variables, then:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>scale</code> (default value <code>nothing</code>) may be set with a vector of <code>n</code> positive
scaling factors. If specified, the problem is solved in the scaled variables
<code>u ∈ ℝⁿ</code> such that <code>u[i] = x[i]/scale[i]</code>. If unspecified, it is assumed that
<code>scale[i] = 1</code> for all variables. Note that the objective function, the
constraints (linear and non-linear), and the bounds remain specified in the
variables. Scaling the variables is useful to improve the conditioning of the
problem, to make the scaled variables <code>u</code> having approximately the same
magnitude, and to adapt to heterogeneous variables or with different units.</p>
</li>
<li>
<p dir="auto"><code>rhobeg</code> (default value <code>1.0</code>) is the initial radius of the trust region. The
radius of the trust region is given by the Euclidean norm of the scaled
variables (see keyword <code>scale</code> above).</p>
</li>
<li>
<p dir="auto"><code>rhoend</code> (default value <code>1e-6*rhobeg</code>) is the final radius of the trust
region. The algorithm stops when the trust region radius becomes smaller or
equal <code>rhoend</code> and the status <code>PRIMA.SMALL_TR_RADIUS</code> is returned.</p>
</li>
<li>
<p dir="auto"><code>ftarget</code> (default value <code>-Inf</code>) is another convergence setting. The
algorithm stops as soon as <code>f(x) ≤ ftarget</code> and the status
<code>PRIMA.FTARGET_ACHIEVED</code> is returned.</p>
</li>
<li>
<p dir="auto"><code>iprint</code> (default value <code>PRIMA.MSG_NONE</code>) sets the level of verbosity of the
algorithm. Possible values are <code>PRIMA.MSG_EXIT</code>, <code>PRIMA.MSG_RHO</code>, or
<code>PRIMA.MSG_FEVL</code>. Note that the values that are printed by the software are
those of the scaled variables (see keyword <code>scale</code> above).</p>
</li>
<li>
<p dir="auto"><code>maxfun</code> (default <code>500*n</code>) is the maximum number of function evaluations
allowed for the algorithm. If the number of calls to <code>f(x)</code> exceeds this
value, the algorithm is stopped and the status <code>PRIMA.MAXFUN_REACHED</code> is
returned.</p>
</li>
<li>
<p dir="auto"><code>npt</code> (default value <code>2n + 1</code>) is the number of points used to approximate
the local behavior of the objective function and such that <code>n + 2 ≤ npt ≤ (n + 1)*(n + 2)/2</code>. The default value corresponds to the one recommended by
M.J.D. Powell.</p>
</li>
<li>
<p dir="auto"><code>xl</code> and <code>xu</code> (default <code>fill(+Inf, n)</code> and <code>fill(-Inf, n)</code>) are the
element-wise lower and upper bounds for the variables. Feasible variables are
such that <code>xl ≤ x ≤ xu</code>.</p>
</li>
<li>
<p dir="auto"><code>nonlinear_eq</code> (default <code>nothing</code>) may be specified with a function, say
<code>c_eq</code>, implementing non-linear equality constraints defined by <code>c_eq(x) = 0</code>. On return, the values of the non-linear equality constraints are given by
<code>info.nl_eq</code> to save calling <code>c_eq(x)</code>.</p>
</li>
<li>
<p dir="auto"><code>nonlinear_ineq</code> (default <code>nothing</code>) may be specified with a function, say
<code>c_ineq</code>, implementing non-linear inequality constraints defined by
<code>c_ineq(x) ≤ 0</code>. On return, the values of the non-linear inequality
constraints are given by <code>info.nl_ineq</code> to save calling <code>c_ineq(x)</code>.</p>
</li>
<li>
<p dir="auto"><code>linear_eq</code> (default <code>nothing</code>) may be specified as a tuple <code>(Aₑ,bₑ)</code> to
impose the linear equality constraints <code>Aₑ⋅x = bₑ</code>.</p>
</li>
<li>
<p dir="auto"><code>linear_ineq</code> (default <code>nothing</code>) may be specified as a tuple <code>(Aᵢ,bᵢ)</code> to
impose the linear inequality constraints <code>Aᵢ⋅x ≤ bᵢ</code>.</p>
</li>
</ul>
