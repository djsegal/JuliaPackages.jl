<p dir="auto">This is a small package that performs linear segmented regression: fitting
piecewise linear functions to data, and simultaneously estimating the best
breakpoints. Three algorithm are implemented, <code>sliding_window</code>, <code>top_down</code>, and
<code>shortest_path</code>.</p>

<p dir="auto">Where <code>segments = [idxs1, idxs2, ...]</code> is an array of indices, with <code>idxs1</code>
corresponding to the indices of <code>xs</code> in the first segment, <code>idxs2</code> the second
segment, etc. Minimum segment lengths are specified with <code>min_segment_length</code>.
By default, the goodness-of-fit is measured using the coefficient of
determination (R²). Each segment must have a minimum R² of <code>fit_threshold</code>. Root
mean squared error can also be used by setting <code>fit_function = :rmse</code>, and
adjusting <code>fit_threshold</code> to a dataset dependent error threshold. In this case,
the root mean squared error must be smaller than <code>fit_threshold</code> for each
segment. By default, the end of a segment is also the start of the next segment,
but this can be changed by setting <code>overlap</code> to <code>false</code> (resulting in disjoint
segmentations).</p>

<p dir="auto">Uses a sliding window approach to segment the data: initially an empty segment
is made, and data added to it until <code>fit_threshold</code> is reached. Then a new
segment is made, and the process repeats until the data is exhausted. This
algorithm is the cheapest to run, but may generate worse fits due to its
simplicity.</p>

<p dir="auto">This algorithm recursively splits the data into two parts, attempting to find
segments that are both long enough, and have a good enough fit (set via the

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Shortest path</h2><a id="user-content-shortest-path" class="anchor" aria-label="Permalink: Shortest path" href="#shortest-path"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This algorithm is <em>my take</em> on the dynamic programming approaches used by the R
packages listed below (NB: not equivalent implementations!). In essence, a
weighted directional graph is constructed, where each node corresponds to an
index of <code>xs</code>, and the edge weight between nodes corresponds to the
goodness-of-fit measure between the two nodes (segment length restrictions and
maximum error are both incorporated). The shortest weighted path that spans <code>xs</code>
is the found with <code>Graphs.a_star</code> (see
<a href="https://github.com/JuliaGraphs/Graphs.jl">Graphs.jl</a>), and should correspond to
the best segmentation.</p>
