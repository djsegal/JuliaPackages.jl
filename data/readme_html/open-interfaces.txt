<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">MaRDI Open Interfaces</h1><a id="user-content-mardi-open-interfaces" class="anchor" aria-label="Permalink: MaRDI Open Interfaces" href="#mardi-open-interfaces"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><em>MaRDI Open Interfaces</em> is a project aiming to improve interoperability
in scientific computing by removing two hurdles that computational scientists
usually face in their daily work.</p>
<p dir="auto">These hurdles are the following.
First, numerical solvers are often implemented in different programming
languages.
Second, these solvers have potentially significantly diverging interfaces
in terms of function names, order of function arguments, and the invocation
order.
Therefore, when a computational scientist wants to switch from one solver
to another, it could take non-negligible effort in code modification
and testing for the correctness.</p>
<p dir="auto"><em>Open Interfaces</em> aim to alleviate these problems by providing automatic data
marshalling between different languages and a set of interfaces for typical
numerical problems such as integration of differential equations and
optimization.</p>
<p dir="auto">This project is the part of the <a href="https://mardi4nfdi.de" rel="nofollow"><em>Mathematical Research Data Initiative
(MaRDI)</em></a>.</p>

<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="assets/arch.png"><img src="assets/arch.png" alt="Architecture of the MaRDI Open Interfaces" style="max-width: 100%;"></a></p>
<p dir="auto">This figure shows the software architecture of the <em>MaRDI Open Interfaces</em>.
There are two principal decoupled parts. The left part is user-facing
and allows a user to request an implementation of some numerical procedure
and then invoke different functions in this implementation to conduct
computations using a unified interface (Gateway)
that hides discrepancies between different implementations.
The other part (on the right) is completely hidden from the user
and works with an implementation of the interface.
Particularly, it loads the implementation and its adapter and converts
user data to the native data for the implementation.</p>

<p dir="auto">For quality assurance, we write unit tests that test communication between
different clients and solvers.
The full test suite can be run using the command</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    make test"><pre>    make <span class="pl-c1">test</span></pre></div>
<p dir="auto">Additionally, to ensure code consistency,
we use <a href="https://pre-commit.com/" rel="nofollow"><code>pre-commit</code></a>.
It is configured to run multiple checks for formatting and trailing whitespace
for all source code in the repository.
During development, the checks can be run automatically by installing
a pre-commit Git hook:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="pre-commit install"><pre class="notranslate"><code>pre-commit install
</code></pre></div>
<p dir="auto">or by invoking it manually via</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="pre-commit run --all-files"><pre class="notranslate"><code>pre-commit run --all-files
</code></pre></div>
<p dir="auto">We recommend running it automatically so that the code is pushed only after
formatting checks.</p>

<p dir="auto">Let's try using <em>Open Interfaces</em> by solving the Van der Pol equation:</p>

  \left(
    1 - x^{2}
  \right) \frac{\mathrm d x}{\mathrm d t} + x = 0, \quad
  x(0) = 2$$</math-renderer>
<p dir="auto">with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="5b272c0862d4a093ba1513b81860353b">$\mu = 1000$</math-renderer>
using different implementations of the IVP interface (interface for solving
initial-value problems for ordinary differential equations):</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="python examples/call_qeq_from_python.py [scipy_ode|sundials_cvode|jl_diffeq]"><pre>python examples/call_qeq_from_python.py [scipy_ode<span class="pl-k">|</span>sundials_cvode<span class="pl-k">|</span>jl_diffeq]</pre></div>

<p dir="auto">This script uses stiff solvers for initial-value problems, why the value

At the end of the computations, the resultant solution is displayed.</p>
