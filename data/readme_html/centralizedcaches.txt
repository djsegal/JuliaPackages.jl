<p dir="auto">CentralizedCaches.jl exists to solve the problem that you want to cache a whole bunch of stuff,
but you also want to develop your code interactively.
These means that sometimes you cache the wrong values.
So you need a way to flush all your caches in order to start fresh.</p>
<p dir="auto">It's basically a way to automate the tracking of your caches.</p>
<p dir="auto">Creating tracked caches is thread-safe, and the tracking does not prevent garbage collection.</p>

<p dir="auto">We expose a macro that is used to track a cache<code>@new_cache Dict()</code> would create a Dict type cache for example.
By default caches are tracked only by their module, but you can place extra code after to add extra keys,
such as <code>@new_cache IdDict() :solutions</code> would create a cache that is tracked by module and then within that under the key <code>solutions</code>.</p>
<p dir="auto">Calling <code>clear_all_caches!(MyModule)</code> called <code>empty!</code> on all caches that are tracked which were declared within <code>MyModude</code>.
and <code>clear_all_caches!(MyModule, :solutions)</code> which calls <code>empty!</code> on the subset of these that were also declared with the <code>:solutions</code> key.
You can call <code>clear_all_caches()</code> without specifying any modules at all, but that will clear caches including potentially in other packages you know nothing about, so if (for example) you had that running in a background thread you might break something by emptying a cache you knew nothing about while it is being read from.</p>
<p dir="auto">Generally you would never all <code>clear_all_caches!</code> in your package code, but rather you would call it manually from the REPL while interactively developing.</p>
