<p dir="auto"><strong>Tools for point-of-interest (POI) extraction, walkability/attractiveness indexes and tiling of XML map data</strong></p>
<p dir="auto"><code>OSMToolset</code> package provides the tools for efficient extraction of <a href="https://en.wikipedia.org/wiki/Point_of_interest" rel="nofollow">point-of-interest</a> from maps and building various custom <a href="https://en.wikipedia.org/wiki/Walkability" rel="nofollow">walkability</a> indexes  in <a href="https://julialang.org/" rel="nofollow">Julia</a>.</p>

<ol dir="auto">
<li>Export points-of-interests (POIs) from a OSM xml map file to a <a href="https://github.com/JuliaData/DataFrames.jl"><code>DataFrame</code></a></li>
<li>A spatial attractiveness index for analyzig location attractivenss across maps (can be used for an example in research of city's walkability index)</li>
<li>A spatial index for finding nearest nodes in maps to a given <code>LLA</code> or <code>ENU</code> coordinates</li>
<li>OSM map tiling/slicing - functionality to tile a large OSM file into smaller tiles without loosing connections on the tile edge. The map tiling works directly on XML files</li>
</ol>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="docs/src/Boston_restaurant.png"><img src="docs/src/Boston_restaurant.png" alt="Restaurant walkability" style="max-width: 100%;"></a>
<br>(a complete code for this visualization can be found <a href="https://pszufe.github.io/OSMToolset.jl/dev/visualize/" rel="nofollow">in the docs</a>)</p>
<p dir="auto">Please note that the maps provided by the <a href="https://www.openstreetmap.org/" rel="nofollow">OpenStreetMap</a> project contain very detailed information about schools, businesses, shops, restaurants, cafes, parking spaces, hospitals etc. With this tool you get an effient, customizable API for extraction of data on such points of interests for further processing. This information can be further used e.g. to build walkability indexes that can be used to explain attractiveness of some parts of a city. Hence the second functionality of the package is to provide an interface (based on the <a href="https://github.com/alyst/SpatialIndexing.jl"><code>SpatialIndexing</code></a> package) for building of efficient attractiveness indexes of any urban area.
Since the OSM map XML files are usully very large, sometimes it is required to tile the files into smailler chunks for efficient parallel processing. Hence, yet another functionality of this package is an OSM file tiler.</p>
<p dir="auto">This toolset has been constructed with performance in mind for large scale scraping of spatial data.
Hence, this package should work sufficiently well with datasets of size of entire states or countries.</p>

<p dir="auto">The native format for OSM files is XML. The files are often huge and for many processing scenarios it might make sense to slice them into smaller portions. That is where this functionality becomes handy.</p>
<p dir="auto">The file tiling can be executed as follows:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="outfiles = tile_osm_file(&quot;file.osm&quot;, nrow=2, ncol=3, out_dir=&quot;some/target/directory&quot;)"><pre class="notranslate"><code>outfiles = tile_osm_file("file.osm", nrow=2, ncol=3, out_dir="some/target/directory")
</code></pre></div>
<p dir="auto">After the execution <code>outfile</code> will be a matrix with file names of all tiles.</p>

<p dir="auto">The OSM tiler is simultanously opening a file writer for each file. The operating system might limit the number of simultanously opened file descriptors. If you want to create large number of tiles you need to either change the operating system setting accordingly or use a recursive approach to file tiling.</p>
