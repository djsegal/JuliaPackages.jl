<p dir="auto">The <a href="https://github.com/org-arl/UnderwaterAcoustics.jl"><code>UnderwaterAcoustics.jl</code></a> project provides a unified interface to many underwater acoustic propagation models including such as <a href="https://org-arl.github.io/UnderwaterAcoustics.jl/stable/pm_pekeris.html" rel="nofollow"><code>PekerisRayModel</code></a>, <a href="https://github.com/org-arl/AcousticRayTracers.jl"><code>RaySolver</code></a>, <a href="https://github.com/org-arl/AcousticsToolbox.jl">Bellhop, Kraken</a>, etc. This project leverages these models to provide a real-time streaming ocean acoustic simulator for software-only or hardware-in-the-loop simulations. The data streams simulate analog-to-digital convertors (ADC) and digital-to-analog convertors (DAC) in acoustic systems.</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using UnderwaterAcoustics

<p dir="auto">Once the simulation is up and running, we can connect to the Virtual Acoustic Ocean and stream acoustic data from various nodes. For example, in the above simulation (with the Grogu UDP protocol), we will have the following UDP ports open once the simulator is running:</p>
<ul dir="auto">
<li><code>9809</code> – command port for node 1 (single channel data)</li>
<li><code>9810</code> – DAC data port for node 1 (single output channel)</li>
<li><code>9819</code> – command port for node 2 (single channel data)</li>
<li><code>9820</code> – DAC data port for node 2 (single output channel)</li>
<li><code>9829</code> – command port for node 3 (4-channel data stream)</li>
<li><code>9830</code> – DAC data port for node 3 (single output channel)</li>
</ul>
<p dir="auto">ADC data can be streamed from any of the nodes by sending a <code>istart</code> command and specifying the UDP port to stream the data to.</p>

<p dir="auto">While the Virtual Acoustic Ocean currently only supports the <a href="./docs/grogu-protocol.md">Grogu UDP real-time streaming protocol</a>, the code is designed to easily allow users to implement their own streaming protocols. If you implement a standard protocol that you feel may be useful to others, please do consider contributing the implementation back to this repository via a pull request (PR).</p>
<p dir="auto">To implement a new protocol, create a new data type (e.g. <code>MyProtocol</code>) and support the following API:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="MyProtocol(client)

<p dir="auto"><code>data</code> matrix contains samples scaled in the ±1 range, with each column containing data for one channel. <code>timestamp</code> are in µs from an arbitrary time origin. <code>seqno</code> is a running packet number for streaming data. <code>id</code> is an opaque numeric ID identifying the tranmission for which an event (transmission start <code>ostart</code> and transmission end <code>ostop</code>) is sent.</p>
<p dir="auto">For detailed documentation on what each API function should do, refer to the Grogu UDP protocol <a href="./src/grogu.jl">implementation</a>.</p>
<p dir="auto">The protocol implementation may call the following API:</p>

<p dir="auto">Currently, the Virtual Acoustic Ocean makes a quasi-static assumption:</p>
<ul dir="auto">
<li>Node reception time is computed at time of transmission, and therefore does not account for any node motion while the transmission is in flight. This is a reasonable simplification for slow moving nodes and short distances, but may not hold at very long range communication.</li>
<li>Node motion does not induce any Doppler in the reception.</li>
</ul>
