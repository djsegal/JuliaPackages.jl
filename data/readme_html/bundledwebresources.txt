<p dir="auto"><em>Automatic local bundling of remote resources as relocatable Julia objects</em></p>
<p dir="auto">A small Julia package to automate the process of bundling web resources from
remote URLs (usually CDNs) into embedded relocatable content that can then be
served from a single server rather than from multiple third-party sources.</p>

CSS bundlers, can be made to participate in the same system but using the

<p dir="auto">The <code>LocalResource</code> type accepts a third optional argument that is a function
<code>(directory, file) -&gt; content</code> that can be used to generate the content of the

generate resources from other resources, such as TypeScript to JavaScript conversion
using the experimental <code>bun_build</code> function.</p>

<p dir="auto">The main use case of these resources is serving them to clients via an HTTP
server. A <code>ResourceRouter(mod::Module)</code> function is exported for this use. You
can define a router for all resources defined in a <code>Module</code> that can be used in
an <code>HTTP.jl</code> server. When <code>Revise</code> is loaded these resources will "live
updated", otherwise they'll remain as static content in production builds that
don't include <code>Revise</code>.</p>

<p dir="auto">Experimental support for bundling web resources is provided via the <code>bun</code>
command-line tool which is provided via the Julia artifacts system and does not
need to be installed manually. <strong>Note that <code>bun</code> does not currently support
Windows.</strong> The <code>BundledWebResources.bun</code> function will throw an error on that
platform currently.</p>
<p dir="auto">A <code>watch</code> function is provided that can register a callback function to be run
each time the <code>bun build</code> rebuilds the bundled files. This can be used to
trigger browser reloads or other actions.</p>

<p dir="auto">Rather than manually downloading and installing fonts to be served by an
application (instead of a CDN) you can use <code>BundledWebResources</code> to bundle
fonts into your application and serve them from there.</p>
<p dir="auto"><a href="https://fontsource.org" rel="nofollow">Fontsource</a> is a good source for retrieving fonts from
for this purpose. Locate a font, or several, for example
<a href="https://fontsource.org/fonts/inter" rel="nofollow">Inter</a>. Navigate to the CDN tab and select
the variants you want to include in your application.</p>
<p dir="auto">Find the current version of the font (rather than using <code>latest</code>, which will
change over time and void the <code>sha256</code> hash). This can be found on the <code>NPM</code>
link on the font page. Also find the URL to use for the font, which will be
<code>url()</code> in the required CSS content. Something like
<code>https://cdn.jsdelivr.net/fontsource/fonts/inter:vf@latest/latin-wght-normal.woff2</code>.
Switch the <code>latest</code> for the version number. E.g.
<code>https://cdn.jsdelivr.net/fontsource/fonts/inter:vf@5.0.16/latin-wght-normal.woff2</code>
so that the <code>sha256</code> hash will be stable.</p>
