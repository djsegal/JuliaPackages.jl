<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Introduction</h2><a id="user-content-introduction" class="anchor" aria-label="Permalink: Introduction" href="#introduction"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package implements a interface in Julia to the taylor tool created by <a href="http://www.maia.ub.es/~angel/" rel="nofollow">Àngel Jorba</a> and contributors. taylor translates movement equations given in a text file to highly efficient C code, also allowing the integration of arbitrary degree jet transport. Its features include:</p>
<ul dir="auto">
<li>parallelisable code (using OpenMP)</li>
<li>flexibility in number type (double, complex, MPFR, user-defined...)</li>
</ul>
<p dir="auto">For more information, <a href="http://www.maia.ub.es/~angel/taylor/" rel="nofollow">see here</a>.</p>
<p dir="auto">At the moment, TaylorInterface supports jet transport for one variable or one symbol, and doesn't support parallelisation of the C code or changing the number type from double. As taylor currently only works on Linux systems, so does TaylorInterface.</p>
<p dir="auto">This package is still in development; feel free to contact me for any questions, suggestions or remarks!</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">First approach</h2><a id="user-content-first-approach" class="anchor" aria-label="Permalink: First approach" href="#first-approach"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package introduces two structures: <code>TaylorGenerator</code> generates a directory containing the files corresponding to a given equation file, and <code>TaylorHandler</code> opens the library thus generated and serves as an interface to access its functions.</p>
<p dir="auto">First, you need an equation file, which looks like this (for more information, see the <a href="https://github.com/joang/taylor2-dist/blob/main/src/manual/manual.pdf">taylor manual</a>):</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="const1 = 3.14;
const2 = 42.;

var1 = 2*x + const1;

diff(x, t) = px;
diff(px, t) = var1 + const2 * x * x;

jet x, px symbols 2 deg 1;"><pre class="notranslate"><code>const1 = 3.14;
const2 = 42.;

var1 = 2*x + const1;

diff(x, t) = px;
diff(px, t) = var1 + const2 * x * x;

jet x, px symbols 2 deg 1;
</code></pre></div>
<p dir="auto">Let's save this in a file, namely <code>eqs.txt</code>. Now, we create a <code>TaylorGenerator</code> and generate a directory:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using TaylorInterface

generator = TaylorGenerator(&quot;eqs.txt&quot;)
generate_dir(generator)"><pre><span class="pl-k">using</span> TaylorInterface

generator <span class="pl-k">=</span> <span class="pl-c1">TaylorGenerator</span>(<span class="pl-s"><span class="pl-pds">"</span>eqs.txt<span class="pl-pds">"</span></span>)
<span class="pl-c1">generate_dir</span>(generator)</pre></div>
<p dir="auto">This will create a directory, copy the equation file in it, call taylor on this file, wrap the generated C files with some convenience functions, and compile them in a <code>lib.so</code> file in the directory. By default, the directory sits in the current directory, and is named <code>taylor_[RANDOM_STRING]</code>, but you can change both parameters with <code>parent_path</code> and <code>name</code> respectively.</p>
<p dir="auto">Now, to open the generated library, we get a <code>TaylorHandler</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="handler = get_handler(generator, false)"><pre>handler <span class="pl-k">=</span> <span class="pl-c1">get_handler</span>(generator, <span class="pl-c1">false</span>)</pre></div>
<p dir="auto">If you have the <code>TaylorGenerator</code> corresponding to the directory you want to open, you can use <code>get_handler</code> as we just did. Otherwise, you need the path to the directory stored in a string; if this string is stored in <code>path</code>, then you can use</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="handler = TaylorHandler(path)"><pre>handler <span class="pl-k">=</span> <span class="pl-c1">TaylorHandler</span>(path)</pre></div>
<p dir="auto">To open the library, we use</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="open_lib(handler)"><pre><span class="pl-c1">open_lib</span>(handler)</pre></div>
<p dir="auto">Now, the loaded library is in <code>handler.lib</code>, and a dictionary to some of its functions is stored in <code>handler.symbols</code>. For instance, let's call the Poincaré map for our above example, and for a duration of 1.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="in = [0., 1.]

<p dir="auto">We propose some default models that come with the package; you can get them with</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="get_model(modelname)"><pre><span class="pl-c1">get_model</span>(modelname)</pre></div>
<p dir="auto">At the moment, we propose:</p>
<ul dir="auto">
<li><code>rpb_sun_earth</code>, the restricted three-body problem for the Sun+Earth system, in synodic (co-rotating) coordinates, assuming circular motion</li>
<li><code>bcp_sun_earth_jupiter</code> and <code>bcp_sun_earth_venus</code>, where we add a perturbation from a planet in circular motion either Jupiter or Venus (the model is called bicircular)</li>
<li><code>rpb_SE_nojet</code>, the same problem as the first, but whereas for the three other cases we computed first-order variational equations, here we remove jet transport for speed.</li>
</ul>
<p dir="auto">Note that you will need to compile the model with <code>compile_eqs(handler)</code> in order to use it.</p>
