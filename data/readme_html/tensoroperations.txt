<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What's new in v5</h2><a id="user-content-whats-new-in-v5" class="anchor" aria-label="Permalink: What's new in v5" href="#whats-new-in-v5"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">Support for cuTENSOR v2 and with that more recent versions of <a href="https://github.com/JuliaGPU/CUDA.jl">CUDA.jl</a>.</p>
</li>
<li>
<p dir="auto">Improved support for automatic differentiation using reverse-mode rules with <a href="https://github.com/JuliaDiff/ChainRulesCore.jl">ChainRulesCore.jl</a>.</p>
</li>
<li>
<p dir="auto">Improved and extended support for backends and allocation strategies, with in particular support for allocating temporary objects using <a href="https://github.com/MasonProtter/Bumper.jl">Bumper.jl</a>.</p>
</li>
<li>
<p dir="auto">Breaking changes to part of the interface to make it more sustainable for future improvements and extensions.</p>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What's new in v4</h2><a id="user-content-whats-new-in-v4" class="anchor" aria-label="Permalink: What's new in v4" href="#whats-new-in-v4"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">The <code>@tensor</code> macro now accepts keyword arguments to facilitate a variety of options that help with debugging, contraction cost and backend selection.</p>
</li>
<li>
<p dir="auto">Experimental support for automatic differentiation has been added by adding reverse-mode chainrules.</p>
</li>
<li>
<p dir="auto">The interface for custom types has been changed and thoroughly documented, making it easier to know what to implement. This has as a consequence that more general element types of tensors are now also possible.</p>
</li>
<li>
<p dir="auto">There is a new interface to work with backends, to allow for dynamic switching between different implementations of the primitive tensor operations or between different strategies for allocating new tensor objects.</p>
</li>
<li>
<p dir="auto">The support for <code>CuArray</code> objects is moved to a package extension, to avoid unnecessary CUDA dependencies for Julia versions &gt;= 1.9</p>
</li>
<li>
<p dir="auto">The cache for temporaries has been removed due to its inconsistent and intricate interplay with multithreading.
However, the new feature of specifying custom allocation strategies can be used to experiment with novel cache-like behaviour in the future.</p>
</li>
</ul>
<blockquote>
<p dir="auto"><strong>WARNING:</strong> TensorOperations 4.0 contains several breaking changes and cannot generally be expected to be compatible with previous versions.</p>
</blockquote>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Code example</h3><a id="user-content-code-example" class="anchor" aria-label="Permalink: Code example" href="#code-example"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">TensorOperations.jl is mostly used through the <code>@tensor</code> macro which allows one
to express a given operation in terms of
<a href="https://en.wikipedia.org/wiki/Abstract_index_notation" rel="nofollow">index notation</a> format,
a.k.a. <a href="https://en.wikipedia.org/wiki/Einstein_notation" rel="nofollow">Einstein notation</a>
(using Einstein's summation convention).</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using TensorOperations
α = randn()
A = randn(5, 5, 5, 5, 5, 5)
B = randn(5, 5, 5)
C = randn(5, 5, 5)
D = zeros(5, 5, 5)
@tensor begin
    D[a, b, c] = A[a, e, f, c, f, g] * B[g, b, e] + α * C[c, a, b]
    E[a, b, c] := A[a, e, f, c, f, g] * B[g, b, e] + α * C[c, a, b]
end"><pre><span class="pl-k">using</span> TensorOperations
α <span class="pl-k">=</span> <span class="pl-c1">randn</span>()
A <span class="pl-k">=</span> <span class="pl-c1">randn</span>(<span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>)
B <span class="pl-k">=</span> <span class="pl-c1">randn</span>(<span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>)
C <span class="pl-k">=</span> <span class="pl-c1">randn</span>(<span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>)
D <span class="pl-k">=</span> <span class="pl-c1">zeros</span>(<span class="pl-c1">5</span>, <span class="pl-c1">5</span>, <span class="pl-c1">5</span>)
<span class="pl-c1">@tensor</span> <span class="pl-k">begin</span>
    D[a, b, c] <span class="pl-k">=</span> A[a, e, f, c, f, g] <span class="pl-k">*</span> B[g, b, e] <span class="pl-k">+</span> α <span class="pl-k">*</span> C[c, a, b]
    E[a, b, c] <span class="pl-k">:=</span> A[a, e, f, c, f, g] <span class="pl-k">*</span> B[g, b, e] <span class="pl-k">+</span> α <span class="pl-k">*</span> C[c, a, b]
<span class="pl-k">end</span></pre></div>
<p dir="auto">In the second to last line, the result of the operation will be stored in the
preallocated array <code>D</code>, whereas the last line uses a different assignment
operator <code>:=</code> in order to define and allocate a new array <code>E</code> of the correct
size. The contents of <code>D</code> and <code>E</code> will be equal.</p>
<p dir="auto">For more detailed information, please see the documentation.</p>
