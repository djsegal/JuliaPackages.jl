<p dir="auto"><em>A Julia ecosystem for Quadratic Unconstrained Binary Optimization</em></p>

<p dir="auto"><a href="https://github.com/psrenergy/QUBO.jl">QUBO.jl</a> is an all-in-one package for working with QUBO models in <a href="https://github.com/jump-dev/JuMP.jl">JuMP</a> and interfacing with their solvers.
This project aggregates and extends functionality from its complementary packages <a href="https://github.com/psrenergy/ToQUBO.jl">ToQUBO.jl</a>, <a href="https://github.com/psrenergy/QUBODrivers.jl">QUBODrivers.jl</a> and <a href="https://github.com/psrenergy/QUBOTools.jl">QUBOTools.jl</a>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">QUBO? 🟦</h2><a id="user-content-qubo-" class="anchor" aria-label="Permalink: QUBO? 🟦" href="#qubo-"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">QUBO is an acronym for <strong>Quadratic Unconstrained Binary Optimization</strong>, a notorious family of Combinatorial Optimization problems.
Recently, significant advances in computing systems and algorithms specialized for sampling QUBO solutions have contributed to its increasing popularity.</p>
<p dir="auto">These novel tools include Quantum Annealing, Quantum Gate-Circuit Optimization Algorithms (Quantum Optimization Alternating Ansatz, Variational Quantum Eigensolver), other hardware-accelerated platforms, such as Coherent Ising Machines and Simulated Bifurcation Machines, not to mention traditional methods such as Simulated Annealing and Parallel Tempering.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Mathematical Model</h3><a id="user-content-mathematical-model" class="anchor" aria-label="Permalink: Mathematical Model" href="#mathematical-model"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Conceptually speaking, it is an optimization model with a <strong>quadratic objective function</strong> on <strong>binary variables</strong> and <strong>no constraints</strong>.
Despite being very simple, these models are capable of representing other nonconvex global optimization problems.</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$$\begin{array}{rl}
  \min &amp; \alpha \left[\mathbf{x}' \mathbf{Q}\,\mathbf{x} + \mathbf{\ell}' \mathbf{x} + \beta \right] \\\
  \textrm{s.t.} &amp; \mathbf{x} \in \lbrace{0, 1}\rbrace^{n}
\end{array}$$</math-renderer>
<details>
    <summary><strong>Show Description</strong></summary>
<p dir="auto">Analizing the model attentively, let <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\mathbf{x}$</math-renderer> be a <strong>vector of boolean (zero-one) variables</strong>.
Take also the <strong>vector of linear terms</strong> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\mathbf{\ell} \in \mathbb{R}^{n}$</math-renderer> and the <strong>strictly upper triangular matrix of quadratic terms</strong> <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\mathbf{Q} \in \mathbb{R}^{n \times n}$</math-renderer>.
Last but not least, consider <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\alpha, \beta \in \mathbb{R}$</math-renderer> as the <strong>scaling</strong> and <strong>offset</strong> parameters, respectively.</p>
<p dir="auto">Note that in this kind of problem, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\min$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\max$</math-renderer> are interchangeable under sign inversion.
Also, spin variables <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$\mathbf{s} \in \lbrace{\pm 1}\rbrace^{n}$</math-renderer> may be employed instead, assuming that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="fe627107358438d587f1e32fdbc07bfb">$s = 2x - 1$</math-renderer> by convention.</p>
</details>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">ToQUBO.jl</h3><a id="user-content-toqubojl" class="anchor" aria-label="Permalink: ToQUBO.jl" href="#toqubojl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><a href="https://github.com/psrenergy/ToQUBO.jl">ToQUBO.jl</a> is a Julia package to reformulate general optimization problems into QUBO (Quadratic Unconstrained Binary Optimization) instances.
This tool aims to convert a broad range of JuMP problems for straightforward application in many physics and physics-inspired solution methods whose normal optimization form is equivalent to the QUBO.
Not only it is has the <a href="https://github.com/psrenergy/ToQUBO.jl#list-of-interpretable-constraints"><strong>widest constraint coverage</strong></a> but also is the <a href="https://github.com/psrenergy/ToQUBO-benchmark"><strong>most performant</strong></a> QUBO reformulation tool available.</p>
<p dir="auto">During execution, <a href="https://github.com/psrenergy/ToQUBO.jl">ToQUBO.jl</a> encodes both discrete and continuous variables, maps constraints, and computes their penalties, performing a few model optimization steps along the process.
<a href="https://github.com/psrenergy/ToQUBO.jl">ToQUBO.jl</a> was written as a <a href="https://github.com/jump-dev/MathOptInterface.jl">MathOptInterface</a> (MOI) layer that automatically maps between input and output models, thus providing a smooth JuMP modeling experience.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">QUBODrivers.jl</h3><a id="user-content-qubodriversjl" class="anchor" aria-label="Permalink: QUBODrivers.jl" href="#qubodriversjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package aims to provide a common <a href="https://github.com/jump-dev/MathOptInterface.jl">MOI</a>-compliant API for QUBO Sampling and Annealing machines.
It also contains testing tools, including utility samplers for performance comparison and sanity checks.</p>
<p dir="auto">It was designed to allow algorithm developers and hardware manufacturers to easily connect their products to the <a href="https://jump.dev" rel="nofollow">JuMP</a> ecosystem.
Its simple interface paves the path for the rapid integration of heterogeneous QUBO solvers, including cloud-based Quantum Computing services (<a href="https://github.com/psrenergy/DWave.jl">DWave.jl</a>, <a href="https://github.com/psrenergy/QiskitOpt.jl">QiskitOpt.jl</a>); Quantum Simulation software (<a href="https://github.com/psrenergy/QuantumAnnealingInterface.jl">QuantumAnnealingInterface.jl</a>; <a href="https://github.com/pedromxavier/CIMOptimizer.jl">CIMOptimizer.jl</a>) and Heuristic solvers (<a href="https://github.com/psrenergy/MQLib.jl">MQLib.jl</a>, <a href="https://github.com/psrenergy/DWaveNeal.jl">DWaveNeal.jl</a>).</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">QUBOTools.jl</h3><a id="user-content-qubotoolsjl" class="anchor" aria-label="Permalink: QUBOTools.jl" href="#qubotoolsjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <a href="https://github.com/psrenergy/QUBOTools.jl">QUBOTools.jl</a> package implements a broad set of utilities for working with QUBO instances.
It defines the abstract interfaces for representing both QUBO models and their solutions.
Besides that, its library contains reference implementations for the proposed interface, making it ready to power other applications.</p>
<p dir="auto">One of its main purposes is to provide fast and reliable conversion mechanism between common file formats for storing such problems.
With <a href="https://github.com/psrenergy/QUBOTools.jl">QUBOTools.jl</a> it is possible to read models from various benchmarking databases and also write models in specifications that most devices will directly handle.</p>
