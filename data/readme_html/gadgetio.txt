<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">GadgetIO.jl</h1><a id="user-content-gadgetiojl" class="anchor" aria-label="Permalink: GadgetIO.jl" href="#gadgetiojl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package provides some basic IO functionality to work with the Smoothed-Particle Hydrodynamics code <a href="https://wwwmpa.mpa-garching.mpg.de/gadget/" rel="nofollow">Gadget</a> by Volker Springel.</p>
<p dir="auto">You can use it to read/write snapshot and subfind output and we also provide some functionality to read the log files.</p>
<p dir="auto">It is taylored for working with the development version of P-Gadget3, specifically OpenGadget3 developed by <a href="https://www.usm.uni-muenchen.de/~dolag/" rel="nofollow">Klaus Dolag</a> and contributers. Development is focused on IO for Binary Format 2.
A lot of the routines are based on IDL scripts by Klaus Dolag (not public).</p>
<p dir="auto">If you use <code>GadgetIO.jl</code> in your publications please cite <a href="https://zenodo.org/badge/latestdoi/270966661" rel="nofollow">Böss &amp; Valenzuela</a>.</p>
<p dir="auto">Please see the <a href="https://ludwigboess.github.io/GadgetIO.jl/dev/" rel="nofollow">Documentation</a> for details.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Reading Snapshot Data</h2><a id="user-content-reading-snapshot-data" class="anchor" aria-label="Permalink: Reading Snapshot Data" href="#reading-snapshot-data"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>GadgetIO.jl</code> is specialized to read <code>Gadget</code> snapshots of <code>Format 2</code>. The structure of a <code>Format 2</code> snapshot is as follows:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="8              # size of the blockname block (Int32)
BLOCKNAME      # Blockname (4*Char)
8+SIZE_BLOCK   # number of bytes to skip if block should not be read
8              # end of blockname block

SIZE_BLOCK     # size of the current block in bytes
{...}          # content of the block ordered by particle type
SIZE_BLOCK     # end of the current block"><pre class="notranslate"><code>8              # size of the blockname block (Int32)
BLOCKNAME      # Blockname (4*Char)
8+SIZE_BLOCK   # number of bytes to skip if block should not be read
8              # end of blockname block

SIZE_BLOCK     # size of the current block in bytes
{...}          # content of the block ordered by particle type
SIZE_BLOCK     # end of the current block
</code></pre></div>
<p dir="auto">which repeats for every block.</p>
<p dir="auto">Gadget defines 6 particle types:</p>
<ul dir="auto">
<li><code>0</code>: Gas particles</li>
<li><code>1</code>: DM particles</li>
<li><code>2</code>: Disk/boundary particles</li>
<li><code>3</code>: Bulge/boundary particles</li>
<li><code>4</code>: Star particles</li>
<li><code>5</code>: Black Hole particles</li>
</ul>
<p dir="auto">So if you want to read for example the poistions of gas particles you can do this by using:</p>
<p dir="auto">julia```
filename = "path/to/your/snapshot"</p>
<p dir="auto">gas_pos = read_block(filename, "POS", parttype=0)</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="

julia```
filename = &quot;path/to/your/snapshot&quot;

<p dir="auto">We recommend running Gadget with the compiler flag <code>WRITE_INFO_BLOCK</code> to make IO easier, however you can also read most blocks out of the box due to fall-back <code>InfoLine</code>s.
If you work on a development version of <code>Gadget</code> that contains output blocks that don't have fall-back <code>InfoLine</code>s you can also supply your own to the <code>read_block</code> function.</p>
<p dir="auto">You can also read subvolumes of simulations, either along the Peano-Hilbert curve or in a brute force way.
Or you can read particles by custom filtering and store the memory-mapping to disk.
See the <a href="https://ludwigboess.github.io/GadgetIO.jl/dev/" rel="nofollow">Documentation</a> for details.</p>
