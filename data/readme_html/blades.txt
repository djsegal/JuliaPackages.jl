<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Blades</h1><a id="user-content-blades" class="anchor" aria-label="Permalink: Blades" href="#blades"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <code>Blades</code> <a href="http://julialang.org" rel="nofollow">Julia</a> package defines the <code>Blade</code> Type
to represent <a href="https://en.wikipedia.org/wiki/Blade_(geometry)" rel="nofollow">k-blades</a>, and
supports a number of mathematical operations on them.</p>
<p dir="auto">Both non-euclidean and degenerate metrics are supported as well as the standard euclidean metric.
This makes it suitable for implementing a wide range of algebras based on graded exterior products.</p>
<ul dir="auto">
<li><a href="https://en.wikipedia.org/wiki/Geometric_algebra" rel="nofollow">Geometric Algebra</a></li>
<li><a href="https://en.wikipedia.org/wiki/Exterior_algebra" rel="nofollow">Exterior Algebra</a></li>
<li><a href="https://en.wikipedia.org/wiki/Clifford_algebra" rel="nofollow">Clifford Algebra</a></li>
</ul>
<p dir="auto">This document attempts to be a somewhat self-contained description of the algebra implemented in the package.  It is recommended to find more complete tutorials or learning materials on Geometric Algebra.</p>

<p dir="auto">e₁, e₂, e₃ are the generating basis 1-vectors that are combined together with the wedge product, <code>∧</code> to form basis vectors of higher grades.<br>

<p dir="auto">The inner product, <code>⋅</code>, choosen for Blades is the left contraction.  For 1-blades it is the same as that used in vector algebra.  This suffices for use in defining our quadratic form.<br>
When blades of grade &gt; 1 are involved it is not, in general, commutative, or even associative.</p>

<p dir="auto">We could expand the algebra with the geometric product <code>u*B = u∧B + u⋅B</code>.
Where <code>u</code> is restricted to be 1-vector, due to non-commutativity/associativity of <code>⋅</code>.</p>
<p dir="auto">The geometric product, addition and other operators on blades are better defined in a more general manner once we have Types for k-vectors and multivectors defined.</p>
<p dir="auto">These Types and operators are defined in the <a href="https://github.com/mewertd2/KVectors.jl">KVectors</a> and <a href="https://github.com/mewertd2/Multivectors.jl">Multivectors</a> packages.</p>
<p dir="auto">If we wished to we could define only addition of Blades with zero to complete our algebra of simple k-vectors ( blades ).</p>

<p dir="auto">Afer defining these operators we could go back in this document and replace occurences of <code>∧</code> and <code>⋅</code> with <code>*</code> to generate the k-blades and metric results using the geometric product.</p>
<p dir="auto">Blades does define the geometric product without the need of the <code>+</code> operator since only one of <code>u∧B</code> or <code>v⋅B</code> is ever non-zero.  This fact expresses the geometric relationship of parallel and orthogonal vectors.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">The Dual/Orthogonal-Complement</h2><a id="user-content-the-dualorthogonal-complement" class="anchor" aria-label="Permalink: The Dual/Orthogonal-Complement" href="#the-dualorthogonal-complement"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A k-blade is a blade of grade k.  For any k-blade spanning a subspace of dimension k in vector space of dimension n, there exists an (n-k)-blade that represents the same object.  This object is known as it's dual.</p>
<p dir="auto">The orthogonal complement is very similar in that it is a map from a k-blade to an (n-k)-blade.  Assuming the metric is non-degenerate.  The difference is that the target space of the orthogonal complement is the same as the domain.  For the dual it is better to think of the target space as not being the same space as the domain.  The dual maps a geometric object to the same object in dual space.</p>
<p dir="auto">Dual space is a very important concept in Projectivized Geometric Algebra.
Blades optionally can generate a set of Types with raised indices if you wish to explicitly track which space you are in.</p>
<p dir="auto">Both the notion of a metric dual and a non-metric dual are represented in Blades.
For a non-degenerate metric ( no 1-vectors square to 0 ) the <code>dual</code> method is an alias for <code>orthogonal_complement</code>, <code>⟂</code>, or <code>!</code>.</p>
<p dir="auto">Defined as <code>!A = A*I⁻¹</code> where <code>I⁻¹</code> is the inverse of the pseudoscalar.</p>
<p dir="auto">It is prefered to not use <code>dual</code> if what you really want is the orthogonal complement.</p>
<p dir="auto"><code>inv</code> the inverse operator is defined by <code>inv(B) = reverse(B)/(B*reverse(B))</code></p>
<p dir="auto"><code>reverse</code> reverses the order of the generating 1-blades for the given Blade.  Generally you end up with the same Blade, possibly with a sign (orientation) flip.</p>
<p dir="auto">Since the inverse of the pseudoscalar does not exist when the metric is degenerate ( <code>I*reverse(I) == 0</code>), we need an alternative mapping.</p>
<p dir="auto">In the case of a degenerate metric, <code>dual</code> is a mapping to/from projectivized dual space and primal space.  This is done with a non-metric duality mapping that chooses a non-zero orthogonal complement in the dual space.</p>
<p dir="auto">Both <code>dual</code> and <code>⟂</code> can be thought of as taking a Blade to it's "other" space.  e.g. plane to normal vector.</p>

<p dir="auto">Raised indices can also be used to represent what is often called the reciprocal basis.  The reciprocal basis is useful for geometry and calculus on curved surfaces.  The reciprocal basis is meant to be independent of the metric when applied to a k-blade with lowered indices.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="eᵢ⋅eʲ = δᵢⱼ"><pre class="notranslate"><code>eᵢ⋅eʲ = δᵢⱼ
</code></pre></div>
<p dir="auto">In this case you want to call <code>@generate_basis</code> with options for reciprocal basis and zeroing mixed indices set to <code>true</code>.</p>
