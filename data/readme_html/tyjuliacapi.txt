<p dir="auto">TyJuliaCAPI.jl provides a stable C API for Julia.</p>
<p dir="auto">These APIs are provided in the form of function pointers, and there are two initialization methods:</p>
<ol dir="auto">
<li>
<p dir="auto">If the caller is Julia, Julia obtains C functions from the external language. These C functions accept function pointers passed by Julia, allowing the external language to access these APIs.</p>
</li>
<li>
<p dir="auto">If the caller is an external language, due to the instability and lack of documentation of Julia's official C API, it is difficult to initialize in the same way as in (1). In this case, we can enable a network protocol to transmit function pointers over the network, allowing both two side to access each other's C API (this approach is inspired by MATLAB's interoperability).</p>
</li>
</ol>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Motivation</h2><a id="user-content-motivation" class="anchor" aria-label="Permalink: Motivation" href="#motivation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The need for TyJuliaCAPI arises from a technical challenge: <strong>How can Julia interact with other external languages within the same process</strong>?</p>
<p dir="auto">We have serval projects implemented in C++/C#, and calling Julia from native code is a crucial requirement.</p>
<p dir="auto">So, how to call Julia from C#: The only solution to this problem is to use the C API.</p>
<p dir="auto">However, although Julia provides a C API (<a href="https://github.com/JuliaLang/julia/blob/master/src/julia.h">julia.h</a>), these APIs have the following issues:</p>
<ol dir="auto">
<li>Lack of documentation.</li>
<li>Requires an understanding of Julia's lifecycle management and garbage collection mechanism.</li>
<li>The API is unstable and changes with every version.</li>
</ol>
<p dir="auto">We, therefore, believe that the current quality of Julia's C API is insufficient to support product development and maintenance.</p>
<p dir="auto">And we need a stable and generic Julia C API.</p>
<p dir="auto">In the past, we have learned a useful technique from <a href="https://github.com/JuliaPy/PythonCall.jl">PythonCall.jl</a> (referred to as GC Pooling), which PythonCall itself used to provide a set of interoperation mechanisms, surpassing similar projects in terms of stability and performance. Following this technique, we have implemented a stable and well-designed C API for Julia, which we call TyJuliaCAPI.</p>
<p dir="auto">In TyJuliaCAPI, the lifecycle management is adopted in a manner similar to the <a href="https://docs.python.org/3/c-api/stable.html" rel="nofollow">Python Stable C API</a> (the most widely applied and highly regarded C API design): objects are created via the C API with inherent references, and when they are no longer needed, external language references are released by using <code>JLFreeFromMe</code>.</p>

<p dir="auto">APIs prefixed with the <code>CORE_API</code> macro are fundamental core APIs, while the rest of the APIs can be expressed using the core APIs. However, they are provided separately due to their high level of common usage.</p>
