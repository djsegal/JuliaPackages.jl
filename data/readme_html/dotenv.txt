<p dir="auto">DotEnv.jl is a lightweight package that loads environment variables from <code>.env</code>
  files into <a href="https://docs.julialang.org/en/latest/manual/environment-variables/" rel="nofollow">=ENV=</a>. Storing configuration in the environment is based on <a href="http://12factor.net/config" rel="nofollow">The
  Twelve-Factor App</a> methodology.</p>
<p dir="auto">Please don’t store secrets in dotenv files, and if you must at least ensure the
  dotenv file(s) are listed in <code>.gitignore</code>.</p>

<p dir="auto">Create a <code>.env</code> file in your project. You can add environment-specific variables
  using the rule <code>NAME=VALUE</code>.  For example:</p>
<pre lang="conf">#.env file
DB_HOST=127.0.0.1
DB_USER=john
DB_PASS=42
</pre>
<p dir="auto">When <code>DotEnv.load!()</code> is called, all variables declared in the <code>.env</code> file that
  are not already present in <code>ENV</code> are loaded into it.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; ENV[&quot;DB_PASS&quot;]
&quot;42&quot;"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-c1">ENV</span>[<span class="pl-s"><span class="pl-pds">"</span>DB_PASS<span class="pl-pds">"</span></span>]
<span class="pl-s"><span class="pl-pds">"</span>42<span class="pl-pds">"</span></span></pre></div>
<p dir="auto">To load variables from dotenv files even when they are already present in the
  environment dictionary, pass <code>override = true</code> to <code>DotEnv.load!</code>.</p>

<p dir="auto"><code>DotEnv.unload!()</code> will reverse the changes of <code>DotEnv.load!()</code>.</p>
<p dir="auto">This works even when the environment is modified incrementally (i.e. loading
  files one at a time).</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Parsing Rules</h2><a id="user-content-parsing-rules" class="anchor" aria-label="Permalink: Parsing Rules" href="#parsing-rules"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ol dir="auto">
  <li>Leading whitespace is ignored</li>
  <li>Empty lines, and lines starting with <code>#</code> are skipped</li>
  <li><code>export</code> prefixes are ignored (e.g. <code>export FOO=bar</code>)</li>
  <li>Empty assignments are regarded as the empty string(<code>EMPTY=</code> becomes <code>"EMPTY" =&gt; ""</code>)</li>
  <li>Keys and values are separated by === or <code>:</code>, and any amount of whitespace</li>
  <li>All values are strings, but can be quoted with single (<code>'</code>) or double quotes (<code>"</code>)</li>
  <li>Quotes of the same type may occur within quoted values, but must be escaped with <code>\</code></li>
  <li>Inline comments are started with a <code>#</code> outside of a quoted value</li>
  <li>Inside double quoted values, <code>\n</code> newlines are expanded, allowing for multiline values</li>
  <li>Extra spaces are removed from both ends of an unquoted value (e.g. <code>FOO</code> some
    value = becomes <code>"FOO" =&gt; "some value"</code>)</li>
  <li>Variable expansion occurs within unquoted and double-quoted values. <code>$NAME</code>,
    <code>${NAME}</code>, and <code>${NAME:-default}</code> expansions are all supported.</li>
  <li>Malformed lines are silently skipped</li>
</ol>
