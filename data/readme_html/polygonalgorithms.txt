<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Representation</h3><a id="user-content-representation" class="anchor" aria-label="Permalink: Representation" href="#representation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Points are represented as tuples and polygons as list of points (tuples).
The last point is assumed to share an edge with the first: <code>n + 1 = 1</code>.</p>
<p dir="auto">For indexing use <code>x_coords</code> and <code>y_coords</code>.
Common broadcasting operations are supplied such as <code>translate</code> and <code>rotate</code>.</p>
<p dir="auto">An alternative representation for polygons is as 2×N matrices.
This form is more natural for indexing and broadcasting operations such as translation and rotation.
Otherwise the algorithms here do not make use of matrix operations.
For example, inverting a matrix has no meaning.</p>
<p dir="auto">To convert between the forms, use <code>matrix_to_points</code> or <code>points_to_matrix</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Algorithms</h2><a id="user-content-algorithms" class="anchor" aria-label="Permalink: Algorithms" href="#algorithms"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For all of the the following <code>n</code> and <code>m</code> are the number of vertices of the polygons.</p>
<ol dir="auto">
<li>Area of polygon and centroid of polygon.
<ul dir="auto">
<li>Shoe-lace formula.</li>
<li>Time complexity: <code>O(n)</code>.</li>
<li>Reference: <a href="https://en.wikipedia.org/wiki/Polygon#Area" rel="nofollow">Wikipedia</a>.</li>
</ul>
</li>
<li>Point in polygon.
<ul dir="auto">
<li>Ray casting with an extension from the following paper: "A Simple and Correct Even-Odd Algorithm for the Point-in-Polygon Problem for Complex Polygons" by Michael Galetzka and Patrick Glauner (2017).</li>
<li>Time complexity: <code>O(n)</code>.</li>
<li>Reference: <a href="https://en.wikipedia.org/wiki/Point_in_polygon" rel="nofollow">Wikipedia</a>, <a href="https://arxiv.org/abs/1207.3502" rel="nofollow">paper</a>.</li>
</ul>
</li>
<li>Convex hull.
<ul dir="auto">
<li>Gift-wrapping algorithm:
<ul dir="auto">
<li>Time complexity: <code>O(nh)</code> where <code>h</code> is the number of points in the hull.</li>
<li>Reference: <a href="https://en.wikipedia.org/wiki/Gift_wrapping_algorithm" rel="nofollow">Wikipedia</a>.</li>
</ul>
</li>
<li>Graham Scan algorithm:
<ul dir="auto">
<li>Time complexity: <code>O(n*log(n))</code>.</li>
</ul>
</li>
</ul>
</li>
<li>Intersection of polygons (polygon clipping).
<ul dir="auto">
<li>Chasing edges algorithm:
<ul dir="auto">
<li>Convex only.</li>
<li>From "A New Linear Algorithm for Intersecting Convex Polygons" (1981) by Joseph O'Rourke et. al.</li>
<li>Time complexity: <code>O(n+m)</code>.</li>
<li>Reference: <a href="https://www.cs.jhu.edu/~misha/Spring16/ORourke82.pdf" rel="nofollow">https://www.cs.jhu.edu/~misha/Spring16/ORourke82.pdf</a></li>
</ul>
</li>
<li>Point search algorithm:
<ul dir="auto">
<li>Convex only.</li>
<li>Combines point in polygon algorithm with intersection of edges.</li>
<li>Time complexity: <code>O(nm)</code>.</li>
<li>For general non-self-intersecting polygons, the intersection points are valid but the order is not.</li>
</ul>
</li>
<li>Weiler-Atherton algorithm:
<ul dir="auto">
<li>Concave and convex but not self-intersecting.</li>
<li>Time complexity: <code>O(nm)</code>.</li>
<li>For a full explanation, see my <a href="https://liorsinai.github.io/mathematics/2023/09/30/polygon-clipping.html" rel="nofollow">blog post</a>.</li>
</ul>
</li>
</ul>
</li>
</ol>
