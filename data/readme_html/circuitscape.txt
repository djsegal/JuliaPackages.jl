<p dir="auto">Circuitscape is an open-source program that uses circuit theory to model connectivity
in heterogeneous landscapes. Its most common applications include modeling movement and gene flow
of plants and animals, as well as identifying areas important for connectivity conservation.</p>
<p dir="auto">Circuitscape has now been rewritten in <a href="https://julialang.org" rel="nofollow">Julia</a> for better performance and scalability.
This work is based on the Python implemention in <a href="https://github.com/Circuitscape/Circuitscape.py">Circuitscape.py</a>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">The New Circuitscape - Modern, Fast and Flexible</h2><a id="user-content-the-new-circuitscape---modern-fast-and-flexible" class="anchor" aria-label="Permalink: The New Circuitscape - Modern, Fast and Flexible" href="#the-new-circuitscape---modern-fast-and-flexible"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The new Circuitscape is built entirely in the Julia language, a new
programming language for technical computing. Julia is built from the
ground up to be <a href="http://julialang.org/benchmarks" rel="nofollow">fast</a>. As such, this offers a
number of advantages over the previous version, and these are detailed below.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Faster and More Scalable</h3><a id="user-content-faster-and-more-scalable" class="anchor" aria-label="Permalink: Faster and More Scalable" href="#faster-and-more-scalable"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">We benchmarked <code>Circuitscape.jl</code> (v0.1.0) with the Python version (v4.0.5) to obtain the
following results. We started up Circuitscape with 16 parallel processes,
and used benchmark problems from the standard Circuitscape
<a href="https://github.com/Circuitscape/BigTests">benchmark suite.</a></p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="docs/src/benchmark/benchmark.png"><img src="docs/src/benchmark/benchmark.png" width="650" height="450" style="max-width: 100%;"></a></p>
<p dir="auto">These benchmarks were run on a Linux (Ubuntu) server machine with the following specs:</p>
<ul dir="auto">
<li>Name: Intel(R) Xeon(R) Silver 4114 CPU</li>
<li>Clock Speed: 2.20GHz</li>
<li>Number of cores: 20</li>
<li>RAM: 384 GB</li>
</ul>
<p dir="auto">From the benchmark, we see that the new version is upto <em>4x faster</em>
on 16 processes. However, the best performing bar in the chart is
<em>Julia-CHOLMOD</em>, which is a new feature introduced.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">New Solver Mode - CHOLMOD</h3><a id="user-content-new-solver-mode---cholmod" class="anchor" aria-label="Permalink: New Solver Mode - CHOLMOD" href="#new-solver-mode---cholmod"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Julia-CHOLMOD is a new solver mode used in the new Circuitscape. It performs a <a href="https://en.wikipedia.org/wiki/Cholesky_decomposition" rel="nofollow">cholesky
decomposition</a> on the graph
constructed, and performs a batched back substitution
to compute the voltages. It plugs into the
<a href="http://faculty.cse.tamu.edu/davis/suitesparse.html" rel="nofollow">CHOLMOD</a> library,
which is part of the SuiteSparse collection of high performance sparse
matrix algorithms.</p>
<p dir="auto">To use the this new mode, include a line in your Circuitscape
INI file:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="solver = cholmod"><pre class="notranslate"><code>solver = cholmod
</code></pre></div>
<p dir="auto">The cholesky decomposition is a direct solver method, unlike the algebraic
multigrid method used by default in both the old and the new version.
The advantage with this new direct method is that it can be much faster than
the iterative solution, within a particular problem size.</p>
<p dir="auto"><em>Word of caution</em>: The cholesky decomposition is not practical
to use beyond a certain problem size because of phenomenon called
<a href="https://algowiki-project.org/en/Cholesky_method#Reordering_to_reduce_the_number_of_fill-in_elements" rel="nofollow">fill-in</a>, which results in loss of sparsity and large memory consumption.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Parallel, everywhere</h3><a id="user-content-parallel-everywhere" class="anchor" aria-label="Permalink: Parallel, everywhere" href="#parallel-everywhere"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The old Circuitscape had limited support for parallelism, which worked on Mac and
Linux, but didn't work on Windows.</p>
<p dir="auto">Julia as a programming language is built from the ground up to be parallel,
and as a result the new Circuitscape natively supports parallelism on all three
platforms.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Single Precision (Experimental)</h3><a id="user-content-single-precision-experimental" class="anchor" aria-label="Permalink: Single Precision (Experimental)" href="#single-precision-experimental"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The new Circuitscape introduces the ability to run problems in
single precision as opposed to the standard double precision.</p>
<p dir="auto">Single precision usually takes much less memory, but trades off
against solution accuracy.</p>
<p dir="auto">Use this new feature by including a line in your config file:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="precision = single"><pre class="notranslate"><code>precision = single
</code></pre></div>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Notes on INI files</h2><a id="user-content-notes-on-ini-files" class="anchor" aria-label="Permalink: Notes on INI files" href="#notes-on-ini-files"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Circuitscape takes as input INI files, which contain paths to the raster map, sources, grounds,
and other inputs, as well as flags for each run. If you're using the <a href="https://circuitscape.org/downloads/" rel="nofollow">GUI</a>
the INI file will automatically be generated for you and then fed into Circuitscape. But if you're
using the Julia prompt, then you must write one yourself. The easiest way to do this is to copy
an INI file <a href="https://github.com/Circuitscape/Circuitscape.jl/tree/master/test/input">from the tests</a> and then modify it depending on your problem.</p>
