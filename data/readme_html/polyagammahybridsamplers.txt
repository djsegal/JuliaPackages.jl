<p dir="auto"><code>PolyaGammaHybridSamplers.jl</code> is a Julia package that implements a hybrid sampling approach for the Pólya-Gamma distribution. The Pólya-Gamma distribution is a continuous distribution on the positive real number line and is most often used for latent variable augmentation in models like logistic regression or logit stick-breaking processes. It is parameterized by two values, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b &amp;gt; 0$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$z\in\mathbb{R}$</math-renderer>, and is often assigned the distributional notation <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(b,z)$</math-renderer>. An excellent tutorial on using the Pólya-Gamma distribution can be found at this <a href="https://gregorygundersen.com/blog/2019/09/20/polya-gamma/" rel="nofollow">blog post</a> by Gregory Gunderson.</p>

<p dir="auto">The class of Pólya-Gamma distributions was first presented in a paper by <a href="http://www.tandfonline.com/doi/abs/10.1080/01621459.2013.829001" rel="nofollow">Polson et al. (2013)</a>. There is no closed-form expression for the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(b,z)$</math-renderer> density function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$f$</math-renderer>, but is rather defined through its Laplace transform:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$$
\mathcal{L}_f(t) = \frac{\cosh^b(\frac{z}{2})}{\cosh^b\left(\sqrt{\frac{z^2/2 + t}{2}}\right)}
$$</math-renderer></p>
<p dir="auto">This can be derived from an alternative definition where the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(b,z)$</math-renderer> distribution is represented as an infinite mixture of gamma variables. The authors comment that a naive approach to sampling could be to generate atruncated number of gamma values and combine them using the mixture formula, but they warn that this approximation is both inefficient and potentially dangerous.</p>
<p dir="auto">In order to develop an effecient yet exact sampling method, the authors drew connections to a subclass of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$J^*$</math-renderer> distributions discussed in <a href="https://www.sciencedirect.com/science/article/pii/S0167715209002867" rel="nofollow">Devroye (2009)</a>. The ultimate conclusion is an extremely efficient rejection sampler, called the <em>Devroye method</em>, that is used to simulate from a <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(1,z)$</math-renderer> distribution. If <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer> is an integer, then the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(b,z)$</math-renderer> distribution can be drawn by summing <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer> independent draws from the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$PG(1,z)$</math-renderer> distribution.</p>
<p dir="auto">The following year, a technical report written by <a href="https://arxiv.org/abs/1405.0506" rel="nofollow">Windle et al. (2014)</a> was published on arXiv detailing an alternative sampling technique and an approximate technique. The alternative technique requires <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b\in[1,4]$</math-renderer>, but allows for otherwise non-integer <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer> values. The approximate algorithm, called the <em>saddle-point sampler</em>, involves approximating the density using the moment generating function and then constructing a smart rejection sampler. The saddle-point sampler is both fast and increasingly accurate for larger values of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer>. The report concludes with a performance comparison between the <em>naive gamma mixture</em>, the <em>Devroye method</em>, the <em>alternative technique</em>, the <em>saddle-point sampler</em>, and a normal approximation. They subsequently suggest the following hybrid sampler scheme to balance accuracy and efficiency:</p>

<p dir="auto">The authors of <a href="http://www.tandfonline.com/doi/abs/10.1080/01621459.2013.829001" rel="nofollow">Polson et al. (2013)</a> published the <a href="https://cran.r-project.org/web/packages/BayesLogit/index.html" rel="nofollow">BayesLogit</a> R package with C++ code implementing the Devroye sampling method, later expanding it to include the techniques presented in <a href="https://arxiv.org/abs/1405.0506" rel="nofollow">Windle et al. (2014)</a>. The source code is available at the <a href="https://github.com/jwindle/BayesLogit">BayesLogit GitHub site</a>. However, it is important to note that, as of version 2.1, inline comments for the main sampling function, <code>rpg_hybrid</code>, state that the <em>alternative technique</em> code needs further review and/or development (<a href="https://github.com/jwindle/BayesLogit/blob/master/src/polyagamma_wrapper.cpp">source</a>, lines 138-141) and instead the <em>naive gamma mixture</em> is used for small, non-integer <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer> values combined with the <em>Devroye method</em> for integer <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b&amp;gt;1$</math-renderer>.</p>
<p dir="auto">Interest in the Pólya-Gamma distribution within the Julia community appears first in a <a href="https://github.com/JuliaStats/Distributions.jl/issues/685" data-hovercard-type="issue" data-hovercard-url="/JuliaStats/Distributions.jl/issues/685/hovercard">GitHub issues thread</a> started by a user called <code>currymj</code> under the main <a href="https://github.com/JuliaStats/Distributions.jl/">Distributions.jl</a> repository. Ultimately, <code>currymj</code> developed a separate package called <a href="https://github.com/currymj/PolyaGammaDistribution.jl">PolyaGammaDistribution.jl</a> that was essentially a direct translation of the <a href="https://cran.r-project.org/web/packages/BayesLogit/index.html" rel="nofollow">BayesLogit</a> <em>Devroye method</em> code for integer <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b02bc8eb78c4aac2e4302ed21d699b98">$b$</math-renderer> parameters.</p>
<p dir="auto">However, Julia would eventually update to v1.0 and begin requiring a different package structure. When asked about future compatibility, a collaborator, user <code>maximerischard</code>, indicated in a <a href="https://github.com/currymj/PolyaGammaDistribution.jl/issues/3" data-hovercard-type="issue" data-hovercard-url="/currymj/PolyaGammaDistribution.jl/issues/3/hovercard">GitHub issues thread</a> that there were no plans to upgrade the package. The user, <code>igutierrezm</code>, who started the thread would then go on to develop a Julia v1.0 compatible package, <a href="https://github.com/igutierrezm/PolyaGammaSamplers.jl">PolyaGammaSamplers.jl</a>. This new package implemented the <em>Devroye method</em> similar to its predecessor, but using the new <a href="https://juliastats.org/Distributions.jl/stable/extends/#Create-New-Samplers-and-Distributions" rel="nofollow">sampler framework</a>, which is a more limited implementation compared to the full distribution requirements of <a href="https://github.com/JuliaStats/Distributions.jl/">Distributions.jl</a>, but is also more fitting for the Pólya-Gamma distribution.</p>
<p dir="auto">Over time, a handful of variations came about, including a <a href="https://github.com/currymj/PolyaGammaDistribution.jl/forks">PolyaGammaDistribution.jl fork</a> by user <code>yunzli</code> (<a href="https://github.com/yunzli/PolyaGammaDistribution.jl">link</a>) and a rewritten <em>Devroye method</em> sampler in <a href="https://github.com/theogf/AugmentedGaussianProcesses.jl">AugmentedGaussianProcesses.jl</a> by user <code>theogf</code>. Perhaps the most recent discourse comes from another <a href="https://github.com/JuliaStats/Distributions.jl/issues/1440" data-hovercard-type="issue" data-hovercard-url="/JuliaStats/Distributions.jl/issues/1440/hovercard">GitHub issues thread</a>, where user <code>theogf</code> asked whether their <em>Devroye method</em> code should be merged into <a href="https://github.com/JuliaStats/Distributions.jl/">Distributions.jl</a>. The issue was ultimately never resolved due to conflicts between the MIT and GPL-3.0 licenses.</p>

<p dir="auto">To generate a random variate, create a sampler object and then use <code>rand</code> (vectorized versions of <code>rand</code> and <code>rand!</code> are also available):</p>

<p dir="auto">Other valid options include <code>DEVROYE</code>, <code>NORMALAPPROX</code>, <code>GAMMAMIXTURE</code>, and <code>DEVROYEGAMMAMIXTURE</code>. But be careful as no warning about the approximation quality or efficiency will be given if the sampler is forced to use a technique that is not appropriate for the given parameters.</p>
