<p dir="auto">This package provides the <code>@stable</code> macro
to enforce that functions have type stable return values.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using DispatchDoctor: @stable

    if x &gt; 0
        return x
    else
        return 0.0
    end
end"><pre><span class="pl-k">using</span> DispatchDoctor<span class="pl-k">:</span> <span class="pl-c1">@stable</span>

<span class="pl-c1">@stable</span> <span class="pl-k">function</span> <span class="pl-en">relu</span>(x)
    <span class="pl-k">if</span> x <span class="pl-k">&gt;</span> <span class="pl-c1">0</span>
        <span class="pl-k">return</span> x
    <span class="pl-k">else</span>
        <span class="pl-k">return</span> <span class="pl-c1">0.0</span>

<p dir="auto">Code which is type stable should safely compile away the check:</p>

<div class="highlight highlight-source-llvm notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="define i64 @julia_f_12055(i64 signext %&quot;x::Int64&quot;) #0 {

<p dir="auto">You can use <code>@stable</code> on blocks of code,
including <code>begin-end</code> blocks, <code>module</code>, and anonymous functions.
The inverse of <code>@stable</code> is <code>@unstable</code> which turns it off:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@stable begin

    f() = rand(Bool) ? 0 : 1.0
    f(x) = x

    module A
        # Will apply to code inside modules:
        g(; a, b) = a + b

        # Will recursively apply to included files:
        include(&quot;myfile.jl&quot;)

        module B
            # as well as nested submodules!

            # `@unstable` inverts `@stable`:
            using DispatchDoctor: @unstable
            @unstable h() = rand(Bool) ? 0 : 1.0

            # This can also apply to code blocks:
            @unstable begin
                h(x::Int) = rand(Bool) ? 0 : 1.0
                # ^ And target specific methods
            end
        end
    end

<p dir="auto">(<em>Tip 2: in the REPL, you must wrap modules with <code>@eval</code>, because the REPL has special handling of the <code>module</code> keyword.</em>)</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">🧪 Options</h3><a id="user-content--options" class="anchor" aria-label="Permalink: 🧪 Options" href="#-options"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">You can provide the following options to <code>@stable</code>:</p>
<ul dir="auto">
<li><code>default_mode::String="error"</code>:
<ul dir="auto">
<li>Change the default mode from <code>"error"</code> to <code>"warn"</code> to only emit a warning, or <code>"disable"</code> to disable type instability checks by default.</li>
<li>To locally or globally override the mode for a package that uses DispatchDoctor, you can use the <code>"instability_check"</code> key in your LocalPreferences.toml (typically configured with Preferences.jl).</li>
</ul>
</li>
<li><code>default_codegen_level::String="debug"</code>:
<ul dir="auto">
<li>Set the code generation level to <code>"min"</code> to only generate a single function body for each stabilized function. The default, <code>"debug"</code>, generates an entire duplicate function so that <code>@code_warntype</code> can be used.</li>
<li>To locally or globally override the code generation level for a package that uses DispatchDoctor, you can use the <code>"instability_check_codegen_level"</code> key in your LocalPreferences.toml.</li>
</ul>
</li>
<li><code>default_union_limit::Int=1</code>:
<ul dir="auto">
<li>Sets the maximum elements in a union to be considered stable. The default is <code>1</code>, meaning that all unions are considered unstable. A value of <code>2</code> would indicate that <code>Union{Float32,Float64}</code> is considered stable, but <code>Union{Float16,Float32,Float64}</code> is not.</li>
<li>To locally or globally override the union limit for a package that uses DispatchDoctor, you can use the <code>"instability_check_union_limit"</code> key in your LocalPreferences.toml.</li>
</ul>
</li>
</ul>
<p dir="auto">Each of these is denoted a <code>default_</code> because you may set them globally or at a per-package level with <code>Preferences.jl</code> (see below).</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">🚑 Usage in packages</h3><a id="user-content--usage-in-packages" class="anchor" aria-label="Permalink: 🚑 Usage in packages" href="#-usage-in-packages"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">You might find it useful to <em>only</em> enable <code>@stable</code> during unit-testing,
to have it check every function in a library, but not throw errors for
downstream users. You may also want to have warnings instead of errors.</p>
<p dir="auto">For this, use the <code>default_mode</code> keyword to set the default behavior:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="module MyPackage
using DispatchDoctor
@stable default_mode=&quot;disable&quot; begin

# Entire package code

end
end"><pre><span class="pl-k">module</span> MyPackage
<span class="pl-k">using</span> DispatchDoctor
<span class="pl-c1">@stable</span> default_mode<span class="pl-k">=</span><span class="pl-s"><span class="pl-pds">"</span>disable<span class="pl-pds">"</span></span> <span class="pl-k">begin</span>

<span class="pl-c"><span class="pl-c">#</span> Entire package code</span>

<span class="pl-k">end</span>
<span class="pl-k">end</span></pre></div>
<p dir="auto"><code>"disable"</code> as the mode will turn <code>@stable</code> into a <em>no-op</em>, so that
DispatchDoctor has no effect on your code by default.</p>
<p dir="auto">The mode is configurable
via <a href="https://github.com/JuliaPackaging/Preferences.jl">Preferences.jl</a>,
meaning that, within your <code>test/runtests.jl</code>, you could add a line <strong>before importing your package</strong>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Preferences: set_preferences!

set_preferences!(&quot;MyPackage&quot;, &quot;instability_check&quot; =&gt; &quot;error&quot;)"><pre><span class="pl-k">using</span> Preferences<span class="pl-k">:</span> set_preferences!

<span class="pl-c1">set_preferences!</span>(<span class="pl-s"><span class="pl-pds">"</span>MyPackage<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>instability_check<span class="pl-pds">"</span></span> <span class="pl-k">=&gt;</span> <span class="pl-s"><span class="pl-pds">"</span>error<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">You can also set to be <code>"warn"</code> if you would just like warnings.</p>
<p dir="auto">You might also find it useful to set
the <code>default_codegen_level</code> parameter to <code>"min"</code> instead of
the default <code>"debug"</code>. This will result in no code duplication,
improving precompilation time (although <code>@code_warntype</code> and error
messages will be less useful).
As with the <code>default_mode</code>, you can configure the codegen level with Preferences.jl
by using the <code>"instability_check_codegen_level"</code> key.</p>
<p dir="auto">Note that for code coverage to work as expected over stabilized code,
you will also need to use <code>default_codegen_level="min"</code>.</p>

<li><strong>When loading code changes with Revise.jl*.</strong>
<ul dir="auto">
<li>*Basically, <code>@stable</code> will attempt to travel through any <code>include</code>'s. However, if you edit the included file and load the changes with Revise.jl, instability checks will get stripped (see <a href="https://github.com/timholy/Revise.jl/issues/634" data-hovercard-type="issue" data-hovercard-url="/timholy/Revise.jl/issues/634/hovercard">Revise#634</a>). The result will be that the <code>@stable</code> will be ignored.</li>
</ul>
</li>
<li><strong>Within certain code blocks and function types:</strong>
<ul dir="auto">
<li>Within an <code>@unstable</code> block</li>
<li>Within a <code>@generated</code> block</li>
<li>Within a <code>quote ... end</code> block</li>
<li>Within a <code>macro ... end</code> block</li>
<li>Within an incompatible macro, such as
<ul dir="auto">
<li><code>@eval</code></li>
<li><code>@generated</code></li>
<li><code>@assume_effects</code></li>
<li><code>@pure</code></li>
<li>Or anything else registered as incompatible with <code>register_macro!</code></li>
</ul>
</li>
<li>Parameterized functions like <code>MyType{T}(args...) = ...</code></li>
<li>Functions with an expression-based name like <code>(::MyType)(args...) = ...</code></li>
<li>A function inside another function (a closure).
<ul dir="auto">
<li>But note the outer function will still be stabilized. So, e.g., <code>@stable f(x) = map(xi -&gt; xi^2, x)</code> would stabilize <code>f</code>, but not <code>xi -&gt; xi^2</code>. Though if <code>xi -&gt; xi^2</code> were unstable, <code>f</code> would likely be as well, and it would get caught!</li>
</ul>
</li>
</ul>
</li>
</ol>
<p dir="auto">Note that you can safely use <code>@stable</code> over all of these cases, and special cases will automatically be skipped. Although, if you use <code>@stable</code> internally in some of these cases, like calling <code>@stable</code> within a function on a closure, such as directly on the <code>xi -&gt; xi^2</code>, then it can still apply.</p>

<p dir="auto">Say that you start using <code>@stable</code> and you run into a type instability error.
What then? How should you fix it?</p>
<p dir="auto">The first thing you can try is using <code>@code_warntype</code> on the
function in question, which will highlight each individual variable's
type with a special color for any instabilities.</p>
<p dir="auto">Note that some of the lines you will see are from DispatchDoctor's inserted
code. If those are bothersome, you can disable the checking with
<code>Preferences.set_preferences!("MyPackage", "instability_check" =&gt; "disable")</code>
followed by restarting Julia.</p>
<p dir="auto">Other, much more powerful options to try include
<a href="https://github.com/JuliaDebug/Cthulhu.jl">Cthulhu.jl</a> and
<a href="https://github.com/aviatesk/JET.jl/">JET.jl</a>, which can
provide more detailed type instability reports in an easier-to-read
format than <code>@code_warntype</code>. Both packages can also descend into
your function calls to help you locate the source of the instability.</p>

<ul dir="auto">
<li>Using <code>@stable</code> is likely to increase precompilation time. (To reduce this effect, try the <code>default_codegen_level</code> above)</li>
<li>Using <code>@stable</code> over an entire package may result in flagging type instabilities on small functions that act as aliases and may otherwise be inlined by the Julia compiler. Try putting <code>@unstable</code> on any suspected such functions if needed.</li>
</ul>
