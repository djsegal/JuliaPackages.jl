<p dir="auto">Interactive <a href="https://github.com/JuliaPlots/Makie.jl">Makie</a> plots in <a href="https://github.com/JuliaGtk/Gtk4.jl">Gtk4</a> windows.</p>
<p dir="auto">This package combines GTK's GtkGLArea and the GLMakie backend. Mouse and keyboard interactivity works just like in GLMakie's GLFW-based backend. There are two ways to draw GLMakie plots using Gtk4Makie:</p>
<ol dir="auto">
<li>As single plots in windows (<code>GTKScreen</code>).</li>
<li>In widgets (<code>GtkMakieWidget</code>), which can be placed at will inside other Gtk4 layout widgets.</li>
</ol>
<p dir="auto">For the window-based plots, Control-W (or Command-W on a Mac) closes the window and F11 (or Command-Shift-F on a Mac) fullscreens the window. Control-S (or Command-S on a Mac) opens a dialog for saving the figure to a PNG file.</p>
<p dir="auto">The widget (#2 above) is unfortunately currently not stable. There is an issue with adding new plots to an existing widget (see <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="2046495603" data-permission-text="Title is private" data-url="https://github.com/JuliaGtk/Gtk4Makie.jl/issues/14" data-hovercard-type="issue" data-hovercard-url="/JuliaGtk/Gtk4Makie.jl/issues/14/hovercard" href="https://github.com/JuliaGtk/Gtk4Makie.jl/issues/14">#14</a>), and not setting up the widget in the right way results in a crash. <strong>Users should use option #1 if at all possible.</strong></p>

<p dir="auto">Note that unlike previous versions, with version 0.2 Gtk4Makie can behave like a Makie backend. This is still experimental (and buggy) and is disabled by default. To enable it call <code>Gtk4Makie.enable_backend(true)</code>.</p>

<p dir="auto">Gtk4Makie has been successfully run on Windows, MacOS, and Linux. However, a problem has been reported by one Linux user on NVidia hardware (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="1650578842" data-permission-text="Title is private" data-url="https://github.com/JuliaGtk/Gtk4Makie.jl/issues/7" data-hovercard-type="issue" data-hovercard-url="/JuliaGtk/Gtk4Makie.jl/issues/7/hovercard" href="https://github.com/JuliaGtk/Gtk4Makie.jl/issues/7">#7</a>). On Wayland, getting GTK4's OpenGL backend to work may require a bit of configuration (see <a href="https://github.com/JuliaGtk/Gtk4.jl#enabling-gtk4s-egl-backend-linux">here</a>). On some modern Linux distributions, GTK4's OpenGL backend (at least the version of the GTK4 library used by Gtk4.jl) does not work on Wayland (<a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="2481862188" data-permission-text="Title is private" data-url="https://github.com/JuliaGtk/Gtk4.jl/issues/72" data-hovercard-type="issue" data-hovercard-url="/JuliaGtk/Gtk4.jl/issues/72/hovercard" href="https://github.com/JuliaGtk/Gtk4.jl/issues/72">JuliaGtk/Gtk4.jl#72</a>).</p>
<p dir="auto">Users should be aware that this package unavoidably relies on Makie internals and is likely to break from time to time when upgrading Makie.</p>
<p dir="auto">Finally, since it is based on Gtk4.jl, going beyond simple use of this package requires some knowledge of the GTK API. Those seeking a smoother experience should consider <a href="https://github.com/Clemapfel/MousetrapMakie.jl">MousetrapMakie.jl</a>, <a href="https://github.com/Clemapfel/Mousetrap.jl">Mousetrap.jl</a>'s package for Makie integration.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Using <code>GTKScreen</code> (one GLMakie screen per GtkWindow)</h3><a id="user-content-using-gtkscreen-one-glmakie-screen-per-gtkwindow" class="anchor" aria-label="Permalink: Using GTKScreen (one GLMakie screen per GtkWindow)" href="#using-gtkscreen-one-glmakie-screen-per-gtkwindow"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This associates a Makie screen (which is basically a canvas) to a <code>GtkWindow</code>, much like the GLMakie backend draws its plots one at a time inside GLFW windows. In Gtk4Makie, the Makie plot is shown in a <code>GtkGLArea</code> that is placed inside a <code>GtkGrid</code>. To add other widgets around the Makie plot in the <code>GTKScreen</code>, you can get the <code>GtkGrid</code> using <code>g = grid(screen)</code>. Widgets can then be added using, for example, <code>g[1,2] = GtkButton("Do something")</code> (adds a button below the plot) or <code>insert!(g, glarea(screen), :top); g[1,1] = GtkButton("Do something else")</code> (adds a button above the plot).</p>
<p dir="auto">The constructor for <code>GTKScreen</code> accepts the following keyword arguments:</p>
<ul dir="auto">
<li><code>size</code>: sets the initial default width and height of the window in pixels</li>
<li><code>title</code>: a string to use as the window title</li>
<li><code>fullscreen</code>: if <code>true</code>, the window is set to fullscreen mode immediately</li>
</ul>
<p dir="auto">By default (except on Mac OS), Gtk4Makie screen windows include a header bar with a menu button. To omit the header bar, create a screen using, for example, <code>GTKScreen(false; resolution=(800, 800))</code>.</p>
<p dir="auto">For a Gtk4Makie <code>Screen</code>, you can access the <code>GtkGLArea</code> where it draws Makie plots using <code>glarea(screen)</code> and the GTK window it's in using <code>window(screen)</code>.</p>

<p dir="auto">The <code>push!</code> function adds a Makie <code>Figure</code> to the widget. This plot widget is what one would expect to work in a package like this, but unfortunately it currently has a lot of problems, as mentioned earlier, and it is not recommended at this time.</p>

<p dir="auto">A window showing the axes and plots in a figure and their attributes can be opened using <code>attributes_window(f=current_figure())</code>. This can be used to experiment with various attributes, or add axis labels and titles before saving a plot. This functionality is experimental, buggy, and likely to grow and evolve over time.</p>
