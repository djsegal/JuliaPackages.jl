<p dir="auto">A code generator for creating Julia projects from SVD files.</p>
<p dir="auto">This package is based on <a href="https://www.keil.com/pack/doc/CMSIS/SVD/html/index.html" rel="nofollow">https://www.keil.com/pack/doc/CMSIS/SVD/html/index.html</a>, but not a complete
implementation of the specification. If you get an error or warning while using this package,
please open an issue (with the SVD in question included, if possible).</p>
<p dir="auto">Known not working:</p>
<ul dir="auto">
<li>Deriving registers/fields from registers/fields that are not direct siblings.</li>
<li>This is mostly because I don't have an example SVD making use of that feature.</li>
</ul>
<p dir="auto">Additionally, it's possible that some definitions generated by this package could have a bug; make sure to check the generated
code for compliance with your SVD. Please do report any bugs discovered through this in an issue.</p>

<p dir="auto">The main API of this package are <code>generateProject</code> and <code>readSVD</code>. Please check their respective docstrings for usage.
In addition to these, the structs <code>Device</code>, <code>Peripheral</code>, <code>Register</code>, <code>Field</code> and <code>CPU</code> are also considered API. Their fieldnames
are inspired by the names from the SVD specification.</p>

<p dir="auto">The source SVD file is placed under <code>src/SVD</code> with its original name. When regenerating, only <code>src/Name.jl</code>, <code>src/peripherals.jl</code> and the <code>src/peripherals</code> directory
will be deleted &amp; regenerated. It is safe to add other directories to the project.</p>

<p dir="auto">To access the data of e.g. the <code>CS</code> register in peripheral <code>ADC</code>, use <code>ADC.CSMod.Reg[]</code>, which will return a bitfield describing the register.
To read a single field of that register, use <code>ADC.CSMod.FieldA[]</code>. Likewise, setting the register/field works through <code>setindex!</code> without indexing arguments.</p>
