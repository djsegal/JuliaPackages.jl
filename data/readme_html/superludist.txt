<p dir="auto">SuperLUDIST.jl is Julia wrapper around the <a href="https://github.com/xiaoyeli/superlu_dist">superlu_dist</a> distributed sparse factorization library. superlu_dist contains a set of subroutines to solve a sparse linear system A*X=B.</p>
<p dir="auto">SuperLUDIST is a parallel extension to the serial SuperLU library. It is targeted for the distributed memory parallel machines. SuperLUDIST is implemented in ANSI C, with OpenMP for on-node parallelism and MPI for off-node communications. We are actively developing GPU acceleration capabilities.</p>

<p dir="auto"><code>SuperLUDIST.jl</code> is available in the General registry through Julia's package manager.
Enter the Pkg REPL mode by typing <code>]</code> in the Julia REPL and then run:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; add SuperLUDIST"><pre>pkg<span class="pl-k">&gt;</span> add SuperLUDIST</pre></div>
<p dir="auto">or equivalently via the <code>Pkg.jl</code> API:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; import Pkg; Pkg.add(&quot;SuperLUDIST&quot;)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">import</span> Pkg; Pkg<span class="pl-k">.</span><span class="pl-c1">add</span>(<span class="pl-s"><span class="pl-pds">"</span>SuperLUDIST<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">Proper use of <code>SuperLUDIST.jl</code> will typically also require <code>MPI.jl</code>, <code>SparseBase.jl</code> and possibly <code>MatrixMarket.jl</code>. These can be installed from the Pkg REPL mode:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; add MPI SparseBase MatrixMarket"><pre>pkg<span class="pl-k">&gt;</span> add MPI SparseBase MatrixMarket</pre></div>
<p dir="auto">or equivalently:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; Pkg.add(&quot;MPI&quot;, &quot;SparseBase&quot;, &quot;MatrixMarket&quot;)"><pre>julia<span class="pl-k">&gt;</span> Pkg<span class="pl-k">.</span><span class="pl-c1">add</span>(<span class="pl-s"><span class="pl-pds">"</span>MPI<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>SparseBase<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>MatrixMarket<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">The binaries provided with Julia may not work correctly on your machine (this is currently affecting at least NERSC Perlmutter).
If this is the case you may provide your own library with:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="SuperLUDIST.set_libraries!(; libsuperlu_dist_Int32 = &lt;PATH TO 32 BIT LIBRARY&gt;, libsuperlu_dist_Int64 = &lt;PATH TO 64 BIT LIBRARY&gt;)"><pre>SuperLUDIST<span class="pl-k">.</span><span class="pl-c1">set_libraries!</span>(; libsuperlu_dist_Int32 <span class="pl-k">=</span> <span class="pl-k">&lt;</span>PATH TO <span class="pl-c1">32</span> BIT LIBRARY<span class="pl-k">&gt;</span>, libsuperlu_dist_Int64 <span class="pl-k">=</span> <span class="pl-k">&lt;</span>PATH TO <span class="pl-c1">64</span> BIT LIBRARY<span class="pl-k">&gt;</span>)</pre></div>
<p dir="auto">These libraries should be built with the proper integer size (32 bit or 64 bit),
and should be linked against the MPI used by MPI.jl (on HPC clusters this should be your system MPI).</p>
<p dir="auto">You may provide one or the other, or both, but if the 32 or 64 bit integer libraries are unavailable 32 bit or 64 bit matrices will be unavailable respectively.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Examples for running in replicated and distributed mode are provided in the examples directory. To run these examples
follow the instructions provided <a href="https://juliaparallel.org/MPI.jl/latest/configuration/" rel="nofollow">here</a> to set up your MPI correctly. In particular <code>mpiexecjl</code> should be in your path (it is typically found in <code>~/.julia/bin</code>)</p>
<p dir="auto">Then you can invoke a driver example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="mpiexecjl -n &lt;nprocs&gt; julia --project examples/basic_example.jl"><pre class="notranslate"><code>mpiexecjl -n &lt;nprocs&gt; julia --project examples/basic_example.jl
</code></pre></div>
<p dir="auto">This command does a couple things. The first part launches MPI with <code>&lt;nprocs&gt;</code> ranks. The second part <code>julia --project</code> activates the current folder. If your installation is in the global environment you may omit <code>--project</code>, or provide a path to the environment you would like to use: <code>--project=~/MySuperLUProject</code>. Finally <code>examples/pdrive.jl</code> is the Julia script to be executed under MPI.</p>
<p dir="auto">Driver routine examples are found in the <code>examples</code> folder of this repository. The examples currently cover basic usage of <code>pgssvx</code> and <code>pgssvx_ABglobal</code> driver routines. These routines load matrix market files and generate right hand sides, which is not a typical use-case. Instead users will often build a submatrix on each rank, and construct a <code>DistributedSuperMatrix</code>.</p>

<ul dir="auto">
<li>CUDA support is currently disabled.</li>
<li>OpenMP will often oversubscribe single node setups. In this case you should use <code>SuperLUDIST.superlu_set_num_threads(Int32, &lt;num&gt;)</code> or <code>SuperLUDIST.superlu_set_num_threads(Int64, &lt;num&gt;)</code> to the number of OpenMP threads desired on each rank.</li>
</ul>
