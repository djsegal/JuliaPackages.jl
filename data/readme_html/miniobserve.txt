<p dir="auto">Minimalist (and minimally intrusive) macro set for extracting information from complex objects.</p>
<p dir="auto">Given a complex object <code>MiniObserve</code> lets you generate functions to extract and print information from that object by means of a simple declarative interface. It can for example be used to extract information from a simulation model at each time step and write that information to a file.</p>
<p dir="auto">Using MiniObserve has several advantages over hand-written analysis code:</p>
<ul dir="auto">
<li>a concise declarative interface that puts all information in one place</li>
<li>output variables are declared once and output is automatically formatted correctly =&gt; adding and removing output variables becomes much less error-prone</li>
<li>a lot of tedious, repetitive and thus brittle code can be avoided</li>
</ul>

<p dir="auto">Most of the heavy lifting is done by the <code>@observe</code> macro:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@observe(statstype, model [, user_arg1...], declarations)"><pre><span class="pl-c1">@observe</span>(statstype, model [, user_arg1<span class="pl-k">...</span>], declarations)</pre></div>
<p dir="auto">It will generate a custom data type to hold the desired information and an overload of the <code>observe</code> function that - given a model object - will calculate the information and return a data object.</p>

<p dir="auto">As a simple example, let us assume we have the following <code>@observe</code> declaration:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@observe Data model user1 user2 begin
	@record &quot;time&quot;      model.time
	@record &quot;N&quot;     Int length(model.population)

	@for ind in model.population begin
		@stat(&quot;capital&quot;, MaxMinAcc{Float64}, MeanVarAcc{FloatT}) &lt;| ind.capital
		@stat(&quot;n_alone&quot;, CountAcc)           &lt;| has_neighbours(ind)
	end

	@record u1			user1
	@record u2			user1 * user2
end"><pre><span class="pl-c1">@observe</span> Data model user1 user2 <span class="pl-k">begin</span>

	<span class="pl-c1">@for</span> ind <span class="pl-k">in</span> model<span class="pl-k">.</span>population <span class="pl-k">begin</span>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Additional parameters</h2><a id="user-content-additional-parameters" class="anchor" aria-label="Permalink: Additional parameters" href="#additional-parameters"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Note that <code>@observe</code> can take arbitrarily many parameters. Of these only the first two (the name of the data type and a model) and the last (the declaration itself) are required. All parameters between the second and the last are passed through unchanged and can for example be used to print additional information that is not part of the model object.</p>
<p dir="auto">In fact there is nothing preventing a user from using <code>@observe</code> on several complex objects at the same time by for example passing two different model objects to <code>observe</code>.</p>

<p dir="auto">An important part of MiniObserve is the ability to analyse collections of items by funneling them through "accumulator" objects. This is particularly important for models that operate on populations of objects, such as agent-based or individual-based models.</p>
<p dir="auto">In the example above this is used in the expression</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="	@for ind in model.population begin
		@stat(&quot;capital&quot;, MaxMinAcc{Float64}, MeanVarAcc{FloatT}) &lt;| ind.capital
		@stat(&quot;n_alone&quot;, CountAcc)           &lt;| has_neighbours(ind)
	end"><pre>	<span class="pl-c1">@for</span> ind <span class="pl-k">in</span> model<span class="pl-k">.</span>population <span class="pl-k">begin</span>
		<span class="pl-c1">@stat</span>(<span class="pl-s"><span class="pl-pds">"</span>capital<span class="pl-pds">"</span></span>, MaxMinAcc{Float64}, MeanVarAcc{FloatT}) <span class="pl-k">&lt;</span><span class="pl-k">|</span> ind<span class="pl-k">.</span>capital
		<span class="pl-c1">@stat</span>(<span class="pl-s"><span class="pl-pds">"</span>n_alone<span class="pl-pds">"</span></span>, CountAcc)           <span class="pl-k">&lt;</span><span class="pl-k">|</span> <span class="pl-c1">has_neighbours</span>(ind)
	<span class="pl-k">end</span></pre></div>
<p dir="auto">The code generated by the macro iterates through <code>model.population</code> and adds some properties of each element to several accumulators that calculate maximum, minimum, variance and mean or count the number of true predicate values, respectively.</p>
<p dir="auto">A few simple accumulators are provided in <code>StatsAccumulator</code>.</p>
