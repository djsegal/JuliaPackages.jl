<p dir="auto">Julia's <code>Semaphore</code> is different from the one described in the book in that it has extra constraints:</p>
<ul dir="auto">
<li><code>Semaphore(sem_size &gt; 0)</code>, i.e. you can't create a <code>Semaphore(0)</code>.</li>
<li>The number of releases (signal) and acquires (wait) must match.
For this reason, we cannot implement the examples with <code>Semaphore</code> without further ado.</li>
</ul>
<p dir="auto">In Julia, most of the time you don't use a <code>Semaphore</code> directly. Instead, you can use a lock (<code>ReentrantLock</code>), which corresponds to a <code>Semaphore(1)</code>, and a <code>Threads.Condition</code> for what is done with "<code>Semaphore(0)</code>" in the book.</p>

<ul dir="auto">
<li><code>barrier.jl</code>: A simple barrier at which all participating tasks wait for each other before moving on.</li>
<li><code>producer_consumer.jl</code>: Producer tasks produce elements (in parallel) and independent consumer tasks process them (in parallel). Can be used/generalized for pipelining.</li>
<li><code>readers_writers.jl</code>: "Critical" section with categorical mutual exclusion of reader tasks (non-exclusive access) and writer tasks (exclusive access). The simpler case of a purely exclusive critical section is not covered because it can simply be realized with a lock.</li>
<li><code>dining_philosophers.jl</code>: Avoid circular synchronization deadlock appearing in the <a href="https://en.wikipedia.org/wiki/Dining_philosophers_problem" rel="nofollow">Dining philosophers problem</a> formulated by Dijkstra.</li>
<li><code>h2o.jl</code>: U.C. Berkeley exercise in which two kinds of tasks, hydrogen and oxygen, should pair up such that they can pass a barrier as complete H₂O molecules (2 H + 1 O → H₂O).</li>
</ul>
