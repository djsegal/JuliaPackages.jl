<p dir="auto">Julia's REPL and its modes are superb. They also offer a variety of ways to interact with the underlying file system -- the <code>cd("somedir")</code> function, a full-blown shell mode, macro capabilities, etc. Yet all involve just a <em>tiny</em> bit more typing of (often shifted) chars, or a mode switch.</p>
<p dir="auto">Shelly provides a modeless and minimal-keystroke way of navigating the file system with <code>cd</code>, <code>ls</code>, and <code>ll</code>, or <code>dir</code> on Windows. (Use <code>lla</code>, <code>lsa</code>, or <code>dira</code> to also show hidden files.) On Linux, some additional Unix shortcuts are available.</p>
<p dir="auto">Shelly does not hack the REPL. Instead, it just uses <code>show</code> on custom types, and it overloads a special-case multiplication (<em>multiply and conquer</em>, if you will). Find out how it works below the examples.</p>
<p dir="auto"><strong>Install with:</strong></p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; add Shelly
julia&gt; using Shelly"><pre>pkg<span class="pl-k">&gt;</span> add Shelly
julia<span class="pl-k">&gt;</span> <span class="pl-k">using</span> Shelly</pre></div>
<p dir="auto"><em>Or, to avoid name collisions, maybe just selectively <code>import</code> the ones you like:</em></p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; import Shelly: ll, lla, ls, lsa, df, ldf, ps1, cc, °,  [Linux only-&gt;] head, tail, wc    # or any subset"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">import</span> Shelly<span class="pl-k">:</span> ll, lla, ls, lsa, df, ldf, ps1, cc, °,  [Linux only<span class="pl-k">-&gt;</span>] head, tail, wc    <span class="pl-c"><span class="pl-c">#</span> or any subset</span></pre></div>
<p dir="auto">In particular, <code>ls</code> might clash with <a href="https://github.com/umlet/FileJockey.jl">FileJockey.jl</a>'s <code>ls()</code> function. But you can always create your own shortcut to it with <code>myls = Shelly.ls</code>.</p>
<p dir="auto"><em>Note: There is no need to import <code>cd</code> or <code>cat</code> -- learn why below.</em>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">How Does it Work?</h2><a id="user-content-how-does-it-work" class="anchor" aria-label="Permalink: How Does it Work?" href="#how-does-it-work"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">Shortcuts like <code>ls</code> and <code>ll</code> are simple -- they are just values:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="struct ShortcutLs &lt;: AbstractShortcut end

const ls = ShortcutLs()"><pre class="notranslate"><code>struct ShortcutLs &lt;: AbstractShortcut end

const ls = ShortcutLs()
</code></pre></div>
<p dir="auto">The <code>Base.show</code> method calls <code>Shelly.atshow</code> for all <code>AbstractShortcut</code>s, where the actual <code>ls</code> printing takes place:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="atshow(_::ShortcutLs) = _ls()"><pre class="notranslate"><code>atshow(_::ShortcutLs) = _ls()
</code></pre></div>
<p dir="auto">Note: following the above logic, you can easily define your own shortcuts!</p>
</li>
<li>
<p dir="auto">Shortcuts that require an argument, like <code>cd</code>, work differently.</p>
<p dir="auto">First, Julia provides a neat way of parsing multiplication without the <code>*</code> operator:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; x = 21
julia&gt; 2x
42"><pre class="notranslate"><code>julia&gt; x = 21
julia&gt; 2x
42
</code></pre></div>
<p dir="auto">If x is of some new, custom type, we can override the multiplication operation:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Base.:*(i::Int64, _::SomeNewType) = ..."><pre class="notranslate"><code>Base.:*(i::Int64, _::SomeNewType) = ...
</code></pre></div>
<p dir="auto">But here we want to use the string <code>cd</code>, which is an already-defined Julia function. Luckily, we don't even have to dispatch on functions in general, but we can dispatch on the <code>cd</code>s singleton type as seen in:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; typeof(cd)
typeof(cd) (singleton type of function cd, subtype of Function)"><pre class="notranslate"><code>julia&gt; typeof(cd)
typeof(cd) (singleton type of function cd, subtype of Function)
</code></pre></div>
<p dir="auto">We can thus use:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Base.:*(i::Int64, _::typeof(cd)) = ShortcutCd(i)"><pre class="notranslate"><code>Base.:*(i::Int64, _::typeof(cd)) = ShortcutCd(i)
</code></pre></div>
<p dir="auto">And underneath, the same logic as above is then at work:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="atshow(x::ShortcutCd) = _cd(x.i)"><pre class="notranslate"><code>atshow(x::ShortcutCd) = _cd(x.i)
</code></pre></div>
</li>
</ul>
