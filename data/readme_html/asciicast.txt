<p dir="auto">Asciicast.jl is all about showcasing Julia code running in a REPL using
technologies developed by the open-source
<a href="https://asciinema.org/" rel="nofollow">asciinema</a> project. (It is totally unaffiliated
with the authors of that project, however).</p>
<p dir="auto">It does so in a few ways:</p>
<ul dir="auto">
<li>provides a convenient way to generate and maintain gifs showing code
execution in READMEs and other documents. See the <a href="https://ericphanson.github.io/Asciicast.jl/dev/markdown_usage/" rel="nofollow">Markdown
Usage</a>
portion of the docs.</li>
<li>provides integration with Documenter, providing <code>@cast</code> Documenter
blocks that render code outputs as gifs in Documenter websites. See
the <a href="https://ericphanson.github.io/Asciicast.jl/dev/documenter_usage/" rel="nofollow">Documenter
Usage</a>
portion of the docs.</li>
<li>provides functionality to generate <code>asciicast</code> files (using the <a href="https://github.com/asciinema/asciinema/blob/asciicast-v2/doc/asciicast-v2.md">v2
file
format</a>)
from Julia code, using the <code>cast""</code> string macro, a <code>record_output</code>
function, or using low-level <code>write_event</code> commands. These files can
be played in the terminal or uploaded to asciinema.org with the
<code>asciinema</code> player, or played in a web browser using
<a href="https://github.com/asciinema/asciinema-player">asciinema-player</a>. See
the <a href="https://ericphanson.github.io/Asciicast.jl/dev/" rel="nofollow">docs</a> for more.</li>
</ul>

<ul dir="auto">
<li>It is easy to use the CLI tool <a href="https://asciinema.org/" rel="nofollow">asciinema</a> directly to record sessions to <code>.cast</code> files or otherwise. That can be a good option if you need keyboard input or face some of the other <a href="https://ericphanson.github.io/Asciicast.jl/dev/limitations/#Limitations" rel="nofollow">Limitations of asciicast.jl</a>.
<ul dir="auto">
<li>In contrast, Asciicast.jl has an advantage in maintainability, in that you don't need to manually re-run sessions to regenerate the outputs.</li>
</ul>
</li>
<li><a href="https://github.com/AtelierArith/Replay.jl">Replay.jl</a> provides a similar Julia-based alternative. Some of the differences I can ascertain:
<ul dir="auto">
<li>Asciicast.jl is based on Documenter's code execution sandboxes (which <a href="https://ericphanson.github.io/Asciicast.jl/dev/limitations/#Cannot-rely-on-stdout-(or-stderr)-in-one-line-being-still-open-in-the-next" rel="nofollow">have their limitations</a>), while Replay.jl has it's own implementation.</li>
<li>Asciicast.jl provides Documenter and pandoc-based document integration with <code>@cast</code> blocks and <code>{cast="true"}</code> blocks, while Replay seems focused on the core replaying-of-sessions. Perhaps these could be composed together somehow?</li>
<li>Possibly other differences; I am not very familiar with Replay.jl. PRs to improve this comparison are appreciated!</li>
</ul>
</li>
</ul>
