<p dir="auto">This package aims to provide a nice interface for compression of multiple arrays of the same size in
sequence. These arrays can be up to 4D. The intended application is to store snapshots of a iterative
process such as a simulation or optimization process. Since sometimes these processes may require a lot of iterations, having compression might save you some RAM. This package uses the <a href="https://zfp.io/" rel="nofollow">ZFP compression algorithm</a> algorithm.</p>

<p dir="auto">This code implements an vector like interface to access compressed
arrays at different time indexes, so to understand the code you need
to first read <a href="https://docs.julialang.org/en/v1/manual/interfaces/#Indexing" rel="nofollow">the julia documentation on indexing
interfaces</a>.
Basically, I had to implement a method for the <code>Base.getindex</code> function which governs if an type
can be indexed like an array or vector. I also wrote a method for the function <code>Base.append!</code> to
add new arrays to the sequential collection of compressed arrays.</p>
<p dir="auto">I also use functions like <a href="https://docs.julialang.org/en/v1/base/arrays/#Base.fill" rel="nofollow"><code>fill</code></a> and
<a href="https://docs.julialang.org/en/v1/base/collections/#Base.map" rel="nofollow"><code>map</code></a>, so reading the documentation
on these functions might also help.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Lossy compression</h2><a id="user-content-lossy-compression" class="anchor" aria-label="Permalink: Lossy compression" href="#lossy-compression"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Lossy compression is achieved by specifying additional keyword arguments
for <code>SeqCompressor</code>, which are <code>tol::Real</code>, <code>precision::Int</code>, and <code>rate::Real</code>.
If none are specified (as in the example above) the compression is lossless
(i.e. reversible). Lossy compression parameters are</p>
<ul dir="auto">
<li><a href="https://zfp.readthedocs.io/en/release0.5.5/modes.html#fixed-accuracy-mode" rel="nofollow"><code>tol</code> defines the maximum absolute error that is tolerated.</a></li>
<li><a href="https://zfp.readthedocs.io/en/release0.5.5/modes.html#fixed-precision-mode" rel="nofollow"><code>precision</code> controls the precision, bounding a weak relative error</a>, see this <a href="https://zfp.readthedocs.io/en/develop/faq.html#q-relerr" rel="nofollow">FAQ</a></li>
<li><a href="https://zfp.readthedocs.io/en/release0.5.5/modes.html#fixed-rate-mode" rel="nofollow"><code>rate</code> fixes the bits used per value.</a></li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Multi file out-of-core parallel compression and decompression</h2><a id="user-content-multi-file-out-of-core-parallel-compression-and-decompression" class="anchor" aria-label="Permalink: Multi file out-of-core parallel compression and decompression" href="#multi-file-out-of-core-parallel-compression-and-decompression"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package has two workflows for compression. It can compress the array into a <code>Vector{UInt8}</code> and
keep it in memory, or it can slice the array and compress each slice, saving each slice to different
files, one per thread.</p>
<p dir="auto">To use this out-of-core approach, you have four options:</p>
<ul dir="auto">
<li>Use the <code>inmemory=false</code> keyword to <code>SeqCompressor</code>. This will create the files for you in <code>tmpdir()</code>,</li>
<li>Specify <code>filepaths::Vector{String}</code> keyword argument with a list of folders, one for each thread,</li>
<li>Specify <code>filepaths::String</code> keyword argument with just one folder that will hold all the files,</li>
<li>Specify <code>envVarPath::String</code> keyword argument with the name of a environment variable that holds
the path to the folder that will hold all the files. This might be useful if you are using a SLURM
cluster, that allows you to access the local node storage via the <code>SLURM_TMPDIR</code> environment variable.</li>
</ul>
