<p dir="auto"><em>Easy customization of startup.jl</em></p>
<p dir="auto">The goal of this package is to provide a simple and uniform way for other packages (like e.g. <code>Revise.jl</code>) to be installed into Julia's <code>startup.jl</code> file. Instead of having to locate, open and edit the file, with this package users could do something akin to:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; import StartupCustomizer
julia&gt; StartupCustomizer.add(StartupCustomizer.Revise())"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">import</span> StartupCustomizer
julia<span class="pl-k">&gt;</span> StartupCustomizer<span class="pl-k">.</span><span class="pl-c1">add</span>(StartupCustomizer<span class="pl-k">.</span><span class="pl-c1">Revise</span>())</pre></div>
<p dir="auto">This would then install <code>Revise.jl</code> into the global environment and paste the initialization code into <code>startup.jl</code> without the user needing to know anything else.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">User Guide</h2><a id="user-content-user-guide" class="anchor" aria-label="Permalink: User Guide" href="#user-guide"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">You can use:</p>
<ul dir="auto">
<li><code>StartupCustomizer.which()</code> to see where your startup file is,</li>
<li><code>StartupCustomizer.status()</code> to see what currently is in your startup.jl</li>
<li><code>StartupCustomizer.list()</code> to get a list of available modules</li>
<li><code>StartupCustomizer.describe(module)</code> to get detailed information on a module</li>
<li><code>StartupCustomizer.add(module...)</code>/<code>StartupCustomizer.remove(module...)</code> to add/remove modules</li>
<li><code>StartupCustomizer.edit()</code> to edit the startup.jl directly by hand.</li>
</ul>
<p dir="auto">Notably <code>add</code>ing modules also installs required packages into the global default environment.</p>
<p dir="auto">You can safely remove <code>StartupCustomizer.jl</code> after you modified your <code>startup.jl</code> with <code>Pkg.remove("StartupCustomizer")</code>.</p>
<p dir="auto">Currently available modules are:</p>
<ul dir="auto">
<li><code>Revise</code>: loads <a href="https://docs.julialang.org/en/v1/manual/workflow-tips/#Revise-based-workflows" rel="nofollow">Revise.jl</a></li>
<li><code>OhMyREPL</code>: enables <a href="https://kristofferc.github.io/OhMyREPL.jl/latest/" rel="nofollow">OhMyRepl.jl</a></li>
<li><code>NumberedPrompt</code>: Switches REPL to a IPython like numbered prompt style. See <a href="https://docs.julialang.org/en/v1/stdlib/REPL/#Numbered-prompt" rel="nofollow">manual</a>.</li>
<li><code>PkgTemplates</code>: defines a function <code>template(; kwargs...)</code> which can be customized for personal preference (see their <a href="https://juliaci.github.io/PkgTemplates.jl/stable/user/#Saving-Templates-1" rel="nofollow">documentation</a>)</li>
</ul>

<p dir="auto">The main concept of this package is that of a <code>StartupModule</code> which handles something you want to put into your startup.jl. All one needs to do to add something new is to make a subtype of <code>AbstractStartupModule</code> and implement 4 methods <code>short_description</code>, <code>long_description</code>, <code>_dependencies</code> and <code>_generate</code>. It is recommended to put the code a module emit into the <code>/templates</code> directory to keep things tidy and have editor support for writing that code.</p>
<p dir="auto">For <code>add</code>,<code>remove</code>,<code>status</code>, this package scans <code>startup.jl</code> to determine what it has written there previously. Only parts that are recognized are ever altered. This package marks section by wrapping them in comments like <code># begin StartupCustomizer.Revise()</code> and <code># end StartupCustomizer.Revise()</code>. These comments also serve as storage for the parameters of the modules, so modules should take care that they are reconstructable from their string representation.</p>
