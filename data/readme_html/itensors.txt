<p dir="auto">The source code for ITensor can be found <a href="https://github.com/ITensor/ITensors.jl">on Github</a>.</p>
<p dir="auto">Additional documentation can be found on the ITensor website <a href="https://itensor.org/" rel="nofollow">itensor.org</a>.</p>
<p dir="auto">An ITensor is a tensor whose interface
is independent of its memory layout. ITensor indices are
objects which carry extra information and which
'recognize' each other (compare equal to each other).</p>
<p dir="auto">The ITensor library also includes composable and extensible
algorithms for optimizing and transforming tensor networks, such as
matrix product state and matrix product operators, such as
the DMRG algorithm.</p>
<p dir="auto">Development of ITensor is supported by the Flatiron Institute, a division of the Simons Foundation.</p>

<ul dir="auto">
<li>
<p dir="auto">May 9, 2024: A new package <a href="https://github.com/ITensor/ITensorMPS.jl">ITensorMPS.jl</a> has been released. We plan to move all of the MPS/MPO functionality in <a href="https://github.com/ITensor/ITensors.jl">ITensors.jl</a> to <a href="https://github.com/ITensor/ITensorMPS.jl">ITensorMPS.jl</a>. For now, ITensorMPS.jl just re-exports the MPS/MPO functionality of ITensors.jl (as well as of <a href="https://github.com/ITensor/ITensorTDVP.jl">ITensorTDVP.jl</a>), such as <code>dmrg</code>, <code>siteinds</code>, <code>MPS</code>, <code>MPO</code>, etc. To prepare for the change over to ITensorMPS.jl, please change <code>using ITensors</code> to <code>using ITensors, ITensorMPS</code> in any code that makes use of MPS/MPO functionality, and if you are using ITensorTDVP.jl change <code>using ITensorTDVP</code> to <code>using ITensorMPS</code> in your code.</p>
</li>
<li>
<p dir="auto">May 8, 2024: ITensors.jl v0.6 has been released. This version deletes the experimental "combine-contract" contraction backend, which was enabled by <code>ITensors.enable_combine_contract()</code>. This feature enabled performing ITensor contractions by first combining indices and then performing contractions as matrix multiplications, which potentially could lead to speedups for certain contractions involving higher-order QN-conserving tensors. However, the speedups weren't consistent with the current implementation, and this feature will be incorporated into the library in a more systematic way when we release our new non-abelian symmetric tensor backend.</p>
</li>
<li>
<p dir="auto">May 2, 2024: ITensors.jl v0.5 has been released. This version removes PackageCompiler.jl as a dependency and moves the package compilation functionality into a package extension. In order to use the <code>ITensors.compile()</code> function going forward, you need to install the PackageCompiler.jl package with <code>using Pkg: Pkg; Pkg.add("PackageCompiler")</code> and put <code>using PackageCompiler</code> together with <code>using ITensors</code> in your code.</p>
</li>
<li>
<p dir="auto">April 16, 2024: ITensors.jl v0.4 has been released. This version removes HDF5.jl as a dependency and moves the HDF5 read and write functions for ITensor, MPS, MPO, and other associated types into a package extension. To enable ITensor HDF5 features, install the HDF5.jl package with <code>using Pkg: Pkg; Pkg.add("HDF5")</code> and put <code>using HDF5</code> together with <code>using ITensors</code> in your code. Other recent changes include support for multiple GPU backends using package extensions.</p>
</li>
<li>
<p dir="auto">March 25, 2022: ITensors.jl v0.3 has been released. The main breaking change is that we no longer support versions of Julia below 1.6. Julia 1.6 is the long term support version of Julia (LTS), which means that going forward versions below Julia 1.6 won't be as well supported with bug fixes and improvements. Additionally, Julia 1.6 introduced many improvements including syntax improvements that we would like to start using with ITensors.jl, which becomes challenging if we try to support Julia versions below 1.6. See <a href="https://www.oxinabox.net/2021/02/13/Julia-1.6-what-has-changed-since-1.0.html" rel="nofollow">here</a> and <a href="https://julialang.org/blog/2021/03/julia-1.6-highlights/" rel="nofollow">here</a> for some nice summaries of the Julia 1.6 release.</p>
</li>
<li>
<p dir="auto">Jun 09, 2021: ITensors.jl v0.2 has been released, with a few breaking changes as well as a variety of bug fixes
and new features. Take a look at the <a href="https://itensor.github.io/ITensors.jl/stable/UpgradeGuide_0.1_to_0.2.html" rel="nofollow">upgrade guide</a>
for help upgrading your code.</p>
</li>
</ul>

<p dir="auto">The ITensors package can be installed with the Julia package manager.
From the Julia REPL, type <code>]</code> to enter the Pkg REPL mode and run:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="~ julia"><pre class="notranslate"><code>~ julia
</code></pre></div>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; ]

pkg&gt; add ITensors"><pre>julia<span class="pl-k">&gt;</span> ]

pkg<span class="pl-k">&gt;</span> add ITensors</pre></div>
<p dir="auto">Or, equivalently, via the <code>Pkg</code> API:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; import Pkg; Pkg.add(&quot;ITensors&quot;)"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-k">import</span> Pkg; Pkg<span class="pl-k">.</span><span class="pl-c1">add</span>(<span class="pl-s"><span class="pl-pds">"</span>ITensors<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">Please note that right now, ITensors.jl requires that you use Julia v1.3 or later (since ITensors.jl relies on a feature that was introduced in Julia v1.3).</p>
<p dir="auto">We recommend using ITensors.jl with Intel MKL in order to get the best possible performance. If you have not done so already, you can replace your current BLAS and LAPACK implementation with MKL by using the MKL.jl package. Please follow the instructions <a href="https://github.com/JuliaComputing/MKL.jl">here</a>.</p>

<p dir="auto">Before making an ITensor, you have to define its indices.
Tensor Index objects carry extra information beyond just their dimension.</p>
<p dir="auto">All Index objects carry a permanent, immutable id number which is
determined when it is constructed, and allow it to be matched
(compare equal) with copies of itself.</p>
<p dir="auto">Additionally, an Index can have up to four tag strings, and an
integer primelevel. If two Index objects have different tags or
different prime levels, they do not compare equal even if they
have the same id.</p>
<p dir="auto">Tags are also useful for identifying Index objects when printing
tensors, and for performing certain Index manipulations (e.g.
priming indices having certain sets of tags).</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using ITensors

<p dir="auto">DMRG is an iterative algorithm for finding the dominant
eigenvector of an exponentially large, Hermitian matrix.
It originates in physics with the purpose of finding
eigenvectors of Hamiltonian (energy) matrices which model
the behavior of quantum systems.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using ITensors, ITensorMPS
let
  # Create 100 spin-one indices
  N = 100
  sites = siteinds(&quot;S=1&quot;,N)

  # Input operator terms which define
  # a Hamiltonian matrix, and convert
  # these terms to an MPO tensor network
  # (here we make the 1D Heisenberg model)
  os = OpSum()
  for j=1:N-1
    os += &quot;Sz&quot;,j,&quot;Sz&quot;,j+1
    os += 0.5,&quot;S+&quot;,j,&quot;S-&quot;,j+1
    os += 0.5,&quot;S-&quot;,j,&quot;S+&quot;,j+1
  end
  H = MPO(os,sites)

  # Create an initial random matrix product state
  psi0 = random_mps(sites)

  # Plan to do 5 passes or 'sweeps' of DMRG,
  # setting maximum MPS internal dimensions
  # for each sweep and maximum truncation cutoff
  # used when adapting internal dimensions:
  nsweeps = 5
  maxdim = [10,20,100,100,200]
  cutoff = 1E-10

  # Run the DMRG algorithm, returning energy
  # (dominant eigenvalue) and optimized MPS
  energy, psi = dmrg(H,psi0; nsweeps, maxdim, cutoff)
  println(&quot;Final energy = $energy&quot;)

  nothing
end
