<p dir="auto">This package has been significantly re-designed as part of a work in progress with Giovanni Compiani and Adam Smith. I have removed the functionality for variable/model selection, but have significantly increased the performance of the package and improved the simplicity of use. The old code has been saved in the <code>copy_old_code</code> branch, if for some reason that code is useful for you.</p>
<p dir="auto">Please let me know if you have any suggestions for the package or find any bugs.</p>

<p dir="auto">There are three important functions included here so far: <code>define_problem</code>, <code>estimate!</code>, and <code>price_elasticity</code>:</p>
<ul dir="auto">
<li><code>define_problem(df::DataFrame; exchange = [], index_vars = ["prices"], FE = [], constraints = [], bO = 2, obj_tol = 1e-5, constraint_tol = 1e-5)</code>: Constructs a <code>problem::NPDProblem</code> using the provided problem characteristics. Inputs:
<ul dir="auto">
<li><code>exchange</code>: A vector of (at most two) groups of products which are exchangeable. E.g., with 4 goods, if the first
and second are exchangeable and so are the third and fourth, set <code>exchange</code> = [[1 2], [3 4]].</li>
<li><code>index_vars</code>: String array listing column names in <code>df</code> which represent variables that enter the inverted index.</li>
<li><code>FE</code>: String array listing column names in <code>df</code> which should be included as fixed effects.</li>
<li><code>obj_tol</code>: Tolerance specifying the value of <code>g_abstol</code> within <code>Optim.Options</code> during optimization.</li>
<li><code>constraint_tol</code>: Tolerance specifying tightness of constraints</li>
<li><code>constraints</code>: A list of symbols of accepted constraints. Currently supported constraints are:
<ul dir="auto">
<li>:monotone: Demand is increasing in the index.</li>
<li>:all_substitutes: All products are substitutes.</li>
<li>:diagonal_dominance_group: Diagonal dominance (see Compiani, 2022) within exchangeable groups.</li>
<li>:diagonal_dominance_all: Diagonal dominance across all products.</li>
<li>:subs_in_group: All products within exchangeable groupings are substitutes.(<strong>Note</strong>: this constraint is the only available nonlinear constraint and will slow down estimation considerably)</li>
</ul>
</li>
</ul>
</li>
<li><code>estimate!(problem::NPDProblem; max_iterations=10000, show_trace = false)</code>: solves <code>problem</code> subject to provided constraints, and replaces <code>problem.results</code> with the resulting parameter vector. <code>max_iterations</code> is passed into Optim.Options for every optimization step.</li>
<li><code>update_constraints!(problem::NPDProblem, new_constraints::Vector{Symbol})</code>: Replaces the constraints in <code>problem</code> with <code>new_constraints</code>. Because of the way <code>:exchangeability</code> is enforced, this function cannot be used to change the structure of exchangeable groupings.</li>
<li><code>price_elasticities!(problem::NPDProblem)</code>: Takes the solved <code>problem</code> as first argument, a <code>DataFrame</code> as the second argument, and evaluates all price elasticities in-sample. Currently does not calculate out-of-sample price elasticities. For this, use the function <code>compute_demand_function!</code>.</li>
<li><code>compute_demand_function!(problem, df; max_iter = 1000, show_trace = false)</code>: estimates the demand function/curve using NPD estimates calculated via estimate!. The function takes in an estimated problem::NPDProblem and a dataframe with counterfactual values of the covariates in the utility function. One must specify all fields that were used in estimation (including shares). The function will change the values of df[!,r"shares"] to take on the value of the estimated demand function. Options:
<ul dir="auto">
<li><code>max_iter</code>: controls the number of iterations for the nonlinear solver calculating market shares. Default is 1000 but well-estimated problems should converge faster.</li>
<li><code>show_trace</code>: if <code>true</code>, Optim will print the trace for each iteration of the nonlinear solver.</li>
</ul>
</li>
</ul>
<p dir="auto">Two helpful additional functions are <code>simulate_logit</code> and <code>toDataFrame</code>, which allows one to easily simulate data from a logit demand system with endogenous prices (and instruments for those prices) to test the <code>NPDemand</code> functions. Usage shown in <code>/examples</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Fixed Effects</h2><a id="user-content-fixed-effects" class="anchor" aria-label="Permalink: Fixed Effects" href="#fixed-effects"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Fixed effects are estimated as parameters, not absorbed from the data. So, be careful including fixed effects with too many values, as this may both slow down the optimization and require more memory.</p>
<p dir="auto">To include fixed effects (categorical variables), use the option <code>FE</code> to provide a vector of strings, where each element of the vector is a name of a column in the provided data <code>df</code>. Note however that at present, variables that are included as fixed effect must be constant across products within a market. The only exception to this rule is <code>"product"</code> which is a keyword which will produce product fixed-effects. There need not be a column named <code>product</code> in the data, and in fact the code will ignore it if it's there.</p>
