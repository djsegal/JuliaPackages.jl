<p dir="auto"><code>VLLimitOrderBook.jl</code> is a package that simulates the dynamics of an <a href="https://www.investopedia.com/terms/o/order-book.asp" rel="nofollow">Order Book</a>. An order book is an electronic list of buy and sell orders for a specific security, which is used to help illustrate the dynamics for that security. This package was based on the previous work of <a href="https://github.com/p-casgrain">p-casgrain Philippe Casgrain</a> and <a href="https://github.com/dm13450">dm13450 Dean</a> in the package <a href="https://github.com/p-casgrain/LimitOrderBook.jl">LimitOrderBook.jl</a>.</p>

<p dir="auto">The original package has the following features:</p>
<ul dir="auto">
<li>Submit and cancel limit orders and submit market orders.</li>
<li>Inspect the order book information and statistics.</li>
<li>Save the order book state to a CSV file.</li>
</ul>
<p dir="auto">Additionally, the package has fixed the following bugs in the original implementation:</p>
<ul dir="auto">
<li>The order book does not track specific users, causing the relevant account to not get updated when an order is matched and removed from the order book.</li>
<li>The order book may allow cross-match limit orders on one side of the book. This is not allowed on most major exchanges. In this package model, we will throw error if such conditions are met.</li>
</ul>
<p dir="auto">Based on original package, the following features have been added or modified:</p>
<ul dir="auto">
<li>The ability to load the order book state from a CSV file.</li>
<li>Improved code testing coverage.</li>
<li>Includes benchmarks for performance evaluation.</li>
<li>Validates accuracy and correctness of the order book from data feed messages from <a href="https://www.nasdaqtrader.com/content/technicalsupport/specifications/dataproducts/NQTVITCHSpecification.pdf" rel="nofollow">Nasdaq TotalViewITCH</a>, a direct data feed product offered by The Nasdaq Stock Market, LLC.</li>
</ul>
<p dir="auto">Based on data feed messages from Nasdaq TotalViewITCH, we also make following changes to enhance the functionality,</p>
<ul dir="auto">
<li>We have added Display &amp; Non-Display field to the Order Struct. This is because orders at the same price level may have different priorities based on their Display &amp; Non-Display features. Orders with display feature always have a higher execution priority than Non-Display orders, even if display order have joined orderbook at a later time. This will help us ensure that orders are executed in the right order.</li>
<li>We have changed the OrderTrait to be non-static and mutable variable. This is because different orders may have different order traits, and there is no way to distinguish this difference from the order feed of Nasdaq. Therefore, we needed to make changes according to specific data feed messages to ensure that we can handle order executed correctly.</li>
<li>We have also added an "allowlocking" boolean field in the OrderTrait. This field is necessary because some orders, such as pegged orders, will allow prices to lock between bid/ask prices (bid/ask price reached a same level). We cannot know this until we receive specific messages from the data feed, i.e when order are executed at different prices. So we need to make changes according to specific data feed messages to ensure that we can handle these types of orders.</li>
<li>We have modified the order to be a mutable structure. This will enable us to make changes to the original order object rather than generating a new object, which will enhance the performance and efficiency of our system</li>
</ul>
<p dir="auto">FAQ:</p>
<p dir="auto"><strong>Why notification is removed in the latest commit of the code?</strong></p>
<ul dir="auto">
<li>We did implement notification feature in the earlier <a href="https://github.com/Renruize12306/VLLimitOrderBook.jl/commit/d1773488d154122ad3fe3fe9dc8ca21d96438453">commits</a>, but we then find the that cross matching between bid/ask price is uncommon, it also lower the matching profiency of Limit Order Book. Hence, we simply remove this feature in the later iterations.</li>
</ul>
