<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is FMI.jl?</h2><a id="user-content-what-is-fmijl" class="anchor" aria-label="Permalink: What is FMI.jl?" href="#what-is-fmijl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><a href="https://github.com/ThummeTo/FMI.jl"><em>FMI.jl</em></a> is a free-to-use software library for the Julia programming language which integrates the <strong>F</strong>unctional <strong>M</strong>ock-Up <strong>I</strong>nterface (<a href="https://fmi-standard.org/" rel="nofollow">fmi-standard.org</a>): load or create, parameterize, differentiate, linearize, simulate and plot FMUs seamlessly inside the Julia programming language!</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Breaking Changes in FMI.jl (starting from v0.14.0 until release of v1.0.0)</h2><a id="user-content-breaking-changes-in-fmijl-starting-from-v0140-until-release-of-v100" class="anchor" aria-label="Permalink: Breaking Changes in FMI.jl (starting from v0.14.0 until release of v1.0.0)" href="#breaking-changes-in-fmijl-starting-from-v0140-until-release-of-v100"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If you want to migrate your project from <a href="https://github.com/ThummeTo/FMI.jl"><em>FMI.jl</em></a> &lt; v1.0.0 to &gt;= v1.0.0, you will face some breaking changes - but they are worth it as you will see! We decided to do multiple smaller breaking changes starting with v0.14.0, instead of one big one. Some of them are already implemented (checked), some are still on the todo (unchecked) but will be implemented before releasing v1.0.0.</p>
<ul class="contains-task-list">
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox" checked=""> Many functions, that are not part of the FMI-standard, had the prefix <code>fmi2...</code> or <code>fmi3...</code>. This was corrected. Now, only functions that are defined by the standard itself, like e.g. <code>fmi2Instantiate</code> are allowed to keep the prefix. Other methods, like <code>fmi2ValueReferenceToString</code>, that where added to make this library more comfortable, are now cleaned to be more the Julia way: <code>valueReferenceToString</code>. If your code errors, the corresponding function might have lost it's prefix, so try this first.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox" checked=""> Wrapper functions where removed, because that is not the Julia way. In most cases, this will not affect your code.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox" checked=""> <a href="https://github.com/ThummeTo/FMICore.jl"><em>FMICore.jl</em></a> and <a href="https://github.com/ThummeTo/FMIImport.jl"><em>FMIImport.jl</em></a> were divided into <a href="https://github.com/ThummeTo/FMICore.jl"><em>FMICore.jl</em></a>, <a href="https://github.com/ThummeTo/FMIImport.jl"><em>FMIImport.jl</em></a> and <a href="https://github.com/ThummeTo/FMIBase.jl"><em>FMIBase.jl</em></a>. <a href="https://github.com/ThummeTo/FMICore.jl"><em>FMICore.jl</em></a> now holds the pure standard definition (C-types and -functions), while <a href="https://github.com/ThummeTo/FMIBase.jl"><em>FMIBase.jl</em></a> holds everything that is needed on top of that in <a href="https://github.com/ThummeTo/FMIImport.jl"><em>FMIImport.jl</em></a> as well as in <a href="https://github.com/ThummeTo/FMIExport.jl"><em>FMIExport.jl</em></a>.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> Updated all library examples.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> Updated all library tests for a better code coverage.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> We tried to document every function, if you find undocumented user-level functions, please open an issue or PR.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> Allocations, type stability and code format where optimized and are monitored by CI now.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> Dependencies are reduced a little, to make the libraries more light-weight.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> RAM for allocated FMUs, their instances and states, is now auto-released. For maximum performance/safety you can use FMUs in blocks (like file reading/writing).</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> New low-level interfaces are introduced, that fit the SciML-ecosystem. For example, a FMU can still be simulated with <code>simulate(fmu)</code>, but one can also decide to create a <code>prob = FMUProblem(fmu)</code> (like an <code>ODEProblem</code>) and use <code>solve(prob)</code> to obtain a solution. Keywords will be adapted to have a fully consistent interface with the remaining SciML-ecosystem.</p>
</li>
<li class="task-list-item">
<p dir="auto"><input type="checkbox" id="" disabled="" class="task-list-item-checkbox"> Optimization for new Julia LTS v1.10, removing code to keep downward compatibility with old LTS v1.6.</p>
</li>
</ul>
<p dir="auto">🎉 After all listed features are implemented, v1.0.0 will be released! 🎉</p>

<p dir="auto">1. Open a Julia-REPL, switch to package mode using <code>]</code>, activate your preferred environment.</p>
<p dir="auto">2. Install <a href="https://github.com/ThummeTo/FMI.jl"><em>FMI.jl</em></a>:</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="(@v1) pkg&gt; add FMI"><pre>(@v1) pkg&gt; add FMI</pre></div>
<p dir="auto">3. If you want to check that everything works correctly, you can run the tests bundled with <a href="https://github.com/ThummeTo/FMI.jl"><em>FMI.jl</em></a>:</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="(@v1) pkg&gt; test FMI"><pre>(@v1) pkg&gt; test FMI</pre></div>
<p dir="auto">4. Have a look inside the <a href="https://github.com/ThummeTo/FMI.jl/tree/examples/examples">examples folder</a> in the examples branch or the <a href="https://thummeto.github.io/FMI.jl/dev/examples/overview/" rel="nofollow">examples section</a> of the documentation. All examples are available as Julia-Script (<em>.jl</em>), Jupyter-Notebook (<em>.ipynb</em>) and Markdown (<em>.md</em>).</p>

<p dir="auto">Contributors are welcome. Before contributing, please read, understand and follow the <a href="https://github.com/SciML/ColPrac">Contributor's Guide on Collaborative Practices for Community Packages</a>.
During development of new implementations or optimizations on existing code, one will have to make design decisions that influence the library performance and usability. The following prioritization should be the basis for decision-making:</p>
<ul dir="auto">
<li><strong>#1 Compliance with standard:</strong> It is the highest priority to be compliant with the FMI standard (<a href="https://fmi-standard.org/" rel="nofollow">fmi-standard.org</a>). Identifiers described in the standard must be used. Topologies should follow the specification as far as the possibilities of the Julia programming language allows.</li>
<li><strong>#2 Performance:</strong> Because <a href="https://github.com/ThummeTo/FMI.jl"><em>FMI.jl</em></a> is a simulation tool, performance is very important. This applies to the efficient use of CPU and GPU, but also the conscientious use of RAM and disc space.</li>
<li><strong>#3 Usability:</strong> The library should be as usable as possible and feel "the Julia way" (e.g. by using multiple dispatch instead of the "C coding style"), as long as being fully compliant with the FMI standard.</li>
</ul>
