<p dir="auto">Fastback provides a lightweight, flexible and highly efficient event-based backtesting library for quantitative trading strategies.</p>
<p dir="auto">The main value of Fastback is provided by the account and bookkeeping implementation.
It keeps track of the open positions, account balance and equity.
Furthermore, the execution logic supports commissions, slippage, partial fills and execution delays in its design.</p>
<p dir="auto">Fastback does not try to model every aspect of a trading system, e.g. brokers, data sources, logging etc.
Instead, it provides basic building blocks for creating a custom backtesting environment that is easy to understand and extend.
For example, Fastback has no notion of "strategy" or "indicator", such constructs are highly strategy specific, and therefore up to the user to define.</p>
<p dir="auto">The event-based architecture aims to mimic the way a real-world trading systems works, where new data is ingested as a continuous data stream, i.e. events.
This reduces the implementation gap from backtesting to real-world execution significantly compared to a vectorized backtesting frameworks.</p>

<ul dir="auto">
<li>Event-based, modular architecture</li>
<li>Multi-currency support
<ul dir="auto">
<li>Hold multiple cash assets in parallel, e.g. USD, EUR, BTC etc.</li>
<li>Trade instruments with different quote currencies corresponding to the account currencies</li>
<li>Helpers for currency conversion</li>
</ul>
</li>
<li>Supports arbitrary price data sources</li>
<li>Supports modelling commissions, execution delays, price slippage and partial fills</li>
<li>Flexible data collectors to historize account balances, drawdowns, etc.</li>
<li>Facilities for parallelized backtesting and hyperparameter optimization</li>
<li>Uses position netting approach for bookkeeping
<ul dir="auto">
<li>Maintains single position per instrument using weighted average cost method</li>
</ul>
</li>
<li>Ability to attach arbirary metadata to instruments and orders in type-safe manner</li>
</ul>
