<p dir="auto"><code>CurvilinearGrids.jl</code> is a Julia package that provides utilities for working with non-uniform curvilinear grids. The core function takes a grid and transforms it from <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(x,y,z) \rightarrow (\xi,\eta,\zeta)$</math-renderer>, where the transformed grid contains elements of unit length in each dimension. A common example of this is to use a body-fit mesh, e.g. a mesh around a wing, and transform it so that it becomes a uniform grid in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(\xi,\eta,\zeta)$</math-renderer>. Then standard finite-difference stencils can be used on the uniform transformed grid. Below is an example of a cylindrical mesh in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(x,y)$</math-renderer> coordinates and the corresponding logical grid in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(\xi,\eta)$</math-renderer>.</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="docs/image.png"><img src="docs/image.png" alt="Alt text" style="max-width: 100%;"></a></p>
<p dir="auto"><code>CurvilinearGrids.jl</code> currently defines the <code>CurvilinearGrid2D</code> and <code>CurvilinearGrid3D</code> types. To construct these, you need to provide the functional form of the grid, e.g. <code>x(i,j), y(i,j)</code> for a 2D mesh.</p>

&quot;&quot;&quot;Create a spherical grid as a function of (r,θ,ϕ)&quot;&quot;&quot;
function sphere_grid(nr, ntheta, nphi)
  r0, r1 = (1, 3) # min/max radius
  (θ0, θ1) = deg2rad.((35, 180 - 35)) # min/max polar angle
  (ϕ0, ϕ1) = deg2rad.((45, 360 - 45)) # min/max azimuthal angle

  # Linear spacing in each dimension
  # Sometimes (ξ, η, ζ) is used instead of (i, j, k), depending on preference
  r(ξ) = r0 + (r1 - r0) * ((ξ - 1) / (nr - 1))
  θ(η) = θ0 + (θ1 - θ0) * ((η - 1) / (ntheta - 1))
  ϕ(ζ) = ϕ0 + (ϕ1 - ϕ0) * ((ζ - 1) / (nphi - 1))

  # simple spherical to cartesian mapping
  x(i,j,k) = r(i) * sin(θ(j)) * cos(ϕ(k))
  y(i,j,k) = r(i) * sin(θ(j)) * sin(ϕ(k))
  z(i,j,k) = r(i) * cos(θ(j))

  return (x, y, z)
end

ni, nj, nk = (5, 9, 11) # number of nodes/vertices in each dimension
nhalo = 2 # halo cells needed for stencils (can be set to 0)

# Obtain the x, y, and z coordinate functions
x, y, z = sphere_grid(ni, nj, nk)

<p dir="auto">The API is still a work-in-progress, but for the moment, these functions are exported:</p>
<p dir="auto">Here <code>idx</code> can be a <code>Tuple</code> or <code>CartesianIndex</code>, and mesh is an <code>AbstractCurvilinearGrid</code>. <strong>Important:</strong> The indices provided to these functions are aware of halo regions, so the functions do the offsets for you. This is by design, since fields attached to the mesh, like density or pressure for example, <em>will</em> have halo regions, and loops through these fields typically have pre-defined limits that constrain the loop to only work in the non-halo cells. If you don't use halo cells, just set <code>nhalo=0</code> in the constructors.</p>
<p dir="auto">The index can be a <code>Tuple</code>, scalar <code>Integer</code>, or <code>CartesianIndex</code>.</p>
<ul dir="auto">
<li>
<code>coord(mesh, idx)</code>: Get the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(x,y,z)$</math-renderer> coordinates at index <code>idx</code>. This can be 1, 2, or 3D.</li>
<li>
<code>centroid(mesh, idx)</code>:  Get the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(x,y,z)$</math-renderer> coordinates of the cell centroid at cell index <code>idx</code>. This can be 1, 2, or 3D.</li>
<li>
<code>metrics(mesh, idx)</code>: Get the cell metric information, e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$\xi_x, \xi_y$</math-renderer>, etc.</li>
<li>
<code>conservative_metrics(mesh, idx)</code>: Get the metrics that are consistent with the Geometric Conservation Law (GCL)</li>
<li>
<code>jacobian(mesh, idx)</code>: Get the determinant of the Jacobian matrix of forward transformation, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$J$</math-renderer>
</li>
<li>
<code>jacobian_matrix(mesh, idx)</code>: Get the Jacobian matrix of the forward transformation</li>
</ul>
<p dir="auto">These functions are primarily used to get the complete set of coordinates for plotting or post-processing. These do <em>not</em> use halo regions, since there geometry is ill-defined here.</p>
<ul dir="auto">
<li><code>coords(mesh)</code> Get the: array of coordinates for the entire mesh (typically for writing to a .vtk for example)</li>
<li><code>centroids(mesh)</code> Get the: array of centroid coordinates for the entire mesh (typically for writing to a <code>.vtk</code> file)</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Grid Metrics</h2><a id="user-content-grid-metrics" class="anchor" aria-label="Permalink: Grid Metrics" href="#grid-metrics"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">When solving equations such as the Navier-Stokes in transformed form (in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$\xi,\eta,\zeta$</math-renderer>), you need to include the grid metric terms. Providing these for the grid is the primary objective of <code>CurvilinearGrids.jl</code>. These conservative grid metrics satisfy the Geometric Conservation Law <a href="https://doi.org/10.2514/3.61273" rel="nofollow">(Thomas &amp; Lombard 1979)</a></p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$$
\hat{\xi}_x, \hat{\xi}_y,...
$$</math-renderer></p>
<p dir="auto">The subscript denotes a partial derivative, so <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$\xi_x = \partial \xi / \partial x$</math-renderer>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Jacobian matrices of transformation</h2><a id="user-content-jacobian-matrices-of-transformation" class="anchor" aria-label="Permalink: Jacobian matrices of transformation" href="#jacobian-matrices-of-transformation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Terminology can be somewhat confusing, but the "Jacobian matrix" is the matrix of partial derivatives that describe the forward or inverse transformation, and uses a bold-face <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$\textbf{J}$</math-renderer>. The "Jacobian" then refers to the determinant of the Jacobian matrix, and is the non-bolded <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$J$</math-renderer>. Some authors refer to the matrix as the "Jacobi matrix" as well. See <a href="https://en.wikipedia.org/wiki/Jacobian_matrix_and_determinant" rel="nofollow">Wikipedia</a> for more details.</p>
<p dir="auto">Forward transformation, or <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$T: (\xi,\eta,\zeta) \rightarrow (x,y,z)$</math-renderer>. These functions are what is provided to the <code>CurvilinearGrid</code> constructors. See the included examples above and in the unit tests.</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$$
\textbf{J} =
\begin{bmatrix}
x_\xi &amp; x_\eta &amp; x_\zeta \\
y_\xi &amp; y_\eta &amp; y_\zeta \\
z_\xi &amp; z_\eta &amp; z_\zeta
\end{bmatrix}
$$</math-renderer></p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$$
J = \det [\textbf{J}]
$$</math-renderer></p>
<p dir="auto">Inverse transformation <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$T^{-1}$</math-renderer>: <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$(x,y,z) \rightarrow (\xi,\eta,\zeta)$</math-renderer> :</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$$
\textbf{J}^{-1} =
\begin{bmatrix}
\xi_x   &amp; \xi_y   &amp; \xi_z   \\
\eta_x  &amp; \eta_y  &amp; \eta_z  \\
\zeta_x &amp; \zeta_y &amp; \zeta_z
\end{bmatrix}
$$</math-renderer></p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="245d23fca5ad66c351819098ca19ad53">$$
J^{-1} = \det [\textbf{J}^{-1}]
$$</math-renderer></p>
