<p dir="auto"><em>A code formatter with rules set in stone.</em></p>
<p dir="auto">Runic is a formatter for the <a href="https://julialang.org/" rel="nofollow">Julia programming language</a> built on
top of <a href="https://github.com/JuliaLang/JuliaSyntax.jl">JuliaSyntax.jl</a>.</p>
<p dir="auto">Similarly to <a href="https://pkg.go.dev/cmd/gofmt" rel="nofollow"><code>gofmt</code></a>, Runic have <em>no configuration</em>. The
formatting rules are set in stone (although not yet complete). This approach is something
that is appreciated by most Go programmers, see for example the following
<a href="https://www.youtube.com/watch?v=PAAkCSZUG1c&amp;t=523s" rel="nofollow">quote</a>:</p>
<blockquote>
<p dir="auto">Gofmt's style is no one's favorite, yet gofmt is everyone's favorite.</p>
</blockquote>

<p dir="auto">Runic can be installed with Julia's package manager:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia -e 'using Pkg; Pkg.add(url = &quot;https://github.com/fredrikekre/Runic.jl&quot;)'"><pre>julia -e <span class="pl-s"><span class="pl-pds">'</span>using Pkg; Pkg.add(url = "https://github.com/fredrikekre/Runic.jl")<span class="pl-pds">'</span></span></pre></div>
<p dir="auto">For CLI usage and editor integration (see <a href="#usage">Usage</a>) it is recommended to install
Runic in a separate project such as e.g. the shared project <code>@runic</code>:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia --project=@runic -e 'using Pkg; Pkg.add(url = &quot;https://github.com/fredrikekre/Runic.jl&quot;)'"><pre>julia --project=@runic -e <span class="pl-s"><span class="pl-pds">'</span>using Pkg; Pkg.add(url = "https://github.com/fredrikekre/Runic.jl")<span class="pl-pds">'</span></span></pre></div>

<p dir="auto">The main interface to Runic is the command line interface (CLI) through the <code>main</code> function
invoked with the <code>-m</code> flag. See the output of <code>julia -m Runic --help</code> below for usage
details.</p>
<p dir="auto">The following snippet can be added to your shell startup file so that the CLI can be invoked
a bit more ergonomically. This assumes Runic is installed in the <code>@runic</code> shared project as
suggested in the <a href="#installation">Installation</a> section above. Adjust the <code>--project</code> flag if
you installed Runic elsewhere.</p>

<p dir="auto">Runic can be used as a formatter in <a href="https://neovim.io/" rel="nofollow">Neovim</a> using
<a href="https://github.com/stevearc/conform.nvim"><code>conform.nvim</code></a>. Refer to the <code>conform.nvim</code>
repository for installation and setup instructions.</p>
<p dir="auto">Runic is not (yet) available directly in <code>conform.nvim</code> so the following configuration needs

<code>--project</code> flag if you installed Runic elsewhere.</p>

<p dir="auto">Runic can be used as a formatter in <a href="https://code.visualstudio.com/" rel="nofollow">VS Code</a> using the
extension <a href="https://marketplace.visualstudio.com/items?itemName=jkillian.custom-local-formatters&amp;ssr=false#overview" rel="nofollow">Custom Local Formatters</a>.</p>
<p dir="auto">After installing the extension you can configure Runic as a local formatter by adding the
following entry to your <code>settings.json</code>:</p>

the first time you execute the command you will be prompted to select a formatter since the

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Checking formatting</h2><a id="user-content-checking-formatting" class="anchor" aria-label="Permalink: Checking formatting" href="#checking-formatting"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Runic has a check-mode that verifies whether files are correctly formatted or not. This mode
is enabled with the <code>--check</code> flag. In check mode Runic will exit with a non-zero code if
any of the input files are incorrectly formatted. As an example, the following invocation
can be used:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="git ls-files -z -- '*.jl' | xargs -0 julia -m Runic --check --diff"><pre>git ls-files -z -- <span class="pl-s"><span class="pl-pds">'</span>*.jl<span class="pl-pds">'</span></span> <span class="pl-k">|</span> xargs -0 julia -m Runic --check --diff</pre></div>
<p dir="auto">This will run Runic's check mode (<code>--check</code>) on all <code>.jl</code> files in the repository and print
the diff (<code>--diff</code>) if the files are not formatted correctly. If any file is incorrectly
formatted the exit code will be non-zero.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Toggle formatting</h3><a id="user-content-toggle-formatting" class="anchor" aria-label="Permalink: Toggle formatting" href="#toggle-formatting"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">It is possible to toggle formatting around expressions where you want to disable Runic's
formatting. This can be useful in cases where manual formatting increase the readability of
the code. For example, manually aligned array literals may look worse when formatted by
Runic.</p>
<p dir="auto">The source comments <code># runic: off</code> and <code># runic: on</code> will toggle the formatting off and on,
respectively. The comments must be on their own line, they must be on the same level in the
syntax tree, and they must come in pairs.</p>
<div class="markdown-alert markdown-alert-note" dir="auto"><p class="markdown-alert-title" dir="auto"><svg class="octicon octicon-info mr-2" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="M0 8a8 8 0 1 1 16 0A8 8 0 0 1 0 8Zm8-6.5a6.5 6.5 0 1 0 0 13 6.5 6.5 0 0 0 0-13ZM6.5 7.75A.75.75 0 0 1 7.25 7h1a.75.75 0 0 1 .75.75v2.75h.25a.75.75 0 0 1 0 1.5h-2a.75.75 0 0 1 0-1.5h.25v-2h-.25a.75.75 0 0 1-.75-.75ZM8 6a1 1 0 1 1 0-2 1 1 0 0 1 0 2Z"></path></svg>Note</p><p dir="auto">For compatibility with <a href="https://github.com/domluna/JuliaFormatter.jl">JuliaFormatter</a> the
comments <code>#! format: off</code> and <code>#! format: on</code> are also recognized by Runic.</p>
</div>

excluded from formatting without having to add a <code># runic: on</code> comment at the end of the
file.</p>
