<p dir="auto">The filesystem and choice of metadata is loosly based on BIDS format [1] .</p>
<p dir="auto">This project was created to standardize data handling of 3D and 4D medical imaging, for now without support for ultrasonography as we are looking for contributor with expertise in this area . It is currently subject to change and I am open to suggestions that would improve the library in construction.
I've included below in categories what needs to be done and some basic ideas on How to approach it. I will post it for consultations with the community and then process to create test cases where Python SimpleItk (or other) methods will be treated as a reference.</p>
<ol dir="auto">
<li>Designing data structure - requirements (need to explicitly specify the most important and the rest will be just in an additional dictionary)
<ul dir="auto">
<li>hold voxel data as a multidimensional array</li>
<li>keep spatial metadata - origin, orientation, spacing</li>
<li>type of the image - label/CT/MRI/PET (need to construct enum for this) - frequently will be needed to be supplied manually</li>
<li>subtype of the image for example if MRI ADC/DWI/T2 etc.  (need to construct enum for this)</li>
<li>type of the voxel data (for example Float32)</li>
<li>Date of saving</li>
<li>Acquisition time</li>
<li>Patient ID if present</li>
<li>current device - (CPU, GPU)</li>
<li>Study UID</li>
<li>Patient UID</li>
<li>Series UID</li>
<li>Study Description</li>
<li>Original file name</li>
<li>Display data - set of colors for the labels; window value for CT scan - will provide set of defaults based on image type and I will modify MedEye3D for convenient visualizations.</li>
<li>Clinical data dictionary - age, gender ...</li>
<li>Is contrast administered</li>
<li>The rest of the metadata loaded from a file to store in a dictionary</li>
</ul>
</li>
<li>Data loading
<ul dir="auto">
<li>Nifti - start with Nifti.jl</li>
<li>Dicom - Dicom.jl</li>
<li>Mha - ?</li>
</ul>
</li>
<li>Modifying voxel data together with spacing data</li>
</ol>
<ul dir="auto">
<li>Modifying orientation of all images to single orientation - for example, RAS (we should select some default orientation) - TODO with AxisArrays.jl plus keep track of origin</li>
<li>Changing spacing to a given spacing - TODO with AxisArrays.jl with Interpolations.jl plus keep track of origin; use nearest neighbor interpolator for the label; and for example b spline for others</li>
<li>Resampling to another grid - for example, resample PET image to CT image based just on spatial metadata keeping track of changed metadata of the moving image TODO with AxisArrays.jl and Interpolations.jl</li>
<li>Cropping and dilatating with adjusting of origin offset TODO with AxisArrays.jl, storing also positions of original image in metadata (some artifacts happen on the image edges)</li>
</ul>
<ol dir="auto">
<li>Adding persistency
<ul dir="auto">
<li>store the data as array in HDF5 and metadata as its attributes</li>
<li>design efficient loading and saving irrespective of the device the array is on</li>
<li>add the possibility to save back as nifty and dicom files for exporting</li>
</ul>
</li>
</ol>
<p dir="auto">Point 3 is the trickiest one to do as there are a lot of corner cases</p>
<p dir="auto">to look for <a href="https://github.com/haberdashPI/MetaArrays.jl">https://github.com/haberdashPI/MetaArrays.jl</a></p>
