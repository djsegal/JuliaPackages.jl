<p dir="auto">Any time RegressionTests.jl is loaded, you can use <code>]bench</code> to run your benchmarks and

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Methodology</h1><a id="user-content-methodology" class="anchor" aria-label="Permalink: Methodology" href="#methodology"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">All the various ways of running benchmarks with this package funnel through a
<code>runbenchmarks</code> function which performs a randomized controlled trial comparing two
versions of a package. Each datapoint is a result of restarting Julia, loading a randomly
chosen version of the target package, and recording the tracked values.</p>
<p dir="auto">The results are then compared in a value independent manner that makes no assumptions about
the actual values of the targets (other than that they are real numbers).</p>
<p dir="auto">We make the following statistical claims for each tracked value <code>t</code></p>
<ul dir="auto">
<li>If the distributions of <code>t</code> is independent of the version being tested, then this will
report a change with probability approximately <code>1e-10</code>.</li>
<li>If the distributions of <code>t</code> on the two tested versions differ<sup><a href="#user-content-fn-1-cb2f3f959fa95de396e4fc9ef3e2c6cb" id="user-content-fnref-1-cb2f3f959fa95de396e4fc9ef3e2c6cb" data-footnote-ref="" aria-describedby="footnote-label">1</a></sup> by at least <code>k ≥ .05</code>,
then this will report a change with probability <code>≥ 0.95</code><sup><a href="#user-content-fn-2-cb2f3f959fa95de396e4fc9ef3e2c6cb" id="user-content-fnref-2-cb2f3f959fa95de396e4fc9ef3e2c6cb" data-footnote-ref="" aria-describedby="footnote-label">2</a></sup>.</li>
<li>All reported changes are tagged as either increases, decreases, or both.</li>
<li>If all percentiles of <code>t</code> are on the primary version are greater than or equal to their
corresponding values on the comparison version, then <code>t</code> will be incorrectly reported as a
decrease with probability <code>≤ 1e-5</code>. (and vice versa)</li>
<li>If there is an increase with significance<sup><a href="#user-content-fn-1-cb2f3f959fa95de396e4fc9ef3e2c6cb" id="user-content-fnref-1-2-cb2f3f959fa95de396e4fc9ef3e2c6cb" data-footnote-ref="" aria-describedby="footnote-label">1</a></sup> <code>k ≥ .05</code>, then that increase will be reported
with probability <code>≥ 0.95</code>.</li>
</ul>
<p dir="auto">Note: the numbers in these statistical claims are based on empirical data. They likely
accurate, but we're still looking for proofs and closed forms.</p>

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">How to interpret conflicting results</h1><a id="user-content-how-to-interpret-conflicting-results" class="anchor" aria-label="Permalink: How to interpret conflicting results" href="#how-to-interpret-conflicting-results"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">While this package claims both to report almost all significant changes and to have no
false positives and to never report anything that is unchanged, we make no claims about
insignificant but nonzero changes. If the distributions of possible outcomes differ by
some <code>0 &lt; k &lt; .05</code>, then we may report a change or nor report a change with no probability
guarantees. Consequently, if you run repeated tests and find some runs report changes and
others do not, you ma conclude with certainty both that there is a change and that it is not
a significant change from a statistical perspective.</p>

<p dir="auto">Significance is measured by the integral from 0 to 1 of <code>(cdf(g)(invcdf(f)(x)) - x)^2</code>.
This can be thought of as the squared area of deviation from x=y in the cdf/cdf plot. When
referring to increases or degreases, we only count area on one side of the x=y line. The
gist of this is that we report a positive result for anything that can be efficiently
detected with low false positivity rates. <a href="#user-content-fnref-1-cb2f3f959fa95de396e4fc9ef3e2c6cb" data-footnote-backref="" aria-label="Back to reference 1" class="data-footnote-backref">↩</a> <a href="#user-content-fnref-1-2-cb2f3f959fa95de396e4fc9ef3e2c6cb" data-footnote-backref="" aria-label="Back to reference 1-2" class="data-footnote-backref">↩<sup>2</sup></a></p>
