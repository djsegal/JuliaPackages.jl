<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Purpose</h2><a id="user-content-purpose" class="anchor" aria-label="Permalink: Purpose" href="#purpose"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This module allows the user to easily run an evolutionary algorithm to create mass-action chemical reaction networks with specific behaviors or to match time series data. It is intended as a research tool for computational systems biology.</p>
<p dir="auto">There are three primary use cases for this packge:</p>
<ol dir="auto">
<li>Evolving reaction networks with specific behaviors. The default is oscillation, but other behaviors may be added in the future. Additionally, users can input time series that reflect those desired behaviors.</li>
<li>Evolving reaction networks (or ensemble models) to fit time series data. Often systems biologist will have timeseries data from experiments and will want to search for a reaction network (or group of them) that can recapitulate the time series data. This is useful for building models, informing future experiments or looking at output models for common reaction themes which may indicate the presence of those reactions in the ground truth.</li>
<li>Parameter (rate constants) fitting. In the case where model topology is known (for example, the biologist has already built the model from first principles) and wants to generate parameter values for those reactions that will recapitulate experimental time series data.</li>
</ol>

<p dir="auto"><strong>Customize Evolution (optional)</strong>
The run_evolution() function takes several optional keyword arguments:</p>
</li>
</ol>
<ul dir="auto">
<li><code>ntrials</code>: the number of trials to run (100 by default)</li>
<li><code>ngenerations</code>: the number of generations per batch (800 by default)</li>
<li><code>population_size</code>: the number of networks in a population</li>
<li><code>pathtosettings</code>: path to a json file storing additional custom settings</li>
<li><code>outputpath</code>: path to a directory where evolution output will be written</li>
<li><code>seed</code>: specify a seed for the random number generator</li>
</ul>
<p dir="auto">For example, to change the population_size to 200 via the command line: <br>
<code>rne.run_evolution(population_size=200)</code></p>

<p dir="auto">The rateconstant_distance_weight setting enables the package to consider differences in reaction weight constants when comparing twp networks. This is necessary if all networks have the same topology, although some adjustments to the value may be necessary.</p>
<p dir="auto">Setting p_rateconstant_mutation to 1.0 prevents the algorithm from adding or deleting reactions during evolution.</p>
