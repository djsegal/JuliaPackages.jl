<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is FMIExchange.jl?</h2><a id="user-content-what-is-fmiexchangejl" class="anchor" aria-label="Permalink: What is FMIExchange.jl?" href="#what-is-fmiexchangejl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">FMIExchange.jl provides ways to easily load Model Exchange Functional Mock-up Units (FMUs) and simulate them using the <a href="https://docs.sciml.ai/DiffEqDocs/stable/" rel="nofollow">DifferentialEquations.jl</a> package.
This package cannot run simulations on its own, but merely provides tools to construct ODEFunctions and callbacks from FMUs.
The user retains full control over the simulation with the powerful and familiar interface of <a href="https://docs.sciml.ai/DiffEqDocs/stable/" rel="nofollow">DifferentialEquations.jl</a>.</p>
<p dir="auto">FMIExchange.jl allows to simulate multiple FMUs at the same time and even combine them with native Julia ODEs; this is the main use-case of this package.
FMIExchange.jl includes some functionality to automate the process of combining multiple models into one simulation: automatic addressing, human-readable address map generation and functions for connecting model inputs and outputs.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is FMIExchange.jl not?</h2><a id="user-content-what-is-fmiexchangejl-not" class="anchor" aria-label="Permalink: What is FMIExchange.jl not?" href="#what-is-fmiexchangejl-not"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">FMIExchange.jl is not a package for simulating or manipulating FMUs: it doesn't include a simulator but merely provides convenience functions to allow simulating FMUs with the <a href="https://docs.sciml.ai/DiffEqDocs/stable/" rel="nofollow">DifferentialEquations.jl</a> package.
<a href="https://github.com/ThummeTo/FMIImport.jl">FMIImport.jl</a> and <a href="https://github.com/ThummeTo/FMICore.jl">FMICore.jl</a> provide functionality for importing and manipulating FMUs.
<a href="https://github.com/ThummeTo/FMI.jl">FMI.jl</a> has built-in FMU simulation functionality, but this is limited to simulating a single FMU at a time and it is impossible to combine native ODEs with FMUs.</p>
<p dir="auto">FMIExchange.jl is not a modelling package.
While it has some basic simulation composition functionality it lacks some crucial features such as algebraic loop resolution.
Some packages that support this are <a href="https://github.com/SciML/ModelingToolkit.jl">ModelingToolkit.jl</a> and <a href="https://github.com/zekeriyasari/Causal.jl">Causal.jl</a>.
Pull requests to make FMIExchange.jl compatible with these packages are welcome!</p>

<p dir="auto">Below example walks you through simulating an FMU using FMIExchange.jl and <a href="https://docs.sciml.ai/DiffEqDocs/stable/" rel="nofollow">DifferentialEquations.jl</a>. The example FMU is a bouncing ball in a 2D space.</p>
<p dir="auto">Import packages. Define FMU file location, and simulation start and stop times.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using FMIExchange

<p dir="auto">Define the FMU inputs, outputs, states.
This step ensures that correct references to the model variables are made in the simulation.
Optionally, the model parameters of the FMU can be changed.</p>

<p dir="auto">Use the <code>CachedFMU2</code> function to load the FMU (the name <code>CachedFMU2</code> is to avoid naming conflicts with related packages).
We then wrap it in a <code>CachedModel</code> struct which will automatically preallocate caches for faster calls to the FMU.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="fmu = CachedFMU2(bbloc, bbstart, bbstop, bbins, bbouts, bbstates, bbparameters)

<p dir="auto">FMU events are handled through callbacks.
FMIExchange.jl can automatically generate the callbacks to handle these events using the <code>get_callbacks</code> function.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# For the bouncing ball, an event occurs whenever the ball hits a wall

<p dir="auto">To run the tests you need to generate the FMUs.
This requires OpenModelica to be installed and the compiler <code>omc</code> to be available in your <code>PATH</code> variable.
The <a href="https://github.com/modelica/ModelicaStandardLibrary">Modelica Standard Library</a>, <a href="https://github.com/lbl-srg/modelica-buildings">Buildings</a>, <a href="https://github.com/open-ideas/IDEAS">IDEAS</a> and <a href="https://gitlab.kuleuven.be/positive-energy-districts/moped.git" rel="nofollow">MoPED</a> libraries should be available in your Modelica path.</p>
<p dir="auto">You can find your Modelica path by creating a <code>mos</code> script with the following contents</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="getModelicaPath()"><pre class="notranslate"><code>getModelicaPath()
</code></pre></div>
<p dir="auto">and running it with <code>omc</code>.
On Linux, the result is <code>~/.openmodelica/libraries</code>.</p>

<p dir="auto">It is possible to download the compiled FMUs from the Github workflow runs of this repository if the artifacts are still available on Github.
First extract all FMUs to <code>deps/fmu/</code>, then run tests as normal.
It is possible that these FMUs do not work on your architecture / OS, in which case you will have to <a href="###-Generating-Test-FMUs">generate the FMUs manually</a>.</p>
