bodies for the <strong>SatelliteToolbox.jl</strong> ecosystem.</p>

<p dir="auto">We can compute the Moon position represented in the Mean-Of-Date (MOD) reference frame
<strong>[1, 2]</strong> using the functions:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="moon_position_mod(jd_tdb::Number[, model]) -&gt; SVector{3, Float64}
moon_position_mod(date_tdb::DateTime[, model]) -&gt; SVector{3, Float64}"><pre><span class="pl-c1">moon_position_mod</span>(jd_tdb<span class="pl-k">::</span><span class="pl-c1">Number</span>[, model]) <span class="pl-k">-&gt;</span> SVector{<span class="pl-c1">3</span>, Float64}
<span class="pl-c1">moon_position_mod</span>(date_tdb<span class="pl-k">::</span><span class="pl-c1">DateTime</span>[, model]) <span class="pl-k">-&gt;</span> SVector{<span class="pl-c1">3</span>, Float64}</pre></div>
<p dir="auto">where the input time <code>jd_tdb</code> (Julian Day) or <code>date_tdb</code> must be represented in the
Barycentric Dynamical Time (TDB).</p>
<p dir="auto">The <code>model</code> must be <code>Val(:Meeus)</code> or <code>Val(:Vallado)</code>. <code>Val(:Meeus)</code> uses the algorithm in
<strong>[2, p. 337]</strong> that provides an accuracy of 10" in the longitude and 4" in the latitude
(the reference does not mention the timespan). <code>Val(:Vallado)</code> uses the algorithm in
<strong>[1, p. 288]</strong> that is 10x faster than <code>Val(:Meeus)</code> but can lead to errors of 0.3° in
longitude and 0.2° in latitude.</p>

<p dir="auto">The packages in <a href="https://github.com/JuliaAstro">JuliaAstro</a> provide the same functionality
with usually more precision than the algorithms here. However, our goal is to build an
attitude and orbit control subsystem written in Julia. In this case, the footprint of each
package matters. Hence, we created this small package to contain the necessary functions
since the extensive feature list in the other packages is unnecessary here.</p>
