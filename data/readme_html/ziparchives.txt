<p dir="auto">Read and write Zip archives in julia.</p>
<p dir="auto">Like Tar.jl, it is designed to use the Zip format to share data between
multiple computers, not to backup a directory and preserve all local filesystem metadata.</p>
<p dir="auto">All public functions are exported, non exported functions and struct fields are internal.</p>
<p dir="auto">See <a href="https://github.com/JuliaIO/ZipArchives.jl/blob/main/test/test_simple-usage.jl">test/test_simple-usage.jl</a> for more examples.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Background</h3><a id="user-content-background" class="anchor" aria-label="Permalink: Background" href="#background"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">An archive contains a list of named entries.
These entries represent archived files or empty directories.
Internally there is no file system like tree structure; however,
the entry name may have "/"s to represented a relative path.</p>
<p dir="auto">At the end of the archive there is a "central directory" of all entry names, sizes,
and other metadata.</p>
<p dir="auto">The central directory gets parsed first when reading an archive.</p>
<p dir="auto">The central directory makes it fast to read just one random entry out of a very large archive.</p>
<p dir="auto">When writing it is important to close the writer so the central directory gets written out.</p>
<p dir="auto">More details on the file format can be found at <a href="https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT" rel="nofollow">https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT</a></p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Limitations</h3><a id="user-content-limitations" class="anchor" aria-label="Permalink: Limitations" href="#limitations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ol dir="auto">
<li>Cannot directly extract all files in an archive and write those files to disk.</li>
<li>Ignores time stamps.</li>
<li>Cannot write an archive fully in streaming mode. See <a href="https://github.com/madler/zipflow">https://github.com/madler/zipflow</a> if you need this functionality.</li>
<li>Encryption and decryption not supported.</li>
<li>Multi disk archives not supported.</li>
<li>Cannot recover data from a corrupted archive. Especially if the end of the archive is corrupted.</li>
</ol>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><a href="https://github.com/fhs/ZipFile.jl">ZipFile</a></h3><a id="user-content-zipfile" class="anchor" aria-label="Permalink: ZipFile" href="#zipfile"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">ZipFile is very similar to ZipArchives at a high level.</p>
<p dir="auto">Currently ZipArchives has the following benefits over ZipFile:</p>
<ol dir="auto">
<li>Full ZIP64 support: archives larger than 4GB can be written.</li>
<li>UTF-8 file name support: entry names correctly mark that they are UTF-8.</li>
<li>Safe multi threaded reading of different entries in a single archive.</li>
<li>Files can be marked as executable. Permissions are handled like in <a href="https://github.com/JuliaIO/Tar.jl#permissions">https://github.com/JuliaIO/Tar.jl#permissions</a></li>
<li>By default when writing an archive, entry names are checked to avoid some common issues if the archive would be extracted on windows.</li>
<li>Ability to append to an existing zip archive, in an <code>IO</code> or in a file on disk.</li>
</ol>
<p dir="auto">ZipArchives currently has the following limitations compared to ZipFile:</p>
<ol dir="auto">
<li>No way to specify the modification time, times are set to 1980-01-01 00:00:00 DOS date time.</li>
<li>No <code>flush</code> function for <code>ZipWriter</code>. <code>close</code> and <code>zip_append_archive</code> can be used instead.</li>
<li>Requires at least Julia 1.6.</li>
<li>No way to read an archive from an <code>IOStream</code>, <code>mmap</code> can be used instead.</li>
</ol>
