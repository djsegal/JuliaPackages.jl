<ul dir="auto">
<li>In <code>linsolve</code>, the keyword argument <code>solver_kwargs</code> has been renamed to <code>updater_kwargs</code>.</li>
<li>In <code>ITensorTDVP.dmrg</code>, <code>dmrg_x</code>, and <code>linsolve</code>, the keyword argument <code>step_observer!</code> has been renamed to <code>sweep_observer!</code>. Either name is allowed in <code>tdvp</code> but <code>step_observer!</code> is preferred and the name <code>sweep_observer!</code> may be deprecated in <code>tdvp</code> in future versions.</li>
<li>Support for <code>ITensors.AbstractObserver</code>-based observers has been removed, use <code>Observers.observer</code> instead.</li>
<li>In <code>contract(operator::MPO, state::MPS; alg="fit", kwargs...)</code>, and <code>apply(operator::MPO, state::MPS; alg="fit", kwargs...)</code>, the keyword argument for specifying an initial guess for the result is now called <code>init</code> instead of <code>init_mps</code>. Additionally, in <code>contract</code>, <code>init</code> should have primed site indices, or more generally should have site indices which are those that are not shared by the input operator and state. In <code>apply</code>, <code>init</code> should have site indices matching those of the input <code>state</code>.</li>

<ul dir="auto">
<li>ITensorTDVP.jl v0.2.0-v0.2.4: The <code>applyexp</code> Krylov exponentiation solver backend was removed, and <code>solver_backend="applyexp"</code> option for <code>tdvp</code> now just calls <code>exponentiate</code> from KrylovKit.jl. <code>applyexp</code> is in many ways the same as <code>exponentiate</code> bit <code>exponentiate</code> has more advanced features like restarts. In these versions, <code>solver_backend="applyexp"</code> prints a warning to that effect. As of ITensorTDVP.jl v0.2.5, we have brought back the <code>applyexp</code> backend because we received reports that it performed better in certain cases. We plan to investigate that issue and make sure <code>exponentiate</code> works as well as <code>applyexp</code> in those cases so that we can go back to just having a single <code>exponentiate</code> backend.</li>
