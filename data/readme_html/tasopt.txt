<p dir="auto">The easiest way to run <code>TASOPT.jl</code> would be to add the package using the julia package manager using the github repository.</p>
<p dir="auto">You can do this by starting a Julia session and then activating the package manager by typing <code>]</code> and then entering:</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; add git@github.com:MIT-LAE/TASOPT.jl.git"><pre>pkg&gt; add git@github.com:MIT-LAE/TASOPT.jl.git</pre></div>
<p dir="auto">You can then import <code>TASOPT</code> as you would with any Julia package:</p>
<div class="highlight highlight-source-julia-console notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; using TASOPT"><pre>julia&gt; <span class="pl-k">using</span> TASOPT</pre></div>

<p dir="auto">If you are going to develop the source code of <code>TASOPT.jl</code> you might benefit from a local clone of the git repository which
can then fit into a workflow using <a href="https://timholy.github.io/Revise.jl/stable/" rel="nofollow"><code>Revise.jl</code></a> for example.</p>
<p dir="auto">Step 1: Clone the git repo locally</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="git clone git@github.com:MIT-LAE/TASOPT.jl.git"><pre>git clone git@github.com:MIT-LAE/TASOPT.jl.git</pre></div>
<p dir="auto">Step 2: <code>cd</code> to the folder where TASOPT is cloned</p>
<p dir="auto">Step 3: Use <code>Pkg</code> to install/ develop the package</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="pkg&gt; dev ."><pre>pkg<span class="pl-k">&gt;</span> dev .</pre></div>
<p dir="auto">You should now be able to import TASOPT from within any Julia script in your base environment.</p>
<p dir="auto">Note: If you clone another version of TASOPT, <code>using TASOPT</code> will always use the directory where <code>dev .</code> was used.</p>
<p dir="auto">If you are using <code>Revise.jl</code> be sure to first import <code>Revise</code> before importing <code>TASOPT</code></p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Revise
using TASOPT"><pre><span class="pl-k">using</span> Revise
<span class="pl-k">using</span> TASOPT</pre></div>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Work in branches</h3><a id="user-content-work-in-branches" class="anchor" aria-label="Permalink: Work in branches" href="#work-in-branches"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Don't commit anything to the main branch. Here's how you create your own fork and branch.<br>
First create a fork of this repo by clicking on "fork" on the top right hand of the github page. This creates a copy of this repo that is separate form this one. This ensures that any chagnes made to your fork will not affect other's forks.</p>
<p dir="auto">You will now need to clone your forked version of the repo to your machine where you will be writing code. This <a href="https://help.github.com/en/github/getting-started-with-github/fork-a-repo">page</a> has a good overview of how to do this whole process.
After this I highly recommend using branches within your own fork and I prefer the git command line interface over the web interface.
Use this command to create a new branch for example <code>dev_prash</code></p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="git checkout -b &lt;name_of_branch&gt;"><pre class="notranslate"><code>git checkout -b &lt;name_of_branch&gt;
</code></pre></div>
<p dir="auto">as you add files, use the following command to tell git to track your file</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="git add &lt;path to file, or use . to track all files&gt;"><pre class="notranslate"><code>git add &lt;path to file, or use . to track all files&gt;
</code></pre></div>
<p dir="auto">once you are happy with the edits you have made, you have to <em>commit</em> the edits by doing</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="git commit -a -m &quot;COMMIT MESSAGE&quot;"><pre class="notranslate"><code>git commit -a -m "COMMIT MESSAGE"
</code></pre></div>
<p dir="auto">make your commit messages useful. These messages along with frequent commits will create a rich history to the repo so as this grows you will be able to track changes and debug more efficiently</p>
<p dir="auto">After committing to your local machine, you need to <em>push</em> these changes to the remote github server. The <em>first</em> time you do this for each branch you need to tell the remote repo what to track</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    git push -u origin &lt;name_of_branch&gt;"><pre>    git push -u origin <span class="pl-k">&lt;</span>name_of_branch<span class="pl-k">&gt;</span></pre></div>
<p dir="auto">for subsequent pushes, you only need to do <code>git push</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Sync your repo with this main repo periodically</h3><a id="user-content-sync-your-repo-with-this-main-repo-periodically" class="anchor" aria-label="Permalink: Sync your repo with this main repo periodically" href="#sync-your-repo-with-this-main-repo-periodically"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Keep syncing your fork to this repo regularly so that you have all the latest bug fixes and changes that others have done.</p>
<p dir="auto">To sync your fork, <code>cd</code> into the right folder on your terminal and do the following</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    git fetch upstream"><pre>    git fetch upstream</pre></div>
<p dir="auto">This fetches all the changes made to the main repo. Then switch to your main branch (you should be working in branches even in your own repo)</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="   git checkout main"><pre>   git checkout main</pre></div>
<p dir="auto">Once you are in your main branch do:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="   git merge upstream/main"><pre>   git merge upstream/main</pre></div>
<p dir="auto">This brings your fork's <code>main</code> branch into sync with the upstream repository, without losing your local changes.</p>
