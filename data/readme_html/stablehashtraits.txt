<p dir="auto">The aim of StableHashTraits is to make it easy to compute a stable hash of any Julia value with minimal boilerplate using trait-based dispatch; here, "stable" means the value will not change across Julia versions (or between Julia sessions).</p>
<p dir="auto">For example:</p>


<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using StableHashTraits

<p dir="auto">Users can define a method of <code>transformer</code> to customize how an object is hashed. It should dispatch on the type to be transformed, and return a function wrapped in <code>Transformer</code>. During hashing, this function is called and its result is the value that is actually hashed.</p>
<p dir="auto">StableHashTraits aims to guarantee a stable hash so long as you only upgrade to non-breaking versions (e.g. <code>StableHashTraits = "1"</code> in <code>[compat]</code> of <code>Project.toml</code>); any changes in an object's hash in this case would be considered a bug.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Use Case and Design Rationale</h2><a id="user-content-use-case-and-design-rationale" class="anchor" aria-label="Permalink: Use Case and Design Rationale" href="#use-case-and-design-rationale"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">StableHashTraits is designed to be used in cases where there is an object you wish to serialize in a content-addressed cache. How and when objects pass the same input to a hashing algorithm is meant to be predictable and well defined, so that the user can reliably define methods of <code>transformer</code> to modify this behavior.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What gets hashed? (hash version 4)</h2><a id="user-content-what-gets-hashed-hash-version-4" class="anchor" aria-label="Permalink: What gets hashed? (hash version 4)" href="#what-gets-hashed-hash-version-4"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This covers the behavior when using the latest hash version (4). You can read the documentation for hash version 1 <a href="https://github.com/beacon-biosignals/StableHashTraits.jl/blob/v1.0.0/README.md">here</a> and hash version 2-3 <a href="https://github.com/beacon-biosignals/StableHashTraits.jl/blob/v1.1.8/README.md">here</a>.</p>
<p dir="auto">When you call <code>stable_hash(x; version=4)</code>, StableHashTraits hashes both the value <code>x</code> and its type <code>T</code>. Rather than hashing the type <code>T</code> itself directly, in most cases instead <code>SructTypes.StructType(T)</code> is hashed, using
<a href="https://github.com/JuliaData/StructTypes.jl">SructTypes.jl</a>. For example, since the "StructType" of Float64 and Float32 are both <code>NumberType</code>, when hashing Float64 and Float32 values, value and <code>NumberType</code> are hashed. This provides a simple trait-based system that doesn't need to rely on internal details. See below for more details.</p>
<p dir="auto">You can customize how the value is hashed using <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.transformer" rel="nofollow"><code>StableHashTraits.transformer</code></a>,
and how its type is hashed using <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.transform_type" rel="nofollow"><code>StableHashTraits.transform_type</code></a>.
If you need to customize either of these functions for a type that you don't own, you can use a <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.@context" rel="nofollow">@context</a> to avoid type piracy.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>StructType.DataType</code></h3><a id="user-content-structtypedatatype" class="anchor" aria-label="Permalink: StructType.DataType" href="#structtypedatatype"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>StructType.DataType</code> denotes a type that is some kind of "record"; i.e. its content is defined by the fields (<code>getfield(f) for f in fieldnames(T)</code>) of the type. Since it is the default, it is used to hash most types.</p>
<p dir="auto">To hash the value, each field value (<code>getfield(f) for f in fieldnames(T)</code>) is hashed.</p>
<p dir="auto">If <code>StructType(T) &lt;: StructTypes.UnorderedStruct</code> (the default), the field values are first sorted by the lexographic order of the field names.</p>
<p dir="auto">The type of a data type is hashed using <code>string(nameof(T))</code>, the <code>fieldnames(T)</code>, (sorting them for <code>UnorderedStruct</code>), along with a hash of the type of each element of <code>fieldtypes(T)</code> according to their <code>StructType</code>.</p>
<p dir="auto">No type parameters are hashed by default. To hash these you need to specialize on <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.transform_type" rel="nofollow"><code>StableHashTraits.transform_type</code></a> for your struct. Note that because <code>fieldtypes(T)</code> is hashed, you don't need to do this unless your type parameters are not used in the specification of your field types.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>StructType.ArrayType</code></h3><a id="user-content-structtypearraytype" class="anchor" aria-label="Permalink: StructType.ArrayType" href="#structtypearraytype"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>ArrayType</code> is used when hashing a sequence of values.</p>
<p dir="auto">To hash the value, each element of an array type is hashed using <code>iterate</code>. If the object <code>isa AbstractArray</code>, the <code>size(x)</code> of the object is also hashed.</p>
<p dir="auto">If <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.is_ordered" rel="nofollow"><code>StableHashTraits.is_ordered</code></a> returns <code>false</code> the elements are first <code>sort</code>ed according to <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.hash_sort_by" rel="nofollow"><code>StableHashTraits.hash_sort_by</code></a>.</p>
<p dir="auto">To hash the type, the string <code>"StructTypes.ArrayType"</code> is hashed (meaning that the kind of array won't matter to the hash value), and the type of the <code>elype</code> is hashed, according to its <code>StructType</code>. If the type <code>&lt;: AbstractArray</code>, the <code>ndims(T)</code> is hashed.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>StructTypes.DictType</code></h3><a id="user-content-structtypesdicttype" class="anchor" aria-label="Permalink: StructTypes.DictType" href="#structtypesdicttype"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To hash the value, each key-value pair of a dict type is hashed, as returned by <code>StructType.keyvaluepairs(x)</code>.</p>
<p dir="auto">If <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.is_ordered" rel="nofollow"><code>StableHashTraits.is_ordered</code></a> returns <code>false</code> (which is the default return value) the pairs are first <code>sort</code>ed according their keys using <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.hash_sort_by" rel="nofollow"><code>StableHashTraits.hash_sort_by</code></a>.</p>
<p dir="auto">To hash the type, the string <code>"StructTypes.DictType"</code> is hashed (meaning that the kind of dictionary won't matter), and the type of the <code>keytype</code> and <code>valtype</code> is hashed, according to its <code>StructType</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>AbstractRange</code></h3><a id="user-content-abstractrange" class="anchor" aria-label="Permalink: AbstractRange" href="#abstractrange"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>AbstractRange</code> constitutes an exception to the rule that we use <code>StructType</code>: for efficient hashing, ranges are treated as another first-class container object, separate from array types.</p>
<p dir="auto">The value is hashed as <code>(first(x), step(x), last(x))</code>.</p>
<p dir="auto">The type is hashed as <code>"Base.AbstractRange"</code> along with the type of the <code>eltype</code>, according to its <code>StructType</code>. Thus, the type of range doesn't matter (just that it is a range).</p>

<p dir="auto">To hash the value, the result of <code>Base.write</code>ing the object is hashed.</p>
<p dir="auto">To hash the type, the value of <code>string("StructType.", nameof_string(StructType(T))))</code> is used (c.f. <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.nameof_string" rel="nofollow"><code>StableHashTraits.nameof_string</code></a> for details). Note that this means the type of the value itself is not being hashed, rather a string related to its struct type.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>missing</code> and <code>nothing</code></h3><a id="user-content-missing-and-nothing" class="anchor" aria-label="Permalink: missing and nothing" href="#missing-and-nothing"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">There is no value hashed for <code>missing</code> or <code>nothing</code>; the type is hashed as the string <code>"Base.Missing"</code> and <code>"Base.Nothing"</code> respectively. Note in particular the string <code>"Base.Missing"</code> does not have the same hash as <code>missing</code>, since the former would have its struct type hashed.</p>

<p dir="auto">Null and Singleton types are hashed solely according to their type (no value is hashed)</p>
<p dir="auto">Their types is hashed by <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.nameof_string" rel="nofollow"><code>StableHashTraits.nameof_string</code></a>
This means the module of the type does not matter: the module of a type is often considered an implementation detail, so it is left out to avoid unexpected hash changes from non-breaking releases that change the module of a type.</p>

If you want to include the module name for a broad set of types, rather than explicitly specifying a module name for each type, you may want to consider calling <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.module_nameof_string" rel="nofollow"><code>StableHashTraits.module_nameof_string</code></a> in the body of your <code>transform_type</code> method. <p dir="auto">Most of the behaviors described below can be customized/changed by using your own hash <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.@context" rel="nofollow"><code>StableHashTraits.@context</code></a>, which can be passed as the second argument to <a href="https://beacon-biosignals.github.io/StableHashTraits.jl/stable/api/#StableHashTraits.stable_hash" rel="nofollow"><code>stable_hash</code></a>. StableHashTraits tries to defer to StructTypes for most defaults instead of making more opinionated choices.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 1.3</h3><a id="user-content-in-13" class="anchor" aria-label="Permalink: In 1.3" href="#in-13"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This release includes a new hash version 4 that has breaking API changes relative to earlier versions, documented above. The prior API is deprecated, however remains the default to avoid breaking users's code. In version 2 of StableHashTraits, which will be released in relatively short order, only hash version 4 will be available.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 1.2</h3><a id="user-content-in-12" class="anchor" aria-label="Permalink: In 1.2" href="#in-12"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This release includes a bugfix to <code>stable_type_id</code> and the underlying hashes that depend on it (true for most types). This bug caused <code>stable_type_id</code> to yield a different value depending on the scope in which <code>stable_type_id</code> was first called for a given type.</p>
<p dir="auto">Now that 1.3 is available, 1.2 should not be used, as it addresses the same bug with a better API, rather than the hotfix applied here.</p>
<p dir="auto">1.2 defines hash version 3, which uses a fixed version of <code>stable_type_id</code> that can be used by leveraging hash version 3. E.g. if you call <code>stable_hash(x, version=3)</code> or use <code>HashVersion{3}()</code> where you would have used <code>HashVersion{2}()</code> you will not be susceptible to the bug. If you make use of <code>stable_type_id</code> directly and want to avoid this bug, you should use <code>StableHashTraits.stable_type_id_fixed</code>.</p>
<p dir="auto">Because existing uses of <code>StableHashTraits</code> might depend on the extant, broken behavior, versions 1 and 2 of hashing remain unchanged.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 1.1</h3><a id="user-content-in-11" class="anchor" aria-label="Permalink: In 1.1" href="#in-11"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This release includes speed improvements of about 100 fold.</p>
<ul dir="auto">
<li><strong>Feature</strong>: <code>HashVersion{2}</code> is a new hash context that can be up to ~100x faster than
<code>HashVersion{1}</code>.</li>
<li><strong>Feature</strong>: The requirements for <code>HashVersion{2}</code> on the passed hash function have been
relaxed, such that <code>alg=crc32</code> should again work (no need to call <code>alg=(x,s=UInt32(0)) -&gt; crc32c(copy(x),s)</code>).</li>
<li><strong>Feature</strong>: <code>@ConstantHash</code> allows for precomputed hash values of constant strings and
numbers.</li>
<li><strong>Feature</strong>:  <code>stable_typename_id</code> and <code>stable_type_id</code> provide compile-time 64 bit hashes
of the types of objects</li>
<li><strong>Feature</strong>: <code>root_version</code>: Most users can safely ignore this new function. If you are
implementing a root context (one that returns <code>parent_context(::MyContext) = nothing</code>) you
will need to define this function. It indicates what version of the hashing
implementations to use (1 or 2). It defaults to 1 to avoid changing the hash values of
existing root contexts, but should be defined to return 2 to make use of the more
optimized implementations used by <code>HashVersion{2}</code>.</li>
<li><strong>Deprecation</strong>: <code>HashVersion{1}</code> has been deprecated, favor version 2 over 1 in all cases
where backwards compatibility is not required.</li>
<li><strong>Deprecation</strong>: <code>qualified_name</code> and <code>qualified_type</code> have been deprecated, in favor of
<code>stable_typename_id</code> and <code>stable_type_id</code>.</li>
<li><strong>Deprecation</strong>: <code>ConstantHash</code> has been deprecated in favor of the more efficient
<code>@ConstantHash</code>. To remove deprecated API: any call to <code>ConstantHash(x)</code> where <code>x</code> is
a constant literal should be changed to <code>@ConstantHash(x)</code>. If <code>x</code> is an expression
you can use <code>FnHash(_ -&gt; x)</code> to achieve the same result. Note however that the use
of a non-literal is probably a code smell, as <code>hash_method</code> should normally only
depend on the type of its arguments.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 1.0:</h3><a id="user-content-in-10" class="anchor" aria-label="Permalink: In 1.0:" href="#in-10"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This is a very breaking release, almost all values hash differently and the API has changed.
However, far fewer manual definitions of <code>hash_method</code> become necessary. The fallback for
<code>Any</code> should handle many more cases.</p>
<ul dir="auto">
<li><strong>Breaking</strong>: <code>transform</code> has been removed, its features are covered by <code>FnHash</code> and
<code>HashAndContext</code>.</li>
<li><strong>Breaking</strong>: <code>stable_hash</code> no longer accepts multiple objects to hash (wrap them in a
tuple instead); it now accepts a single object to hash, and the second positional argument
is the context (see below for details on contexts).</li>
<li><strong>Breaking</strong>: The default <code>alg</code> for <code>stable_hash</code> is <code>sha256</code>; to use the old default
(crc32c) you can pass <code>alg=(x,s=UInt32(0)) -&gt; crc32c(copy(x),s)</code>.</li>
<li><strong>Deprecation</strong>: The traits to return from <code>hash_method</code> have changed quite a bit. You
will need to replace the old names as follows to avoid deprecation warnings during your
tests:
<ul dir="auto">
<li>Favor <code>StructHash()</code> (which uses <code>fieldnames</code> instead of <code>propertynames</code>)
to <code>UseProperties()</code>.</li>
<li><em>BUT</em> to reproduce <code>UseProperties()</code>, call <code>StructHash(propertynames =&gt; getproperty)</code></li>
<li>Replace <code>UseQualifiedName()</code> with <code>FnHash(qualified_name, HashWrite())</code></li>
<li>Replace <code>UseSize(method)</code> with <code>(FnHash(size), method)</code></li>
<li>Replace <code>UseTable</code> with <code>FnHash(Tables.columns, StructHash(Tables.columnnames =&gt; Tables.getcolumn))</code></li>
</ul>
</li>
<li><strong>Deprecation</strong>: The fallback methods for hashing are defined within a specific
context (<code>HashVersion{1}</code>). Any contexts you make should define a <code>parent_context</code>
method that returns e.g. <code>HashVersion{1}</code> so that the fallback implementation for any
methods of <code>hash_method</code> you don't implement work properly. (A default version of
<code>parent_context</code> raises a deprecation warning and returns <code>HashVersion{1}</code>). Refer to the
discussion below about contexts.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 0.3:</h3><a id="user-content-in-03" class="anchor" aria-label="Permalink: In 0.3:" href="#in-03"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To prevent reshaped arrays from having the same hash (<code>stable_hash([1 2; 3 4]) == stable_hash(vec([1 2; 3 4]))</code>) the hashes for all arrays with more than 1 dimension have
changed.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">In 0.2:</h3><a id="user-content-in-02" class="anchor" aria-label="Permalink: In 0.2:" href="#in-02"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To support hasing of all tables (<code>Tables.istable(x) == true</code>), hashes have changed for such
objects when:</p>
<ol dir="auto">
<li>calling <code>stable_hash(x)</code> did not previously error</li>
<li><code>x</code> is not a <code>DataFrame</code> (these previously errored)</li>
<li><code>x</code> is not a <code>NamedTuple</code> of tables columns (these have the same hash as before)</li>
<li><code>x</code> is not an <code>AbstractArray</code> of <code>NamedTuple</code> rows (these have the same hash as before)</li>
<li><code>x</code> can be successfully written to an IO buffer via <code>Base.write</code> or
<code>StableHashTraits.write</code> (otherwise it previously errored)</li>
<li><code>x</code> has no specialized <code>stable_hash</code> method defined for it (otherwise
the hash will be the same)</li>
</ol>
<p dir="auto">Any such table now uses the method <code>UseTable</code>, rather than <code>UseWrite</code>, and so would have the
same hash as a <code>DataFrame</code> or <code>NamedTuple</code> with the same column contents instead of its
previous hash value. For example if you had a custom table type <code>MyCustomTable</code> for which
you only defined a <code>StableHashTraits.write</code> method and no <code>hash_method</code>, its hash will be
changed unless you now define <code>hash_method(::MyCustomTable) = UseWrite()</code>.</p>
