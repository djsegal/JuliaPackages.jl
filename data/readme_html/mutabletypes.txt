<p dir="auto">This package provides mutable boolean, integer, rational, real and complex types. Their arithmetic operators are overloaded. The package also exports wrappers for the common math functions.</p>
<p dir="auto">The intent of these mutable types is for their use in immutable data structures that contain a field or fields that need the capability to have their values changed during runtime. For example, a data structure that holds material properties may include a boolean field 'ruptured' that would get turned on (converted from <code>false</code> to <code>true</code>) after a rupture event has occurred, thereafter enabling a change in material properties to take place moving forward.</p>
<p dir="auto">To use this module you will need to add it to your package:</p>

They are needed to read and write objects of types <code>Rational</code>, <code>MRational</code>, <code>Complex</code> and <code>MComplex</code> from and to JSON files.</p>

<p dir="auto">There are methods that read and write the above mutable objects from and to a file to make these data persistent. JSON (JavaScript Object Notation) files are used for this purpose. JSON files store data in key-value pairs, and are therefore an ideal format for storing julia <code>struct</code> types to file. JSON files are lightweight, text-based, human-readable, and can even be edited using a standard text editor.</p>
<p dir="auto">To open an existing JSON file for reading, one can call</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="function openJSONReader(my_dir_path::String, my_file_name::String)::IOStream"><pre class="notranslate"><code>function openJSONReader(my_dir_path::String, my_file_name::String)::IOStream
</code></pre></div>
<p dir="auto">e.g., <code>json_stream = openJSONReader("home/my_dir", "my_file.json").</code> This reader attaches to a file located in directory <code>my_dir_path</code> whose name is <code>my_file_name</code> ending with a <code>.json</code> extension. The file is opened in read-only mode. This reader points to the beginning of the file at its creation.</p>
<p dir="auto">To create a new, or open an existing JSON file for writing, one can call</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="function openJSONWriter(my_dir_path::String, my_file_name::String)::IOStream"><pre class="notranslate"><code>function openJSONWriter(my_dir_path::String, my_file_name::String)::IOStream
</code></pre></div>
<p dir="auto">e.g., <code>json_stream = openJSONWriter("home/my_dir", "my_file.json").</code> This writer attaches to a file located in directory <code>my_dir_path</code> whose name is <code>my_file_name</code> ending with a <code>.json</code> extension. The file is opened in write-create-append mode. This writer points to the beginning of the file, whether it already exists or is to be newly created.</p>
<p dir="auto">To close the file to which a JSON stream is attached, simply call</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="function closeJSONStream(json_stream::IOStream)"><pre class="notranslate"><code>function closeJSONStream(json_stream::IOStream)
</code></pre></div>
<p dir="auto">Methods have been created for reading and writing that take advantage of the multiple dispatch capability of the Julia compiler. The chosen protocal requires that one knows the type belonging to an object to be read in before it can actually be read in. As implemented, the JSON stream does not store type information.</p>

<p dir="auto">For the various <code>toString</code> interfaces listed above, their keywords are given default values that can be overwritten. Specifically,</p>
<ul dir="auto">
<li><code>format</code>: An exponential or scientific output will be written whenever <code>format</code> is set to <code>e</code> or <code>E</code>; otherwise, the output will be written in a fixed-point notation.</li>
<li><code>precision</code>: The number of significant figures to be used in a numeric representation, precision ∈ {3, …, 7}.</li>
<li><code>aligned</code>: If <code>true</code>, a white space will appear before <code>true</code> when converting a <code>MBool</code> to string, or a white space will appear before the first digit in a number whenever its value is non-negative. Aligning is useful, e.g., when stacking outputs, like when printing out a matrix as a string.</li>
</ul>

<p dir="auto">Methods, operators and math functions pertaining to these types (except for <code>copy</code> and <code>deepcopy</code>) return instances belonging to their associated core types: viz., <code>Bool,</code> <code>Integer,</code> <code>Rational,</code> <code>Real</code> or <code>Complex</code>. This is because their intended use is to permit mutable fields to be incorporated into what are otherwise immutable data structures; thereby, allowing such fields to have a potential to change their values. Mutable fields belonging to immutable data structures have the necessary infrastructure to be able to be used seamlessly in simple mathematical formulae outside the data structure itself.</p>
