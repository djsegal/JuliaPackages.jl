<p dir="auto"><a href="https://github.com/JuliaDSP/MFCC.jl/actions/workflows/CI.yml"><img src="https://github.com/JuliaDSP/MFCC.jl/actions/workflows/CI.yml/badge.svg" alt="CI" style="max-width: 100%;"></a></p>
<p dir="auto">A package to compute Mel Frequency Cepstral Coefficients.</p>
<p dir="auto">The essential routine is re-coded from Dan Ellis's rastamat package, and parameters are named similarly.</p>
<p dir="auto">Please note that the feature-vector array consists of a vertical stacking of row-vector features.  This is consistent with the sense of direction of, e.g., <code>Base.cov()</code>, but inconsistent with, e.g., <code>DSP.spectrogram()</code> or <code>Clustering.kmeans()</code>.</p>
<p dir="auto"><code>mfcc()</code> has many parameters, but most of these are set to defaults that <em>should</em> mimick HTK default parameters (not thoroughly tested).</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mfcc(x::Vector, sr=16000.0, defaults::Symbol; args...)"><pre><span class="pl-c1">mfcc</span>(x<span class="pl-k">::</span><span class="pl-c1">Vector</span>, sr<span class="pl-k">=</span><span class="pl-c1">16000.0</span>, defaults<span class="pl-k">::</span><span class="pl-c1">Symbol</span>; args<span class="pl-k">...</span>)</pre></div>
<p dir="auto">Extract MFCC features from the audio data in <code>x</code>, using parameter settings characterized by <code>defaults</code></p>
<ul dir="auto">
<li><code>:rasta</code>: defaults according to Dan Ellis' Rastamat package</li>
<li><code>:htk</code>: defaults mimicking defaults of HTK (unverified)</li>
<li><code>:nbspeaker</code>: narrow-band speaker recognition</li>
<li><code>:wbspeaker</code>: wide-band speaker recognition</li>
</ul>
<p dir="auto">The actual routine for MFCC computation has many parameters, these are basically the same parameters as in Dan Ellis's rastamat package.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mfcc(x::AbstractVector{&lt;:AbstractFloat}, sr::Real=16000.0; wintime=0.025, steptime=0.01, numcep=13, preemph=0.97, lifterexp=-22, nbands=20, minfreq=0.0, maxfreq=sr/2, fbtype=:htkmel, bwidth=1.0, modelorder=0, dcttype=3, dither::Real=false, sumpower::Bool=false, usecmp::Bool=false)"><pre><span class="pl-c1">mfcc</span>(x<span class="pl-k">::</span><span class="pl-c1">AbstractVector{&lt;:AbstractFloat}</span>, sr<span class="pl-k">::</span><span class="pl-c1">Real</span><span class="pl-k">=</span><span class="pl-c1">16000.0</span>; wintime<span class="pl-k">=</span><span class="pl-c1">0.025</span>, steptime<span class="pl-k">=</span><span class="pl-c1">0.01</span>, numcep<span class="pl-k">=</span><span class="pl-c1">13</span>, preemph<span class="pl-k">=</span><span class="pl-c1">0.97</span>, lifterexp<span class="pl-k">=</span><span class="pl-k">-</span><span class="pl-c1">22</span>, nbands<span class="pl-k">=</span><span class="pl-c1">20</span>, minfreq<span class="pl-k">=</span><span class="pl-c1">0.0</span>, maxfreq<span class="pl-k">=</span>sr<span class="pl-k">/</span><span class="pl-c1">2</span>, fbtype<span class="pl-k">=</span><span class="pl-c1">:htkmel</span>, bwidth<span class="pl-k">=</span><span class="pl-c1">1.0</span>, modelorder<span class="pl-k">=</span><span class="pl-c1">0</span>, dcttype<span class="pl-k">=</span><span class="pl-c1">3</span>, dither<span class="pl-k">::</span><span class="pl-c1">Real</span><span class="pl-k">=</span><span class="pl-c1">false</span>, sumpower<span class="pl-k">::</span><span class="pl-c1">Bool</span><span class="pl-k">=</span><span class="pl-c1">false</span>, usecmp<span class="pl-k">::</span><span class="pl-c1">Bool</span><span class="pl-k">=</span><span class="pl-c1">false</span>)</pre></div>
<p dir="auto">This is the main routine computing MFCCs.  <code>x</code> should be a 1D vector of <code>FloatingPoint</code> samples of speech, sampled at a frequency of <code>sr</code>.  Every <code>steptime</code> seconds, a frame of duration <code>wintime</code> is analysed.  The log energy in a filterbank of <code>nbands</code> bins is computed, and a cepstral (discrete cosine transform) representation is made, keeping only the first <code>numcep</code> coefficients (including log energy).  The result is a tuple of three values:</p>
<ul dir="auto">
<li>a matrix with <code>numcep</code> columns and for each speech frame a row of MFCC coefficients</li>
<li>the power spectrum computed with <code>DSP.spectrogram()</code> from which the MFCCs are computed</li>
<li>a dictionary containing information about the parameters used for extracting the features.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Pre-set feature extraction applications</h2><a id="user-content-pre-set-feature-extraction-applications" class="anchor" aria-label="Permalink: Pre-set feature extraction applications" href="#pre-set-feature-extraction-applications"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">We have defined a couple of standard sets of parameters that should function well for particular applications in speech technology.  They are accessible through the higher level function <code>feacalc()</code>.  The top-level interface for calculating features is</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="feacalc(wavfile::AbstractString, application::Symbol; kwargs...)"><pre><span class="pl-c1">feacalc</span>(wavfile<span class="pl-k">::</span><span class="pl-c1">AbstractString</span>, application<span class="pl-k">::</span><span class="pl-c1">Symbol</span>; kwargs<span class="pl-k">...</span>)</pre></div>
<p dir="auto">This will compute speech features suitable for a specific <code>application</code>, which currently can be one of:</p>
<ul dir="auto">
<li><code>:nbspeaker</code>: narrowband (telephone speech) speaker recognition: 19 MFCCs + log energy, deltas, energy-based speech activity detection, feature warping (399 samples)</li>
<li><code>:wbspeaker</code>: wideband speaker recognition: same as above but with wideband MFCC extraction parameters</li>
<li><code>:language</code>: narrowband language recognition: Shifted Delta Cepstra, energy-based speech activity detection, feature warping (299 samples)</li>
<li><code>:diarization</code>: 13 MFCCs, utterance mean and variance normalization</li>
</ul>
<p dir="auto">The <code>kwargs...</code> parameters allow for various options in file format, feature augmentation, speech activity detection and MFCC parameter settings.  They trickle down to versions of <code>feacalc()</code> and <code>mfcc()</code>, allowing for more detailed specification of these parameters.</p>
<p dir="auto"><code>feacalc()</code> returns a tuple of three structures:</p>
<ul dir="auto">
<li>a <code>Matrix</code> of features, one row per frame</li>
<li>a <code>Dict</code> with metadata about the speech (length, SAD selected frames, etc.)</li>
<li>a <code>Dict</code> with the MFCC parameters used for feature extraction</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">More fine-grained control of <code>feacalc()</code></h3><a id="user-content-more-fine-grained-control-of-feacalc" class="anchor" aria-label="Permalink: More fine-grained control of feacalc()" href="#more-fine-grained-control-of-feacalc"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="feacalc(wavfile::AbstractString; method=:wav, kwargs...)"><pre><span class="pl-c1">feacalc</span>(wavfile<span class="pl-k">::</span><span class="pl-c1">AbstractString</span>; method<span class="pl-k">=</span><span class="pl-c1">:wav</span>, kwargs<span class="pl-k">...</span>)</pre></div>
<p dir="auto">This function reads an audio file from disk and represents the audio as a <code>Matrix</code>, and then runs the feature extraction.</p>
<p dir="auto">The <code>method</code> parameter determines what method is used for reading in the audio file:</p>
<ul dir="auto">
<li><code>:wav</code>: use Julia's native <a href="https://github.com/dancasimiro/WAV.jl">WAV</a> library to read RIFF/WAVE <code>.wav</code> files</li>
<li><code>:sox</code>: use external <code>sox</code> program for figuring out the audio file format and converting to native representation</li>
<li><code>:sph</code>: use external <code>w_decode</code> program to deal with (compressed) NIST sphere files</li>
</ul>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="feacalc(x::Array; chan=:mono, augtype=:ddelta, normtype=:warp, sadtype=:energy, dynrange::Real=30., nwarp::Int=399, sr::AbstractFloat=8000.0, source=&quot;:array&quot;, defaults=:nbspeaker, mfccargs...)"><pre><span class="pl-c1">feacalc</span>(x<span class="pl-k">::</span><span class="pl-c1">Array</span>; chan<span class="pl-k">=</span><span class="pl-c1">:mono</span>, augtype<span class="pl-k">=</span><span class="pl-c1">:ddelta</span>, normtype<span class="pl-k">=</span><span class="pl-c1">:warp</span>, sadtype<span class="pl-k">=</span><span class="pl-c1">:energy</span>, dynrange<span class="pl-k">::</span><span class="pl-c1">Real</span><span class="pl-k">=</span><span class="pl-c1">30.</span>, nwarp<span class="pl-k">::</span><span class="pl-c1">Int</span><span class="pl-k">=</span><span class="pl-c1">399</span>, sr<span class="pl-k">::</span><span class="pl-c1">AbstractFloat</span><span class="pl-k">=</span><span class="pl-c1">8000.0</span>, source<span class="pl-k">=</span><span class="pl-s"><span class="pl-pds">"</span>:array<span class="pl-pds">"</span></span>, defaults<span class="pl-k">=</span><span class="pl-c1">:nbspeaker</span>, mfccargs<span class="pl-k">...</span>)</pre></div>
<p dir="auto">The <code>chan</code> parameter specifies for which channel in the audio file you want features.  Possible values are:</p>
<ul dir="auto">
<li><code>:mono</code>: average all channels</li>
<li><code>:a</code>, <code>:b</code>, ...: Use the first (left), second (right), ... channel</li>
<li><code>c::Int</code>: Use the <code>c</code>th channel</li>
</ul>
<p dir="auto">The <code>augtype</code> parameter specifies how the speech features are augmented.  This can be:</p>
<ul dir="auto">
<li><code>:none</code> for no additional features</li>
<li><code>:delta</code> for 1st order derivatives</li>
<li><code>:ddelta</code> for first and second order derivatives</li>
<li><code>:sdc</code> for replacement of the MFCCs with shifted delta cepstra with the default parameters <code>n, d, p, k = 7, 1, 3, 7</code></li>
</ul>
<p dir="auto">The <code>normtype</code> parameter specifies how the features are normalized after extraction</p>
<ul dir="auto">
<li><code>:none</code> for no normalization</li>
<li><code>:warp</code> for short-time Gaussianization using <code>nwarp</code> frames, see <code>warp()</code> below</li>
<li><code>:mvn</code> for mean and variance normalization, see <code>znorm()</code> below</li>
</ul>
<p dir="auto">The <code>sad</code> parameter controls if Speech Activity Detection is carried out on the features, filtering out frames that do not contain speech</p>
<ul dir="auto">
<li><code>:none</code>: apply no SAD</li>
<li><code>:energy</code>: apply energy based SAD, omitting frames with an energy less than <code>dynrange</code> below the maximum energy of the file.</li>
</ul>
<p dir="auto">The various applications actually have somewhat different parameter settings for the basic MFCC feature extraction, see the <code>defaults</code> parameter of <code>mfcc()</code> above.</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="warp(x::Matrix, w=399)"><pre><span class="pl-c1">warp</span>(x<span class="pl-k">::</span><span class="pl-c1">Matrix</span>, w<span class="pl-k">=</span><span class="pl-c1">399</span>)</pre></div>
<p dir="auto">This transforms columns of <code>x</code> by short-time Gaussianization.  Each value in the middle of <code>w</code> rows is replaced with its normal deviate (the quantile function of the normal distribution) based on its rank within the <code>w</code> values.  The result has the same dimensions as <code>x</code>, but the values are chosen from a discrete set of <code>w</code> normal deviates.</p>

<p dir="auto">This normalizes the data <code>x</code> on a column-by-column basis by an affine transformation, making the per-column mean 0 and variance 1.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Derivatives</h3><a id="user-content-derivatives" class="anchor" aria-label="Permalink: Derivatives" href="#derivatives"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Derivative of features, fitted over <code>width</code> consecutive frames:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="deltas(x::Matrix, width::Int)"><pre><span class="pl-c1">deltas</span>(x<span class="pl-k">::</span><span class="pl-c1">Matrix</span>, width<span class="pl-k">::</span><span class="pl-c1">Int</span>)</pre></div>
<p dir="auto">The derivatives are computed over columns individually, and before the derivatives are computed the data is padded with repeats of the first and last rows.  The resulting matrix has the same size as <code>x</code>.  <code>deltas()</code> can be applied multiple times in order to get higher order derivatives.</p>

<p dir="auto">This function expands (MFCC) features in <code>x</code> by computing derivatives over <code>2d+1</code> consecutive frames for the first <code>n</code> columns of <code>x</code>, stacking derivatives shifted over <code>p</code> frames <code>k</code> times.  Before the calculation, the deltas are zero padded so that the results have the same number of rows as <code>x</code>.</p>
