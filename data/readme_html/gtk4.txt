<p dir="auto">GUI building using <a href="https://www.gtk.org" rel="nofollow">GTK</a> version 4. See <a href="https://github.com/JuliaGraphics/Gtk.jl">Gtk.jl</a> for an unmaintained Julia package that wraps GTK version 3. <strong>Note that Gtk.jl and Gtk4.jl cannot be imported in the same Julia session.</strong></p>
<p dir="auto">This package builds on Gtk.jl but uses GObject introspection to support more of the functionality of the GTK library and its dependencies. Libraries that are wrapped by this package include <a href="https://docs.gtk.org/glib/" rel="nofollow">libglib</a>, <a href="https://docs.gtk.org/gobject/" rel="nofollow">libgobject</a>, and <a href="https://docs.gtk.org/gio/" rel="nofollow">libgio</a> (all in the <code>GLib</code> submodule), <a href="https://docs.gtk.org/Pango/" rel="nofollow">libpango</a> (in the <code>Pango</code> submodule), <a href="https://docs.gtk.org/gdk-pixbuf/" rel="nofollow">libgdkpixbuf</a> (in the <code>GdkPixbufLib</code> submodule), and <a href="https://docs.gtk.org/gdk4/" rel="nofollow">libgdk4</a>, <a href="https://docs.gtk.org/gsk4/" rel="nofollow">libgsk4</a>, and <a href="https://docs.gtk.org/gtk4/" rel="nofollow">libgtk4</a> (in the main <code>Gtk4</code> module). GObject introspection for Julia is implemented using <a href="https://github.com/JuliaGtk/Gtk4.jl/tree/main/GI">GI.jl</a>, which is also hosted in this repository.</p>
<p dir="auto">Documentation for the master branch version of this package can be found <a href="https://juliagtk.github.io/Gtk4.jl/dev/" rel="nofollow">here</a>. Example code can be found <a href="https://github.com/JuliaGtk/Gtk4.jl/tree/main/examples">here</a>. Complete GTK documentation is available at <a href="https://www.gtk.org/docs" rel="nofollow">https://www.gtk.org/docs</a>.</p>

<p dir="auto">This package is intended to be a relatively thin wrapper of the GTK library based largely on GObject introspection, analogous to <a href="https://pypi.org/project/PyGObject/" rel="nofollow">PyGObject</a>. Using it beyond simple widgets requires some knowledge of the GTK API (the Gtk4.jl <a href="https://juliagtk.github.io/Gtk4.jl/dev/" rel="nofollow">documentation</a> covers a small fraction of the API available through introspection). It is also very possible to crash or freeze Julia if you're not careful.</p>
<p dir="auto">Those seeking a more user friendly, well documented, curated GUI building experience based on GTK should consider using <a href="https://github.com/Clemapfel/mousetrap.jl">Mousetrap</a>. Other popular packages for creating desktop GUI interfaces include <a href="https://github.com/JuliaGraphics/QML.jl">QML.jl</a>, <a href="https://github.com/JuliaGizmos/Blink.jl">Blink.jl</a>, <a href="https://github.com/davidanthoff/Electron.jl">Electron.jl</a>, and <a href="https://github.com/Gnimuc/CImGui.jl">CImGui.jl</a>.</p>

<p dir="auto">For auto-generated code, Gtk4.jl relies on GObject introspection data generated on a Linux x86_64 machine, which may result in code that crashes on 32 bit computers. This mostly seems to affect obscure parts of GLib that are unlikely to be useful to Julia users, but 32 bit users should be aware of this.</p>
<p dir="auto">Note that this package uses binaries for the GTK library and its dependencies that are built and packaged using <a href="https://github.com/JuliaPackaging/BinaryBuilder.jl">BinaryBuilder.jl</a>. On Linux it does <strong>not</strong> use the binaries that are packaged with your distribution. The build scripts for the binaries used by Gtk4.jl, including the library versions currently being used, can be found by perusing <a href="https://github.com/JuliaPackaging/Yggdrasil.jl">Yggdrasil.jl</a>.</p>

<p dir="auto">Gtk4.jl can interfere with <a href="https://github.com/JuliaPy/PyPlot.jl">PyPlot.jl</a>. Calling Gtk4 functions before PyPlot functions seems to work better, and changing the PyPlot backend to one that does not involve GTK (any version) may prevent issues.
Gtk4.jl has also been reported to interfere with <a href="https://github.com/MakieOrg/Makie.jl">GLMakie.jl</a>, though this doesn't always seem to happen. To use Gtk4 based packages with Makie, you can use <a href="https://github.com/JuliaGtk/Gtk4Makie.jl">Gtk4Makie.jl</a>.</p>

<p dir="auto">On Wayland, a Cairo-based fallback backend will be used unless you tell <code>libglvnd_jll</code> where to find libEGL. This can be done by setting the environment variable __EGL_VENDOR_LIBRARY_DIRS. See <a href="https://gitlab.freedesktop.org/glvnd/libglvnd/-/blob/master/src/EGL/icd_enumeration.md" rel="nofollow">here</a> for details.</p>
<p dir="auto">For convenience, in Gtk4.jl this can be set as a preference for a particular Julia environment using Preferences.jl:</p>

Gtk4<span class="pl-k">.</span><span class="pl-c1">set_EGL_vendorlib_dirs</span>(<span class="pl-s"><span class="pl-pds">"</span>/usr/share/glvnd/egl_vendor.d<span class="pl-pds">"</span></span>)
[ Info<span class="pl-k">:</span> Setting will take effect after restarting Julia.</pre></div>
<p dir="auto">where "/usr/share/glvnd/egl_vendor.d" is a typical location for Mesa's libEGL (this should be modified if it's somewhere else on your distribution). Other vendor-provided libraries may be in other locations, and a colon-separated list of directories can be used for that situation. <strong>Note that this has only been tested for the Mesa-provided libEGL on Fedora and Ubuntu.</strong></p>
