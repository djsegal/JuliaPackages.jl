<p dir="auto">This package implements kernel functions that are optimized for one-dimensional input and
that are GPU-compatible by default.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage</h2><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package expands the KernelFunctions.jl package (which is automatically loaded and
reexported) by a new abstract type <code>ScalarKernel</code>.
Its subtypes include a couple of base kernels with the <code>Scalar</code> prefix.
On 1-dimensional inputs, they give exactly the same output as their KernelFunctions.jl
counterparts, e.g.:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using ScalarKernelFunctions

k1 = ScalarSEKernel() # from this package
k2 = SEKernel() # from KernelFunctions.jl
x = rand(100)
kernelmatrix(k1, x) ≈ kernelmatrix(k2, x) # true"><pre><span class="pl-k">using</span> ScalarKernelFunctions

k1 <span class="pl-k">=</span> <span class="pl-c1">ScalarSEKernel</span>() <span class="pl-c"><span class="pl-c">#</span> from this package</span>
k2 <span class="pl-k">=</span> <span class="pl-c1">SEKernel</span>() <span class="pl-c"><span class="pl-c">#</span> from KernelFunctions.jl</span>
x <span class="pl-k">=</span> <span class="pl-c1">rand</span>(<span class="pl-c1">100</span>)
<span class="pl-c1">kernelmatrix</span>(k1, x) <span class="pl-k">≈</span> <span class="pl-c1">kernelmatrix</span>(k2, x) <span class="pl-c"><span class="pl-c">#</span> true</span></pre></div>
<p dir="auto">When combining subtypes of <code>ScalarKernel</code> using <code>+</code>, <code>with_lengthscale</code>, another subtype of
<code>ScalarKernel</code> will be produced, which means that specialized implementations will be used
for the composite kernel as well.
Mixing specialized and "normal" kernels will also work, but will no longer use the
specialized implementation.</p>
<p dir="auto">Specializing on 1d input allows to achieve lower allocation counts and faster evaluation,
especially combined with AD packages such as Zygote or Enzyme. Parameter fields are also
scalar, which saves allocations with repeated construction of the kernel, e.g. when kernel
parameters are being optimized.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">GPU-compatibility by default</h3><a id="user-content-gpu-compatibility-by-default" class="anchor" aria-label="Permalink: GPU-compatibility by default" href="#gpu-compatibility-by-default"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The kernels in this package are implemented using broadcast, which allows them to work on
the GPU by default. We also export a <code>gpu</code> function, which converts any kernel to use
<code>Float32</code> parameters (where needed), and calling <code>kernelmatrix</code> will preserve <code>Float32</code> to
be most efficient on GPUs. For example, this is how we use a kernel on <code>CuArray</code>s:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using CUDA
x = CUDA.rand(100)
k = ScalarPeriodicKernel() |&gt; gpu # ScalarPeriodicKernel{Float32}(1.0f0)
kernelmatrix(k, x) # returns 100×100 CuArray{Float32, 2, CUDA.Mem.DeviceBuffer}"><pre><span class="pl-k">using</span> CUDA
x <span class="pl-k">=</span> CUDA<span class="pl-k">.</span><span class="pl-c1">rand</span>(<span class="pl-c1">100</span>)
k <span class="pl-k">=</span> <span class="pl-c1">ScalarPeriodicKernel</span>() <span class="pl-k">|&gt;</span> gpu <span class="pl-c"><span class="pl-c">#</span> ScalarPeriodicKernel{Float32}(1.0f0)</span>
<span class="pl-c1">kernelmatrix</span>(k, x) <span class="pl-c"><span class="pl-c">#</span> returns 100×100 CuArray{Float32, 2, CUDA.Mem.DeviceBuffer}</span></pre></div>
<p dir="auto">Omitting the <code>gpu</code> conversion will of course also work, but will be quite a bit slower.</p>
