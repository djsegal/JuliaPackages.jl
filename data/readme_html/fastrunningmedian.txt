<p dir="auto"><a id="user-content-fastrunningmedian.running_median" href="#FastRunningMedian.running_median">#</a>
<strong><code>FastRunningMedian.running_median</code></strong> — <em>Function</em>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="running_median(input, window_length, tapering=:symmetric; kwargs...) -&gt; output"><pre><span class="pl-c1">running_median</span>(input, window_length, tapering<span class="pl-k">=</span><span class="pl-c1">:symmetric</span>; kwargs<span class="pl-k">...</span>) <span class="pl-k">-&gt;</span> output</pre></div>
<p dir="auto">Run a median filter of <code>window_length</code> over the input array and return the result.</p>
<p dir="auto">If the input array is multidimensional, the median will be run only over the first dimension, i.e. over all columns indepedently.</p>
<p dir="auto"><strong>Taperings</strong></p>
<p dir="auto">The tapering decides the behaviour at the ends of the input. The available taperings are:</p>
<ul dir="auto">
<li><code>:symmteric</code> or <code>:sym</code>: Ensure that the window is symmetric around each point of the output array by always growing or shrinking the window by 2. The output has the same length as the input if <code>window_length</code> is odd. If <code>window_length</code> is even, the output has one element less.</li>
<li><code>:asymmetric</code> or <code>:asym</code>: Always adds or removes one element when calculating the next output value. Creates asymmetric windowing at the edges of the array. If the input is N long, the output is N+window_length-1 elements long.</li>
<li><code>:asymmetric_truncated</code> or <code>:asym_trunc</code>: The same as asymmetric, but truncated at beginning and end to match the length of <code>:symmetric</code>.</li>
<li><code>:none</code> or <code>:no</code>: No tapering towards the ends. If the input has N elements, the output is only N-window_length+1 long. Equivalent to "roll" from <a href="https://github.com/JeffreySarnoff/RollingFunctions.jl">RollingFunctions</a>.</li>
<li><code>:beginning_only</code> or <code>:start</code>: At the beginning, always grow the window by one but do not taper the end. This is equivalent to asymmetric but truncated at the end such that the output length matches the input length. Equivalent to "run" from <a href="https://github.com/JeffreySarnoff/RollingFunctions.jl">RollingFunctions</a>.</li>
</ul>
<p dir="auto">If you choose an even <code>window_length</code>, the elements of the output array lie in the middle between the input elements on a continuous underlying axis.</p>
<p dir="auto">With the exception of <code>:beginning_only</code>, all taperings are mirror symmetric with respect to the middle of the input array.</p>
<p dir="auto"><strong>Keyword Arguments</strong></p>
<ul dir="auto">
<li><code>nan=:include</code>: By default, NaN values in the window will turn the median NaN as well. Use <code>nan = :ignore</code> to ignore NaN values and calculate the median over the remaining values in the window. If there are only NaNs in the window, the median will be NaN regardless.</li>
<li><code>output_eltype=Float64</code>: Element type of the output array. The output element type should allow converting from Float64 and the input element type. The exception is odd window lengths with taperings <code>:no</code> or <code>:sym</code>, in which case the output element type only has to allow converting from the input element type.</li>
</ul>
<p dir="auto"><strong>Performance</strong></p>
<p dir="auto">The underlying algorithm should scale as O(N log w) with the input length N and the window_length w.</p>

<p dir="auto">For large window lengths, this package performs even better than calling <code>runmed</code> in R, which uses the Turlach implementation written in C. For small window lengths, the Stuetzle implementation in R still outperforms this package, but the overhead from RCall doesn't seem worth it. Development of a fast implementation for small window lengths is ongoing, see the corresponding issues for details.</p>
<p dir="auto">In contrast to this package, <a href="https://github.com/sairus7/SortFilters.jl">SortFilters.jl</a> supports arbitrary probability levels, for example to calculate quantiles.</p>

<p dir="auto"><a id="user-content-fastrunningmedian.median" href="#FastRunningMedian.median">#</a>
<strong><code>FastRunningMedian.median</code></strong> — <em>Function</em>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="median(mf::MedianFilter; nan=:include)"><pre><span class="pl-c1">median</span>(mf<span class="pl-k">::</span><span class="pl-c1">MedianFilter</span>; nan<span class="pl-k">=</span><span class="pl-c1">:include</span>)</pre></div>
<p dir="auto">Determine the current median in <code>mf</code>.</p>
<p dir="auto"><strong>NaN Handling</strong></p>
<p dir="auto">By default, any NaN value in the filter will turn the result NaN.</p>
<p dir="auto">Use the keyword argument <code>nan = :ignore</code> to ignore NaN values and calculate the median  over the remaining values. If there are only NaNs, the median will be NaN regardless.</p>
<p dir="auto"><strong>Implementation</strong></p>
<p dir="auto">If the number of elements in MedianFilter is odd, the low_heap is always one element bigger than the high_heap. The top element of the low_heap then is the median.</p>
<p dir="auto">If the number of elements in MedianFilter is even, both heaps are the same size and the median is the mean of both top elements.</p>
