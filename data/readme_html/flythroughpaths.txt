<p dir="auto">This package makes it easier to create "fly-through" animations of 3d visualizations.
All of the examples below assume you've loaded the package with <code>using FlyThroughPaths</code>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Representation of paths and view state</h3><a id="user-content-representation-of-paths-and-view-state" class="anchor" aria-label="Permalink: Representation of paths and view state" href="#representation-of-paths-and-view-state"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Paths are parametrized by time <code>t</code>, represented in units of seconds. All paths implicitly start at <code>t=0</code>.</p>
<p dir="auto">The representation of view state is independent of any particular plotting package, although our parametrization is inspired by <a href="https://docs.makie.org/stable/explanations/cameras/#3d_camera" rel="nofollow">Makie's 3D camera</a>:</p>
<ul dir="auto">
<li><code>eyeposition</code>: the 3d coordinates of the camera</li>
<li><code>lookat</code>: the 3d coordinates of the point of the camera's "focus" (center of gaze)</li>
<li><code>upvector</code>: the 3d direction that will correspond to the top of the view. Any component of this vector in the direction of <code>lookat - eyeposition</code> is ignored/discarded.</li>
<li><code>fov</code>: the angle (in degrees) of the cone centered on <code>lookat - eyeposition</code> that should be captured.</li>
</ul>

<p dir="auto">Keyword options include:</p>
<ul dir="auto">
<li><code>constraint</code> (<code>:none</code> or <code>:rotation</code>): specify a value to keep constant during motion. <code>:rotation</code> performs a rotation around <code>lookat</code>. Note that if the separation between <code>eyeposition</code> and <code>lookat</code> is not constant, then the trajectory will be elliptical rather than circular.</li>
<li><code>speed</code> controls how the change is made across time:
<ul dir="auto">
<li><code>:constant</code>: speed is instantaneously set to a new constant value that will arrive at the endpoint at the specified time</li>
<li><code>:sinusoidal</code>: speed will initially increase (starting at a speed of 0), achieve a maximum at the midpoint, and then decrease back to 0.</li>
</ul>
</li>
</ul>

<p dir="auto">The starting state, <code>P0</code> in the diagram, is taken from the endpoint of <code>path</code>. Over the next <code>Δt</code> seconds, one then moves towards the last <code>ViewState</code> argument of <code>bezier</code>, orienting successively towards any prior arguments. Probably the most robust option is to use <code>bezier(Δt, P1, P2, P3)</code>, which can be interpreted as "depart <code>P0</code> traveling towards <code>P1</code>, and arrive at <code>P3</code> as if you had come from <code>P2</code>." The view does not actually pass through <code>P1</code> and <code>P2</code>, but these set the initial and final tangents of the curve.</p>
