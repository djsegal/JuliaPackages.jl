<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto"><span> <strong>About</strong> </span></h1><a id="user-content--about-" class="anchor" aria-label="Permalink: About" href="#-about-"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><strong>Jchemo</strong> was initially dedicated to <strong>partial least squares regression (PLSR) and discrimination (PLSDA) models</strong>
and their extensions, in particular locally weighted PLS models (<strong>LWPLS-R</strong> &amp; <strong>-DA</strong>; e.g. <a href="https://doi.org/10.1002/cem.3209" rel="nofollow">https://doi.org/10.1002/cem.3209</a>). The package has then been expanded to <strong>many other models</strong> for <strong>dimension reduction</strong> and <strong>regression and discrimination</strong> (<a href="https://mlesnoff.github.io/Jchemo.jl/dev/domains/" rel="nofollow">see the list of functions here</a>).</p>
<p dir="auto">Why the name <strong>Jchemo</strong>?: Since it is orientated to <strong>chemometrics</strong> , in brief the use of biometrics for chemistry). But most of the provided methods are <strong>generic to other application domains</strong>.</p>
<p dir="auto"><strong>Jchemo</strong> is organized between</p>
<ul dir="auto">
<li><strong>transformers</strong> (that have a function <code>transf</code>),</li>
<li><strong>predictors</strong> (that have a function <code>predict</code>),</li>
<li><strong>utility functions</strong>.</li>
</ul>
<p dir="auto">Some models, such as PLSR models, are both a transformer and a predictor.</p>
<p dir="auto">Ad'hoc <strong>pipelines</strong> of operations can also be built by the user.
In <strong>Jchemo</strong>, a pipeline is a <strong>chain of <em>K</em> modeling steps</strong> containing</p>
<ul dir="auto">
<li>either <strong><em>K</em> transform steps</strong>,</li>
<li>or <strong><em>K</em> - 1 transform steps</strong> and <strong>a final prediction step</strong>.</li>
</ul>
<p dir="auto">The pipelines are built with function <code>pip</code>, see <a href="https://github.com/mlesnoff/Jchemo.jl/tree/master?tab=readme-ov-file#fitting-a-pipeline"><strong>here</strong></a>.</p>
<p dir="auto"><strong>Warnings</strong></p>
<ul dir="auto">
<li>A breaking change has been made between <strong>version 0.3.7</strong> and <strong>version 0.4.0</strong> for the embedded syntax, with the use of the new function <code>model</code>. For instance:
<ul dir="auto">
<li><code>mod = plskern(; nlv = 15)</code> is now writen as <code>mod = model(plskern; nlv = 15)</code>. Other things have not changed.</li>
</ul>
</li>
<li>Major breaking changes were made between <strong>version 0.2.4</strong> and <strong>version 0.3.0</strong>. Mainly, a new <strong>embedded syntax</strong> was proposed.</li>
</ul>
<p dir="auto">See <a href="https://mlesnoff.github.io/Jchemo.jl/dev/news/" rel="nofollow"><strong>What changed</strong></a> for details.</p>

<p dir="auto">Two syntaxes are allowed for <strong>transformers</strong> and <strong>predictors</strong>:</p>
<ol dir="auto">
<li>the <strong>embedded</strong> syntax, using function <code>model</code>, see <a href="https://github.com/mlesnoff/Jchemo.jl/tree/master?tab=readme-ov-file#-examples-of-syntax-"><strong>here</strong></a>.</li>
<li>the direct syntax (the same as for versions &lt;= 0.2.4),</li>
</ol>
<p dir="auto">The <strong>embedded</strong> syntax makes easier the building of ad'hoc pipelines (chains) of models, and is now favored. Only this embbeded syntax is given in the examples (<strong>help pages</strong> of the functions).</p>
<p dir="auto">Most the <strong>Jchemo</strong> functions have <strong>keyword arguments</strong> (<code>kwargs</code>). The keyword arguments required/allowed in a function can be found in the <strong>Index of function section</strong> of the documentation:</p>
<ul dir="auto">
<li><a href="https://mlesnoff.github.io/Jchemo.jl/stable/api/" rel="nofollow">Stable</a></li>
<li><a href="https://mlesnoff.github.io/Jchemo.jl/dev/api/" rel="nofollow">Developping</a></li>
</ul>
<p dir="auto">or by displaying the function's help page in the REPL, for instance for function <code>plskern</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; ?plskern"><pre>julia<span class="pl-k">&gt;</span> ?plskern</pre></div>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Tuning predictive models</h3><a id="user-content-tuning-predictive-models" class="anchor" aria-label="Permalink: Tuning predictive models" href="#tuning-predictive-models"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Generic <strong>grid-search functions</strong> are available to tune the predictors:</p>
<ul dir="auto">
<li><a href="https://mlesnoff.github.io/Jchemo.jl/stable/api/#Jchemo.gridscore-NTuple%7B5,%20Any%7D" rel="nofollow"><code>gridscore</code></a> (<em>test-set</em> validation)</li>
<li><a href="https://mlesnoff.github.io/Jchemo.jl/stable/api/#Jchemo.gridcv-Tuple%7BAny,%20Any,%20Any%7D" rel="nofollow"><code>gridcv</code></a> (cross-validation).</li>
</ul>
<p dir="auto">Highly accelerated versions of these tuning tools have been implemented for models based on latent variables (LVs) and ridge regularization.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Multi-threading</h3><a id="user-content-multi-threading" class="anchor" aria-label="Permalink: Multi-threading" href="#multi-threading"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Some <strong>Jchemo</strong> functions (in particular those using kNN selections) use <strong>multi-threading</strong>
to speed the computations. Taking advantage of this requires to specify a relevant number
of threads (e.g. from the <em>Settings</em> menu of the VsCode Julia extension and the file <em>settings.json</em>).</p>
