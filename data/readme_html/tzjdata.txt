<p dir="auto">TZJData provides releases of the <a href="https://www.iana.org/time-zones" rel="nofollow">IANA tzdata</a> compiled into the tzjfile (time zone julia file) format. The compiled data stored via <a href="https://pkgdocs.julialang.org/v1/artifacts/" rel="nofollow">package artifacts</a> and used by the <a href="https://github.com/JuliaTime/TimeZones.jl">TimeZones.jl</a> as an the source of pre-computed time zones.</p>

<p dir="auto">The TZJData package uses <a href="https://semver.org/" rel="nofollow">semantic versioning</a> like any other Julia package. Unlike most Julia packages however the TZJData package also uses build metadata to indicate the associated IANA tzdata release (e.g. TZJData release <code>1.0.0+2023c</code> uses tzdata 2023c). Each TZJData release is only associated with a single IANA tzdata release but multiple TZJData releases may correspond to the same IANA tzdata release (i.e. <code>1.0.0+2023c</code> and <code>1.0.1+2023c</code> both use tzdata 2023c).</p>
<p dir="auto">In addition to the standard semantic versioning rules used by Julia packages the TZJData package also adheres to the following internal rules:</p>
<ol dir="auto">
<li>The build metadata is used to indicate the tzdata version associated with each release (e.g. <code>2023c</code>)</li>
<li>A minor release MUST be made when the tzdata version used has been updated to a newer version. A update to the tzdata version must be the immediate next release.</li>
<li>A major release MUST be made if the tzjfile format is changed in a non-backwards compatible manner</li>
<li>A major release MUST be used if it is desired to release older tzdata versions. In such a scenario ALL subsequent tzdata versions should be also be made into new releases to ensure the latest release in this major series is the latest tzdata.</li>
</ol>
