<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Performance</h3><a id="user-content-performance" class="anchor" aria-label="Permalink: Performance" href="#performance"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">I write this package aim to study some heavy quantum many-body problems (e.g. high-$T_c$ superconductivity, typical bond dimension <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$D \sim 10^4$</math-renderer>  ), therefore the performance is the the most important metric.</p>
<ul dir="auto">
<li>Non-abelian symmetries (e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$U_1\times SU_2$</math-renderer> symmetry for spin-1/2 fermions) can significantly accelerate the computation, therefore we choose <a href="https://github.com/Jutho/TensorKit.jl">TensorKit.jl</a> as the backend to perform the basic tensor operations.</li>
<li>The hamiltonian MPO can be represented as a sparse one with abstract horizontal bonds so that the interaction terms can be distributed to different threads or workers, together with nested multi-threaded BLAS (with the help of <a href="https://github.com/JuliaLinearAlgebra/MKL.jl">MKL.jl</a>).</li>
<li>The local operators are classified and wrapped as parametric types for further optimizations via multiple dispatch.</li>
<li>
<a href="https://doi.org/10.1103/PhysRevLett.130.246402" rel="nofollow">Controlled bond expansion (CBE)</a> techniques are implemented (modified for compatibility with parallelism) to reduce the complexity, e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$O(D^3d^2)$</math-renderer> to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$O(D^3d)$</math-renderer> for DMRG and TDVP.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Convenience</h3><a id="user-content-convenience" class="anchor" aria-label="Permalink: Convenience" href="#convenience"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>The MPS-level operations are separated with the lower tensor-level operations so modifying codes with different symmetries, lattices and models is quite simple.</li>
<li>We provide a hamiltonian generator via automata (like <code>OpSum</code> in <a href="https://github.com/ITensor/ITensors.jl">ITensors.jl</a>) so that the interactions can be added in a simple and general way, details please see the tutorials.</li>
<li>We also provide some similar interfaces so that you can measure the  observales and correlations conveniently. Note these computations can also be multi-threaded.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">MPO supports</h3><a id="user-content-mpo-supports" class="anchor" aria-label="Permalink: MPO supports" href="#mpo-supports"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><a href="https://www.cqm2itp.com/" rel="nofollow">Our group</a> works on purification-based finite-temperature simulations therefore we provide more MPO supports than other MPS packages.</p>
<ul dir="auto">
<li>Almost all methods for MPS are also implemented for MPO.</li>
<li>Some finite-temperature algorithms such as series-expansion thermal tensor network (<a href="https://doi.org/10.1103/PhysRevB.95.161104" rel="nofollow">SETTN</a>) and tangent space tensor renormalization group (<a href="https://doi.org/10.1103/PhysRevLett.130.226502" rel="nofollow">tanTRG</a>) are provided.</li>
</ul>

<p dir="auto">Now this package contains</p>
<ul dir="auto">
<li>DMRG for searching ground states.</li>
<li>SETTN and tanTRG for finite-temperature simulations. Both thermal quantites and observables can be obtained.</li>
<li>Ground state and finite-temperature dynamics can be studied with real-time evolution based on TDVP. Note this is still under development.</li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Multi-threading settings</h3><a id="user-content-multi-threading-settings" class="anchor" aria-label="Permalink: Multi-threading settings" href="#multi-threading-settings"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">Only multi-threading is stable in current version, please make sure Julia is started with <a href="https://docs.julialang.org/en/v1/manual/multi-threading/#man-multithreading" rel="nofollow">multiple threads</a>. It will throw a warning to remind you when loading <code>FiniteMPS</code> with a single thread.</p>
<p dir="auto">TODO: I will add single-thread mode and try to support multi-processing in the future.</p>
</li>
<li>
<p dir="auto">If the linear algebra backend is <code>OpenBlas</code>, nested multi-threading is forbidden (a related discussion <a href="https://carstenbauer.github.io/ThreadPinning.jl/stable/explanations/blas/" rel="nofollow">here</a>). So just close the parallelism of BLAS via</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="BLAS.set_num_threads(1)"><pre>BLAS<span class="pl-k">.</span><span class="pl-c1">set_num_threads</span>(<span class="pl-c1">1</span>)</pre></div>
</li>
<li>
<p dir="auto">If using MKL as the linear algebra backend, you can set the number of blas threads similarly and nested multi-threading can be supported in this case. Note MKL is invalid for some cpus and you should also close the BLAS parallelism in such case. You can follow <a href="https://github.com/JuliaLinearAlgebra/MKL.jl">MKL.jl</a> to check if MKL is loaded successfully or not.</p>
<blockquote>
<p dir="auto">[!WARNING] Warning:
Please make sure the total threads number is not larger than the cpu cores (physical, without hyper-threading). Otherwise, the performance will become much worse due to confliction. You can estimate the total threads via</p>
</blockquote>

<p dir="auto">The first step is to choose a local space, i.e. the local 1-site Hilbert space and some 1-site operators according to the model and symmetry used. We predefine some in folder <code>LocalSpace</code> and you can use the documentation to see which operators are provided in it, e.g</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="help?&gt; U₁Spin"><pre>help?<span class="pl-k">&gt;</span> U₁Spin</pre></div>
<blockquote>
<p dir="auto">[!NOTE] Note:
It is impossible to predefine all local spaces so you must write a new one if that you need is not in it. Moreover, some <code>no method</code> errors may occur when using a new defined one due to the multiple-dispatch-based implementations may not cover all kinds of operators. Please feel free to submit an issue if this happens and I will deal with it as soon as possible.</p>
</blockquote>

We use a tree-like struct <code>InteractionTree</code> to store them and provide an interface named <code>addIntr!</code> to add terms. The following is a demo code to generate the hamiltonian of an AFM Heisenberg chain.</p>

<p dir="auto">Although the <code>FiniteMPS</code> package is written in an object-oriented style, a procedure-oriented script is still required for a concrete question. You can freely design it with the following sweep methods such as</p>
<ul dir="auto">
<li>DMRGSweep2!, DMRGSweep1!<br>
The standard 2-site/1-site DMRG sweep.</li>
<li>TDVPSweep2!, TDVPSweep1!<br>
The standard 2-site/1-site TDVP sweep.</li>
</ul>
<p dir="auto">being the usually used building blocks.</p>
<p dir="auto">Note a trilayer tensor network (namely environment), e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$\langle \Psi|H|\Psi\rangle$</math-renderer> where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$\ket{\Psi}$</math-renderer> the MPS and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$H$</math-renderer> the hamiltonian MPO, instead of the state <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4c3b45bfe982bbe90be5c2287ff0c0ec">$\ket\Psi$</math-renderer>, should be passed in. The following code will initialize a random MPS and then generate the environment.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# initialize

<p dir="auto">More detailed usages of the above functions can be found in the documentation.</p>
<blockquote>
<p dir="auto">[!NOTE] Note:
Symmetries may limit the choice of auxiliary space, e.g. the spin quantum number must be integers or half integers alternately along the sites for spin-1/2 systems as fusing the physical space will exactly shift quantum number by 1/2. If the auxiliary space (<code>Rep[U₁](i =&gt; 1 for i in -1:1//2:1)</code> here) is not chosen appropriately to be compatible with the symmetry, some errors will occur when generating the MPS or later.</p>
</blockquote>
<p dir="auto">For example, you can use <code>DMRGSweep2!</code> to obtain the ground state MPS</p>
