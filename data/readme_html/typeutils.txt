<p dir="auto">Package <code>TypeUtils</code> provides useful methods to deal with types in
<a href="https://www.julialang.org" rel="nofollow">Julia</a> and facilitate coding with numbers whether
they have units or not. The package provides methods to strip units from
numbers or numeric types, convert the numeric type of quantities (not their
units), determine appropriate numeric type to carry computations mixing numbers
with different types and/or units. These methods make it easy to write code
that works consistently for numbers with any units (including none). The
intention is that the <code>TypeUtils</code> package automatically extends its exported
methods when packages such as
<a href="https://github.com/PainterQubits/Unitful.jl"><code>Unitful</code></a> are loaded.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Cast value to type</h2><a id="user-content-cast-value-to-type" class="anchor" aria-label="Permalink: Cast value to type" href="#cast-value-to-type"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The method, <code>as</code> is designed to <em>cast</em> a value to a given type. The name was
inspired by the built-in <a href="https://ziglang.org/" rel="nofollow">Zig</a> function
<a href="https://ziglang.org/documentation/master/#as" rel="nofollow"><code>@as</code></a>.</p>
<p dir="auto">A first usage is:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="as(T, x)"><pre><span class="pl-c1">as</span>(T, x)</pre></div>
<p dir="auto">which yields <code>x</code> converted to type <code>T</code>. This behaves like a lazy version of
<code>convert(T,x)::T</code> doing nothing if <code>x</code> is already of type <code>T</code> and performing
the conversion and the type assertion otherwise.</p>
<p dir="auto">By default, the <code>as</code> method calls <code>convert</code> only if needed but also implements
a number of conversions not supported by <code>convert</code>. The <code>as</code> method is
therefore a bit more versatile than <code>convert</code> while relaxing the bother to
remember which function or constructor to call to efficiently perform the
intended conversion. For example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; as(Tuple, CartesianIndex(1,2,3)) # yields tuple of indices

<p dir="auto">Another usage is:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="as(T)"><pre><span class="pl-c1">as</span>(T)</pre></div>
<p dir="auto">which yields a callable object that converts its argument to type <code>T</code>. This can
be useful with <code>map</code>. For instance:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="map(as(Int), dims)"><pre><span class="pl-c1">map</span>(<span class="pl-c1">as</span>(Int), dims)</pre></div>
<p dir="auto">to convert <code>dims</code> to a tuple (or array) of <code>Int</code>s.</p>
<p dir="auto">Additional conversions becomes possible if another package such as
<a href="https://github.com/emmt/TwoDimensional.jl"><code>TwoDimensonal</code></a> is loaded.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Unitless value or type</h2><a id="user-content-unitless-value-or-type" class="anchor" aria-label="Permalink: Unitless value or type" href="#unitless-value-or-type"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>unitless(x)</code> yields <code>x</code> without its units, if any. <code>x</code> can be a number or a
numeric type. In the latter case, <code>unitless</code> behaves like <code>bare_type</code> described
below.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Bare, real, and floating-point numerical types</h2><a id="user-content-bare-real-and-floating-point-numerical-types" class="anchor" aria-label="Permalink: Bare, real, and floating-point numerical types" href="#bare-real-and-floating-point-numerical-types"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>bare_type(x)</code> yields the bare numeric type of <code>x</code> (a numeric value or type).
If this method is not extended for a specific type, the fallback implementation
yields <code>typeof(one(x))</code>. With more than one argument, <code>bare_type(args...)</code>
yields the type resulting from promoting the bare numeric types of <code>args...</code>.
With no argument, <code>bare_type()</code> yields <code>TypeUtils.BareNumber</code> the union of bare
numeric types that may be returned by this method.</p>
<p dir="auto"><code>real_type(x)</code> yields the bare real type of <code>x</code> (a numeric value or type). If
this method is not extended for a specific type, the fallback implementation
yields <code>typeof(one(real(x))</code>. With more than one argument, <code>real_type(args...)</code>
yields the type resulting from promoting the bare real types of <code>args...</code>. With
no argument, <code>real_type()</code> yields <code>Real</code> the super-type of types that may be
returned by this method.</p>
<p dir="auto">The only difference between <code>bare_type</code> and <code>real_type</code> is how they treat
complex numbers. The former preserves the complex kind of its argument while
the latter always returns a real type. You may assume that <code>real_type(x) = real(bare_type(x))</code>. Conversely, <code>convert_bare_type(T,x)</code> yields a complex
result if <code>T</code> is complex and a real result if <code>T</code> is real whatever <code>x</code>, while
<code>convert_real_type(T,x)</code> yields a complex result if <code>x</code> is complex and a real
result if <code>x</code> is real, only the real part of <code>T</code> matters for
<code>convert_real_type(T,x)</code>. See examples below.</p>
<p dir="auto"><code>floating_point_type(args...)</code> yields a floating-point type appropriate to
represent the bare real type of <code>args...</code>. With no argument,
<code>floating_point_type()</code> yields <code>AbstractFloat</code> the super-type of types that may
be returned by this method. You may consider <code>floating_point_type(args...)</code> as
an equivalent to to<code>float(real_type(args...))</code>. The floating-point type can be
seen as the numerical precision for computations involving <code>args...</code>.</p>
<p dir="auto"><code>convert_bare_type(T,x)</code> converts the bare numeric type of <code>x</code> to the bare
numeric type of <code>T</code> while preserving the units of <code>x</code> if any. Argument <code>x</code>
may be a number or a numeric type, while argument <code>T</code> must be a numeric type.
If <code>x</code> is one of <code>missing</code>, <code>nothing</code>, <code>undef</code>, or the type of one of these
singletons, <code>x</code> is returned.</p>
<p dir="auto"><code>convert_real_type(T,x)</code> converts the bare real type of <code>x</code> to the bare real
type of <code>T</code> while preserving the units of <code>x</code> if any. Argument <code>x</code> may be a
number or a numeric type, while argument <code>T</code> must be a numeric type. If <code>x</code>
is one of <code>missing</code>, <code>nothing</code>, <code>undef</code>, or the type of one of these
singletons, <code>x</code> is returned.</p>
<p dir="auto"><code>convert_floating_point_type(T,x)</code> converts the bare real type of <code>x</code> to the
suitable floating-point type for type <code>T</code> while preserving the units of <code>x</code>
if any. Argument <code>x</code> may be a number or a numeric type, while argument <code>T</code>
must be a numeric type. If <code>x</code> is one of <code>missing</code>, <code>nothing</code>, <code>undef</code>, or
the type of one of these singletons, <code>x</code> is returned. You may consider
<code>convert_floating_point_type(T,x)</code> as an equivalent to
to <code>convert_real_type(float(real_type(T)),x)</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Deal with array element types</h2><a id="user-content-deal-with-array-element-types" class="anchor" aria-label="Permalink: Deal with array element types" href="#deal-with-array-element-types"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <code>TypeUtils</code> package provides a few methods to deal with array element
types:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>promote_eltype(args...)</code> yields the promoted element type of the arguments
<code>args...</code> which may be anything implementing the <code>eltype</code> method.</p>
</li>
<li>
<p dir="auto"><code>convert_eltype(T,A)</code> yields an object similar to <code>A</code> except that its
elements have type <code>T</code>.</p>
</li>
<li>
<p dir="auto"><code>as_eltype(T,A)</code> yields an array which lazily converts its entries to type
<code>T</code>. This can be seen as a memory-less version of <code>convert_eltype(T,A)</code>. The
method <code>as_eltype</code> is similar to the method <code>of_eltype</code> provided by the
<a href="https://github.com/JuliaArrays/MappedArrays.jl/tree/master"><code>MappedArrays</code></a>
package.</p>
</li>
</ul>
<p dir="auto">Methods <code>convert_eltype(T,A)</code> and <code>as_eltype(T,A)</code> just return <code>A</code> itself if
its elements are of type <code>T</code>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Type of result returned by a function</h2><a id="user-content-type-of-result-returned-by-a-function" class="anchor" aria-label="Permalink: Type of result returned by a function" href="#type-of-result-returned-by-a-function"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The call:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="g = as_return(T, f)"><pre>g <span class="pl-k">=</span> <span class="pl-c1">as_return</span>(T, f)</pre></div>
<p dir="auto">yields a callable object such that <code>g(args...; kwds...)</code> lazily converts the
value returned by <code>f(args...; kwds...)</code> to the type <code>T</code>. Methods
<code>return_type(g)</code> and <code>parent(g)</code> can be used to respectively retrieve the type
<code>T</code> and the original function <code>f</code>. A similar kind of object be built with the
composition operator:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="g = as(T)∘f"><pre>g <span class="pl-k">=</span> <span class="pl-c1">as</span>(T)<span class="pl-k">∘</span>f</pre></div>
<p dir="auto">The method <code>return_type</code> may also be used as:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="T = return_type(f, argtypes...)"><pre>T <span class="pl-k">=</span> <span class="pl-c1">return_type</span>(f, argtypes<span class="pl-k">...</span>)</pre></div>
<p dir="auto">to infer the type <code>T</code> of the result returned by <code>f</code> when called with arguments
of types <code>argtypes...</code>.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Destructure an object as values and restructure values as an object</h2><a id="user-content-destructure-an-object-as-values-and-restructure-values-as-an-object" class="anchor" aria-label="Permalink: Destructure an object as values and restructure values as an object" href="#destructure-an-object-as-values-and-restructure-values-as-an-object"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">It is sometime useful to collect the values stored by a structured object into
simple collection of values (a tuple or a vector). The reverse operation is
also needed. The call:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="vals = destructure(obj)"><pre>vals <span class="pl-k">=</span> <span class="pl-c1">destructure</span>(obj)</pre></div>
<p dir="auto">yields a tuple, <code>vals</code>, of the values of the structured object <code>obj</code> and,
conversely, the call:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="obj = restructure(T, vals)"><pre>obj <span class="pl-k">=</span> <span class="pl-c1">restructure</span>(T, vals)</pre></div>
<p dir="auto">builds a structured object of type <code>T</code> given <code>vals</code>, a tuple or a vector of its
values.</p>
<p dir="auto">For an immutable concrete object <code>obj</code>, the following identity holds:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="restructure(typeof(obj), destructure(obj)) === obj"><pre><span class="pl-c1">restructure</span>(<span class="pl-c1">typeof</span>(obj), <span class="pl-c1">destructure</span>(obj)) <span class="pl-k">===</span> obj</pre></div>
<p dir="auto">It is also possible to destructure an object into a given vector of values:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="destructure!(vals, obj)"><pre><span class="pl-c1">destructure!</span>(vals, obj)</pre></div>
<p dir="auto">Optionally, in <code>restructure</code> and <code>destructure!</code> methods, keyword <code>offset</code> may
be specified to not start with the first value in <code>vals</code>.</p>
<p dir="auto">Method <code>struct_length</code> yields the minimal number of values needed to
destructure an object.</p>

<p dir="auto">The following example shows a first attempt to use <code>bare_type</code> to implement
efficient in-place multiplication of an array (whose element may have units) by
a real factor (which must be unitless in this context):</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function scale!(A::AbstractArray, α::Number)

<p dir="auto">An improvement is to realize that when <code>α</code> is a real while the entries of <code>A</code>
are complexes, it is more efficient to multiply the entries of <code>A</code> by a
real-valued multiplier rather than by a complex one. Implementing this is as
simple as replacing <code>convert_bare_type</code> by <code>convert_real_type</code> to only convert
the bare real type of the multiplier while preserving its complex/real kind:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function scale!(A::AbstractArray, α::Number)

    end
    return A

    <span class="pl-c1">@inbounds</span> <span class="pl-c1">@simd</span> <span class="pl-k">for</span> i <span class="pl-k">in</span> <span class="pl-c1">eachindex</span>(A)

    <span class="pl-k">end</span>

<p dir="auto">This latter version consistently and efficiently deals with <code>α</code> being real
while the entries of <code>A</code> are reals or complexes, and with <code>α</code> and the entries
of <code>A</code> being complexes. If <code>α</code> is a complex and the entries of <code>A</code> are reals,
the statement <code>A[i] *= alpha</code> will throw an <code>InexactConversion</code> if the
imaginary part of <code>α</code> is not zero. This check is probably optimized out of the
loop by Julia but, to handle this with guaranteed no loss of efficiency, the
code can be written as:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function scale!(A::AbstractArray, α::Union{Real,Complex})
    alpha = if α isa Complex &amp;&amp; bare_type(eltype(A)) isa Real
        convert(real_type(eltype(A)), α)
    else
        convert_real_type(eltype(A), α)
    end
    @inbounds @simd for i in eachindex(A)
        A[i] *= alpha
    end
    return A
end"><pre><span class="pl-k">function</span> <span class="pl-en">scale!</span>(A<span class="pl-k">::</span><span class="pl-c1">AbstractArray</span>, α<span class="pl-k">::</span><span class="pl-c1">Union{Real,Complex}</span>)

        <span class="pl-c1">convert</span>(<span class="pl-c1">real_type</span>(<span class="pl-c1">eltype</span>(A)), α)
    <span class="pl-k">else</span>
        <span class="pl-c1">convert_real_type</span>(<span class="pl-c1">eltype</span>(A), α)

    <span class="pl-k">end</span>
    <span class="pl-k">return</span> A

<p dir="auto">The restriction <code>α::Union{Real,Complex}</code> accounts for the fact that in-place
multiplication imposes a unitless multiplier. Since the test leading to the
expression used for <code>alpha</code> is based on the types of the arguments, the branch
is eliminated at compile time and the type of <code>alpha</code> is known by the compiler.
The <code>InexactConversion</code> exception may then only be thrown by the call to
<code>convert</code> in the first branch of the test.</p>
<p dir="auto">This seemingly very specific case was in fact the key point to allow for
packages such as <a href="https://github.com/emmt/LazyAlgebra.jl">LazyAlgebra</a> or
<a href="https://github.com/emmt/LinearInterpolators.jl">LinearInterpolators</a> to work
seamlessly on arrays whose entries may have units. The <code>TypeUtils</code> (formerly
<code>Unitless</code>) package was created to cover this need as transparently as
possible.</p>
