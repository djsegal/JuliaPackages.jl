<ul dir="auto">
<li><code>@sizes</code>: Very simple size print</li>
<li><code>@typeof</code>: Simplest type print</li>
<li><code>@display</code> and <code>@println</code>: Simplest print</li>
<li><code>@dtime</code>: Simple execution time measurement</li>
<li><code>@clear_line</code>: Clear above terminal line</li>
<li><code>@async_showerr</code> and <code>@asyncsafe</code>: Error-handling for async operations</li>
<li><code>findfirst_typed</code>: Typesafe find first</li>
<li><code>idxI</code>: Extract elements at specific index from array of arrays</li>
<li><code>push_ifne!</code>: Push if not exist.</li>
</ul>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Why Use BoilerplateCvikli?</h2><a id="user-content-why-use-boilerplatecvikli" class="anchor" aria-label="Permalink: Why Use BoilerplateCvikli?" href="#why-use-boilerplatecvikli"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">@show is extremely useful because it eliminates the need for parentheses. While this might seem minor, it's crucial for quick typing. Julia's most important debugging function should adopt this style as it is very fast to type. Of course, in other languages, you would use macros for this, but that introduces a significant amount of boilerplate code, which is a cognitive burden and should be reduced as much as possible.</p>
<p dir="auto">That is why @sizes and @typeof are also extremely useful. It could be standardized by the community, though my focus is primarily on supporting my own goals.</p>
<p dir="auto">Some of these boilerplates are so trivial that they're already on Julia Discourse. I've just copied some of them.</p>

<p dir="auto">Here are some other productivity tools I recommend:</p>
<ul dir="auto">
<li>The best stacktrace I am using: RelevanceStacktrace.jl. Reduce error search to ZERO! JuliaSyntax.jl will give us even more possibilities.</li>
<li>I have a fork of the julia-vscode plugin that is also extremely useful; I cannot emphasize this enough. Sadly, Python cannot do this as well as Julia. - - This is actually the main reason Julia is the best language today.</li>
<li>Sysimage creator that is also really great! It can precompile packages while keeping them modifiable from outside. As of Julia 1.9, this is less of a big deal.</li>
<li>PkgResolver package that could be expanded and added to the sysimage, so it would automatically find and resolve package issues when using "add" and "dev". This project's goal is to reduce the problem of package resolving to just running one simple script.</li>
<li>Also, there is ExtremeBoilerplate, which introduces type piracy issues to further improve the codebase. (However, if the specified package adopts the function, it won't cause type piracy. 😊)</li>
<li>I will share more later on.</li>
</ul>
