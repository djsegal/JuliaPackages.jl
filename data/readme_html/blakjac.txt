<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Introduction</h2><a id="user-content-introduction" class="anchor" aria-label="Permalink: Introduction" href="#introduction"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">BLAKJac is implemented in the Julia language. It relates to the MR-STAT functionality and aims to predict or minimize the noise levels in the reconstructed quantitative maps.</p>
<p dir="auto">Two of its main functions are</p>
<ul dir="auto">
<li>Analyzer: given a sequence of encoding values and of RF pulse angles, it predicts the resulting noise level.</li>
<li>Optimizer: given a sequence of encoding values, it generates a sequence of RF pulse angles that is presumed to be optimal in terms of noise level.
The Optimizer makes use of the Analyzer.</li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Analyzer</h3><a id="user-content-analyzer" class="anchor" aria-label="Permalink: Analyzer" href="#analyzer"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In essence, the analyzer has as its input</p>
<ul dir="auto">
<li>The RF sequence: a vector of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer> complex values, with e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}=5\cdot 224=1120$</math-renderer>. The magnitude of the complex values expresses the flip angle in degrees.</li>
<li>The <em>trajectorySet</em>. See dedicated section below.</li>
<li>A large bunch of options, in the form of a dictionary. For details, see BLAKJac_analysis and BLAKJac_defaults</li>
</ul>
<p dir="auto">There is one additional parameter:</p>
<ul dir="auto">
<li>[Actually an output] Optionally, a dictionary of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$I^{-1}$</math-renderer> matrices, where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$I$</math-renderer> is the diagonalized Fisher Information Matrix. Such a dictionary may be useful if the optimizer is run a multiplicity of times.</li>
</ul>
<p dir="auto">As an <em>Output</em>, the Analyzer returns</p>
<ul dir="auto">
<li>A vector of noise levels of length <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$p$</math-renderer>, with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$p$</math-renderer> being the number of properties. For the time being, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$p$</math-renderer> is always 3.</li>
<li>An estimate of the <em>information content</em> that can be expected from the scan; for the time being, a pretty immature metric.</li>
<li>
<em>b1factorRMS</em>: an indication on how sensitive the sequence is to deviations of B1+.</li>
</ul>
<p dir="auto">Mostly, only the first output is used, the vector of noise levels. These have a somewhat quantitative meaning: these are scaled such that if <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$T_1$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$T_2$</math-renderer> were to be known beforehand, an ideal sequence would result in the vector [1.0, 0.0, 0.0]. Typically, the results are on the order of 3; a value of 2 is “good”, a value over 4 is generally bad and if it results in values below 1.0, then something is fishy – unless strong regularization has been applied (see “options”).</p>

<p dir="auto">In brief, the optimizer has a trajectorySet as input and it spits out an RF sequence. And it needs a lot of options.</p>
<p dir="auto">The input:</p>
<ul dir="auto">
<li>A <em>trajectorySet</em>. See dedicated section below.</li>
<li>A large bunch of options, in the form of a dictionary.</li>
<li>(Optionally) a random-value seed. Relevant if the option opt_initialize (see below) is set to cRandom30. By default, every run of the optimizer will always return the same pattern. If different realizations are needed, each call to the optimizer must be done with a different seed (Int).</li>
</ul>
<p dir="auto">Output</p>
<ul dir="auto">
<li>It returns an RF sequence: a vector of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer> complex values, with e.g. <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}=5\cdot 224=1120$</math-renderer>. The magnitude of the complex values expresses the flip angle in degrees.</li>
</ul>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">TrajectorySet</h2><a id="user-content-trajectoryset" class="anchor" aria-label="Permalink: TrajectorySet" href="#trajectoryset"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <em>trajectorySet</em>. This is a vector of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer> vectors (in Cartesian applications, these are vectors of length 1) of <em>TrajectoryElement</em>. And a TrajectoryElement is a tuple, mostly used for <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(k_y,k_z)$</math-renderer> – and then, in 2D-cases, the value of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_z$</math-renderer> is fixed (typically, always 0).</p>
<p dir="auto">Note that in the 2D case, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_x$</math-renderer> is actually ignored, assuming that all samples of the readout share the same history – which ignores T2-decay during readout.</p>
<p dir="auto">The reason of making the trajectorySet a vector of vectors is for non-Cartesian: then, it can be e.g. a vector of 20 spirals of 1000 samples each and “$(k_y,k_z)$” has to be interpreted as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(k_x,k_y)$</math-renderer>.</p>
<p dir="auto">The function TrajectorySet(kyVector, kzVector) may be useful before invoking the Analyzer: it converts an <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer>-vector of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y$</math-renderer> values and an <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer>-vector of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_z$</math-renderer> values into an <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$N_{TR}$</math-renderer>-vector of singleton-vectors of tuples <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(k_y,k_z)$</math-renderer>. That function has the following (tricky?) logic: if any of the provided <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y$</math-renderer> or <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_z$</math-renderer> values is negative, then it assumes <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(k_y,k_z)=(0,0)$</math-renderer> corresponds to zero spatial frequency. If the provided values are all nonnegative, it assumes the center of the range to correspond to zero spatial frequency. This logic is due to legacy reasons, where typically <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y=1:224$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_z=1$</math-renderer> would be provided, so TrajectorySet shifts the values by (112,1) in that example.</p>

<p dir="auto">There are lots of option parameters, some of them are deprecated and some have defaults that are very rarely adapted. For that purpose, the following function is available:</p>
<p dir="auto">BLAKJac_defaults!(trajectorySet::Vector{&lt;:Vector{&lt;:TrajectoryElement}}, options::Dict)</p>
<p dir="auto">It does not return anything, but the “!” indicates that options will be modified by it. Note: it only assigns uninitialized options to a default value. Options that are already filled in will be left unmodified. To set all options to default, use</p>
<p dir="auto">recon_options = Dict() # erase all existing settings</p>
<p dir="auto">BLAKJac.BLAKJac_defaults!(trajectorySet, recon_options)</p>
<p dir="auto">The <em>trajectorySet</em> is a parameter, since some defaults are set accordingly to the encoding sequence.</p>

<p dir="auto">Remarks:</p>
<p dir="auto">(R1)
: maxMeas: Maximum expected number of measurements per phase-encoding value. A ToDo item: this should be automatic, but for the time being, it has to be provided by the user. If there is no variable density, then the default value has to be set to 4 times the number of k-spaces, i.e. 4<em>nTR/nky in 2D sequences and to 8</em>nTR/(nky*nkz) if two phase-encoding directions are applied (which points to a flaw in the default, in the case of 3D).</p>
<p dir="auto">Why 4 or 8 and not 1? One factor of 2 is needed because of assumed positivity of T1 and T2, for which the signal at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(k_y,k_z)$</math-renderer> and at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(-k_y,-k_z)$</math-renderer> has to be considered jointly. Another factor of 2 (per dimension) is needed because the entered <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y$</math-renderer> or <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_z$</math-renderer> values are allowed to be fractional.
In the case of a fractional value of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y$</math-renderer>, e.g. at <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$k_y=n+f$</math-renderer> with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$f\in [0,1)$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n$</math-renderer> an integer, part of the signal is assigned to the integer location <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n$</math-renderer> and another part to integer location <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n+1$</math-renderer>. To be precise, a fraction <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$\cos({\pi f}/{2})$</math-renderer> is assigned to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$\sin({\pi f}/{2})$</math-renderer> to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(n+1)$</math-renderer>. This implies that we have some, albeit minimalistic, multi-coil capacity in our system. The cos() and sin() functions have been chosen in order to make this “splitting” noise-neutral, since it preserves the total noise power.</p>
<p dir="auto">(R2)
: invregval: Although the actual reconstruction does not apply explicit regularization, the Analyzer assumes that it does. With the assumed default of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$200^{-2}$</math-renderer>, the Analyzer acts as if regularization would bias the reconstructed maps towards <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$(\rho,T_1,T_2)=(0,T_{1,ref},T_{2,ref})$</math-renderer>, by striving for a minimal squared error in the case that the SNR is around 200. In our case, “SNR” has to be seen as the expected value of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">${\sqrt{(1/N_{voxels})\sum_{voxels}(T_1(r)-T_{1,ref})^2}}/{\sigma_{T_1}}$</math-renderer>.
The parameter can also be used to indicate that a given parameter is “known”. E.g. by setting invregval to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$[10^{+6}.10^{+6},200^{-2}]$</math-renderer>, we indicate that  and T1 are known and that all data are assumed to be used to estimate T2.</p>
<p dir="auto">(R3)
: The current default of the T1T2set is set to
[(0.8183, 0.0509), (0.67, 0.2066), (1.2208, 0.1253), (0.2465, 0.0461), (2.2245, 0.3082), (0.3677, 0.0461), (0.3677, 0.1253)]</p>
<p dir="auto">(R4)
: The options sizeStep, portion_size, portion_step and opt_iterations_limit are Opimizer options. Following approach is used: in a first stage the Vector sizeStep is relevant; let it be <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$[n_1,n_2,n_3]$</math-renderer> as an example. In that first stage, the Optimizer internally runs a series of optimizations. The first one is to optimize the flip angle on <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n_1$</math-renderer> equidistant points, the other flip angles following by cubic-spline interpolation. Subsequently, the result is cubic-spline interpolated to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n_2$</math-renderer> equidistant points to act as a starting point on an optimization on <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$n_2$</math-renderer> points, etc. Once this is done, the result is used as a starting point for the second stage of optimizations (deprecated by now): the Optimizer will then optimize <em>individual</em> RF pulses. Since the optimization process cannot reasonably handle a large number (over 50 or so) of parameters simultaneously, it only addresses a portion of size portion_size at a time, taking all other RF pulses as fixed. Once such a portion is considered optimized, the portion advances by portion_step pulses. In some cases, this may result in sequences with pulses around 180 degrees, but not if a sar_limit has been imposed to e.g. 40 degrees RMS.
The total number of internal runs should therefore be</p>
<p dir="auto">length(sizeStep)+ceil(nTR/portion_step).</p>
<p dir="auto">This can be reduced by the option parameter opt_iterations_limit. When omitting the second stage (which is advised), the default opt_iterations_limit=length(sizeStep) is appropriate.</p>
<p dir="auto">(R5)
: Internal Optimizer options. Default is
Optim.Options(time_limit = 3000.0, iterations = 100000, f_tol=1.0e-2, g_tol = 1.0e-3)
The first two options are useful to stop the prevent “the optimizer being stuck, either by non-convergence or due to a parameter choice that would require ages to converge.
On f_tol and g_tol, the latest insights are that these should be set stricter in order to avoid grossly-suboptimal false minima. A value of around <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="e242cdc0389d416fb40d45f8bb042a62">$10^{-8}$</math-renderer> should be default.</p>
<p dir="auto">(R6)
: Valid values are:</p>
<ul dir="auto">
<li>"noise level" (not accounting for SAR or high flip angles),</li>
<li>"low-flip corrected noise" (penalty on the maximum flip angle in the sequence, on the assumption that, on a fixed TR, it will thereby reduce the sampling-time and consequently increase the noise by a certain factor),</li>
<li>"information content", "information content penalized" (immature – do not use),</li>
<li>(Legacy )"sar-limited noise" (a heavy penalty term is added if the root-mean-square of the RF pulses exceeds a limit). Deprecated. Instead, combine "noise level" with account_SAR=true</li>
</ul>
