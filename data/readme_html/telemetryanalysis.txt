<p dir="auto">This package defines an API to fetch and process telemetry packages from satellites.</p>
<p dir="auto">Notice that this package does not provide a complete set of functionalities by itself. The
user must add other packages that uses the API defined here to implement the required
functions.</p>

<p dir="auto">It must implement two functions as follows.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function TelemetryAnalysis._api_init_telemetry_source(::Type{T}, vargs...; kwargs...)::T"><pre><span class="pl-k">function</span> TelemetryAnalysis<span class="pl-k">.</span><span class="pl-en">_api_init_telemetry_source</span>(<span class="pl-k">::</span><span class="pl-c1">Type{T}</span>, vargs<span class="pl-k">...</span>; kwargs<span class="pl-k">...</span>)<span class="pl-k">::</span><span class="pl-c1">T</span></pre></div>
<p dir="auto">This function initializes the source of type <code>T</code>. The arguments and keywords can be selected
arbitrarily depending on the source's characteristic. The function must return an object of
type <code>T</code>.</p>
<p dir="auto">It is advisable to document the arguments and keywords by extending the documentation of the
object <code>init_telemetry_source</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function TelemetryAnalysis._api_get_telemetry(source::T, start_time::DateTime, end_time::DateTime)::Vector{TelemetryPacket}"><pre><span class="pl-k">function</span> TelemetryAnalysis<span class="pl-k">.</span><span class="pl-en">_api_get_telemetry</span>(source<span class="pl-k">::</span><span class="pl-c1">T</span>, start_time<span class="pl-k">::</span><span class="pl-c1">DateTime</span>, end_time<span class="pl-k">::</span><span class="pl-c1">DateTime</span>)<span class="pl-k">::</span><span class="pl-c1">Vector{TelemetryPacket}</span></pre></div>

It must return encapsulate each packet in a <code>TelemetryPacket</code> and return a

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Databases</h2><a id="user-content-databases" class="anchor" aria-label="Permalink: Databases" href="#databases"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A database must define three information:</p>
<ol dir="auto">
<li>How to get the timestamp from the telemetry packet;</li>
<li>How to unpack the telemetry packet into raw data; and</li>
<li>The variables inside the telemetry packet.</li>
</ol>
<p dir="auto">The database object is created by the function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="create_telemetry_database(label::String; kwargs...)"><pre><span class="pl-c1">create_telemetry_database</span>(label<span class="pl-k">::</span><span class="pl-c1">String</span>; kwargs<span class="pl-k">...</span>)</pre></div>
<p dir="auto">where <code>label</code> defined the database label. The available keywords are:</p>
<ul dir="auto">
<li>
<p dir="auto"><code>get_telemetry_timestamp::Function</code>: A function that must return the timestamp of a
telemetry packet. The API is:</p>
<p dir="auto"><code>get_telemetry_timestamp(tmpacket::TelemetryPacket)::DateTime</code></p>
<p dir="auto">(<strong>Default</strong> = <code>_default_get_telemetry_timestamp</code>)</p>
</li>
<li>
<p dir="auto"><code>unpack_telemetry::Function</code>: A function that must return a <code>AbstractVector{UInt8}</code> with
the telemetry frame unpacked, which will be passed to the transfer functions. If the frame
is not valid, it must return <code>nothing</code>. The function API must be:</p>
<p dir="auto"><code>unpack_telemetry(tmpacket::TelemetryPacket)::AbstractVector{UInt8}</code></p>
<p dir="auto">(<strong>Default</strong> = <code>_default_unpack_telemetry</code>)</p>
</li>
</ul>
<p dir="auto">After creating the database, the variables can be added using the function:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="add_variable!(database::TelemetryDatabase, label::Symbol, [position::Int, size::Int,] tf::Function; kwargs...)"><pre><span class="pl-c1">add_variable!</span>(database<span class="pl-k">::</span><span class="pl-c1">TelemetryDatabase</span>, label<span class="pl-k">::</span><span class="pl-c1">Symbol</span>, [position<span class="pl-k">::</span><span class="pl-c1">Int</span>, size<span class="pl-k">::</span><span class="pl-c1">Int</span>,] tf<span class="pl-k">::</span><span class="pl-c1">Function</span>; kwargs<span class="pl-k">...</span>)</pre></div>
<ul dir="auto">
<li><code>database::TelemetryDatabase</code>: Database.</li>
<li><code>label::Symbol</code>: Variable label in the database.</li>
<li><code>position::Int</code>: Variable position in the telemetry database.</li>
<li><code>size::Int</code>: Size of the variable.</li>
<li><code>btf::Function</code>: Bit transfer function. For more information, see section
<a href="@ref"><code>Bit transfer function</code></a>.</li>
<li><code>tf::Function</code>: Variable transfer function. For more information, see section
<a href="@ref"><code>Transfer function</code></a>.</li>
</ul>
<p dir="auto">!!! note
The <code>position</code> and <code>size</code> can be omitted if the variable is obtained only by the
processed values of other variables. In this case, the keyword <code>dependencies</code> must not
be <code>Nothing</code>.</p>
<p dir="auto">This function allows the following keywords:</p>
<ul dir="auto">
<li><code>alias::Union{Nothing, Symbol}</code>: An alias of the variable. In this case, the function
<a href="@ref"><code>get_variable_description</code></a> will also consider this alias when searching.
(<strong>Default</strong> = <code>nothing</code>)</li>
<li><code>default_view::Symbol</code>: Select the default view for this variable during processing. For
the list of available options, see <a href="@ref"><code>process_telemetry_packets</code></a>.
(<strong>Default</strong> = <code>:processed</code>)</li>
<li><code>dependencies::Union{Nothing, Vector{Symbol}}</code>: A vector containing a list of dependencies
required to obtain the processed value of this variable. If it is <code>nothing</code>, then the
variable does not have dependencies. (<strong>Default</strong> = <code>nothing</code>)</li>
<li><code>description::String</code>: A description about the variable.</li>
<li><code>endianess::Symbol</code>: <code>:littleendian</code> or <code>:bigendian</code> to indicate the endianess
of the variable. (<strong>Default</strong> = <code>:littleendian</code>)</li>
</ul>

<p dir="auto">The bit transfer function must have the following signature:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function btf(frame::AbstractVector{UInt8})::AbstractVector{UInt8}"><pre><span class="pl-k">function</span> <span class="pl-en">btf</span>(frame<span class="pl-k">::</span><span class="pl-c1">AbstractVector{UInt8}</span>)<span class="pl-k">::</span><span class="pl-c1">AbstractVector{UInt8}</span></pre></div>
<p dir="auto">Its purpose is to obtain the <code>frame</code> from the telemetry and process to the bits related to
the current telemetry variable. The <code>frame</code> is a set of bytes obtained from the variable
parameters <code>position</code>, <code>size</code>, and <code>endianess</code>.</p>

with the <code>btf</code> and process to a raw value. This value will be used in the transfer function
to obtain the variable processed data.</p>
