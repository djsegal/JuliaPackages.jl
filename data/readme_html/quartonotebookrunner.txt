<p dir="auto">This Julia package provides a code evaluation engine that Quarto
can use. Please run the <code>quarto</code> CLI tool rather than this package
directly unless you would like to help with the development of this engine.</p>
<p dir="auto">Starting from the <strong>pre-release</strong> <a href="https://github.com/quarto-dev/quarto-cli/releases/tag/v1.5.29"><code>v1.5.29</code></a>
this engine is available out-of-the-box with <code>quarto</code> when you set <code>engine: julia</code> in
your Quarto notebook files (setting it project-wide via <code>_quarto.yml</code> <a href="https://github.com/quarto-dev/quarto-cli/issues/3157" data-hovercard-type="issue" data-hovercard-url="/quarto-dev/quarto-cli/issues/3157/hovercard">is not yet supported</a>). You don't need to follow the developer instructions
below.</p>

<p dir="auto">Notebooks are run in isolated Julia processes. The first call to <code>run!</code> for each
notebook will start a new Julia process. Subsequent <code>run!</code>s will reuse the same
process for each notebook. The process will be closed when <code>close!</code> is called.</p>
<p dir="auto">Each <code>run!</code> of a notebook will evaluate code blocks in a new Julia <code>Module</code> so
that struct definitions and other global constants can be redefined between
runs. Non-constant globals are GC'd between runs to avoid memory leaks.</p>
<p dir="auto">Note that no caching is implemented, or any form of reactive evaluation.</p>

<p dir="auto">The <code>QuartoNotebookRunner</code> package is what users install themselves (or have
installed via <code>quarto</code>). This package manages the parsing of Quarto notebooks,
passing of parsed code blocks to the worker processes that run the code in
isolation, as well as communicating with the <code>quarto</code> process that requests the
rendering of a notebook.</p>
<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto"><code>QuartoNotebookWorker</code></h4><a id="user-content-quartonotebookworker" class="anchor" aria-label="Permalink: QuartoNotebookWorker" href="#quartonotebookworker"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <code>QuartoNotebookWorker</code> package, located at <code>src/QuartoNotebookWorker</code>, is a
"local" package that is loaded into every worker process that runs a notebook.
This worker package has no dependencies outside of the standard library.</p>
<p dir="auto">There are several external package dependencies that are used by this worker
package, but the code for them is vendored dynamically into the worker package,
rather than being added as external dependencies. This avoids a user potentially
running into conflicting versions of packages should they require a different
version.</p>
<p dir="auto">To debug issues within the worker package you can directly run a REPL with it
loaded rather than having to create a notebook and run code through it. Use the
following to import <code>QuartoNotebookWorker</code> in a REPL session:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; using QuartoNotebookRunner # Load the runner package.

julia&gt; QuartoNotebookRunner.WorkerSetup.debug() # Start a subprocess with the worker package loaded."><pre class="notranslate"><code>julia&gt; using QuartoNotebookRunner # Load the runner package.

julia&gt; QuartoNotebookRunner.WorkerSetup.debug() # Start a subprocess with the worker package loaded.
</code></pre></div>
<p dir="auto">A new Julia REPL will start <em>inside</em> of the current one.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; QuartoNotebookWorker.&lt;tab&gt; # Access the worker package."><pre class="notranslate"><code>julia&gt; QuartoNotebookWorker.&lt;tab&gt; # Access the worker package.
</code></pre></div>
<p dir="auto">Use <code>ctrl-d</code> (or <code>exit()</code>) to exit the worker REPL and return to the main REPL.</p>
<p dir="auto">If you have <code>Revise</code>, <code>TestEnv</code>, or <code>Debugger</code> available within your global
environment then those will be loaded into the interactive worker process as
well to aid in debugging. Editing code within the <code>src/QuartoNotebookWorker</code>
folder will reflect the changes in the REPL via <code>Revise</code> in the normal way.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Adding package "integrations"</h3><a id="user-content-adding-package-integrations" class="anchor" aria-label="Permalink: Adding package &quot;integrations&quot;" href="#adding-package-integrations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Some packages require custom integrations to be written to make them behave as
expected within the worker processes that run notebooks. For example, <code>Plots.jl</code>
requires a custom integration to work correctly with <code>quarto</code>'s image format and
dimension settings.</p>
<p dir="auto">This is achieved by using Julia's native package extension mechanism. You can
find all the current package integrations in the <code>src/QuartoNotebookWorker/ext</code>
folder. Typically this is done via adding function hooks within the <code>__init__</code>
method of the extension that run at different points during notebook execution.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Package Extensions</h3><a id="user-content-package-extensions" class="anchor" aria-label="Permalink: Package Extensions" href="#package-extensions"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">As discussed above <code>QuartoNotebookWorker</code> is implemented as a full Julia package
rather than just a <code>Module</code> loaded into the worker processes. This allows for
any package to extend the functionality provided by the worker. To do this make
use <code>Requires.jl</code> (or the mechanism that it leverages) to load extension code
that requires <code>QuartoNotebookWorker</code>.</p>

<p dir="auto">With this addition whenever <code>PackageName</code> is loaded into a <code>.qmd</code> file that is
being run with <code>engine: julia</code> the extension code in the <code>extension.jl</code> file
will be loaded. Below are the available interfaces that are can be extended.</p>

<p dir="auto">The <code>expand</code> function is used to inform <code>QuartoNotebookWorker</code> that a specific
Julia type should not be rendered and instead should be converted into a series
of notebook cells that are themselves evaluated and rendered. This allows for
notebooks to generate a dynamic number of cells based on runtime information
computed within the notebook rather than just the static cells of the original
notebook source.</p>
<p dir="auto">The below example shows how to create a <code>Replicate</code> type that will be expanded
into <code>n</code> cells of the same value.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import PackageName

<p dir="auto">The <code>Cell</code> type takes a value, which can be any Julia type. If it is a
<code>Function</code> then the result of the <code>Cell</code> will be the result of calling the
<code>value()</code>, including any printing to <code>stdout</code> and <code>stderr</code> that may occur during
the call. If it is any other type then the result of the <code>Cell</code> will be the
value itself.</p>

<p dir="auto">Optional <code>code</code> keyword allows fake source code for the cell to be set, which
will be rendered by <code>quarto</code>. Note that the source code is never parsed or
evaluated. Additionally the <code>options</code> keyword allows for defining cell options
that will be passed to <code>quarto</code> to control cell rendering such as captions,
layout, etc.</p>
