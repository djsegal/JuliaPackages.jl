<p dir="auto">The procedure for registering a new package is the same as for releasing a new version.
If the registration bot is not added to the repository, <code>@JuliaRegistrator</code> register will not result in package registration.</p>
<p dir="auto">Quick Summary:</p>
<ol dir="auto">
<li>Set the <code>(Julia)Project.toml</code> version field in your repository to your new desired <code>version</code>.</li>
<li>Comment <code>@JuliaRegistrator register()</code> on the commit/branch you want to register (e.g. like <a href="https://github.com/JuliaRegistries/Registrator.jl/issues/61#issuecomment-483486641" data-hovercard-type="issue" data-hovercard-url="/JuliaRegistries/Registrator.jl/issues/61/hovercard">here</a> or <a href="https://github.com/chakravala/Grassmann.jl/commit/3c3a92610ebc8885619f561fe988b0d985852fce#commitcomment-33233149">here</a>).</li>
<li>If something is incorrect, adjust, and redo step 1</li>
<li>If the automatic tests pass, but a moderator makes suggestions (e.g., manually updating your <code>(Julia)Project.toml</code> to include a [compat] section with version requirements for dependencies), then incorporate suggestions as you see fit into a new commit, and redo step 2 for the new commit. You don't need to do anything to close out the old request.</li>
<li>Finally, either rely on the <a href="https://github.com/marketplace/actions/julia-tagbot">TagBot GitHub Action</a> to tag and make a github release or alternatively tag the release manually.</li>
</ol>
