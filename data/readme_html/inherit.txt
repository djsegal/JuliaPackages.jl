<p dir="auto">Inherit.jl is used to inherit fields and interface definitions from a supertype. It supports programming with an <strong>object-oriented flavor</strong> in Julia, whenever this is more appropriate than developing under traditional Julia patterns.</p>
<p dir="auto"><strong>Fields</strong> defined in a supertype are automatically inherited by each subtype, and <strong>method declarations</strong> are checked for each subtype's implementation. An <strong>inheritance hierachy</strong> across multiple modules is supported. To accomplish this, macro processing is used to construct <strong>native Julia types</strong>, which allows the the full range of Julia syntax to be used in most situations.</p>

<p dir="auto">Use <code>@abstractbase</code> to declare an abstract supertype, and use <code>@implement</code> to inherit from such a type. Standard <code>struct</code> syntax is used.</p>

<p dir="auto">Note that the definition of <code>cost</code> function inside of <code>Fruit</code> is interpreted as an interface declaration; it does not result in a method being defined.</p>
<p dir="auto">!!! info
What this declaration means is that when invoking the <code>cost</code> function, passing an object which is a subtype of <code>Fruit</code> (declared with the <code>@implement</code> macro) to the <code>fruit::Fruit</code> parameter must be able to dispatch to some method instance. This is verified when a module is first loaded.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Interaction with modules</h1><a id="user-content-interaction-with-modules" class="anchor" aria-label="Permalink: Interaction with modules" href="#interaction-with-modules"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">An object oriented programming style can be useful to applications that span across multiple modules. Even though <strong>Inherit.jl</strong> can be used inside of scripts, its true usefulness is to assert <strong>common interfaces</strong> shared by different data types from different modules. <strong>Verification</strong> of method declarations take place in the <code>__init__()</code> function of the module which the implementing type belongs to (i.e. where the <code>@implement</code> macro is used).</p>

<p dir="auto">The specially named module-level (i.e. top-level) function <code>__init__()</code> is called after the module has been fully loaded by Julia. If an interface definition has not been met, an exception will be thrown.</p>

<p dir="auto">Upon loading module <code>M1</code>, Inherit.jl throws an <code>ImplementError</code> from the <code>__init__()</code> function, telling you that it's looking for a method signature that can dispatch <code>cost(::M1.Orange, ::Float64)</code>. <div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">The <code>@postinit</code> macro</h2><a id="user-content-the-postinit-macro" class="anchor" aria-label="Permalink: The @postinit macro" href="#the-postinit-macro"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The presence of an <code>@abstractbase</code> or <code>@implement</code> macro causes Inherit.jl to generate and <strong>overwrite</strong> the module's <code>__init__()</code> function. To execute your own module initialization code, the <code>@postinit</code> macro is available. It accepts a function as argument and registers that function to be executed after <code>__init__()</code>. Multiple occurrences of <code>@postinit</code> will result in each function being called successively.</p>

<p dir="auto">We can make a few observations regarding the above example:</p>
<ul dir="auto">
<li>A <strong>summary message</strong> is printed after each module is loaded, showing Inherit.jl is active.</li>
<li><strong>Multiple levels of inheritance</strong> is possible across multiple modules.</li>
<li>Method definitions <strong>are quite flexible</strong>. In a method declaration, you can name a supertype anywhere that's valid in Julia, and it will be checked for proper dispatch of subtypes.</li>
<li>The function <code>M1.cost</code> was <strong>automatically imported</strong> into module <code>M2</code>. The function still lives in module <code>M1</code> together with its method instances, but it is available in <code>M2</code> through the symbol <code>cost</code>.
<ul dir="auto">
<li>While not shown in this example, you can <strong>extend <code>M1.cost</code></strong> by writing <code>function cost(...) ... end</code> in module <code>M2</code></li>
</ul>
</li>
<li><strong>Docstrings are preserved</strong>. Docstring for method declarations are added to the end of any  method docstrings.</li>
</ul>
<p dir="auto">!!! info
When implementing a method declaration, supertypes inside of containers like (e.g. Pair, Vector, Dict) may not be substituted with a subtype, because Julia's type parameters are invariant. However, a ranged supertype parameter (prefixed with &lt;:) can be substituted with a ranged subtype.</p>

<p dir="auto">To have module <code>__init__()</code> log an error message instead of throwing an exception, add <code>setreportlevel(ShowMessage)</code> near the front of the module. You can also disable interface checking altogether with <code>setreportlevel(SkipInitCheck)</code></p>
<p dir="auto">By default, module <code>__init__()</code> writes its summary message at the <code>Info</code> log level. You can change this by setting <code>ENV["INHERIT_JL_SUMMARY_LEVEL"]</code> to one of <code>["debug", "info", "warn", "error", "none"]</code>.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Limitations</h1><a id="user-content-limitations" class="anchor" aria-label="Permalink: Limitations" href="#limitations"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Parametric types are currently not supported. Basic support for parametric concrete types is being planned.</p>
<p dir="auto">Methods are examined only for their positional arguments. Inherit.jl has no special knowledge of keyword arguments, but this may improve in the future.</p>
<p dir="auto">Inherit.jl has no special knowledge about constructors (inner or otherwise). They're treated like normal functions. As a result, constructor inheritance is not available.</p>
<p dir="auto">Short form function definitions such as <code>f() = nothing</code> are not supported for method declaration; use the long form <code>function f() end</code> instead. Using short form for method implementation can be problematic as well (e.g. when the function is imported from another module); it's generally safer to use long form.</p>
