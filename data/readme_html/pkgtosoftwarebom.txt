<p dir="auto">This package produces a Software Bill of Materials (SBOM) describing your Julia environment. At this time, the SBOM produced is in the (<a href="https://github.com/SamuraiAku/SPDX.jl">SPDX</a>) format.  Contributions to support other SBOM formats are welcome.</p>
<p dir="auto">I created PkgToSoftwareBOM.jl to help the Julia ecosystem get prepared for the emerging future of software supply chain security. If we want to see Julia adoption to continue to grow, then we need to be able to easily create SBOMs to supply to the organizations using Julia packages.</p>
<p dir="auto">PkgToSoftwareBOM interfaces with the standard library Pkg to fill in the SBOM data fields. Information filled out today includes:</p>
<ul dir="auto">
<li>A complete package dependency list including
<ul dir="auto">
<li>versions in use</li>
<li>where the package can be downloaded from</li>
<li>SPDX verification code</li>
<li>determines the declared license and scans all source files for additional licenses present</li>
</ul>
</li>
<li>A complete artifact list
<ul dir="auto">
<li>artifact version resolved to the target platform
<ul dir="auto">
<li>target platform may be changed by an advanced user</li>
</ul>
</li>
<li>where the artifact can be downloaded from</li>
<li>download checksum</li>
<li>determines the declared license and scans all source files for additional licenses present</li>
</ul>
</li>
</ul>
<p dir="auto">Future versions may be able to fill in additional fields including copyright text.</p>
<p dir="auto">PkgToSoftwareBOM defaults to using the General registry but can use other registries and even mutiple registries as the source(s) of package information.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is an SBOM?</h2><a id="user-content-what-is-an-sbom" class="anchor" aria-label="Permalink: What is an SBOM?" href="#what-is-an-sbom"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">An SBOM is a formal, machine-readable inventory of software components and dependencies, information about those components, and their hierarchical relationships. These inventories should be comprehensive – or should explicitly state where they could not be. SBOMs may include open source or proprietary software and can be widely available or access-restricted.</p>
<p dir="auto">For a further information about SBOMs, their importance and how they can be used please see the Software Bill of Materials website maintained by the <a href="https://ntia.gov/page/software-bill-materials" rel="nofollow">National Telecommuications and Information Administration</a></p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Why do you care about SBOMs?</h2><a id="user-content-why-do-you-care-about-sboms" class="anchor" aria-label="Permalink: Why do you care about SBOMs?" href="#why-do-you-care-about-sboms"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">SBOMs are an important component of developing software security practices. US Presidential Executive Order <a href="https://www.whitehouse.gov/briefing-room/presidential-actions/2021/05/12/executive-order-on-improving-the-nations-cybersecurity/" rel="nofollow">EO 14028</a> established SBOMs as one method by which the federal government will establish the provenence of software in use. Commercial organizations are also using SBOMs for the same reason.</p>

<p dir="auto">PkgToSofwareBOM automatically exports the package <a href="https://github.com/SamuraiAku/SPDX.jl">SPDX</a> which defines the SBOM datatypes and functions for reading and writing. Please see the <code>SPDX</code> documentation for full documentation.</p>
<p dir="auto">There are two use cases envisioned:</p>
<ul dir="auto">
<li>Users: Create an SBOM of your current environment. Submit this file to your organization</li>

<p dir="auto">A developer SBOM will contain information that PkgToSoftwareBOM cannot determine on its own, such as the package's license and the developer's name. To add this information to the SBOM requires calling generateSPDX() with non-default parameters.</p>
<p dir="auto">The first thing a developer must determine is the name of their SBOM file. The reason is that PkgToSoftwareBOM computes a checksum of your source code and saves it in the SBOM file. Since the SBOM is included in the package's source tree PkgToSoftwareBOM must know what the file's name is so that it (and others who wish to re-compute the checksum themselves) can skip the file during the calculation. A suggested format for the SBOM filename is <code>MyPackageName.spdx.json</code></p>
<p dir="auto">By default, PkgToSoftwareBOM will exclude the <code>.git</code> folder in your package development directory from the checksum calcuclation. PkgToSoftwareBOM does not process the directions of `.gitignore' files nor does it ignore untracked files. It is recommended that you make sure to commit all your code and restore the repo to a pristine state before running PkgToSoftwareBOM</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Use a package server as the DownloadLocation</h3><a id="user-content-use-a-package-server-as-the-downloadlocation" class="anchor" aria-label="Permalink: Use a package server as the DownloadLocation" href="#use-a-package-server-as-the-downloadlocation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The package developer's GitHub (or other) repository is the canonical source for the package code. By default, this repository is used to populate the field DownloadLocation in each package description.</p>
<p dir="auto">But in everyday use, very few people actually download from there. Instead Pkg defaults to using the package server maintained by JuliaLang (<a href="https://pkg.julialang.org" rel="nofollow">https://pkg.julialang.org</a>) or another package server specified by <code>ENV["JULIA_PKG_SERVER"]</code>. A package server maintains compressed tarballs of released source code for packages tracked by a registry. So you can argue that the SBOM should reflect that in the name of accuracy.</p>
<p dir="auto">Also not every analyst would find it useful to be directed to the repo and then be expected to figure out how to use git to extract the correct version. A straight download location could be easier for them.</p>
<p dir="auto">The user can change the DownloadLocation to the package server through the use of the keyword <code>use_packageserver</code> when creating a spdxCreationData object (see example below)</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="spdxCreationData(use_packageserver= true)"><pre><span class="pl-c1">spdxCreationData</span>(use_packageserver<span class="pl-k">=</span> <span class="pl-c1">true</span>)</pre></div>
<p dir="auto">When this keyword is used, PkgToSoftwareBOM will determine if each package has a valid package server URL and use it if available. If the JuliaLang package server is used, then the package Supplier field will be updated to reflect that.</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Organization:  JuliaLang  ()"><pre class="notranslate"><code>Organization:  JuliaLang  ()
</code></pre></div>
<p dir="auto">If a valid package server URL cannot be determined, then the repository link will be used.</p>
<p dir="auto">In all cases, the repository URL is documented in the HomePage field of the package description.</p>

<p dir="auto">In the general case, it is impossible to find the source code of an artifact solely from the Julia package it is used in.</p>
<p dir="auto">However probably the majority of artifacts in use today are wrapped inside Julia Linked Library (JLL) packages generated by <a href="https://github.com/JuliaPackaging/BinaryBuilder.jl">BinaryBuilder.jl</a>. This tool builds the artifacts using <a href="https://github.com/JuliaPackaging/Yggdrasil">Yggdrasil</a> the Julia community build tree. BinaryBuilder then wraps the artifact inside an autogenerated Julia Linked Library (JLL) package.  That registered package contains known sentence patterns and hyperlinks in its README back to the branch in Yggdrasil that generated the artifacts. PkgToSoftwareBOM can extract this information from the README and create an entry in the SBOM showing that the artifact was GENERATED_FROM Yggdrasil.</p>
<p dir="auto">The user can optionally invoke this capability through the use of the keyword <code>find_artifactsource</code> when creating a spdxCreationData object (see example below)</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="spdxCreationData(find_artifactsource= true)"><pre><span class="pl-c1">spdxCreationData</span>(find_artifactsource<span class="pl-k">=</span> <span class="pl-c1">true</span>)</pre></div>
<p dir="auto">If PkgToSoftwareBOM cannot determine the source of an artifact, an entry will not be created.</p>

<p dir="auto">The majority of users and developers only ever use the General registry and that is what PkgToSoftwareBOM defaults to to find package information.</p>
<p dir="auto">If you would like to use a different registry or search multiple registries, you just call <code>generateSPDX</code> with two arguments.</p>
<p dir="auto">For example to create a User Environment SBOM using the General registry and another registry called "PrivateRegistry", type:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="sbom= generateSPDX(spdxCreationData(), [&quot;PrivateRegistry&quot;, &quot;General&quot;]);"><pre>sbom<span class="pl-k">=</span> <span class="pl-c1">generateSPDX</span>(<span class="pl-c1">spdxCreationData</span>(), [<span class="pl-s"><span class="pl-pds">"</span>PrivateRegistry<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>General<span class="pl-pds">"</span></span>]);</pre></div>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">How does PkgToSoftwareBOM determine what the license of the package or artifact is?</h2><a id="user-content-how-does-pkgtosoftwarebom-determine-what-the-license-of-the-package-or-artifact-is" class="anchor" aria-label="Permalink: How does PkgToSoftwareBOM determine what the license of the package or artifact is?" href="#how-does-pkgtosoftwarebom-determine-what-the-license-of-the-package-or-artifact-is"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">PkgToSoftwareBOM scans the entire julia package or artifact for license information.  If the scanning locates a file containing a recognized software license, the license is recorded in the <code>LicenseInfoFromFiles</code> property of the SBOM package description but does not record which file(s) the license was found in. The license scan follows these rules (LicenseCheck.jl, version 0.2.2)</p>
<ul dir="auto">
<li>All plaintext files less than 450 KB are scanned</li>
</ul>
<p dir="auto">During that search PkgToSoftwareBOM looks for an overall package license in the following locations:</p>
<ul dir="auto">
<li>For Julia packages, in the package root directory</li>
<li>For artifacts, in the root directory and in the directory <code>share/licenses</code></li>
</ul>
<p dir="auto">If files with a valid license are found in the expected location, PkgToSoftwareBOM declares the file where the license takes up the greatest percentage of the total file to be the package license, as you would expect a package license to contain only the license text and nothing else.</p>

<p dir="auto">Advanced users may wish to create an SBOM in which the artifacts are targeted to a different platform than the one that PkgToSoftwareBOM is running on.  For example, create an SBOM for an x86 linux installation from an M1 Macbook.</p>
<p dir="auto">To do this, the user must first create a platform object describing the target platform.  For example, to create a platform object for the hardware you are currently running on:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Base.BinaryPlatforms
myplatform= HostPlatform()"><pre><span class="pl-k">using</span> Base<span class="pl-k">.</span>BinaryPlatforms
myplatform<span class="pl-k">=</span> <span class="pl-c1">HostPlatform</span>()</pre></div>
<p dir="auto">Creating a platform object for other hardware is left as an exercise for the advanced user.</p>
