<p dir="auto"><a href="https://github.com/jw3126/ONNXRunTime.jl">ONNXRunTime</a> provides inofficial <a href="https://github.com/JuliaLang/julia">julia</a> bindings for <a href="https://github.com/microsoft/onnxruntime">onnxruntime</a>.
It exposes both a low level interface, that mirrors the official <a href="https://github.com/microsoft/onnxruntime/blob/v1.8.1/include/onnxruntime/core/session/onnxruntime_c_api.h#L347">C-API</a>, as well as an high level interface.</p>
<p dir="auto">Contributions are welcome.</p>

<p dir="auto">Memory allocated by a model is eventually automatically released after
it goes out of scope, when the model object is deleted by the garbage
collector. It can also be immediately released with <code>release(model)</code>.</p>
<p dir="auto">The low level API mirrors the offical <a href="https://github.com/microsoft/onnxruntime/blob/v1.8.1/include/onnxruntime/core/session/onnxruntime_c_api.h#L347">C-API</a>. The above example looks like this:</p>

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Breaking Changes in version 0.4.</h1><a id="user-content-breaking-changes-in-version-04" class="anchor" aria-label="Permalink: Breaking Changes in version 0.4." href="#breaking-changes-in-version-04"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">Support for CUDA.jl is changed from version 3 to versions 4 and 5.</p>
</li>
<li>
<p dir="auto">Support for Julia versions less than 1.9 is dropped. The reason for
this is to switch the conditional support of GPUs from being based
on the Requires package to being a package extension. As a
consequence the ONNXRunTime GPU support can now be precompiled and
the CUDA.jl versions can be properly controlled via Compat.</p>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Setting the CUDA Runtime Version in Tests</h1><a id="user-content-setting-the-cuda-runtime-version-in-tests" class="anchor" aria-label="Permalink: Setting the CUDA Runtime Version in Tests" href="#setting-the-cuda-runtime-version-in-tests"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For GPU tests using ONNXRunTime, naturally the tests must depend on
and import CUDA and cuDNN. Additionally a supported CUDA runtime
version needs to be used, which can be somewhat tricky to set up for
the tests.</p>
<p dir="auto">First some background. What <code>CUDA.set_runtime_version!(v"11.8")</code>
effectively does is to</p>
<ol dir="auto">
<li>Add a <code>LocalPreferences.toml</code> file containing</li>
</ol>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="[CUDA_Runtime_jll]
version = &quot;11.8&quot;"><pre class="notranslate"><code>[CUDA_Runtime_jll]
version = "11.8"
</code></pre></div>
<ol start="2" dir="auto">
<li>In <code>Project.toml</code>, add</li>
</ol>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="[extras]
CUDA_Runtime_jll = &quot;76a88914-d11a-5bdc-97e0-2f5a05c973a2&quot;"><pre class="notranslate"><code>[extras]
CUDA_Runtime_jll = "76a88914-d11a-5bdc-97e0-2f5a05c973a2"
</code></pre></div>
<p dir="auto">If your test environment is defined by a <code>test</code> target in the top
<code>Project.toml</code> you need to</p>
<ol dir="auto">
<li>
<p dir="auto">Add a <code>LocalPreferences.toml</code> in your top directory with the same
contents as above.</p>
</li>
<li>
<p dir="auto">Add <code>CUDA_Runtime_jll</code> to the <code>extras</code> section of <code>Project.toml</code>.</p>
</li>
<li>
<p dir="auto">Add <code>CUDA_Runtime_jll</code> to the <code>test</code> target of <code>Project.toml</code>.</p>
</li>
</ol>
<p dir="auto">If your test environment is defined by a <code>Project.toml</code> in the <code>test</code>
directory, you instead need to</p>
<ol dir="auto">
<li>
<p dir="auto">Add a <code>test/LocalPreferences.toml</code> file with the same contents as
above.</p>
</li>
<li>
<p dir="auto">Add <code>CUDA_Runtime_jll</code> to the <code>extras</code> section of <code>test/Project.toml</code>.</p>
</li>
</ol>
