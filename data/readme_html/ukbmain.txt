<p dir="auto">This package aims at providing various command line interfaces to manipulate a UKB main dataset in order to generate <code>phenotypes</code>, <code>confounders</code>, <code>covariates</code> and <code>treatments</code> files. The specification of this process is done via a YAML configuration file for which a base is provided in <code>config/config.yaml</code>.</p>
<p dir="auto">The associated docker image, hosted on <a href="https://hub.docker.com/r/olivierlabayle/ukbmain" rel="nofollow">Docker Hub</a>, provides an environment to run all of the commands described below.</p>

<p dir="auto">The data in a UKB main dataset is organised in fields. The fields themselves may not represent a specific trait but a list of traits organised in array and/or instances (see the <a href="https://biobank.ndph.ox.ac.uk/~bbdatan/Accessing_UKB_data_v2.3.pdf" rel="nofollow">Accessing data guide</a>). An example configuration file corresponding to the traits reported by the <a href="http://geneatlas.roslin.ed.ac.uk/" rel="nofollow">gene ATLAS</a> is provided in <code>config/config.yaml</code> and if you want to run a generic PheWAS it may simply be used as it is.</p>
<p dir="auto">This YAML file contains up to 5 main entries:</p>
<ul dir="auto">
<li>phenotypes</li>
<li>confounders</li>
<li>covariates</li>
<li>treatments</li>
<li>subset</li>
</ul>
<p dir="auto">Each entry is further organised as a list of traits of interest. Depending on their data type, the traits can be queried in any of the following ways:</p>
<ul dir="auto">
<li>Continuous and Integer variables: Those can be queried by providing the associated UKB field-id. This can be done either as a single field or list of fields to make the file more readable. The optional "field" keyword can be used. Only the first column (<code>-0.0</code>) of the field, usually corresponding to the first assessment visit, is used.</li>
<li>Categorical variables: The behavior is different depending on the field and output file:
<ul dir="auto">
<li>Disease fields 40006, 20002, 41202, 41204: The keyword <code>field</code> must be used. Those variables are encoded by the UKB as lists and will be converted to binary variables indicating the presence/absence of a specific trait. When encoded by ICD10 codes, those traits can be defined either by the exact code or by parent codes or blocks. For instance the code <code>A010</code> represents Typhoid Fever while the code <code>A01</code> represents Typhoid and paratyphoid fevers. Further <code>A01-A03</code> represents either Typhoid and paratyphoid fevers, Other Salmonella infections or Shigellosis. Further definition of aggregated diseases can be defined by the keywords <code>any</code> and <code>name</code> where <code>any</code> is a list of codes and <code>name</code> is the name of the aggregate. Finally, we also provide the ability to consider the union of fields themselves, as long as they are encoded in the same way (for instance 41202, 41204) to define trait with the "FIELD_1 | FIELD_2 | ..." pattern.</li>
<li>Other categorical variables: Only the first column (<code>-0.0</code>) is used and will be one hot encoded (except for extra treatments). If no codings are specified, all codes will be extracted, otherwise only those specified will be extracted.</li>
<li>Categorical variables for treatments: Values are simply extracted per the given codes (or all codes if none is provided).</li>
</ul>
</li>
<li>Ordinal variables: Some traits are declared as categorical by the UKB but an ordinal interpretation may be more appropriate. We have identified and hardcoded a list of such traits in the <code>ORDINAL_FIELDS</code> constant.</li>
</ul>
<p dir="auto">For further examples, look into the <code>test/config</code> folder.</p>
