<p dir="auto"><code>FluxMLBenchmarks</code> is a benchmarking tool designed for FluxML community, which allows for the creation of different benchmarking environments by installing different sets of dependencies and comparing the results.</p>

<p dir="auto">The performance of a package need measured under the condition that other packages and tools remain constant. However, in the case of mutual influence between <strong>multiple packages of different versions</strong>, <strong>2 sets of dependencies</strong> need to be provided simultaneously. As for this scenario, you can use <code>--baseline</code> and <code>--target</code> as well:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; BASELINE=&lt;Dependency Representation A1 of baseline&gt;,&lt;Dependency Representation B1 of baseline&gt;,&lt;Dependency Representation C1... of baseline&gt;

<p dir="auto">Sometimes we need to run benchmarks for multiple sets of dependencies simultaneously. To meet this benchmarking requirements, you can use <code>--deps-list</code>:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; DEPS_LIST=&lt;Dependencies List&gt;
&gt; julia --project=benchmark benchmark/runbenchmarks.jl --cli --deps-list=$DEPS_LIST"><pre><span class="pl-k">&gt;</span> DEPS_LIST=<span class="pl-k">&lt;</span>Dependencies List<span class="pl-k">&gt;</span>
<span class="pl-k">&gt;</span> julia --project=benchmark benchmark/runbenchmarks.jl --cli --deps-list=<span class="pl-smi">$DEPS_LIST</span></pre></div>
<p dir="auto">For specification, <code>Dependencies List</code> is a single string that simulates an array, with each element separated by a semicolon. Each element adheres to the format of <code>Dependency Representation</code>. However, <strong>Unlike the previous output <code>result-baseline.json</code> and <code>result-target.json</code>, the output format for this feature is <code>result-1.json</code>, <code>result-2.json</code>, <code>result-n.json</code>...</strong></p>
<p dir="auto">e.g.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; DEPS_LIST=&quot;NNlib,Flux;https://github.com/FluxML/NNlib.jl#backports-0.8.21,Flux;https://github.com/skyleaworlder/NNlib.jl#backports-0.8.21,Flux@0.13.12&quot;
&gt; julia --project=benchmark benchmark/runbenchmarks.jl --cli --deps-list=$DEPS_LIST"><pre><span class="pl-k">&gt;</span> DEPS_LIST=<span class="pl-s"><span class="pl-pds">"</span>NNlib,Flux;https://github.com/FluxML/NNlib.jl#backports-0.8.21,Flux;https://github.com/skyleaworlder/NNlib.jl#backports-0.8.21,Flux@0.13.12<span class="pl-pds">"</span></span>

<p dir="auto">Each argument represents an operation this tool will perform. The corresponding relationship is:</p>
<ul dir="auto">
<li><code>--pr</code>: "benchmark/script/runbenchmarks-pr.jl" You can specify <code>--target</code> <code>--baseline</code> <code>--enable</code> <code>--disable</code></li>
<li><code>--cli</code>: "benchmark/script/runbenchmarks-cli.jl" You can specify <code>--deps-list</code> <code>--enable</code> <code>--disable</code></li>
<li>(<strong>Not recommended, used by GitHub Actions</strong>) <code>--cache-setup</code>: "benchmark/script/cachesetup-cli.jl" You can specify <code>--target</code> <code>--baseline</code></li>
<li>(<strong>Not recommended, used by GitHub Actions</strong>) <code>--merge-reports</code>: "benchmark/script/mergereports-cli.jl" You can specify <code>--target</code> <code>--baseline</code> <code>--push-result</code> <code>--push-username</code> <code>--push-useremail</code> <code>--push-password</code></li>
</ul>

<p dir="auto">Benchmarking always takes amount of time. In order to focus on the targets and reduce the time consumption of our benchmarking tool, the <code>--enable</code> and <code>--disable</code> options are used to specify <strong>the parts to be included</strong> and <strong>the parts to be excluded</strong> respectively.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; julia --project=benchmark benchmark/runbenchmarks.jl --cli  \
&gt;   --enable=&lt;ENABLED_PARTS&gt; \
&gt;   --disable=&lt;DISABLED_PARTS&gt; \
&gt;   --deps-list=&lt;Dependencies List&gt;"><pre><span class="pl-k">&gt;</span> julia --project=benchmark benchmark/runbenchmarks.jl --cli  \
<span class="pl-k">&gt;</span>   --enable=<span class="pl-k">&lt;</span>ENABLED_PARTS<span class="pl-k">&gt;</span> \
<span class="pl-k">&gt;</span>   --disable=<span class="pl-k">&lt;</span>DISABLED_PARTS<span class="pl-k">&gt;</span> \
<span class="pl-k">&gt;</span>   --deps-list=<span class="pl-k">&lt;</span>Dependencies List<span class="pl-k">&gt;</span></pre></div>
<p dir="auto">For specification, <code>Enabled Parts</code> and <code>Disabled Parts</code> have the same format, which is a single string that simulates an array, with each element separated by a semicolon.</p>
<p dir="auto"><code>--enable</code> is used to specify the files that should be included, and by default (<code>--enable</code> not specified) all files in the <code>benchmark/benchmark</code> are included. <code>--disable</code> is used to specify the files that should be excluded, and the default value is an empty string.</p>
<p dir="auto">More precisely, the granularity of the element of <code>Enabled Parts</code> and <code>Disabled Parts</code> is currently at the file-level, and supports two levels of files, which means that now <strong>our tool will recognize the name of each file in <code>benchmark/benchmark</code> and all the files under <code>benchmark/benchmark/**</code> before benchmarking</strong>.</p>
<p dir="auto"><strong>Each top-level element in <code>Enabled Parts</code> and <code>Disable Parts</code> should be exactly the name of the file under <code>benchmark/benchmark</code>; each second-level element should be the name of the file under the dir that has the same name of top-level file</strong>.</p>
<blockquote>
<p dir="auto">I don't recommend using <code>--enable</code> and <code>--disable</code> at the same time. But if you do, <code>--disable</code> takes priority over <code>--enable</code>.</p>
<p dir="auto">e.g. if <code>--enable</code> is set "flux,nnlib" while <code>--disable</code> is set "nnlib", only benchmarks in "benchmark/benchmark/flux.jl" will be executed.</p>
</blockquote>
