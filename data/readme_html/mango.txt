<p dir="auto">Mango.jl allows the user to create simple agents with little effort and in the same time offers options to structure agents with complex behaviour.</p>
<p dir="auto">The agents agents can run in two different ways: in <strong>real-time</strong>, or <strong>simulated</strong>. In real-time, the agents will run as fast as possible and communicate as specified by the protocol ("they run as developed"). In the simulation mode, the agent system and their specified tasks will be scheduled and stepped (continous or discrete) and the communication will be simulated using articial delays. One big unique characteristic of Mango.jl is that both ways use the same agent-api, meaning you can develop, evaluate your agent system in a controlled simulated environment and then transfer it to a real-time setting without (majorly) changing the implementation of your agents, as both execution ways use the same API with different environments (and containers).</p>
<p dir="auto"><strong>Note:</strong> <em>This project is still in an early development stage.
We appreciate constructive feedback and suggestions for improvement.</em></p>

<ul dir="auto">
<li>Container mechanism to speedup local message exchange</li>
<li>Structuring complex agents with loose coupling and agent roles</li>
<li>Built-in codecs</li>
<li>Supports communication between agents directly via TCP and MQTT</li>
<li>Built-in tasks mechanisms for proactive agent actions</li>
<li>Continous and discrete stepping simulation using an external clock to rapidly run and inspect simulations designed for longer time-spans
<ul dir="auto">
<li>Integrated communication and task simulation modules</li>
<li>Integrated environment with which the agents can interact in a common space</li>
</ul>
</li>
</ul>

<p dir="auto">The following simple showcase demonstrates how you can define agents in Mango. Jl, assign them to containers and send messages via a TCP connection. For more information on the specifics and other features (e.g. MQTT, modular agent using roles, simulation, tasks), please have a look at our <a href="https://offis-dai.github.io/Mango.jl/stable" rel="nofollow">Documentation</a>!</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Mango

# Create the container instances with TCP protocol
container = create_tcp_container(&quot;127.0.0.1&quot;, 5555)
container2 = create_tcp_container(&quot;127.0.0.1&quot;, 5556)

# An agent in `Mango.jl` is a struct defined with the `@agent` macro.
# We define a `TCPPingPongAgent` that has an internal counter for incoming messages.
@agent struct TCPPingPongAgent
    counter::Int
end

# Create instances of ping pong agents
ping_agent = TCPPingPongAgent(0)
pong_agent = TCPPingPongAgent(0)

# register each agent to a container and give them a name
register(container, ping_agent, &quot;Agent_1&quot;)
register(container2, pong_agent, &quot;Agent_2&quot;)

# When an incoming message is addressed at an agent, its container will call the `handle_message` function for it. 
# Using Julias multiple dispatch, we can define a new `handle_message` method for our agent.
function Mango.handle_message(agent::TCPPingPongAgent, message::Any, meta::Any)
    agent.counter += 1

    println(
        &quot;$(agent.aid) got a message: $message.&quot; *
        &quot;This is message number: $(agent.counter) for me!&quot;
    )

    # doing very important work
    sleep(0.5)

    if message == &quot;Ping&quot;
        reply_to(agent, &quot;Pong&quot;, meta)
    elseif message == &quot;Pong&quot;
        reply_to(agent, &quot;Ping&quot;, meta)
    end
end

# With all this in place, we can send a message to the first agent to start the repeated message exchange.
# To do this, we need to start the containers so they listen to incoming messages and send the initating message.
# The best way to start the container message loops and ensure they are correctly shut down in the end is the
# `activate(containers)` function.
activate([container, container2]) do
    send_message(ping_agent, &quot;Ping&quot;, address(pong_agent))

    # wait for 5 messages to have been sent
    while ping_agent.counter &lt; 5
        sleep(1)
    end
