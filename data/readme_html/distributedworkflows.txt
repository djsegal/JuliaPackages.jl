<li>
<p dir="auto">DistributedWorkflows.jl requires the package manager Spack to install necessary binaries. Follow the steps from <a href="https://spack.readthedocs.io/en/latest/getting_started.html" rel="nofollow">Spack - Getting Started</a> to install Spack. You might also want to read <a href="https://spack.readthedocs.io/en/latest/basic_usage.html" rel="nofollow">Spack - Basic Usage</a> to learn basic usage of Spack.</p>
<blockquote>
<hr>
<p dir="auto"><strong>Note:</strong></p>
<p dir="auto">If you already have Spack installed and sourced in your path, then you may skip the above step.</p>

<p dir="auto"><em>OR</em></p>
<p dir="auto">Download the binary file specific to your operating system from one of the links below:</p>

</li>
<li>
<p dir="auto">Once the installation is complete, navigate to the directory where you saved your binary file and install it in a target location of your choice as follows:</p>

</blockquote>
<blockquote>
<hr>

<p dir="auto">You are free to choose any other target location besides <code>zeda</code>.</p>

<p dir="auto">If the installation was successful, then running the following should load the required dependencies of <code>DistributedWorkflows.jl</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">How to use DistributedWorkflows.jl</h2><a id="user-content-how-to-use-distributedworkflowsjl" class="anchor" aria-label="Permalink: How to use DistributedWorkflows.jl" href="#how-to-use-distributedworkflowsjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To use <code>DistributedWorkflows</code> to parallelise an application, the following steps are required:</p>
<ol dir="auto">
<li>Setting up your Julia application structure. </li>
<li>Designing a workflow in the form of a Petri net.</li>
<li>A serializer descriptor. If you are using Julia's default serializer then you can skip this step.</li>
<li>Setting up the workflow launcher.</li>
<li>Compile and execute.</li>
</ol>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">A Simple Example</h3><a id="user-content-a-simple-example" class="anchor" aria-label="Permalink: A Simple Example" href="#a-simple-example"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">With the following example, we demonstrate the usage with a simple "Hello World" example.</p>
<p dir="auto">Assuming that we use Julia's native serializer, let's say we have the following Julia code to run:</p>

<p dir="auto">It could be stored in a file, say <code>hello.jl</code>. Based on this piece of code we can see that the workflow is a Petri net with 2 input places, 1 transition, and 2 output places.</p>
<p dir="auto">The Petri net can now be constructed as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# A Petri net with 2 input places and 2 output places

p2 = place(&quot;input_file2&quot;)
p3 = place(&quot;output_file1&quot;)

<p dir="auto">When working within an environment like IJulia or Pluto, it is possible to visualise the workflow before generating the XML format of it by running <code>show_workflow(pn)</code>.
It is also possible to generate a rendering and store it to disk by running <code>savefig(pn)</code>.
This call would save the workflow as a PNG in a default location.
The output for both methods would look like the image below:</p>
<p dir="auto"><a target="_blank" rel="noopener noreferrer" href="examples/images/hello_julia.png"><img src="examples/images/hello_julia.png" alt="hello_julia_net" style="max-width: 100%;"></a></p>
<p dir="auto">To visualise the workflow in one of the other formats and a specific path use <code>savefig(pnet::PetriNet, format::Symbol, path::String)</code>. For example, <code>savefig(pn, :svg, "home/usr/zeda/net")</code> generates an SVG of the above Petri net and stores it in the path <code>home/usr/zeda/net</code>.</p>
<blockquote>
<hr>
<p dir="auto"><strong>Warning:</strong></p>
<p dir="auto">The renderer works best if you have graphviz installed on your system. For Ubuntu 22 you can do <code>apt install graphviz</code> to install it.</p>
<hr>
</blockquote>
<blockquote>
<hr>
<p dir="auto"><strong>Note:</strong></p>
<p dir="auto">The number of transitions coincide with the number of Julia methods to execute. Each input/output token corresponds to a string containing the file name where data is stored.</p>

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="client(&lt;number-of-workers&gt;, &quot;/path/to/nodefile&quot;, &quot;rif-strategy&quot;)"><pre><span class="pl-c1">client</span>(<span class="pl-k">&lt;</span>number<span class="pl-k">-</span>of<span class="pl-k">-</span>workers<span class="pl-k">&gt;</span>, <span class="pl-s"><span class="pl-pds">"</span>/path/to/nodefile<span class="pl-pds">"</span></span>, <span class="pl-s"><span class="pl-pds">"</span>rif-strategy<span class="pl-pds">"</span></span>)</pre></div>

<ul dir="auto">
<li>Serializer agnostic, for details see <a href="docs/src/Serialization/custom_serializer.md">custom serialize</a> section in the documentation.</li>
<li>Reduced complexity in deploying your parallel application.</li>
<li>Localised testing of workflow, before launching expensive cluster resources.</li>
<li>Write your own <code>xpnet</code> file and compile your workflow using the <code>compile_workflow()</code> function.</li>
<li>You could also, generate a Petri net in Julia using <code>PetriNet()</code> and generate the <code>xpnet</code> file from the Petri net using <code>generate_workflow()</code> before compiling it.</li>
<li>Visualise Petri net within the Julia REPL in multiple formats.</li>
</ul>
