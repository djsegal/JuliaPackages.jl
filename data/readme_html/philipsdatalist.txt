<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto"><code>read_data_list(path::String)</code></h4><a id="user-content-read_data_listpathstring" class="anchor" aria-label="Permalink: read_data_list(path::String)" href="#read_data_listpathstring"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>This function reads samples from the .data file. There are a limited number of <em>complex data vector types</em> (e.g. <code>STD</code>, <code>NOI</code>). For each type, the samples are stored separately in a <code>Vector{ComplexF32}</code>. The vectors with samples are stored together in a <code>NamedTuple</code> with fieldnames corresponding to the different types (e.g. <code>STD</code>, <code>NOI</code>).</li>
<li>The general scan information is extracted from the .list file and stored as <code>info::Vector{String}</code>.</li>
<li>The <code>attributes</code> of each of the <em>complex data vectors</em> is extracted from the .list file. For each <em>complex data vector type</em> the attributes are stored in a <code>DataFrame</code> and the <code>DataFrames</code> are stored in a <code>NamedTuple</code>.</li>
<li>The function returns <code>samples_per_type</code>, <code>attributes_per_type</code> and <code>info</code>.</li>
</ul>
<p dir="auto">This package only really <em>reads</em> the .{data,list} files and it does not <em>process</em> (e.g. sort) the data.</p>
<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto"><code>data_list_to_kspace(path::String)</code></h4><a id="user-content-data_list_to_kspacepathstring" class="anchor" aria-label="Permalink: data_list_to_kspace(path::String)" href="#data_list_to_kspacepathstring"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>This function reads in the .{data,list} files using <code>read_data_list</code> and then it sorts the samples of type <code>STD</code> into a k-space.</li>
<li>The k-space has named dimensions. The dimension names are found in <code>DIMENSIONS_STD</code>. By default, dimensions of size 1 are dropped.</li>
<li>The <code>kspace</code> array is also an <code>OffsetArray</code>.  This allows, for example, the k-space center(s) to be extracted as <code>kspace[kx=0, ky=0, kz=0]</code>. After FFT-ing, it make sense to get rid of the offsets.</li>
<li>For highly undersampled scans, this approach is memory-inefficient because non-sampled readouts will be stored as zeros.</li>
</ul>

<p dir="auto">The .data file is a binary file that contain measured samples in (complex) single precision floating point format.</p>
<p dir="auto">For further processing of the data (e.g. sorting), note that the samples are grouped as <em>complex data vectors</em> (Philips' phrasing). There are several complex data vector types:</p>

<p dir="auto">The .list file contains the attributes for each of the complex data vectors and which samples belong to which <em>complex data vector</em> (using <code>size</code> and <code>offset</code>). It also contains some <em>general information</em> of the scan such as the k-space and image space coordinate ranges, the number of locations, dynamics and averages.</p>
