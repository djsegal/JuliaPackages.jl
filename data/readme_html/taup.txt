<p dir="auto">A Julia wrapper for the <a href="https://www.seis.sc.edu/taup/" rel="nofollow">TauP Toolkit</a>, a Java Package for the calculation of seismic travel-times, ray paths, and related quantities through 1D spherical Earth velocity models (<a href="https://github.com/crotwell/TauP">GitHub Repo</a>).</p>
<p dir="auto">Goal of this project is to provide TauP's functionality inside Julia. At present, this package includes Julia wrappers to <code>taup_time</code> (calculation of seismic travel-times, ray parameters, incidence and take-off angles) and <code>taup_path</code> (calculation of ray paths and along-ray travel-time information) and supports the placement of receivers below Earth's surface. Additionaly, Julia wrappers to TauP's geodsic methods and functions for reading and writing TauP model files are provided. Wrappers are built using <a href="https://github.com/JuliaInterop/JavaCall.jl">JavaCall.jl</a>.</p>
<p dir="auto">For examples on how to use TauP.jl, see <code>tutorial.jl</code>.</p>
<p dir="auto">Note that an older wrapper package for TauP named <a href="https://github.com/anowacki/TauPy.jl">TauPy.jl</a> is available. However, <code>TauPy</code> is a Julia wrapper of a Python wrapper found in the <a href="https://docs.obspy.org/" rel="nofollow">ObsPy</a> package for calling TauP's time and path methods. The motivation for this project was to create an updated and pure Julia wrapper for TauP. Those familiar with ObsPy may want to consider <code>TauPy</code> depending on their use case.</p>

<p dir="auto">The package is part of the Julia General Registetry and can be istalled via the package manager:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; import Pkg

<p dir="auto"><code>TauP.jl</code> ships with the latest version of TauP that has been tested with the wrappers (currently v2.6.1). By default, this local version of TauP will be used by the wrappers unless the environnment variable <code>TAUP_JAR</code> is defined. In this case, <code>TAUP_JAR</code> should hold the the path to the desired TauP jar-file. This can be defined from a julia session prior to loading the TauP.jl package as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="julia&gt; ENV[&quot;TAUP_JAR&quot;] = &quot;path to TauP jar-file&quot;"><pre>julia<span class="pl-k">&gt;</span> <span class="pl-c1">ENV</span>[<span class="pl-s"><span class="pl-pds">"</span>TAUP_JAR<span class="pl-pds">"</span></span>] <span class="pl-k">=</span> <span class="pl-s"><span class="pl-pds">"</span>path to TauP jar-file<span class="pl-pds">"</span></span></pre></div>

<p dir="auto">For JavaCall to function properly, please set the environment variable <code>JULIA_COPY_STACKS = 1</code> before starting Julia. See <a href="https://github.com/JuliaInterop/JavaCall.jl">JavaCall documentation</a> for more details.</p>
<p dir="auto">Additionally, MacOS users must start Julia with the flag <code>julia --handle-signals=no</code> to avoid Java-related segmentation faults.</p>

<p dir="auto">The option <code>verbose = true</code> enables TauP-like screen output of the results which are stored in the TimeTauP structure.</p>
<p dir="auto">If performance is important or cleaner output is desired, a lower-level syntax designed for single-phase calculations can be used. For example,</p>

<p dir="auto">Here, <code>TimeObj</code> is a structure corresponding to TauP's Time object that contains all the relevant information for running <code>taup_time</code>. A tuple of arguments is returned with the travel-time <code>t</code>, ray parameter <code>p</code>, take-off angle <code>i</code>, and incidence angle <code>j</code>.</p>
<p dir="auto">Note that <code>TimeObj</code> is modified in the call to <code>taup_time!</code> to contain the relevant travel-time information. However, the same <code>TimeObj</code> may still be used on subsequent calculations and its calculation parameters may be updated via various set_* functions.</p>
<p dir="auto">For convenience, a variety of methods for different input arguments (e.g., geographic source and receiver positions) are also implemented. See function help for details.</p>
<p dir="auto">For more examples, see <code>tutorial.jl</code>.</p>
