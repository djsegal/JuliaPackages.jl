<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">The Estrin's scheme</h2><a id="user-content-the-estrins-scheme" class="anchor" aria-label="Permalink: The Estrin's scheme" href="#the-estrins-scheme"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Given an arbitrary polynomial</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$$P(x) = C_0 + C_1 x + C_2 x^2 + C_3 x^3 + ⋯ + C_n x^n$$</math-renderer>
<p dir="auto">one can group adjacent terms into sub-expressions of the form <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$(A + Bx)$</math-renderer> and rewrite it as a polynomial in <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$x^2$</math-renderer>:</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$$P(x) = (C_0 + C_1x) + (C_2 + C_3 x) x^2 + ⋯ = Q(x^2).$$</math-renderer>
<p dir="auto">These parameter can be calculated in parallel via SIMD, which can be more efficient than the traditional Horner's method.</p>
<p dir="auto">However, it is obvious that the Estrin's scheme needed additional <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$N$</math-renderer> registers to store the intermediate results, which may be a bottleneck when the polynomial is large.
Thus, the tile-based Estrin's scheme is proposed to reduce the number of registers needed.
Instead of calculating the polynomial in one step, the tile-based Estrin's scheme divides the polynomial into multiple tiles (here I took the tiling size as <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$n = 16$</math-renderer>), as</p>
<math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$$P(x) = C'_0 + C'_1 x^{n} + C'_2 x^{2n} + C'_3 x^{3n} + ⋯ = Q(x^{n})$$</math-renderer>
<p dir="auto">where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$C'_i$</math-renderer> is the coefficient of the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="b419c157a5e072de3d40d7384e26137f">$i$</math-renderer>-th tile calculated by the Estrin's scheme.
Then this process can be repeated recursively until the polynomial is small enough.</p>
