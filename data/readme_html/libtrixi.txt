<p dir="auto"><strong>Libtrixi</strong> is an interface library for using
<a href="https://github.com/trixi-framework/Trixi.jl">Trixi.jl</a> from C/C++/Fortran.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Prerequisites</h3><a id="user-content-prerequisites" class="anchor" aria-label="Permalink: Prerequisites" href="#prerequisites"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Currently, libtrixi is only developed and tested for Linux. Furthermore, the following
software packages need to be made available locally before installing libtrixi:</p>
<ul dir="auto">
<li><a href="https://julialang.org/downloads/platform/" rel="nofollow">Julia</a> v1.8+</li>
<li>C compiler with support for C11 or later (e.g., <a href="https://gcc.gnu.org/" rel="nofollow">gcc</a> or <a href="https://clang.llvm.org/" rel="nofollow">clang</a>)</li>
<li>Fortran compiler with support for Fortran 2018 or later (e.g., <a href="https://gcc.gnu.org/fortran/" rel="nofollow">gfortran</a>)</li>
<li><a href="https://cmake.org/" rel="nofollow">CMake</a></li>
<li>MPI (e.g., <a href="https://www.open-mpi.org/" rel="nofollow">OpenMPI</a> or <a href="https://www.mpich.org/" rel="nofollow">MPICH</a>)</li>
<li><a href="https://www.hdfgroup.org/solutions/hdf5/" rel="nofollow">HDF5</a></li>
<li><a href="https://github.com/DLR-AMR/t8code">t8code</a></li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Building</h3><a id="user-content-building" class="anchor" aria-label="Permalink: Building" href="#building"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For building, <code>cmake</code> and its typical workflow is used.</p>
<ol dir="auto">
<li>
<p dir="auto">It is recommended to create an out-of-source build directory, e.g.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mkdir build
cd build"><pre>mkdir build
<span class="pl-c1">cd</span> build</pre></div>
</li>
<li>
<p dir="auto">Call cmake</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cmake -DCMAKE_BUILD_TYPE=(Debug|Release) -DCMAKE_INSTALL_PREFIX=&lt;install_directory&gt; .."><pre>cmake -DCMAKE_BUILD_TYPE=(Debug<span class="pl-k">|</span>Release) -DCMAKE_INSTALL_PREFIX=<span class="pl-k">&lt;</span>install_directory<span class="pl-k">&gt;</span> ..</pre></div>
<p dir="auto"><code>cmake</code> should find <code>MPI</code> and <code>Julia</code> automatically. If not, the directories
can be specified manually.
The <code>cmake</code> clients <code>ccmake</code> or <code>cmake-gui</code> could be useful.</p>
<ul dir="auto">
<li>Specifying the directory <code>install_directory</code> for later installation is optional.</li>
<li>Optional specification of build type sets some default compiler options for optimized
or debug code.</li>
<li>Building with t8code support is optional. It requires to pass
<code>-DT8CODE_PREFIX=&lt;t8code_install_directory&gt;</code>.</li>
</ul>
</li>
<li>
<p dir="auto">Call make</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="make"><pre>make</pre></div>
<p dir="auto">This will build and place <code>libtrixi.so</code> in the current directory along with its
header and a Fortran <code>mod</code> file. Your application will have to include and link
against these.</p>
<p dir="auto">Examples can be found in the <code>examples</code> subdirectory.</p>
</li>
<li>
<p dir="auto">Install (optional)</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="make install"><pre>make install</pre></div>
<p dir="auto">This will install all provided files to the specified location.</p>
</li>
</ol>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Setting up Julia</h3><a id="user-content-setting-up-julia" class="anchor" aria-label="Permalink: Setting up Julia" href="#setting-up-julia"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Besides the library being installed, you need to configure Julia for use with libtrixi. For
this, create a directory where all necessary files will be placed, e.g., <code>libtrixi-julia</code>.
Then, you can use the <a href="utils/libtrixi-init-julia"><code>utils/libtrixi-init-julia</code></a> tool (also
available at <code>&lt;install_directory&gt;/bin</code>) to do the rest for you. A minimal example would be:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mkdir libtrixi-julia
cd libtrixi-julia
&lt;install_directory&gt;/bin/libtrixi-init-julia \
    --t8code-library &lt;t8code_install_directory&gt;/lib/libt8.so
    &lt;install_directory&gt;"><pre>mkdir libtrixi-julia
<span class="pl-c1">cd</span> libtrixi-julia
<span class="pl-k">&lt;</span>install_directory<span class="pl-k">&gt;</span>/bin/libtrixi-init-julia \
    --t8code-library <span class="pl-k">&lt;</span>t8code_install_directory<span class="pl-k">&gt;</span>/lib/libt8.so
    <span class="pl-k">&lt;</span>install_directory<span class="pl-k">&gt;</span></pre></div>
<p dir="auto">Use <code>libtrixi-init-julia -h</code> to get help.</p>
<p dir="auto">In your code, pass the path to the <code>libtrixi-julia</code> directory to <code>trixi_initialize</code>,
see the code of the examples. If you did not modify the default value for the Julia depot
when calling <code>libtrixi-init-julia</code>, libtrixi will find it automatically.
Otherwise, when running a program that uses libtrixi, you need to make sure to set the
<code>JULIA_DEPOT_PATH</code> environment variable to point to the <code>&lt;julia-depot&gt;</code> folder reported.</p>
<p dir="auto">If you intend to use additional Julia packages, besides <code>Trixi</code> and <code>OrdinaryDiffEq</code>, you
will have to add them to your Julia project (i.e. use
<code>julia --project=&lt;libtrixi-julia_directory&gt;</code> and <code>import Pkg; Pkg.add(&lt;package&gt;)</code>).</p>

<p dir="auto">To use libtrixi in your program, you need to specify <code>-I$LIBTRIXI_PREFIX/include</code> for the
include directory with header and module files, <code>-L$LIBTRIXI_PREFIX/lib</code> for the library
directory, and <code>-ltrixi</code> for the library itself during your build process. Optionally, you
can additionally specify <code>-Wl,-rpath,$LIBTRIXI_PREFIX/lib</code> such that the runtime loader
knows where to find <code>libtrixi.so</code>. Here, <code>$LIBTRIXI_PREFIX</code> is the install prefix you
specified during the CMake configure stage with <code>-DCMAKE_INSTALL_PREFIX</code>
(see <a href="#building">above</a>).</p>
<p dir="auto">An example <code>Makefile</code> is provided with
<a href="examples/MakefileExternal"><code>examples/MakefileExternal</code></a>, which can be invoked from inside
the <code>examples/</code> directory as</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="make -f MakefileExternal LIBTRIXI_PREFIX=path/to/libtrixi/prefix"><pre>make -f MakefileExternal LIBTRIXI_PREFIX=path/to/libtrixi/prefix</pre></div>

<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Note on thread-local storage (TLS)</h4><a id="user-content-note-on-thread-local-storage-tls" class="anchor" aria-label="Permalink: Note on thread-local storage (TLS)" href="#note-on-thread-local-storage-tls"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">On Linux and FreeBSD systems (i.e., <em>not</em> on macOS or Windows), Julia may internally
use a faster implementation for thread-local storage (TLS), which is used whenever Julia
functions such task management, garbage collection etc. are used in a multithreaded
context, or when they are themselves multithreaded. To activate the fast TLS in your
program, you need to add the file <code>$LIBTRIXI_PREFIX/lib/libtrixi_tls.o</code> to the list of files
that are linked with your main program. See <code>MakefileExternal</code> for an example of how to do
this. If you skip this step, everything will work as usual, but some things might run
slightly slower.</p>
