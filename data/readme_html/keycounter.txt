<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Event Number</h2><a id="user-content-event-number" class="anchor" aria-label="Permalink: Event Number" href="#event-number"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">KeyCounter needs to read keyboard events from a file in <code>/dev/input</code>. However, there are several files numbered <code>event0</code>, <code>event1</code>, etc and which corresponds to your keyboard is somewhat random. KeyCounter will attempt to autodetect the correct one, but this is likely to not succeed by itself.</p>
<p dir="auto">Depending on how strange your setup or keyboard is, you should be able to auto detect your keyboard by supplying the <code>keyboard</code> parameter with the make and model of your keyboard (ie "Razer Blackwidow").</p>
<p dir="auto">If KeyCounter can't determine the keyboard number correctly then you may be able to determine the correct event number by examining the text file <code>/proc/bus/input/devices</code>. Within this file look for a section with the correct <code>N: [Name]</code> line and a corresponding <code>H: ... kbd eventN</code> line.</p>
<p dir="auto">Alternatively, use <code>sudo hexdump /dev/input/eventN</code> for each N in turn and type some keys and see if there is any data produced. For the correct N you should receive data whenever a key is pressed or released.</p>
<p dir="auto">The correct value of N can then be passed to KeyCounter with the <code>event</code> parameter.</p>

<p dir="auto">KeyCounter will attempt to auto detect the correct keyboard device. If this doesn't work you can supply the make and model of the keyboard or the correct event number, along with other settings, as keyword arguments to <code>countkeys</code>. Accepted keywords are:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="* keyboard: (String) name of the keyboard to assist with autodetecting. Using just keywords like the make and model works best (ie &quot;logitech g512&quot;)
* event: (Int) number of the event file to read from
* input: (String) event file to read from (ie /dev/input/event0). Overrides `event` setting
* output: (String) filename to save results to
* interval: (String) frequency to save results, in the format `[Nd][Nh][Nm][Ns]`
* quiet: (Bool) whether to suppress output
* debug: (Bool) whether to display debugging information (overrides `quiet`)
* user: (Int) user id for ownership of the output file (as we are running as root)"><pre class="notranslate"><code>* keyboard: (String) name of the keyboard to assist with autodetecting. Using just keywords like the make and model works best (ie "logitech g512")
* event: (Int) number of the event file to read from
* input: (String) event file to read from (ie /dev/input/event0). Overrides `event` setting
* output: (String) filename to save results to
* interval: (String) frequency to save results, in the format `[Nd][Nh][Nm][Ns]`
* quiet: (Bool) whether to suppress output
* debug: (Bool) whether to display debugging information (overrides `quiet`)
* user: (Int) user id for ownership of the output file (as we are running as root)
</code></pre></div>
<p dir="auto">To stop counting keys, simply type <code>&lt;CTRL&gt;+C</code> (<code>^C</code>) or, if running in the background, send SIGINT to the process. Keys counted will be saved to the output file before exiting.</p>
