<p dir="auto"><em>Julia implementation of Branched Latent Neural Maps (BLNMs), a computational tool for generic functional mapping of physical processes to build accurate and efficient surrogate models.</em></p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Mathematical details</h2><a id="user-content-mathematical-details" class="anchor" aria-label="Permalink: Mathematical details" href="#mathematical-details"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">BLNMs structurally disentangle inputs with different intrinsic roles, such as time and model parameters, by means of feedforward partially-connected neural networks. These partial connections can be propagated from the first hidden layer throughout the outputs according to the chosen disentanglement level. Furthermore, BLNMs may be endowed with latent variables in the output space, which enhance the learned dynamics of the neural map. A BLNM is defined by a simple, lightweight architecture, easy and fast to train, while effectively reproducing physical processes with sharp gradients and fast dynamics in complex solution manifolds. It breaks the curse of dimensionality by requiring small training datasets and do not degrade in accuracy when tested on a different discretization than the one used for training.
For the case of inputs given by time and model parameters coming, for instance, from a differential equation, BLNMs can be defined as follows:</p>
<p dir="auto"><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathbf{z}(t) = \mathcal{B L \kern0.05em N \kern-0.05em M} \left(t, \boldsymbol{\theta}; \mathbf{w} \right) \text{ for } t \in [0, T].$</math-renderer></p>
<p dir="auto">This partially-connected neural network is represented by weights and biases <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathbf{w} \in \mathbb{R}^{N_\mathrm{w}}$</math-renderer>, and introduces a map <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathcal{B L \kern0.05em N \kern-0.05em M} \colon \mathbb{R}^{1 + N_\mathcal{P}} \to \mathbb{R}^{N_\mathrm{z}}$</math-renderer> from time <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$t$</math-renderer> and model parameters <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\boldsymbol{\theta} \in \boldsymbol{\Theta} \subset \mathbb{R}^{N_\mathcal{P}}$</math-renderer> to a state vector <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathbf{z}(t) = [\mathbf{z}_ \mathrm{physical}(t), \mathbf{z}_ \mathrm{latent}(t)]^T$</math-renderer>.
The state vector <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathrm{z}(t) \in \mathbb{R}^{N_\mathrm{z}}$</math-renderer> contains <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathbf{z}_ \mathrm{physical}(t)$</math-renderer> physical fields of interest, as well as interpretable <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="652b0af0f94c7ee32a47044c1970a3a7">$\mathbf{z}_\mathrm{latent}(t)$</math-renderer> latent temporal variables without a direct physical representation, that enhance the learned dynamics of the BLNM.
During the optimization process of the neural network tunable parameters, the Mean Square Error (MSE) between the BLNM outputs and observations, both in non-dimensional form, is minimized.
Time and model parameters are also normalized during the training phase of the BLNM.</p>
<p dir="auto">This package can be seamlessly extended to include more than two branches involving different sets of inputs, such as space, time, model-specific parameters and geometrical features.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Getting started</h2><a id="user-content-getting-started" class="anchor" aria-label="Permalink: Getting started" href="#getting-started"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Make sure to activate the environment contained in <code>Project.toml</code> with <code>julia 1.8.5</code> installed.</p>
<p dir="auto">The repository currently contains three different test cases:</p>
<ul dir="auto">
<li>Create a geometry-specific surrogate model to reproduce in silico 12-lead electrocardiograms (ECGs) while spanning 7 cell-to-organ level model parameters (<code>train_HLHS_ECGs.jl</code>, <code>train_hyperopt_HLHS_ECGs.jl</code>, <code>test_HLHS_ECGs.jl</code>)</li>
<li>Digital twinning of cardiac electrophysiology to match clinical 12-lead ECGs (<code>digital_twin_HLHS_ECGs.jl</code>)</li>
<li>Create a cell-based surrogate model that simulates the action potential of the <a href="https://elifesciences.org/articles/48890" rel="nofollow">Tomek Rodriguez-O'Hara Rudy (ToR-ORd) ionic model</a> at limit cycle while spanning 14 relevant cellular conductances (<code>train_ToR-ORd.jl</code>, <code>test_ToR-ORd.jl</code>)</li>
</ul>
<p dir="auto">For the sake of illustration on the first test case, a BLNM with user-defined parameters can be trained by running <code>train_HLHS_ECGs.jl</code> within the Julia REPL.
Once the BLNM is trained, the mean square error on the training and testing datasets can be computed and some plots can be shown by calling <code>test_HLHS_ECGs.jl</code>.
Running <code>import Pkg; Pkg.instantiate()</code> is usually necessary to properly initialize the environment within the Julia REPL.
MPI-based hyperparameters tuning with K-fold cross-validation should be run in a bash terminal by typing:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="mpirun -n K julia --project=. train_hyperopt_HLHS_ECGs.jl"><pre>mpirun <span class="pl-k">-</span>n K julia <span class="pl-k">--</span>project<span class="pl-k">=</span>. train_hyperopt_HLHS_ECGs<span class="pl-k">.</span>jl</pre></div>
<p dir="auto">where K represents the number of K-folds.
Note that a suitable MPI implementation should be installed in order to run the last command.</p>
<p dir="auto"><code>BLNM.jl</code> defines the actual BLNMs implementation, <code>InOut.jl</code> contains input-output features and <code>Utils.jl</code> introduces some generic utilities.</p>
