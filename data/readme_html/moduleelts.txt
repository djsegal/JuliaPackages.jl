<strong><code>ModuleElts</code></strong> — <em>Module</em>.</p>
<p dir="auto">Module Elements –- elements of free modules.</p>
<p dir="auto">A  <code>ModuleElt{K,V}</code> represents an element of  a free module where the basis elements  are of type <code>K</code> and the coefficients are of type <code>V</code>. Usually you want  objects of type <code>V</code> to be elements of a (not necessarily commutative) ring,  but it can also  be useful if they  just belong to an abelian group. This is similar to the SageMath CombinatorialFreeModule. You can also think of  them as <code>SparseVector</code>s, where  the keys can be  of type <code>K</code> instead of integers.</p>
<p dir="auto">This  basic data  structure is  used in  many places  in my  packages as an efficient   representation.  For   example,  the   type  <code>Monomial</code>,  which represents multivariate monomials is a <code>ModuleElt{Symbol,Int}</code>:</p>
<p dir="auto"><code>x^2y^-3</code> is represented by <code>ModuleElt(:x=&gt;2,:y=&gt;-3)</code></p>
<p dir="auto">And  multivariate polynomials are  represented by a <code>ModuleElt{Monomial,C}</code> where <code>C</code> is the type of the coefficients:</p>
<p dir="auto"><code>x*y-z^2</code> is represented by <code>ModuleElt(x*y=&gt;1,z^2=&gt;-1)</code></p>
<p dir="auto"><code>ModuleElts</code>  are  also  used  for  cyclotomics, CycPols, elements of Hecke algebras, etc…</p>
<p dir="auto">A  <code>ModuleElt{K,V}</code> is essentially a  list of <code>Pairs{K,V}</code>. The constructor takes  as argument a list of pairs, or a variable number of pair arguments, or a generator of pairs.</p>
<p dir="auto">We provide two implementations:</p>
<ul dir="auto">
<li><code>HModuleElt</code>, an implementation by <code>Dict</code>s</li>
</ul>
<p dir="auto">This  requires  the  type  <code>K</code>  to  be  hashable.  This  is  a  very simple implementation  since the interface of the type  is close to that of dicts; the  only difference  is that  keys with  cofficient zero are discarded –- which  is necessary, since for checking the equality of module elements one needs a canonical form for each element.</p>
<ul dir="auto">
<li><code>ModuleElt</code>, a faster implementation by a vector of pairs sorted by key.</li>
</ul>
<p dir="auto">This requires that the type <code>K</code> has an <code>isless</code> method. This implementation is  two to  four times  faster than  the <code>Dict</code> implementation and requires half the memory.</p>
<p dir="auto">Both  implementations  have  the  same  methods,  which are mostly the same methods  as a  <code>Dict</code> (<code>haskey</code>,  <code>getindex</code>, <code>setindex</code>, <code>keys</code>, <code>values</code>. <code>pairs</code>,   <code>first</code>,  <code>iterate</code>,  <code>length</code>,  <code>eltype</code>,  <code>copy</code>),  with  some exceptions.  Adding elements  is implemented  as <code>merge(+,...)</code>  which is a variation  on  <code>merge</code>  for  <code>Dict</code>s  where  keys with coefficient zero are discarded  after the operation  (here <code>+</code> can  be replaced by any operation <code>op</code> with the property that <code>op(0,x)=op(x,0)=x</code>).</p>
<p dir="auto">A  module element can also be negated, or multiplied or divided (<code>/</code>or <code>//</code> or  <code>\</code>) by any element (acting on  coefficients) if the method is defined between  the  type  <code>V</code>  and  that  element;  the order of the arguments is respected,  which  allows  to  implement  left  and  right  modules  if the multiplication  is  not  commutative  for  <code>V</code>.  There  are also <code>zero</code> and <code>iszero</code> methods.</p>
<p dir="auto"><code>ModuleElt</code>s have methods <code>cmp</code> and <code>isless</code> which <code>HModuleElt</code>s don't have (the  definition is lexicographic order). There is also <code>ModuleElts.merge2</code> which  does the same as  merge but is valid  for more general operations – thus  is more expensive since it needs  more checks for zero results (I use it with <code>min</code> and <code>max</code> which implement <code>gcd</code> and <code>lcm</code> for <code>Monomial</code>s and <code>CycPol</code>s).</p>

<p dir="auto"><a id="user-content-moduleelts.moduleelt" href="#ModuleElts.ModuleElt">#</a>
<strong><code>ModuleElts.ModuleElt</code></strong> — <em>Type</em>.</p>
<p dir="auto"><code>ModuleElt{K,V}</code>  has a  similar interface  to <code>Dict{K,V}</code>,  but instead of assuming  that <code>K</code> is hashable, it assumes  that <code>K</code> is sortable. This also has the advantage that ModuleElts are naturally sortable.</p>
<p dir="auto">The  only field, a <code>Vector{Pair{K,V}}</code>, is  kept sorted by <code>K</code>; by default, the  constructor checks sorting, adds values with the same key, and deletes keys with zero value. This can be overriden with the keyword <code>check=false</code>.</p>
<p dir="auto"><a href="https://github.com/jmichel7/ModuleElts.jl/blob/701d90fc408e308af44a82bb1b5c3d9e504cc681/src/ModuleElts.jl#L217-L225">source</a><br></p>
<p dir="auto"><a id="user-content-base.merge-tuple{function, moduleelt, moduleelt}" href="#Base.merge-Tuple{Function, ModuleElt, ModuleElt}">#</a>
<strong><code>Base.merge</code></strong> — <em>Method</em>.</p>
<p dir="auto"><code>merge(op::Function,a::ModuleElt,b::ModuleElt)</code></p>
<p dir="auto">is  like <code>merge(op,a,b)</code> for  <code>Dict</code>s, except that  keys with value <code>0</code> are deleted after the operation is done.</p>
<p dir="auto">The  code is only  valid for <code>op</code>s  such that <code>op(0,x)=op(x,0)=x</code> otherwise the result is wrong. You can use <code>ModuleElts.merge2</code> for a (more expensive) function which always works.</p>
<p dir="auto"><a href="https://github.com/jmichel7/ModuleElts.jl/blob/701d90fc408e308af44a82bb1b5c3d9e504cc681/src/ModuleElts.jl#L254-L263">source</a><br></p>
<p dir="auto"><a id="user-content-moduleelts.merge2" href="#ModuleElts.merge2">#</a>
<strong><code>ModuleElts.merge2</code></strong> — <em>Function</em>.</p>
<p dir="auto"><code>ModuleElts.merge2(op::Function,a::ModuleElt,b::ModuleElt)</code></p>
<p dir="auto">does  <code>op</code> between coefficients of  the same basis element  in <code>a</code> and <code>b</code>. This  version works  for general  ops (not  necessarily commutative  or not satisfying  op(0,x)=op(x,0)=x).  It  currently  has  too  much  overhead to replace  <code>merge</code> for  + or  other ops  such that  op(0,x)==op(x,0)=x. It is useful for max or min which do lcm and gcd of <code>Monomial</code>s or <code>CycPol</code>s.</p>

<strong><code>Base.getindex</code></strong> — <em>Method</em>.</p>
<p dir="auto"><code>getindex(x::ModuleElt,key)</code>  returns the value in  <code>x</code> associated with the <code>given key</code>. It returns zero if the key does not occur in <code>x</code>.</p>
