<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Overview</h1><a id="user-content-overview" class="anchor" aria-label="Permalink: Overview" href="#overview"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">PluoPages.jl is a site generation system inspired by <a href="https://www.11ty.dev/" rel="nofollow">https://www.11ty.dev/</a>. It's a tool that turns a folder of files (Pluto notebook, Markdown files, images, and more) into a complete static website, that you can host using a service like GitHub Pages or Netlify.</p>
<p dir="auto">PlutoPages searches for input files, and turns them into web pages. There are three <strong>template systems</strong>:</p>
<ul dir="auto">
<li><strong><code>.jlhtml</code> files</strong> are rendered by <a href="https://github.com/JuliaPluto/HypertextLiteral.jl">HypertextLiteral.jl</a></li>
<li><strong><code>.jlmd</code> files</strong> are rendered by <a href="https://github.com/JuliaPluto/MarkdownLiteral.jl">MarkdownLiteral.jl</a></li>
<li><strong><code>.jl</code> files</strong> are rendered by <a href="https://github.com/JuliaPluto/PlutoSliderServer.jl">PlutoSliderServer.jl</a></li>
</ul>
<p dir="auto">The <code>/src/</code> folder is scanned for files, and all files are turned into HTML pages.</p>
<p dir="auto">Paths correspond to URLs. For example, <code>src/en/docs/install.jlmd</code> will become available at <code>plutojl.org/en/docs/install/</code>. For files called <em>"index"</em>, the URL will point to its parent, e.g. <code>src/en/docs/index.jlmd</code> becomes <code>plutojl.org/en/docs/</code>. Remember that changing URLs is very bad! You can't share Pluto with your friends if the links break.</p>
<p dir="auto">You can generate &amp; preview your website locally (more on this later), and there is a github action that you can use to generate the website when we push to the <code>main</code> branch, to deploy your website automatically when you change the code.</p>

<p dir="auto">We use <em>Julia</em> as our templating system! Because we use HypertextLiteral and MarkdownLiteral, you can write regular Markdown files and HTML files, but you can also include <code>$(interpolation)</code> to spice up your documents! For example:</p>
<div class="highlight highlight-text-md notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# Hey there!

<p dir="auto">Besides small inline values, you can also write big code blocks, with <code>$(begin ... end)</code>, and you can output HTML. Take a look at some of our files to learn more!</p>

<p dir="auto">Pluto notebooks will be rendered to HTML and included in the page. What you see is what you get!</p>
<p dir="auto">We are not running a slider server currently, but we will probably add it in the future!</p>
<p dir="auto">Notebook outputs are <strong>cached</strong> (for a long time) by the file hash. This means that a notebook file will only ever run once, which makes it much faster to work on the website. If you need to re-run your notebook, add a space somewhere in the code :)</p>

<p dir="auto">Every page <strong>should probably</strong> include:</p>
<ul dir="auto">
<li><em><code>title</code></em>: Will be used in the sidebar, on Google, in the window header, and on social media.</li>
<li><em><code>description</code></em>: Will be used on hover, on Google, and on social media.</li>
<li><em><code>tags</code></em>: List of <em>tags</em> that are used to create collections out of pages. Our sidebar uses collections to know which pages to list. (more details in <code>sidebar data.jl</code>)</li>
<li><em><code>layout</code></em>: The name of a layout file in <code>src/_includes</code>. For basic Markdown or HTML, you probably want <code>md.jlmd</code>. For Pluto, you should use <code>layout.jlhtml</code>.</li>
</ul>
