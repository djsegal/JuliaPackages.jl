<p dir="auto"><a href="https://mlhetland.github.io/Allocations.jl/dev" rel="nofollow"><img src="https://camo.githubusercontent.com/45c316268f541933640ad68f61395986888f4d46bc9641b40e53d337576c6456/68747470733a2f2f696d672e736869656c64732e696f2f62616467652f646f63732d6465762d626c75652e737667" alt="" data-canonical-src="https://img.shields.io/badge/docs-dev-blue.svg" style="max-width: 100%;"></a></p>
<p dir="auto">The Allocations package deals with the fair allocation of indivisible items
to a set of agents. For some background on this topic, see, e.g., the <a href="https://en.wikipedia.org/wiki/Fair_item_allocation" rel="nofollow">Wikipedia
entry on fair item
allocation</a>, or the surveys
by <a href="https://arxiv.org/abs/2208.08782" rel="nofollow">Amanatidis et al.</a> and
<a href="https://doi.org/10.1145/3505156.3505162" rel="nofollow">Suksompong</a>, on the unconstrained and
constrained versions of the problem, respectively.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Installation</h2><a id="user-content-installation" class="anchor" aria-label="Permalink: Installation" href="#installation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To install the package, you can simply import it in the <a href="https://docs.julialang.org/en/v1/stdlib/REPL/" rel="nofollow">Julia
REPL</a>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; using Allocations"><pre class="notranslate"><code>julia&gt; using Allocations
</code></pre></div>
<p dir="auto">Press enter at the resulting prompt to install both the package and its
dependencies.</p>
<p dir="auto">To install a more recent version than the released one, you can use the package
manager directly. In the Julia REPL, press <code>]</code> to enter the <code>Pkg</code> REPL, and then
add the package directly from the source:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="pkg&gt; add https://github.com/mlhetland/Allocations.jl"><pre class="notranslate"><code>pkg&gt; add https://github.com/mlhetland/Allocations.jl
</code></pre></div>
<p dir="auto">You can then import the module as before.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Basic use</h2><a id="user-content-basic-use" class="anchor" aria-label="Permalink: Basic use" href="#basic-use"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">To specify an allocation problem instance, create a valuation profile:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; V = Profile([1 2 3; 2 3 1])
Additive{Matrix{Int64}} with 2 agents and 3 items:
 1  2  3
 2  3  1"><pre class="notranslate"><code>julia&gt; V = Profile([1 2 3; 2 3 1])
Additive{Matrix{Int64}} with 2 agents and 3 items:
 1  2  3
 2  3  1
</code></pre></div>
<p dir="auto"><code>Profile</code> is an abstract class, and <code>Profile(X::Matrix)</code> is an alias for
<code>Additive(X)</code>. Once you have a valuation profile, you can use an allocation
function (ones called <code>alloc_...</code>), e.g., for finding a maximum Nash welfare
(MNW) allocation:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; res = alloc_mnw(V);"><pre class="notranslate"><code>julia&gt; res = alloc_mnw(V);
</code></pre></div>
<p dir="auto">Note that the first time you call an allocation function, it may take some time
to finish, because there's quite a lot of compilation going on behind the
scenes. From then on, in the same REPL session, there will be much less
overhead.</p>
<p dir="auto">These functions take a <code>Profile</code> as input and return a named tuple with the
field <code>alloc</code> referring to an <code>Allocation</code>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; A = res.alloc
Allocation with 2 agents and 3 items:
  1 =&gt; {3}
  2 =&gt; {1, 2}"><pre class="notranslate"><code>julia&gt; A = res.alloc
Allocation with 2 agents and 3 items:
  1 =&gt; {3}
  2 =&gt; {1, 2}
</code></pre></div>
<p dir="auto">The bundles of each agent is available through the <code>bundle</code> function:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; bundle(A, 2)
Set{Int64} with 2 elements:
  2
  1"><pre class="notranslate"><code>julia&gt; bundle(A, 2)
Set{Int64} with 2 elements:
  2
  1
</code></pre></div>
<p dir="auto">Bundles should not be modified directly, as the <code>Allocation</code> also maintains an
inverse mapping, from items to agents. Rather, use the <code>give!</code> and <code>deny!</code>
functions.</p>
<p dir="auto">Some allocation functions may produce other results as well, such as properties
of the allocation that are naturally computed as part of the allocation process.
For the MNW case, the objective value (the Nash welfare, which is being
maximized) is available as <code>mnw</code>:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; res.mnw
15.0"><pre class="notranslate"><code>julia&gt; res.mnw
15.0
</code></pre></div>
<p dir="auto">The allocation functions also permit a matrix argument as a shortcut, implicitly
creating an <code>Additive</code>. For example, you can find a maximin share (MMS)
allocation as follows:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; alloc_mms([1 1 2 3; 2 1 2 3]).alloc
Allocation with 2 agents and 4 items:
  1 =&gt; {2, 3}
  2 =&gt; {1, 4}"><pre class="notranslate"><code>julia&gt; alloc_mms([1 1 2 3; 2 1 2 3]).alloc
Allocation with 2 agents and 4 items:
  1 =&gt; {2, 3}
  2 =&gt; {1, 4}
</code></pre></div>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Solver configuration</h2><a id="user-content-solver-configuration" class="anchor" aria-label="Permalink: Solver configuration" href="#solver-configuration"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Several allocation functions use mixed-integer linear programming via
<a href="https://jump.dev" rel="nofollow">JuMP</a>. Depending on the choice of MIP solver, solving even
moderately-sized instances may take a significant amount of time. Choosing a
different solver (from the default <code>HiGHS.Optimizer</code>) may speed things up
considerably. For example, with the appropriate license, one could use use
<a href="https://www.gurobi.com" rel="nofollow">Gurobi</a> as follows:<sup><a href="#user-content-fn-2-8698e6cc05e08ec711e96c2a192cc5c1" id="user-content-fnref-2-8698e6cc05e08ec711e96c2a192cc5c1" data-footnote-ref="" aria-describedby="footnote-label">1</a></sup></p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Allocations.conf.MIP_SOLVER = Gurobi.Optimizer"><pre class="notranslate"><code>Allocations.conf.MIP_SOLVER = Gurobi.Optimizer
</code></pre></div>
<p dir="auto">It is also possible to supply the <code>Optimizer</code> (or other optimizer factories,
e.g., constructed using <code>optimizer_with_attributes</code>) as the <code>solver</code> keyword
argument to the relevant allocation functions.</p>
<p dir="auto">Normally, the MIP solvers will print out quite a lot of information about what
they're doing. If you're not interested in this output, you can generally turn
it off using some solver-specific flag, supplied to
<code>optimizer_with_attributes</code>.<sup><a href="#user-content-fn-3-8698e6cc05e08ec711e96c2a192cc5c1" id="user-content-fnref-3-8698e6cc05e08ec711e96c2a192cc5c1" data-footnote-ref="" aria-describedby="footnote-label">2</a></sup> This is also where you'd supply other
parameters, e.g., indicating time limits, acceptable inaccuracies, etc. For
example:<sup><a href="#user-content-fn-4-8698e6cc05e08ec711e96c2a192cc5c1" id="user-content-fnref-4-8698e6cc05e08ec711e96c2a192cc5c1" data-footnote-ref="" aria-describedby="footnote-label">3</a></sup></p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="Allocations.conf.MIP_SOLVER = optimizer_with_attributes(
    Gurobi.Optimizer,
    &quot;LogToConsole&quot; =&gt; 0,     # No console output
    &quot;TimeLimit&quot; =&gt; 60,       # Finish within 60 seconds
    &quot;MipGap&quot; =&gt; 0.05,        # Permit 5% suboptimality
)"><pre class="notranslate"><code>Allocations.conf.MIP_SOLVER = optimizer_with_attributes(
    Gurobi.Optimizer,
    "LogToConsole" =&gt; 0,     # No console output
    "TimeLimit" =&gt; 60,       # Finish within 60 seconds
    "MipGap" =&gt; 0.05,        # Permit 5% suboptimality
)
</code></pre></div>
<p dir="auto">If you're unable to get rid of the output using solver parameters, a simple
solution is to just silence all output while allocating:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; redirect_stdout(devnull) do
           alloc_mnw(V)
       end"><pre class="notranslate"><code>julia&gt; redirect_stdout(devnull) do
           alloc_mnw(V)
       end
</code></pre></div>
<p dir="auto">If that doesn't do the trick, you could add <code>redirect_stderr</code> as well.</p>
