<p dir="auto">OverflowContexts provides easy manipulation of (integer, or any type that opts-in) arithmetic modes.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Justification</h2><a id="user-content-justification" class="anchor" aria-label="Permalink: Justification" href="#justification"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">By default, Julia generally uses overflowing (unchecked) integer math (other than division methods), which silently wraps around from the maximum to the minimum value when it gets too large or small, respectively. This choice is because checking for overflow is slower and means that any integer arithmetic could throw an exception, which the compiler would need to account for.</p>
<p dir="auto">With base Julia, if a user wishes to use checked arithmetic, they would need to bring in <code>Base.Checked</code> and explicitly use e.g., <code>checked_add(x, y)</code> rather than the natural operator. This is cumbersome, but we can use Julia's metaprogramming features to remove this overhead.</p>

<p dir="auto">Division-related operators and methods (<code>÷</code>, <code>div</code>, <code>fld</code>, <code>cld</code>, <code>%</code>, <code>rem</code>, <code>mod</code>), in contrast, are checked by default in Julia. This is primarily because the LLVM compiler deems division by 0, or <code>-typemin(T) ÷ -one(T)</code> to be undefined behavior. Also, integer division on CPUs are generally quite slow and so this choice doesn't make much difference for performance. This package provides unchecked and saturating variants of these methods. The main benefit of the unchecked methods is that they are guaranteed to not throw an exception, however the result of a bad division should not be relied on. The saturating variant defines division by zero by treating <code>typemin(T)</code> and <code>typemax(T)</code> as saturating towards infinity, and returning <code>0</code> for <code>0 ÷ 0</code>. The saturating remainder methods produce complementary values.</p>
<p dir="auto">Julia has a more complex <code>div</code> API than is supported here (e.g. supporting rounding modes) but this package just covers the two-argument methods available inside <code>Base.Checked</code>.</p>

<p dir="auto">If you are writing a module and desire to set the default type of arithemtic for the module, place e.g., <code>@default_unchecked</code>, <code>@default_checked</code>, <code>@default_saturating</code> at the top of the module. This macro defines module-local copies of all of the supported arithemtic operators and methods, mapping them to the appropriate <code>unchecked</code>, <code>checked_</code>, or <code>saturating_</code> methods. The defaults do not affect anything inside the expression/block-level macros. These defaults may also be used on the REPL to switch between modes, although keep in mind that it will also cause previous methods defined on the REPL (in the <code>Main</code> module) to be recompiled with the new default.</p>

<p dir="auto">If you are implementing your own <code>Number</code> types, this package should just work for you so long as you extend the Base operators and the Base.Checked <code>checked_</code> methods. For <code>saturating_</code>, your package will need to either take OverflowContexts as a dependency or a weak dependency with a package extension in order to import the <code>saturating_</code> methods, until/unless Julia implements them directly.</p>
