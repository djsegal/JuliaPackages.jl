<p dir="auto"><a href="https://github.com/jump-dev/KNITRO.jl">KNITRO.jl</a> is a wrapper for the
<a href="https://www.artelys.com/knitro" rel="nofollow">Artelys Knitro solver</a>.</p>
<p dir="auto">It has two components:</p>
<ul dir="auto">
<li>a thin wrapper around the <a href="https://www.artelys.com/tools/knitro_doc/3_referenceManual/callableLibraryAPI.html" rel="nofollow">C API</a></li>
<li>an interface to <a href="https://github.com/jump-dev/MathOptInterface.jl">MathOptInterface</a>.</li>
</ul>
<p dir="auto"><strong>KNITRO.jl v0.14.0 introduced a number of breaking changes to the low-level C
API. See the Low-level wrapper section for details.</strong></p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Installation</h2><a id="user-content-installation" class="anchor" aria-label="Permalink: Installation" href="#installation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">First, obtain a license and install a copy of KNITRO from
<a href="https://www.artelys.com/knitro" rel="nofollow">Artelys</a>.</p>
<p dir="auto">Then, install <code>KNITRO.jl</code> using the Julia package manager:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="import Pkg
Pkg.add(&quot;KNITRO&quot;)"><pre><span class="pl-k">import</span> Pkg
Pkg<span class="pl-k">.</span><span class="pl-c1">add</span>(<span class="pl-s"><span class="pl-pds">"</span>KNITRO<span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">If you are having trouble installing KNITRO.jl, here are several things to try:</p>
<ul dir="auto">
<li>Make sure that you have defined your global variables correctly, for example
with <code>export KNITRODIR="/path/to/knitro-vXXX-$OS-64"</code> and <code>export LD_LIBRARY_PATH="$LD_LIBRARY_PATH:$KNITRODIR/lib"</code>. You can check that
<code>KNITRO.jl</code> sees your library with <code>using KNITRO; KNITRO.has_knitro()</code>.</li>
<li>If <code>KNITRO.has_knitro()</code> returns <code>false</code> but you are confident that your paths
are correct, try running <code>Pkg.build("KNITRO")</code> and restarting Julia. In at
least one user's experience, installing and using KNITRO in a temporary Julia
environment (activated with <code>] activate --temp</code>) does not work and the need to
manually build is likely the reason why.</li>
</ul>

<p dir="auto">The complete C API can be accessed via <code>KNITRO.KN_xx</code> functions, where the names
and arguments are identical to the C API.</p>
<p dir="auto">See the <a href="https://www.artelys.com/app/docs/knitro/" rel="nofollow">KNITRO documentation</a>
for details.</p>
<p dir="auto">As general rules when converting from Julia to C:</p>
<ul dir="auto">
<li>When KNITRO requires a <code>Ptr{T}</code> that holds one element, like <code>double *</code>,
use a <code>Ref{T}()</code>.</li>
<li>When KNITRO requires a <code>Ptr{T}</code> that holds multiple elements, use
a <code>Vector{T}</code>.</li>
<li>When KNITRO requires a <code>double</code>, use <code>Cdouble</code></li>
<li>When KNITRO requires an <code>int</code>, use <code>Cint</code></li>
<li>When KNITRO requires a <code>NULL</code>, use <code>C_NULL</code></li>
</ul>
<p dir="auto">Extensive examples using the C wrapper can be found in <code>examples/</code>.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Breaking changes</h3><a id="user-content-breaking-changes" class="anchor" aria-label="Permalink: Breaking changes" href="#breaking-changes"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">KNITRO.jl v0.14.0 introduced a number of breaking changes to the low-level C
API. The main changes were:</p>
<ol dir="auto">
<li>removing Julia-specific functions like <code>KN_set_param</code>. Use the C API functions
like <code>KN_set_int_param</code> and <code>KN_set_double_param_by_name</code>.</li>
<li>removing intermediate methods that tried to make the C API more Julia-like.
For example, we have removed the <code>KN_add_var</code> method that returned the index of
the variable. There is now only the method from the C API.</li>
</ol>
<p dir="auto">If you have trouble updating, please open a GitHub issue.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Multi-threading</h2><a id="user-content-multi-threading" class="anchor" aria-label="Permalink: Multi-threading" href="#multi-threading"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Due to limitations in the interaction between Julia and C, KNITRO.jl disables
multi-threading if the problem is nonlinear. This will override any options such
as <code>par_numthreads</code> that you may have set.</p>
<p dir="auto">If you are using the low-level API, opt-in to enable multi-threading by calling
<code>KN_solve(model.env)</code> instead of <code>KN_solve(model)</code>, where <code>model</code> is the value
returned by <code>model = KN_new()</code>. Note that calling <code>KN_solve(model.env)</code> is an
advanced operation because it requires all callbacks you provide to be threadsafe.</p>
