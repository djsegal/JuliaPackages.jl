<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Purpose</h2><a id="user-content-purpose" class="anchor" aria-label="Permalink: Purpose" href="#purpose"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This package contains a collection of linear operators that are in particular useful for multi-dimensional signal and image processing tasks. All operators are build using the LinearOperators.jl base type and derive from <code>AbstractLinearOperator</code>. For example this package
provides operators for the FFT (Fast Fourier Transform) and its non-equidistant variant (NFFT), the DCT (Discrete Cosine Transform), and the Wavelet transform. This package, however, does not implement
these transformation itself but uses established libraries for them. So in fact, LinearOperatorCollection's main purpose is to add a wrapper around low-level libraries like
FFTW.jl and NFFT.jl, which allows to use the transformation as if they would be linear operators, i.e. implement <code>Op * x</code>, <code>adjoint(Op) * x</code> and the <code>mul!</code> based in-place variants of the former.</p>

<p dir="auto">After loading the package one can construct an operator <code>Op</code> using the generic syntax</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="op = Op(T; kargs...) "><pre>op <span class="pl-k">=</span> <span class="pl-c1">Op</span>(T; kargs<span class="pl-k">...</span>) </pre></div>
<p dir="auto">Here, <code>T</code> is the element type of the operator that usually should match the element type that
the operator will later operate on. The keyword arguments are operator specific but there are
some common parameters. For instance, most operators have a <code>shape</code> parameter, which encodes
the size of the vector <code>x</code>, the operator is applied to</p>

<p dir="auto">The following shows how to build a two dimensional FFT operator and apply it to an image:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using LinearOperatorCollection, FFTW, LinearAlgebra

# apply operator
y = F * x
# apply the adjoint operator
z = adjoint(F) * y

# apply the in place variants, which do not allocate memory during the computation
mul!(y, F, x)
mul!(z, adjoint(F), x)"><pre><span class="pl-k">using</span> LinearOperatorCollection, FFTW, LinearAlgebra

<p dir="auto">Currently the following operators are implemented:</p>
<ul dir="auto">
<li><code>WeightingOp</code>: A diagonal weighting matrix</li>
<li><code>SamplingOp</code>: An operator which (sub)-samples the input vector</li>
<li><code>NormalOp</code>: An operator building the normal matrix <code>A' W A</code> in a lazy fashion</li>
<li><code>GradientOp</code>: An operator calculating the gradient along one or several directions</li>
<li><code>FFTOp</code>: An operator applying the fast Fourier transform</li>
<li><code>DCTOp</code>: An operator applying the discrete cosine transform</li>
<li><code>DSTOp</code>: An operator applying the discrete sine transform</li>
<li><code>NFFTOp</code>: An operator applying the non-equidistant fast Fourier transform</li>
<li><code>WaveletOp</code>: An operator applying the wavelet transformation</li>
</ul>
