<p dir="auto">Pseudo-likelihood maximization in <a href="http://julialang.org" rel="nofollow">Julia</a>. If you use this algorithm, you should cite:</p>
<ol dir="auto">
<li>
<p dir="auto">M. Ekeberg, C. Lovkvist, Y. Lan, M. Weigt, E. Aurell, Improved
contact prediction in proteins: Using pseudolikelihood to infer Potts
models, Phys. Rev. E 87, 012707 (2013)</p>
</li>
<li>
<p dir="auto">M. Ekeberg, T. Hartonen, E. Aurell, Fast pseudolikelihood
maximization for direct-coupling analysis of protein structure from
many homologous amino-acid sequences,
<a href="http://arxiv.org/abs/1401.4832" rel="nofollow">arXiv:1401.4832</a> (supplementary
material)</p>
</li>
</ol>
<p dir="auto">The present software is a Julia implementation of above mentioned
papers, with no reference to the original MATLAB implementation.</p>
<p dir="auto">The code requires Julia version 1.5 or later.</p>

<p dir="auto">To load the code just type</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="julia&gt; using PlmDCA"><pre class="notranslate"><code>julia&gt; using PlmDCA
</code></pre></div>
<p dir="auto">The functions in this package are written to maximize performance. Most
computationally-heavy functions can use multiple threads (start julia with
the <code>-t</code> option or set the <code>JULIA_NUM_THREADS</code> environment variable).
For more information on how set correctly the number of threads, please
refer to the online <a href="https://docs.julialang.org/en/v1/manual/multi-threading/" rel="nofollow">Julia Documentation on Multi-Threading</a>.</p>
<p dir="auto">The software provides two main functions <code>plmdca(filename::String, ...)</code> and <code>plmdca_sym(filename::String,...)</code> (resp. the asymmetric and
symmetric coupling version of the algorithm). Empirically it turns out
that the asymmetric version is faster and more accurate. This function
take as input the name of a (possibly zipped) multiple sequence.</p>
<p dir="auto">We also provide another function <code>mutualinfo(filename::String,...)</code> to
compute the mutual information score.</p>
<p dir="auto">There are a number of possible algorithmic strategies for the
optimization problem. As long as local gradient-based optimization is
concerned, this is a list of <code>:symbols</code> (associated to the different
methods):</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content=":LD_MMA, :LD_SLSQP, :LD_LBFGS, :LD_TNEWTON_PRECOND
:LD_TNEWTON_PRECOND_RESTART, :LD_TNEWTON, :LD_VAR2, :LD_VAR1"><pre class="notranslate"><code>:LD_MMA, :LD_SLSQP, :LD_LBFGS, :LD_TNEWTON_PRECOND
:LD_TNEWTON_PRECOND_RESTART, :LD_TNEWTON, :LD_VAR2, :LD_VAR1
</code></pre></div>
<p dir="auto">After some experiments, we found that the best compromise between
accuracy and speed is achieved by the Low Storage BFGS method
<code>:LD_LBFGS</code>, which is the default method in the code. The other
methods can be set changing the default optional argument
(e.g. <code>method=:LD_SLSQP</code>).</p>

<p dir="auto">The functions output a <code>type PlmOut</code> (say <code>X</code>) with 4 fields:</p>
<ul dir="auto">
<li><code>X.Jtensor</code>: the coupling matrix <code>J[ri,rj,i,j]</code> a symmetrized
<code>q x q x N x N</code> array, where <code>N</code> is the number of residues in the
multiple sequence alignment, and <code>q</code> is the alphabet "size" (typically
21 for proteins).</li>
<li><code>X.htensor</code>: the external field <code>h[r_i,i]</code> <code>q x N</code> array.</li>
<li><code>X.pslike</code>: the pseudolikelihood</li>
<li><code>X.score</code>:  a  vector of <code>Tuple{Int,Int,Float64}</code> containing the candidate contacts in descending score order (residue1, residue2 , score12).</li>
</ul>
