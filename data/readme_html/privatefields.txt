<p dir="auto">Disables the <code>A.x</code> syntax for fields marked <code>@private</code> when defining a struct.</p>
<p dir="auto">The only way to access these fields is through the (much less ergonomic) <code>getfield</code> function, or through a <code>getter</code> or <code>accessor</code> method you define.</p>
<p dir="auto">Also allows privileged access to fields through another macro on method definitions. This lets us use the dot syntax, but only within the scope of that method and only for particular types we specially annotate</p>

@private_struct struct Foo{X,Y}
    @private x::X
    y::Y
end

foo1 = Foo(3.0, 4.0)
foo2 = Foo(5, 6)

# 4-colon syntax denotes that only f1 should allow private access to fields
@private_method f(f1::::Foo, f2::Foo) = f1.x + f2.y
g(f1::Foo, f2::Foo) = f1.x + f2.y

f(foo1, foo2) # 9.0

g(foo1, foo2) # ERROR: PrivacyError: Attempted to directly access private field Foo.x outside private context"><pre><span class="pl-c"><span class="pl-c">#</span> @private denotes the private fields</span>
