<p dir="auto"><strong>IOStructs</strong> is a Julia package that helps write structs which represent (part of) a file format.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Custom Readers/Writers</h3><a id="user-content-custom-readerswriters" class="anchor" aria-label="Permalink: Custom Readers/Writers" href="#custom-readerswriters"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If you want to use a field with a type that doesn't have defined <code>Base.read</code>/<code>Base.write</code> methods, you can provide your own.  The syntax is:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="# Provide a custom reader only
field::Type = read_expr

# Provide custom reader and writer
field::Type = [read_expr, write_expr]"><pre class="notranslate"><code># Provide a custom reader only
field::Type = read_expr

# Provide custom reader and writer
field::Type = [read_expr, write_expr]
</code></pre></div>
<p dir="auto">where</p>
<ul dir="auto">
<li><code>read_expr</code> is an expression that reads the field from an <code>io::IO</code> object.  This expression can use any field names defined before it in the struct.</li>
<li><code>write_expr</code> is an object that will be written via <code>Base.write(io, write_expr)</code>.  This expression can use all of the field names.</li>
</ul>
<p dir="auto">Note that both <code>read_expr</code> and <code>write_expr</code> are evaluated in the context of the struct, so you can refer to other fields.  Additionally, the <code>read_expr</code> has access to the <code>io</code> object.</p>

<p dir="auto">The <code>IOStructs.roundtrip</code> is a simple function that writes a struct to a stream and reads it back in.  It's useful for testing that the <code>Base.read</code> and <code>Base.write</code> methods are working correctly.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto"><code>Reserved{N}</code> and <code>Skip{N}</code></h3><a id="user-content-reservedn-and-skipn" class="anchor" aria-label="Permalink: Reserved{N} and Skip{N}" href="#reservedn-and-skipn"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Sometimes file formats have reserved or unused sections.  Both <code>Reserved</code> and <code>Skip</code> are used to represent these sections.  The difference is that:</p>
<ul dir="auto">
<li>For <code>Reserved{N}</code>, the underlying data is stored as a <code>NTuple{N, UInt8}</code>.</li>
<li>For <code>Skip{N}</code>, the underlying data is not stored at all.  Writing a <code>Skip{N}</code> will write <code>0x00</code> <code>N</code> times.</li>
</ul>
