<p dir="auto">JOS (Julia Object System) is an extension to the Julia Programming language that supports classes and meta-classes, multiple inheritance and generic functions with multiple-dispatch methods.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Introduction</h3><a id="user-content-introduction" class="anchor" aria-label="Permalink: Introduction" href="#introduction"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A Meta-Object Protocol (MOP) mediates the behavior of an object-oriented system, e.g., the instantiation of objects (and, therefore, classes), inheritance from superclasses, and method invocation. The Smalltalk language was the first to propose a metaobject protocol, which was mostly used to manage the creation of instances of classes. The Common Lisp Object System (CLOS) went much farther, but its MOP is considerably more complex, in particular, because of CLOS’ support for multiple inheritance, generic functions, and multiple-dispatch methods.
Unfortunately, it is usually diﬀicult to implement MOPs in programming languages that were not designed to be extended and this has been one of the biggest obstacles for the wider acceptance of MOPs. There are programming languages, however, that allow language extensions and Julia is one of them.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Goals</h3><a id="user-content-goals" class="anchor" aria-label="Permalink: Goals" href="#goals"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The main goal is to implement JOS, the Julia Object System, an extension to the Julia programming language that supports classes and metaclasses, multiple inheritance, and generic functions with multiple-dispatch methods. The implementation should follow the way those ideas were implemented in CLOS, in particular, in what regards the CLOS MOP.
It is important to note that Julia already provides its own version of generic functions and multiple dispatch methods but it does not support classes or inheritance (much less, multiple inheritance). This means that you will need to implement your own version of these concepts, although you might find it advantageous to use the ones already available in Julia to support your implementation in a meta-circular style.
To implement JOS, it is important to first understand how CLOS operates. At the end of this document you will find multiple references explaining CLOS. You might also find it useful to look at different implementations of CLOS and of its derivatives, such as PCL - The Portable implementation of CLOS, for Common Lisp, Tiny-CLOS, for Scheme, Swindle, for Racket. The Dylan programming language is also an important source of ideas. As is usual nowadays, there is a large amount of information available online.
In the rest of this document, whenever we mention the concepts of generic function or method, we are referring to the ones you need to implement and not to those of Julia. Whenever we mention the concept of function (the non-generic variety), we are referring to Julia’s generic functions.
This document also includes multiple examples of the use of JOS. To shorten the output, arrays will be printed in simplified form, avoiding the element type and with an horizontal layout. Moreover, when only a fraction of the array is relevant for the example, we will use ... for the remaining, unspecified, elements, as in [a, b, ...].
You must implement, at the very least, the features described in the following sections:</p>
<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Classes</h4><a id="user-content-classes" class="anchor" aria-label="Permalink: Classes" href="#classes"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Classes are created using the macro <strong>@defclass</strong> that, in its simplest form, takes the name of the class to define, a possibly empty vector of superclasses, and a possibly empty vector of slot names.
Here is one class to implement complex numbers in rectangular representation:</p>
<p dir="auto"><code>@defclass(ComplexNumber, [], [real, imag])</code></p>
<p dir="auto">Note that an empty vector of superclasses is equivalent to a vector containing the Object class. Besides creating the class, a <strong>@defclass</strong> form also creates a global variable with the same name of the class that references the class, allowing it to be used to create instances of that class.</p>

<p dir="auto">To create instances of a class, the <strong>new</strong> function is used. This function takes, as mandatory argument, the class to instantiate, and as keyword arguments, the values of the slots to initialize.
For example, we can create an instance of the previous class and assign it to variable c1 using the following expression:</p>
<p dir="auto"><code>c1 = new(ComplexNumber, real=1, imag=2)</code></p>

<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Generic Functions and Methods</h4><a id="user-content-generic-functions-and-methods" class="anchor" aria-label="Permalink: Generic Functions and Methods" href="#generic-functions-and-methods"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">A generic function is defined using the macro <strong>@defgeneric</strong>, as follows:</p>
<p dir="auto"><code>@defgeneric add(a, b)</code></p>
<p dir="auto">Note that a generic function does not specify behavior. That is the role of methods.
A method is defined using the macro <strong>@defmethod</strong>, as follows:</p>
<p dir="auto"><code>@defmethod add(a::ComplexNumber, b::ComplexNumber) = new(ComplexNumber, real=(a.real + b.real), imag=(a.imag + b.imag))</code></p>
<p dir="auto">The method definition should have the same parameters as the corresponding generic function, each one typed with the class to which it applies. An omitted type means that the parameter has the most generic type, i.e., <strong>Top</strong>.
When a method is defined, if the corresponding generic function does not exists, it is automatically created using, as parameters, the names of the parameters of the method.</p>

<p dir="auto"><code>@defgeneric print_object(obj, io)</code></p>

<p dir="auto">As is visible in the previous interaction, <strong>ComplexNumber</strong> is an instance of <strong>Class</strong>. Additionally, <strong>Class</strong> is also an instance of <strong>Class</strong>, i.e., it is its own class. <div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Class Options</h4><a id="user-content-class-options" class="anchor" aria-label="Permalink: Class Options" href="#class-options"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">As mentioned before, classes are created using the macro <strong>@defclass</strong>. However, the macro supports additional options that are important to know. In fact, the macro takes the name of the class to define, a possibly empty vector of superclasses, a possibly empty vector of slot definitions with corresponding options, and, optionaly, a metaclass specification.
Here is one example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@defclass(Person, [],
    [[name, reader=get_name, writer=set_name!],

    [friend, reader=get_friend, writer=set_friend!]],
    metaclass=UndoableClass)"><pre><span class="pl-c1">@defclass</span>(Person, [],
    [[name, reader<span class="pl-k">=</span>get_name, writer<span class="pl-k">=</span>set_name!],
    [age, reader<span class="pl-k">=</span>get_age, writer<span class="pl-k">=</span>set_age!, initform<span class="pl-k">=</span><span class="pl-c1">0</span>],

<p dir="auto">Once again, note that an empty vector of superclasses is equivalent to a vector containing the <strong>Object</strong> class.
In the class definition, each slot is described by a vector containing the name of the slot followed by a possibly empty sequence of keyword arguments specifying readers, writers, and initforms, as exemplified above. Note that a slot without <strong>initform</strong> is equivalent to a slot with <strong>missing</strong> as <strong>initform</strong>.
To simplify class definitions, an explicit <strong>initform</strong> option can be replaced by an equivalent slot initialization. This means that, instead of writing the explicit slot definition</p>
<p dir="auto"><code>[foo, reader=get_foo, writer=set_foo!, initform=123]</code></p>
<p dir="auto">one can write the shorter, but equivalent definition</p>
<p dir="auto"><code>[foo=123, reader=get_foo, writer=set_foo!]</code></p>
<p dir="auto">Additionally, if no other options are provided, the definition can be further simplified by droping the vector syntax. This means that <strong>foo=123</strong> is equivalent to <strong>[foo, initform=123]</strong> and <strong>foo</strong> is equivalent to <strong>[foo]</strong>.
The metaclass option is used to specify the class of the class being defined, i.e., the metaclass of the class’ instances.
Besides creating the class, a @defclass form also creates a global variable with the same name of the class that references the class, as demonstrated in the following interaction:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; Person

<span class="pl-k">&lt;</span>UndoableClass Person<span class="pl-k">&gt;</span></pre></div>
<p dir="auto">Notice how classes are printed. That happens because there is a default printing method specialized for classes:</p>
<p dir="auto"><code>@defmethod print_object(class::Class, io) = print(io, "&lt;$(class_name(class_of(class))) $(class_name(class))&gt;")</code></p>

<div class="markdown-heading" dir="auto"><h4 class="heading-element" dir="auto">Generic Function Calls</h4><a id="user-content-generic-function-calls" class="anchor" aria-label="Permalink: Generic Function Calls" href="#generic-function-calls"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The application of a generic function to concrete arguments, by default, involves multiple steps. Given a generic function gf and a list of arguments args, the default behavior executes the following steps: (1) selects the set of applicable methods of gf, (2) sorts them according to their specificity, and, finally, (3) applies the most specific method to args while allowing that method to call the
next most specific method using the <strong>call_next_method</strong> function. If there is no applicable method, the generic function <strong>no_applicable_method</strong> is called, using the gf and args as its two arguments. The default behavior of that function is to raise an error.
As an example, considering the previous method definition for the generic function <strong>add</strong>, the following interaction should be expected:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="&gt; add(123, 456)
ERROR: No applicable method for function add with arguments (123, 456)"><pre><span class="pl-k">&gt;</span> <span class="pl-c1">add</span>(<span class="pl-c1">123</span>, <span class="pl-c1">456</span>)
ERROR<span class="pl-k">:</span> No applicable method <span class="pl-k">for</span> <span class="pl-k">function</span> add with arguments (<span class="pl-c1">123</span>, <span class="pl-c1">456</span>)</pre></div>

<p dir="auto">You might assume that precedence among applicable methods is determined by left-to-right consideration of the parameter types. <p dir="auto">To support multiple inheritance, it is necessary to compute the class <em>precedence list</em> of a class. The generic function <strong>compute_cpl</strong> computes it for any class given as an argument. The result is an array that contains the class itself followed by a linearization of the class’s superclass graph, i.e., the set of classes that are reachable from that class by following the superclass relation. The default behavior is to do that linearization in a <em>breadth-first</em> manner. As an example, consider the following hierarchy:</p>

<p dir="auto">The critical aspect of this work is the support for metaobject protocols. In fact, most of the behavior of the system is controled by generic functions specialized in different metaclasses. These generic functions include the allocation of objects (<strong>allocate_instance</strong>), the initialization of objects (<strong>initialize</strong>), the computation of the class precedence list (<strong>compute_cpl</strong>), etc. The following
sections illustrate the use of some of these protocols.</p>
<div class="markdown-heading" dir="auto"><h5 class="heading-element" dir="auto">Class Instantiation Protocol</h5><a id="user-content-class-instantiation-protocol" class="anchor" aria-label="Permalink: Class Instantiation Protocol" href="#class-instantiation-protocol"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The non-generic function <strong>new</strong> is responsible for creating instances of classes (and, therefore, also instances of metaclasses, i.e., classes). It receives the class to instantiate and a series of keyword arguments, calls the generic functions <strong>allocate_instance</strong> to create the non-initialized instance, and then calls the generic function <strong>initialize</strong> to initialize it using the keyword arguments. It is because JOS’ generic functions do not support keyword arguments that new is non-generic. Its definition is as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="new(class; initargs...) =

    end"><pre><span class="pl-en">new</span>(class; initargs<span class="pl-k">...</span>) <span class="pl-k">=</span>

        <span class="pl-c1">initialize</span>(instance, initargs)
        instance

<p dir="auto">To allow flexibility in the representation of instances, for example, to support the dictionary-based approach used in Python, it is necessary to have a protocol that mediates the way slots are accessed. Diferently from the CLOS MOP that calls the generic function <strong>slot-value-using-class</strong> every time an instance’s slot is accessed, JOS uses a more eﬀicient approach, calling the generic function <strong>compute_getter_and_setter</strong> just once (at class initialization time) for each different slot. This function receives the class object, the slot name, and an index corresponding to the position of that slot in the slots of the class. This index should be used for array-based representations of instances but might be ignored for dictionary-based representations. The generic function must return a tuple of non-generic functions, where the first one gets the value of a slot and the second
one sets the value of a slot. The first function takes an instance as an argument while the second one takes an instance and a new value to place in the corresponding slot.
As a complete example of the use of this protocol, consider the problem of creating <em>undoable classes</em>. First, we present the support code:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="undo_trail = []

<div class="markdown-heading" dir="auto"><h5 class="heading-element" dir="auto">Class Precedence List Protocol</h5><a id="user-content-class-precedence-list-protocol" class="anchor" aria-label="Permalink: Class Precedence List Protocol" href="#class-precedence-list-protocol"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">When a class is initialized, its class precedence list is computed by calling the generic function <strong>compute_cpl</strong> with the class object and is then cached in the class object. The default behavior, implemented on the specialization of the generic function for instances of <strong>Class</strong>, is to produce the linearization of the class graph that is reachable from the class by following the superclass relation in a breadth-first manner. This is similar but not entirely identical to the approaches used in CLOS or in Dylan, which use more complex algorithms.
The good news is that the pre-defined behavior is not the only one that is possible. As an example, we will implement the Flavors approach to the class precedence list, which requires a depth-first walk of the inheritance graph, from left to right, with duplicates removed from the right and with <strong>Object</strong> and <strong>Top</strong> appended on the right.
Given that we just want to change the way the <strong>compute_cpl</strong> operates, while preserving the existing behavior for the remaining protocols, we start by creating a new (meta)class that inherits from <strong>Class</strong>:</p>
<p dir="auto"><code>@defclass(FlavorsClass, [Class], [])</code></p>
<p dir="auto">We then specialize the generic function <strong>compute_cpl</strong> so that, for classes that are instances of <strong>FlavorsClass</strong>, the class precedence list is computed according to the Flavors strategy:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@defmethod compute_cpl(class::FlavorsClass) =
    let depth_first_cpl(class) =
            [class, foldl(vcat, map(depth_first_cpl, class_direct_superclasses(class)), init=[])...],
        base_cpl = [Object, Top]
        vcat(unique(filter(!in(base_cpl), depth_first_cpl(class))), base_cpl)
    end"><pre><span class="pl-c1">@defmethod</span> <span class="pl-en">compute_cpl</span>(class<span class="pl-k">::</span><span class="pl-c1">FlavorsClass</span>) <span class="pl-k">=</span>
    <span class="pl-k">let</span> <span class="pl-en">depth_first_cpl</span>(class) <span class="pl-k">=</span>
            [class, <span class="pl-c1">foldl</span>(vcat, <span class="pl-c1">map</span>(depth_first_cpl, <span class="pl-c1">class_direct_superclasses</span>(class)), init<span class="pl-k">=</span>[])<span class="pl-k">...</span>],
        base_cpl <span class="pl-k">=</span> [Object, Top]
        <span class="pl-c1">vcat</span>(<span class="pl-c1">unique</span>(<span class="pl-c1">filter</span>(<span class="pl-k">!</span><span class="pl-c1">in</span>(base_cpl), <span class="pl-c1">depth_first_cpl</span>(class))), base_cpl)
    <span class="pl-k">end</span></pre></div>
