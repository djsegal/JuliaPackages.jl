<p dir="auto">Satisfiability.jl is a package for representing satisfiability modulo theories (SMT) problems in Julia. This package provides a simple front-end interface to common SMT solvers, including full support for vector-valued and matrix-valued expressions. Currently, the theories of propositional logic, uninterpreted functions, Integers, Reals and fixed-size BitVectors are supported. We will eventually add support for all <a href="http://smtlib.cs.uiowa.edu/theories.shtml" rel="nofollow">SMT-LIB standard theories</a>.</p>
<p dir="auto">What you can do with this package:</p>
<ul dir="auto">
<li>Cleanly specify SMT expressions using Julia's built-in broadcasting and iteration capabilities to write concise expressions.</li>
<li>Generate files in the <a href="http://www.smtlib.org/" rel="nofollow">SMT-LIB</a> specification language.</li>
<li>Interact with any solver that follows the SMT-LIB standard. We test with Z3, CVC5, and Yices.</li>
</ul>
<p dir="auto">You can read the documentation <a href="https://elsoroka.github.io/Satisfiability.jl/" rel="nofollow">here</a>.</p>

<p dir="auto">An uninterpreted function is a function where the input-to-output mapping isn't known. The task of the SMT solver is to find this mapping such that some logical statements hole true. Let's find out if there exists a function <code>f(x)</code> such that <code>f(f(x)) == x</code>, <code>f(x) == y</code> and <code>x != y</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="@satvariable(x, Bool)
@satvariable(y, Bool)
@uninterpreted(f, Bool, Bool)

status = sat!(distinct(x,y), f(x) == y, f(f(x)) == x, solver=Z3())
println(&quot;status = $status&quot;)"><pre><span class="pl-c1">@satvariable</span>(x, Bool)
<span class="pl-c1">@satvariable</span>(y, Bool)
<span class="pl-c1">@uninterpreted</span>(f, Bool, Bool)

status <span class="pl-k">=</span> <span class="pl-c1">sat!</span>(<span class="pl-c1">distinct</span>(x,y), <span class="pl-c1">f</span>(x) <span class="pl-k">==</span> y, <span class="pl-c1">f</span>(<span class="pl-c1">f</span>(x)) <span class="pl-k">==</span> x, solver<span class="pl-k">=</span><span class="pl-c1">Z3</span>())
<span class="pl-c1">println</span>(<span class="pl-s"><span class="pl-pds">"</span>status = <span class="pl-v">$status</span><span class="pl-pds">"</span></span>)</pre></div>
<p dir="auto">The problem is <code>:SAT</code>, so there is such a function! Since the satisfying assignment for an uninterpreted function is itself a function, Satisfiability.jl sets the value of <code>f</code> to this function. Now calling <code>f(value)</code> returns the value of this satisfying assignment.</p>
