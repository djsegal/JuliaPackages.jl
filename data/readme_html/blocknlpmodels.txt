<p dir="auto">This package provides a modeling framework based on <a href="https://github.com/JuliaSmoothOptimizers/NLPModels.jl">NLPModels.jl</a> for block structured nonlinear optimization problems (NLPs) in Julia. Specifically, one can use this package to model NLPs of the following form:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$$
\begin{array}{ll}
\displaystyle \mathop{\mathrm{minimize}}\limits_{x}  &amp; \displaystyle \sum\limits_{i \in B} f_i(x_i) \\
\displaystyle \mathrm{subject\ to} &amp; \displaystyle x_i \in X_i := \left\{x_i \in \mathbb{R}^{m_i}: c_{ij} (x) = 0, \ j \in E_i, \ c_{ij}(x) \geq 0, \ j \in I_i \right\}, \ \ i \in B, \\
&amp; \displaystyle \sum_{i \in B} A_i x_i = b,
\end{array}
$$</math-renderer></p>
<p dir="auto">where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$B$</math-renderer> is the set of variable blocks, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$X_i$</math-renderer> is the domain of the <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$i^\mathrm{th}$</math-renderer> variable block <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$x_i$</math-renderer> consisting of a set <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$E_i$</math-renderer> of equality constraints, and a set <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$I_i$</math-renderer> of inequality constraints. All functions <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$f_i$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$c_{ij}$</math-renderer> are assumed to be smooth, real-valued functions that can be nonlinear and noconvex. Note that the constraints linking the variable blocks must be linear.</p>
<p dir="auto">In this package, block structured NLPs of the above form are represented by an instance of <code>AbstractBlockNLPModel</code>.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Quickstart Guide</h2><a id="user-content-quickstart-guide" class="anchor" aria-label="Permalink: Quickstart Guide" href="#quickstart-guide"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Suppose we want to model the following NLP that can be decomposed into three univariate blocks:</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$$
\begin{array}{ll}
\displaystyle \mathop{\mathrm{minimize}}\limits_{x_1, x_2, x_3} &amp; \displaystyle \sum\limits_{i=1}^3 (x_i - a_i)^2 \\
\displaystyle \mathrm{subject\ to} &amp; \displaystyle 0 \leq x_i \leq 1, \ \ i \in \{ 1, 2, 3 \} \\
&amp; \displaystyle \sum\limits_{i=1}^3 x_i = b,
\end{array}
$$</math-renderer></p>
<p dir="auto">where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$a_1, a_2, a_3$</math-renderer> and <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$b$</math-renderer> are some scalar constants.</p>
<p dir="auto">We start by initializing an empty <code>BlockNLPModel</code>:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="blocknlp = BlockNLPModel()"><pre>blocknlp <span class="pl-k">=</span> <span class="pl-c1">BlockNLPModel</span>()</pre></div>
<p dir="auto">Next, we add the NLP blocks to <code>blocknlp</code>. For this step, the subproblems need to be made available as <code>AbstractNLPModel</code> objects. Assuming that <code>nlp_blocks</code> is a 3-element vector containing the three NLP blocks of our example above, we add these blocks to <code>blocknlp</code> by using the <code>add_block!</code> function as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="for i in 1:3
    add_block!(blocknlp, nlp_blocks[i])
end"><pre><span class="pl-k">for</span> i <span class="pl-k">in</span> <span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">3</span>
    <span class="pl-c1">add_block!</span>(blocknlp, nlp_blocks[i])
<span class="pl-k">end</span></pre></div>
<p dir="auto">Once the blocks have been added the next step is to add the linking constraints. For this, we make use of the <code>add_links!</code> method in this package. This is defined as follows:</p>
<p dir="auto"><code>add_links!(block_nlp_model, n_constraints, links, rhs_constants)</code>, where</p>
<ul dir="auto">
<li><code>block_nlp_model</code> is an instance of <code>BlockNLPModel</code></li>
<li><code>n_constraints</code> is the number of linking constraints that are being added to <code>block_nlp_model</code></li>
<li><code>links</code> is a dictionary that specifies which block is being linked with what coefficients</li>
<li><code>rhs_constants</code> is the right-hand-side vector for the linking constraints</li>
</ul>
<p dir="auto">For our example above, we add the linking constraint as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="add_links!(blocknlp, 1, Dict(1 =&gt; [1.], 2 =&gt; [1.], 3 =&gt; [1.]), b)"><pre><span class="pl-c1">add_links!</span>(blocknlp, <span class="pl-c1">1</span>, <span class="pl-c1">Dict</span>(<span class="pl-c1">1</span> <span class="pl-k">=&gt;</span> [<span class="pl-c1">1.</span>], <span class="pl-c1">2</span> <span class="pl-k">=&gt;</span> [<span class="pl-c1">1.</span>], <span class="pl-c1">3</span> <span class="pl-k">=&gt;</span> [<span class="pl-c1">1.</span>]), b)</pre></div>
<p dir="auto">With this, we have finished modeling the above example as an <code>AbstractBlockNLPModel</code>.</p>
<p dir="auto">In addition to a modeling framework, this package also provides several callback functions to enable easy implementation of several popular NLP decomposition algorithms to efficiently solve large instances of block structured NLPs. We highlight some of the important ones here:</p>
<ol dir="auto">
<li>
<p dir="auto">For the dual decomposition method, one can call <code>DualizedNLPBlockModel</code> for the subproblems to dualize their objective. This method is defined as follows:</p>
<p dir="auto"><code>DualizedNLPBlockModel(nlp, λ, A)</code>, where</p>
<ul dir="auto">
<li>nlp: the subproblem to be dualized as an instance of <code>AbstractNLPModel</code></li>
<li>λ: vector of dual variables corresponding to the linking constraints assosciated with the nlp block <code>nlp</code></li>
<li>A: linking constraint matrix block assosciated with the nlp block <code>nlp</code></li>
</ul>
</li>
</ol>
<p dir="auto">This function will return the dualized block model as an instance of <code>AbstractNLPModel</code>.</p>
<p dir="auto">As an example, suppose for the problem shown above, we wish to dualize the second nlp block. Here we assume that the dual variables are stored in variable <code>y</code>. Dualization can be achieved as follows:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="A = get_linking_matrix_blocks(blocknlp)
dualized_block = DualizedNLPBlockModel(blocknlp.blocks[2].problem_block, y[blocknlp.problem_size.con_counter+1:end], A[2])"><pre>A <span class="pl-k">=</span> <span class="pl-c1">get_linking_matrix_blocks</span>(blocknlp)
dualized_block <span class="pl-k">=</span> <span class="pl-c1">DualizedNLPBlockModel</span>(blocknlp<span class="pl-k">.</span>blocks[<span class="pl-c1">2</span>]<span class="pl-k">.</span>problem_block, y[blocknlp<span class="pl-k">.</span>problem_size<span class="pl-k">.</span>con_counter<span class="pl-k">+</span><span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">end</span>], A[<span class="pl-c1">2</span>])</pre></div>
<ol start="2" dir="auto">
<li>To support the implementation of ADMM, we provide the following callback function:</li>
</ol>
<p dir="auto"><code>AugmentedNLPBlockModel(nlp, y, ρ, A, b, x)</code>, where</p>
<ul dir="auto">
<li>nlp: the subproblem which is to be augmented</li>
<li>y: the dual variables corresponding to the linking constraints</li>
<li>
<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$\rho$</math-renderer>: penalty parameter</li>
<li>A: matrix containing the linking constraint coefficients</li>
<li>b: the right-hand-side vector for the linking constraints</li>
<li>x: current estimate of the primal variables</li>
</ul>
<p dir="auto">The output of this function will be the augmented block model as an instance of <code>AbstractNLPModel</code>.</p>
<p dir="auto">Again, as an illustration, we augment the objective function of the secoond NLP block of the above example problem. We assume <code>x</code> and <code>y</code> are the current estimates of the primal and dual variables, respectively. Further, we assume <code>ρ</code> to be the penalty parameter.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="A = get_linking_matrix(blocknlp)
b = get_rhs_vector(blocknlp)
dualized_block = AugmentedNLPBlockModel(blocknlp.blocks[2], y[blocknlp.problem_size.con_counter+1:end], ρ, A, b, x)"><pre>A <span class="pl-k">=</span> <span class="pl-c1">get_linking_matrix</span>(blocknlp)
b <span class="pl-k">=</span> <span class="pl-c1">get_rhs_vector</span>(blocknlp)
dualized_block <span class="pl-k">=</span> <span class="pl-c1">AugmentedNLPBlockModel</span>(blocknlp<span class="pl-k">.</span>blocks[<span class="pl-c1">2</span>], y[blocknlp<span class="pl-k">.</span>problem_size<span class="pl-k">.</span>con_counter<span class="pl-k">+</span><span class="pl-c1">1</span><span class="pl-k">:</span><span class="pl-c1">end</span>], ρ, A, b, x)</pre></div>
<ol start="3" dir="auto">
<li>We also support the addition of a proximal term to an augmented objective. This can be achieved with the following method:</li>
</ol>
<p dir="auto"><code>ProxAugmentedNLPBlockModel(nlp, y, ρ, A, b, x, P)</code>, where <code>P</code><math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="eda30ef94e9c13eb62af2b715b5a2be8">$, \in \mathbb{R}^{m_i \times m_i}$</math-renderer> is a sparse matrix containing the weights for the proximal term. All other arguments are the same as defined for the <code>AugmentedNLPBlockModel</code> method.</p>
<p dir="auto">This implementation of this method follows the same steps as for the <code>AugmentedNLPBlockModel</code> method. The only difference being the addition of a sparse <code>P</code> matrix which can be defined by making use of the <code>SparseArrays.jl</code> package in Julia.</p>
<ol start="4" dir="auto">
<li>Finally, our package also provides the user an option to convert the <code>AbstractBlockNLPModel</code> into a full-space <code>AbstractNLPModel</code> which can be solved with any general purpose NLP solver. The method for this is as follows:</li>
</ol>
<p dir="auto"><code>FullSpaceModel(block_nlp_model)</code>, where <code>block_nlp_model</code> is an instance of <code>AbstractBlockNLPModel</code>.</p>
<p dir="auto">For example, suppose we desire to solve the three block problem described above with <code>MadNLP.jl</code>. This can be done by executing the following set of commands:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="full_model = FullSpaceModel(blocknlp)
solution = madnlp(full_model)"><pre>full_model <span class="pl-k">=</span> <span class="pl-c1">FullSpaceModel</span>(blocknlp)
solution <span class="pl-k">=</span> <span class="pl-c1">madnlp</span>(full_model)</pre></div>
<p dir="auto">assuming that <code>MadNLP.jl</code> has already been imported in the environment.</p>
