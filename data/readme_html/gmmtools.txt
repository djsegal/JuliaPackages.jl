<p dir="auto"><em>Preliminary/In progress.</em></p>
<p dir="auto">A toolbox for generalized method of moments (GMM) with functionality aimed at streamlining estimating models that have long runtime, using parallel computing.</p>
<p dir="auto">This package takes care of several `menial' tasks: saving and loading estimation results from files, seamlessly continuing long-running jobs that failed mid-estimation, creating publication-ready tables using RegressionTables.jl. The package gives special attention to the optimizer "backend" used to minimize the GMM objective function, and several options are available.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Key Features</h2><a id="user-content-key-features" class="anchor" aria-label="Permalink: Key Features" href="#key-features"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Core estimation features:</p>
<ol dir="auto">
<li>one- and two-step GMM estimation</li>
<li>nonlinear optimizer: support for Optim.jl and LsqFit.jl backends, multiple initial conditions, box constraints, automatic differentiation (AD)</li>
<li>inference: (1) asymptotic i.i.d. and (2) Bayesian (weighted) bootstrap</li>
</ol>
<p dir="auto">Convenience features:</p>
<ol dir="auto">
<li>integrated with RegressionTables.jl for publication-quality tables</li>
<li>efficiently resume estimation based on incomplete results (e.g. when bootstrap run #63, or initial condition #35, fails or runs out of time or out of memory after many hours)</li>
<li>parallel over initial conditions (embarrassingly parallel using <code>Distributed.jl</code>)</li>
<li>parallel bootstrap</li>
<li>suitable for running on computer clusters (e.g. using slurm)</li>
<li>simple option to normalize parameters before they are fed to the optimizer</li>
<li>simple example to estimate a subset of parameters and use fixed values for the others (works with AD)</li>
</ol>

<p dir="auto"><code>GMMTools.fit(...)</code> saves the estimation results in two files: <code>fit.csv</code> contains a table with one row per set of initial conditions, and <code>fit.json</code> contains several estimation parameters and results. <code>GMMTools.write(myfit::GMMFit, opts::GMMOptions; subpath="fit")</code> is the lower level function to write <code>GMMFit</code> objects to files.</p>
<p dir="auto"><code>GMMTools.vcov_simple(...)</code> saves a <code>vcov.json</code> file that includes, among other objects, the variance-covariance matrix <code>myfit.vcov.V</code>. <code>GMMTools.vcov_bboot(...)</code> also saves two files <code>vcov_boot_fits_df.csv</code> (all individual runs for all bootstrap runs) and <code>vcov_boot_weights.csv</code> (rows are bootstrap runs, columns are data observations). The lower level function is <code>GMMTools.write(myvcov::GMMvcov, opts::GMMOptions; subpath="vcov")</code>.</p>
<p dir="auto"><code>GMMTools.read_fit(full_path; subpath="fit", show_trace=false)</code> reads estimation results and loads them into a <code>GMMFit</code> object. <code>GMMTools.read_vcov(full_path; subpath="vcov", show_trace=false)</code> reads vcov results and loads them into a <code>GMMvcov</code> object. Note that <code>GMMTools.read_fit()</code> attempts to also read the vcov from the same folder. Otherwise, read the vcov separately and attach it using</p>

<p dir="auto">By default, any error during optimization stops the entire estimation (or inference) command.</p>
<p dir="auto">Set the <code>GMMOptions</code> field <code>throw_errors=false</code> to capture these errors and write them to file, but not interrupt the rest of the estimation procedure.</p>
<ul dir="auto">
<li>when using multiple initial conditions, all iterations that error are recorded in <code>myfit.fits_df</code> with <code>errored=true</code> and <code>obj_value=Inf</code>. If all iterations error, we have <code>myfit.errored=true</code> and several other fields are recorded as <code>missing</code></li>
<li>for bootstrap results, similar rules apply. Note that inference objects (SEs, vcov, etc.) are computed dropping the bootstrap runs that errored. <code>@warn</code> messages should be displayed to remind the user that this is happenening. It is the user's responsibility to ensure this behavior is ok for their use case.</li>
</ul>

<p dir="auto"><strong>Scaling parameters.</strong> The <code>theta_factors</code> option in <code>GMMOptions()</code> requests that the parameters be scaled before feeding them to the optimizer. Parameter theta[i] will be replaced by theta[i] * theta_factors[i] before optimization. Rule of thumb: if <code>theta[i]</code> is on the order of <code>10^M</code>, pick <code>theta_factor[i] = 10^(-M)</code>.</p>
<p dir="auto">Example. Suppose <code>theta = [alpha, beta]</code> and we expect <code>alpha</code> to be between 0 and 1 while <code>beta</code> to be on the order of 0 to 1000. In general (not always) it's a good idea to scale <code>beta</code> down to approximately 0 to 1, which will ensure that the optimizer "cares" similarly about <code>alpha</code> and <code>beta</code>. (This also helps to make sense of magnitude of the default optimizer tolerance for theta, typically called <code>x_tol</code>.) We achieve this simply by selecting <code>theta_factors=[1.0, 0.001]</code>. All other inputs and outputs should have the original magnitudes: initial conditions <code>theta0</code> and final estimates <code>myfit.theta_hat</code>.</p>
<p dir="auto"><strong>Estimating a subset of parameters.</strong> See <a href="https://github.com/Gkreindler/GMMTools.jl/blob/main/examples/example_ols_parallel.jl">examples/example_ols_fixed.jl</a></p>
