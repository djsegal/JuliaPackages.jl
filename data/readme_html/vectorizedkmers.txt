<p dir="auto">VectorizedKmers.jl is a Julia package primarily designed for fast <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-mer counting of biological sequences. The core idea is that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-mers with an alphabet size of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$N$</math-renderer> are essentially integers in base <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$N$</math-renderer>, and can be used as indices in a vector of size <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$N^K$</math-renderer> to count the corresponding <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-mers.</p>
<p dir="auto">This data structure can be used to quickly approximate distances between sequences. Notably, the squared Euclidean distance was used to approximate edit distance in <a href="https://doi.org/10.1093/nar/gkz657" rel="nofollow">this paper</a>. The dot product has also proven to be a useful metric for comparing correlation between sequences.</p>

<p dir="auto">The main downside of counting <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-mers this way is that the arrays grow exponentially with respect to <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>. The 31-mer array of a DNA sequence would have a length of <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$4^{31} = 4,611,686,018,427,387,904$</math-renderer>, which is equivalent to four exbibytes of memory, if the values are stored with 8-bit integers — which is just not feasible, really. Not only does allocating a lot of memory take up a lot of memory, but it can also take a substantial amount of time! This method of counting <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-mers therefore works best for lower <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="f7cf3eea85040cc0ced20db5b25e2c9f">$K$</math-renderer>-values.</p>
