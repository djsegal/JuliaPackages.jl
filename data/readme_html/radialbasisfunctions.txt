<ol dir="auto">
<li>
<p dir="auto">A critical dependency of this package is <a href="https://github.com/KristofferC/NearestNeighbors.jl">NearestNeighbors.jl</a> which requires that the dimension of each data point is inferrable. To quote from NearestNeighbors.jl:</p>
<blockquote>
<p dir="auto">The data, i.e., the points to build up the tree from. It can either be</p>
<ul dir="auto">
<li>a matrix of size nd × np with the points to insert in the tree where nd is the dimensionality of the points and np is the number of points</li>
<li>a vector of vectors with fixed dimensionality, nd, which must be part of the type. Specifically, data should be a Vector{V}, where V is itself a subtype of an AbstractVector and such that eltype(V) and length(V) are defined. (For example, with 3D points, V = SVector{3, Float64} works because eltype(V) = Float64 and length(V) = 3 are defined in V.)</li>
</ul>
</blockquote>
<p dir="auto">That said, we currently only support the second option here (<code>Vector{AbstractVector}</code>), but plan to support matrix inputs in the future.</p>
</li>
<li>
<p dir="auto"><code>Interpolator</code> uses all points, but there are plans to support local collocation / subdomains like the operators use.</p>
</li>
</ol>
