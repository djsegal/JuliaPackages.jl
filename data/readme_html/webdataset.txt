<p dir="auto">WebDataset is a standard for representing dataset for training deep learning and machine learning models, with other implementation in Python <a href="http://github.com/tmbdev/webdataset">github.com/tmbdev/webdataset</a> and Go <a href="http://github.com/tmbdev/tarp">github.com/tmbdev/tarp</a>.</p>
<p dir="auto">WebDataset solves the small files problem and enables massively parallel and high bandwidth I/O for training on both small and very large (petascale) datasets.</p>
<p dir="auto">This is a first cut at a Julia implementation, taking advantage of Julia's multithreading.</p>

<p dir="auto">WebDatasets consists of a collection of tar files ("shards"). Each tar file is read sequentially, and multiple shards may be read in parallel.</p>
<p dir="auto">Within each tar file, files with a common basename but different extensions are grouped together into training samples. The "basename" is defined here as the directory name plus the file name up to the first "." in the file name.</p>
<p dir="auto">Training samples for learning stereo models might contain a sequence of samples of the form:</p>

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Creating Datasets</h1><a id="user-content-creating-datasets" class="anchor" aria-label="Permalink: Creating Datasets" href="#creating-datasets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Since WebDatasets are just tar files, you can use many different tools to create and process them. All you need to make sure is that files that belong to the same training sample are adjacent to each other and have the same basename.</p>
<p dir="auto">If your data is already laid out like that on the file system, you can use <code>tar --sorted</code>:</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="$ tar --sort=name -cf - dataset &gt; dataset.tar"><pre>$ tar --sort=name -cf - dataset <span class="pl-k">&gt;</span> dataset.tar</pre></div>
<p dir="auto">You can also use the <code>tarp create</code> command (at <a href="http://github.com/tmbdev/tarp">github.com/tmbdev/tarp</a>) with a recipe file, use <code>tarp split</code> to split large datasets into multiple shards, and <code>tarp shuffle</code> to shuffle datasets.</p>
<p dir="auto">And you can use Python or Julia scripts to write such files directly. For example, <a href="https://github.com/tmbdev/webdataset-lightning/blob/main/makeshards.py">makeshards.py</a> uses some existing PyTorch code to quickly convert Imagenet data into sharded tar files.</p>

<p dir="auto">This says that every file ending in <code>.cls</code> should be decoded with the <code>clsdecode</code> function and every file ending in <code>.json</code> should be decoded using <code>jsondecode</code>. Files matching the regular expression should have their matching portion renamed to <code>.img</code> and should be decoded using the <code>imdecode</code> function.</p>
<p dir="auto">Decoder functions should take <code>UInt8</code> arrays containing the binary file content and decode into whatever data structure is desired. Augmentation functions take the decoded outputs as inputs and produce new outputs. Collating functions take a list of decoded items (e.g., all files ending in <code>.img</code>) and can, for example, stack them together into arrays.</p>

Collating transforms that array of images into a single array representing the entire batch. Here, we're using the <code>Flux.batch</code> function for that.</p>

<p dir="auto">The <code>dataloader</code> function gives you one particular way of multithreaded data loading and augmentation. It is built from a number of simple iterators that you can reuse and recombine in other ways if you like. You can also use distributed computing for distributed loading and augmentation. The core functionality is expressed by this composition of iterators:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# open either a file or a pipe: source
