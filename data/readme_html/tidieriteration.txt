<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">What is TidierIteration.jl?</h2><a id="user-content-what-is-tidieriterationjl" class="anchor" aria-label="Permalink: What is TidierIteration.jl?" href="#what-is-tidieriterationjl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">TidierIteration.jl is a 100% Julia implementation of the <code>purrr</code> R package. It aims to ease the different ways to map functions to Julia objects: Arrays, Dicts, and so on. It also provides some tools of functional programming: adverbs, composition, safe-functions and more.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Comparison to <code>purrr</code></h2><a id="user-content-comparison-to-purrr" class="anchor" aria-label="Permalink: Comparison to purrr" href="#comparison-to-purrr"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In R <a href="https://purrr.tidyverse.org/" rel="nofollow"><code>purrr</code> package</a>, there are many ways to apply a function to each element of a set: the many <code>map_</code> variants (<code>map_lgl</code> returns a vector of logicals, <code>map_chr</code> returns a vector of strings/characters, etc) and so on exist because the <code>map</code> function returns a <code>list</code> in R, which is a wild beast (R lists allow any kind of elements, and few functions are optimized (i.e. vectorized) on them as opposed to vectors). In comparison, R vectors are always of just one type (integers, booleans, etc.)</p>
<p dir="auto">In Julia, arrays are already the most general structure in the sense that they can contain any kind of element. Arrays of just one type (say, integers) are still arrays. We don't need the <code>_lgl</code> and <code>_chr</code> variants.</p>
<p dir="auto">Besides that, the name <code>map</code> is already taken in Julia and its arguments are fatally in the opposite order of the purrr <code>map</code>! Because of that, we decided to implement the <code>map_tidy</code> function, which takes an iterable object <code>x</code> as the first argument and a function <code>f</code> as the second. <code>map_tidy(x, f)</code> means that for each element of <code>x</code>, we want to apply the function <code>f</code> and return an array.</p>
<p dir="auto">So, instead of defining a function like <code>map_int</code> in Julia, you can just type:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="map_tidy(x, Int ∘ f)"><pre><span class="pl-c1">map_tidy</span>(x, Int <span class="pl-k">∘</span> f)</pre></div>
<p dir="auto">or, even better, let <code>f</code> return an integer.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Why use <code>TidierIteration</code> then?</h3><a id="user-content-why-use-tidieriteration-then" class="anchor" aria-label="Permalink: Why use TidierIteration then?" href="#why-use-tidieriteration-then"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto">The object <code>x</code> is always the first element of the <code>map_*</code> family, so it's easy to pipe them;</p>
</li>
<li>
<p dir="auto">We extend the <code>map_*</code> family to Julia objects which are not <code>map</code>ped by default, like dictionaries, for which we have <code>map_values()</code> and <code>map_keys()</code>;</p>
</li>
<li>
<p dir="auto">We also provide the <code>map2</code>, <code>imap</code> and <code>pmap</code> methods to <code>map</code> over 2 or n elements at the same time;</p>
</li>
<li>
<p dir="auto">We provide the <code>flatten_*</code> functions to tidy wild dictionaries (like JSON responses from APIs) and many adverbs.</p>
</li>
</ul>
