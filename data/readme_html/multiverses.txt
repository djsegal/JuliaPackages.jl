<p dir="auto">A multiverse analysis aims to investigate the robustness of a scientific claim to variations in the data analysis process, such as choices in the measurement process or statistical modeling.
Each set of choices defines a distinct "universe" with potentially different results or conclusions.</p>
<p dir="auto">This Julia package provides a set of macro functions for taking some arbitrary Julia code and re-running the code under different possible assignment choices.</p>
<p dir="auto">For more background and practical guidance for use, see some of the following articles:</p>
<ul dir="auto">
<li>Del Giudice and Gangestad (2021): <a href="https://journals.sagepub.com/doi/10.1177/2515245920954925" rel="nofollow">A Traveler’s Guide to the Multiverse: Promises, Pitfalls, and a Framework for the Evaluation of Analytic Decisions</a></li>
<li>Simonsohn et al. (2018): <a href="https://urisohn.com/sohn_files/wp/wordpress/wp-content/uploads/Paper-Specification-curve-2018-11-02.pdf" rel="nofollow">Specification Curve: Descriptive and Inferential Statistics on All Reasonable Specifications</a></li>
<li>Steegan et al. (2016): <a href="https://journals.sagepub.com/doi/10.1177/1745691616658637" rel="nofollow">Increasing Transparency Through a Multiverse Analysis</a></li>
</ul>
<p dir="auto">See also the closely related R package, <a href="https://github.com/MUCollective/multiverse/">multiverse</a>.</p>

<p dir="auto">In the code above, we have some set of x, y, z points, and we measure the mean of the z values for a subset of points determined by chosen thresholds on x and y.
We could turn this into a multiverse analysis as follows.</p>

<p dir="auto">In the example above, we have surrounded the analysis code within the <code>@explore</code> block.
Within the code block, we specified two choices with the<code>@choice</code> macro.
Note that a choice has to assign a collection to a variable.
We have also specified one result with the <code>@measure</code> macro.</p>
<p dir="auto">When constructing this multiverse, we first look for all choices made (<code>x_threshold</code> and <code>y_threshold</code>), and collect the possible values for each choice (here both consist of a list of the same five numbers).
Then we construct the list with the set of all possible choices (i.e., the Cartesian product of the choice sets).
Finally, we iteratively pick the next possible set of choices, evaluate the analysis when assigning those choices, and keep track of the associated measurement results.</p>
<p dir="auto">The returned object (called <code>multiverse</code> in the example), has the type <code>Multiverse</code>, and the package provides the accessor methods <code>choices</code>, <code>measurements</code>, <code>choice_table</code>, and <code>measurement_table</code>.
The first two methods return the tuple of choice and measurement symbols for the analysis (e.g., <code>(:x_threshold, :y_threshold)</code> and <code>(:mean_z,)</code> respectively, in this example).
The last two methods each provide a vector of named tuples.
A row in the table corresponds to one universe within the multiverse analysis, representing a distinct set of choices made, and the corrsponding measurement values.</p>
<p dir="auto">The <code>Multiverse</code> type also supports the <a href="https://tables.juliadata.org/stable/" rel="nofollow">Tables.jl</a> interface, so you can do, e.g., <code>DataFrame(multiverse)</code> to get a data frame with the contents of both the choice table and the measurement table all together.</p>

<p dir="auto">The behavior of the <code>@explore</code> macro is to find all choice sets and then immediately evaluate each universe.
For any moderately complicated or slow-to-compute analysis, you may want more fine-grained control over the evaluation process.
For instance, you might want to randomly sample the choice sets, cache results to disk for a long running computation, or simply include a <a href="https://github.com/timholy/ProgressMeter.jl">progress meter</a>.</p>
<p dir="auto">The <code>@enter</code> macro constructs a <code>Multiverse</code> object from a code block analogously to the <code>@explore</code> macro, but it does not yet evaluate any of the universes.
By default, the measurement values will all be <code>nothing</code>.</p>
<p dir="auto">You can selectively run and store the measurement results of a universe with the <code>explore!</code> method as follows:</p>

    @choose x = 1:10
    @measure y = x + 42
end
for i in 1:length(m)
    explore!(m, i)
end"><pre>m <span class="pl-k">=</span> <span class="pl-c1">@enter</span> <span class="pl-k">begin</span>

<p dir="auto">The only macros exported by this package are <code>@explore</code> and <code>@enter</code>.
The <code>@choice</code> and <code>@measure</code> macros are not actually defined macro functions; rather they are merely syntax used to construct the analysis.</p>
<p dir="auto">Note that the right-hand side of the choice assignment will be evaluated in the scope of the macro-calling module at the time of macro expansion.
This is to allow for an arbitrary expression returning a collection to be used, rather than just a literal vector or tuple.
All other code evaluation is currently postponed to until after the macro has been expanded.</p>
