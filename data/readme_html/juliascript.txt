<p dir="auto"><strong>You have a julia script.jl and want to run it fast?</strong></p>
<p dir="auto">Welcome to <code>juliascript</code>! It is built for exactly that purpose.</p>

<ol dir="auto">
<li>Make sure <code>julia</code> is installed via <a href="https://github.com/JuliaLang/juliaup">juliaup</a></li>
<li>Then run the following in a Linux bash terminal</li>
</ol>

<p dir="auto">Now you can run <code>juliascript yourscript.jl</code> on the terminal, or use the shebang <code>#!/usr/bin/env juliascript</code> as the first line of your exectuable script.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">How it works</h2><a id="user-content-how-it-works" class="anchor" aria-label="Permalink: How it works" href="#how-it-works"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>The first time <code>juliascript yourscript.jl</code> runs <code>yourscript.jl</code>, it will create a corresponding julia module and track all precompile statements from the actual run.</li>
<li>From the second time onwards, it will then run as fast as julia's precompilation system allows for it.</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Further speedup</h3><a id="user-content-further-speedup" class="anchor" aria-label="Permalink: Further speedup" href="#further-speedup"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Sometimes the speedup this gives may not be satisfying. Then you can manually create a <strong>sysimage</strong> to improve performance even further.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="juliascript packagecompile yourscript.jl"><pre>juliascript packagecompile yourscript.jl</pre></div>
<p dir="auto">Depending on your script this may take from 5 minutes up to 30 minutes.</p>
<p dir="auto">Every further call <code>juliascript yourscript.jl</code> will then use the sysimage (until you make a change to yourscript.jl).</p>

<ul dir="auto">
<li>
<p dir="auto"><code>JULIASCRIPT_PACKAGECOMPILE_ALWAYS=true</code></p>
<p dir="auto">If set, <code>juliascript myscript.jl</code> will automatically packagecompile a new or changed <code>myscript.jl</code>. The creation of the sysimage is run in the background, consuming compute resources, but otherwise it is not blocking the script execution.</p>
</li>
</ul>
