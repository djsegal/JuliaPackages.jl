<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">About</h2><a id="user-content-about" class="anchor" aria-label="Permalink: About" href="#about"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><code>StructuralIdentifiability.jl</code> is a Julia package for assessing structural parameter identifiability of parametric ODE models, both local and global.
This includes computation of identifiable functions of states and parameters. The package also offers functionality to assess local identifiability
in discrete-time models.
For an introduction to structural identifiability, we refer to <a href="#review">[2]</a>.</p>

<p dir="auto">A parametric ODE system in the state-space from can be defined by the <code>@ODEmodel</code> macro:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="ode = @ODEmodel(
    x1'(t) = -(a01 + a21) * x1(t) + a12 * x2(t) + u(t),
    x2'(t) = a21 * x1(t) - a12 * x2(t) - x3(t) / b,
    x3'(t) = x3(t),
    y(t) = x2(t)
)"><pre>ode <span class="pl-k">=</span> <span class="pl-c1">@ODEmodel</span>(
    x1<span class="pl-k">'</span>(t) <span class="pl-k">=</span> <span class="pl-k">-</span>(a01 <span class="pl-k">+</span> a21) <span class="pl-k">*</span> <span class="pl-c1">x1</span>(t) <span class="pl-k">+</span> a12 <span class="pl-k">*</span> <span class="pl-c1">x2</span>(t) <span class="pl-k">+</span> <span class="pl-c1">u</span>(t),
    x2<span class="pl-k">'</span>(t) <span class="pl-k">=</span> a21 <span class="pl-k">*</span> <span class="pl-c1">x1</span>(t) <span class="pl-k">-</span> a12 <span class="pl-k">*</span> <span class="pl-c1">x2</span>(t) <span class="pl-k">-</span> <span class="pl-c1">x3</span>(t) <span class="pl-k">/</span> b,
    x3<span class="pl-k">'</span>(t) <span class="pl-k">=</span> <span class="pl-c1">x3</span>(t),
    <span class="pl-en">y</span>(t) <span class="pl-k">=</span> <span class="pl-c1">x2</span>(t)
)</pre></div>
<p dir="auto">In this example:</p>
<ul dir="auto">
<li><code>x1(t), x2(t), x3(t)</code> are the <strong>state variables</strong>, they defined the state of the system and are assumed to be unknown;</li>
<li><code>u(t)</code> is the <strong>input/control variable</strong> which is assumed to be known and generic (exciting) enough;</li>
<li><code>y(t)</code> is the <strong>output variable</strong> which is assumed to be observed in the experiments and, thus, known;</li>
<li><code>a01, a21, a12, b</code> are unknown scalar <strong>parameters</strong>.</li>
</ul>
<p dir="auto">Note that there may be multiple inputs and outputs.</p>

<p dir="auto">The identifiability of the parameters in the model can be assessed by the <code>assess_identifiability</code> function as follows</p>

<p dir="auto">The returned value is a dictionary from the parameter of the model to one of the symbols</p>

</ul>

can be still identifiable. However, it may be not so easy to guess these functions (even in this example). Good news is that this is not needed!
Function <code>find_identifiable_functions</code> can find generators of all identifiable functions of a given model. For instance:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="find_identifiable_functions(ode)"><pre><span class="pl-c1">find_identifiable_functions</span>(ode)</pre></div>

<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="3-element Vector{AbstractAlgebra.Generic.Frac{Nemo.QQMPolyRingElem}}:
 a21
 a01*a12
 a01 + a12"><pre class="notranslate"><code>3-element Vector{AbstractAlgebra.Generic.Frac{Nemo.QQMPolyRingElem}}:

<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="find_identifiable_functions(ode, with_states = true)"><pre><span class="pl-c1">find_identifiable_functions</span>(ode, with_states <span class="pl-k">=</span> <span class="pl-c1">true</span>)</pre></div>

</code></pre></div>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Assessing local identifiability</h3><a id="user-content-assessing-local-identifiability" class="anchor" aria-label="Permalink: Assessing local identifiability" href="#assessing-local-identifiability"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Local identifiability can be assessed efficiently even for the models for which global identifiability analysis is out of reach.
This can be done using the <code>assess_local_identifiability</code> function, for example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="assess_local_identifiability(ode)"><pre><span class="pl-c1">assess_local_identifiability</span>(ode)</pre></div>
<p dir="auto">The returned value is a dictionary from parameters and state variables to <code>1</code> (is locally identifiable/observable) and <code>0</code> (not identifiable/observable) values. In our example:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="OrderedDict{Any, Bool} with 7 entries:
  x1(t) =&gt; 1
  x2(t) =&gt; 1
  x3(t) =&gt; 0
  a01   =&gt; 1
  a12   =&gt; 1
  a21   =&gt; 1
  b     =&gt; 0"><pre class="notranslate"><code>OrderedDict{Any, Bool} with 7 entries:
  x1(t) =&gt; 1
  x2(t) =&gt; 1
  x3(t) =&gt; 0
  a01   =&gt; 1
  a12   =&gt; 1
  a21   =&gt; 1
  b     =&gt; 0
</code></pre></div>
<p dir="auto">As for <code>assess_identifiability</code>, one can assess local identifiability of arbitrary rational functions in the parameters (and also states) by providing a list of such functions as the second argument.</p>
<p dir="auto"><strong>Remark</strong> The algorithms we used are randomized, the default probability of the correctness of the result is 99%, one can change it by changing the value of a keyword argument <code>p</code> to any real number between 0 and 1, for example:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# pobability of correctness 99.9%
assess_identifiability(ode; p = 0.999)"><pre><span class="pl-c"><span class="pl-c">#</span> pobability of correctness 99.9%</span>
<span class="pl-c1">assess_identifiability</span>(ode; p <span class="pl-k">=</span> <span class="pl-c1">0.999</span>)</pre></div>
