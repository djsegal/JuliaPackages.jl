<p dir="auto">The primary interface provided by StructUtils.jl is in the form of the exported <code>@noarg</code>, <code>@defaults</code>, and <code>@tags</code> macros, along with the unexported (to avoid clashing with the Base definition) of <code>StructUtils.@kwdef</code>. These macros can be used on struct definitions to provide a more ergonomic and flexible way to define structs with default values, keyword constructors, and more.</p>
<p dir="auto">The <code>@noarg</code> macro can be used to define a "no argument" constructor, and must be used with mutable structs. This allows
for programmatic construction and discovery of the supported behavior. Default values and field tags can also be defined in <code>@noarg</code> structs.</p>
<p dir="auto">The <code>@defaults</code> macro can be used to define default values for fields in any kind of struct, and constructors will be defined that allow for the omission of fields with default values. Note that all fields with default values must be defined after any fields without default values.</p>
<p dir="auto">The <code>@tags</code> macro can be used to define tags for fields in any kind of struct.</p>
<p dir="auto">The <code>@kwdef</code> macro mirros the functionality of the Base defintion, while also allowing for the inclusion of field tags.</p>
<p dir="auto">The other major interface StructUtils.jl provides is the <code>StructUtils.make(T, source)</code> function. It allows programmatic construction of a type <code>T</code> from a variety of source objects.
For example, I could have a custom struct <code>Foo</code> and be able to construct an instance from an array of values, a dictionary, a database cursor, a JSON object, etc. This is done by allowing source objects to implement interfaces for how fields should be provided programmatically (the primary means being the <code>StructUtils.applyeach</code> function), while <code>StructUtils.make</code> uses the programmatic knowledge from the above-mentioned macros, along with potential field tags, to construct the object.</p>
<p dir="auto">Additional documentation is forth-coming around how package developers can use the "under the hood" machinery of StructUtils.jl to provide a more flexible and ergonomic interface to their users, like custom serialization/deserialization, database interaction, etc.</p>
