<p dir="auto">Julia is well-suited for interactive, REPL-like applications, as well as a viable replacement for many <code>bash</code> scripting workflows. This package aims to streamline and help customize the end user experience (UX) of such Julia command line applications.</p>
<p dir="auto"><em>Scripting UX:</em></p>
<ul dir="auto">
<li>
<p dir="auto">Maximally-local and flexible <strong>option parsing</strong>.</p>
</li>
<li>
<p dir="auto">Custom file extension groups like (as in <code>:jpeg</code> == "jpg" or "JPG" or "Jpeg")</p>
</li>
<li>
<p dir="auto">Terse and <strong>deferred color output</strong></p>
</li>
<li>
<p dir="auto"><strong>Interrupt</strong> and <strong>SIGPIPE</strong> handling.</p>
</li>
<li>
<p dir="auto">Tweaks to specific <strong>error message formats</strong> aimed not at developers but at application end users.</p>
</li>
</ul>
<p dir="auto"><em>REPL UX:</em></p>
<ul dir="auto">
<li>
<p dir="auto">Aliases for commonly used REPL <strong>pipe workflows</strong>.</p>
</li>
<li>
<p dir="auto"><strong>Reverse assignment</strong> in pipes (experimental).</p>
</li>
<li>
<p dir="auto"><strong>Shortcut shell commands</strong> in the Julia REPL mode (in progress).</p>
</li>
</ul>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">"Local" Option Parsing</h3><a id="user-content-local-option-parsing" class="anchor" aria-label="Permalink: &quot;Local&quot; Option Parsing" href="#local-option-parsing"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Good option parsers for Julia exist, see <a href="https://github.com/carlobaldassi/ArgParse.jl">ArgParse.jl</a> or <a href="https://github.com/zachmatson/ArgMacros.jl">ArgMacros.jl</a> or <a href="https://github.com/attractivechaos/Getopt.jl">Getopt.jl</a>. CommandLiner's <code>getopt</code>/<code>getargs</code> use a C/GNU/<a href="https://www.gnu.org/software/libc/manual/html_node/Getopt.html" rel="nofollow">getopt</a>-inspired approach. It</p>
<ul dir="auto">
<li>supports <strong>in-order</strong> processing/parsing -- one can always randomly permute the option input later after all;</li>
<li>is maximally <strong>local</strong> -- options are defined where the are being <code>if</code>-ed upon;</li>
<li>checks and <strong>converts</strong> int/float types, and a string like <code>-8</code> is treated as an <em>argument</em> instead of an <em>option</em>.</li>
</ul>
<p dir="auto">In a script, you alternately call <code>getopt</code> to get an option like <code>-x</code>, and <code>getargs</code> to get its arguments:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="function main()  # your main function

            ..
        elseif opt === nothing  # &quot;naked&quot; arguments without preceding option
            args = getargs()
            ..
        else
            error(&quot;unknown option&quot;)
        end
    end
end"><pre><span class="pl-k">function</span> <span class="pl-en">main</span>()  <span class="pl-c"><span class="pl-c">#</span> your main function</span>

<ul dir="auto">
<li><code>getopt()</code> pops and returns the next option from ARGS; if no option is found (i.e., string not starting with "--" or "-"), returns <code>nothing</code> (the arguments that would possibly follow are "naked").</li>
<li><code>getargs()</code> returns all arguments up to the next option; must find at least 1.</li>
<li><code>getargs0()</code> returns all arguments up to the next option (0 or more).</li>
<li><code>getarg()</code> returns one argument (not as vector).</li>
<li><code>getargs("sfii")</code> returns a vector of 4 arguments, a string, a float and two integers. Fails if more or fewer arguments are encountered, or if types do not match.</li>
<li><code>getargs("si*")</code> return a vector with a string argument and 0+ ints.</li>
</ul>
<p dir="auto">if <code>stopatopt</code> is <code>false</code>, all command line strings are treated as arguments (default distinguishes between options and arguments).</p>
<p dir="auto">if <code>mustexhaust</code> is <code>false</code>, you can read n arguments, and leave additional, "naked arguments" for later parsing (default fails if there are valid arguments left, i.e., if the next string in <code>ARGS</code> is not an option).</p>

<p dir="auto"><code>EnduserError</code> is an exception type meant to signal that the end user would not benefit from a full backtrace, e.g., with errors such as "file not found". Thrown with <code>erroruser(msg)</code>.</p>
<p dir="auto">The function <code>hushexit(f::Function)</code> calls <code>f</code>, and suppresses SIGPIPE exceptions gracefully, handles &lt;Ctrl+C&gt;..</p>
<p dir="auto">The macro <code>@main</code> is a shortcut for the file guard in a script; it calls <strong>your</strong> <code>main</code> function via <code>hushexit(main)</code>.</p>
