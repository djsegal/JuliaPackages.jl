<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Introduction</h2><a id="user-content-introduction" class="anchor" aria-label="Permalink: Introduction" href="#introduction"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">This module defines types representing <a href="https://en.wikipedia.org/wiki/Finite_field" rel="nofollow">finite fields</a>. It
supports both fields of prime order and of prime power order.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Synopsis</h2><a id="user-content-synopsis" class="anchor" aria-label="Permalink: Synopsis" href="#synopsis"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The easiest way to create Galois fields is with the <code>@GaloisField</code> and <code>@GaloisField!</code>
macros. Typically, you use the former for a field of prime order and the latter
for a field of prime power order. In the prime power case, you pass a display
name / variable name for the primitive element.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using GaloisFields

const F = @GaloisField 29     # ℤ/29ℤ
const G = @GaloisField! 27 β   # degree-3 extension of ℤ/3ℤ; multiplicatively generated by β

F(2)^29 == F(2)
β^27 == β"><pre><span class="pl-k">using</span> GaloisFields

<span class="pl-k">const</span> F <span class="pl-k">=</span> <span class="pl-c1">@GaloisField</span> <span class="pl-c1">29</span>     <span class="pl-c"><span class="pl-c">#</span> ℤ/29ℤ</span>
<span class="pl-k">const</span> G <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> <span class="pl-c1">27</span> β   <span class="pl-c"><span class="pl-c">#</span> degree-3 extension of ℤ/3ℤ; multiplicatively generated by β</span>

<p dir="auto">The exclamation mark <code>!</code> is intended to convey that the macro has a side-effect:
for example, in the code above, it assigns a variable called <code>β</code>.</p>
<p dir="auto">The macros also accept special symbols for specifying the field. This is more
difficult to type (<a href="https://docs.julialang.org/en/v1.1/manual/unicode-input/#Unicode-Input-1" rel="nofollow">docs</a>) but more elegant to read:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = @GaloisField ℤ/29ℤ
const G = @GaloisField 𝔽₂₇ β"><pre><span class="pl-k">const</span> F <span class="pl-k">=</span> <span class="pl-c1">@GaloisField</span> ℤ<span class="pl-k">/</span><span class="pl-c1">29</span>ℤ

<p dir="auto">If you want to pass your own generator for the representation of a field
of order <code>q = p^n</code>, you can:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = @GaloisField! 𝔽₃ β^2 + β + 2

<p dir="auto">Lastly, there's also function interfaces in cases where macros are not
appropriate:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = GaloisField(29)               # ℤ/29ℤ

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Fast multiplications</h2><a id="user-content-fast-multiplications" class="anchor" aria-label="Permalink: Fast multiplications" href="#fast-multiplications"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In some cases, we make use of <a href="https://en.wikipedia.org/wiki/Zech's_logarithm" rel="nofollow">Zech's logarithms</a> for faster multiplications.
By default, this happens if the order of the field is less than <code>2^16</code>, if the
characteristic is not 2, and if the primitive element is also a multiplicative
generator. However, you can override this by calling either of</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="GaloisFields.enable_zech_multiplication(F)
GaloisFields.disable_zech_multiplication(F)"><pre>GaloisFields<span class="pl-k">.</span><span class="pl-c1">enable_zech_multiplication</span>(F)
GaloisFields<span class="pl-k">.</span><span class="pl-c1">disable_zech_multiplication</span>(F)</pre></div>
<p dir="auto"><em>before</em> doing any multiplication operation. If you call this function on a
field whose primitive element is <em>not</em> a multiplicative generator, this will
throw a warning.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Conversions</h2><a id="user-content-conversions" class="anchor" aria-label="Permalink: Conversions" href="#conversions"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If you specify your own minimum polynomial, we make no assumptions about
conversions between fields. For example, when defining</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = @GaloisField! 𝔽₂ β^2 + β + 1
const G = @GaloisField! 𝔽₂ γ^2 + γ + 1"><pre><span class="pl-k">const</span> F <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₂ β<span class="pl-k">^</span><span class="pl-c1">2</span> <span class="pl-k">+</span> β <span class="pl-k">+</span> <span class="pl-c1">1</span>
<span class="pl-k">const</span> G <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₂ γ<span class="pl-k">^</span><span class="pl-c1">2</span> <span class="pl-k">+</span> γ <span class="pl-k">+</span> <span class="pl-c1">1</span></pre></div>
<p dir="auto">an operation like</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="G(β)"><pre><span class="pl-c1">G</span>(β)</pre></div>
<p dir="auto">will throw an error. The mathematical reason is that  the fields <code>F</code> and <code>G</code>
are isomorphic, but there is two different isomorphisms. ("They are not <em>canonically</em>
isomorphic.") To choose an identification, you can use the <code>identify</code> function
(which is not exported by default, so we use its full path):</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="GaloisFields.identify(β =&gt; γ^2)
GaloisFields.identify(γ =&gt; β^2)"><pre>GaloisFields<span class="pl-k">.</span><span class="pl-c1">identify</span>(β <span class="pl-k">=&gt;</span> γ<span class="pl-k">^</span><span class="pl-c1">2</span>)
GaloisFields<span class="pl-k">.</span><span class="pl-c1">identify</span>(γ <span class="pl-k">=&gt;</span> β<span class="pl-k">^</span><span class="pl-c1">2</span>)</pre></div>
<p dir="auto">This allows for conversions such as</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="G(β)
convert(F, γ + 1)"><pre><span class="pl-c1">G</span>(β)
<span class="pl-c1">convert</span>(F, γ <span class="pl-k">+</span> <span class="pl-c1">1</span>)</pre></div>
<p dir="auto">The inner workings of this distinction are based on the symbol names. So
if you define <code>F</code> and <code>G</code> with the <em>same</em> symbol and minimum polynomial:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = @GaloisField! 𝔽₂ β^2 + β + 1
const G = @GaloisField! 𝔽₂ β^2 + β + 1"><pre><span class="pl-k">const</span> F <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₂ β<span class="pl-k">^</span><span class="pl-c1">2</span> <span class="pl-k">+</span> β <span class="pl-k">+</span> <span class="pl-c1">1</span>
<span class="pl-k">const</span> G <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₂ β<span class="pl-k">^</span><span class="pl-c1">2</span> <span class="pl-k">+</span> β <span class="pl-k">+</span> <span class="pl-c1">1</span></pre></div>
<p dir="auto">then they are just considered equal and conversions work without extra work.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Conversions for the default minimum polynomials</h2><a id="user-content-conversions-for-the-default-minimum-polynomials" class="anchor" aria-label="Permalink: Conversions for the default minimum polynomials" href="#conversions-for-the-default-minimum-polynomials"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If you do not specify a minimum polynomial, for example by using</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="const F = @GaloisField! 𝔽₈₁ β
const G = @GaloisField! 𝔽₉ γ"><pre><span class="pl-k">const</span> F <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₈₁ β
<span class="pl-k">const</span> G <span class="pl-k">=</span> <span class="pl-c1">@GaloisField!</span> 𝔽₉ γ</pre></div>
<p dir="auto">then we use <a href="https://en.wikipedia.org/wiki/Conway_polynomial_(finite_fields)" rel="nofollow">Conway polynomials</a>. They have special compatibility
relations between them, allowing conversions:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="β^10 == γ"><pre>β<span class="pl-k">^</span><span class="pl-c1">10</span> <span class="pl-k">==</span> γ</pre></div>
<p dir="auto">This works provided <code>F</code> and <code>G</code> have the same characteristic <code>p</code>. If the order
of either is a power of the other, we convert into the bigger field. If not, we
convert both into the field of order <code>p^N</code>, where <code>N</code> is the least common
multiple of the extension degrees of <code>F</code> and <code>G</code> over ℤ/pℤ.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Constructing a tower of field extensions</h2><a id="user-content-constructing-a-tower-of-field-extensions" class="anchor" aria-label="Permalink: Constructing a tower of field extensions" href="#constructing-a-tower-of-field-extensions"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In some applications of finite fields it is convenient to use extensions
of already defined finite field, i. e. the extensions of the type
<code>G</code> of power <code>q^m</code> over <code>F</code> of power <code>q</code> where <code>q = p^n</code> for some integers <code>m, n</code>.
It is possible to construct an extension of already defined finite field:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="# creating field with 29 elements

# G is a subfield of H
# H has |G|^3 elements"><pre><span class="pl-c"><span class="pl-c">#</span> creating field with 29 elements</span>

<span class="pl-c"><span class="pl-c">#</span> the polynomial x^2 - 2 is irreducible over F29</span>
