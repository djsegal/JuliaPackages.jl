<p dir="auto"><strong>MESTI</strong> (<ins>M</ins>axwell's <ins>E</ins>quations <ins>S</ins>olver with <ins>T</ins>housands of <ins>I</ins>nputs) is an open-source software for full-wave electromagnetic simulations in frequency domain using finite-difference discretization on the <a href="https://meep.readthedocs.io/en/latest/Yee_Lattice" rel="nofollow">Yee lattice</a>.</p>
<p dir="auto">MESTI implements the <strong>augmented partial factorization (APF)</strong> method described in <a href="https://doi.org/10.1038/s43588-022-00370-6" rel="nofollow">this paper</a>. While conventional methods solve Maxwell's equations on every element of the discretization basis set (which contains much more information than is typically needed), APF bypasses such intermediate solution step and directly computes the projected quantities of interest: a generalized scattering matrix given any list of input source profiles and any list of output projection profiles. It can jointly handle thousands of inputs without a loop over them, using fewer computing resources than what a conventional direct method uses to handle a single input. It is exact with no approximation beyond discretization.</p>
<p dir="auto">The MESTI.jl package here provides all the features in the 2D MATLAB version <a href="https://github.com/complexphoton/MESTI.m">MESTI.m</a> and additionally supports 3D vectorial systems, anisotropic <em>ε</em>, MPI parallelization, both single-precision and double-precision arithmetics, and can perform subpixel smoothing for the geometric shapes handled by <a href="https://github.com/stevengj/GeometryPrimitives.jl">GeometryPrimitives.jl</a>. It is written in Julia.</p>
<p dir="auto">In the 3D case, MESTI.jl solves</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$$
\left[ \nabla\times\left( \nabla\times \right) - \frac{\omega^2}{c^2}\bar{\bar{\varepsilon}}({\bf r}) \right] {\bf E}({\bf r}) = {\bf b}({\bf r}).
$$</math-renderer></p>
<p dir="auto">For 2D systems in the transverse-magnetic (TM) polarization (<em>Ex</em>, <em>Hy</em>, <em>Hz</em>), MESTI.jl solves</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$$
\left[ -\frac{\partial^2}{\partial y^2} -\frac{\partial^2}{\partial z^2} - \frac{\omega^2}{c^2}\varepsilon_{xx}(y,z) \right] E_x(y,z)= b(y,z),
$$</math-renderer></p>
<p dir="auto">where <strong>b</strong>(<strong>r</strong>) or <em>b</em>(<em>y</em>,<em>z</em>) is the source profile.</p>
<p dir="auto">MESTI.jl is a general-purpose solver with an interface written to provide maximal flexibility. It supports</p>
<ul dir="auto">
<li>Full 3D vectorial systems.</li>
<li>TM polarization for 2D systems.</li>
<li>Any tensor or scalar relative permittivity profile <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$\bar{\bar{\varepsilon}}({\bf r})$</math-renderer>, which can be real-valued or complex-valued.</li>
<li>Open boundary modeled by a <a href="https://en.wikipedia.org/wiki/Perfectly_matched_layer" rel="nofollow">perfectly matched layer (PML)</a> placed on any side(s), with both imaginary-coordinate and real-coordinate stretching (so the PML can accelerate the attenuation of evanescent waves in addition to attenuating the propagating waves).</li>
<li>Periodic, Bloch periodic, perfect electrical conductor (PEC), and/or perfect magnetic conductor (PMC) boundary conditions.</li>
<li>
<a href="https://meep.readthedocs.io/en/latest/Subpixel_Smoothing" rel="nofollow">Subpixel smoothing</a> for the geometric shapes handled by <a href="https://github.com/stevengj/GeometryPrimitives.jl">GeometryPrimitives.jl</a> through function <a href="https://github.com/complexphoton/MESTI.jl/blob/main/src/mesti_subpixel_smoothing.jl"><code>mesti_subpixel_smoothing()</code></a>.</li>
<li>Any material dispersion <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$\bar{\bar{\varepsilon}}$</math-renderer>(<em>ω</em>), since this is a frequency-domain method.</li>
<li>Any list of input source profiles (user-specified or automatically built).</li>
<li>Any list of output projection profiles (or no projection, in which case the complete field profiles are returned).</li>
<li>Real-valued or complex-valued frequency <em>ω</em>.</li>
<li>Automatic or manual choice between APF or a conventional direct solver (<em>e.g.</em>, to compute the full field profile) as the solution method.</li>
<li>Linear solver using MUMPS (requires installation) or the built-in routines in Julia (which uses UMFPACK).</li>
<li>Shared memory parallelism (with multithreaded BLAS and with OpenMP in MUMPS) and distributed memory parallelism (with MPI in MUMPS).</li>
<li>Single-precision or double-precision arithmetic.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">When to use MESTI.jl?</h2><a id="user-content-when-to-use-mestijl" class="anchor" aria-label="Permalink: When to use MESTI.jl?" href="#when-to-use-mestijl"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">MESTI.jl can perform most linear-response computations for arbitrary structures, such as</p>
<ul dir="auto">
<li>Scattering problems: transmission, reflection transport through complex media, waveguide bent, grating coupler, radar cross-section, controlled-source electromagnetic surveys, <em>etc</em>.</li>
<li>Thermal emission.</li>
<li>Local density of states.</li>
<li><a href="https://github.com/complexphoton/metalens_inverse_design">Inverse design</a> based on the above quantities.</li>
</ul>
<p dir="auto">Since MESTI.jl can use the APF method to handle a large number of input states simultaneously, the computational advantage of MESTI.jl is the most pronounced in multi-input systems.</p>
<p dir="auto">There are use cases that MESTI.jl can handle but is not necessarily the most efficient, such as</p>
<ul dir="auto">
<li>Broadband response problems involving many frequencies but only a few input states. Time-domain methods like FDTD may be preferred as they can compute a broadband response without looping over the frequencies.</li>
<li>Problems like plasmonics that require more than an order of magnitude difference in the discretization grid size at different regions of the structure. Finite-element methods may be preferred as they can handle varying spatial resolutions. (Finite-element methods can also adopt APF, but MESTI.jl uses finite difference with a fixed grid size.)</li>
<li>Homogeneous structures with a small surface-to-volume ratio. Boundary element methods may be preferred as they only discretize the surface.</li>
</ul>
<p dir="auto">Problems that MESTI.jl does not handle:</p>
<ul dir="auto">
<li>Nonlinear systems (<em>e.g.</em>, <em>χ</em><sup>(2)</sup>, <em>χ</em><sup>(3)</sup>, gain media).</li>
<li>Magnetic systems (<em>e.g.</em>, spatially varying permeability <em>μ</em>).</li>
</ul>
<p dir="auto">For eigenmode computation, such as waveguide mode solver and photonic band structure computation, one can use <a href="./src/mesti_build_fdfd_matrix.jl"><code>mesti_build_fdfd_matrix.jl</code></a> to build the matrix and then compute its eigenmodes. However, we don't currently provide a dedicated function to do so.</p>

<p dir="auto">MESTI.jl is written and run in Julia programming language. Follow the standard process to download and install Julia. We can download Julia <a href="https://julialang.org/downloads/" rel="nofollow">here</a>. Suppose we installed the 1.9.3 version of Julia. After Julia is installed, we can add the path of your Julia to <code>PATH</code> through the terminal by</p>

See this <a href="./mumps">MUMPS installation</a> page for steps to install MUMPS. For this MESTI (v0.5.0), it is compatible with MUMPS versions 5.7.0 and 5.7.1, but not with versions earlier than 5.7.0. We highly recommend using the latest version of MUMPS.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Usage Summary</h2><a id="user-content-usage-summary" class="anchor" aria-label="Permalink: Usage Summary" href="#usage-summary"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The function <code>mesti(syst, B, C, D)</code> provides the most flexibility. Structure <code>syst</code> specifies the permittivity profile, boundary conditions in <em>x</em>, <em>y</em>, and <em>z</em>, which side(s) to put PML with what parameters, the wavelength, and the discretization grid size. Any list of input source profiles can be specified with matrix <code>B</code>, each column of which specifies one source profile <strong>b</strong>(<strong>r</strong>). Any list of output projection profiles can be specified with matrix <code>C</code>. Matrix <code>D</code> is optional (treated as zero when not specified) and subtracts the baseline contribution; see the <a href="https://doi.org/10.1038/s43588-022-00370-6" rel="nofollow">APF paper</a> for details.</p>
<p dir="auto">The function <code>mesti2s(syst, in, out)</code> deals specifically with scattering problems in two-sided or one-sided geometries where <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$\bar{\bar{\varepsilon}}(\bf r)$</math-renderer>  consists of an inhomogeneous scattering region with homogeneous spaces on the low (<em>-z</em>) and high (<em>+z</em>) sides, light is incident from those sides, the boundary condition in <em>z</em> is outgoing, and the boundary condition in <em>y</em> and <em>x</em> is closed (<em>e.g.</em>, periodic or PEC). The user only needs to specify the input and output sides or channel indices or wavefronts through <code>in</code> and <code>out</code>. The function <code>mesti2s()</code> automatically builds the source matrix <code>B</code>, projection matrix <code>C</code>, baseline matrix <code>D</code>, and calls <code>mesti()</code> for the computation. Flux normalization in <em>z</em> is applied automatically so, when the PML is thick enough, the full scattering matrix is unitary when <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$\bar{\bar{\varepsilon}}$</math-renderer> is Hermitian everywhere [<em>i.e.</em>, <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$\bar{\bar{\varepsilon}}({\bf r})=\bar{\bar{\varepsilon}}^\dagger({\bf r})$</math-renderer> for all <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">${\bf r}$</math-renderer>].</p>
<p dir="auto">To compute the complete field profiles, simply omit the argument <code>C</code> or <code>out</code>.</p>
<p dir="auto">The solution method, the linear solver to use, and other options can be specified with a structure <code>opts</code> as an optional input argument to <code>mesti()</code> or <code>mesti2s()</code>; see documentation for details. They are chosen automatically when not explicitly specified.</p>
<p dir="auto">The function <a href="./src/mesti_build_channels.jl"><code>mesti_build_channels()</code></a> can be used to build the input and/or output matrices when using <code>mesti()</code> or to determine which channels are of interest when using <code>mesti2s()</code>.</p>
<p dir="auto">The function <a href="./src/mesti_subpixel_smoothing.jl"><code>mesti_subpixel_smoothing()</code></a> can be used to build the permittivity profile with subpixel smoothing.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Multithreading and MPI</h2><a id="user-content-multithreading-and-mpi" class="anchor" aria-label="Permalink: Multithreading and MPI" href="#multithreading-and-mpi"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">MESTI.jl can use both distributed memory parallelization across nodes/sockets through MPI and shared memory parallelization within one node/socket through multithreading (if MUMPS was compiled with multithreading enabled). The multithreading speed-up comes from using a multithreaded BLAS library and L0-threads feature in MUMPS. Parts of the MUMPS utilize multithreading with L0-threads through OpenMP directives. With APF, most of the computing time is spent on factorization within MUMPS (<em>e.g.</em>, see Fig 2d of the <a href="https://doi.org/10.1038/s43588-022-00370-6" rel="nofollow">APF paper</a>). The factorization and solving stages within MUMPS are parallelized. The building and analyzing stages are not performance-critical and are not parallelized.</p>
<p dir="auto">L0-threads (see the MUMPS Users' guide for details) in multithreading enhances the time performance, but marginally increases the memory usage. It is enabled by default when it is in 1D, 2D, or 2.5D ((width in <em>x</em>)<em>(width in <em>y</em>)/(thickness in <em>z</em>) $\geqslant 100$). In full 3D ((width in <em>x</em>)</em>(width in <em>y</em>)/(thickness in <em>z</em>) <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="8e0ad5de2145c4eeeea88a38a7201fcf">$&amp;lt; 100$</math-renderer>), memory usage is critical and we do not use L0-threads by default. We can change from the default by setting the field <code>opts.use_L0_threads</code> in the input argument <code>opts</code>.</p>
<p dir="auto">In MUMPS, multithreading is more efficient than MPI, both in speed and in memory usage. So, we should maximize multithreading before using MPI. For example, if we use one node with a single socket having 8 cores (where the 8 cores sharing the same memory), we should use one MPI process (<em>i.e.</em>, no MPI) with 8 threads, instead of 8 MPI processes with one thread each. As another example, if we use 3 nodes, each node has 2 sockets, and each socket has 4 cores sharing the same memory of that socket (so, 24 cores in total), we should use 6 MPI processes (one per socket) with 4 threads per MPI process, instead of 24 MPI processes with one thread each.</p>
<p dir="auto">The default number of threads is the number of cores available on the machine (either the number of physical cores, or the number of cores requested when running the job with a scheduler like Slurm on a cluster). Therefore, we only need to launch MESTI with the number of MPI processes equaling the total number of sockets.</p>
<p dir="auto">We can set the number of threads to be different from the default by setting the environment variable <code>OMP_NUM_THREADS</code> or the field <code>opts.nthreads_OMP</code> of the optional input argument <code>opts</code>.</p>
<p dir="auto">To use MPI, we should prepare the script to construct the system on the main processor and call worker processors when needed. An example script and its corresponding submission script on a cluster are provided in the <a href="./MPI">MPI</a> folder.</p>
<p dir="auto">To check the actual number of MPI processes and threads used in MUMPS, set <code>opts.verbal_solver = true</code> in the input argument and look at the standard output from MUMPS. For example, the following output</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="      executing #MPI =      2 and #OMP =      4"><pre lang="text:Output" class="notranslate"><code>      executing #MPI =      2 and #OMP =      4
</code></pre></div>
<p dir="auto">shows 2 MPI processes with 4 threads each.</p>
