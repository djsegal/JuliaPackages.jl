<p dir="auto">Documentation as interfaces. 接口 (Jiēkǒu) is the Chinese word for interfaces and APIs. This one works with the <code>public</code> keyword.</p>
<p dir="auto">Julia uses docstrings to define interfaces. This is a flexible way of creating interfaces in a dynamic language, but also creates trouble for automation and tooling. Jieko is a package that provides a infrastructure for defining interfaces that works with DocStringExtension with precisely the signature of the interface.</p>

<p dir="auto">Julia interfaces and public APIs are defined by documentation. There is no strict requirement
on which interface an object should implement, but rather the interface is defined by the
documentation. This is a flexible way of defining interfaces in a dynamic language, but it
also creates trouble for automation and tooling.</p>
<p dir="auto">Existing approaches like <a href="https://juliahub.com/ui/Packages/General/Interfaces" rel="nofollow">Interfaces</a> approach
the problem by defining the interface explicitly as an object. This is a good approach for people
want to define interfaces explicitly and in a more strict way. However, it becomes very verbose and not
working well with Julia's documenation system.</p>
<p dir="auto">On the other hand, existing solution in <a href="https://juliahub.com/ui/Packages/General/DocStringExtensions" rel="nofollow">DocStringExtensions</a>
fails to provide the precise interface definition in the docstring. For example, <code>SIGNATURES</code> will ignore
type annotations and only show the method name and argument names.</p>
