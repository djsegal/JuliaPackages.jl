<p dir="auto">The package provides the <code>@docmatch</code> macro, which allows one to simulate the behaviour of <code>```@docs```</code> blocks interactively. This is helpful in case a function has many different methods and docstrings, and one wants to include a specific one. In particular in the presence of type parameters, this can be a frustrating experience due to <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="365207716" data-permission-text="Title is private" data-url="https://github.com/JuliaLang/julia/issues/29437" data-hovercard-type="issue" data-hovercard-url="/JuliaLang/julia/issues/29437/hovercard" href="https://github.com/JuliaLang/julia/issues/29437">JuliaLang/julia#29437</a>. Here is a simple example:</p>

<p dir="auto">The macro returns the docstrings (including metadata). In view of <code>```@docs ```</code> blocks, the most imporant information is the "Include in ..." field. This provides the right invocation to include the specific docstring. For example, if we want to include the second docstring, in our documentation markdown source we would write:</p>
<div class="snippet-clipboard-content notranslate position-relative overflow-auto" data-snippet-clipboard-copy-content="```@docs
Base.sin(::AbstractMatrix{&lt;:Real})
```"><pre class="notranslate"><code>```@docs
Base.sin(::AbstractMatrix{&lt;:Real})
```
</code></pre></div>

<p dir="auto">Note that the type of the signature is garbled due to <a class="issue-link js-issue-link" data-error-text="Failed to load title" data-id="365207716" data-permission-text="Title is private" data-url="https://github.com/JuliaLang/julia/issues/29437" data-hovercard-type="issue" data-hovercard-url="/JuliaLang/julia/issues/29437/hovercard" href="https://github.com/JuliaLang/julia/issues/29437">JuliaLang/julia#29437</a>. This also messes up the lookup. Here we are warned about this and a suggested way to fix it is provided via <code>foo(::Array{S, 1}, ::Array{T, 2}) where {S, T&lt;:S}</code>.</p>
