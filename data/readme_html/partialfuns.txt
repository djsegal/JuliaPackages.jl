<p dir="auto">Support for:</p>
<ul dir="auto">
<li>fixed argument counts</li>
<li>varargs</li>
<li>non-final varargs</li>
<li>type assertion</li>
<li>keyword arguments</li>
<li><code>getindex</code></li>
<li><code>getproperty</code></li>
<li><code>string</code> interpolation</li>
<li><code>tuple</code></li>
<li><code>NamedTuple</code></li>
<li><code>Base.vect</code></li>
<li><code>vcat</code></li>
<li><code>hcat</code></li>
<li><code>adjoint</code></li>
<li><code>Core.apply_type</code></li>
<li>unfixed function name</li>
<li>broadcasting</li>
</ul>
<p dir="auto">Does not support at the moment:</p>
<ul dir="auto">
<li><code>setindex!</code></li>
<li><code>setproperty!</code></li>
<li><code>hvcat</code></li>
<li><code>hvncat</code></li>
<li>broadcast fusion</li>
</ul>
<p dir="auto">Provides types:</p>
<ul dir="auto">
<li><code>PartialFun</code>, which generalizes</li>
<li><code>Fix1</code> and</li>
<li><code>Fix2</code> with backward compatibility, and</li>
<li><code>FixFirst</code> and</li>
<li><code>FixLast</code></li>
</ul>

<p dir="auto">Then the fun begins!</p>
<p dir="auto"><code>init_repl()</code> makes it so that underscores are parsed on every line in the REPL. Otherwise, you can use the <code>@underscores</code> macro. This macro is recursive, so you can call the macro on entire code blocks.</p>
<p dir="auto">Note: This code performs a syntax transform at the earliest stage possible, meaning that it will break macros that use underscores. If this was a language feature instead of just user code, that wouldn't be the case, because the syntax transform would occur <em>after</em> macro expansion.</p>
