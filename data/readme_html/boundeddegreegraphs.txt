<p dir="auto">This package provides simple graph types which do preallocate data such that the operations <code>add_edge!, rem_edge!, has_edge</code> are in-place for bounded degree graphs (also called uniformly sparse graphs).</p>
<ul dir="auto">
<li>The preallocated memory is of size <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="ef9221d11122e09646519a511aeb51f6">$\mathcal{O}( \Vert G \Vert \mathrm{deg}(G) )$</math-renderer>.
If the degree is exeeded, then the type might occasionally allocate, but still works.</li>
<li>The operations <code>has_edge</code>, <code>add_edge</code> and <code>rem_edge</code> take <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="ef9221d11122e09646519a511aeb51f6">$\mathcal{O}( \mathrm{deg}(G) )$</math-renderer> time, since it required to iterate a list of size <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="ef9221d11122e09646519a511aeb51f6">$\mathrm{deg}(G)$</math-renderer>.</li>
<li>In the simple test case below, the speed-up compared to <code>SimpleGraph</code> is by a factor <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="ef9221d11122e09646519a511aeb51f6">$\times 2$</math-renderer>. <strong>Speedup holds only for small degrees!</strong>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Application in agent-based modelling</h3><a id="user-content-application-in-agent-based-modelling" class="anchor" aria-label="Permalink: Application in agent-based modelling" href="#application-in-agent-based-modelling"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto"><em>The original application is for biological modelling of cell migration, where one has to dynamically create and destroy adhesive contacts between cells. Due to geometric constraints the resulting graph is of bounded degree.</em></p>

<p dir="auto">Internally, the adjacent vertices for each vertex <code>i</code> are stored in a <code>Vector{Int64}</code> which has zeros at unoccupied places. Each time a new vertex is added, one of the free spots will be used.
If no free spots are left, then <code>push!(adj, j)</code> is used to add new edges (which will allocate occasionally).</p>
