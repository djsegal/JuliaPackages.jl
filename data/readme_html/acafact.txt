<p dir="auto">A simple and dependency-free <a href="https://link.springer.com/article/10.1007/s00607-002-1469-6" rel="nofollow">adaptive cross approximation (ACA)</a>
factorization in Julia.</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Usage</h1><a id="user-content-usage" class="anchor" aria-label="Permalink: Usage" href="#usage"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Let's create a matrix with low numerical rank:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using LinearAlgebra
pts1 = range(0.0, 1.0, length=100)

<p dir="auto">One easy way to use <code>ACAFact.jl</code> is to just provide your matrix and a maximum
allowed rank for the approximation:</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="for rk in (5, 10, 15, 20, 25)
  (U, V) = aca(K, rk)
  @show (rk, opnorm(K - U*V'))
end"><pre><span class="pl-k">for</span> rk <span class="pl-k">in</span> (<span class="pl-c1">5</span>, <span class="pl-c1">10</span>, <span class="pl-c1">15</span>, <span class="pl-c1">20</span>, <span class="pl-c1">25</span>)
  (U, V) <span class="pl-k">=</span> <span class="pl-c1">aca</span>(K, rk)
  <span class="pl-c1">@show</span> (rk, <span class="pl-c1">opnorm</span>(K <span class="pl-k">-</span> U<span class="pl-k">*</span>V<span class="pl-k">'</span>))
<span class="pl-k">end</span></pre></div>
<p dir="auto">Another thing you can do is provide a desired <code>opnorm</code> error for <code>||K - U*V'||</code>...but I wouldn't bet the farm that the error control is all that
guaranteed. Greedy deterministic pivoting schemes can be tricked, or at least
made very inefficient! It does work pretty well in toy applications at least
though, so it isn't useless.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="for tol in (1e-4, 1e-6, 1e-8, 1e-10, 1e-12, 1e-14)
  (U, V) = aca(K, tol=tol; maxrank=100)
  @show tol, size(U, 2), opnorm(K - U*V')
end"><pre><span class="pl-k">for</span> tol <span class="pl-k">in</span> (<span class="pl-c1">1e-4</span>, <span class="pl-c1">1e-6</span>, <span class="pl-c1">1e-8</span>, <span class="pl-c1">1e-10</span>, <span class="pl-c1">1e-12</span>, <span class="pl-c1">1e-14</span>)
  (U, V) <span class="pl-k">=</span> <span class="pl-c1">aca</span>(K, tol<span class="pl-k">=</span>tol; maxrank<span class="pl-k">=</span><span class="pl-c1">100</span>)
  <span class="pl-c1">@show</span> tol, <span class="pl-c1">size</span>(U, <span class="pl-c1">2</span>), <span class="pl-c1">opnorm</span>(K <span class="pl-k">-</span> U<span class="pl-k">*</span>V<span class="pl-k">'</span>)
<span class="pl-k">end</span></pre></div>
<p dir="auto">If you want something that is completely non-allocating, you can pre-allocate a
cache. Note that if you also provide a <code>tol</code> here, you will terminate early but
the function won't remove the unused columns in <code>U</code> and <code>V</code>. The <code>rnk</code> return
parameter gives you the rank of the approximation, so you should work with
<code>view(U, :, 1:rnk)</code>, for example.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="cache       = ACAFact.ACACache(Float64, length(pts1), length(pts2), 50) # max rank 50
(U, V)      = (zeros(length(pts1), 50), zeros(length(pts2), 50))
(rnk, _, _) = ACAFact.aca!(K, U, V, cache=cache) # zero allocations"><pre>cache       <span class="pl-k">=</span> ACAFact<span class="pl-k">.</span><span class="pl-c1">ACACache</span>(Float64, <span class="pl-c1">length</span>(pts1), <span class="pl-c1">length</span>(pts2), <span class="pl-c1">50</span>) <span class="pl-c"><span class="pl-c">#</span> max rank 50</span>
(U, V)      <span class="pl-k">=</span> (<span class="pl-c1">zeros</span>(<span class="pl-c1">length</span>(pts1), <span class="pl-c1">50</span>), <span class="pl-c1">zeros</span>(<span class="pl-c1">length</span>(pts2), <span class="pl-c1">50</span>))
(rnk, _, _) <span class="pl-k">=</span> ACAFact<span class="pl-k">.</span><span class="pl-c1">aca!</span>(K, U, V, cache<span class="pl-k">=</span>cache) <span class="pl-c"><span class="pl-c">#</span> zero allocations</span></pre></div>
<p dir="auto">One note here though: this <code>ACACache</code> does carry state that gets used in the
factorizations, so if you want to factorize a new matrix that is the same size
as <code>K</code> with the same cache, be sure to <code>ACAFact.resetcache!(cache)</code>.</p>

<p dir="auto">To me, the best reason to use a greedy partially-pivoted factorization like the
ACA is to build low-rank approximations for matrices where you cannot afford to
pass over every entry even once. To accommodate this use case, <code>ACAFact.jl</code> has
an interface</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="  ACAFact.col!(buf, K, j)
  ACAFact.row!(buf, K, j)"><pre>  ACAFact<span class="pl-k">.</span><span class="pl-c1">col!</span>(buf, K, j)
  ACAFact<span class="pl-k">.</span><span class="pl-c1">row!</span>(buf, K, j)</pre></div>
<p dir="auto">that expects <code>buf</code> to be filled with the corresponding column/row of <code>K</code>. So if
you have some cool operator that is defined implicitly or whatever, all you need
to do add special methods</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="  ACAFact.col!(buf, K::MyCoolObject, j) = # ...
  ACAFact.row!(buf, K::MyCoolObject, j) = # ..."><pre>  ACAFact<span class="pl-k">.</span><span class="pl-en">col!</span>(buf, K<span class="pl-k">::</span><span class="pl-c1">MyCoolObject</span>, j) <span class="pl-k">=</span> <span class="pl-c"><span class="pl-c">#</span> ...</span>
  ACAFact<span class="pl-k">.</span><span class="pl-en">row!</span>(buf, K<span class="pl-k">::</span><span class="pl-c1">MyCoolObject</span>, j) <span class="pl-k">=</span> <span class="pl-c"><span class="pl-c">#</span> ...</span></pre></div>
<p dir="auto">and you can create low-rank approximations that never touch rows/columns of your
matrix that aren't selected as pivots. It would be nice if you could also
implement <code>Base.size(K::MyCoolObject)</code>, but if for some reason you don't want to
you can compute the ACA of <code>K</code> with <code>aca(K, [...], sz=(size_K_1, size_K_2))</code>.</p>
