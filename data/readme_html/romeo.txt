<p dir="auto">This repository contains ROMEO 3D/4D unwrapping on arrays and a command line interface for MR data in NIfTI format.<br>
A compiled command line tool is available under <a href="https://github.com/korbinian90/ROMEO">ROMEO</a> (windows and linux executables; does not require a Julia installation) and otherwise, for opening NIfTI files in Julia <a href="https://github.com/JuliaIO/NIfTI.jl">NIfTI.jl</a> or <a href="https://github.com/korbinian90/MriResearchTools.jl">MriResearchTools.jl</a> can be helpful.</p>

<p dir="auto">Install Julia 1.9 or newer (<a href="https://julialang.org" rel="nofollow">https://julialang.org</a>)<br>
Copy the file <a href="https://github.com/korbinian90/ROMEO.jl/blob/master/romeo.jl">romeo.jl</a> from this repository to a convenient location. An alias for <code>romeo</code> as <code>julia &lt;path-to-file&gt;/romeo.jl</code> might be useful.</p>
<div class="highlight highlight-source-shell notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="    $ julia &lt;path-to-file&gt;/romeo.jl phase.nii -m mag.nii -t [2.1,4.2,6.3] -o results"><pre>    $ julia <span class="pl-k">&lt;</span>path-to-file<span class="pl-k">&gt;</span>/romeo.jl phase.nii -m mag.nii -t [2.1,4.2,6.3] -o results</pre></div>
<p dir="auto">On the first run, the dependencies will be installed automatically.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Multi-Echo</h3><a id="user-content-multi-echo" class="anchor" aria-label="Permalink: Multi-Echo" href="#multi-echo"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If multi-echo data is available, supplying ROMEO with multi-echo information should improve the unwrapping accuracy. The same is true for magnitude information.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Phase Offsets</h3><a id="user-content-phase-offsets" class="anchor" aria-label="Permalink: Phase Offsets" href="#phase-offsets"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If the multi-echo data contains <strong>large phase offsets</strong> (phase at echo time zero), default template unwrapping might fail. Setting the <code>individual-unwrapping</code> flag is a solution, as it performs spatial unwrapping for each echo instead. The computed B0 map is not corrected for remaining phase offsets.</p>
<p dir="auto">For proper handling, the phase offsest can be removed using <code>mcpc3ds</code> from <code>MriResearchTools</code>. This works for monopolar and bipolar data, already combined or uncombined channels. However, if the phase is already "corrupted" by other coil combination algorithms, it might not be possible to estimate and remove the phase offsets.</p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Repeated Measurements (EPI)</h3><a id="user-content-repeated-measurements-epi" class="anchor" aria-label="Permalink: Repeated Measurements (EPI)" href="#repeated-measurements-epi"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">4D data with an equal echo time for all volumes should be unwrapped as 4D for best accuracy and temporal stability. The echo times can be set to <code>TEs=ones(size(phase,4))</code></p>
<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">Setting the Template Echo</h3><a id="user-content-setting-the-template-echo" class="anchor" aria-label="Permalink: Setting the Template Echo" href="#setting-the-template-echo"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">In certain cases, the phase of the first echo/time-point looks differently than the rest of the acquisition, which can occur due to flow compensation of only the first echo or not having reached the steady state in fMRI. This might cause template unwrapping to fail, as the first echo is chosen as the template by default.<br>
With the optional argument <code>template=2</code>, this can be changed to the second (or any other) echo/time-point.</p>
