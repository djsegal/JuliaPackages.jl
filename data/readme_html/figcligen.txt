<p dir="auto">Generate Julia code that provide functions to run CLI programs.</p>
<p dir="auto">The specification to generate this code is similar to what <a href="https://fig.io/" rel="nofollow">Fig</a> uses, but in JSON format. So for popular CLIs, a starting point can be the spec found in the <a href="https://github.com/withfig/autocomplete">Fig autocomplete repo</a>. Remember to convert from <code>js</code> to <code>json</code> format.</p>

<p dir="auto">Generate a Julia module for a CLI based on a specification file.
Refer to <a href="#generated-code-structure">Generated Code Structure</a> for more details of the code generated.</p>
<p dir="auto">Arguments:</p>
<ul dir="auto">
<li><code>specfile</code>: path to the specification file</li>
<li><code>outputfile</code>: path to the output file</li>
</ul>
<p dir="auto">Keyword arguments:</p>
<ul dir="auto">
<li><code>custom_include</code>: a string to include at the top of the generated module</li>
<li><code>ignore_base_command</code>: if <code>true</code>, do not generate the base command.
The base command must be made available by the caller,
either by including it in <code>custom_include</code> or by
defining it in the module before calling <code>generate</code>.</li>
</ul>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Generated Code Structure</h2><a id="user-content-generated-code-structure" class="anchor" aria-label="Permalink: Generated Code Structure" href="#generated-code-structure"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Code is generated into a module named <code>CLI</code>. The module name is fixed, the intent being for it to be wrapped within another module or package.</p>
<p dir="auto">The primary command line options are generated as methods within the module, with names same as the option name. The optional parameters are keyword arguments. And the methods accept other arguments to be passed to the command.</p>
<p dir="auto">An example that generates a CLI for <code>grep</code> is included:</p>
<ul dir="auto">
<li><code>grep</code> <a href="test/specs/grep.json">specs</a></li>
<li><code>grep</code> <a href="examples/grep.jl">generated code</a></li>
<li><code>grep</code> <a href="test/greptest.jl">example use of generated code</a></li>
</ul>
<p dir="auto">A more complex spec is that of Open Policy Agent:</p>
<ul dir="auto">
<li><code>opa</code> <a href="test/specs/opa.json">specs</a></li>
<li><code>opa</code> <a href="examples/opa.jl">generated code</a></li>
</ul>

<p dir="auto">Each method accepts an instance of <code>CommandLine</code> as the first argument that holds the execution context. It has the following members:</p>
<ul dir="auto">
<li><code>exec</code>: a no argument function that provides the base command to execute in a julia <code>do</code> block.</li>
<li><code>cmdopts</code>: keyword arguments that should be used to further customize the <code>Cmd</code> creation</li>
<li><code>pipelineopts</code>: keyword arguments that should be used to further customize the <code>pipeline</code> creation</li>
</ul>
<p dir="auto"><code>CommandLine</code> is generated by default, and is termed as the "base command". It can be overridden during code generation by passing the optional <code>ignore_base_command</code> and <code>custom_include</code> keyword arguments. See <a href="#code-generation">"Code generation"</a>.</p>
