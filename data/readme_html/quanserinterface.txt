<p dir="auto"><a href="https://github.com/baggepinnen/QuanserInterface.jl/actions/workflows/CI.yml?query=branch%3Amain"><img src="https://github.com/baggepinnen/QuanserInterface.jl/actions/workflows/CI.yml/badge.svg?branch=main" alt="Build Status" style="max-width: 100%;"></a></p>
<p dir="auto">This repo contains a Julia interface to the Quanser hardware-in-the-loop (HIL) SDK. This allows you to control their devices, reading measurements and issuing control commands etc.</p>
<p dir="auto">See the Youtube vidoe series <a href="https://youtube.com/playlist?list=PLC0QOsNQS8hZtOQPHdtul3kpQwMOBL8Qc&amp;si=E5alRBkegrN0P3DM" rel="nofollow">Control of a rotary pendulum using Julia</a> for several examples on how to use this package.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Installation</h2><a id="user-content-installation" class="anchor" aria-label="Permalink: Installation" href="#installation"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ol dir="auto">
<li>Install the hardware-in-the-loop (HIL) interface from here <a href="https://github.com/quanser/hil_sdk_linux_x86_64">https://github.com/quanser/hil_sdk_linux_x86_64</a> (change linux to what's appropriate for your system)</li>
<li>To use the <code>PythonBackend</code> Install Quanser python packages as described <a href="https://docs.quanser.com/quarc/documentation/python/installation.html" rel="nofollow">here</a> and manually install and load PythonCall (the python backend is an extension). Optionally, set the default backend using <code>QuanserInterface.set_default_backend("python")</code>.</li>
<li>To use the C backend (default), install the sdk, and if on Linux, possibly symlink <code>sudo ln -s /usr/lib/x86_64-linux-gnu/libquanser_communications.so.1 /lib/libquanser_communications.so</code> (or wherever the library is located on your system), I had issues with the <code>.1</code> suffix causing Libdl not to find the library. The easiest way to install all the required shared libraries is to follow the python install instructions, i.e., issue the <code>sudo apt install python3-quanser-apis</code> after having added their package server.</li>
</ol>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Run on hardware</h2><a id="user-content-run-on-hardware" class="anchor" aria-label="Permalink: Run on hardware" href="#run-on-hardware"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">If you have a Qube servo 3 connected to your machine, you can run one of the demos in the <code>examples</code> folder. The procedure is as follows</p>
<ol dir="auto">
<li>Instantiate a device object, e.g. <code>process = QubeServo()</code> or <code>process = QubeServoPendulum()</code></li>
<li>Home the device (calibrate measurement offsets) by calling <code>home!</code>. This is only required for the <code>QubeServoPendulum()</code>, (unless you're interested in position control of the <code>QubeServo</code>). <code>home!</code> expects the arm of the device to be all the way to the left, hitting the end stop (if you are looking at the front logo of the device). The pendulum is expected to hang straight down. You can optionally provide the angle in degrees to <code>home!</code>, in this case, positive angles are to the left of zero (seen from above / right-hand rule with thumb pointing down). This must be done each time the device is powered on, and sometimes has to be redone when the device freaks out. There is also a function <code>go_home</code> which tries to move the arm to angle zero using a simple PI controller.</li>
<li>Call <code>measure(process)</code> to read some measurements from the device.</li>
<li>Call <code>control(process, [0.5])</code> to issue a control command to the device. The <code>0.5</code> here should make the device move to positive angles (to the left). Reset by calling <code>control(process, [0.0])</code>.</li>
<li>Try one of the examples.</li>
</ol>
<p dir="auto">Method signatures in this package are typically picky with types, e.g., Ints are not accepted where <code>Float64</code> is required by the device.</p>

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Hardware safety</h2><a id="user-content-hardware-safety" class="anchor" aria-label="Permalink: Hardware safety" href="#hardware-safety"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Some control loops in the examples directory contain a check for if the arm angle is out of bounds, and terminates the experiment by issuing <code>control(process, [0.0])</code> and returning if it is. This tries to prevent bad tuning from tearing the pendulum off the device or slamming into the end stops. Poorly tuned controllers can easily cause the magnetic connection to fail.</p>
<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">Glossary</h2><a id="user-content-glossary" class="anchor" aria-label="Permalink: Glossary" href="#glossary"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<code>Ts</code> sample time, the time interval at which control loops are run. Typically in the range of 50-200Hz (<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="9a951430898b63450afc8516ec593c6c">$T_s \in [0.02, 0.005]$</math-renderer>) for the Qube-Servo 3.</li>
<li>
<code>Tf</code> final time (duration).</li>
<li>
<code>y</code> measurement</li>
<li>
<code>u</code> control command</li>
<li>
<code>x</code> state</li>
<li>
<code>xh</code> state estimate (<math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="9a951430898b63450afc8516ec593c6c">$\hat x$</math-renderer>)</li>
<li>
<code>r</code> reference</li>
<li>
<code>e</code> error</li>
<li>
<code>K</code> proportional controller gain, sometimes also denotes a Kalman gain matrix</li>
<li>
<code>Ki</code> integral controller gain</li>
<li>
<code>Kf</code> Coulomb friction compensation parameter</li>
<li>
<code>L</code> state-feedback gain matrix <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="9a951430898b63450afc8516ec593c6c">$u = -Lx$</math-renderer> or <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="9a951430898b63450afc8516ec593c6c">$u = L(x_r-x)$</math-renderer>
</li>
<li>
<code>Q1, Q2</code> cost matrices for the LQR problem <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="9a951430898b63450afc8516ec593c6c">$J = \int_0^\infty x^T Q_1 x + u^T Q_2 u dt$</math-renderer>
</li>
<li>
<code>R1, R2</code> covariance matrices for the Kalman filter</li>
</ul>
