<p dir="auto">The package implements the following resampling algorithms</p>
<ul dir="auto">
<li>Random Oversampling</li>
<li>Random Walk Oversampling (RWO)</li>
<li>Random Oversampling Examples (ROSE)</li>
<li>Synthetic Minority Oversampling Technique (SMOTE)</li>
<li>Borderline SMOTE1</li>
<li>SMOTE-Nominal (SMOTE-N)</li>
<li>SMOTE-Nominal Categorical (SMOTE-NC)</li>
<li>Random Undersampling</li>
<li>Cluster Undersampling</li>
<li>EditedNearestNeighbors Undersampling</li>
<li>Tomek Links Undersampling</li>
<li>Balanced Bagging Classifier (@MLJBalancing.jl)</li>
</ul>
<p dir="auto">To see various examples where such methods help improve classification performance, check the <a href="https://juliaai.github.io/Imbalance.jl/dev/examples/" rel="nofollow">tutorials section</a> of the documentation.</p>
<p dir="auto">Interested in contributing with more? Check <a href="https://juliaai.github.io/Imbalance.jl/dev/contributing/" rel="nofollow">this</a>.</p>

<div class="markdown-heading" dir="auto"><h3 class="heading-element" dir="auto">🏓 Table Transforms Interface</h3><a id="user-content--table-transforms-interface" class="anchor" aria-label="Permalink: 🏓 Table Transforms Interface" href="#-table-transforms-interface"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">The <a href="https://juliaml.github.io/TableTransforms.jl/stable/transforms/" rel="nofollow"><code>TableTransforms</code> interface</a> operates on single tables; it assumes that <code>y</code> is one of the columns of the given table. Thus, it follows a similar pattern to the <code>MLJ</code> interface except that the index of <code>y</code> is a required argument while instantiating the model and the data to be transformed via <code>apply</code> is only one table <code>Xy</code>.</p>
<div class="highlight highlight-source-julia notranslate position-relative overflow-auto" dir="auto" data-snippet-clipboard-copy-content="using Imbalance
using Imbalance.TableTransforms
using TableTransforms

# Generate imbalanced data
num_rows = 200

<div class="markdown-heading" dir="auto"><h2 class="heading-element" dir="auto">📜 Rationale</h2><a id="user-content--rationale" class="anchor" aria-label="Permalink: 📜 Rationale" href="#-rationale"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">Most if not all machine learning algorithms can be viewed as a form of empirical risk minimization where the object is to find the parameters <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$\theta$</math-renderer> that for some loss function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$L$</math-renderer> minimize</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$$\hat{\theta} = \arg\min_{\theta} \frac{1}{N} \sum_{i=1}^{N} L(f_{\theta}(x_i), y_i)$$</math-renderer></p>
<p dir="auto">The underlying assumption is that minimizing this empirical risk corresponds to approximately minimizing the true risk which considers all examples in the populations which would imply that <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$f_\theta$</math-renderer> is approximately the true target function <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$f$</math-renderer> that we seek to model.</p>
<p dir="auto">In a multi-class setting with <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$K$</math-renderer> classes, one can write</p>
<p dir="auto"><math-renderer class="js-display-math" style="display: block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$$\hat{\theta} = \arg\min_{\theta} \left( \frac{1}{N_1} \sum_{i \in C_1} L(f_{\theta}(x_i), y_i) + \frac{1}{N_2} \sum_{i \in C_2} L(f_{\theta}(x_i), y_i) + \ldots + \frac{1}{N_K} \sum_{i \in C_K} L(f_{\theta}(x_i), y_i) \right)$$</math-renderer></p>
<p dir="auto">Class imbalance occurs when some classes have much fewer examples than other classes. In this case, the terms corresponding to smaller classes contribute minimally to the sum which makes it possible for any learning algorithm to find an approximate solution to minimizing the empirical risk that mostly only minimizes the over the significant sums. This yields a hypothesis <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$f_\theta$</math-renderer> that may be very different from the true target <math-renderer class="js-inline-math" style="display: inline-block" data-static-url="https://github.githubassets.com/static" data-run-id="4eb6c529ae542ac61aeb3fa3b9a209b1">$f$</math-renderer> with respect to the minority classes which may be the most important for the application in question.</p>
<p dir="auto">One obvious possible remedy is to weight the smaller sums so that a learning algorithm more easily avoids approximate solutions that exploit their insignificance which can be seen to be equivalent to repeating examples of the observations in minority classes. This can be achieved by naive random oversampling which is offered by this package along with other more advanced oversampling methods that function by generating synthetic data or deleting existing ones. You can read more about the class imbalance problem and learn about various algorithms implemented in this package by reading <a href="https://medium.com/@essamwissam/class-imbalance-and-oversampling-a-formal-introduction-c77b918e586d" rel="nofollow">this</a> series of articles on Medium.</p>
<p dir="auto">To our knowledge, there are no existing maintained Julia packages that implement resampling algorithms for multi-class classification problems or that handle both nominal and continuous features. This has served as a primary motivation for the creation of this package.</p>
