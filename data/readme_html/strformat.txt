<p dir="auto">The following extra format sequences (see <a href="https://github.com/JuliaString/StrLiterals.jl">StrLiterals</a> for the full specification) are added:</p>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">C style formatting specification language</h1><a id="user-content-c-style-formatting-specification-language" class="anchor" aria-label="Permalink: C style formatting specification language" href="#c-style-formatting-specification-language"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto"><code>\%&lt;ccc&gt;&lt;formatcode&gt;(arguments)</code> is interpolated as a call to <code>cfmt("%&lt;ccc&gt;&lt;formatcode&gt;",arguments)</code>, where <code>&lt;ccc&gt;&lt;formatcode&gt;</code> is a C-style format string.</p>
</li>
<li>
<p dir="auto">and  is [flags][width][.precision][length]</p>
</li>
<li>
<p dir="auto">supported flags are: <code> </code>, <code>-</code>, <code>+</code>, <code>0</code>, <code>#</code>, and <code>'</code> (add comma thousand separators)</p>
</li>
<li>
<p dir="auto">formatcode := <code>d</code> | <code>D</code> | <code>u</code> | <code>U</code> | <code>o</code> | <code>O</code> | <code>x</code> | <code>X</code> | <code>e</code> | <code>E</code> | <code>f</code> | <code>F</code> | <code>g</code> | <code>G</code> | <code>a</code> | <code>A</code> | <code>c</code> | <code>C</code> | <code>s</code> | <code>S</code> | <code>i</code> | <code>p</code> | <code>n</code></p>
</li>
<li>
<p dir="auto">length is ignored (it was only needed for C/C++ since argument values don't have types)</p>
</li>
</ul>
<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Type based formatting</h1><a id="user-content-type-based-formatting" class="anchor" aria-label="Permalink: Type based formatting" href="#type-based-formatting"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<ul dir="auto">
<li>
<p dir="auto"><code>\%(value, arguments...)</code> is interpolated as a call to <code>fmt(value, arguments...)</code>.
This is especially useful when defaults have been set for the type of the first argument.</p>
</li>
<li>
<p dir="auto"><code>fmt_default!{T}(::Type{T}, syms::Symbol...; kwargs...)</code> sets the defaults for a particular type.</p>
</li>
<li>
<p dir="auto"><code>fmt_default!(syms::Symbol...; kwargs...)</code> sets the defaults for all types.</p>
</li>
<li>
<p dir="auto"><code>reset!{T}(::Type{T})</code> resets the defaults for a particular type.</p>
</li>
<li>
<p dir="auto"><code>defaultSpec(x)</code> will return the defaults for the type of x, and</p>
</li>
<li>
<p dir="auto"><code>defaultSpec{T}(::Type{T})</code> will return the defaults for the given type.</p>
</li>
</ul>
<p dir="auto">Symbols that can currently be used are: <code>:ljust</code> or <code>:left</code>, <code>:rjust</code> or <code>:right</code>, <code>:center</code>, <code>:commas</code>, <code>:zpad</code> or <code>:zeropad</code>, and <code>:ipre</code> or <code>:prefix</code>.
Several keyword arguments can also be used:</p>

<div class="markdown-heading" dir="auto"><h1 class="heading-element" dir="auto">Python style formatting specification language</h1><a id="user-content-python-style-formatting-specification-language" class="anchor" aria-label="Permalink: Python style formatting specification language" href="#python-style-formatting-specification-language"><svg class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">(supports most all options except for '%' currently)</p>
<ul dir="auto">
<li>spec  ::= [[fill]align][sign][#][0][width][,_][.prec][type]</li>
<li>fill  ::= </li>
<li>align ::= '&lt;' | '^' | '&gt;'</li>
<li>sign  ::= '+' | '-' | ' '</li>
<li>width ::= </li>
<li>prec  ::= </li>
<li>type  ::= 'b' | 'c' | 'd' | 'e' | 'E' | 'f' | 'F' | 'g' | 'G' | 'n' | 'o' | 'x' | 'X' | 's'</li>
</ul>
<p dir="auto">Please refer to <a href="http://docs.python.org/2/library/string.html#formatspec" rel="nofollow">http://docs.python.org/2/library/string.html#formatspec</a>
for more details</p>
<p dir="auto">The syntax is slightly different, <code>\{&lt;formatspec&gt;}(expression)</code>, instead of <code>{variable:formatspec}</code>, so as to fit better with Julia's string syntax.</p>
